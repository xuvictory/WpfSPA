## 产品概述

WPF 上位机开发学习平台的内容优化任务。第 13 章 23 篇文章由统一模板批量生成，9 个知识卡片（白话理解/官方定义/由来背景/核心要点/适用场景/常见踩坑/最佳实践/上手练习/相关知识链接）均为通用套话，各篇之间高度雷同，缺乏与主题、与工控上位机场景的真实关联。各篇的完整示例代码已就绪（提交 a7b8056），本次仅重写文字卡片，示例代码与 YAML front-matter 原样保留。

## 核心功能

- 逐篇重写 23 篇的 9 个 Callout 卡片，彻底去除模板废话
- 每篇内容贴合自身知识点与现有示例主题（UI 虚拟化、Freezable 冻结、WeakEventManager 弱事件、位图解码缓存、视觉树、DrawingVisual、布局循环、延迟分页、async/await、IDisposable、Effect 特效、节流防抖、渲染层级、FPS 监控、布局计算、Snoop、VS 诊断、绑定调试、热重载、内存分析等），各篇不得雷同
- 删除每篇 `[!origin]` 卡片后残留的"本章节背景：工控现场对稳定性的要求近乎苛刻…"游离段落
- 相关知识链接改为站内真实文章互链（章内互链 + 跨章节链接 + 官方文档），禁止空话
- 完成后全目录校验模板特征清零、无格式污染，提交一次 commit

## 技术方案

### 执行策略

- 任务性质：纯 Markdown 内容重写，不涉及代码实现，不改动 `meta.json`、`src/`、`styles/` 与其余章节
- 参照标杆：每批动笔前先读 `public/content/07-mvvm/什么是-mvvm.md` 与 `public/content/11-advanced-ui/dpi-感知模式设置.md` 确认风格；再读本批各篇原文，逐篇 `write_to_file` 重写
- 保留部分：每篇 YAML front-matter（title/section/parent）与 `[!example]` 完整示例代码块原样保留
- 重写范围：`[!plain]` `[!def]` `[!origin]` `[!essentials]` `[!scene]` `[!pitfall]` `[!best]` `[!practice]` `[!related]` 共 9 个卡片，并删除 `[!origin]` 后的游离段落

### 写作规范（源自归档第 8 节，07/10/11 章已验证）

- `[!plain]`：用工控生活化类比讲清概念本质，不复读标题，不同篇用不同类比
- `[!def]`：真实准确的定义，区分"框架/特性/API/模式"，关键 API 写全限定归属，附官方文档链接
- `[!origin]`：真实历史与设计动机（如虚拟化源于 ItemsControl 控件膨胀、WeakEventManager 源于强引用泄漏）
- `[!essentials]`：本篇独有要点清单（机制、参数、适用条件），3-5 条
- `[!scene]`：针对主题的工控上位机真实场景，至少一条带具体数字（如 10 万点、100Hz、50ms）
- `[!pitfall]`：3 条真实易错点，每条含"现象 → 原因 → 解决"因果链
- `[!best]`：3 条可落地的工程实践（如 Freeze 时机、Recycling 模式选择、节流窗口值）
- `[!practice]`：Lv.1 运行改参数 → Lv.2 加功能 → Lv.3 改造/综合，结合本篇 API 可验证
- `[!related]`：真实站内链接，格式 `→ [标题](相对路径或#/chapter/…)`，前置/后续/关联必须指向真实存在的文章（07-16 章互链用文件名核实），官方文档用 learn.microsoft.com 具体页

### 校验方法（每批完成后执行）

- `search_content` 查目标目录模板特征应清零：`工控现场对稳定性的要求近乎苛刻`、`微软官方定义和实现`、`Lv.1 照猫画虎`、`请确保你已经理解了本章节之前的内容`、`本章节背景`
- `search_content pattern=^\+` 检查无 `+` 前缀污染
- 用 `[subagent:code-explorer]` 批量核实 23 篇 `[!related]` 中站内链接指向的文章文件真实存在
- 提交采用 UTF-8 消息文件方式（`git commit -F`），避免 PowerShell 中文编码问题，提交信息"13.性能优化与调试章节高质量内容更新"
