## 产品概述

完成 WPF 上位机学习平台菜单"15. 部署与发布"章节的代办事项：将 `public/content/15-deployment/` 下 10 篇文章的 `[!example] 完整示例` 卡片占位符（`// 📝 待补充实际示例代码`）替换为真实可运行、贴合上位机/工控场景的 WPF 示例代码（XAML + C# 两段代码块），逐篇编写，完成后校验并提交一次 commit。

- 按 15.1 发布方式 / 15.2 部署注意事项 / 15.3 版本管理三个子章节，为 10 篇文章各编写一个展示本节独有知识点的可运行 Demo：
- 发布环境诊断面板（独立/单文件发布）
- 部署方式对比看板（框架依赖 vs 独立部署）
- ClickOnce 更新检查面板（含非 ClickOnce 环境回退提示）
- MSI 安装信息读取器（Uninstall 注册表项）
- 开机自启动配置面板（注册表 Run 项查询/设置/移除）
- 运行环境体检（.NET Runtime 检查）
- 设备参数配置面板（读取配置文件回显）
- Windows 服务监控面板（ServiceController 查询状态）
- 语义版本号解析比较工具（SemVer）
- 版本信息查看器（Assembly Version vs File Version 对比）
- 只修改 `[!example]` 卡片内容，其余 9 种 Callout、meta.json、src/、styles/、index.html 及其他章节一律不动

- 完成后校验（占位符清零、无 + 前缀污染、改动范围仅限本章节）并提交 commit（提交信息"15.部署与发布菜单内容更新"）

## 技术栈

- 项目为纯前端 SPA（Vite + 原生 JS + marked），内容为 Markdown 文章；本任务不涉及平台代码改动，仅编辑 `public/content/15-deployment/*.md`
- 示例代码为 WPF 桌面应用（C# + XAML），面向 .NET 6+（WPF 上位机开发学习内容）

## 实现方案

### 编写策略

- 以 `public/content/04-controls/button-按钮.md` 的 `[!example]` 卡片为结构模板、`06-graphics` 各篇为代码规范参照，每篇将统一占位符串替换为"场景标题 + MainWindow.xaml + MainWindow.xaml.cs"标准三段结构
- 每篇示例必须突出本文独有知识点，避免万能模板；部署章节涉及系统级 API（注册表、Windows 服务、ClickOnce、运行时信息），演示采用只读查询或安全回退逻辑，避免破坏性写入

### 关键技术决策

- 注册表自启动（开机自启动设置）：演示 HKCU\Software\Microsoft\Windows\CurrentVersion\Run 项的查询/写入/删除，写入时仅在用户显式点击"启用"按钮时执行，并给出说明注释
- 运行时检查（目标机器 .NET Runtime 检查、框架依赖对比）：使用 `Environment.Version`、`RuntimeInformation.FrameworkDescription`、`AppContext` 读取运行时信息；程序集目录文件统计用 `Directory.GetFiles` 限定可执行文件所在目录
- 配置文件（依赖项打包与配置文件）：示例读取随应用分发的 `appsettings.json`（相对路径），使用 `JsonSerializer`/`ConfigurationManager` 类风格演示，避免绝对路径
- ClickOnce（clickonce-发布）：`ApplicationDeployment.IsNetworkDeployed` 判断当前是否 ClickOnce 部署，非部署环境显示回退提示而非抛异常
- MSI 安装信息（msi-安装包wix-toolset）：读取 `HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall` 子项，展示 DisplayName/DisplayVersion/InstallLocation 字段
- Windows 服务（windows-服务模式）：`System.ServiceProcess.ServiceController.GetServices()` 查询服务状态，仅演示 Status 读取
- 版本管理两篇（SemVer / Assembly vs File）：纯逻辑演示——SemVer 自实现主/次/修订号解析比较；版本信息用 `Assembly.GetExecutingAssembly().GetName().Version` 与 `FileVersionInfo.GetVersionInfo()` 对比展示

### 可靠性约束

- 所有系统级 API 调用包裹 try-catch，异常在界面状态栏回显，保证示例在任何开发机可编译运行
- 每篇文章只做一次替换；替换后保留 `[!example]` 卡片结尾的 `> ` 空引用行，与全章风格一致
- 代码块语言标记：XAML 用 `xml`，后台代码用 `csharp`
