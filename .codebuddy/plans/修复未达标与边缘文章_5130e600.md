## 技术方案

### 修复原则

- **只补不毁**:保留每篇现有的 frontmatter、一级标题、以及已达标的 Callout 内容(plain/def/example/scene/best/practice/related 大多已合格),仅在缺口处补齐缺失 Callout 并适度充实薄弱段落;不重写整篇、不做无关润色。
- **范式参照**:00-prelude 的 C# 基础文参照已达标同章文章 `public/content/00-prelude/try-catch-finally.md`(10 种 Callout 全齐、示例用 ```csharp 代码块、工控场景贴合);05-core-concepts 的 2 篇参照满分范文 `public/content/05-core-concepts/什么是依赖属性.md`。
- **串行编辑纪律**:同一文件的多次修改必须串行执行(每次编辑前重新读取该文件),严格区分空行与 `>` 引用空行,匹配串精确。

### 每篇缺失内容编写规范(第 8.2 节)

- `origin 由来背景`:写该 C# 主题的真实历史/设计动机(如 TPL 诞生背景、异常机制替代错误码、泛型引入动机),禁止"《标题》的诞生源于实际开发中的痛点"式空话。
- `essentials 核心要点`:该主题真正相关的要点清单(如 CancellationToken 的 IsCancellationRequested/ThrowIfCancellationRequested/Register;FileStream 的 Seek/缓冲区/异步),每条带 API 或代码片段。
- `pitfall 常见踩坑`:2-3 个真实坑,每条含"现象 → 原因 → 解决/预防"。
- `best 最佳实践`:主题相关的可落地实践,而非通用命名规范套话。
- `scene 适用场景`:✅ 适用 / ❌ 不适用正反对比,各篇不雷同。
- `practice 上手练习`:Lv.1 运行改参数 → Lv.2 加功能 → Lv.3 工控场景改造。
- `related 相关知识链接`:← 前置 / → 后续 / ⇄ 关联(指向站内真实文章,跨章用「第 N 章·文章名」格式)/ 📖 learn.microsoft.com 官方文档具体页。
- 示例:00-prelude 用 ```csharp 代码块即可(该章属 C_SHARP_ONLY_DIRS,不要求 XAML);示例须贴合 PLC/串口/Modbus/传感器/设备轮询等上位机场景。
- 补正文:薄弱文章在 plain/def 等处补充实质性技术解释,使 bodyLen ≥ 700(目标 1000-1200)。
