## 需求概述

用户发现提交 `33055f5`（09 章）的提交信息显示为乱码，要求修复。经排查确认 `304fe8d`（07 章）同样乱码，用户已确认**9 章 + 7 章一并修复**。

## 问题根因

提交信息存在双重编码污染：正确中文的 UTF-8 字节被 PowerShell 按 GBK 误解码成乱码字符，再按 UTF-8 存储进 commit 对象。commit 对象内实际存储的字节即为乱码字符串的 UTF-8 编码（已通过 `git cat-file` + Node 解压读取原始字节确认，非终端显示问题）。

## 修复目标

- `33055f5`（9 章）提交信息修复为：`9.上位机通讯协议菜单内容更新`
- `304fe8d`（7 章）提交信息修复为：`7.MVVM设计模式菜单内容更新`（标题依据《完整知识菜单.md》第 1137 行 "## 7. MVVM 设计模式"，格式与 8/9 章一致）
- `6a54a0c`（8 章，正常）提交信息保持不变
- 仅重写 commit 对象 message，**文件内容（tree）零改动**；工作区未提交修改（10-data-collection 章等）不得受影响
- 三个提交均未 push（origin/main 最新为 `ea518a6`），重写历史安全，**不执行 push**

## 技术选型

- **Git 历史重写**：`git filter-branch --msg-filter`（仅重写 commit message，tree 不变；git 2.39+ 的 deprecation 警告忽略即可）
- **编码处理**：Node.js（环境已验证可用，`TextDecoder('gbk')` 支持 full-icu，用于反向验证）
- **规避编码陷阱**：全程以字节/十六进制匹配与校验，不在 PowerShell 命令行直接传递任何中文（命令行传中文会二次乱码，已实测）

## 实施方案

### 1. 生成修复脚本 fix-msg.js（仓库根目录，UTF-8 无 BOM）

脚本从 stdin 接收 git 传入的旧 message 字节，按字节精确匹配后替换，其余原样输出：

- 匹配 9 章乱码字节 → 输出 `9.上位机通讯协议菜单内容更新\n` 的 UTF-8 字节
- 匹配 7 章乱码字节 → 输出 `7.MVVM设计模式菜单内容更新\n` 的 UTF-8 字节
- 其他（8 章）→ 原样输出

关键设计：

- 四组字节全部以十六进制数组硬编码（旧乱码字节在执行前先从对应 git 对象读取确认；正确字节已人工核算，并在执行时通过 Node 从《完整知识菜单.md》第 1137 行标题 + 8 章 commit 后缀交叉推导验证，双保险）
- 匹配前对输入 `trim` 尾部换行符，输出固定补 `\n`

### 2. 执行历史重写

```
git filter-branch -f --msg-filter "node fix-msg.js" ea518a6..HEAD
```

- 范围覆盖 8/7/9 三个提交，8 章经脚本原样输出（hash 随父链变化但 message 不变，无影响）
- filter-branch 使用 .git-rewrite 临时工作树，不触碰真实工作区；若意外报 dirty 错误，先 `git stash push` 再执行、完成后 `git stash pop`（stash 范围与重写提交无文件重叠，无冲突风险）

### 3. 字节级校验（Node 内联脚本，十六进制输出，不依赖终端中文显示）

- 新 9/7 章提交 message 字节 == 期望的正确 UTF-8 字节（PASS/FAIL）
- 反向验证：`TextDecoder('gbk')` 解码新 message 字节后再 UTF-8 编码 == 旧乱码字节（证明正确还原了污染前状态）
- `git diff <旧hash> <新hash> --stat` 为空 = tree 未变（文件内容零改动）
- 修复前后 `git status --short` 快照对比一致 = 工作区未提交修改未动

### 4. 清理

- 删除 fix-msg.js
- `git update-ref -d refs/original/refs/heads/main`（删除 filter-branch 备份引用）
- `git reflog expire --expire=now --all`（清除旧引用）
- **不执行** `git gc --prune=now`（保留旧 commit 对象，必要时可回退）

## 性能与可靠性

- 仅重写 3 个 commit 对象，开销可忽略
- 全程在 .git 内部操作，工作区文件零触碰
- 所有校验输出为十六进制字节，杜绝终端编码干扰

## 关键代码结构

fix-msg.js 核心逻辑（字节级匹配替换，无实现细节外的复杂度）：

- 输入：stdin 字节流（旧 commit message）
- 常量：G9_OLD/G7_OLD（旧乱码字节数组）、G9_NEW/G7_NEW（正确 UTF-8 字节数组，含尾部 `0A`）
- 处理：trim 尾部换行 → 与 G9_OLD/G7_OLD 逐字节比较 → 命中输出对应正确字节，否则原样输出
