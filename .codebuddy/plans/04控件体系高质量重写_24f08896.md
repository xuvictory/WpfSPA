## 用户需求

将 WPF 上位机开发学习平台「菜单 4」——第 4 章「控件体系」（`public/content/04-controls/`，共 48 篇）的全部文章，按《章节内容更新经验归档.md》第 8 节确立的「高质量文章写作规范」逐篇重写，使每篇达到与第 7 章标杆文章（`07-mvvm/什么是-mvvm.md`）同等质量。

## 产品概述

现有 48 篇文章的 `[!example] 完整示例` 已包含真实可运行的上位机示例代码（保留不动），但其余 9 个 Callout 均为批量生成的"废话模板"：白话理解复读标题、官方定义笼统且缺少真实 API 归属与文档链接、由来背景空话、核心要点为通用五点套话、适用场景全章雷同、踩坑/最佳实践/练习/相关链接均为通用占位文案，且存在游离段落「本章节背景：控件是构建界面的积木块…」。

## 核心功能

- 逐篇重写 9 个 Callout：白话理解（上位机场景生活化类比）、官方定义（真实准确 + API 全限定归属 + 具体官方文档链接）、由来背景（真实历史动机）、核心要点（与该控件真正相关的要点清单）、适用场景（各篇不雷同的针对性适用/不适用场景）、常见踩坑（每条含现象→原因→解决）、最佳实践（可落地）、上手练习（Lv.1-Lv.4 四档具体练习）、相关知识链接（章内用文件名互链、跨章指向真实文章、官方文档指向具体页面）
- 删除「本章节背景」游离段落；保留 frontmatter、H1 标题与完整示例代码不动
- 全部 48 篇重写完成后校验模板特征清零，并以 UTF-8 消息文件提交

## 技术方案

纯 Markdown 内容重写任务，不涉及代码与前端改动。沿用项目既有规范与工作流，不改动 `meta.json`、`quizzes.json`、`src/`、`styles/`、`index.html`、`README.md`。

### 实施方案

1. **标杆参照**：以 `public/content/07-mvvm/什么是-mvvm.md` 为高质量样板（plain 场景类比、def 真实定义+全限定归属、origin 真实历史、essentials 主题要点、scene 针对性场景、pitfall 现象→原因→解决、best 可落地实践、practice 四档、related 真实互链）；示例代码风格参照 `04-controls/button-按钮.md` 现有示例（保留不动）。
2. **每篇处理流程**：`read_file` 读全篇 → 按 Callout 区域用 `replace_in_file` 逐块替换（plain/def/origin+删除游离段落/essentials/scene/pitfall/best/practice/related）→ 保留 frontmatter、H1、`[!example]` 全文原样。
3. **分批策略**：按 meta.json 中 04 章的 11 个 subgroup 分成 5 批编写（每批 8-11 篇），避免一次性堆积。
4. **写作细则**（遵循归档第 8.2/8.3 节）：

- def 写全限定 API 归属（如 `System.Windows.Controls.Button`、`ToggleButton.IsChecked`），附 learn.microsoft.com 具体控件文档页；
- related 章内互链用文件名（如 `combobox-下拉选择框`），跨章用「第 N 章「文章名」」格式，官方文档用具体页面；
- pitfall 每条含「现象 → 原因 → 解决/预防」；practice 补齐 Lv.4 挑战；scene 各篇不得雷同；
- 不修改示例代码；如示例前一句话场景描述与新写的 plain/scene 冲突，仅允许微调该描述句，代码本身不动。

5. **校验**：`search_content` 统计 04-controls 下模板特征（`是 WPF 上位机开发中的一项重要知识`、`微软官方定义和实现`、`Lv.1 照猫画虎`、`请确保你已经理解了本章节之前的内容`、`本章节背景：控件是构建界面的积木块`、`^\+` 前缀污染）计数均为 0；抽查 2-3 篇渲染后的 XAML/C# 对应关系未被破坏。
6. **提交**：用 `write_to_file` 写 UTF-8 消息文件 `_msg.txt`（如「4.控件体系菜单内容高质量重写」），执行 `git commit -F _msg.txt` 后删除临时文件，避免 PowerShell 中文 GBK 编码坑。

### 实施注意

- `meta.json` 约 13.8 万字符，禁止 `read_file` 全文，仅用 `search_content` 局部提取；
- 同一文件必须串行编辑：改完一处读一次再改下一处，避免写锁超时/匹配失败；
- 每批写完后立即用 `search_content pattern=^\+` 检查格式污染；
- 爆炸半径控制：仅允许改动 `public/content/04-controls/` 下 48 个 md 与归档文档，其余目录不动。

### 架构说明

内容组织沿用现有「十段式深度教学法」10 种 Callout 结构，不新增或删减结构；互链关系在章内通过文件名、跨章通过章节号+文章名建立真实导航，确保文章间形成可追溯的学习链路。
