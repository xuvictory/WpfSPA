# 相机通信与图像显示

> [!plain] 白话理解
> 工业相机就是车间里的"眼睛"，上位机则是看监控的"人"：相机每秒送来几十帧画面，程序要把这些画面一帧帧显示在窗口里。这里用到的 `WriteableBitmap` 是一块"边写边显示的画布"——每来一帧，先 `Lock()` 把画布锁住（防止显示到一半被改），把像素数据拷进后台缓冲区（`BackBuffer`），再 `AddDirtyRect` 告诉它"这块区域变了"并 `Unlock()` 解锁刷新。三步一解锁，一帧就上屏了。
> 示例用灰度噪声帧模拟工业相机的 10FPS 视频流，右侧实时显示帧率与累计帧数，点"拍照"把当前帧存成 PNG。脱离真实相机也能跑通"采集 → 显示 → 保存"的完整链路；接真实相机时，只把模拟生成像素换成相机 SDK 的回调数据即可。

> [!def] 官方定义
> **工业相机**通过 **GigE Vision**（基于千兆以太网，2006 年发布标准）、**USB3 Vision**（2013）或 Camera Link 等接口传输图像，厂商提供 C/C++ SDK（如海康机器人 MVS、Basler pylon），上位机通过 C# 互操作（P/Invoke/C++/CLI 封装）获取帧数据。
> **WriteableBitmap** 是 `System.Windows.Media.Imaging` 中可动态更新的位图：`Lock()` 锁定后台缓冲区，`BackBuffer` 指向像素内存，`AddDirtyRect` 标记更新区域，`Unlock()` 提交刷新——适合逐帧更新视频流。**PngBitmapEncoder** 用于将帧编码保存为 PNG。文档见 https://learn.microsoft.com/zh-cn/dotnet/api/system.windows.media.imaging.writeablebitmap

> [!origin] 由来背景
> 机器视觉（Machine Vision）从上世纪 1970 年代进入工厂：日本基恩士、美国 Cognex 等厂商率先把"相机 + 图像算法"用于电子元件检测，替代人眼质检；2000 年代以太网相机与 GigE Vision 标准（AIA 协会发布）让视觉系统普及化——一根网线同时传图像和供电（PoE），PC 直接当图像处理主机。
> 上位机集成相机的经典痛点是把"相机 SDK 的帧数据"变成"WPF 能显示的图像"。WPF 早期只支持静态 `BitmapImage`，每帧 new 一张既慢又占内存；`WriteableBitmap` 提供了可复用的像素缓冲区，成为视频流显示的标配。海康 MV-CE060 等相机型号的 SDK 回调数据，经 `Marshal.Copy` 拷入 `BackBuffer`，就是示例中这十几行代码的真实形态。

> [!essentials] 核心要点
> - **WriteableBitmap 缓冲机制**：`Lock → 拷贝 BackBuffer → AddDirtyRect → Unlock` 四步完成一帧上屏，缺一不可
> - **模拟帧保真**：灰度噪声帧按 10FPS 节奏生成，链路（采集→显示→保存）与真实相机完全一致
> - **帧率统计**：每秒结算一次 FPS（`_fpsCount` 归零 + 记录起点），监控采集是否达标
> - **PNG 保存**：`PngBitmapEncoder` 把当前帧编码写盘，拍照功能零依赖即可用
> - **启停控制**：`DispatcherTimer` 控制采集启停，重复启动前先 Stop，防止多定时器叠加

> **MainWindow.xaml.cs —— 后台代码：**
> ```csharp
> using System;
> using System.IO;
> using System.Runtime.InteropServices;
> using System.Windows;
> using System.Windows.Media;
> using System.Windows.Media.Imaging;
> using System.Windows.Threading;
>
> namespace HmiDemo
> {
>     public partial class MainWindow : Window
>     {
>         private const int FrameW = 640, FrameH = 480;
>         private readonly DispatcherTimer _timer = new DispatcherTimer();
>         private readonly Random _rand = new Random();
>         private WriteableBitmap _bitmap;
>         private int _frames, _fpsCount;
>         private DateTime _last = DateTime.Now;
>
>         public MainWindow()
>         {
>             InitializeComponent();
>             _timer.Interval = TimeSpan.FromMilliseconds(100); // 模拟 10FPS 采集
>             _timer.Tick += OnCapture;
>         }
>
>         private void OnToggle(object sender, RoutedEventArgs e)
>         {
>             if (_timer.IsEnabled)
>             {
>                 _timer.Stop(); CamBtn.Content = "开始采集"; StatusText.Text = "相机停止";
>             }
>             else
>             {
>                 _timer.Start(); CamBtn.Content = "停止采集";
>                 StatusText.Text = "采集中…"; StatusText.Foreground = Brushes.LimeGreen;
>             }
>         }
>
>         // 模拟相机采集一帧：生成灰度噪声图（真实项目为相机 SDK 的图像回调）
>         private void OnCapture(object sender, EventArgs e)
>         {
>             if (_bitmap == null)
>             {
>                 _bitmap = new WriteableBitmap(FrameW, FrameH, 96, 96, PixelFormats.Gray8, null);
>                 CamImage.Source = _bitmap;
>             }
>             var buffer = new byte[FrameW * FrameH];
>             _rand.NextBytes(buffer);
>             _bitmap.Lock();                                    // 锁定后台缓冲区
>             Marshal.Copy(buffer, 0, _bitmap.BackBuffer, buffer.Length);
>             _bitmap.AddDirtyRect(new Int32Rect(0, 0, FrameW, FrameH));
>             _bitmap.Unlock();                                  // 解锁并刷新显示
>
>             // 帧率统计：每秒结算一次
>             _frames++; _fpsCount++;
>             var now = DateTime.Now;
>             if ((now - _last).TotalSeconds >= 1)
>             {
>                 FpsText.Text = $"{_fpsCount} FPS";
>                 _fpsCount = 0; _last = now;
>             }
>             FrameText.Text = _frames.ToString();
>         }
>
>         // 拍照：把当前帧编码为 PNG 保存到程序目录
>         private void OnSnapshot(object sender, RoutedEventArgs e)
>         {
>             if (_bitmap == null) return;
>             var encoder = new PngBitmapEncoder();
>             encoder.Frames.Add(BitmapFrame.Create(_bitmap));
>             encoder.Save(File.Create("snapshot.png"));
>             StatusText.Text = $"已保存 snapshot.png（第 {_frames} 帧）";
>         }
>     }
> }
> ```
>

> [!scene] 适用场景
> ✅ 视觉检测平台图像采集：GigE/USB3 工业相机接入，实时显示采集画面供操作员确认
> ✅ 相机联调与标定：看帧率是否达标、图像是否正常、拍照存图供后续算法调试
> ✅ 无相机环境的教学演示：模拟帧跑通"采集→显示→保存"链路，硬件就位只换数据源
> ✅ 图像采集留档：产品批次、缺陷样本的原始图保存（PNG/BMP），供追溯与算法训练
> ❌ 只需显示静态图片：用 `BitmapImage` 更简单（见第 6 章「bitmapimage」）
> ❌ 高帧率大图（200FPS × 5MP）：WriteableBitmap + UI 线程吃力，应分离采集线程 + 帧队列 + 双缓冲

> [!pitfall] 常见踩坑
> 坑 1：**Lock 后忘记 Unlock** → 画布一直锁定，界面卡死/抛异常"缓冲区已被锁定" → Lock/Unlock 成对出现，放进 try/finally 保证解锁
>
> 坑 2：**像素数组长度与 Bitmap 尺寸不匹配**（Gray8 每像素 1 字节，数组必须是 `W*H` 字节）→ 拷贝越界或图像花屏 → 先确认 `PixelFormats.Gray8` 的字节数（1B/px），数组长度严格等于 `W*H`
>
> 坑 3：**写了 BackBuffer 却漏了 AddDirtyRect** → 画面不刷新，还以为是数据没进来 → 每次拷贝后必须 `AddDirtyRect(new Int32Rect(0,0,W,H))` 标记整帧更新
>
> 坑 4：**在相机 SDK 回调线程里直接操作 UI** → 跨线程访问异常（与串口 DataReceived 同理）→ 回调只收帧进队列，UI 用 Dispatcher 定时取帧刷新（见「串口数据采集模块」的线程模型）

> [!best] 最佳实践
> - `WriteableBitmap` 创建一次反复复用（改 BackBuffer 内容），不要每帧 new，减少 GC 与内存碎片
> - 采集与显示分离：相机线程 → 帧队列（`ConcurrentQueue`）→ UI `DispatcherTimer` 定时取最新帧，天然防抖且不卡 UI
> - 相机参数（分辨率、帧率、像素格式）界面可配，真实相机参数变化不用改代码
> - 帧率与丢帧计数常驻界面，"数据停更/掉帧"本身是视觉系统的重要告警
> - 真实项目用相机厂商 SDK（MVS/pylon）+ 封装类（`CameraService`），模拟版与真实版实现同一接口可切换（参考「modbus-通信层封装」）
> - 截图保存路径用绝对路径 + 时间戳命名，避免同名覆盖

> [!practice] 上手练习
> **Lv.1 照猫画虎**：运行示例，观察灰度噪声画面按 10FPS 刷新、FPS/帧数递增，点"拍照"生成 snapshot.png
> **Lv.2 小试牛刀**：把模拟帧从纯噪声改为"亮度渐变的竖条纹"（模拟工件移动），并添加一个"图像灰度均值"实时显示

> **Lv.4 挑战**：实现"采集线程 + 帧队列"架构：相机回调入队、UI 定时取最新帧并统计帧率/丢帧率；再把 `CameraService` 抽成接口，模拟版与 MVS 版切换运行
