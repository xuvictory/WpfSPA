# 运动控制卡通信

> [!plain] 白话理解
> 运动控制卡就像给机器装了个"自动驾驶司机"：上位机只需要说"X 轴开到位置 100、速度 50"，控制卡就自己算好加减速、输出脉冲，把伺服电机稳稳送到位。上位机的活儿只有两件：**下发命令**（目标位置 + 速度）和**轮询状态**（现在到哪了、到位没有）。
> 示例把这个模式完整跑通：点"开始点位运动"就是下发命令，`DispatcherTimer` 每 100ms 轮询一次"当前位置"——这里用速度 × 时间模拟控制卡的位置积分推进，位置按步长一步步逼近目标，误差小于 0.01 时判定"运动到位"并亮起完成信号。接真实控制卡时，这条"命令 → 轮询"链路不变，只是把模拟推进换成读控制卡的寄存器/回调。这与「modbus-通信层封装」的"下发 → 轮询"是同一套路，只是设备从 PLC 换成了控制卡。

> [!def] 官方定义
> **运动控制卡**（Motion Control Card）是以 DSP/FPGA 为核心的插卡式控制器（如固高 GTS、雷赛 DMC、正运动 ZMC）：上位机通过 PCIe/USB 通信，调用厂商 SDK（DLL 导出的 C 函数）下发**点位运动**（Point-to-Point）、**连续轨迹**（插补）等指令；控制卡负责脉冲输出、编码器反馈与加减速规划，并回报轴状态（位置、速度、到位信号、报警）。
> 通信模型为典型的**"下发命令 → 轮询状态"**（Command-Poll）：上位机调用 `gt_motion`/`dmc_set_vector` 等 SDK 函数下发命令，再以固定周期调用 `gt_get_position` 等函数读回轴状态。控制卡 API 文档参考固高 https://www.googoltech.com.cn/ 与雷赛 https://www.leisai.com/ 官网。

> [!origin] 由来背景
> 运动控制卡的历史可追溯到 PC 数控（CNC）的兴起：1980 年代，专用数控系统（NC）价格昂贵、封闭，业界尝试用"PC + 插卡"替代——一块 ISA/PCI 插卡输出脉冲、PC 跑上位软件，成本骤降且开放可编程。1990-2000 年代固高、雷赛等国产厂商崛起，把点位、插补、电子齿轮等能力固化成 SDK，工业自动化（点胶机、贴片机、激光切割）大量采用。
> 对上位机开发者的启示是：运动控制卡把"发脉冲、管电机"的底层活全包了，上位机只做"业务编排"——何时下发什么命令、轮询什么状态、异常怎么处理。本篇示例把"命令 + 轮询"的最小模型跑通，理解后接真实 SDK 只是把模拟替换成 API 调用，架构完全不变。

> [!essentials] 核心要点
> - **命令-轮询模式**：上位机下发（目标位置/速度）与轮询（当前位置/到位信号）分离，两条路径并行运转
> - **点位运动参数**：轴号（X/Y）、目标位置、运动速度三元组决定一次点位运动
> - **位置积分模拟**：`_x += Sign(目标-当前) * Min(|距离|, 速度×周期)` 模拟控制卡的加减速推进，100ms 一拍
> - **到位判定**：误差小于阈值（0.01）判定到位并置"完成信号"，对应真实系统的到位（In-Position）检测
> - **回原点**：Home 命令把目标清零，实际系统还涉及原点开关回零（见「轴状态监控与轨迹编程」）

> **MainWindow.xaml.cs —— 后台代码：**
> ```csharp
> using System;
> using System.Windows;
> using System.Windows.Media;
> using System.Windows.Threading;
>
> namespace HmiDemo
> {
>     public partial class MainWindow : Window
>     {
>         // 轴当前状态（实际项目由控制卡驱动轮询回读）
>         private double _x, _y;
>         private double _xTarget, _yTarget;
>         private double _speed = 50; // 单位/秒
>         private bool _moving;
>         private readonly DispatcherTimer _timer = new DispatcherTimer();
>
>         public MainWindow()
>         {
>             InitializeComponent();
>             _timer.Interval = TimeSpan.FromMilliseconds(100); // 100ms 轮询一次
>             _timer.Tick += OnPoll;
>             _timer.Start();
>         }
>
>         // 下发点位运动命令：设定目标位置与速度
>         private void OnMove(object sender, RoutedEventArgs e)
>         {
>             double target = double.Parse(TargetBox.Text);
>             _speed = double.Parse(SpeedBox.Text);
>             if (AxisBox.SelectedIndex == 0) _xTarget = target; else _yTarget = target;
>             _moving = true;
>             CmdLog.Text = $"命令已下发：{(AxisBox.SelectedIndex == 0 ? "X" : "Y")} 轴 → {target} @ {_speed}/s";
>             CmdLog.Foreground = Brushes.Orange;
>         }
>
>         // 回原点命令
>         private void OnHome(object sender, RoutedEventArgs e)
>         {
>             _xTarget = 0; _yTarget = 0; _moving = true;
>             CmdLog.Text = "回原点命令已下发";
>             CmdLog.Foreground = Brushes.Orange;
>         }
>
>         // 轮询状态：控制卡按速度朝目标移动，这里模拟位置积分推进
>         private void OnPoll(object sender, EventArgs e)
>         {
>             double step = _speed * 0.1; // 100ms × 速度 = 每拍位移
>             if (_moving)
>             {
>                 _x += Math.Sign(_xTarget - _x) * Math.Min(Math.Abs(_xTarget - _x), step);
>                 _y += Math.Sign(_yTarget - _y) * Math.Min(Math.Abs(_yTarget - _y), step);
>                 if (Math.Abs(_x - _xTarget) < 0.01 && Math.Abs(_y - _yTarget) < 0.01)
>                 {
>                     _moving = false; // 到达目标，读回"运动到位"完成信号
>                     CmdLog.Text = "运动到位（完成信号）";
>                     CmdLog.Foreground = Brushes.LimeGreen;
>                 }
>             }
>             AxisStateText.Text = $"X 轴：{_x:F1}　Y 轴：{_y:F1}　{(_moving ? "运动中" : "运动停止")}";
>         }
>     }
> }
> ```

> [!scene] 适用场景
> ✅ 多轴运动平台：点胶、焊锡、贴片、锁螺丝等设备用控制卡驱动多轴，上位机编排动作
> ✅ 视觉 + 运动联动：视觉定位结果（见「检测逻辑与结果统计」）转成目标坐标，下发控制卡完成"看-动"闭环
> ✅ 点位运动控制：X/Y 平台走位、Z 轴点胶升降，命令-轮询模式足够
> ✅ 教学与仿真：无硬件时用模拟推进验证上位机逻辑，接真卡只换通信层
> ❌ 简单单轴启停：继电器/PLC 即可控制，控制卡大材小用
> ❌ 多轴高速插补（五轴联动、CNC 轮廓加工）：需要专业插补功能与 EtherCAT 总线，一般控制卡力不从心

> [!pitfall] 常见踩坑
> 坑 1：**输入不校验直接 double.Parse** → 操作工输入"abc"或空串，程序直接崩溃 → 用 `double.TryParse` 并校验速度 > 0、位置在行程范围内（限位）
>
> 坑 2：**命令下发后不做确认** → 以为命令已执行，实际控制卡忙碌/连接断开，轴纹丝不动 → 下发后查询命令状态/返回码，失败提示"命令未接受"，结合轮询确认轴确实动了
>
> 坑 3：**轮询频率与运动节拍失配** → 轮询太慢错过到位信号，太快浪费 CPU → 轮询周期与速度匹配（100ms 对 50/s 速度，每拍位移 5 单位），到位判定带阈值（0.01）防抖动
>
> 坑 4：**没有急停与异常路径** → 轴撞到限位或电机报警，程序还在傻等"到位" → 轮询必须同时读报警/限位状态，异常立即停止并提示（真实项目接硬急停回路）

> [!best] 最佳实践
> - 把控制卡 SDK 封装成 `MotionCard` 类（Init/Move/Home/GetPosition），业务层只调接口，模拟版与真实版可切换（同「modbus-通信层封装」思路）
> - 所有下发命令打印日志（轴号/目标/速度/返回码），现场排查"为什么没动"靠日志说话
> - 单位统一：界面用工程单位（mm），底层换算成脉冲（`位置 × 脉冲当量`），换算只在封装层做一次
> - 轮询状态与 UI 刷新分离：轮询更新数据，UI 绑定展示（见「viewmodel-与-ui-设计」），避免在轮询里直接改控件
> - 每次运动前检查：轴已使能（Enable）、无报警、目标在限位内；运动后确认到位，形成完整闭环
> - 急停按钮常驻界面且逻辑独立于业务线程，与硬急停回路配合，双保险

> [!practice] 上手练习
> **Lv.1 照猫画虎**：运行示例，选 X 轴目标 100 速度 50 点"开始点位运动"，观察位置每拍推进、到位后绿字"运动到位"；再点"回原点"
> **Lv.2 小试牛刀**：把位置推进改为"先匀加速后匀速"两段式（前 30% 位置加速、后 70% 匀速），观察到达时间变化；输入校验（TryParse + 速度>0）
> **Lv.3 融会贯通**：增加"急停"按钮：点击后 `_moving=false` 并冻结目标，状态栏红色提示；再模拟"超行程"（目标 > 200 拒绝下发并提示限位）
> **Lv.4 挑战**：封装 `IMotionCard` 接口（`MoveTo`/`Home`/`GetPosition`/`EmergencyStop`），实现模拟版与真实版（P/Invoke 调用固高 `gt_*` 系列函数）两套实现，界面只依赖接口；再增加轴状态机（见「设备状态机设计」）管理"空闲/运动中/到位/报警"
