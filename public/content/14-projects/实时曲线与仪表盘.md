# 实时曲线与仪表盘

> [!plain] 白话理解
> 实时曲线就像医院的心电图机：温度每 0.5 秒产生一个采样点，连成一条线不断向右延伸，到达屏幕右沿就把最旧的点挤出去，形成"传送带"式滚动。数据在变，但曲线永远只显示最近 60 个点，眼睛看的就是"刚才到现在"的趋势。
> 旁边的仪表盘像汽车油表：ProgressBar 的长条模拟指针位置，数字直接显示当前温度，一眼就能读出"现在 27.3℃"。曲线看趋势、仪表看瞬时，两者配合就是上位机监控界面的基本功。实现上，曲线是往 Canvas 里挂一条 Polyline，每次只更新它的 Points 数据点集合，界面自动重绘——WPF 的"保留模式渲染"让这件事变得非常简单。

> [!def] 官方定义
> **Polyline** 是 `System.Windows.Shapes` 命名空间下的 2D 图形元素（Shape 派生类）：通过 `Points`（`PointCollection`）定义一组折线顶点，设置 `Stroke`/`StrokeThickness` 描述线样式。它采用**保留模式渲染**（Retained Mode）：WPF 合成器维护场景树，修改 `Points` 后系统自动重绘，无需手动调用重画 API。
> **Canvas** 是 WPF 布局面板之一，通过 `Canvas.Left`/`Canvas.Top` 按坐标定位子元素，适合做图表绘制底板（坐标原点在左上角，Y 轴向下）。官方文档见 https://learn.microsoft.com/zh-cn/dotnet/api/system.windows.shapes.polyline

> [!origin] 由来背景
> 实时曲线最早见于医疗与工业的记录仪：20 世纪初的机械笔式记录仪用纸带匀速走纸，笔头随信号摆动，画出的就是"时间-幅值"曲线。工业 HMI（人机界面）沿用了这一习惯，把"历史趋势图"作为标配画面——操作工看曲线能判断升温快慢、波动是否异常，比只看数字直观得多。
> WPF 中实现曲线最直接的途径就是 Polyline + Canvas：把"走纸"变成"数据点滚动"，把"笔头摆动"变成"Y 坐标映射"。当数据量小、更新频率中等（每秒几个点到几十个点）时，自绘方案足够轻量；更专业的曲线库（LiveCharts2、OxyPlot）底层也是同样的原理，只是把坐标轴、网格、缩放这些细节封装好了。

> [!essentials] 核心要点
> - **Polyline + Points**：曲线先挂到 Canvas 上，每次更新 `Points` 集合即自动重绘，不用重建图形对象
> - **坐标映射**：画布原点在左上角且 Y 轴向下，温度值要先做逆变换：`y = h - (value - min) / (max - min) * h`
> - **布局检查**：`ChartCanvas.ActualWidth < 1` 时窗口尚未布局完成，直接 return 跳过本次，避免除零/绘制到不可见区域
> - **滚动窗口**：数据点保留最近 60 个，`Count > 60` 就 `RemoveAt(0)`，曲线只显示时间窗口内的趋势
> - **仪表盘模拟**：用 `ProgressBar`（Min=0/Max=50）的 Value 表示指针位置，配合数值文本组成简易仪表

> **MainWindow.xaml.cs —— 后台代码：**
> ```csharp
> using System;
> using System.Collections.Generic;
> using System.Windows;
> using System.Windows.Media;
> using System.Windows.Shapes;
> using System.Windows.Threading;
>
> namespace HmiDemo
> {
>     public partial class MainWindow : Window
>     {
>         private readonly DispatcherTimer _timer = new DispatcherTimer();
>         private readonly List<double> _points = new List<double>();
>         private readonly Random _rand = new Random();
>         private readonly Polyline _line = new Polyline
>         {
>             Stroke = new SolidColorBrush(Color.FromRgb(0x58, 0xA6, 0xFF)),
>             StrokeThickness = 2
>         };
>
>         public MainWindow()
>         {
>             InitializeComponent();
>             ChartCanvas.Children.Add(_line); // 曲线先挂到画布上，之后只更新数据点
>             _timer.Interval = TimeSpan.FromMilliseconds(500);
>             _timer.Tick += OnTick;
>             _timer.Start();
>         }
>
>         private void OnTick(object sender, EventArgs e)
>         {
>             // 窗口尚未布局完成时 ActualWidth 为 0，先跳过本次绘制
>             if (ChartCanvas.ActualWidth < 1) return;
>
>             // 模拟采集：20~30℃ 之间随机波动
>             double temp = 20 + _rand.NextDouble() * 10;
>             _points.Add(temp);
>             if (_points.Count > 60) _points.RemoveAt(0); // 曲线窗口保留 60 个点
>
>             // 坐标映射：X 均匀分布，Y 与温度成反比（画布 Y 轴向下）
>             double w = ChartCanvas.ActualWidth, h = ChartCanvas.ActualHeight;
>             var pts = new PointCollection();
>             for (int i = 0; i < _points.Count; i++)
>             {
>                 double x = i * (w - 4) / 59.0;
>                 double y = h - 4 - (_points[i] - 15) / 40.0 * (h - 8); // 量程 15~55℃
>                 pts.Add(new Point(x, y));
>             }
>             _line.Points = pts; // 保留模式渲染：更新数据点即自动重绘曲线
>
>             GaugeText.Text = $"{temp:F1} ℃";
>             GaugeBar.Value = temp;
>             TimeText.Text = DateTime.Now.ToString("HH:mm:ss");
>         }
>     }
> }
> ```
>

> [!scene] 适用场景
> ✅ 实时趋势监控：温湿度、压力、流量等连续量的"最近 N 分钟"走势，操作工一眼判断是否异常
> ✅ 仪表盘指示：单点数值的直观呈现（温度、液位、转速），ProgressBar/弧形仪表比纯数字更有视觉反馈
> ✅ 教学演示与中小型项目：数据点几千个以内、每秒更新几十次以下，Polyline 自绘零依赖、可控性好
> ✅ 大屏看板模块：与「大屏可视化看板」配合，把曲线作为看板的一个区域
> ❌ 十万级以上大数据量回放：自绘 Points 过多会卡顿，应改用 OxyPlot/LiveCharts2 或降采样
> ❌ 需要缩放、平移、十字光标等交互分析：自绘成本高，直接用成熟图表库更划算

> [!pitfall] 常见踩坑
> 坑 1：**窗口未布局完成就绘制** → `ActualWidth/ActualHeight` 为 0，映射计算出现 NaN，曲线画不出来或异常 → 每次 Tick 开头检查 `ActualWidth < 1` 直接 return，布局完成后自然恢复
>
> 坑 2：**忘了画布 Y 轴向下** → 温度越高曲线位置越低，曲线方向"倒挂"，看着像降温 → 映射公式用 `y = h - 4 - (v - min) / (max - min) * (h - 8)` 做反转
>
> 坑 3：**Points 无限增长** → 跑一天 `_points` 有几十万点，每次重算整条曲线，界面越来越卡 → 固定时间窗口（60 点）并 `RemoveAt(0)`，或改用环形缓冲
>
> 坑 4：**量程写死不匹配数据** → 数据全超出量程时曲线变成一条贴在顶部的直线 → 量程由 `min/max` 常量集中定义，必要时根据数据自动扩展

> [!best] 最佳实践
> - 量程、窗口点数、采样间隔等参数抽成常量/配置，集中管理便于调参（如 `PointWindow = 60`）
> - 曲线、仪表、时间戳的更新放在同一个 Tick 里，保证三者数据同源、显示一致
> - 用 `PointCollection` 复用而不是每次 new：减少 GC 压力，高频更新时更流畅
> - 曲线配色沿用工控暗色主题：背景 `#161B22`、曲线强调蓝 `#58A6FF`，报警可切换为橙红
> - 数据点少于需求时要标注"模拟数据"水印，避免演示时被误认为真实测量值
> - 项目进入正式阶段、曲线需求变复杂时，及时评估迁移 OxyPlot/LiveCharts2，不要硬撑自绘

> [!practice] 上手练习
> **Lv.1 照猫画虎**：运行示例，观察曲线每 0.5 秒新增一点、60 点滚动、仪表与数字同步显示当前温度
> **Lv.2 小试牛刀**：把采样间隔改为 200ms、窗口点数改为 120，观察曲线变"密"的效果；再调整量程常量（15/55）观察坐标缩放
> **Lv.3 融会贯通**：新增一条湿度曲线（第二条 Polyline，绿色 `#238636`），与温度共用 Canvas，两条线同时滚动互不干扰
> **Lv.4 挑战**：把示例改写为 MVVM 结构：ViewModel 暴露 `ObservableCollection<Point>`，用绑定驱动 Polyline（注意绑定集合的性能），或引入 OxyPlot 在 View 层绘制真实坐标轴
