# 历史趋势与报表

> [!plain] 白话理解
> 实时画面看"现在"，历史趋势看"过去"：把每一秒采样的温度连同时间戳存进"历史库"，之后随时能回放"昨天下午 3 点温度是多少、走势如何"。报表则是把历史数据整理成可交付的产物——示例里点"生成报表"，全部采样记录就整理成 CSV 表格（时间,温度），既能展示也能存成文件发给质量部门。
> 示例的结构就是一个迷你"历史库 + 报表"：`_history`/`_times` 两个列表存数据，`DrawChart` 把历史画成折线（和「实时曲线与仪表盘」同款坐标映射，只是数据源从实时变为历史），`OnReport` 用 `StringBuilder` 拼 CSV。真实系统把内存列表换成历史数据库（如 SQLite/时序库），查询带时间段、统计聚合，但"存历史 → 画趋势 → 出报表"这条链一模一样。

> [!def] 官方定义
> **历史数据库**（Historical Database）是 SCADA/工业系统用于长期存储带时间戳的采样数据的存储层，区别于实时数据库（只存最新值）。常见选型：关系库（SQLite/SQL Server）、**时序数据库**（InfluxDB、TDengine，为时间序列优化写入与查询）。
> **趋势曲线**（Trend Chart）是按时间轴绘制的历史数据折线，用于分析走势与波动。**报表**（Report）是将数据按模板汇总成结构化文档（CSV/Excel/PDF）。示例中 `List<double> + List<DateTime>` 即最小历史库，`StringBuilder` 拼 CSV 即最小报表生成。CSV 格式见 https://tools.ietf.org/html/rfc4180

> [!origin] 由来背景
> 历史数据的价值在工业界很早就被认识到：DCS/SCADA 从 1980 年代起就把"历史趋势"作为标配功能——操作员需要回放"事故前 10 分钟参数怎么变的"来定位原因。历史数据随之从"过程记录"升级为"改进依据"：报表用于交接班、质量分析、能耗审计。
> 技术选型上，2000 年代后时序数据库兴起：InfluxDB（2013）、TDengine（2017）针对"按时间追加、按时间段聚合"优化，写读性能远超通用关系库（见「时序数据库简介」）。示例用内存列表模拟历史库，重点是讲清"采样入历史 → 趋势绘制 → 报表导出"这条业务链；接真实时序库时，只需把 `_history.Add` 换成数据库写入，把 `DrawChart` 的取数换成时间范围查询。

> [!essentials] 核心要点
> - **历史库最小模型**：`List<double>`（值）+ `List<DateTime>`（时间戳）成对存储，采样即追加
> - **趋势绘制**：历史折线与实时曲线同款坐标映射（Y 轴反向 + 量程映射），数据源换成历史列表
> - **时间戳贯穿**：每条采样记录带精确时间，趋势横轴、报表时间列都依赖它
> - **CSV 报表**：`StringBuilder` 拼 `时间,温度(℃)` 表格，`AppendLine` 逐行追加，可存文件可分发给质量部门
> - **历史只追加**：采样数据只增不删（历史库的写模型），查询走独立路径（画图/报表）

> **MainWindow.xaml.cs —— 后台代码：**
> ```csharp
> using System;
> using System.Collections.Generic;
> using System.Text;
> using System.Windows;
> using System.Windows.Media;
> using System.Windows.Shapes;
> using System.Windows.Threading;
>
> namespace HmiDemo
> {
>     public partial class MainWindow : Window
>     {
>         private readonly DispatcherTimer _timer = new DispatcherTimer();
>         private readonly Random _rand = new Random();
>         private readonly List<double> _history = new List<double>(); // 历史库
>         private readonly List<DateTime> _times = new List<DateTime>();
>
>         public MainWindow()
>         {
>             InitializeComponent();
>             _timer.Interval = TimeSpan.FromSeconds(1);
>             _timer.Tick += OnSample;
>         }
>
>         private void OnToggle(object sender, RoutedEventArgs e)
>         {
>             if (_timer.IsEnabled) { _timer.Stop(); ToggleBtn.Content = "开始采样"; }
>             else { _timer.Start(); ToggleBtn.Content = "停止采样"; }
>         }
>
>         // 每秒采样一次温度并写入"历史库"
>         private void OnSample(object sender, EventArgs e)
>         {
>             _history.Add(20 + _rand.NextDouble() * 10);
>             _times.Add(DateTime.Now);
>             HistoryList.Items.Insert(0,
>                 $"{_times[^1]:HH:mm:ss}  {_history[^1]:F1} ℃");
>             SampleText.Text = $"已采样 {_history.Count} 条";
>             DrawChart();
>         }
>
>         // 把历史数据绘制为趋势折线
>         private void DrawChart()
>         {
>             if (ChartCanvas.ActualWidth < 1 || _history.Count < 2) return;
>             ChartCanvas.Children.Clear();
>             double w = ChartCanvas.ActualWidth, h = ChartCanvas.ActualHeight;
>             var pts = new PointCollection();
>             for (int i = 0; i < _history.Count; i++)
>             {
>                 double x = i * (w - 4) / (Math.Max(_history.Count, 2) - 1);
>                 double y = h - 4 - (_history[i] - 15) / 40.0 * (h - 8);
>                 pts.Add(new Point(x, y));
>             }
>             ChartCanvas.Children.Add(new Polyline
>             {
>                 Points = pts,
>                 Stroke = new SolidColorBrush(Color.FromRgb(0x58, 0xA6, 0xFF)),
>                 StrokeThickness = 2
>             });
>         }
>
>         // 生成 CSV 报表：实际项目可写入文件或打印
>         private void OnReport(object sender, RoutedEventArgs e)
>         {
>             var sb = new StringBuilder();
>             sb.AppendLine("时间,温度(℃)");
>             for (int i = 0; i < _history.Count; i++)
>                 sb.AppendLine($"{_times[i]:yyyy-MM-dd HH:mm:ss},{_history[i]:F1}");
>             ReportText.Text = $"报表已生成：{_history.Count} 条记录（CSV 格式，可保存为文件）";
>         }
>     }
> }
> ```

> [!scene] 适用场景
> ✅ 历史趋势回放：事故/异常复盘时回放"事发前 N 分钟参数走势"，定位根因
> ✅ 交接班报表：班次产量、温度/压力统计汇总，交接班信息透明
> ✅ 质量与能耗分析：把历史数据与合格率、能耗关联分析，输出改进依据
> ✅ 长期趋势监控：工艺参数漂移（如炉温缓慢爬升）只有从历史趋势才能发现
> ❌ 只看实时画面的小工具：无历史查询需求，加历史库是多余建设
> ❌ 超大数据量（数年点位秒级存储）：单机内存/关系库扛不住，应选时序库 + 数据压缩/降采样

> [!pitfall] 常见踩坑
> 坑 1：**时间戳与值错位**（两个列表不同步添加）→ 趋势曲线时间轴对不上，报表时间乱序 → 采样时 `_history.Add(value)` 与 `_times.Add(now)` 成对执行；真实库用一条 INSERT 带时间戳保证原子
>
> 坑 2：**内存历史无限增长** → 程序跑一个月，列表几十万条，画图越来越卡、内存飙升 → 演示设上限（如最近 1000 条），真实系统落地时序库、按期归档/压缩
>
> 坑 3：**坐标映射除零/越界**（历史少于 2 条或画布未布局）→ 绘制异常或画不出 → `ActualWidth < 1` 与 `Count < 2` 提前 return；x 坐标分母用 `Math.Max(Count,2)-1` 防除零
>
> 坑 4：**报表把原始值当最终数据**（没有单位、精度、时间格式约定）→ 报表数据无法跨系统使用 → 报表字段统一格式（`yyyy-MM-dd HH:mm:ss`、`F1` 精度、带单位），CSV 遵守 RFC 4180

> [!best] 最佳实践
> - 历史数据统一"带时间戳写入、按时间范围查询"，从采样那一刻就绑定时间（`_times` 与 `_history` 同步）
> - 趋势图与实时曲线共用坐标映射工具方法，量程统一（本示例 15~55），避免两处实现漂移
> - 报表生成抽成独立方法（`BuildCsv()`），UI 只触发与显示，结果可单测、可复用
> - 历史库选型循序渐进：内存列表（教学）→ SQLite（单机持久）→ 时序库（海量），存取的抽象接口先行
> - 采样频率与需求匹配：趋势看分钟级、报表看日级，不必全部秒级入库（存量大、价值低）
> - 报表输出前校验记录非空，空历史点"生成报表"应提示"暂无数据"而非生成空表

> [!practice] 上手练习
> **Lv.1 照猫画虎**：运行示例，点"开始采样"每秒新增一条历史，趋势折线逐渐延伸，点"生成报表"看 CSV 汇总文本
> **Lv.2 小试牛刀**：给历史列表设上限（如 60 条），超限移除最旧记录，验证趋势窗口滑动而非无限增长
> **Lv.3 融会贯通**：把内存历史替换为 SQLite：`INSERT` 采样记录（时间/值），趋势与报表改为从库中按时间范围 `SELECT` 查询
> **Lv.4 挑战**：增加"时间段查询"：界面选起止时间，趋势与报表只显示该时段数据；再为报表增加统计行（平均/最大/最小温度），输出完整 CSV 并保存到文件
