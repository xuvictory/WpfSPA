# 大屏可视化看板

> [!plain] 白话理解
> 大屏看板就是车间的"中控大电视"：挂在墙上让所有人抬头就能看见今天产量多少、目标完成多少、良品率多少、几台设备在线。它的设计逻辑是"一屏看全厂"——顶上是醒目的标题，中间四张 KPI 卡片各管一项关键指标，底部再放一条产线整体状态。数字越大越醒目，颜色区分主次（蓝=产量、绿=达成/良品）。
> 看板与普通窗口最大的不同是**刷新节奏**：2 秒刷一次，宁可慢也不闪烁，因为它是给"人站着看"的，不是给"人操作"的。数据来自各设备服务的聚合（示例用随机数模拟），界面只负责把已经算好的 KPI 摆得整齐好看。掌握"大标题 + KPI 卡片 + 定时刷新"这个骨架，你就能把任何产线指标做成大屏。

> [!def] 官方定义
> **可视化看板**（Dashboard，又称管理驾驶舱）源于 1990 年代商业智能（BI）领域：将关键绩效指标（KPI）以图形化、卡片化形式集中呈现，使管理者"一屏掌握"业务状态。生产大屏是其在工业现场的形态，通常对接 MES/SCADA 数据源，定时拉取指标刷新展示。
> WPF 实现要点：`UniformGrid` 均分 KPI 卡片、`DispatcherTimer` 定时刷新、深色高对比配色保证远距离可读。大屏常见刷新周期为 1-5 秒，避免高刷造成闪烁与无谓负载。布局与网格概念见 https://learn.microsoft.com/zh-cn/dotnet/desktop/wpf/controls/panels-overview

> [!origin] 由来背景
> "把关键数据挂到墙上让大家都能看见"的管理实践，源自精益生产的**目视化管理**（Visual Management）：丰田生产方式用安灯（Andon）系统把产线异常状态亮灯公示，工人、班长、主管随时可见，问题即时暴露、即时处理。这一理念后来与商业智能结合，演变出数字化的"生产指挥中心大屏"。
> 技术上，早期大屏是"电视墙 + 组态软件"（WinCC、组态王），如今 WPF 也能轻松实现：深色背景降低光污染、高对比色远距离可读、2 秒刷新匹配"人眼扫读"节奏。本篇示例浓缩了"标题 + KPI 卡片 + 状态区"的标准大屏布局，后续 SCADA 章节的全局监控画面与之一脉相承。

> [!essentials] 核心要点
> - **一屏四卡**：今日产量/目标达成率/良品率/在线设备四张 KPI 卡均分，`UniformGrid Columns="4"` 等宽对齐
> - **定时刷新**：`DispatcherTimer` 每 2 秒更新一批 KPI，刷新节奏匹配"人站着扫读"而非"人操作"
> - **层级配色**：大标题强调蓝 `#58A6FF`、KPI 数值蓝/绿区分主次、深底 `#0D1117` 远距离可读
> - **状态区**：底部"产线运行状态"显示运行中 + 最近更新时间戳，数据停更一眼可辨
> - **数据聚合**：KPI 由各设备服务聚合而来（示例用随机数模拟），大屏本身不产数只展示

> **MainWindow.xaml.cs —— 后台代码：**
> ```csharp
> using System;
> using System.Windows;
> using System.Windows.Media;
> using System.Windows.Threading;
>
> namespace HmiDemo
> {
>     public partial class MainWindow : Window
>     {
>         private readonly DispatcherTimer _timer = new DispatcherTimer();
>         private readonly Random _rand = new Random();
>
>         public MainWindow()
>         {
>             InitializeComponent();
>             _timer.Interval = TimeSpan.FromSeconds(2); // 大屏每 2 秒刷新一批数据
>             _timer.Tick += OnRefresh;
>             _timer.Start();
>         }
>
>         // 大屏数据模拟刷新：实际项目从各设备服务聚合而来
>         private void OnRefresh(object sender, EventArgs e)
>         {
>             double output = 500 + _rand.NextDouble() * 300; // 今日产量
>             double rate = 70 + _rand.NextDouble() * 28;     // 达成率
>             double quality = 96 + _rand.NextDouble() * 4;   // 良品率
>             int online = 3 + _rand.Next(2);                 // 在线设备数
>
>             Kpi1Text.Text = $"{output:F0}";
>             Kpi2Text.Text = $"{rate:F1}%";
>             Kpi3Text.Text = $"{quality:F1}%";
>             Kpi4Text.Text = $"{online} / 4";
>             LineStateText.Text = $"运行中  ·  数据更新 {DateTime.Now:HH:mm:ss}";
>         }
>     }
> }
> ```

> [!scene] 适用场景
> ✅ 车间/中控室大屏：挂在墙上的综合监控屏，产量、质量、设备状态一屏展示，供全员目视
> ✅ 生产指挥中心：多产线 KPI 汇聚，管理层巡视与会议投屏使用
> ✅ 交接班看板：当班产量、达成率、异常项公示，交接班信息透明
> ✅ 展会/演示屏：深色大屏风格自带"科技感"，适合方案展示
> ❌ 单人操作界面：大屏只展示不操作，需要交互的功能应放回普通窗口
> ❌ 高密度信息（几十项指标）：一屏塞满反而看不清，应分级：大屏看全局、小屏看细节

> [!pitfall] 常见踩坑
> 坑 1：**刷新太快导致闪烁**（每 200ms 刷一次）→ 数字跳动让人眼花，且高频刷新无谓占用 → 大屏刷新周期 1-5 秒即可，指标本身是统计量，不需要"实时到毫秒"
>
> 坑 2：**KPI 卡片无单位/无口径**（显示"86"）→ 看的人猜不出是 86 件还是 86% → 每张卡片"标题 + 数值 + 单位"，达成率/良品率显式带 `%`
>
> 坑 3：**颜色随意用**（红绿蓝各占一半）→ 颜色失去"优先级"语义，异常不突出 → 主指标统一蓝/绿，异常/告警才用红橙，颜色是信息不是装饰
>
> 坑 4：**数据停更无提示** → 采集线程挂了，大屏还显示旧数据，现场按旧数据决策 → 状态区显示"数据更新 HH:mm:ss"，超时未更新应自动标灰/闪烁告警

> [!best] 最佳实践
> - 大屏数据走"聚合服务"：各设备服务把 KPI 汇总成 DTO，大屏只绑定展示，不直接访问采集层
> - 深色背景（`#0D1117`）+ 高对比数值（`#58A6FF`/`#238636`）是工业大屏的通用配色，远距离可读
> - 关键指标配"目标值"（如达成率目标 90%），达标绿色、未达标黄色/红色，一眼判断好坏
> - 大屏窗口固定全屏（无边框 `WindowStyle=None` + `WindowState=Maximized`），防误关误缩放
> - 刷新时间戳常驻角落，"数据停更"本身就是最重要的告警
> - 真实项目把 KPI 数据源换成「通信管理与-oee-计算」「设备管理与采集调度」的聚合结果，示例的随机数只做演示

> [!practice] 上手练习
> **Lv.1 照猫画虎**：运行示例，观察四张 KPI 卡片每 2 秒刷新、底部状态区时间戳更新
> **Lv.2 小试牛刀**：把大屏窗口改为无边框全屏（`WindowStyle="None"` + `WindowState="Maximized"`），并新增一张"设备平均稼动率"卡片（第 5 列）
> **Lv.3 融会贯通**：给达成率卡加目标判定：≥90% 绿色、<90% 橙色，并让"在线设备"低于 3 台时底部状态区变红
> **Lv.4 挑战**：把 KPI 数据源换成真实聚合：接入「设备管理与采集调度」的设备在线数、「通信管理与-oee-计算」的 OEE，用事件/接口让大屏订阅数据服务，实现"数据服务驱动大屏"
