# 串口数据采集模块

> [!plain] 白话理解
> 车间的温湿度传感器通过串口线把数据送进电脑，就像现场工人拿着对讲机汇报数据——但负责收听的"值班员"（SerialPort 的 DataReceived 事件）跑在后台线程，而显示数据的大屏（UI）必须由主线程来画。如果值班员直接上手去改大屏，程序立刻报"调用线程无法访问此对象"然后崩溃。
> 解决办法是让值班员把数据交给"传话员"——`Dispatcher.Invoke`，由它切回主线程再去刷新大屏。本篇示例为了脱离真实硬件也能演示，用 `DispatcherTimer` 每秒模拟一帧串口数据，走的是完全相同的"后台产生数据 → 切回 UI 线程 → 刷新界面"链路。理解了这个机制，接真实串口时只需把定时器换成 `SerialPort.DataReceived` 即可。

> [!def] 官方定义
> **SerialPort** 是 `System.IO.Ports` 命名空间下的类，用于控制串行端口文件资源，提供 `Open()`/`Close()`/`Write()`/`Read()` 及 `DataReceived` 事件等成员；`DataReceived` 在**辅助线程**上触发（收到数据即回调），因此不能在其中直接操作 UI。见 https://learn.microsoft.com/zh-cn/dotnet/api/system.io.ports.serialport
> **Dispatcher** 是 WPF 的线程调度器：每个 UI 线程绑定一个 Dispatcher，通过 `Invoke`/`BeginInvoke`（同步/异步）把委托调度回 UI 线程执行，解决跨线程更新 UI 的问题，这就是 WPF 的"线程亲和性"（Thread Affinity）模型。见 https://learn.microsoft.com/zh-cn/dotnet/desktop/wpf/advanced/threading-model

> [!origin] 由来背景
> 串行通信是工业自动化最古老的"语言"：RS-232 标准由 EIA 于 1962 年发布，用于计算机与调制解调器通信；到 1980 年代 RS-485 总线出现，支持多点、长距离传输，至今仍是温湿度传感器、PLC、仪表的主流物理层。SerialPort 类就是 .NET 对这套古老接口的现代封装。
> 但串口的"异步接收"与 WPF 的"UI 线程独占"存在天然矛盾：SerialPort 在数据到达时于后台线程触发 `DataReceived`，而 WPF 控件只能在创建它的线程（主线程）上更新。于是"后台收数据 → Dispatcher 切线程 → 刷新 UI"成了所有串口上位机的标准姿势。本篇把这个套路用模拟数据完整演示一遍——这也是后续 Modbus、运动控制等所有通信类项目的公共骨架。

> [!essentials] 核心要点
> - **接收线程**：`SerialPort.DataReceived` 在后台线程触发，事件里先收字节、组帧、解析，**不碰 UI**
> - **线程切换**：通过 `Dispatcher.Invoke`/`BeginInvoke` 把 UI 更新调度回主线程，避免"跨线程访问"异常
> - **模拟先行**：无硬件时用 `DispatcherTimer` 按同样节奏产生数据，把"收→切线程→刷新"链路完整跑通
> - **状态切换**：开始/停止采集按钮切换 `_timer.IsEnabled`，重复启动前先 Stop，防止事件叠加
> - **列表上限**：历史记录只保留最近 10 条（`while (Items.Count > 10) RemoveAt(10)`），防止内存无限增长

> **MainWindow.xaml.cs —— 后台代码：**
> ```csharp
> using System;
> using System.Windows;
> using System.Windows.Media;
> using System.Windows.Threading;
>
> namespace HmiDemo
> {
>     public partial class MainWindow : Window
>     {
>         private readonly DispatcherTimer _timer = new DispatcherTimer();
>         private readonly Random _rand = new Random();
>         private int _frameCount;
>
>         public MainWindow()
>         {
>             InitializeComponent();
>             _timer.Interval = TimeSpan.FromSeconds(1); // 模拟串口 1 秒一帧
>             _timer.Tick += OnDataArrived;
>         }
>
>         private void OnToggle(object sender, RoutedEventArgs e)
>         {
>             if (_timer.IsEnabled) { _timer.Stop(); StartBtn.Content = "开始采集"; }
>             else { _timer.Start(); StartBtn.Content = "停止采集"; }
>         }
>
>         // 模拟下位机上报数据：实际项目中此处为
>         // SerialPort.DataReceived → 组帧 → 校验解析 → 更新 UI
>         private void OnDataArrived(object sender, EventArgs e)
>         {
>             double temp = 20 + _rand.NextDouble() * 10; // 20~30℃
>             double hum = 40 + _rand.NextDouble() * 20;  // 40~60%RH
>             TempText.Text = $"{temp:F1} ℃";
>             HumText.Text = $"{hum:F1} %RH";
>             // 温度超过 28℃ 高亮警示，否则恢复强调蓝
>             TempText.Foreground = temp > 28
>                 ? Brushes.OrangeRed
>                 : new SolidColorBrush(Color.FromRgb(0x58, 0xA6, 0xFF));
>
>             _frameCount++;
>             FrameCountText.Text = $"已收 {_frameCount} 帧";
>             HistoryList.Items.Insert(0, $"[{DateTime.Now:HH:mm:ss}] 温度 {temp:F1}℃  湿度 {hum:F1}%RH");
>             // 只保留最近 10 条记录，防止列表无限增长
>             while (HistoryList.Items.Count > 10) HistoryList.Items.RemoveAt(10);
>         }
>     }
> }
> ```

> [!scene] 适用场景
> ✅ 接入真实串口温湿度传感器/气象站：PC 通过 USB 转串口接设备，`DataReceived` 接收、解析、刷新 UI
> ✅ 多路 RS-485 总线采集：一个串口挂多个传感器，靠站号区分设备，串口层统一收帧、业务层分路
> ✅ 无硬件环境的教学/演示：用 `DispatcherTimer` 模拟采集节奏，先把链路跑通，硬件就位后只换数据源
> ✅ 低速采集的巡检系统：每秒 1 帧级别（温度、流量、液位），串口吞吐完全够用
> ❌ 高速大批量采集（>1 万点/秒）：串口波特率上限（115200 ≈ 11.5KB/s）是瓶颈，应改用以太网/PCI 采集卡
> ❌ 单机内部数据交换：同一进程内共享内存或命名管道远比串口高效可靠

> [!pitfall] 常见踩坑
> 坑 1：**在 DataReceived 里直接改 UI** → 运行时抛 `InvalidOperationException: 调用线程无法访问此对象` → 事件里只收数据，UI 更新一律通过 `Dispatcher.Invoke` 调度到主线程
>
> 坑 2：**DataReceived 频繁触发导致 UI 卡顿** → 设备高速连发时事件几十毫秒触发一次，每次 Invoke 都排队 → 事件里先攒进缓冲区/队列，UI 端用 `DispatcherTimer` 定时批量刷新，或改用 `BeginInvoke` 且合并重复刷新
>
> 坑 3：**串口未释放/重复打开** → 设备被占用报"访问被拒绝"，或程序退出后串口仍被占用 → 关闭窗体时 `_serialPort.Close()` + `Dispose()`，打开前检查 `IsOpen`，用 `try/finally` 保证释放

> [!best] 最佳实践
> - 真实串口统一走"接收缓冲区 + 组帧解析"管道：`DataReceived` 只 `ReadExisting` 进缓冲，帧解析交给独立方法，UI 只消费解析结果
> - UI 更新用 `Dispatcher.BeginInvoke`（异步）而非 `Invoke`（同步），接收线程不等待 UI，避免背压
> - 波特率、数据位、校验位、停止位做成界面可配置项，现场设备参数不统一时不用改代码
> - 打开串口前用 `SerialPort.GetPortNames()` 列出可用端口，选择后校验端口确实存在再 Open
> - 采集与界面解耦：采集层返回"帧已解析数据"，UI 层只负责展示，为后续接入数据库、报警模块留接口

> [!practice] 上手练习
> **Lv.1 照猫画虎**：运行示例，点击"开始采集"观察每秒刷新、前 10 条记录滚动、温度 >28℃ 变橙红色高亮
> **Lv.2 小试牛刀**：给示例加上湿度上限（如 55%RH）高亮判断，参照温度逻辑用 `Brushes.OrangeRed` 切换湿度颜色
> **Lv.3 融会贯通**：把模拟数据源替换为真实 `SerialPort`：新建串口（如 COM3，115200，无校验），在 `DataReceived` 中把收到的字节当作一帧温度数据，经 `Dispatcher` 刷新 `TempText`
> **Lv.4 挑战**：在采集层引入"接收缓冲区 + 帧解析"结构：把 `ParseFrame(byte[] buffer)` 独立成类，支持粘帧/半帧（缓存跨次数据），模拟一次发两帧、半帧测试解析稳定性
