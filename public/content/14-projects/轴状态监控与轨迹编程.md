# 轴状态监控与轨迹编程

> [!plain] 白话理解
> 单轴"走到某位置"叫点位运动，多轴按一串目标点连起来走就是"轨迹"——比如点胶机沿工件的轮廓一圈走。轨迹编程要做两件事：**把点存成列表**（操作工输入 X、Y 坐标依次加入）和**让轴沿列表逐点走**（插补）。
> 示例的插补逻辑就是核心：每 50ms 计算"当前点到目标点的方向"（`dx/dist`），沿方向走一步（最多 2.5 单位），一步没走完就不停逼近；距离小于 0.5 判定到位，切换下一个点。左侧 Canvas 实时画出轨迹折线和绿色圆点（轴当前位置），像看动画一样观察轴"沿轨迹爬行"。真实控制卡的插补也是"目标点 + 定时步进"的思想，只是步长、加减速由硬件计算得又细又准。

> [!def] 官方定义
> **轨迹编程**（Trajectory Programming）指按顺序定义一系列目标点（Waypoints）并控制执行器依次到达的编程方式，是 CNC/点胶/焊接等应用的基础。**插补**（Interpolation）是控制卡在相邻目标点之间按周期计算中间位置的算法（直线插补/圆弧插补）。
> 示例用 **P2P 逐点插补**实现：`OnTick` 每 50ms 计算向量 `(dx,dy)`、距离 `dist`，步进 `step = Min(dist, 2.5)`，沿单位向量推进；`dist < 0.5` 判定到位并取下一轨迹点。画布坐标映射 `Map(p)` 把 0~100 规划坐标换算为像素坐标（Y 轴向下需取反），与「实时曲线与仪表盘」的坐标变换同源。

> [!origin] 由来背景
> 轨迹插补源自数控机床的数学基础：1950 年代 MIT 伺服机构实验室（MIT Servomechanisms Lab）为数控机床研发插补算法，用"在起点终点之间按脉冲周期计算中间点"解决"直线怎么走、圆弧怎么画"的问题；1970 年代微处理器普及后，插补器从专用硬件变成控制卡固件/软件。
> 运动控制系统由此形成分工：控制卡在硬件级以毫秒/微秒级周期做插补，上位机只需"下发轨迹点列表 + 轮询状态"。示例把插补简化成"50ms 一步"搬进上位机，用于教学演示和视觉伺服等场景；理解"目标点 → 定时步进 → 到位判定 → 下一个点"这条链，再去看控制卡 SDK 的插补指令（`gt_line`/`dmc_pmove`）就能对号入座。

> [!essentials] 核心要点
> - **轨迹点列表**：`List<Point>` 存轨迹点，输入框 `TryParse` 校验后加入并同步到 ListBox 显示
> - **逐点插补**：`OnTick` 每 50ms 计算向量与距离，`step = Min(dist, 2.5)` 限速步进，模拟连续运动
> - **到位判定**：`dist < 0.5` 判到位（对应 In-Position 阈值），到位即切下一个轨迹点，走完停止
> - **坐标映射**：规划坐标（0~100）→ 画布像素坐标，Y 轴取反（`100 - p.Y`），轨迹显示与物理方向一致
> - **实时可视化**：Polyline 画规划轨迹、绿色圆点画轴当前位置，状态文本同步坐标

> **MainWindow.xaml.cs —— 后台代码：**
> ```csharp
> using System;
> using System.Collections.Generic;
> using System.Windows;
> using System.Windows.Media;
> using System.Windows.Shapes;
> using System.Windows.Threading;
>
> namespace HmiDemo
> {
>     public partial class MainWindow : Window
>     {
>         private readonly List<Point> _trajectory = new List<Point>();
>         private readonly DispatcherTimer _timer = new DispatcherTimer();
>         private Point _axisPos; // 轴当前位置
>         private int _current;   // 正在前往的轨迹点索引
>         private bool _running;
>
>         public MainWindow()
>         {
>             InitializeComponent();
>             _timer.Interval = TimeSpan.FromMilliseconds(50);
>             _timer.Tick += OnTick;
>         }
>
>         private void OnAdd(object sender, RoutedEventArgs e)
>         {
>             if (!double.TryParse(XBox.Text, out double x) ||
>                 !double.TryParse(YBox.Text, out double y)) return;
>             _trajectory.Add(new Point(x, y));
>             PointList.Items.Add($"{x:F0}, {y:F0}");
>             DrawTrajectory();
>         }
>
>         private void OnClear(object sender, RoutedEventArgs e)
>         {
>             _trajectory.Clear();
>             PointList.Items.Clear();
>             TrackCanvas.Children.Clear();
>             _running = false; _timer.Stop();
>         }
>
>         private void OnRun(object sender, RoutedEventArgs e)
>         {
>             if (_trajectory.Count == 0) return;
>             _current = 0;
>             _running = true;
>             _timer.Start();
>         }
>
>         // 运动插补：每 50ms 朝目标点移动一步，到位后取下一个轨迹点
>         private void OnTick(object sender, EventArgs e)
>         {
>             if (!_running) return;
>             Point target = _trajectory[_current];
>             double dx = target.X - _axisPos.X, dy = target.Y - _axisPos.Y;
>             double dist = Math.Sqrt(dx * dx + dy * dy);
>             if (dist < 0.5)
>             {
>                 _current++;
>                 if (_current >= _trajectory.Count) { _timer.Stop(); _running = false; }
>                 return;
>             }
>             double step = Math.Min(dist, 2.5); // 每拍最多移动 2.5 单位
>             _axisPos = new Point(_axisPos.X + dx / dist * step, _axisPos.Y + dy / dist * step);
>             UpdateAxis();
>         }
>
>         private void UpdateAxis()
>         {
>             StatusText.Text = $"轴位置：({_axisPos.X:F0}, {_axisPos.Y:F0})";
>             DrawAxis();
>         }
>
>         // 坐标映射：0~100 规划坐标 → 画布像素坐标（画布 Y 轴向下，需取反）
>         private Point Map(Point p)
>         {
>             double w = TrackCanvas.ActualWidth - 10, h = TrackCanvas.ActualHeight - 10;
>             return new Point(5 + p.X / 100 * w, 5 + (100 - p.Y) / 100 * h);
>         }
>
>         private void DrawTrajectory()
>         {
>             TrackCanvas.Children.Clear();
>             if (_trajectory.Count < 2) return;
>             var pts = new PointCollection();
>             foreach (var p in _trajectory) pts.Add(Map(p));
>             TrackCanvas.Children.Add(new Polyline
>             {
>                 Points = pts,
>                 Stroke = new SolidColorBrush(Color.FromRgb(0x58, 0xA6, 0xFF)),
>                 StrokeThickness = 2
>             });
>         }
>
>         // 当前位置用绿色圆点标识
>         private void DrawAxis()
>         {
>             var dot = new Ellipse
>             {
>                 Width = 10, Height = 10,
>                 Fill = new SolidColorBrush(Color.FromRgb(0x23, 0x86, 0x36))
>             };
>             Canvas.SetLeft(dot, Map(_axisPos).X - 5);
>             Canvas.SetTop(dot, Map(_axisPos).Y - 5);
>             TrackCanvas.Children.Add(dot);
>         }
>     }
> }
> ```
>

> [!scene] 适用场景
> ✅ 点胶/焊接/锁螺丝轨迹：操作工用"输入点→加入列表→运行"方式示教轨迹，上位机按点执行
> ✅ 视觉引导定位：视觉测出目标坐标（见「检测逻辑与结果统计」）批量填入轨迹点，实现"看-动"联动
> ✅ 多轴联动演示与教学：无硬件用 Canvas 可视化插补过程，直观理解轨迹编程
> ✅ 工艺路径规划：走位路径（避障/顺序）先在界面上规划验证，再下发控制卡
> ❌ 高速连续运动（需要真正平滑插补、拐角过渡）：上位机 50ms 步进不够，必须用控制卡硬件插补
> ❌ 圆弧/样条等复杂轨迹：逐点直线逼近误差大，应用控制卡圆弧插补或 CAM 生成 G 代码

> [!pitfall] 常见踩坑
> 坑 1：**输入非法坐标直接进轨迹**（"abc"、负数超出行程）→ 运行后轴飞到界外或程序异常 → 添加时 `double.TryParse` 校验 + 范围检查（0~100），不合法直接 return 并提示
>
> 坑 2：**轨迹点为空就运行** → 点"运行轨迹"无反应或下标越界 → `OnRun` 开头检查 `_trajectory.Count == 0` 直接返回，按钮在无点时可置灰（IsEnabled 绑定）
>
> 坑 3：**走完轨迹后忘了清理状态**（`_current` 不回 0、定时器不停）→ 再次运行从半路开始或重复触发 → 走完在 `_current >= Count` 分支中 `_timer.Stop()` + `_running=false`；"清空轨迹"同时停止运动
>
> 坑 4：**坐标映射忘了 Y 轴反转** → 轨迹显示上下颠倒，操作工以为轴走错方向 → 映射公式 Y 轴取反（`(100 - p.Y)`），并用已知点验证映射结果

> [!best] 最佳实践
> - 轨迹点、步长、到位阈值抽成常量/配置：`StepPerTick=2.5`、`ArriveThreshold=0.5`，调参不动逻辑
> - "清空轨迹"必须同时停定时器、清状态（`_current`/`_running`），防止残留状态影响下次运行
> - 运行中禁止重复点"运行轨迹"（`_running` 时直接 return），防多重定时器叠加
> - 轨迹列表与画布同步：每增删一个点都重绘折线，操作工所见即所得
> - 位置显示保留到整数（`F0`）避免数字跳动干扰；真实系统坐标精度由脉冲当量决定
> - 接真实控制卡时，"目标点下发"与"插补执行"分离：上位机负责生成点序列，插补交给控制卡（`gt_line` 等），上位机只轮询到位状态

> [!practice] 上手练习
> **Lv.1 照猫画虎**：运行示例，依次添加 `(10,10)`、`(80,10)`、`(80,80)`、`(10,80)` 四个点并"运行轨迹"，观察绿色圆点沿折线走一圈回到起点
> **Lv.2 小试牛刀**：把步长改为 5（更快）、到位阈值改为 1.0，观察速度与到位抖动变化；给坐标输入加范围校验（0~100）
> **Lv.3 融会贯通**：增加"暂停/继续"按钮（`_timer.Stop()`/`Start()`），并在画布上标出轨迹点编号（TextBlock 或小圆点）
> **Lv.4 挑战**：把插补改为"恒定速度"（每拍位移与到目标距离无关，恒为步长）并加入加减速（前 20% 加速、后 20% 减速）；再把轨迹点列表与「运动控制卡通信」的 `IMotionCard` 对接，模拟"下发点 → 控制卡轮询回报"的真实流程
