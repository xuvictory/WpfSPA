# 检测逻辑与结果统计

> [!plain] 白话理解
> 视觉检测的逻辑很简单：相机量出一个工件的尺寸（比如 50.03mm），上位机把它和图纸上的公差带（±0.10mm）比一比——落在公差内就是 OK（合格），超出就是 NG（不合格）。然后像记考勤一样不断累计：检测了多少件、OK 多少、NG 多少、合格率多少。
> 示例模拟了这条产线节拍：每 0.5 秒"检测"一件（尺寸在标称 50.00mm 上下浮动），结果徽章亮绿（OK）或亮红（NG），下方四个统计数字实时滚动，合格率同时画成进度条。这背后是一个很现实的质量管理问题：合格率低，到底是测量有系统偏差、还是工艺真的不稳定？这些统计就是质量分析的原始依据。

> [!def] 官方定义
> **公差**（Tolerance）是机械设计中允许的尺寸偏差范围，如 Φ50±0.10mm；**判定逻辑**（Go/No-Go）把测量值与公差带比较，输出合格（OK）或不合格（NG）。**合格率**（Yield/Pass Rate）= OK 数 / 检测总数 × 100%，是产线质量的核心 KPI。
> 视觉检测上位机的职责是：接收视觉算法输出的测量结果 → 执行判定 → 累计统计 → 输出控制信号（如剔除 NG 工件）。测量误差模型上，真实测量值 = 真值 + 系统误差 + 随机误差，示例用 `(rand.NextDouble()*2-1)*0.3` 模拟随机误差，`Math.Abs(error) <= Tolerance` 即判定逻辑。

> [!origin] 由来背景
> "测量 → 判定 → 统计"是质量管理的百年老路：20 世纪初泰勒的科学管理与休哈特（Shewhart）的统计过程控制（SPC，1924 年控制图）把"合格率、公差、控制线"带入工厂；二战后全面质量管理（TQM）把质量数据作为改进依据；如今 MES 系统里"首检、巡检、终检"的判定统计一脉相承。
> 视觉检测把它自动化了：人工卡尺测量变成相机 + 算法，人工登记变成自动统计。上位机在这里的角色是"质检员 + 统计员"：拿到视觉算法（如 OpenCV、Halcon 输出）的测量值，按公差判定，累计成合格率，必要时联动剔除机构（PLC 发信号）。本篇示例浓缩了这个闭环的判定与统计部分。

> [!essentials] 核心要点
> - **判定逻辑**：测量值与标称值的偏差 `Math.Abs(error) <= Tolerance` 即 OK，公差带是唯一判据
> - **误差模拟**：`(rand.NextDouble()*2-1)*0.3` 生成 ±0.3mm 随机测量误差，与公差 ±0.10mm 对比自然产生 OK/NG 分布
> - **统计累计**：`_total/_ok/_ng` 三个计数器随每次检测递增，合格率 = OK/总数 × 100
> - **双通道反馈**：结果徽章（绿 OK / 红 NG）+ 统计数字 + 进度条，判定与趋势一屏可见
> - **节拍控制**：`DispatcherTimer` 500ms 一件模拟产线节拍，启停由按钮控制

> **MainWindow.xaml.cs —— 后台代码：**
> ```csharp
> using System;
> using System.Windows;
> using System.Windows.Media;
> using System.Windows.Threading;
>
> namespace HmiDemo
> {
>     public partial class MainWindow : Window
>     {
>         private const double Tolerance = 0.10; // 公差带 ±0.10mm
>         private readonly DispatcherTimer _timer = new DispatcherTimer();
>         private readonly Random _rand = new Random();
>         private int _total, _ok, _ng, _workNo;
>
>         public MainWindow()
>         {
>             InitializeComponent();
>             _timer.Interval = TimeSpan.FromMilliseconds(500); // 每 0.5 秒检测一件
>             _timer.Tick += OnDetect;
>         }
>
>         private void OnToggle(object sender, RoutedEventArgs e)
>         {
>             if (_timer.IsEnabled) { _timer.Stop(); StartBtn.Content = "开始自动检测"; }
>             else { _timer.Start(); StartBtn.Content = "停止检测"; }
>         }
>
>         // 检测一件工件：模拟视觉测量尺寸，与公差比较判定 OK / NG
>         private void OnDetect(object sender, EventArgs e)
>         {
>             _workNo++;
>             WorkNoText.Text = _workNo.ToString();
>
>             // 标称 50.00mm，测量误差在 ±0.3mm 内随机（含系统偏差与噪声）
>             double error = (_rand.NextDouble() * 2 - 1) * 0.3;
>             double measured = 50.00 + error;
>             SizeText.Text = $"{measured:F3} mm";
>
>             bool ok = Math.Abs(error) <= Tolerance;
>             if (ok)
>             {
>                 _ok++;
>                 SetResult("OK", Color.FromRgb(0x23, 0x86, 0x36));
>             }
>             else
>             {
>                 _ng++;
>                 SetResult("NG", Color.FromRgb(0xDA, 0x36, 0x33));
>             }
>             _total++;
>
>             TotalText.Text = _total.ToString();
>             OkText.Text = _ok.ToString();
>             NgText.Text = _ng.ToString();
>             double rate = _total > 0 ? (double)_ok / _total * 100 : 0;
>             RateText.Text = $"{rate:F1}%";
>             RateBar.Value = rate;
>         }
>
>         private void SetResult(string text, Color color)
>         {
>             ResultText.Text = text;
>             ResultBadge.Background = new SolidColorBrush(color);
>             ResultText.Foreground = Brushes.White;
>         }
>     }
> }
> ```

> [!scene] 适用场景
> ✅ 尺寸/外观在线检测：视觉算法输出测量值，上位机按公差判定 OK/NG 并统计
> ✅ 产线质量看板：合格率实时滚动展示，异常（合格率骤降）即时暴露
> ✅ 检测记录追溯：每件工件的测量值与判定结果入数据库，支持事后质量分析（SPC）
> ✅ 联动剔除：NG 计数触发 PLC 信号，自动剔除不合格品（见「modbus-通信层封装」写寄存器）
> ❌ 纯图像显示不做判定的场景：判定逻辑是多余的，只做「相机通信与图像显示」即可
> ❌ 单次抽检不统计：一次性量一下不累计，直接用 MessageBox 提示即可，不必上统计看板

> [!pitfall] 常见踩坑
> 坑 1：**判定阈值写错方向/边界**（`error < Tolerance` 漏了等号，或对偏差取绝对值前就判断）→ 临界件误判 NG 或 OK → 判定用 `Math.Abs(error) <= Tolerance`，边界值（等于公差）明确为合格并用测试用例覆盖
>
> 坑 2：**统计口径混乱**（总数、OK、NG 各自累加时机不同）→ 三数之和与总数对不上，报表无法解释 → 每次检测统一在同一个方法里 `_total++` 且只加一次 OK 或 NG，保证 `total == ok + ng`
>
> 坑 3：**误差模型不真实**（只生成纯随机，没有系统偏差）→ 演示合格率看起来"太随机"，无法模拟"工艺跑偏" → 增加系统偏差项（如 `+0.05` 恒定偏移），可演示"合格率随偏移增大而下降"的过程
>
> 坑 4：**只统计不保存** → 重启后统计清零，质量追溯没有依据 → 每次判定结果（工件号/时间/测量值/判定）写入数据库（见「需求与数据库设计」），统计从库中重算

> [!best] 最佳实践
> - 判定逻辑与统计逻辑分离成纯方法（`IsOk(measured, nominal, tol)`、`Stats.Add(result)`），便于单元测试与复用
> - 公差、标称值做成配置（不同产品不同公差），不写死在代码里
> - 判定结果三要素齐全：工件号 + 测量值 + 判定徽章，一条记录可追溯
> - 合格率同时用数字 + 进度条展示，趋势一眼可读；异常（连续 3 件 NG）可加声光提示
> - 统计结果持久化到数据库，与「历史趋势与报表」联动输出质量日报
> - 演示数据标注"模拟测量"，正式系统以视觉算法（Halcon/OpenCV）输出为数据源

> [!practice] 上手练习
> **Lv.1 照猫画虎**：运行示例，观察工件号递增、尺寸浮动、OK/NG 徽章切换、四个统计数字与合格率进度条联动
> **Lv.2 小试牛刀**：把公差改为 ±0.05mm，观察合格率明显下降；再给判定加"临界预警"（偏差 > 0.08 显示橙色"临界"）
> **Lv.3 融会贯通**：在统计中增加"连续 NG 数"，连续 3 件 NG 时状态栏红色告警并自动暂停检测
> **Lv.4 挑战**：把每次判定结果（工件号/时间/尺寸/结果）写入 SQLite 表，重启后从库恢复统计；再接入「相机通信与图像显示」的真实帧数据，用图像像素均值作为"测量值"完成图像到判定的闭环
