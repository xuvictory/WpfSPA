# 大量控件同时可见

> [!plain] 白话理解
> 监控画面要显示几万个数据点时，别一上来就"一个点一个控件"——每个控件都是要参与布局、渲染、命中测试的"正式员工"，招 2 万个"正式员工"再大的公司（UI）也扛不住。**DrawingVisual** 则是"临时工+团体签"：不用每个点都签劳动合同（创建 UIElement），而是把所有点画进一张"大图纸"（一个 `DrawingVisual`），一次性交给 UI。示例对比最直观：2000 个 `Border` 控件塞进 Canvas 要慢慢排、越加越卡；`DrawingVisual` 画 5 万个点只需一个节点、毫秒级完成。**能批量绘制的图形就别逐点建控件**，这是海量数据可视化的第一原则。

> [!def] 官方定义
> 大量控件同时可见是 WPF 性能陷阱之一：当界面中同时存在成千上万个 `UIElement`（控件）时，每个元素都要参与布局（Measure/Arrange）、渲染（Render）、命中测试（Hit Test）与输入路由，成本随数量线性甚至超线性增长，导致布局阻塞、帧率骤降。`DrawingVisual`（`System.Windows.Media` 命名空间）是解决该问题的轻量绘制原语：它本身是一个 `Visual`（不派生自 `UIElement`，无布局/输入/事件能力），通过 `RenderOpen()` 返回的 `DrawingContext` 一次绘制大量 `Drawing` 指令，再用自定义 `FrameworkElement` 宿主（重写 `VisualChildrenCount`/`GetVisualChild`，见示例 `VisualHost`）挂入可视化树。典型组合：`DrawingVisual` 批量绘制 + `Freezable.Freeze()` 冻结画刷提升共享性能。详见官方文档：[DrawingVisual 概述](https://learn.microsoft.com/zh-cn/dotnet/desktop/wpf/graphics-multimedia/drawing-visual-objects)、[Visual 对象概述](https://learn.microsoft.com/zh-cn/dotnet/desktop/wpf/graphics-multimedia/visual-layer-programming)。

> [!origin] 由来背景
> WPF 社区早期做"散点图、管线图、监控点阵"时踩过同一记闷棍：用 `Ellipse`/`Border` 逐点堆控件，几百个还行，几千个开始卡，上万个直接假死。原因不是某个控件慢，而是 `UIElement` 的"全套服务"太重——每个都要布局、渲染、命中测试。微软提供的 `DrawingVisual` 正是为此设计：它是一个轻到极致的 `Visual`，把绘制指令批量交给渲染系统，一次性完成。于是"自绘"成为海量图形可视化的标准答案：游戏地图上的元素、示波器波形、设备分布图，凡是"只看不点"的图形都该走这条路线。上位机监控图元的数量级（几千到几万）正是这套方案的主场。

> [!essentials] 核心要点
> - **UIElement 是重资产**：有布局、事件、样式、模板全套能力，代价是每个都有独立成本
> - **DrawingVisual 是轻量**：无布局/事件/命中测试，只负责"画"，一个 Visual 能承载海量绘制指令
> - **宿主三件套**：自定义 `FrameworkElement` + `VisualChildrenCount` + `GetVisualChild` 挂载（示例 `VisualHost`）
> - **RenderOpen 一次画完**：`using (var dc = visual.RenderOpen())` 批量绘制，`Freeze()` 画刷减少共享开销（示例做法）
> - **取舍**：需要交互（点击/hover）的图形仍要 UIElement，纯展示图形走 DrawingVisual，交互热点另叠加少量控件

> [!example] 完整示例
> **海量图元可视化：2000 个 UI 控件 vs DrawingVisual 一次性绘制 5 万个点：**
>
> **MainWindow.xaml：**
> ```xml
> <Window x:Class="HmiDemo.MainWindow"
>         xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
>         xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
>         Title="大量控件同时可见" Height="430" Width="560"
>         WindowStartupLocation="CenterScreen" Background="#0D1117">
>     <StackPanel Margin="15" Background="#161B22" Padding="15">
>         <TextBlock Text="海量数据可视化：控件 vs DrawingVisual"
>                    Foreground="#58A6FF" FontSize="16" FontWeight="Bold"/>
>         <Border Background="#0D1117" BorderBrush="#21262D" BorderThickness="1"
>                 Height="220" Margin="0,10,0,0">
>             <Grid>
>                 <Canvas x:Name="DrawCanvas" Background="Transparent"/>
>                 <TextBlock Text="点击下方按钮生成海量图元" Foreground="#8B949E"
>                            Margin="8" VerticalAlignment="Top"/>
>             </Grid>
>         </Border>
>         <TextBlock x:Name="ResultText" Foreground="#8B949E" Margin="0,10,0,0" TextWrapping="Wrap"/>
>         <StackPanel Orientation="Horizontal" Margin="0,10,0,0">
>             <Button Content="添加 2000 个控件（慢）" Click="OnAddControls" Padding="8"
>                     Background="#21262D" Foreground="White"/>
>             <Button Content="绘制 5 万点 DrawingVisual（快）" Click="OnDrawVisual" Padding="8" Margin="8,0,0,0"
>                     Background="#58A6FF" Foreground="White"/>
>             <Button Content="清空" Click="OnClear" Padding="8" Margin="8,0,0,0"
>                     Background="#21262D" Foreground="White"/>
>         </StackPanel>
>     </StackPanel>
> </Window>
> ```
>
> **MainWindow.xaml.cs —— 后台代码：**
> ```csharp
> using System;
> using System.Collections.Generic;
> using System.Diagnostics;
> using System.Windows;
> using System.Windows.Controls;
> using System.Windows.Media;
>
> namespace HmiDemo
> {
>     public partial class MainWindow : Window
>     {
>         private readonly VisualHost _host = new VisualHost();  // 承载 DrawingVisual 的宿主
>         private int _controlCount;
>
>         public MainWindow()
>         {
>             InitializeComponent();
>             DrawCanvas.Children.Add(_host);
>         }
>
>         // 低效做法：为每个数据点创建一个 UIElement，控件过多会拖垮布局与渲染
>         private void OnAddControls(object sender, RoutedEventArgs e)
>         {
>             var sw = Stopwatch.StartNew();
>             var rnd = new Random(42);
>             for (int i = 0; i < 2000; i++)
>             {
>                 var dot = new Border
>                 {
>                     Width = 2,
>                     Height = 2,
>                     Background = new SolidColorBrush(Color.FromRgb(0x8B, 0x94, 0x9E)),
>                     HorizontalAlignment = HorizontalAlignment.Left,
>                     VerticalAlignment = VerticalAlignment.Top,
>                     Margin = new Thickness(rnd.Next(0, (int)DrawCanvas.ActualWidth),
>                                            rnd.Next(0, (int)DrawCanvas.ActualHeight), 0, 0)
>                 };
>                 DrawCanvas.Children.Add(dot);
>             }
>             sw.Stop();
>             _controlCount += 2000;
>             ResultText.Text = $"已添加 {_controlCount} 个控件，耗时 {sw.Elapsed.TotalMilliseconds:F0} ms" +
>                               "（控件越多，布局与渲染越慢）";
>         }
>
>         // 高效做法：用 DrawingVisual 一次性绘制，不产生任何 UIElement
>         private void OnDrawVisual(object sender, RoutedEventArgs e)
>         {
>             var sw = Stopwatch.StartNew();
>             var visual = new DrawingVisual();
>             using (var dc = visual.RenderOpen())
>             {
>                 var brush = new SolidColorBrush(Color.FromRgb(0x58, 0xA6, 0xFF));
>                 brush.Freeze();   // 冻结后可跨线程共享，减少开销
>                 var rnd = new Random(42);
>                 for (int i = 0; i < 50000; i++)
>                 {
>                     var x = rnd.Next(0, (int)DrawCanvas.ActualWidth);
>                     var y = rnd.Next(0, (int)DrawCanvas.ActualHeight);
>                     dc.DrawRectangle(brush, null, new Rect(x, y, 2, 2));
>                 }
>             }
>             _host.Add(visual);
>             sw.Stop();
>             ResultText.Text = $"DrawingVisual 绘制 50000 个点，耗时 {sw.Elapsed.TotalMilliseconds:F1} ms，" +
>                               "界面只有 1 个 Visual 节点，控件数不变";
>         }
>
>         private void OnClear(object sender, RoutedEventArgs e)
>         {
>             _host.Clear();
>             _controlCount = 0;
>             ResultText.Text = "已清空";
>         }
>     }
>
>     // 自定义视觉宿主：负责把 DrawingVisual 挂进可视化树
>     internal class VisualHost : FrameworkElement
>     {
>         private readonly List<Visual> _visuals = new List<Visual>();
>
>         protected override int VisualChildrenCount => _visuals.Count;
>
>         protected override Visual GetVisualChild(int index) => _visuals[index];
>
>         public void Add(Visual v)
>         {
>             _visuals.Add(v);
>             AddVisualChild(v);
>         }
>
>         public void Clear()
>         {
>             foreach (var v in _visuals) RemoveVisualChild(v);
>             _visuals.Clear();
>         }
>     }
> }
> ```

> [!scene] 适用场景
> ✅ 设备分布图/管线图：一张画面几千个设备点位，`DrawingVisual` 批量绘制后毫秒级刷新
> ✅ 数据散点图：示波器波形、散点统计动辄几万点，逐点控件必卡（示例就是 5 万点）
> ✅ 状态点阵/报警矩阵：几百上千个状态灯，静态或低频变化时全部并入一个 DrawingVisual
> ✅ 大屏监控画面：投屏大屏图形多，自绘显著降低 UI 线程负担
> ✅ 缩略图/微型图表：小尺寸图表复用同一 DrawingVisual，多图表叠加不卡
> ❌ 需要交互的图形（点击查看详情、hover 提示），自绘丢失事件，需额外叠加交互层
> ❌ 控件数量本就不多（几百以内）且需要完整样式/模板的普通界面（直接用 UIElement）

> [!pitfall] 常见踩坑
> 坑 1：**DrawingVisual 没挂进可视化树** → 现象：绘制了但屏幕上什么都不显示 → 原因：`DrawingVisual` 本身不是 `UIElement`，不加入 `Canvas.Children` 无法显示 → 解决：用自定义 `FrameworkElement` 宿主重写 `VisualChildrenCount`/`GetVisualChild` 挂载（示例 `VisualHost`）
> 
> 坑 2：**自绘区域要交互却忘了命中测试** → 现象：画面上的图形点不动、没反应 → 原因：`DrawingVisual` 不做命中测试，也没有点击事件 → 解决：交互热点用透明 `UIElement` 叠加（一个区域一个），或对 `VisualHost` 实现 `HitTestCore`；纯展示图形才全部自绘
>
> 坑 3：**每次更新都重建整个 DrawingVisual** → 现象：数据每秒刷新 10 次，每次重绘 5 万点，依然卡 → 原因：频繁 `RenderOpen` 重建大绘图指令集本身有成本 → 解决：区分"变化区域"与"静态区域"，静态区域只建一次；变化区域用更小的 DrawingVisual 局部刷新（配合 `频繁-ui-更新节流防抖` 控制刷新频率）

> [!best] 最佳实践
> - 判断口诀：**"只看不点、量大成灾" → DrawingVisual；"要点击、要模板" → UIElement**，混合场景两套并用
> - `RenderOpen` 里用冻结画刷（示例 `brush.Freeze()`），`DrawingVisual` 大量绘制时性能收益明显
> - 静态图形一次性绘制并缓存；动态图形单独分层，避免全量重绘
> - 结合 `wpf-performance-suite` 看板验证：对比"控件方案 vs 自绘方案"的 FPS 与视觉树节点数，用数字验收
> - 超大场景（百万级点）考虑结合 `WriteableBitmap` 逐像素绘制（见 `writeablebitmap-可写入位图`），DrawingVisual 也有上限

> [!practice] 上手练习
> **Lv.1 照猫画虎**：运行示例，先点"添加 2000 个控件"观察耗时与卡顿，清空后点"绘制 5 万点"对比毫秒级速度；用 `wpf-performance-suite` 的节点统计看两者节点数差异
> **Lv.2 小试牛刀**：把示例改成"动态曲线"：用 `DispatcherTimer` 每 100ms 追加一个新数据点，重绘 `DrawingVisual`，画出一条滚动的 1 万点曲线，观察帧率（`视觉树与渲染线程` 的 FPS 方法）
> **Lv.3 融会贯通**：实现"设备分布图"：地图背景用 `Image`（`图片优化与位图缓存`），5000 个设备点位用 DrawingVisual 自绘，其中 20 个"重点设备"叠加透明 `Button` 支持点击弹窗；用 `wpf-performance-suite` 验证整体 FPS 稳定在 60，并写一份"控件 vs 自绘"对比报告
