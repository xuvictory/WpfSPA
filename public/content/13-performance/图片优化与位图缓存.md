# 图片优化与位图缓存

> [!plain] 白话理解
> 把加载图片想成"进货搬运"：一张 4000×3000 的现场照片，界面里只显示 100×80 的缩略图。**不优化**，就是把整张大图原样搬进仓库（内存）再缩小展示，光这一张就吃几十 MB；**优化**，就是在进货时直接告诉仓库"我只要 100×80 的那一小份"（`DecodePixelWidth`），搬进来的就是小尺寸位图，内存瞬间降两个数量级。示例里同一个文件，优化前后内存占用相差 10 倍以上。位图缓存则是"同一个文件只解码一次，多个地方共用一份"，配合 `Freeze()` 让渲染线程直接复用 GPU 缓存。

> [!def] 官方定义
> 位图解码优化是指通过 `BitmapImage` 的 `DecodePixelWidth`/`DecodePixelHeight` 指定解码目标尺寸，让 WPF 在解码时就按目标大小生成位图，而不是把全尺寸位图载入内存后再缩放，从而大幅降低内存占用（全尺寸位图占用 = 宽 × 高 × 4 字节，如 4000×3000 约 48 MB）。`BitmapCacheOption.OnLoad`（`CacheOption`）表示文件一次性加载进内存并立即关闭文件流；`OnDemand`（默认）延迟解码直到首次渲染。`BitmapImage` 属于 `Freezable`，`Freeze()` 后可跨线程共享并缓存渲染数据。相关 API：`BitmapImage`（`System.Windows.Media.Imaging`）、`DecodePixelWidth`、`BitmapCacheOption`、`CacheOption`。详见官方文档：[位图图像](https://learn.microsoft.com/zh-cn/dotnet/desktop/wpf/graphics-multimedia/imaging-overview)、[BitmapImage](https://learn.microsoft.com/zh-cn/dotnet/api/system.windows.media.imaging.bitmapimage)、[DecodePixelWidth](https://learn.microsoft.com/zh-cn/dotnet/api/system.windows.media.imaging.bitmapimage.depixelwidth)。

> [!origin] 由来背景
> WPF 早期开发者最常被坑的地方就是图片内存：一张手机拍的照片（4000×3000）放 `<Image>` 里显示成缩略图，任务管理器内存却多出几十 MB——因为 WPF 默认**整图解码**后再交给渲染。工业现场还常见"摄像头抓拍大图 + 列表展示缩略图"的组合，几百个缩略图就把内存吃光，程序变成"内存无底洞"。微软在 `BitmapImage` 里提供了 `DecodePixelWidth` 这个"按需解码"参数，但文档偏角落、踩坑的人多。此后"解码尺寸 = 显示尺寸"成了 WPF 图片性能的黄金法则，也是位图缓存、虚拟化列表里图片模板优化的前提。

> [!essentials] 核心要点
> - **解码即缩小**：`DecodePixelWidth` 指定解码目标宽度（高度自动等比），避免整图进内存
> - **OnLoad vs OnDemand**：`OnLoad` 立即读入内存、释放文件流（适合一次性静态图）；`OnDemand` 延迟解码（适合大量图，渲染时才解）
> - **必冻结**：`BitmapImage` 是 Freezable，`Freeze()` 后可跨线程共享 + 渲染缓存复用（见 `冻结-freezable-对象`）
> - **占位图兜底**：大图异步加载期间用占位图，`Source` 就绪后替换，避免界面空白闪烁
> - **换算公式**：内存 ≈ 宽 × 高 × 4 字节（BGRA），解码尺寸减半，内存直接降到 1/4

> [!example] 完整示例
> **图片优化：DecodePixelWidth 缩小解码 + BitmapCacheOption.OnLoad + Freeze 对比内存：**
>
> **MainWindow.xaml：**
> ```xml
> <Window x:Class="HmiDemo.MainWindow"
>         xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
>         xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
>         Title="图片优化与位图缓存" Height="380" Width="600"
>         WindowStartupLocation="CenterScreen" Background="#0D1117">
>     <Grid Margin="15" Background="#161B22" Padding="15">
>         <Grid.RowDefinitions>
>             <RowDefinition Height="Auto"/>
>             <RowDefinition Height="Auto"/>
>             <RowDefinition Height="Auto"/>
>             <RowDefinition Height="*"/>
>         </Grid.RowDefinitions>
>         <TextBlock Text="图片优化：缩小解码 + 立即加载 + 冻结" Foreground="#58A6FF" FontSize="16" FontWeight="Bold"/>
>         <StackPanel Grid.Row="1" Orientation="Horizontal" Margin="0,12,0,0">
>             <Button Content="原始方式加载（整图解码）" Click="OnLoadOriginal" Padding="8"
>                     Background="#F85149" Foreground="White"/>
>             <Button Content="优化方式加载（缩小解码）" Click="OnLoadOptimized" Padding="8" Margin="8,0,0,0"
>                     Background="#238636" Foreground="White"/>
>         </StackPanel>
>         <TextBlock x:Name="MemText" Grid.Row="2" Foreground="#8B949E" Margin="0,12,0,0" TextWrapping="Wrap"/>
>         <Border Grid.Row="3" Margin="0,12,0,0" BorderBrush="#21262D" BorderThickness="1">
>             <Image x:Name="Img" Stretch="Uniform" Margin="8" HorizontalAlignment="Center" VerticalAlignment="Center"/>
>         </Border>
>     </Grid>
> </Window>
> ```
>
> **MainWindow.xaml.cs —— 后台代码：**
> ```csharp
> using System.Diagnostics;
> using System.IO;
> using System.Windows;
> using System.Windows.Media.Imaging;
>
> namespace HmiDemo
> {
>     public partial class MainWindow : Window
>     {
>         private readonly string _imagePath =
>             Path.Combine(AppDomain.CurrentDomain.BaseDirectory, "sample_photo.jpg");
>
>         public MainWindow()
>         {
>             InitializeComponent();
>             GenerateSampleImage();   // 生成一张 4000x3000 的示例大图
>         }
>
>         // 原始方式：整图解码，一张 4000x3000 的图占约 48MB 内存
>         private void OnLoadOriginal(object sender, RoutedEventArgs e)
>         {
>             var bmp = new BitmapImage();
>             bmp.BeginInit();
>             bmp.UriSource = new Uri(_imagePath);
>             bmp.CacheOption = BitmapCacheOption.OnDemand;   // 默认：整图延迟解码
>             bmp.EndInit();
>             Img.Source = bmp;
>             Report($"原始方式：整图 4000x3000 解码，内存 {Process.GetCurrentProcess().WorkingSet64 / 1024d / 1024d:F1} MB");
>         }
>
>         // 优化方式：缩小解码到 300px + OnLoad 立即释放文件 + 冻结共享
>         private void OnLoadOptimized(object sender, RoutedEventArgs e)
>         {
>             var bmp = new BitmapImage();
>             bmp.BeginInit();
>             bmp.UriSource = new Uri(_imagePath);
>             bmp.DecodePixelWidth = 300;                     // 关键：按显示尺寸解码
>             bmp.CacheOption = BitmapCacheOption.OnLoad;     // 立即读入内存，关闭文件流
>             bmp.EndInit();
>             bmp.Freeze();                                   // 冻结：跨线程共享 + 缓存复用
>             Img.Source = bmp;
>             Report($"优化方式：解码到 300px 宽，内存 {Process.GetCurrentProcess().WorkingSet64 / 1024d / 1024d:F1} MB");
>         }
>
>         private void Report(string msg) => MemText.Text = msg;
>
>         // 生成一张示例大图（真实项目中是相机抓拍图或现场照片）
>         private void GenerateSampleImage()
>         {
>             if (File.Exists(_imagePath)) return;
>             var bmp = new System.Drawing.Bitmap(4000, 3000);
>             using (var g = System.Drawing.Graphics.FromImage(bmp))
>             {
>                 g.Clear(System.Drawing.Color.SteelBlue);
>                 g.DrawString("Sample Photo", new System.Drawing.Font("Arial", 120),
>                     System.Drawing.Brushes.White, 100, 100);
>             }
>             bmp.Save(_imagePath);
>         }
>     }
> }
> ```

> [!scene] 适用场景
> ✅ 抓拍图片列表：相机每小时抓拍一张现场大图，列表页要展示几百个缩略图，缩小解码后内存从几 GB 降到几十 MB
> ✅ 产品/设备图片管理：图片库动辄上千张原始照片，列表模板里 `DecodePixelWidth=200` 是标配
> ✅ 日志图片回放：巡检记录图片按时间回放，`OnLoad` 立即加载让翻页无延迟
> ✅ 大图预览：点击缩略图后查看原图，预览时才按全尺寸解码，平时只保留小图
> ✅ 多页面共享同一图片：同一个 Logo/背景图用冻结位图，多处 `Image` 共用一份缓存
> ❌ 需要原图编辑的流程（编辑前必须全尺寸位图，缩小解码会丢信息）
> ❌ 图片本身就小的场景（小于 200px 的图标，优化收益微乎其微）

> [!pitfall] 常见踩坑
> 坑 1：**整图解码后内存爆炸** → 现象：加载几张相机大图，进程内存涨到几百 MB，界面变卡 → 原因：`DecodePixelWidth` 未设置，4000×3000 的图按 48 MB/张整图进内存 → 解决：按显示尺寸设置 `DecodePixelWidth`（示例优化分支），列表场景配虚拟化
> 
> 坑 2：**OnDemand 导致文件句柄不释放** → 现象：删除/覆盖图片文件时提示"文件被占用" → 原因：`OnDemand`（默认）延迟解码，文件流保持打开 → 解决：静态图用 `CacheOption = BitmapCacheOption.OnLoad`（示例），用完即释放文件流
>
> 坑 3：**反复加载同一图片造成内存重复** → 现象：切换页面、滚动列表后内存持续上涨 → 原因：每次新建 `BitmapImage`，同一文件被反复解码，且未冻结无法复用 → 解决：缓存已解码的冻结位图（字典按路径缓存），命中直接复用；`Image` 卸载时置空 `Source` 释放引用

> [!best] 最佳实践
> - 铁律：**解码尺寸 = 显示尺寸**，列表缩略图 `DecodePixelWidth` 设成模板高度即可（示例 300px）
> - 图片较多时统一走"图片缓存服务"：`ConcurrentDictionary<string, BitmapImage>` 按路径缓存冻结位图
> - 静态大图用 `OnLoad` + `Freeze()`，动态/大量图用 `OnDemand` 结合虚拟化（见 `ui-虚拟化`）
> - 异步加载大图：后台解码完成后 `Dispatcher` 赋值，避免主线程卡顿（见 `异步绑定与延迟`）
> - 用进程内存做对比验证（示例 `Report`），把"优化前后内存数字"写进代码评审

> [!practice] 上手练习
> **Lv.1 照猫画虎**：运行示例，分别点两个按钮，观察 `MemText` 的内存数字差异；把 `DecodePixelWidth` 改成 50/800 再看内存变化
> **Lv.2 小试牛刀**：给示例加一个 `Button`："加载 100 张缩略图"：用循环 `DecodePixelWidth=100` 加载同一张图生成 100 个 `Image`，对比不设 `DecodePixelWidth` 时的内存
> **Lv.3 融会贯通**：实现图片缓存服务：`Dictionary<string, BitmapImage>` 缓存冻结位图，供多个页面共用；再结合 `异步绑定与延迟` 做一个"先占位、后异步加载缩略图"的设备照片列表页
