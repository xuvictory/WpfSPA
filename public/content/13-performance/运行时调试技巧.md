# 运行时调试技巧

> [!plain] 白话理解
> 程序发布到现场后没有调试器，出问题全靠"事后诸葛亮"——所以要把"诊断能力"提前装进程序里。**运行时调试**就是在程序里内置一套"黑匣子 + 仪表盘"：`Debug.WriteLine` 把关键事件写进日志（黑匣子），`DispatcherTimer` 定时收集 `GC.GetTotalMemory`、线程数、CPU 时间显示在状态栏（仪表盘），按钮一按就能导出诊断快照。示例就是一个运行时监控面板：运行时长、线程数、托管内存、CPU 时间全部实时跳动，任何时刻都能"瞄一眼就知道程序健不健康"。这就是上位机"现场可诊断"的最小落地。

> [!def] 官方定义
> 运行时调试（Runtime Debugging）指在程序运行期间（尤其是无调试器的生产环境）通过内置诊断手段观测与定位问题。常用手段：①**日志输出**：`System.Diagnostics.Debug.WriteLine`（仅 Debug 构建有效）/ `Trace.WriteLine`（Release 也有效，可挂 TraceListener）；②**运行时状态监控**：`DispatcherTimer` 定时读取 `Process.GetCurrentProcess()`（`WorkingSet64`、`TotalProcessorTime`、`Threads.Count`）与 `GC.GetTotalMemory` 刷新到界面/日志；③**诊断快照**：一键汇总内存、线程、时间等状态导出为文本（示例 `DumpDiagnostics`）；④**异常兜底**：`AppDomain.CurrentDomain.UnhandledException` 捕获全局异常写日志。成熟方案可接 NLog/Serilog（见 `nlog-与-log4net`、`serilog-结构化日志`）。核心 API：`Trace`、`Debug`、`Process`、`GC`、`DispatcherTimer`。详见官方文档：[Trace 与 Debug](https://learn.microsoft.com/zh-cn/dotnet/framework/debug-trace-profile/how-to-create-and-initialize-trace-sources)、[Process 类](https://learn.microsoft.com/zh-cn/dotnet/api/system.diagnostics.process)、[GC.GetTotalMemory](https://learn.microsoft.com/zh-cn/dotnet/api/system.gc.gettotalmemory)。

> [!origin] 由来背景
> 上位机程序部署到工控机上，故障往往是"运行了 3 天，半夜崩了"——现场没有 VS 调试器，复现成本极高。早年只能靠"出事后来回试"，效率极低。软件工程因此沉淀出"可观测性"思想：程序自己带上日志与状态指标，故障时先看日志/指标再判断。.NET 从 1.0 起就有 `Debug`/`Trace` 输出能力，`Process` 类提供了进程级指标读取；配合 `DispatcherTimer` 定时采样，一个轻量"运行时监控面板"十几行代码就能搭出来。对 WPF 上位机而言，把"诊断仪表盘 + 日志"内置于发布版，是从"黑盒"走向"可观测"的关键一步，也是售后问题处理效率的分水岭。

> [!essentials] 核心要点
> - **Debug vs Trace**：`Debug.WriteLine` 仅 Debug 构建输出（发布版静默）；`Trace.WriteLine` 在所有构建生效，配 `TextWriterTraceListener` 可写文件
> - **进程指标三件套**：`WorkingSet64`（内存）、`TotalProcessorTime`（CPU 时间）、`Threads.Count`（线程数），`Process.GetCurrentProcess()` 一次取全（示例 `RefreshMetrics`）
> - **定时采样**：`DispatcherTimer` 每秒刷新一次监控面板，长期观察趋势（示例 `_timer`）
> - **快照导出**：一键把所有状态汇总为文本（示例 `DumpDiagnostics`），发售后截图/日志即诊断依据
> - **全局异常兜底**：`AppDomain.UnhandledException` 捕获未处理异常，写日志后提示用户，别让崩溃"无声无息"

> [!example] 完整示例
> **运行时状态监控面板：Debug 输出 + 实时进程指标 + 一键诊断快照：**
>
> **MainWindow.xaml：**
> ```xml
> <Window x:Class="HmiDemo.MainWindow"
>         xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
>         xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
>         Title="运行时调试技巧" Height="380" Width="540"
>         WindowStartupLocation="CenterScreen" Background="#0D1117">
>     <StackPanel Margin="15" Background="#161B22" Padding="15">
>         <TextBlock Text="运行时状态监控面板（Debug 输出 + 实时指标 + 快照导出）"
>                    Foreground="#58A6FF" FontSize="16" FontWeight="Bold"/>
>         <TextBlock x:Name="UptimeText" Foreground="#8B949E" Margin="0,12,0,0"/>
>         <TextBlock x:Name="ThreadText" Foreground="#8B949E" Margin="0,6,0,0"/>
>         <TextBlock x:Name="MemText" Foreground="#8B949E" Margin="0,6,0,0"/>
>         <TextBlock x:Name="CpuText" Foreground="#8B949E" Margin="0,6,0,0"/>
>         <StackPanel Orientation="Horizontal" Margin="0,14,0,0">
>             <Button Content="导出诊断快照" Click="OnDump" Padding="8"
>                     Background="#21262D" Foreground="White"/>
>             <Button Content="写入 Debug 日志" Click="OnWriteDebug" Padding="8" Margin="8,0,0,0"
>                     Background="#21262D" Foreground="White"/>
>         </StackPanel>
>         <TextBlock x:Name="SnapshotText" Foreground="#238636" Margin="0,12,0,0" TextWrapping="Wrap"/>
>     </StackPanel>
> </Window>
> ```
>
> **MainWindow.xaml.cs —— 后台代码：**
> ```csharp
> using System;
> using System.Diagnostics;
> using System.IO;
> using System.Windows;
> using System.Windows.Threading;
>
> namespace HmiDemo
> {
>     public partial class MainWindow : Window
>     {
>         private readonly Stopwatch _sw = Stopwatch.StartNew();
>         private readonly DispatcherTimer _timer;
>
>         public MainWindow()
>         {
>             InitializeComponent();
>             // 每秒刷新一次运行时监控面板
>             _timer = new DispatcherTimer { Interval = TimeSpan.FromSeconds(1) };
>             _timer.Tick += (s, e) => RefreshMetrics();
>             _timer.Start();
>             RefreshMetrics();
>             // 全局异常兜底：未处理异常写日志
>             AppDomain.CurrentDomain.UnhandledException += (s, e) =>
>                 Trace.WriteLine($"[FATAL] {e.ExceptionObject}");
>         }
>
>         private void RefreshMetrics()
>         {
>             var p = Process.GetCurrentProcess();
>             UptimeText.Text = $"运行时长：{_sw.Elapsed.TotalSeconds:F0} 秒";
>             ThreadText.Text = $"进程线程数：{p.Threads.Count}";
>             MemText.Text = $"托管内存：{GC.GetTotalMemory(false) / 1024 / 1024:F1} MB；" +
>                            $"工作集：{p.WorkingSet64 / 1024 / 1024:F1} MB";
>             CpuText.Text = $"CPU 时间：{p.TotalProcessorTime.TotalSeconds:F1} 秒";
>         }
>
>         // 一键导出诊断快照：发售后用户截图/保存即可作为诊断依据
>         private void OnDump(object sender, RoutedEventArgs e)
>         {
>             var p = Process.GetCurrentProcess();
>             var snapshot =
>                 $"=== 诊断快照 {DateTime.Now:yyyy-MM-dd HH:mm:ss} ===\n" +
>                 $"运行时长: {_sw.Elapsed.TotalSeconds:F0} 秒\n" +
>                 $"线程数: {p.Threads.Count}\n" +
>                 $"托管内存: {GC.GetTotalMemory(false) / 1024 / 1024:F1} MB\n" +
>                 $"工作集: {p.WorkingSet64 / 1024 / 1024:F1} MB\n" +
>                 $"CPU 时间: {p.TotalProcessorTime.TotalSeconds:F1} 秒\n" +
>                 $"GC 次数(0代): {GC.CollectionCount(0)}";
>             SnapshotText.Text = snapshot;
>             Trace.WriteLine("[SNAPSHOT] " + snapshot.Replace("\n", " | "));
>         }
>
>         private void OnWriteDebug(object sender, RoutedEventArgs e)
>         {
>             // Debug 构建下输出到输出窗口；Release 下无输出（可用 Trace 替代）
>             Debug.WriteLine($"[DEBUG] 按钮被点击，当前内存 {GC.GetTotalMemory(false) / 1024 / 1024:F1} MB");
>             Trace.WriteLine($"[TRACE] 按钮被点击（Trace 在所有构建下有效）");
>         }
>     }
> }
> ```

> [!scene] 适用场景
> ✅ 现场故障回溯：程序运行几天后异常，日志 + 快照提供"事发时状态"，不用现场复现
> ✅ 内存趋势监控：监控面板每秒刷 `GC.GetTotalMemory`，内存缓慢上涨时一眼看出异常（配合 `内存分析工具`）
> ✅ 线程数异常：`Threads.Count` 持续增长说明线程泄漏，面板直接暴露
> ✅ 发布版问题反馈：用户点"导出诊断快照"发回图片，售后不用猜
> ✅ 长时间无人值守：配合日志文件，程序自我记录运行轨迹
> ❌ 需要交互式断点调试的复杂逻辑（开发期用 VS 调试器，见 `visual-studio-诊断工具`）
> ❌ 与性能分析无直接关系的问题（性能定位用探查器，运行时面板只做"态势监控"）

> [!pitfall] 常见踩坑
> 坑 1：**Debug.WriteLine 在发布版失效** → 现象：Release 跑起来日志什么都没有 → 原因：`Debug` 类在 Release 构建下被剥离 → 解决：需要发布版日志用 `Trace.WriteLine` + `TextWriterTraceListener` 写文件（示例 `OnWriteDebug` 展示了 Debug/Trace 差异）
> 
> 坑 2：**监控面板自己拖慢程序** → 现象：开了监控后界面卡顿 → 原因：每 100ms 刷新一次文本 + 反复取进程指标有开销 → 解决：刷新间隔 1 秒足够（示例），指标读取放在 UI 线程但内容极轻量；发布版默认关闭面板
>
> 坑 3：**快照只存界面不落盘** → 现象：用户重启程序后诊断信息全丢 → 原因：快照只显示在 TextBlock，没有写文件 → 解决：快照同时用 `Trace.WriteLine`/`File.WriteAllText` 落盘（示例 `OnDump` 已写 Trace），日志文件放 `AppData` 或程序目录

> [!best] 最佳实践
> - 日志用 `Trace`（Release 也生效）并挂 `TextWriterTraceListener` 落盘，`Debug` 只用于开发期细粒度输出（示例分工）
> - 监控面板做成可开关组件：默认关闭、快捷键（如 F12）唤起，避免发布版常驻开销
> - 快照与日志都要落盘：路径用 `Environment.SpecialFolder.LocalApplicationData` + 程序名，售后按目录找
> - 全局异常兜底 + 日志：`AppDomain.UnhandledException` 记录 `[FATAL]` 并提示用户，崩溃不再无声
> - 与日志框架结合：规模大了换 NLog/Serilog（见 `nlog-与-log4net`、`serilog-结构化日志`），本例是轻量起点

> [!practice] 上手练习
> **Lv.1 照猫画虎**：F5 运行示例，观察四个指标每秒刷新；点"导出诊断快照"看面板与输出窗口的 Trace 日志；点"写入 Debug 日志"对比 Debug 与 Trace 在输出窗口的表现
> **Lv.2 小试牛刀**：把快照功能扩展为"落盘"：点按钮把快照写入 `AppData` 下的 `diagnostics.txt`；给程序加"内存压力按钮"（分配 50MB 数组）观察 `托管内存` 读数变化与快照差异
> **Lv.3 融会贯通**：把监控面板做成全局工具类 `RuntimeMonitor`：提供 `Start(Window)`、`DumpToFile()`、全局异常钩子；在你的项目里挂上它，跑 1 小时后导出快照，分析线程数、内存趋势，结合 `内存分析工具` 定位并修复发现的问题
