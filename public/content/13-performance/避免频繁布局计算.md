# 避免频繁布局计算

> [!plain] 白话理解
> 布局计算就是 WPF 在每次界面变化后"重新量一遍所有控件位置尺寸"的流程：控件大小变了、位置变了、新增删除了，都要整套重算。把它想成搬办公室——只有真的换了桌子才值得全楼重新画工位图。**频繁布局**的典型错误是：数据每刷新一次就触发一次全楼重画。示例里的对比最直观：实时温度数字用 `Text` 属性更新，只改文字内容，走的是渲染路径，500 次更新毫无压力；如果手贱把数字塞进 `Width`（改变布局属性），每次都要重新布局，界面卡到飞起。**更新内容用 Text/属性，别用尺寸/位置**，就是本节的精髓。

> [!def] 官方定义
> 布局（Layout）是 WPF 中由 `LayoutManager`（`System.Windows` 内部）驱动的两阶段过程：`Measure`（测量：确定每个元素期望尺寸）与 `Arrange`（排列：确定最终位置与尺寸）。当元素的布局相关属性（`Width`、`Height`、`Margin`、`DockPanel.Dock`、`Visibility` 等）发生变化时，会触发 `InvalidateMeasure`/`InvalidateArrange`，导致整棵受影响子树的布局重算。渲染属性（如 `TextBlock.Text`、`Brush.Color`）变化只走渲染路径，不触发布局。高频数据更新时若更新的是布局属性，会造成"数据每秒刷新 N 次 → 布局重算 N 次"的性能放大。核心事件：`FrameworkElement.LayoutUpdated`（每次布局周期后触发）；`Dispatcher` 的 `DispatcherPriority.Render` 是布局完成后到渲染前的时机。详见官方文档：[布局系统](https://learn.microsoft.com/zh-cn/dotnet/desktop/wpf/advanced/layout)、[FrameworkElement.LayoutUpdated](https://learn.microsoft.com/zh-cn/dotnet/api/system.windows.frameworkelement.layoutupdated)。

> [!origin] 由来背景
> WPF 诞生后，很多从 WinForms 转来的开发者延续"刷新就是改属性"的习惯：数据一变就更新控件的 `Width`/`Height`/位置，结果发现比 WinForms 卡得多。原因在于 WPF 的布局系统是"级联重算"——一个元素的尺寸变化会向上冒泡（`Arrange` 后父级可能也要重排），配合高频数据更新就成倍放大。官方性能文档专门把"更新高频属性不要触发布局"列为重点：尽量更新 `Text`、`Color` 这类只走渲染的属性，尺寸/位置类属性留给真正的结构性变化。理解 `LayoutUpdated` 的触发频率，也是诊断"为什么我的界面卡"的关键一步。

> [!essentials] 核心要点
> - **两类属性**：布局属性（`Width`/`Height`/`Margin`/`Visibility`）触发重算；渲染属性（`Text`/`Color`/`Opacity`）只重绘不重排
> - **级联放大**：一个元素尺寸变化可能引发父级、兄弟、甚至整棵子树重排，成本随树规模上升
> - **LayoutUpdated**：每次布局周期后触发，频率高，适合"布局完成后做什么"，不适合重活
> - **高频更新原则**：实时数值用 `Text` 更新，别改 `Width`/`Height`；变化的位置用 `TranslateTransform`（渲染层变换）而非改 `Margin`
> - **合并刷新**：同一时刻的多处变化尽量合并到一次布局周期（用 `DispatcherPriority.Render` 或节流，见 `频繁-ui-更新节流防抖`）

> [!example] 完整示例
> **布局计算优化：实时温度监控改 Text（渲染）vs 改 Width（布局）对比：**
>
> **MainWindow.xaml：**
> ```xml
> <Window x:Class="HmiDemo.MainWindow"
>         xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
>         xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
>         Title="避免频繁布局计算" Height="360" Width="560"
>         WindowStartupLocation="CenterScreen" Background="#0D1117">
>     <Grid Margin="15" Background="#161B22" Padding="15">
>         <Grid.RowDefinitions>
>             <RowDefinition Height="Auto"/>
>             <RowDefinition Height="Auto"/>
>             <RowDefinition Height="Auto"/>
>             <RowDefinition Height="*"/>
>         </Grid.RowDefinitions>
>         <TextBlock Text="避免频繁布局计算：Text 更新 vs Width 更新"
>                    Foreground="#58A6FF" FontSize="16" FontWeight="Bold"/>
>         <StackPanel Grid.Row="1" Orientation="Horizontal" Margin="0,12,0,0">
>             <Button Content="Text 方式更新（渲染）" Click="OnUpdateByText" Padding="8"
>                     Background="#238636" Foreground="White"/>
>             <Button Content="Width 方式更新（布局）" Click="OnUpdateByWidth" Padding="8" Margin="8,0,0,0"
>                     Background="#F85149" Foreground="White"/>
>         </StackPanel>
>         <TextBlock x:Name="TempText" Grid.Row="2" Foreground="#8B949E" Margin="0,12,0,0" TextWrapping="Wrap"/>
>         <!-- 模拟温度计：用 Text 更新数值，用 Width 模拟柱状条 -->
>         <Grid Grid.Row="3" Margin="0,12,0,0">
>             <Grid.RowDefinitions>
>                 <RowDefinition Height="Auto"/>
>                 <RowDefinition Height="*"/>
>             </Grid.RowDefinitions>
>             <TextBlock x:Name="ValueText" Grid.Row="0" Foreground="#58A6FF" FontSize="26"
>                        HorizontalAlignment="Center" Text="25.0 °C"/>
>             <Border Grid.Row="1" Margin="0,8,0,0" Background="#0D1117" BorderBrush="#21262D" BorderThickness="1">
>                 <Grid>
>                     <Rectangle x:Name="BarRect" Height="18" Fill="#238636" HorizontalAlignment="Left" Width="50"/>
>                     <TextBlock Text="柱状条（Width 触发布局）" Foreground="#484F58" Margin="8,0,0,0"/>
>                 </Grid>
>             </Border>
>         </Grid>
>     </Grid>
> </Window>
> ```
>
> **MainWindow.xaml.cs —— 后台代码：**
> ```csharp
> using System;
> using System.Diagnostics;
> using System.Windows;
> using System.Windows.Threading;
>
> namespace HmiDemo
> {
>     public partial class MainWindow : Window
>     {
>         private readonly Random _rnd = new Random();
>         private DispatcherTimer _timer;
>         private bool _useTextMode;
>
>         public MainWindow() => InitializeComponent();
>
>         // Text 方式：只改文字内容，走渲染路径，不触发布局重算
>         private void OnUpdateByText(object sender, RoutedEventArgs e)
>         {
>             _useTextMode = true;
>             StartStress();
>         }
>
>         // Width 方式：修改控件尺寸，每次触发整棵子树布局重算
>         private void OnUpdateByWidth(object sender, RoutedEventArgs e)
>         {
>             _useTextMode = false;
>             StartStress();
>         }
>
>         private void StartStress()
>         {
>             var sw = Stopwatch.StartNew();
>             _timer?.Stop();
>             _timer = new DispatcherTimer { Interval = TimeSpan.FromMilliseconds(16) };
>             _timer.Tick += (s, e) =>
>             {
>                 double value = 20 + _rnd.NextDouble() * 10;   // 模拟 20~30°C 实时温度
>                 if (_useTextMode)
>                 {
>                     ValueText.Text = $"{value:F1} °C";        // 渲染路径：轻量
>                 }
>                 else
>                 {
>                     BarRect.Width = 50 + value * 5;           // 布局路径：触发重算
>                 }
>                 TempText.Text = $"{(_useTextMode ? "Text 方式" : "Width 方式")}，" +
>                                 $"已运行 {sw.Elapsed.TotalSeconds:F1} 秒";
>             };
>             _timer.Start();
>         }
>     }
> }
> ```

> [!scene] 适用场景
> ✅ 实时温度/压力/流量显示：每秒刷新 10~50 次数值，用 `Text` 更新毫无压力，改 `Width` 就会卡
> ✅ 状态指示动画：进度条、液位柱变化用 `Width` 是合理需求，但要控制频率（如 10Hz 以内）并考虑渲染层变换
> ✅ 监控画面元素移动：设备标记位置变化用 `TranslateTransform` 平移（渲染层），不要改 `Margin`/`Canvas.Left`
> ✅ 高频报警闪烁：报警状态切换用 `Visibility` 会触发布局，改用 `Opacity`（渲染层）闪烁更平滑
> ✅ 数据刷新与 UI 刷新解耦：采集线程 1000 条/秒，UI 只按 10Hz 合并刷新（见 `频繁-ui-更新节流防抖`）
> ❌ 低频交互（按钮点击后改一次尺寸）：布局开销可以忽略，不必过度优化
> ❌ 需要真实参与布局的动画（如 Grid 列宽动画），此时布局重算是业务需要

> [!pitfall] 常见踩坑
> 坑 1：**高频更新布局属性** → 现象：温度/转速数值界面卡顿，CPU 飙高 → 原因：每秒几十次改 `Width` 导致整棵子树反复 Measure/Arrange → 解决：数值用 `Text` 更新（示例 Text 分支），柱状动画控制频率或用渲染层变换
> 
> 坑 2：**Visibility 频繁切换** → 现象：报警闪烁时整个区域闪烁、卡顿 → 原因：`Visibility` 切换触发布局重算（Collapsed 元素从布局中移除）→ 解决：闪烁用 `Opacity` 动画，或 `Visibility` 切换控制在低频（≥100ms）
>
> 坑 3：**在 LayoutUpdated 里做重活** → 现象：每次布局都卡一下，布局越多越卡 → 原因：`LayoutUpdated` 每次布局周期都触发，事件里放重逻辑等于每帧都执行 → 解决：`LayoutUpdated` 只做轻量检测（如记录布局次数），重活移到 `DispatcherTimer` 或节流回调中

> [!best] 最佳实践
> - 实时数值一律 `Text`/`Content` 更新；要动位置的用 `TranslateTransform`、`RotateTransform`（渲染层变换）
> - 布局属性更新做节流：`DispatcherTimer` 至少 10Hz 以内，配合 `频繁-ui-更新节流防抖` 的合并策略
> - 动画用 WPF 动画系统（`DoubleAnimation`）而非手动改属性，动画系统内部已做优化调度
> - 用 `LayoutUpdated` 计数器量化"布局频率"：优化前后对比次数，用数据说话
> - 大列表/大树的页面优先保证结构稳定：不要频繁增删节点（触发整树重排），用 `ObservableCollection` 的批量更新（见 `ui-虚拟化`）

> [!practice] 上手练习
> **Lv.1 照猫画虎**：运行示例，分别点两个按钮运行 10 秒，对比流畅度；把 `BarRect.Width` 更新改为 `TranslateTransform` 平移一个 10px 宽的方块模拟液位，感受渲染层变换的顺滑
> **Lv.2 小试牛刀**：给示例加一个 `LayoutUpdated` 计数器（每秒打印布局次数），对比 Text 方式与 Width 方式下布局次数的数量级差异
> **Lv.3 融会贯通**：实现一个"设备状态大屏"：温度、压力、转速多个数值每秒刷新 20 次全部用 Text；报警灯闪烁用 `Opacity` 动画；设备标记移动用 `TranslateTransform`；最后用 `视觉树与渲染线程` 的 FPS 工具验证优化前后帧率
