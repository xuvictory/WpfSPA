# 弱事件模式

> [!plain] 白话理解
> 普通事件订阅（`+=`）是"强捆绑"：事件源死死攥着订阅者，攥住就不撒手，哪怕订阅者已经下班了（不再需要），也会被一直拽着不回收——这就是泄漏。**弱事件模式**是"柔性连接"：事件源只轻轻搭着订阅者（弱引用），订阅者一旦没有别处引用、该下班了，就能随时走人（被 GC 回收）。示例里用 `WeakEventManager` 给报警中心订阅者"松绑"，点"强制 GC"后你能亲眼看到订阅对象被回收——而如果换成普通 `+=`，它就会一直赖在内存里。

> [!def] 官方定义
> 弱事件模式（Weak Event Pattern）是 WPF 为"事件源生命周期长于订阅者"场景设计的标准方案：通过 `WeakEventManager`（`System.Windows` 命名空间）代理事件订阅，使事件源仅持有订阅者的**弱引用**（`WeakReference`），从而在不阻止订阅者被 GC 回收的前提下继续传递事件。.NET 4.5+ 提供了泛型版本 `WeakEventManager<TEventSource, TEventArgs>`，可直接 `AddHandler`/`RemoveHandler` 订阅。事件源需满足：事件类型为 `EventHandler`/`EventHandler<T>` 且事件名为 "EventName" 形式。非 WPF 场景也有通用弱事件库（如 Prism 的 `WeakEventHandler`）。核心机制：事件源 → WeakEventManager（持弱引用）→ 订阅者，事件触发时由管理器检查订阅者是否存活，存活则回调。详见官方文档：[弱事件模式](https://learn.microsoft.com/zh-cn/dotnet/desktop/wpf/advanced/weak-event-patterns)、[WeakEventManager<TEventSource,TEventArgs>](https://learn.microsoft.com/zh-cn/dotnet/api/system.windows.weakeventmanager-2)。

> [!origin] 由来背景
> 在 .NET 中，事件本质是"委托列表里的强引用"。早期开发者写界面时常犯一个错：把"订阅事件"当一次性操作，窗口关了就忘——结果事件源（常常是全局单例或长存服务）永远持有一堆已经死掉的窗口引用，内存只涨不跌。微软在 WPF 1.0 引入 `WeakEventManager` 专门解决"发布者比订阅者活得久"的矛盾，但其设计较繁琐（要为每个事件写一个管理器子类）。直到 .NET 4.5 推出 `WeakEventManager<TSource,TArgs>` 泛型版本，弱事件才成为"一行代码就能用"的日常工具。上位机中，报警中心、数据服务、设备驱动都是典型的长生命周期事件源，订阅它们的窗口/页面正是弱事件的主战场。

> [!essentials] 核心要点
> - **适用范围**：事件源长期存活 + 订阅者短生命周期（窗口、页面、列表行对象）时用弱事件
> - **泛型写法**：`WeakEventManager<AlarmCenter, AlarmEventArgs>.AddHandler(center, nameof(AlarmCenter.AlarmRaised), OnAlarm)`（示例写法）
> - **与强事件对比**：强事件源持有强引用（泄漏风险）；弱事件源持有弱引用（不阻止回收）
> - **代价与边界**：弱事件有少量转发开销；订阅者若无其他强引用持有，可能被提前回收导致收不到事件
> - **卸载对应**：`RemoveHandler` 对应移除；生命周期可控且能显式退订的场景，普通事件 + 退订也可行

> [!example] 完整示例
> **WeakEventManager 弱事件订阅：事件源长期存活时，订阅对象仍可被正常回收：**
>
> **MainWindow.xaml：**
> ```xml
> <Window x:Class="HmiDemo.MainWindow"
>         xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
>         xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
>         Title="弱事件模式" Height="340" Width="560"
>         WindowStartupLocation="CenterScreen" Background="#0D1117">
>     <StackPanel Margin="15" Background="#161B22" Padding="15">
>         <TextBlock Text="WeakEventManager 弱事件订阅演示"
>                    Foreground="#58A6FF" FontSize="16" FontWeight="Bold"/>
>         <TextBlock x:Name="InfoText" Foreground="#8B949E" Margin="0,10,0,0" TextWrapping="Wrap"/>
>         <StackPanel Orientation="Horizontal" Margin="0,14,0,0">
>             <Button Content="创建弱事件订阅" Click="OnSubscribe" Padding="8"
>                     Background="#21262D" Foreground="White"/>
>             <Button Content="触发一次报警事件" Click="OnRaise" Padding="8" Margin="8,0,0,0"
>                     Background="#21262D" Foreground="White"/>
>         </StackPanel>
>         <Button Content="强制 GC 检查对象存活" Click="OnCheck" Padding="8" Margin="0,10,0,0"
>                 Background="#21262D" Foreground="White" HorizontalAlignment="Left"/>
>         <TextBlock x:Name="StatusText" Foreground="#58A6FF" Margin="0,14,0,0" TextWrapping="Wrap"/>
>     </StackPanel>
> </Window>
> ```
>
> **MainWindow.xaml.cs —— 后台代码：**
> ```csharp
> using System;
> using System.Windows;
>
> namespace HmiDemo
> {
>     public partial class MainWindow : Window
>     {
>         private readonly AlarmCenter _center = new AlarmCenter();
>         private WeakReference _subRef;   // 弱引用观测订阅对象是否存活
>
>         public MainWindow()
>         {
>             InitializeComponent();
>             InfoText.Text = "普通事件（+=）会强引用订阅者导致泄漏；WeakEventManager 改为弱引用，订阅者可随时被 GC 回收。";
>         }
>
>         // 用 WeakEventManager 订阅：事件源只持有弱引用，不阻止订阅对象回收
>         private void OnSubscribe(object sender, RoutedEventArgs e)
>         {
>             var sub = new AlarmSubscriber(_center);
>             _subRef = new WeakReference(sub);
>             sub = null;   // 局部变量置空
>             StatusText.Text = "已用 WeakEventManager 创建订阅，局部引用已置空";
>         }
>
>         // 触发一次报警事件，验证弱事件仍能正常收到
>         private void OnRaise(object sender, RoutedEventArgs e) => _center.Raise("温度越限");
>
>         // 强制 GC 后检查：弱事件订阅对象应能被回收（无泄漏）
>         private void OnCheck(object sender, RoutedEventArgs e)
>         {
>             GC.Collect();
>             GC.WaitForPendingFinalizers();
>             GC.Collect();
>             bool alive = _subRef?.IsAlive == true;
>             StatusText.Text = alive
>                 ? "订阅对象仍存活：如果这是强事件订阅，就形成了泄漏"
>                 : "订阅对象已被回收：弱事件模式没有阻止 GC，无泄漏";
>         }
>     }
>
>     // 事件源：模拟上位机报警中心，生命周期与程序一致
>     public class AlarmCenter
>     {
>         public event EventHandler<AlarmEventArgs> AlarmRaised;
>         public void Raise(string msg) => AlarmRaised?.Invoke(this, new AlarmEventArgs(msg));
>     }
>
>     public class AlarmEventArgs : EventArgs
>     {
>         public AlarmEventArgs(string message) => Message = message;
>         public string Message { get; }
>     }
>
>     // 弱事件订阅者：事件源持有弱引用，订阅对象可随时被回收
>     public class AlarmSubscriber
>     {
>         public AlarmSubscriber(AlarmCenter center) =>
>             WeakEventManager<AlarmCenter, AlarmEventArgs>.AddHandler(
>                 center, nameof(AlarmCenter.AlarmRaised), OnAlarm);
>
>         private void OnAlarm(object sender, AlarmEventArgs e) =>
>             Console.WriteLine($"收到报警：{e.Message}");
>     }
> }
> ```

> [!scene] 适用场景
> ✅ 报警中心订阅：报警页面（生命周期短）订阅全局报警中心（生命周期长），页面关闭后能回收
> ✅ 数据服务/设备驱动订阅：监控页订阅 PLC 数据更新事件，切换页面后旧页面对象不留存
> ✅ 多窗口应用：子窗口订阅主窗口事件，关闭子窗口后内存回落
> ✅ 列表行对象：每行订阅长存服务的状态事件，行被移除后能回收
> ✅ 插件/模块化应用：模块卸载时必须能释放对全局服务的事件引用
> ❌ 发布者与订阅者生命周期相同（如单例服务订阅另一个单例，二者都常驻，弱事件无意义）
> ❌ 事件源生命周期短于订阅者（事件源先被回收，弱事件反而引入无谓转发开销）

> [!pitfall] 常见踩坑
> 坑 1：**弱事件后订阅"失灵"** → 现象：改用 `WeakEventManager` 后，某些场景事件不再触发 → 原因：订阅者没有其他强引用，被 GC 提前回收了 → 解决：确认订阅者由业务代码显式持有（如页面对象被导航框架持有）；弱事件只解"泄漏"，不解"生命周期管理"
> 
> 坑 2：**事件签名不满足泛型要求** → 现象：`WeakEventManager<TSource,TArgs>.AddHandler` 编译报错 → 原因：泛型版要求事件为 `EventHandler<T>` 且事件名 = "名称" 形式、来源为 `TSource` → 解决：自定义事件改为标准 `EventHandler<T>` 签名，或用非泛型 `WeakEventManager` + 自定义管理器子类
>
> 坑 3：**把弱事件当万能解药** → 现象：全部订阅都改成弱事件，反而出现"偶发收不到消息"的诡异 bug → 原因：弱引用语义被误用，订阅者生命周期与事件需求不匹配 → 解决：先判断"谁活得久"：事件源活得久 → 弱事件；订阅者活得久或可控 → 普通事件 + 成对退订（见 `wpf-内存常见问题与泄漏场景`）

> [!best] 最佳实践
> - 判断口诀：**"事件源活得久，订阅者用得短" → 用弱事件**；其余场景普通事件 + 成对 `-=` 即可
> - 泛型 `WeakEventManager<T,TArgs>` 是首选（一行代码），`nameof(事件名)` 保证重命名安全
> - 结合 `资源释放与-idisposable`：窗口 `Closed` 里统一 `RemoveHandler`，双保险防泄漏
> - 用 `WeakReference` + `GC.Collect()` 验证弱事件确实生效（示例 `OnCheck` 就是标准自证）
> - 需要转发多类事件时，把订阅集中到一个管理类，避免每处都裸写 `WeakEventManager` 调用
