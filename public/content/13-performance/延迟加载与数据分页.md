# 延迟加载与数据分页

> [!plain] 白话理解
> 把 10 万条点位记录比作一整本县志：你翻看时只需要当前这一页的内容。**一次性全加载**，相当于把整本书从头到尾背下来再开始看，费时费内存；**分页加载**，就是每次只翻开你要的那一页（`Skip` 跳过前面的、`Take` 取这一页 100 条），看完了再翻下一页。示例用两个按钮"上一页/下一页"，在内存里的 10 万条数据中只把当前 100 条塞进 `ListBox`，数据总量再大，界面负担始终只有一页——这就是"延迟加载"的核心思想：**用到什么，才加载什么**。

> [!def] 官方定义
> 延迟加载（Lazy Loading）是一种资源优化策略：将数据（或控件、图片、模块）的创建/加载推迟到首次真正被访问时才执行，避免一次性初始化全部资源。数据分页（Pagination）是其典型实现：把大数据集按固定页大小（PageSize）切分为若干页，每次只取并展示当前页。在 WPF 中常用 LINQ 的 `Skip(n)` / `Take(n)` 对内存集合分页，或对数据库用 `OFFSET/FETCH`、`ROW_NUMBER()` 实现服务端分页。延迟加载还有更精细的形态：`Lazy<T>`（首次取值时才构造）、`async/await` 配合后台加载（见 `异步绑定与延迟`）、图片按需解码（见 `图片优化与位图缓存`）。详见官方文档：[Lazy<T>](https://learn.microsoft.com/zh-cn/dotnet/api/system.lazy-1)、[Enumerable.Skip](https://learn.microsoft.com/zh-cn/dotnet/api/system.linq.enumerable.skip)、[Enumerable.Take](https://learn.microsoft.com/zh-cn/dotnet/api/system.linq.enumerable.take)。

> [!origin] 由来背景
> 桌面应用早期"大数据列表"的常态是：启动时一把梭把数据库全量读进内存，再塞给列表控件。数据量从几千涨到几十万后，启动要等十几秒、内存吃掉几百 MB，用户只能干瞪眼。软件工程由此沉淀出"延迟初始化"思想：能晚加载就晚加载，能按需取就按需取。在 Web 领域，分页几乎是查询标配；在 WPF 上位机里，点位记录、报警历史、工艺参数配方这类"量大且常驻"的数据，天然适合分页展示——用户通常只关心最近几十条或按时间/条件筛选后的少量记录，全量加载纯属浪费。`Lazy<T>` 是 .NET 4.0 对"延迟"能力的标准化封装，把"首次访问才构造"写成了语言级支持。

> [!essentials] 核心要点
> - **分页三要素**：页大小（PageSize）、当前页索引、总页数（`(总数 + PageSize - 1) / PageSize`）
> - **Skip/Take**：`_all.Skip((page - 1) * PageSize).Take(PageSize)` 是内存分页的标准写法，返回新集合、原数据不动
> - **越界保护**：页码夹在 `1..总页数` 之间（示例的 `page < 1 ? 1 : (page > total ? total : page)`），翻页才不出错
> - **延迟思想可迁移**：`Lazy<T>` 延迟构造对象、`BitmapImage` 延迟解码、模块延迟加载，同源同理
> - **分页不是万能**：如果必须一次性展示 10 万条供人滚动浏览，应优先用 `UI 虚拟化`（页面只显示、控件按需建）

> [!example] 完整示例
> **数据分页加载：10 万条点位记录分页显示，每次只加载当前页 100 条：**

> **MainWindow.xaml：**
> ```xml
> <Window x:Class="HmiDemo.MainWindow"
>         xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
>         xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
>         Title="延迟加载与数据分页" Height="400" Width="520"
>         WindowStartupLocation="CenterScreen" Background="#0D1117">
>     <Grid Margin="15" Background="#161B22" Padding="10">
>         <Grid.RowDefinitions>
>             <RowDefinition Height="Auto"/>
>             <RowDefinition Height="*"/>
>             <RowDefinition Height="Auto"/>
>             <RowDefinition Height="Auto"/>
>         </Grid.RowDefinitions>
>         <TextBlock Text="10 万条点位记录分页加载（每页 100 条）"
>                    Foreground="#58A6FF" FontSize="16" FontWeight="Bold"/>
>         <ListBox x:Name="RecordList" Grid.Row="1" Margin="0,10,0,10"
>                  Background="#0D1117" Foreground="#8B949E" BorderBrush="#21262D">
>             <ListBox.ItemTemplate>
>                 <DataTemplate>
>                     <StackPanel Orientation="Horizontal">
>                         <TextBlock Text="{Binding Id}" Foreground="#58A6FF" Width="60"/>
>                         <TextBlock Text="{Binding Name}" Foreground="#8B949E" Width="160"/>
>                         <TextBlock Text="{Binding Value, StringFormat=F2}" Foreground="#238636"/>
>                     </StackPanel>
>                 </DataTemplate>
>             </ListBox.ItemTemplate>
>         </ListBox>
>         <StackPanel Grid.Row="2" Orientation="Horizontal">
>             <Button Content="上一页" Click="OnPrev" Padding="8"
>                     Background="#21262D" Foreground="White"/>
>             <Button Content="下一页" Click="OnNext" Padding="8" Margin="8,0,0,0"
>                     Background="#21262D" Foreground="White"/>
>         </StackPanel>
>         <TextBlock x:Name="PageText" Grid.Row="3" Foreground="#8B949E" Margin="0,10,0,0" TextWrapping="Wrap"/>
>     </Grid>
> </Window>
> ```
>
> **MainWindow.xaml.cs —— 后台代码：**
> ```csharp
> using System.Collections.Generic;
> using System.Linq;
> using System.Windows;
>
> namespace HmiDemo
> {
>     public partial class MainWindow : Window
>     {
>         private readonly List<PointRecord> _all = new List<PointRecord>();  // 全量数据（10 万条）
>         private int _pageIndex;                 // 当前页
>         private const int PageSize = 100;       // 每页 100 条
>
>         public MainWindow()
>         {
>             InitializeComponent();
>             // 初始化全量数据，模拟 10 万条点位记录
>             for (int i = 0; i < 100000; i++)
>                 _all.Add(new PointRecord(i, $"点位 {i % 100 + 1}", i * 0.5));
>             LoadPage(1);
>         }
>
>         private void LoadPage(int page)
>         {
>             int total = (_all.Count + PageSize - 1) / PageSize;
>             _pageIndex = page < 1 ? 1 : (page > total ? total : page);
>             // 延迟加载：只取当前页数据，避免一次加载 10 万条
>             var pageData = _all.Skip((_pageIndex - 1) * PageSize).Take(PageSize).ToList();
>             RecordList.ItemsSource = pageData;
>             PageText.Text = $"第 {_pageIndex} / {total} 页，共 {_all.Count} 条记录（当前页 {pageData.Count} 条）";
>         }
>
>         private void OnPrev(object sender, RoutedEventArgs e) => LoadPage(_pageIndex - 1);
>
>         private void OnNext(object sender, RoutedEventArgs e) => LoadPage(_pageIndex + 1);
>     }
>
>     public class PointRecord
>     {
>         public PointRecord(int id, string name, double value)
>         {
>             Id = id; Name = name; Value = value;
>         }
>
>         public int Id { get; }
>         public string Name { get; }
>         public double Value { get; }
>     }
> }
> ```

> [!scene] 适用场景
> ✅ 历史报警/历史曲线查询：按时间段查出 10 万条记录，分页每页 100 条展示，翻页秒开
> ✅ 点位配置管理：设备点位 5 万+，一次加载拖慢启动，分页 + 关键字筛选后启动与查询都快
> ✅ 数据库大表查询：`SELECT ... ORDER BY id OFFSET ? ROWS FETCH NEXT 100 ROWS ONLY` 服务端分页，只传当前页数据
> ✅ 配方/工艺参数档案：大批量参数以"页"为单位浏览编辑，符合操作习惯
> ✅ 启动页懒加载：主界面先出框架，耗时模块（历史报表、视频画面）切到该页时才加载
> ❌ 需要连续滚动浏览全部数据的场景（分页割裂体验，改用 `UI 虚拟化`）
> ❌ 数据量只有几百条的页面（分页反而增加点击次数，一次加载更直接）

> [!pitfall] 常见踩坑
> 坑 1：**分页后忘记保留全量数据** → 现象：翻到第 2 页数据"消失"，只剩当前页 → 原因：只把当前页塞进 `ItemsSource`，原集合没有保留 → 解决：全量数据放独立字段（示例的 `_all`），分页只做 `Skip/Take`，绝不覆盖全量引用
> 
> 坑 2：**页码越界没保护** → 现象：删掉最后一页数据后点"下一页"，列表变空或抛异常 → 原因：页索引越过总页数，`Skip` 返回空集 → 解决：加载前先做 `page < 1 ? 1 : (page > total ? total : page)` 夹取（示例 `LoadPage` 内已做）
>
> 坑 3：**误以为分页能解决一切大数据问题** → 现象：分页后想滚动浏览全部历史，却发现每页之间跳转割裂、拖不到中间 → 原因：分页适合"查询+翻页"语义，不适合"连续滚动浏览" → 解决：滚动浏览场景用 `UI 虚拟化`（10 万条也能流畅滚），分页留给"按条件查历史"场景

> [!best] 最佳实践
> - 页大小按人眼舒适取 50~200 条（示例用 100），太小点按频繁、太大失去分页意义
> - 数据来源是数据库时，优先做**服务端分页**：只查当前页，避免 10 万条全量进内存
> - 翻页是高频操作：当前页数据缓存一份，点"上一页/下一页"直接复用，减少重复计算
> - 分页 + 虚拟化组合拳：即使每页 500 条，`ListBox` 也开虚拟化，双保险防卡顿
> - 用 `Lazy<T>` 延迟构造重量级单例（如数据库连接、历史报表控件），把启动耗时摊到首次使用

> [!practice] 上手练习
> **Lv.1 照猫画虎**：运行示例，连续点"下一页"从第 1 页翻到第 1000 页，观察 `PageText` 页码与数据内容，修改 `PageSize` 为 50/200 体会差异
> **Lv.2 小试牛刀**：增加"首页/末页/跳转页码"功能：输入页码回车直达，用 `TextBox` 接收页码、复用 `LoadPage` 完成跳转
> **Lv.3 融会贯通**：把分页推广到数据库场景：用 SQLite 建一张 10 万行表，`SELECT * FROM points ORDER BY id LIMIT 100 OFFSET ?` 实现真正的服务端分页，翻页时只从数据库取当前页，对比内存分页的启动时间与内存占用
