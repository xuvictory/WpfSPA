# 开机自启动设置

> [!plain] 白话理解
> 车间操作站的软件最好"开机自己就起来"，别等操作员手动双击。原理很简单：在注册表 `HKCU\...\CurrentVersion\Run` 里写一条启动命令，Windows 登录时就会自动运行。但"能自启"不等于"做得好"——写错位置、路径带空格、静默改用户设置，都会变成现场事故。本节把启用、关闭、状态查询讲透，核心原则：**自启动是用户显式选择的，不是程序偷偷干的**。

> [!def] 官方定义
> **开机自启动**：让程序在 Windows 登录后自动运行的机制。常见实现：注册表 Run 键（`HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 或 `HKLM\...\Run`，值为带引号的命令字符串）、启动文件夹（`shell:startup`）、计划任务（`schtasks`）。.NET 侧用 `Microsoft.Win32.Registry` 读写 Run 键，`Process.GetCurrentProcess().MainModule.FileName` 获取当前 exe 路径。HKCU 仅当前用户生效、无需管理员权限；HKLM 对所有用户生效、需管理员权限。官方文档：https://learn.microsoft.com/zh-cn/windows/win32/setupapi/run-and-runonce-registry-keys

> [!origin] 由来背景
> 从 Windows 3.x 时代 `Win.ini` 里的 `run=` 行，到 Windows 95 引入注册表 Run 键，再到任务计划程序，Windows 的"自启动"机制一路演进：Run 键简单直接、人人皆知，是上位机自启动的主流做法；启动文件夹对用户透明、方便手动管理；计划任务则能精确控制触发时机（开机时/登录时/延迟）。微软文档明确区分 `Run`（登录时启动）与 `RunOnce`（一次性启动）。本节采用 HKCU Run 键——车间单用户场景下无需管理员权限、卸载干净，是上位机最常用的姿势。

> [!essentials] 核心要点
> - **HKCU vs HKLM**：`HKCU\...\Run` 当前用户、免管理员权限；`HKLM\...\Run` 所有用户、需提权——车间单用户选 HKCU
> - **值格式**：Run 键值为"带引号的完整命令"，路径含空格必须加 `"` 包裹（示例代码已处理）
> - **只读查询安全**：`OpenSubKey`（不带 writable）只读查询不会改系统；写操作才用 `CreateSubKey` / `writable:true`
> - **用户显式授权**：自启动必须由用户点击"启用"触发，程序首次启动静默写 Run 键属于越权行为
> - **清理要干净**：关闭自启动 = 删除对应值；卸载程序时也要移除，避免残留启动项

> [!example] 完整示例
> **自启动配置面板：读写 HKCU Run 注册表项实现开机自启动的启用/关闭/状态查询（用户显式点击才写入）：**
>
> **MainWindow.xaml：**
> ```xml
> <Window x:Class="HmiDemo.MainWindow"
>         xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
>         xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
>         Title="开机自启动设置" Height="420" Width="560"
>         WindowStartupLocation="CenterScreen" Background="#0D1117">
>     <StackPanel Margin="15">
>         <TextBlock Text="开机自启动设置" FontSize="18" FontWeight="Bold"
>                    Foreground="#58A6FF" Margin="0,0,0,10"/>
>         <Border Background="#161B22" Padding="12" CornerRadius="6" Margin="0,0,0,10">
>             <StackPanel>
>                 <TextBlock x:Name="TxtStatus" Foreground="#238636" Margin="0,2" FontWeight="Bold"/>
>                 <TextBlock x:Name="TxtCommand" Foreground="#8B949E" Margin="0,2" TextWrapping="Wrap"/>
>             </StackPanel>
>         </Border>
>         <StackPanel Orientation="Horizontal">
>             <Button Content="启用自启动" Click="OnEnable" Padding="10" Margin="0,0,8,0"
>                     Background="#238636" Foreground="White"/>
>             <Button Content="关闭自启动" Click="OnDisable" Padding="10" Margin="0,0,8,0"
>                     Background="#DA3633" Foreground="White"/>
>             <Button Content="刷新状态" Click="OnRefresh" Padding="10"
>                     Background="#21262D" Foreground="White"/>
>         </StackPanel>
>         <TextBlock x:Name="TxtHint" Foreground="#8B949E" TextWrapping="Wrap" Margin="0,10,0,0"/>
>     </StackPanel>
> </Window>
> ```
>
> **MainWindow.xaml.cs —— 后台代码：**
> ```csharp
> using System;
> using System.Diagnostics;
> using System.Windows;
> using Microsoft.Win32;
>
> namespace HmiDemo
> {
>     public partial class MainWindow : Window
>     {
>         private const string RunKeyPath = @"Software\Microsoft\Windows\CurrentVersion\Run";
>         private const string AppName = "HmiDemo";
>
>         public MainWindow()
>         {
>             InitializeComponent();
>             Loaded += (_, _) => OnRefresh(null, null);
>         }
>
>         private void OnRefresh(object sender, RoutedEventArgs e)
>         {
>             try
>             {
>                 // 读取 HKCU\...\CurrentVersion\Run 下的自启动项（只读查询，安全）
>                 using RegistryKey runKey = Registry.CurrentUser.OpenSubKey(RunKeyPath);
>                 string cmd = runKey?.GetValue(AppName) as string;
>                 TxtStatus.Text = string.IsNullOrEmpty(cmd) ? "未启用" : "已启用";
>                 TxtCommand.Text = string.IsNullOrEmpty(cmd) ? "" : "命令：" + cmd;
>                 TxtHint.Text = "状态读取自 HKCU\\Software\\Microsoft\\Windows\\CurrentVersion\\Run";
>             }
>             catch (Exception ex)
>             {
>                 MessageBox.Show("读取注册表失败：" + ex.Message, "开机自启动");
>             }
>         }
>
>         private void OnEnable(object sender, RoutedEventArgs e)
>         {
>             try
>             {
>                 // 用户显式点击才写入注册表：指向当前可执行文件，加引号防止路径含空格
>                 using RegistryKey runKey = Registry.CurrentUser.CreateSubKey(RunKeyPath);
>                 string exe = Process.GetCurrentProcess().MainModule.FileName;
>                 runKey.SetValue(AppName, "\"" + exe + "\"");
>                 TxtStatus.Text = "已启用（下次开机自动启动）";
>                 TxtCommand.Text = "命令：" + exe;
>                 TxtHint.Text = "已写入 HKCU Run 键；仅对当前用户生效，无需管理员权限";
>             }
>             catch (Exception ex)
>             {
>                 MessageBox.Show("启用失败：" + ex.Message, "开机自启动");
>             }
>         }
>
>         private void OnDisable(object sender, RoutedEventArgs e)
>         {
>             try
>             {
>                 // 删除自启动项（值为空时跳过，避免误删）
>                 using RegistryKey runKey = Registry.CurrentUser.OpenSubKey(RunKeyPath, writable: true);
>                 if (runKey?.GetValue(AppName) != null)
>                     runKey.DeleteValue(AppName);
>                 TxtStatus.Text = "已关闭";
>                 TxtCommand.Text = "";
>                 TxtHint.Text = "已从注册表移除自启动项";
>             }
>             catch (Exception ex)
>             {
>                 MessageBox.Show("关闭失败：" + ex.Message, "开机自启动");
>             }
>         }
>     }
> }
> ```
> 

> [!scene] 适用场景
> ✅ 车间操作站/一体机"开机进系统即运行"：操作员不碰键盘，程序自动拉起
> ✅ 客户要求"像家电一样开机就用"的交付：省去培训操作员找图标、双击的环节
> ✅ 值班机、无人值守设备：登录后自动跑采集/监控程序，断电重启后自动恢复
> ❌ 需要开机前（无登录会话）运行的场景：Run 键依赖登录，用 Windows 服务或计划任务（见 `windows-服务模式`）
> ❌ 需要多重启动条件/延迟控制的场景：Run 键只支持"登录即启动"，复杂策略用计划任务更合适

> [!pitfall] 常见踩坑
> 坑 1：**路径含空格不自启** → 现象：配置了自启动，重启后程序没起来 → 原因：Run 键值没加引号，`C:\Program Files\Hmi\App.exe` 被拆成两段执行 → 解决：写值一律用 `"\"" + exe + "\""` 包裹（示例代码已处理）
>
> 坑 2：**根键选错导致"只有管理员生效"或"换用户失效"** → 现象：写入 HKLM 后普通用户登录不自启；或写入 HKCU 后换账户就没了 → 原因：两个 Run 键的作用域不同 → 解决：按实际部署账户决定——车间机统一用部署账户登录就用对应 HKCU；需要全用户生效才用 HKLM（需管理员权限）
>
> 坑 3：**程序没提示就改注册表，被当成"流氓行为"** → 现象：安装后偷偷写自启动，杀毒软件报警、客户投诉 → 原因：未征求用户同意 → 解决：自启动开关做成界面上的显式按钮（本节示例就是这种设计），并把"已写入 Run 键"的提示展示给用户

> [!best] 最佳实践
> - 自启动做成"用户显式开关"：界面提供启用/关闭按钮，绝不静默写注册表（示例代码即此设计）
> - 写值前先查重：若 Run 键里已有同名值，先确认是不是自己程序的，避免覆盖别的程序
> - 状态查询用只读 API：`OpenSubKey`（不带 writable）读状态，写操作才开写权限，减少误改风险
> - 提供"延迟启动"选项（可选）：车间机开机后外设可能未就绪，可配合计划任务或程序内延迟逻辑，避免启动即报错
> - 卸载时清理自启动：在卸载逻辑/卸载脚本中删除 Run 键对应值，不给客户留垃圾

> [!practice] 上手练习
> **Lv.1 照猫画虎**：运行示例程序，点"启用自启动"，用 `regedit` 查看 `HKCU\...\CurrentVersion\Run` 下新增的值；点"关闭"确认被删除
> **Lv.2 小试牛刀**：把程序移到含空格的路径（如 `C:\Program Files\HmiDemo\`）再启用，重启验证自启动正常
> **Lv.3 融会贯通**：程序启动时读取 Run 键，把"当前是否已自启"状态显示在界面上，与开关按钮联动
> **Lv.4 拆层挑战**：增加"开机延迟 N 秒"选项：自启动命令带参数（如 `--delay 30`），程序内部用 `System.Threading.Timer` 延迟初始化采集（结合第 8 章异步知识）
