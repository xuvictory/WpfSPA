# 独立发布与单文件发布

> [!plain] 白话理解
> 框架依赖发布像"去客户现场用他家的电饭煲"——你要保证客户机器上装了 .NET；独立发布则是"自带整套厨具"，把运行时一起背过去，到哪都能开火。单文件发布更进一步：把散落的几十上百个 dll 全部塞进一个 exe，客户拿到的就是一个文件。工控现场的一体机、无网环境、不让随便装软件的机器上，独立/单文件发布是"一个 exe 扔过去就能跑"的底气。

> [!def] 官方定义
> **独立发布（self-contained）** 是 .NET 的发布模式之一：把目标应用的代码与所选 .NET 运行时一起输出到发布目录，目标机**无需预装任何 .NET Runtime** 即可运行；**单文件发布（single-file）** 在此基础上把所有文件（应用、运行时、依赖）捆绑进**单个可执行文件**。通过 `dotnet publish` 控制：`dotnet publish -c Release -r win-x64 --self-contained`（独立发布），加 `/p:PublishSingleFile=true`（单文件）。运行时判定 API：`RuntimeInformation.FrameworkDescription` 显示实际运行时版本；`Assembly.GetEntryAssembly().Location` 在单文件模式返回空字符串。官方文档：https://learn.microsoft.com/zh-cn/dotnet/core/deploying/single-file/overview

> [!origin] 由来背景
> .NET Framework 时代部署最大的痛点是"目标机必须先装对应版本框架"：客户机器缺运行时，程序双击没反应，现场工程师只能现场装框架、还要面对版本冲突。.NET Core 1.0（2016 年）引入自包含发布，把运行时装进应用目录，从此"拷贝即运行"成为可能；单文件发布最初以实验特性出现在 .NET Core 3.0（2019 年 9 月），到 .NET 5 趋于稳定，配合裁剪（Trimming）成为分发 WPF 工控软件的主流姿势。

> [!essentials] 核心要点
> - **两种模式**：框架依赖（FDD，小体积、需目标机运行时）vs 独立发布（SCD，大体积、零依赖），`dotnet publish -r <RID>` 指定目标平台（win-x64 / win-arm64 等）
> - **单文件开关**：`/p:PublishSingleFile=true` 把一切打进一个 exe；`/p:IncludeNativeLibrariesForSelfExtract=true` 控制原生 dll 是否解包到临时目录
> - **体积权衡**：独立发布会把整个运行时带上，常见 60-150 MB；可用 `/p:PublishTrimmed=true` 裁剪（WPF 支持有限，需逐一验证）
> - **运行时判定**：`AppContext.BaseDirectory` 在单文件模式下指向"解包后的临时目录"，`Assembly.Location` 为空——程序里写文件别依赖 exe 旁路径
> - **产物验证**：检查发布目录的文件数与总大小即可判断形态（独立发布文件多、单文件仅 1 个 exe）

> ```csharp
> using System;
> using System.IO;
> using System.Reflection;
> using System.Windows;
>
> namespace HmiDemo
> {
>     public partial class MainWindow : Window
>     {
>         public MainWindow()
>         {
>             InitializeComponent();
>             Loaded += (_, _) => OnCheckClick(null, null);   // 启动即检测一次
>         }

>         private void OnCheckClick(object sender, RoutedEventArgs e)
>         {
>             try
>             {
>                 // Environment.Version：获取当前 .NET 运行时版本（独立发布时为随包携带的运行时版本）

>                 TxtLocation.Text = "程序集路径：" + (isSingleFile ? "（单文件/内存加载）"
>                     : Assembly.GetEntryAssembly().Location);
>                 // AppContext.BaseDirectory：运行时解包后的基础目录
>                 TxtSingleFile.Text = "单文件发布：" + (isSingleFile ? "是（所有依赖已打包进单个 exe）" : "否");
>                 // 统计基础目录文件数：单文件发布时通常只剩 1-2 个文件

>                 TxtCommand.Text = "参考发布命令（框架依赖）：" + Environment.NewLine +
>                     "dotnet publish -c Release -r win-x64" + Environment.NewLine +
>                     "参考发布命令（单文件）：" + Environment.NewLine +
>                     "dotnet publish -c Release -r win-x64 --self-contained /p:PublishSingleFile=true";
>             }
>             catch (Exception ex)
>             {
>                 MessageBox.Show("检测失败：" + ex.Message, "发布环境诊断");
>             }
>         }
>     }
> }
> ```

> [!scene] 适用场景
> ✅ 目标机没装 .NET 的一体机/工控机：独立发布把运行时一起背过去，零依赖直接跑
> ✅ 离线、无外网环境：客户内网装不了运行时，独立/单文件发布是唯一省心解
> ✅ 交付物要"一个 exe 搞定"的便携分发：单文件发布后 U 盘拷一个文件即可，不会漏拷 dll
> ✅ 多应用要不同 .NET 版本共存：独立发布各带各的运行时，互不干扰
> ❌ 内网已统一装好 .NET、要省体积省带宽的场景：用 `框架依赖-vs-独立部署比较` 的 FDD 更合适
> ❌ 需要频繁小版本增量更新的场景：单文件每次全量重发，更新粒度粗、流量大

> [!pitfall] 常见踩坑
> 坑 1：**只加 `--self-contained` 忘了 `-r`，发布出"假的独立版"** → 现象：发布目录很小、目标机仍提示缺 .NET → 原因：没指定 RID 时产物不一定自包含 → 解决：命令写全 `dotnet publish -c Release -r win-x64 --self-contained`
>
> 坑 2：**单文件模式下程序找不到配置文件** → 现象：`Assembly.Location` 返回空、`Directory.GetCurrentDirectory()` 指向解包临时目录，配置读不到 → 原因：单文件运行时程序集从临时解包目录加载 → 解决：路径一律基于 `AppContext.BaseDirectory` 计算，现场可改的配置放 exe 旁而非打进单文件
>
> 坑 3：**裁剪（Trimming）剪掉了反射要用的类型** → 现象：发布后 `Type.GetType` / 序列化 / 动态加载返回 null → 原因：`PublishTrimmed=true` 的静态分析覆盖不了反射和动态绑定 → 解决：WPF 项目谨慎裁剪，必要时用 `[DynamicDependency]` 或 `TrimmerRootAssembly` 保留，先不裁剪验证功能再逐步裁剪

> [!best] 最佳实践
> - 发布命令固化成脚本：`dotnet publish -c Release -r win-x64 --self-contained -p:PublishSingleFile=true` 存成 `publish.bat`，避免手敲漏参数
> - 工控机 CPU 弱可加 `-p:PublishReadyToRun=true`：预编译缩短启动时间，代价是体积再增
> - 现场可改的配置与程序分离：`appsettings.json` 等放 exe 旁，客户改配置不用重新发布
> - 发布后在"干净虚拟机"验证：新建一台没装 .NET 的 Windows 跑一遍，确认零依赖成立
> - 记录每次发布的参数：RID、裁剪、单文件、目标框架版本写进发布说明，版本回溯不靠猜

> [!practice] 上手练习
> **Lv.1 照猫画虎**：对示例项目执行 `dotnet publish -c Release -r win-x64 --self-contained`，对比发布目录大小与框架依赖发布的差异
> **Lv.2 小试牛刀**：加 `/p:PublishSingleFile=true` 再发布一次，看文件数从几十个变成 1 个，双击运行验证正常
> **Lv.3 融会贯通**：把发布目录拷到一台未装 .NET 的虚拟机/一体机运行，验证零依赖；用 `RuntimeInformation.FrameworkDescription` 打印实际运行时
> **Lv.4 拆层挑战**：结合 `框架依赖-vs-独立部署比较` 和 `依赖项打包与配置文件`，做一份"同一项目 FDD/SCD/单文件三种形态的体积、启动速度、目标机要求"对比实验记录
