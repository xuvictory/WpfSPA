# 依赖项打包与配置文件

> [!plain] 白话理解
> 把程序交给客户，不只是"拷个 exe"。一个 WPF 上位机发布目录里除了主程序，还有一堆 dll、依赖库、配置文件——少带一个 dll 程序就起不来，配置放错位置客户改参数又找不到。本节讲清楚"哪些文件必须随发布一起分发、配置放哪、怎么读最稳"，让你交付的目录干净、完整、客户能自己改配置。

> [!def] 官方定义
> **依赖项（dependency）**：应用运行所依赖的程序集与库（框架库、NuGet 包、原生 dll、资源文件），发布时需随主程序一起分发或由运行时解析；**配置文件**：应用外置的参数载体，.NET 常见 `appsettings.json`（`Microsoft.Extensions.Configuration` 读取）与 `App.config`（.NET Framework 的 XML 配置）。**拷贝规则**：`.csproj` 里 `<Content>`/`<None>` + `CopyToOutputDirectory` 控制哪些文件进入发布目录。官方文档：https://learn.microsoft.com/zh-cn/dotnet/core/extensions/configuration

> [!origin] 由来背景
> .NET Framework 时代依赖打进 GAC 或 bin 目录，配置用 `App.config`（XML），发布 ≈ 拷贝 bin 文件夹，"漏文件"是现场翻车第一原因。.NET Core（2016 年）引入 JSON 配置体系与"发布目录即运行目录"的思想：`dotnet publish` 输出什么，目标机就要什么；`CopyToOutputDirectory` 精确控制随包文件；`appsettings.json` 成为 .NET 配置的事实标准。NuGet 包引用同时把依赖管理前置到构建期，发布时只输出"真正用到的文件"，"打包哪些依赖"从手忙脚乱变成可配置、可审计。

> [!essentials] 核心要点
> - **发布目录 = 运行目录**：`dotnet publish` 输出的所有文件就是目标机要拷贝的内容，缺一不可
> - **拷贝规则**：`<None CopyToOutputDirectory="PreserveNewest">`（或 `Always`）控制配置文件等随发布分发
> - **配置读取**：`appsettings.json` 用 `JsonSerializer` 或 `Microsoft.Extensions.Configuration` 读取；路径用 `AppContext.BaseDirectory` 拼接，别用当前工作目录
> - **默认值兜底**：配置缺失或解析失败时，程序用默认值照常运行，不能直接崩（示例代码已演示）
> - **敏感配置**：连接串、口令不要硬编码进程序集，放配置文件并考虑加密（见 12 章 `配置加密与运行时修改`）

> [!example] 完整示例
> **设备参数配置面板：读取随发布目录分发的 appsettings.json（PLC IP/端口、串口、采集周期）并回显，配置缺失时使用默认值兜底：**
>
> **MainWindow.xaml：**
> ```xml
> <Window x:Class="HmiDemo.MainWindow"
>         xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
>         xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
>         Title="依赖项打包与配置文件" Height="460" Width="580"
>         WindowStartupLocation="CenterScreen" Background="#0D1117">
>     <StackPanel Margin="15">
>         <TextBlock Text="设备参数配置（appsettings.json）" FontSize="18" FontWeight="Bold"
>                    Foreground="#58A6FF" Margin="0,0,0,10"/>
>         <Border Background="#161B22" Padding="12" CornerRadius="6" Margin="0,0,0,10">
>             <StackPanel>
>                 <TextBlock x:Name="TxtPlcIp" Foreground="#8B949E" Margin="0,2"/>
>                 <TextBlock x:Name="TxtPlcPort" Foreground="#8B949E" Margin="0,2"/>
>                 <TextBlock x:Name="TxtSerialPort" Foreground="#8B949E" Margin="0,2"/>
>                 <TextBlock x:Name="TxtBaudRate" Foreground="#8B949E" Margin="0,2"/>
>                 <TextBlock x:Name="TxtPollInterval" Foreground="#8B949E" Margin="0,2"/>
>             </StackPanel>
>         </Border>
>         <Button Content="重新读取配置文件" Click="OnLoadConfig" Padding="8" Margin="0,0,0,10"
>                 Background="#21262D" Foreground="White"/>
>         <TextBlock x:Name="TxtJson" Foreground="#8B949E" TextWrapping="Wrap"
>                    FontFamily="Consolas" FontSize="12"/>
>     </StackPanel>
> </Window>
> ```
>
> **MainWindow.xaml.cs —— 后台代码：**
> ```csharp
> using System;
> using System.IO;
> using System.Text.Json;
> using System.Windows;
>
> namespace HmiDemo
> {
>     // 与 appsettings.json 对应的数据结构（发布时随程序一起拷贝到输出目录）
>     public class AppConfig
>     {
>         public string PlcIp { get; set; } = "192.168.1.10";
>         public int PlcPort { get; set; } = 502;
>         public string SerialPort { get; set; } = "COM3";
>         public int BaudRate { get; set; } = 9600;
>         public int PollIntervalMs { get; set; } = 100;
>     }
>
>     public partial class MainWindow : Window
>     {
>         public MainWindow()
>         {
>             InitializeComponent();
>             Loaded += (_, _) => OnLoadConfig(null, null);
>         }
>
>         private void OnLoadConfig(object sender, RoutedEventArgs e)
>         {
>             try
>             {
>                 // 配置文件与 exe 同目录分发，使用相对路径读取，避免硬编码绝对路径
>                 string path = Path.Combine(AppContext.BaseDirectory, "appsettings.json");
>                 AppConfig cfg;
>                 if (File.Exists(path))
>                 {
>                     cfg = JsonSerializer.Deserialize<AppConfig>(File.ReadAllText(path)) ?? new AppConfig();
>                     TxtJson.Text = "已加载配置：" + Environment.NewLine + File.ReadAllText(path);
>                 }
>                 else
>                 {
>                     // 配置文件缺失时使用默认值兜底，程序照常运行
>                     cfg = new AppConfig();
>                     TxtJson.Text = "未找到 appsettings.json，使用默认配置：" + Environment.NewLine +
>                         "{\n  \"PlcIp\": \"192.168.1.10\",\n  \"PlcPort\": 502,\n" +
>                         "  \"SerialPort\": \"COM3\",\n  \"BaudRate\": 9600,\n  \"PollIntervalMs\": 100\n}";
>                 }
>
>                 TxtPlcIp.Text = "PLC IP：" + cfg.PlcIp;
>                 TxtPlcPort.Text = "PLC 端口：" + cfg.PlcPort;
>                 TxtSerialPort.Text = "串口号：" + cfg.SerialPort;
>                 TxtBaudRate.Text = "波特率：" + cfg.BaudRate;
>                 TxtPollInterval.Text = "采集周期：" + cfg.PollIntervalMs + " ms";
>             }
>             catch (Exception ex)
>             {
>                 MessageBox.Show("读取配置失败：" + ex.Message, "配置文件");
>             }
>         }
>     }
> }
> ```
> 

> [!scene] 适用场景
> ✅ 发布前整理交付目录：确认程序集、依赖、配置文件、运行库齐全，客户拷过去就能跑
> ✅ 现场参数需要客户/工程师修改：PLC IP、串口号、采集周期放 `appsettings.json`，改配置不重发程序
> ✅ 单文件发布与配置分离：现场可改的配置放 exe 旁，程序从外部读取（见 `独立发布与单文件发布`）
> ✅ 多环境切换（开发/测试/产线）：不同环境不同配置，发布时带上对应配置文件
> ❌ 纯逻辑库、无外部参数的小组件：不需要外置配置，硬编码或常量即可
> ❌ 配置需要强一致、防篡改的场合：纯文件配置不够，需结合权限与加密方案（见 12 章 `配置加密与运行时修改`）

> [!pitfall] 常见踩坑
> 坑 1：**配置文件没拷到发布目录** → 现象：本地调试正常，拷到目标机后程序用默认值跑或报"配置读取失败" → 原因：`.csproj` 没配 `CopyToOutputDirectory`，publish 输出里根本没有该文件 → 解决：`<None Update="appsettings.json"><CopyToOutputDirectory>PreserveNewest</CopyToOutputDirectory></None>`
>
> 坑 2：**用 `Environment.CurrentDirectory` 找配置文件** → 现象：双击 exe 正常，从别的目录/快捷方式启动就找不到配置 → 原因：工作目录不一定是 exe 所在目录 → 解决：一律用 `AppContext.BaseDirectory` 拼接（单文件模式下它指向解包临时目录，注意区分，见 `独立发布与单文件发布`）
>
> 坑 3：**配置反序列化失败整程序崩溃** → 现象：客户手改 JSON 少个逗号，程序启动直接报错 → 原因：解析异常没有兜底 → 解决：解析包 try-catch，失败时回退默认值并把错误写进日志（见 12 章 `serilog-结构化日志`）

> [!best] 最佳实践
> - 配置文件用 JSON（`appsettings.json`）作为默认载体：结构清晰、客户好改，可结合 12 章 `appsettingsjson推荐方案`
> - 路径一律基于 `AppContext.BaseDirectory`，绝不依赖"当前目录"；单文件发布时配置放 exe 旁
> - 提供"配置模板"：发布目录附带 `appsettings.default.json` 作为示例，客户照抄改名即用
> - 配置项分组命名：`Device:Plc:Ip`、`Device:Plc:Port` 这类嵌套结构比扁平 Key 更好维护
> - 升级程序不覆盖现场配置：`CopyToOutputDirectory` 只管"初装"，升级时用独立数据目录或合并逻辑（见 `clickonce-发布` 坑 3）

> [!practice] 上手练习
> **Lv.1 照猫画虎**：运行示例程序，确认 `appsettings.json` 与 exe 同目录时配置正常加载；删除配置文件验证默认值兜底
> **Lv.2 小试牛刀**：往配置里加一个 `DisplayMode` 字段，在界面回显，验证"改配置 → 重启 → 生效"链路
> **Lv.3 融会贯通**：在 `.csproj` 里配置 `CopyToOutputDirectory=PreserveNewest`，重新发布后检查发布目录确实包含该文件
> **Lv.4 拆层挑战**：实现"配置校验 + 日志"：加载配置后校验必填项，非法值写日志并回退默认值；把配置读取封装成单例 `AppConfig`（参考 12 章 `单例模式`）
