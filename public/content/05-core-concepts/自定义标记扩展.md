# 自定义标记扩展

> [!plain] 白话理解
> WPF 内置的标记扩展已经很强了——Binding 负责数据、StaticResource 负责资源。但总有些"奇怪的换算"你不想每次都写 C# 代码来处理，比如：把 `true/false` 映射成"运行/停止"文字、把数值映射成颜色、把枚举值翻译成中文。这时候你就可以**自己写标记扩展**——继承 `MarkupExtension`，重写 `ProvideValue` 方法，在里面写你的换算逻辑。然后在 XAML 里用你的扩展就像用内置的一样：`{local:MyConverter Value}`。自定义标记扩展 = 把重复的换算逻辑"打包"成 XAML 能直接调用的函数。

> [!def] 官方定义
> 自定义标记扩展是一个继承自 `System.Windows.Markup.MarkupExtension` 抽象类的具体类，必须重写 `ProvideValue(IServiceProvider)` 方法。该方法接收的 `IServiceProvider` 参数可查询 XAML 解析上下文（如目标属性类型 `IProvideValueTarget`、URI 上下文 `IUriContext` 等）。在 XAML 中引用时，类名后缀 `Extension` 可以省略。标记扩展支持构造函数参数和命名属性参数两种方式传递数据。

> [!origin] 由来背景
> 标记扩展的设计模式源自"表达式求值"思想。在 XAML 设计之初，微软就意识到不可能预埋所有"字符串→对象"的转换需求——开发者的业务场景千奇百怪。所以 MarkupExtension 被设计成 `abstract` 类，开放给开发者自定义。这体现了 WPF 架构的核心理念：**"框架提供机制，开发者提供策略"**。Binding 能成为最强大的标记扩展，正是因为它站在 MarkupExtension 这个可扩展的框架之上。

> [!essentials] 核心要点
> - **继承 MarkupExtension 类**：这是唯一的硬性要求
> - **重写 ProvideValue 方法**：该方法返回的值会赋给目标属性，必须返回目标属性兼容的类型
> - **类名后缀 Extension**：命名约定，如 `AlarmColorExtension`，XAML 中使用 `{local:AlarmColor ...}` 省略后缀
> - **构造函数参数**：`{local:AlarmColor Red}` 中的 `Red` 对应构造函数参数，位置敏感
> - **命名属性参数**：`{local:AlarmColor Level=High}` 中的 `Level` 对应类的属性，顺序无关
> - **MarkupExtensionReturnType 特性**：标记扩展类上可加 `[MarkupExtensionReturnType(typeof(Brush))]` 提示 IDE 返回类型

> **StatusToColorExtension.cs** — 把状态文字映射为颜色
> ```csharp
> using System;
> using System.Windows.Markup;
> using System.Windows.Media;
> 
> namespace HmiDemo;
> 
> [MarkupExtensionReturnType(typeof(Brush))]
> public class StatusToColorExtension : MarkupExtension
> {
>     // 构造函数参数：状态文字
>     public string Status { get; set; }
> 
>     // 无参构造函数（XAML 要求）
>     public StatusToColorExtension() { }
> 
>     // 带参构造函数：{local:StatusToColor 运行中}
>     public StatusToColorExtension(string status)
>     {
>         Status = status;
>     }
> 
>     public override object ProvideValue(IServiceProvider serviceProvider)
>     {
>         return Status switch
>         {
>             "运行中" => new SolidColorBrush(
>                 (Color)ColorConverter.ConvertFromString("#3FB950")),
>             "报警" or "过载报警" or "故障" => new SolidColorBrush(
>                 (Color)ColorConverter.ConvertFromString("#CC2222")),
>             "待机" or "离线" => new SolidColorBrush(
>                 (Color)ColorConverter.ConvertFromString("#999999")),
>             "警告" => new SolidColorBrush(
>                 (Color)ColorConverter.ConvertFromString("#FF6B35")),
>             _ => new SolidColorBrush(Colors.Gray)
>         };
>     }
> }
> ```
>
> **ProgressToWidthExtension.cs** — 把进度值映射为宽度
> ```csharp
> using System;
> using System.Windows.Markup;
> 
> namespace HmiDemo;
> 
> [MarkupExtensionReturnType(typeof(double))]
> public class ProgressToWidthExtension : MarkupExtension
> {
>     // 构造参数：进度值 0-100
>     public double Value { get; set; }
> 
>     // 命名属性参数：最大宽度（像素）
>     public double MaxWidth { get; set; } = 300;
> 
>     public ProgressToWidthExtension() { }
> 
>     public ProgressToWidthExtension(double value)
>     {
>         Value = value;
>     }
> 
>     public override object ProvideValue(IServiceProvider serviceProvider)
>     {
>         // 进度百分比 → 实际像素宽度
>         return Math.Max(0, Math.Min(MaxWidth, MaxWidth * Value / 100.0));
>     }
> }
> ```
>
> **EnumDescExtension.cs** — 枚举值翻译为中文
> ```csharp
> using System;
> using System.ComponentModel;
> using System.Reflection;
> using System.Windows.Markup;
> 
> namespace HmiDemo;
> 
> [MarkupExtensionReturnType(typeof(string))]
> public class EnumDescExtension : MarkupExtension
> {
>     public Type EnumType { get; set; }
>     public string Value { get; set; }
> 
>     public EnumDescExtension() { }
> 
>     public EnumDescExtension(Type enumType)
>     {
>         EnumType = enumType;
>     }
> 
>     public override object ProvideValue(IServiceProvider serviceProvider)
>     {
>         if (EnumType == null || !EnumType.IsEnum)
>             return "??";
> 
>         // 反射获取枚举成员的 Description 特性
>         var members = EnumType.GetMembers();
>         var names = string.Join(" | ", 
>             System.Linq.Enumerable.Select(members, m =>
>             {
>                 var attr = m.GetCustomAttribute<DescriptionAttribute>();
>                 return attr?.Description ?? m.Name;
>             }));
>         return names;
>     }
> }
> 
> // 报警级别枚举
> public enum AlarmLevel
> {
>     [Description("提示级别 — 轻微异常")]
>     Info,
>     [Description("警告级别 — 需关注")]
>     Warning,
>     [Description("危险级别 — 立即处理")]
>     Critical
> }
> ```
>
> 三个自定义标记扩展分别演示了：
> 1. **StatusToColorExtension**：构造参数传入状态文字，返回对应颜色画刷——最简单的映射型扩展
> 2. **ProgressToWidthExtension**：构造参数 + 命名属性参数，做数值换算——带配置的计算型扩展
> 3. **EnumDescExtension**：通过 `IServiceProvider` 获取目标信息（简化版），反射读取枚举的 Description 特性

> [!scene] 适用场景
> - ✅ 数值→颜色映射（温度值→红/绿/黄）——`{local:TempToColor 85}`
> - ✅ 枚举→中文描述翻译（报警等级、设备状态、工作模式）——`{local:EnumDesc AlarmLevel.High}`
> - ✅ 数值→格式化字符串（传感器值 + 单位）——`{local:SensorFormat Value=23.5, Unit='°C'}`
> - ✅ 布尔值→可见性映射（需要反逻辑时）——`{local:InverseBool IsEnabled}`
> - ✅ 进度值→UI尺寸（进度条宽度、仪表盘角度）——`{local:ScaleToWidth Percent=75, Max=500}`
> - ❌ 复杂业务逻辑——标记扩展的 ProvideValue 会被多次调用，不适合做数据库查询、网络请求
> - ❌ 需要绑定到 ViewModel 的动态值——标记扩展在 XAML 加载时求值，不适合需要响应数据变化的场景（这种情况应该用 IValueConverter + Binding）

> [!pitfall] 常见踩坑
> - **坑1：ProvideValue 返回类型不匹配**。如果目标是 `Brush` 属性但你返回了 `string`，运行时会抛 InvalidCastException。解决方案：在扩展类上加 `[MarkupExtensionReturnType(typeof(Brush))]` 提醒自己，内部严格返回对应类型。
> - **坑2：标记扩展被多次调用**。如果同一个扩展在多个地方使用，`ProvideValue` 也会被调用多次。不要在 ProvideValue 里做耗时操作（如文件读写）。解决方案：把不变的数据在扩展类的构造函数中预先计算好（如静态字典映射），ProvideValue 只做 O(1) 查找。
> - **坑3：忘记提供无参构造函数**。XAML 解析器在遇到 `{local:MyExt Arg=value}`（只使用命名参数）时需要无参构造函数。解决方案：始终提供无参构造函数，带参构造函数作为可选。

> [!best] 最佳实践
> - 标记扩展的 ProvideValue 应保持为纯函数——相同的输入永远返回相同的结果，不依赖外部可变状态
> - 在 ProvideValue 中可以通过 `serviceProvider.GetService(typeof(IProvideValueTarget))` 获取目标对象和目标属性信息，用于更灵活的逻辑
> - 命名要有业务含义：`{local:TempToColor}` 比 `{local:Converter1}` 好得多
> - 如果逻辑变复杂（多步骤、条件分支多），考虑改用 IValueConverter + Binding 而非标记扩展——标记扩展更适合"确定性的映射"

> [!practice] 上手练习
> - **Lv.1 照猫画虎**：实现一个 `InvertBoolExtension`——接收一个 `bool` 值，返回取反后的 `bool`（用于 Visibility 等属性的逆向绑定场景）。XAML 中使用 `{local:InvertBool true}` → `false`
> - **Lv.2 小试牛刀**：实现一个 `SensorFormatExtension`——接收数值 `Value` 和单位 `Unit` 两个参数，返回格式化字符串。如 `{local:SensorFormat Value=85.3, Unit='°C'}` → `"85.3 °C"`
> - **Lv.3 融会贯通**：实现一个 `PlcAddressExtension`——接收 PLC 设备名和寄存器地址，通过 `IProvideValueTarget` 获取目标属性信息（属性名、类型），自动选择合适的 PLC 数据类型和读取方式。如 `{local:PlcAddress Device='PLC1', Register='D100'}` — 目标属性是 `double` → 自动读取 D100~D101 两个寄存器并组成 double
