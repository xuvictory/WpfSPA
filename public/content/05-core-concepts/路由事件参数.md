# 路由事件参数

> [!plain] 白话理解
> `RoutedEventArgs` 是路由事件的"快递单"——上面记载了：谁发的货（`Source`）、原始发货人（`OriginalSource`）、签收状态（`Handled`）、运送路线（路由策略）。每次事件传递，都是这份快递单在不同中转站之间流通——每个中转站（事件处理器）收到同一张单子，可以在上面做标记（设 `Handled=true`），这样后续中转站看到标记就不处理了。理解了这个快递单上的每个字段，你就理解了路由事件 80% 的用法。

> [!def] 官方定义
> `RoutedEventArgs` 是所有 WPF 路由事件的基类事件参数。核心属性包括：`RoutedEvent`（触发的是哪个路由事件对象）、`Source`（逻辑树中引发事件的元素）、`OriginalSource`（视觉树中最底层的原始源元素）、`Handled`（是否已被标记为处理）。子类 `MouseButtonEventArgs` 额外提供了 `ClickCount`、`LeftButton` 等鼠标状态；`KeyEventArgs` 额外提供了 `Key`、`KeyboardDevice` 等键盘状态。隧道和冒泡事件共享同一个 `RoutedEventArgs` 实例。

> [!origin] 由来背景
> 在 .NET 1.0 中，所有事件的参数都是 `EventArgs` 的子类，但每个事件都独立——不存在参数传递。WPF 引入路由事件后，需要事件参数能携带"传递状态"，于是 `RoutedEventArgs` 新增了 `Handled` 属性。这个设计的一个精妙之处是：隧道事件和冒泡事件使用同一个参数实例——这意味着在隧道阶段（PreviewXxx）中做的修改（如 Handled=true），会直接影响冒泡阶段是否触发。这是 WPF 输入系统实现"预览-确认"模式的基础。

> [!essentials] 核心要点
> - **Source ≠ OriginalSource**：Source 是逻辑源（XAML 中写的那个元素），OriginalSource 是视觉树最底层的元素（如 Button 内的 TextBlock）
> - **Handled 是共享状态**：隧道和冒泡阶段同一个实例，隧道设 Handled=true 会阻止冒泡
> - **RoutedEvent 区分事件类型**：可以用来判断"这个处理器被哪种事件触发了"
> - **并非所有路由事件参数都是 RoutedEventArgs**：`Button.Click` 就是基础 `RoutedEventArgs`，而 `MouseDown` 是 `MouseButtonEventArgs`

> **MainWindow.xaml.cs**
 ```csharp
using System.Text;
using System.Windows;
using System.Windows.Controls;
using System.Windows.Input;

namespace HmiDemo;

public partial class MainWindow : Window
{
    public MainWindow()
    {
        InitializeComponent();
    }

    private void Log(string prefix, RoutedEventArgs e)
    {
        var sb = new StringBuilder();
        sb.AppendLine($"━━━ {prefix} ━━━");
        sb.AppendLine($"  RoutedEvent    : {e.RoutedEvent.Name}");
        sb.AppendLine($"  RoutingStrategy: {e.RoutedEvent.RoutingStrategy}");
        sb.AppendLine($"  Source         : {e.Source.GetType().Name}");
        sb.AppendLine($"  OriginalSource : {e.OriginalSource.GetType().Name}");
        sb.AppendLine($"  Handled        : {e.Handled}");

        if (e is MouseButtonEventArgs mbe)
        {
            sb.AppendLine($"  ClickCount     : {mbe.ClickCount}");
            sb.AppendLine($"  LeftButton     : {mbe.LeftButton}");
            sb.AppendLine($"  GetPosition    : {mbe.GetPosition(this):F0}");
        }

        if (e is KeyEventArgs ke)
        {
            sb.AppendLine($"  Key            : {ke.Key}");
        }

        sb.AppendLine($"  IsSameInstance*: {(e.RoutedEvent.RoutingStrategy == RoutingStrategy.Tunnel ? "(与冒泡阶段共用实例)" : "")}");
        sb.AppendLine();

        // 追加到日志
        txtLog.Text += sb.ToString();

        // 如果勾选了"拦截"，在隧道阶段设 Handled=true
        if (chkHandled.IsChecked == true
            && e.RoutedEvent.RoutingStrategy == RoutingStrategy.Tunnel)
        {
            e.Handled = true;
            txtLog.Text += "  >>> Handled=true，后续冒泡事件不触发\n\n";
        }
    }

    // ═══════════ Window 层 ═══════════
    private void OnWindowPreviewMouseDown(object sender, MouseButtonEventArgs e)
        => Log("Window.PreviewMouseDown", e);

    private void OnWindowMouseDown(object sender, MouseButtonEventArgs e)
        => Log("Window.MouseDown", e);

    // ═══════════ Button 层 ═══════════
    private void OnBtnPreviewMouseDown(object sender, MouseButtonEventArgs e)
        => Log("Button.PreviewMouseDown", e);

    private void OnBtnMouseDown(object sender, MouseButtonEventArgs e)
        => Log("Button.MouseDown", e);

    private void OnBtnPreviewMouseUp(object sender, MouseButtonEventArgs e)
        => Log("Button.PreviewMouseUp", e);

    private void OnBtnMouseUp(object sender, MouseButtonEventArgs e)
        => Log("Button.MouseUp", e);

    private void OnBtnClick(object sender, RoutedEventArgs e)
        => Log("Button.Click (合成事件, RoutedEventArgs)", e);

    // ═══════════ 设备卡片层 ═══════════
    private void OnCardPreviewMouseDown(object sender, MouseButtonEventArgs e)
        => Log("Card.PreviewMouseDown", e);

    private void OnCardMouseDown(object sender, MouseButtonEventArgs e)
        => Log("Card.MouseDown", e);
}
 ```
>
> 运行后分别点击按钮和设备卡片，观察每个事件参数的字段值：
> - 点击按钮内的文字区域，`Source=Button` 而 `OriginalSource=TextBlock`（或 `TextBlockView`）
> - `Click` 的 RoutedEventArgs 没有 `ClickCount`（不是 MouseButtonEventArgs）
> - 勾选拦截后，隧道事件显示为已处理，冒泡阶段日志完全不出现

> [!scene] 适用场景
> ✅ 需要区分事件来自哪个控件——通过 `Source` 判断
> ✅ 需要知道视觉树最底层的点击对象——通过 `OriginalSource` 实现精确的"点击空白处关闭"逻辑
> ✅ 需要在事件处理链中"截断"事件——设置 `Handled=true`
> ✅ 需要通过 `GetPosition` 获取鼠标位置——配合拖拽、缩放等功能
> ❌ 拿 `RoutedEventArgs` 做业务数据传递——它不提供自定义数据字段，用 EventHandler<T> 自己定义

> [!pitfall] 常见踩坑
> 坑 1：**在 Click 事件中访问 `(e as MouseButtonEventArgs)?.ClickCount` 返回 null** → `Click` 是合成事件，参数是 `RoutedEventArgs` 不是 `MouseButtonEventArgs`。如果想获取鼠标信息，在 `PreviewMouseLeftButtonDown` 中获取。
>
> 坑 2：**`Source` 可能不是你想的那个类型** → 点击 Button 里的 Image，`Source=Button`（OK），但点击 Button 里的 Border 里的 StackPanel——还是 `Button`。因为逻辑路由会把 `Source` 提升到最近的逻辑父元素。如果需要精确视觉源，用 `OriginalSource`。
>
> 坑 3：**`GetPosition` 在不同元素上返回不同坐标** → `e.GetPosition(this)` 和 `e.GetPosition(null)` 不一样。`null` 表示相对于屏幕左上角。

> [!best] 最佳实践
> - 事件处理中做类型判断优先用 `if (e.Source is Button btn)`，因为 `Source` 是逻辑元素，类型稳定
> - `OriginalSource` 可能会返回系统内部视觉元素（如 `TextBlockView`），不适合做业务判断
> - 调试事件流时，在每个处理器中打日志 + 打印 `e.RoutedEvent.Name`，能快速理清触发顺序
> - 上位机中通常不需要深入关注 `OriginalSource`——`Source` 在 99% 场景下够用
