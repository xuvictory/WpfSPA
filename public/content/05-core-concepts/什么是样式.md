# 什么是样式？

> [!plain] 白话理解
> WPF 的样式（Style）就像 CSS 中的 class——你可以定义一套外观规则（字体、颜色、大小、边距...），然后把它"批处理"套用到一组同类控件上。比如你希望所有"主要按钮"都是橙色背景、白色粗体字、圆角 4px——不用在每个按钮上写三遍属性，定义一个 Style 就行。更妙的是，样式不仅管"静态外观"，还能加触发器（Trigger）——"鼠标悬停变亮""勾选时变色"，这些交互效果也能用 Style 表达。样式 = 给控件穿上一套可以复用的"外观套餐"。

> [!def] 官方定义
> Style 是 WPF 中的外观定义对象，继承自 `DispatcherObject`，包含一组 `Setter`（属性设置器）和/或 `EventSetter`（事件设置器），以及可选的 `Trigger` 集合。Style 通过 `TargetType` 指定适用的控件类型，通过 `x:Key` 提供唯一标识（隐式样式可省略 Key）。Style 支持 `BasedOn` 属性实现样式继承。当 Style 应用于控件时，其 Setter 中定义的依赖属性值会以 Style 优先级（低于本地值、高于默认值）写入控件的属性系统。

> [!origin] 由来背景
> WinForms 中没有 Style 概念——你想让 20 个按钮长一样，只能写个 `SetButtonStyle(Button btn)` 函数，在代码里循环调用。这不仅麻烦，还无法在设计器中预览效果。WPF 将 Style 做成了 XAML 原生特性：可视化的声明式定义 + 自动应用 + 继承 + 触发器。这让 WPF 的 UI 设计从"控件级"升级到"样式级"，带来了 Web 前端中 CSS 一样的复用体验，同时保留了强类型系统的编译检查。

> [!essentials] 核心要点
> - **TargetType**：指定样式适用于哪种控件（如 `Button`、`TextBox`）
> - **Setter**：核心成员，每个 Setter 设置一个属性值（`Property="Background" Value="Red"`）
> - **x:Key**：样式名称，用于显式引用（隐式样式省略 Key，靠 TargetType 自动匹配）
> - **BasedOn**：继承另一个样式，只覆盖差异部分
> - **Trigger**：条件触发器，如鼠标悬停变色、选中状态切换
> - **优先级**：本地值 > Style 中的 Setter > 默认值

> 这个例子展示了样式的四种用法：
> 1. **简单样式**（DeviceCardStyle）：纯 Setter 设置，无触发器
> 2. **文字样式**（DeviceNameStyle）：专用于 TextBlock 的字体样式
> 3. **带触发器的样式**（ActionButtonStyle）：鼠标悬停/按下效果
> 4. **样式继承**（AlarmButtonStyle）：BasedOn ActionButtonStyle，只覆盖颜色

> [!scene] 适用场景
> - ✅ 统一控件外观——所有"确认"按钮一样的颜色、所有"报警"按钮红色
> - ✅ 上位机设备状态色——正常=绿色、警告=橙色、报警=红色、离线=灰色
> - ✅ 表单输入框——所有 TextBox 统一样式（背景、边框、焦点色）
> - ✅ 带交互效果的控件——悬停高亮、按下阴影、选中变色
> - ✅ 样式继承——"基础按钮"定义通用属性，"主要按钮""危险按钮"等子样式只覆盖差异
> - ❌ 复杂控件内部结构——应该用 ControlTemplate（模板）而非 Style

> [!pitfall] 常见踩坑
> - **坑1：Style 的 Setter 设置了非依赖属性**。Style 只能设置依赖属性（DependencyProperty），对 CLR 属性设置会报编译错误（XLS0415）。解决方案：确认目标属性是依赖属性（在文档中标注为"dependency property"）。
> - **坑2：BasedOn 引用的 Key 不存在或循环引用**。BasedOn 链的样式必须在当前 Resources 或祖先 Resources 中存在，且不能形成环。解决方案：确保被继承的样式定义在使用之前（XAML 顺序上靠前），或放在 Application.Resources 中。
> - **坑3：Style 中同时定义了本地值和样式值，以为样式会覆盖**。依赖属性的优先级中，本地值（直接在控件上写 `Background="Red"`）优先级高于 Style 中的 Setter。解决方案：如果想用样式覆盖，不要在控件的 XAML 标签上设置同名属性。

> [!best] 最佳实践
> - 样式按"功能角色"命名：`PrimaryButtonStyle`、`DangerButtonStyle`、`CardStyle`，而非 `Style1`、`Style2`
> - 把通用样式放在 `App.xaml` 的 `Application.Resources` 中，页面专属样式放在各自的 Window/Page 级 Resources
> - 使用 BasedOn 建立样式层级——基础样式定义通用属性，派生样式只覆盖差异
> - 上位机的数字显示用等宽字体样式（Consolas/Cascadia Code），配合右对齐，看起来更专业

> [!practice] 上手练习
> - **Lv.1 照猫画虎**：为设备状态指示灯创建一个 Style（用 Ellipse 做 TargetType），包含 3 种状态颜色：正常绿、报警红、离线灰
> - **Lv.2 小试牛刀**：创建一个带 IsMouseOver 触发器的"传感器数据卡片"样式——默认半透明背景，悬停时变亮并显示阴影效果
> - **Lv.3 融会贯通**：设计一套完整的上位机 UI 样式体系——基础控件样式（Button、TextBox、ComboBox）+ 业务样式（DeviceCard、AlarmBadge、StatusLight）+ 样式继承链
