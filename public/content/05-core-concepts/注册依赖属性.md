# 注册依赖属性

> [!plain] 白话理解
> 注册依赖属性就像是**给汽车上牌照**。一辆裸车（`DependencyObject` 子类）出厂时没有任何自定义能力，你得去车管所（`DependencyProperty.Register`）给它办个牌照（`DependencyProperty` 静态字段），牌照上登记了车主（`ownerType`）、车型（`propertyType`）、发动机号（`PropertyMetadata`）。办完牌照，这辆车才能在"电子眼系统"（数据绑定）和"ETC 通道"（动画系统）中被识别和管理。不注册？你这车在 WPF 的高速公路上寸步难行。

> [!def] 官方定义
> `DependencyProperty.Register()` 是创建依赖属性的唯一入口。它需要一个唯一的属性名（字符串）、属性值类型（`Type`）、所有者类型（`Type`）和属性元数据（`PropertyMetadata` 或 `FrameworkPropertyMetadata`）。注册成功后返回一个 `DependencyProperty` 实例，它被 WPF 内部哈希表存储，并以 `ownerType + propertyName` 作为全局唯一键。重复注册同名属性会抛出异常。可选的回调包括：`PropertyChangedCallback`（值变化通知）、`CoerceValueCallback`（值强制调整）、`ValidateValueCallback`（值合法性校验）。

> [!origin] 由来背景
> 在最早的 WPF 设计中，依赖属性注册方案经过了多次迭代。最初考虑过用 Attribute 标记（类似 `[DependencyProperty]`），但 MS 团队最终选择了"静态字段 + Register 调用"模式，因为：(1) 编译时无法确定全局属性表，需要运行时注册；(2) 静态构造函数的执行时机是确定的（类型首次被使用前），保证了属性在访问前一定已注册；(3) 元数据在派生类中覆写 `OverrideMetadata` 是依赖属性系统的重要特性，Attribute 方案难以表达这种继承关系。

> [!essentials] 核心要点
> - **必须用 static readonly 字段**：`public static readonly DependencyProperty XxxProperty = ...`
> - **PropertyMetadata vs FrameworkPropertyMetadata**：后者提供更多标志位（AffectsRender、Inherits 等）和默认值更新回调
> - **ValidateValueCallback 先于 CoerceValueCallback**：校验不通过直接抛异常，Coercion 不会执行
> - **不同重载**：`Register`（读写）、`RegisterReadOnly`（只读）、`RegisterAttached`（附加属性）
> - **CLR 包装器不能加逻辑**：必须纯粹调用 `GetValue/SetValue`

> **TemperatureController.xaml.cs**——核心注册代码：
 ```csharp
using System.Windows;
using System.Windows.Controls;

namespace HmiDemo;

public partial class TemperatureController : UserControl
{
    // ═══ 注册 1：设定温度（TargetTemperature） ═══
    // 三个回调同时使用：Validate → Coerce → Changed
    public static readonly DependencyProperty TargetTemperatureProperty =
        DependencyProperty.Register(
            nameof(TargetTemperature),
            typeof(double),
            typeof(TemperatureController),
            new FrameworkPropertyMetadata(
                defaultValue: 25.0,
                flags: FrameworkPropertyMetadataOptions.AffectsRender,
                propertyChangedCallback: OnTargetChanged,
                coerceValueCallback: CoerceTargetTemperature),
            validateValueCallback: ValidateTargetTemperature);
    //                                    ↑ 第一个被调用：校验合法性
    //                 ↑ 第二个被调用：强制调整（Coercion）
    //                    ↑ 最后一个被调用：变化通知

    // ═══ 注册 2：当前温度（CurrentTemperature，只读） ═══
    private static readonly DependencyPropertyKey CurrentTemperaturePropertyKey =
        DependencyProperty.RegisterReadOnly(
            nameof(CurrentTemperature),
            typeof(double),
            typeof(TemperatureController),
            new PropertyMetadata(25.0));
    public static readonly DependencyProperty CurrentTemperatureProperty =
        CurrentTemperaturePropertyKey.DependencyProperty;

    // ═══ 注册 3：温控状态（只读） ═══
    private static readonly DependencyPropertyKey StatusPropertyKey =
        DependencyProperty.RegisterReadOnly(
            nameof(Status),
            typeof(string),
            typeof(TemperatureController),
            new PropertyMetadata("待设定"));
    public static readonly DependencyProperty StatusProperty =
        StatusPropertyKey.DependencyProperty;

    // ═══ CLR 包装器 ═══
    public double TargetTemperature
    {
        get => (double)GetValue(TargetTemperatureProperty);
        set => SetValue(TargetTemperatureProperty, value);
    }

    public double CurrentTemperature
    {
        get => (double)GetValue(CurrentTemperatureProperty);
        private set => SetValue(CurrentTemperaturePropertyKey, value);
    }

    public string Status
    {
        get => (string)GetValue(StatusProperty);
        private set => SetValue(StatusPropertyKey, value);
    }

    // ═══ 三个回调 ═══

    /// <summary>
    /// ValidateValueCallback：返回 false 则抛 ArgumentException
    /// 注意：这是唯一一个参数是 object 而非 DependencyObject 的回调
    /// </summary>
    private static bool ValidateTargetTemperature(object value)
    {
        double temp = (double)value;
        return !double.IsNaN(temp) && !double.IsInfinity(temp);
    }

    /// <summary>
    /// CoerceValueCallback：强制钳制温度在 -50°C ~ 300°C 之间
    /// </summary>
    private static object CoerceTargetTemperature(
        DependencyObject d, object baseValue)
    {
        double val = (double)baseValue;
        if (val < -50.0) return -50.0;
        if (val > 300.0) return 300.0;
        return val;
    }

    /// <summary>
    /// PropertyChangedCallback：目标温度变化时更新状态和UI
    /// </summary>
    private static void OnTargetChanged(DependencyObject d,
        DependencyPropertyChangedEventArgs e)
    {
        var ctrl = (TemperatureController)d;
        var newTemp = (double)e.NewValue;
        ctrl.CurrentTemperature = newTemp;  // 模拟：设定即到达
        ctrl.UpdateStatus(newTemp);
        ctrl.UpdateUI();
    }

    private void UpdateStatus(double temp)
    {
        Status = temp switch
        {
            < 0   => "低温模式",
            < 50  => "常温模式",
            < 150 => "中温模式",
            _     => "高温模式"
        };
    }

    private void UpdateUI()
    {
        txtTarget.Text = TargetTemperature.ToString("F1");
        txtCurrent.Text = CurrentTemperature.ToString("F1");
        txtStatus.Text = $"状态: {Status}";
    }

    public TemperatureController()
    {
        InitializeComponent();
        Loaded += (_, _) => UpdateUI();
    }

    private void OnDecreaseClick(object sender, RoutedEventArgs e)
    {
        TargetTemperature -= 5;  // 触发 Validate → Coerce → Changed
    }

    private void OnIncreaseClick(object sender, RoutedEventArgs e)
    {
        TargetTemperature += 5;
    }
}
 ```
>
> 当用户点击"升温"或"降温"时，执行链路为：
>
> 1. `SetValue` 调用 `ValidateTargetTemperature`（校验不是 NaN/Infinity）→ 通过
> 2. `CoerceTargetTemperature` 强制钳制到 [-50, 300] → 得到最终值
> 3. `OnTargetChanged` 更新 UI 和状态文字
>
> 如果设 TargetTemperature = 500，Coercion 会钳制到 300；如果设为 double.NaN，Validate 阶段就会抛异常。

> [!scene] 适用场景
> ✅ 自定义控件/UserControl 的任何需要绑定、样式、动画的属性
> ✅ 需要范围限制的属性——务必加 CoerceValueCallback
> ✅ 需要合法性校验的属性——加 ValidateValueCallback（比如 IP 地址格式）
> ✅ 需要属性变化驱动 UI 更新的场景——在 PropertyChangedCallback 中处理
> ❌ 简单的内部状态值——用普通 CLR 属性或私有字段

> [!pitfall] 常见踩坑
> 坑 1：**ValidateValueCallback 中写业务逻辑** → 这个回调是在属性系统内部的锁中执行的，开销过大会阻塞整个 UI 线程。解决方案：只在 Validate 中做简单的格式/范围判断，复杂逻辑放到 Changed 中异步处理。
>
> 坑 2：**CoerceValueCallback 中又修改同一个属性** → 这会造成无限循环调用。解决方案：Coercion 只返回修正后的值，不要调用 SetValue，不要修改其他可能触发回写的属性。
>
> 坑 3：**`ValidateValueCallback` 的签名不是 `DependencyObject`** → 它是 `Func<object, bool>`，不能强转成 `DependencyObject` 来访问实例。解决方案：如果校验需要实例上下文，用 `CoerceValueCallback` 代替。

> [!best] 最佳实践
> - 注册时用 `nameof()` 代替字符串字面量，重构安全
> - CoerceValueCallback 保持轻量——它会在动画每帧中被调用，不要在里面做 IO 或复杂计算
> - 如果 ValidateValueCallback 做数值范围判断，记得到 CoerceValueCallback 中也做一遍——因为动画和绑定不经过 Validate！
> - 用 `FrameworkPropertyMetadata` 而非 `PropertyMetadata`，设置正确的 Options 标志位
