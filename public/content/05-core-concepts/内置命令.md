# 内置命令

> [!plain] 白话理解
> WPF 内置了一大堆"开箱即用"的命令，存放在五个静态类中。`ApplicationCommands` 里有 Cut/Copy/Paste/Undo/Redo/Save/Open/Print——这些都是编辑器应用标配；`NavigationCommands` 里有 BrowseBack/BrowseForward/Refresh——浏览器型应用专用；`EditingCommands` 里是 ToggleBold/ToggleItalic/IncreaseFontSize——富文本编辑器专用；`ComponentCommands` 和 `MediaCommands` 各司其职。这些内置命令的好处是——TextBox 和 RichTextBox 已经**自动实现了它们的 Execute 和 CanExecute**。你只需要在 XAML 中把命令绑定到按钮上，不用写一行代码，剪贴板操作就能正常工作。

> [!def] 官方定义
> WPF 内置命令定义在五个静态类中：
>
> `ApplicationCommands`（应用级命令如 Cut、Copy、Paste、Undo、Redo、Save、Open、Print 等）、
>
> `NavigationCommands`（导航命令如 BrowseBack、BrowseForward、Refresh、Search）、
>
> `EditingCommands`（编辑命令如 ToggleBold、ToggleItalic、AlignLeft、AlignCenter、IncreaseFontSize）、
>
> `ComponentCommands`（组件命令如 MoveUp、MoveDown、ScrollPageUp）、
>
> `MediaCommands`（媒体命令如 Play、Pause、Stop、NextTrack）。
>
> 所有内置命令都使用 `RoutedUICommand` 类型，自带文本（Text）和快捷键（InputGestures）属性。

> [!origin] 由来背景
> WPF 1.0 发布时，剪贴板操作的 CM（命令管理器）非常粗糙——TextBox 默认不支持 Ctrl+C/V。WPF 团队意识到，如果每个开发者在每个 TextBox 上都手动写 KeyDown 事件判断 Ctrl+C 然后调用 Clipboard.SetText，代码质量和一致性都会很差。于是他们创建了这五类内置命令库，并让 TextBox、RichTextBox、FlowDocumentReader 等控件"预注册"了这些命令的 CommandBinding。到了 .NET 3.5 SP1，又做了性能优化——减少了 CommandManager 的轮询频率。在 WinUI 3 中，这些内置命令仍然可用。

> [!essentials] 核心要点
> - **五类内置命令库**：ApplicationCommands、NavigationCommands、EditingCommands、ComponentCommands、MediaCommands
> - **预注册控件**：TextBox → Cut/Copy/Paste/Undo/Redo；RichTextBox → 几乎所有 EditingCommands
> - **RoutedUICommand**：内置命令的基类，自带 Text 和 KeyGesture
> - **InputBindings 自动呼应**：TextBox 的 Ctrl+C 由内置命令驱动，不需要手写键盘事件
> - **可直接在 Button 上绑定**：`<Button Command="ApplicationCommands.Save"/>`

> **MainWindow.xaml.cs**
 ```csharp
using System.Windows;
using System.Windows.Controls;

namespace HmiDemo;

public partial class MainWindow : Window
{
    public MainWindow()
    {
        InitializeComponent();
    }

    // 展示选择变化（用于演示 Cut/Copy 的自动启用/禁用）
    private void OnSelectionChanged(object sender, RoutedEventArgs e)
    {
        if (sender is TextBox tb)
        {
            bool hasSelection = tb.SelectionLength > 0;
            txtLog.Text = $"焦点在: {tb.Name}\n"
                + $"选中长度: {tb.SelectionLength} 字符\n"
                + (hasSelection
                    ? "→ Cut/Copy 按钮自动启用"
                    : "→ Cut/Copy 按钮自动禁用");
        }
    }
}
 ```
>
> 运行后：选中文字 → Cut/Copy 按钮自动启用；未选中 → 自动禁用。粘贴、撤销、重做同理。这些行为**不需要一行额外代码**——WPF 内置命令系统 + TextBox 的预注册绑定做到了。

> [!scene] 适用场景
> ✅ 文本编辑类界面——利用内置 Cut/Copy/Paste/Undo/Redo
> ✅ 文档查看器——利用 NavigationCommands 的浏览导航
> ✅ 富文本编辑器——利用 EditingCommands 的全部格式化命令
> ✅ 工具栏/右键菜单中设置标准操作
> ❌ 需要自定义可执行性判断的复杂操作——用 ICommand + RelayCommand

> [!pitfall] 常见踩坑
> 坑 1：**内置命令按钮不灰/不响应——因为没有焦点控件提供 CommandBinding** → 内置命令需要当前焦点控件有对应的 CommandBinding。如果焦点在 ComboBox 上，Cut 命令可能不可用。解决方案：用 `CommandTarget` 属性显式指定命令目标。
>
> 坑 2：**Cut/Copy 在 PasswordBox 中不可用** → PasswordBox 故意禁用了剪贴板命令。解决方案：如果需要，手动实现。
>
> 坑 3：**Ctrl+C 复制不生效——焦点在 Button 上** → 内置命令的 CommandBinding 在 TextBox 中。如果焦点不在 TextBox，Ctrl+C 无效。解决方案：用 `CommandManager.AddPreviewExecutedHandler` 注册全局处理器。

> [!best] 最佳实践
> - 文本编辑功能直接依赖内置命令——不要重复造轮子
> - 用 `CommandTarget="{Binding ElementName=txtContent}"` 确保命令作用在正确的控件上
> - 内置命令按钮配合 `ToolBar` 使用，视觉效果和快捷键提示更专业
> - 如果要在自定义控件中支持内置命令，用 `CommandBindings.Add(new CommandBinding(...))` 注册
