# 什么是依赖属性？

> [!plain] 白话理解
> 依赖属性（DependencyProperty）就像是 Excel 里的**公式单元格**。普通 CLR 属性好比一个写死的数字——`Width = 100`，写完就不变了。依赖属性则像一个公式 `=A1*2 + B1`——当 A1 或 B1 变化时，结果自动更新。在 WPF 中，控件的 `Width`、`Background` 这些属性都是依赖属性，它们可以从样式继承、从父元素继承、从数据绑定获取、被动画驱动——这些"依赖"关系正是名字的由来。普通属性做不到这一点，因为它只是一个简单的 get/set 包裹的私有字段，没有"变化通知"和"动态求值"的机制。

> [!def] 官方定义
> 依赖属性是 WPF 属性系统的核心，它是一种静态注册、动态解析的属性。依赖属性通过 `DependencyProperty.Register()` 静态方法注册到一个全局的 `PropertyStore` 中，而不是存储在对象实例的私有字段里。它的值由 WPF 属性系统按照一套严格的优先级规则动态计算得出，支持数据绑定、样式、动画、继承、默认值、强制回调等多种特性。依赖属性只能定义在继承自 `DependencyObject` 的类中。

> [!origin] 由来背景
> 在 WinForms 时代，控件的属性就是简单的 CLR 属性。这带来几个痛点：(1) 如果要让一个控件的 `ForeColor` 跟主题走，必须手动监听主题变化事件逐个修改；(2) 数据绑定需要手写大量样板代码；(3) 动画需要靠 `Timer` 逐帧修改属性值，极易闪烁；(4) 属性值多了之后内存开销大——每个实例都存一份默认值。WPF 的依赖属性系统一举解决了这四个问题：通过 `DependencyProperty` 全局注册表 + `EffectiveValueEntry` 值缓存 + 属性变化通知，实现了一套高效的属性管理机制。Silverlight、UWP、WinUI、MAUI 全部沿用了这套设计。

> [!essentials] 核心要点
> - **不是普通的 get/set**：依赖属性的值不是存实例字段里，而是由 WPF 属性系统动态计算
> - **值有优先级**：动画 > 本地值 > 模板绑定 > 样式 Setter > 继承值 > 默认值，共 11 级
> - **变化可通知**：值改变时自动触发 PropertyChangedCallback，绑定的 UI 自动刷新
> - **内存高效**：未显式赋值的属性不占内存，使用全局注册的默认值
> - **必须依附 DependencyObject**：普通类不能用依赖属性，必须继承自 `DependencyObject`
> - **用 static 字段持有**：`public static readonly DependencyProperty XxxProperty = ...` 是标准模式

> **DeviceStatusBox.xaml.cs**（核心——依赖属性的定义和使用）：
 ```csharp
using System;
using System.Windows;
using System.Windows.Controls;
using System.Windows.Media;

namespace HmiDemo;

public partial class DeviceStatusBox : UserControl
{
    // ═══════════════ 依赖属性定义 ═══════════════

    // 设备名称（string 类型的依赖属性）
    public static readonly DependencyProperty DeviceNameProperty =
        DependencyProperty.Register(
            nameof(DeviceName),              // 属性名
            typeof(string),                  // 属性类型
            typeof(DeviceStatusBox),         // 所有者类型
            new PropertyMetadata(
                "未命名设备",
                OnDeviceNameChanged));       // 变化回调

    // 状态码（int）：0=离线 1=运行 2=报警
    public static readonly DependencyProperty StatusCodeProperty =
        DependencyProperty.Register(
            nameof(StatusCode),
            typeof(int),
            typeof(DeviceStatusBox),
            new PropertyMetadata(0, OnStatusCodeChanged));

    // 状态颜色（Color 派生属性，由 StatusCode 决定，只读暴露）
    private static readonly DependencyPropertyKey StatusColorPropertyKey =
        DependencyProperty.RegisterReadOnly(
            nameof(StatusColor),
            typeof(Color),
            typeof(DeviceStatusBox),
            new PropertyMetadata(Colors.Gray));
    public static readonly DependencyProperty StatusColorProperty =
        StatusColorPropertyKey.DependencyProperty;

    // 状态文字（string 派生属性）
    private static readonly DependencyPropertyKey StatusTextPropertyKey =
        DependencyProperty.RegisterReadOnly(
            nameof(StatusText),
            typeof(string),
            typeof(DeviceStatusBox),
            new PropertyMetadata("离线"));
    public static readonly DependencyProperty StatusTextProperty =
        StatusTextPropertyKey.DependencyProperty;

    // 心率（模拟值）
    public static readonly DependencyProperty HeartRateProperty =
        DependencyProperty.Register(
            nameof(HeartRate),
            typeof(int),
            typeof(DeviceStatusBox),
            new PropertyMetadata(0));

    // ═══════════════ CLR 包装器 ═══════════════
    // 注意：CLR 包装器只能调用 GetValue/SetValue，不能加任何逻辑！
    public string DeviceName
    {
        get => (string)GetValue(DeviceNameProperty);
        set => SetValue(DeviceNameProperty, value);
    }

    public int StatusCode
    {
        get => (int)GetValue(StatusCodeProperty);
        set => SetValue(StatusCodeProperty, value);
    }

    public Color StatusColor
    {
        get => (Color)GetValue(StatusColorProperty);
        private set => SetValue(StatusColorPropertyKey, value);
    }

    public string StatusText
    {
        get => (string)GetValue(StatusTextProperty);
        private set => SetValue(StatusTextPropertyKey, value);
    }

    public int HeartRate
    {
        get => (int)GetValue(HeartRateProperty);
        set => SetValue(HeartRateProperty, value);
    }

    // ═══════════════ 回调逻辑 ═══════════════

    private static void OnDeviceNameChanged(DependencyObject d,
        DependencyPropertyChangedEventArgs e)
    {
        // 设备名改了，这里可以做日志记录或校验
        var box = (DeviceStatusBox)d;
        System.Diagnostics.Debug.WriteLine(
            $"设备改名: {e.OldValue} → {e.NewValue}");
    }

    private static void OnStatusCodeChanged(DependencyObject d,
        DependencyPropertyChangedEventArgs e)
    {
        var box = (DeviceStatusBox)d;
        int code = (int)e.NewValue;
        switch (code)
        {
            case 0:  // 离线
                box.StatusColor = Colors.Gray;
                box.StatusText = "离线";
                box.HeartRate = 0;
                break;
            case 1:  // 运行
                box.StatusColor = Color.FromRgb(0x3F, 0xB9, 0x50);
                box.StatusText = "运行中";
                box.HeartRate = new Random().Next(800, 1500);
                break;
            case 2:  // 报警
                box.StatusColor = Color.FromRgb(0xD4, 0xA0, 0x17);
                box.StatusText = "报警!";
                box.HeartRate = new Random().Next(1500, 2200);
                break;
        }
    }

    public DeviceStatusBox()
    {
        InitializeComponent();
    }
}
 ```

> **MainWindow.xaml.cs**：
 ```csharp
using System.Windows;

namespace HmiDemo;

public partial class MainWindow : Window
{
    public MainWindow()
    {
        InitializeComponent();
    }

    private void OnStartMotorClick(object sender, RoutedEventArgs e)
    {
        statusBox1.StatusCode = 1;  // 运行
        txtLog.Text = ">>> M-101 已启动，心率检测开启";
    }

    private void OnStopMotorClick(object sender, RoutedEventArgs e)
    {
        statusBox1.StatusCode = 0;  // 离线
        txtLog.Text = ">>> M-101 已停机";
    }

    private void OnAlarmClick(object sender, RoutedEventArgs e)
    {
        statusBox2.StatusCode = 2;  // 报警
        txtLog.Text = ">>> VFD-01 报警！请立即处理";
    }

    private void OnOfflineClick(object sender, RoutedEventArgs e)
    {
        statusBox2.StatusCode = 0;  // 离线
        txtLog.Text = ">>> VFD-01 已离线";
    }
}
 ```
>
> 这个示例展示了依赖属性的核心能力：**修改一个属性值，多个关联属性自动联动**。当你把 `StatusCode` 从 0 改成 1，`StatusColor`、`StatusText`、`HeartRate` 三个只读依赖属性会自动更新，绑定的 UI 元素（边框颜色、指示灯、状态文字、心率数值）也会实时刷新——这就是依赖属性系统自动完成的。

> [!scene] 适用场景
> ✅ 控件的所有外观属性（Width、Background、Visibility 等）
> ✅ 需要参与数据绑定的自定义控件属性
> ✅ 需要被动画驱动的属性（如 Opacity、RenderTransform）
> ✅ 需要从父元素继承值的属性（如 DataContext、FlowDirection）
> ✅ 需要属性变化通知联动其他属性的场景（如本例 StatusCode → StatusColor）
> ❌ 简单的数据传输对象（DTO）——普通 CLR 属性就够，依赖属性太重
> ❌ 不参与 UI 的 Model 层——用 `INotifyPropertyChanged` 更合适

> [!pitfall] 常见踩坑
> 坑 1：**在 CLR 包装器里加逻辑** → `get { ... return (int)GetValue(...); }` 中写了验证或日志。WPF 框架在某些情况下会绕过 CLR 包装器直接调用 `GetValue()/SetValue()`（如数据绑定、动画），你的逻辑不会被执行。解决方案：用 `PropertyChangedCallback` 或 `CoerceValueCallback`。
>
> 坑 2：**依赖属性放在普通类中** → 编译报错或运行时崩溃。依赖属性的宿主类必须继承 `DependencyObject`，因为 `GetValue/SetValue` 是 `DependencyObject` 的方法。
>
> 坑 3：**把依赖属性写成实例字段** → `public DependencyProperty MyProp = ...` 而不是 `public static readonly`。依赖属性必须用静态字段注册，因为它属于"类型"而不是"实例"，整个 `PropertyStore` 以类型+属性名为 Key 存储值。

> [!best] 最佳实践
> - 依赖属性命名遵循 `XxxProperty` 后缀约定，CLR 包装器命名为 `Xxx`，工具链和反编译器都依赖这个命名模式
> - 用 `nameof()` 注册属性名而不是写死字符串，避免拼写错误和重命名遗漏
> - PropertyChangedCallback 方法声明为 `static`，需要访问实例时通过 `(YourType)d` 强转，避免闭包陷阱
> - 如果用只读依赖属性（`RegisterReadOnly`），`DependencyPropertyKey` 必须 `private`，确保只有该类能修改
> - 上位机中大量交互数据建议优先用依赖属性，配合 Binding 直接绑定到 UI——比手动逐个赋值高效得多
