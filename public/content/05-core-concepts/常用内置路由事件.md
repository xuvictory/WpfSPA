# 常用内置路由事件

> [!plain] 白话理解
> WPF 有超过 200 个内置路由事件，别被数量吓到——你日常上位机开发中，真正会用到的核心事件不超过 20 个。它们分为几大类：**鼠标事件**（点击、移动、滚轮）、**键盘事件**（按下、抬起）、**控件事件**（Click、SelectionChanged、TextChanged）、**生命周期事件**（Loaded、Unloaded、Initialized）、**焦点事件**（GotFocus、LostFocus）。记住这些"必考"事件就足够应付 90% 的场景了。

> [!def] 官方定义
> WPF 内置路由事件分布在 `UIElement`、`FrameworkElement`、`Control`、具体控件类等层级。`UIElement` 提供了基础的鼠标/键盘/触控/拖放事件（如 MouseLeftButtonDown、KeyDown、Drop）；`FrameworkElement` 增加了生命周期事件（Loaded、Unloaded、SizeChanged）；`Control` 增加了焦点事件（GotFocus、LostFocus）和 MouseDoubleClick；具体控件类（Button、TextBox、ListBox 等则增加了 Click、TextChanged、SelectionChanged 等控件专属事件。

> [!origin] 由来背景
> WPF 的输入系统比 WinForms 复杂得多——它需要同时支持鼠标、键盘、触控笔、触摸屏四种输入设备，每种设备都有一套路由事件。为了让开发者不至于迷失，WPF 团队将输入设备抽象为三个虚拟基类：`MouseDevice`、`KeyboardDevice`、`StylusDevice`，每种设备的原始输入先经过"隧道→源→冒泡"管道，再转换为高层控件事件（Click、TextInput 等）。你在上位机中 95% 的时间只需要处理高层控件事件，但底层输入事件在实现拖拽、热区等高级功能时非常有用。

> [!essentials] 核心要点
> - **鼠标类**：MouseLeftButtonDown/Up（点击）、MouseMove（移动）、MouseWheel（滚轮）
> - **键盘类**：KeyDown/Up（按键）、PreviewKeyDown（隧道版）
> - **控件类**：Button.Click、TextBox.TextChanged、ComboBox.SelectionChanged
> - **生命周期**：Loaded（加载完成）、Unloaded（从树移除）、Initialized（初始化完成）
> - **焦点类**：GotFocus（获得焦点）、LostFocus（失去焦点）、GotKeyboardFocus
> - **大小变化**：SizeChanged（尺寸变化）、LayoutUpdated（布局更新）

> **MainWindow.xaml.cs**
 ```csharp
using System.Windows;
using System.Windows.Controls;
using System.Windows.Input;

namespace HmiDemo;

public partial class MainWindow : Window
{
    public MainWindow()
    {
        InitializeComponent();
    }

    // ═══ 生命周期的 ═══
    private void OnWindowLoaded(object sender, RoutedEventArgs e)
        => txtLog.Text = "[Loaded] 窗口加载完成，可以开始交互";

    private void OnWindowSizeChanged(object sender, SizeChangedEventArgs e)
        => txtLog.Text = $"[SizeChanged] {e.PreviousSize.Width:F0}x{e.PreviousSize.Height:F0} → {e.NewSize.Width:F0}x{e.NewSize.Height:F0}";

    // ═══ 键盘的 ═══
    private void OnWindowKeyDown(object sender, KeyEventArgs e)
        => txtLog.Text = $"[KeyDown] {e.Key} — 可做快捷键响应";

    // ═══ TextBox 的事件 ═══
    private void OnTextChanged(object sender, TextChangedEventArgs e)
        => txtNamePreview.Text = $"当前输入: {txtName.Text}  (TextChanged 实时触发)";

    private void OnFocusChanged(object sender, RoutedEventArgs e)
    {
        string action = e.RoutedEvent == UIElement.GotFocusEvent ? "获得" : "失去";
        txtLog.Text = $"[{(action == "获得" ? "GotFocus" : "LostFocus")}] 配方名称文本框{action}焦点";
    }

    // ═══ ComboBox 的事件 ═══
    private void OnSelectionChanged(object sender, SelectionChangedEventArgs e)
    {
        if (cmbType.SelectedItem is ComboBoxItem item)
            txtTypePreview.Text = $"已选择: {item.Content}  (SelectionChanged 触发)";
    }

    // ═══ Slider 的事件 ═══
    private void OnSliderValueChanged(object sender,
        RoutedPropertyChangedEventArgs<double> e)
    {
        txtTemp.Text = $"{sldTemp.Value:F1} °C";
    }

    // ═══ Button 的事件 ═══
    private void OnSaveClick(object sender, RoutedEventArgs e)
        => txtLog.Text = "[Click] 配方已保存 ✓";

    private void OnLoadClick(object sender, RoutedEventArgs e)
        => txtLog.Text = "[Click] 配方已加载 ✓";

    private void OnClearClick(object sender, RoutedEventArgs e)
    {
        txtName.Text = "";
        cmbType.SelectedIndex = -1;
        sldTemp.Value = 0;
        txtLog.Text = "[Click] 所有输入已清空";
    }

    private void OnBtnMouseEnter(object sender, MouseEventArgs e)
        => txtLog.Text = "[MouseEnter] 鼠标进入保存按钮区域";

    private void OnBtnMouseLeave(object sender, MouseEventArgs e)
        => txtLog.Text = "[MouseLeave] 鼠标离开保存按钮区域";

    // ═══ CheckBox 的事件 ═══
    private void OnAutoSaveChanged(object sender, RoutedEventArgs e)
    {
        string state = (sender as CheckBox)?.IsChecked == true ? "开启" : "关闭";
        string name = (sender as CheckBox)?.Content?.ToString() ?? "未知";
        txtLog.Text = $"[Checked/Unchecked] {name}: {state}";
    }
}
 ```

> 这个配方编辑器涵盖了上位机开发中最常用的 10+ 种内置路由事件，每一种都有实际的可操作 UI 和日志反馈。

> [!scene] 适用场景
> ✅ Button.Click：几乎所有确认、提交、切换操作
> ✅ TextBox.TextChanged：实时搜索、输入校验、字数统计
> ✅ ComboBox.SelectionChanged：下拉选择后联动更新其他控件
> ✅ Slider.ValueChanged：数值调节、参数微调
> ✅ Loaded：初始化数据加载、启动定时器
> ✅ KeyDown：全局快捷键、回车确认、Esc 取消
> ✅ SizeChanged/WrapPanel 自适应布局

> [!pitfall] 常见踩坑
> 坑 1：**Slider.ValueChanged 在 XAML 中设置初始值时也会触发** → 如果在 XAML 给 Slider 设 `Value="80"`，加载时就会触发一次 ValueChanged。解决方案：用 `IsLoaded` 标志位跳过首次触发。
>
> 坑 2：**TextBox.TextChanged 每个字符都触发** → 如果做网络搜索（每次打字发一次请求），会严重浪费带宽。解决方案：用 `async` + `CancellationTokenSource` 实现 300ms 防抖。
>
> 坑 3：**GotFocus/LostFocus 在 WPF 中有两个版本** → `UIElement.GotFocus` 和 `UIElement.GotKeyboardFocus`。前者检查逻辑焦点（Logical Focus），后者检查键盘焦点。通常用 `GotFocus` 就行，但在复合控件场景中两者可能不同。

> [!best] 最佳实践
> - 上位机表单界面优先用 ComboBox 替代一堆单选按钮——配合 SelectionChanged 联动效率高
> - Slider 配合 TextBlock 双向显示（如上例）是最基本的工业仪表模式
> - TextChanged 不要直接绑定到业务操作——中间加防抖层
> - 窗口生命周期事件（Loaded/Unloaded）是初始化和资源清理的最佳时机

> [!practice] 上手练习
> **Lv.1 照猫画虎**：运行上面的配方编辑器，逐一操作每个控件，观察各事件触发的时机和日志输出
> **Lv.2 小试牛刀**：在 TextBox 上添加防抖逻辑——TextChanged 不再实时记录日志，而是 500ms 无输入后才记录
> **Lv.3 融会贯通**：用这些内置事件实现一个"操作日志系统"——把所有控件的操作事件（Click/TextChanged/SelectionChanged 等）统一记录到 ListBox，包含时间戳和操作详情
