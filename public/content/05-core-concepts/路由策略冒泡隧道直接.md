# 路由策略：冒泡、隧道、直接

> [!plain] 白话理解
> 路由事件有三种"旅行方式"：
> - **冒泡（Bubbling）**：像水烧开时气泡从锅底往上冒——事件从被点击的具体元素出发，一路经过父元素、祖父元素、曾祖父元素，直到顶层的 Window。大部分 WPF 事件（`MouseDown`、`KeyDown`、`Button.Click`）都是冒泡的。
> - **隧道（Tunneling）**：像地铁从地面往下钻——事件从顶层的 Window 开始，一路经过子元素、孙子元素，最终到达被点击的那个元素。隧道事件以 `Preview` 开头，如 `PreviewMouseDown`、`PreviewKeyDown`。
> - **直接（Direct）**：像打电话——事件只在源元素触发，不往上也不往下传递。只有明确用 `AddHandler(routedEvent, handler, true)` 且传入 `handledEventsToo` 才能拦截。用的很少，主要是为特殊场景保留。

> [!def] 官方定义
> WPF 路由事件有三种策略，由 `RoutingStrategy` 枚举定义：`Bubbling`（冒泡，值 0）从事件源沿可视树向上传递到根元素；`Tunneling`（隧道，值 1）从根元素沿可视树向下传递到事件源；`Direct`（直接，值 2）仅在事件源处理，不沿树传递。隧道事件和冒泡事件成对出现——`PreviewXxx`（隧道）先触发，接着是 `Xxx`（冒泡）。两者共享同一个 `RoutedEventArgs` 实例，隧道事件的 `Handled=true` 会阻止后续冒泡事件触发。

> [!origin] 由来背景
> 路由策略的灵感来自 HTML DOM 事件模型中的"捕获阶段"和"冒泡阶段"——W3C 在 DOM Level 2 Events 中定义了这两个阶段。WPF 团队借鉴了这个设计但做了改进：
>
> (1) 它不只是 "捕获→目标→冒泡"，而是一整条连续的树路径；
>
> (2) 增加了 `Direct` 策略保持向后兼容；
>
> (3) 隧道和冒泡共享同一个事件参数，使得中间层可以在隧道阶段修改参数影响冒泡阶段。
>
> 这种设计让"权限拦截"、"输入验证"、"全局快捷键"等高级场景变得异常简洁。

> [!essentials] 核心要点
> - **隧道先行，冒泡在后**：`PreviewXxx` → `Xxx`，中间没有任何其他事件插入
> - **共享同一实例**：隧道和冒泡是同一个 `RoutedEventArgs` 对象，隧道中 `Handled=true` 会阻止冒泡
> - **`e.Handled` 截断传递**：设置为 `true` 后，控件树上游（冒泡）或下游（隧道）不再收到
> - **Bubbling 最常用**：80% 的路由事件都是冒泡策略
> - **Direct 几乎不用**：只在自定义路由事件中有极少数应用场景

> **MainWindow.xaml.cs**
 ```csharp
using System;
using System.Windows;
using System.Windows.Controls;
using System.Windows.Input;

namespace HmiDemo;

public partial class MainWindow : Window
{
    public MainWindow()
    {
        InitializeComponent();
    }

    private void Log(string level, string msg)
    {
        txtLog.Text += $"[{level}] {msg}\n";
        txtLog.ScrollToEnd();
    }

    // ═══════════ 隧道事件（从上到下：Window → Grid → Outer → Middle → Inner） ═══════════

    private void OnWindowPreviewMouseDown(object sender, MouseButtonEventArgs e)
        => Log("隧道-1", "Window.PreviewMouseDown ← 隧道阶段起点");

    private void OnGridPreviewMouseDown(object sender, MouseButtonEventArgs e)
        => Log("隧道-2", $"Grid.PreviewMouseDown");

    private void OnBorderOuterPreviewMouseDown(object sender, MouseButtonEventArgs e)
        => Log("隧道-3", $"Outer.PreviewMouseDown");

    private void OnBorderMiddlePreviewMouseDown(object sender, MouseButtonEventArgs e)
    {
        Log("隧道-4", $"Middle.PreviewMouseDown (到达中部)");
        if (chkHandled.IsChecked == true)
        {
            e.Handled = true;
            Log("拦截", "⚠ Middle 设 Handled=true，冒泡阶段将不会触发！");
        }
    }

    private void OnBorderInnerPreviewMouseDown(object sender, MouseButtonEventArgs e)
        => Log("隧道-5", "Inner.PreviewMouseDown ← 隧道阶段终点（事件源）");

    // ═══════════ 冒泡事件（从下到上：Inner → Middle → Outer → Grid → Window） ═══════════

    private void OnBorderInnerMouseDown(object sender, MouseButtonEventArgs e)
        => Log("冒泡-1", "Inner.MouseDown ← 冒泡阶段起点（事件源）");

    private void OnBorderMiddleMouseDown(object sender, MouseButtonEventArgs e)
        => Log("冒泡-2", $"Middle.MouseDown");

    private void OnBorderOuterMouseDown(object sender, MouseButtonEventArgs e)
        => Log("冒泡-3", $"Outer.MouseDown");

    private void OnGridMouseDown(object sender, MouseButtonEventArgs e)
        => Log("冒泡-4", $"Grid.MouseDown");

    private void OnWindowMouseDown(object sender, MouseButtonEventArgs e)
        => Log("冒泡-5", "Window.MouseDown ← 冒泡阶段终点");

    private void OnClearLogClick(object sender, RoutedEventArgs e)
        => txtLog.Text = "";
}
 ```
>
> 运行后点击红色区域（Inner Border），日志输出会清晰展示：
> - **隧道阶段**：Window → Grid → Outer → Middle → Inner（从上到下）
> - **冒泡阶段**：Inner → Middle → Outer → Grid → Window（从下到上）
> - 勾选"中层拦截"后再点，隧道在 Middle 处设 `Handled=true`，后续**整个冒泡阶段都不触发**

> [!scene] 适用场景
> ✅ 冒泡：父容器统一监听子元素事件（如工具条管理所有按钮的 Click）
> ✅ 冒泡：子控件操作后通知父级更新状态
> ✅ 隧道：全局快捷键/全局输入拦截（如在 Window 层拦截所有 Escape 键）
> ✅ 隧道：操作前校验/权限检查（Preview 阶段有"否决权"）
> ✅ 隧道：拖放操作中预处理鼠标事件
> ❌ 不需要经过控件树的独立对象间通信——用 EventAggregator 或 Mediator 模式

> [!pitfall] 常见踩坑
> 坑 1：**隧道 + 冒泡用了两个不同的 EventArgs** → 实际它们是**同一个对象**。如果在隧道阶段的 Middle 层修改 `e.Handled=true`，冒泡阶段的 Outer/Grid/Window 全收不到事件。
>
> 坑 2：**`Click` 是冒泡事件，但没有对应的 `PreviewClick`** → `Click` 是 `ButtonBase` 内部通过 `MouseLeftButtonDown`+`MouseLeftButtonUp` 组合生成的"合成事件"，没有对应的隧道事件。需要用 `PreviewMouseLeftButtonDown` 做前置拦截。
>
> 坑 3：**在隧道阶段 `e.Handled=true` 后，这个事件对大部分控件就"消失"了** → 除非用 `AddHandler(routedEvent, handler, handledEventsToo: true)` 显式指定监听已处理事件。

> [!best] 最佳实践
> - 上位机中，用 Window 层隧道事件做全局 Esc 退出全屏/F11 切换等快捷键
> - 父容器用冒泡统一管理子控件事件时，别忘了判断 `e.Source` 类型——子元素的子元素的事件也会冒上来
> - 不要在路由事件处理器中加 Thread.Sleep 或同步网络访问——所有处理都在 UI 线程
> - 如果多个层级都注册了同类型事件，注意处理顺序，防止重复处理同一操作
