# 依赖属性应用场景

> [!plain] 白话理解
> 依赖属性不是"什么时候用"的问题，而是"你能不用的时候才不用"的问题——在 WPF 的 UI 层，你几乎**每时每刻都在和依赖属性打交道**。你在 XAML 里写 `Width="200"`，`Width` 是依赖属性；你绑定数据 `{Binding Name}`，`Text` 是依赖属性；你给按钮加了样式让背景变蓝，`Background` 是依赖属性；你写了一个淡入动画，`Opacity` 是依赖属性。依赖属性就像 WPF 的"地下电力系统"——你平时看不到，但没有了它，WPF 的整个大厦都会停电。

> [!def] 官方定义
> 依赖属性主要在以下六个应用场景中发挥核心作用：数据绑定（Data Binding）、样式（Styles）、动画（Animations）、属性值继承（Property Value Inheritance）、数据验证（Validation）和自定义控件开发（Custom Control Authoring）。每一种场景都利用了依赖属性系统的不同特性：绑定利用变化通知、样式利用值优先级、动画利用动态值计算、继承利用 FrameworkPropertyMetadataOptions.Inherits 标志位、验证利用 ValidateValueCallback、自定义控件则综合使用所有特性。

> [!origin] 由来背景
> WPF 刚发布时（2006 年），很多从 WinForms 转过来的开发者都问："依赖属性到底有什么用？我直接用 string、int、bool 不也挺好？"微软的 PM 们写了一篇著名的 MSDN 文章《Why DependencyProperties?》，列举了 7 个没有依赖属性就做不到的事情，排在第一位的就是数据绑定。后来随着 MVVM 模式的流行和 WPF 在企业级开发中的普及，依赖属性的应用场景被反复验证和扩展，形成了今天这六大场景的共识。

> [!essentials] 核心要点
> - **数据绑定**：依赖属性作为 Binding 目标，自动接收和更新绑定的数据
> - **样式与模板**：Setter 和 Trigger 通过优先级系统修改值，不影响本地值
> - **动画**：`BeginAnimation` 驱动依赖属性值连续变化，动画结束后可回退或保持
> - **属性值继承**：DataContext、FontSize 等沿逻辑树自动向下传递
> - **数据验证**：通过 ValidateValueCallback 或绑定 ValidationRule 实现
> - **自定义控件**：将自己的属性暴露给 XAML、Binding 和 Style 的唯一方式

> 一个上位机场景的"电机控制面板"，在单个界面中展示依赖属性的四大核心应用场景：

> **MotorViewModel.cs**——数据层：
 ```csharp
using System.ComponentModel;
using System.Runtime.CompilerServices;

namespace HmiDemo;

public class MotorViewModel : INotifyPropertyChanged
{
    private double _speed;
    public double Speed
    {
        get => _speed;
        set { _speed = value; OnPropertyChanged(); }
    }

    private string _status = "停止";
    public string Status
    {
        get => _status;
        set { _status = value; OnPropertyChanged(); }
    }

    public event PropertyChangedEventHandler? PropertyChanged;
    protected void OnPropertyChanged([CallerMemberName] string? name = null)
        => PropertyChanged?.Invoke(this, new PropertyChangedEventArgs(name));
}
 ```

> **MainWindow.xaml.cs**：
 ```csharp
using System.Windows;
using System.Windows.Media.Animation;

namespace HmiDemo;

public partial class MainWindow : Window
{
    private readonly MotorViewModel _motor = new MotorViewModel();

    public MainWindow()
    {
        InitializeComponent();
        DataContext = _motor;  // 场景4：DataContext 沿树向下继承
    }

    private void OnStartClick(object sender, RoutedEventArgs e)
    {
        _motor.Speed = 1500;
        _motor.Status = "运行中 — 转速 1500 RPM";
    }

    private void OnStopClick(object sender, RoutedEventArgs e)
    {
        // 场景3：用动画平滑降到 0
        var anim = new DoubleAnimation(_motor.Speed, 0,
            new Duration(System.TimeSpan.FromSeconds(1.5)))
        {
            DecelerationRatio = 0.5  // 减速缓出
        };
        // 场景1：Slider 的值通过 Binding 驱动 ProgressBar 值
        // 场景3：动画驱动 Speed 属性平滑变化
        _motor.Status = "正在停机...";
        anim.Completed += (_, _) => _motor.Status = "已停止";
        sliderSpeed.BeginAnimation(
            System.Windows.Controls.Primitives.RangeBase.ValueProperty, anim);
    }

    private void OnAnimateClick(object sender, RoutedEventArgs e)
    {
        _motor.Status = "动画演示中...";
        // 场景3：动画驱动 Slider.Value（依赖属性），再通过 Binding 联动 ViewModel
        var anim = new DoubleAnimation(0, 3000,
            new Duration(System.TimeSpan.FromSeconds(2)))
        {
            AutoReverse = true,
            RepeatBehavior = new RepeatBehavior(2)
        };
        anim.Completed += (_, _) => _motor.Status = "动画结束";
        sliderSpeed.BeginAnimation(
            System.Windows.Controls.Primitives.RangeBase.ValueProperty, anim);
    }
}
 ```
>
> 这个面板浓缩了依赖属性四大场景：
> - **场景1 数据绑定**：Slider.Value ↔ ViewModel.Speed ↔ ProgressBar.Value 三向绑定
> - **场景2 样式**：DataTrigger 自动改变 ProgressBar 颜色，转速为 0 时变灰
> - **场景3 动画**：`BeginAnimation` 驱动 Slider（依赖属性）平滑变化，联动整个绑定链
> - **场景4 值继承**：DataContext 从 Window 自动继承到所有子控件；FontSize 跨层级继承

> [!scene] 适用场景
> ✅ 数据绑定：任何需要 UI 与数据自动同步的地方，这是依赖属性最常见的用途
> ✅ 样式：统一控件外观、主题切换、状态驱动变色（如上例 DataTrigger）
> ✅ 动画：平滑过渡、加载效果、数值仪表的指针运动
> ✅ 值继承：DataContext（MVVM 基石）、FontSize/FontFamily（全局字体）、FlowDirection（国际化）
> ✅ 自定义控件：封装可复用的 UI 组件，将状态暴露为依赖属性供外部 Binding
> ❌ 纯数据计算——没有 UI 关联的逻辑层，用普通 CLR 属性

> [!pitfall] 常见踩坑
> 坑 1：**动画结束后 Slider 无法手动拖动** → 因为 `FillBehavior="HoldEnd"` 的动画会"锁死"依赖属性的值。解决方案：在 `Completed` 事件中调用 `BeginAnimation(RangeBase.ValueProperty, null)` 移除动画，再用 `SetValue` 固化动画终值。
>
> 坑 2：**值继承"不生效"——子元素设置了本地值** → 本地值的优先级高于继承值。如果子元素 XAML 中写了 `FontSize="12"`，父元素再怎么改 FontSize 都不会影响子元素。解决方案：子元素不设置该属性，让继承自然生效。
>
> 坑 3：**大量动画同时运行导致卡顿** → 每个动画每帧都会触发 CoerceValueCallback 和 PropertyChangedCallback。解决方案：合并动画到 `Storyboard`，降低 `DesiredFrameRate`，或者用 CompositionTarget.Rendering 手工控制帧率。

> [!best] 最佳实践
> - Binding 是最常用的依赖属性场景，掌握它就能解决 90% 的 UI 更新需求
> - 样式不要过于复杂——如果一个 Style 超过 30 行，考虑拆分成多个 Style 或改用模板
> - 动画优先用 XAML 中的 `Storyboard` 声明，代码中的 `BeginAnimation` 适合动态场景
> - 值继承是 WPF 的高级特性——不是所有属性都能继承，需要显式设置 `FrameworkPropertyMetadataOptions.Inherits`
> - 上位机中常用组合：Binding（数据驱动） + DataTrigger（状态变色） + Storyboard（报警闪烁）
