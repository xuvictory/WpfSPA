# 注册自定义路由事件

> [!plain] 白话理解
> 注册自定义路由事件就像是**在控件上开设了一个"事件广播站"**。当你自己写了一个自定义控件（比如"设备仪表盘"），你想让外界知道"仪表盘的指针到达了警戒线"。普通 CLR 事件只能通知直接订阅者，但路由事件可以让这个通知沿着控件树一路向上传递——父容器、爷爷容器、甚至整个窗口都能"监听到"这个设备报警了。注册过程很简单：用 `EventManager.RegisterRoutedEvent` 注册、声明 CLR 事件包装器、在合适时机 `RaiseEvent` 触发。

> [!def] 官方定义
> 自定义路由事件通过 `EventManager.RegisterRoutedEvent(string name, RoutingStrategy strategy, Type handlerType, Type ownerType)` 注册。它返回一个 `RoutedEvent` 实例，必须用 `public static readonly` 字段持有。CLR 事件包装器使用 `add { AddHandler(XxxEvent, value); }` 和 `remove { RemoveHandler(XxxEvent, value); }` 模式，将 CLR 事件的订阅/取消订阅映射到 WPF 的路由事件管理器。触发事件调用 `RaiseEvent(new RoutedEventArgs(XxxEvent, this))`。

> [!origin] 由来背景
> WPF 团队在最初实现路由事件时，考虑了两种注册方案：一种是内部 API（像依赖属性那样全托管），另一种是显式注册。最终选择了显式注册，因为路由事件需要复杂的路由判定算法（沿可视树查找监听器），这部分逻辑如果对开发者隐藏会非常危险——错误的参数组合可能在运行时静默失败。`EventManager.RegisterRoutedEvent` 的四个参数分别控制路由策略、处理器签名、所有者类型，任何错误都能在注册时立即暴露。

> [!essentials] 核心要点
> - **用 static readonly 字段持有**：`public static readonly RoutedEvent XxxEvent = EventManager.RegisterRoutedEvent(...)`
> - **CLR 包装器必须用 AddHandler/RemoveHandler 模式**：不是简单 delegate 的 `+=` / `-=`
> - **RaiseEvent 触发**：`RaiseEvent(new RoutedEventArgs(XxxEvent, this))`
> - **隧道+冒泡成对注册**：通常是两个 RoutedEvent（一个是 Tunnel，一个是 Bubble）
> - **路由策略决定传递方向**：选择 Bubbling 或 Tunneling

> [!example] 完整示例
>
> 自定义一个"报警仪表盘"控件，当数值超过阈值时触发自定义路由事件 `AlarmTriggered`，让父容器统一响应：
>
> **AlarmGauge.cs**——自定义控件 + 路由事件：
 ```csharp
using System;
using System.Windows;
using System.Windows.Controls;
using System.Windows.Media;
using System.Windows.Shapes;

namespace HmiDemo;

public class AlarmGauge : Control
{
    // ═══ 注册路由事件 ═══
    public static readonly RoutedEvent AlarmTriggeredEvent =
        EventManager.RegisterRoutedEvent(
            "AlarmTriggered",            // 事件名称
            RoutingStrategy.Bubble,      // 冒泡策略
            typeof(RoutedEventHandler),  // 处理器签名
            typeof(AlarmGauge));         // 所有者类型

    // ═══ CLR 事件包装器 ═══
    public event RoutedEventHandler AlarmTriggered
    {
        add => AddHandler(AlarmTriggeredEvent, value);
        remove => RemoveHandler(AlarmTriggeredEvent, value);
    }

    // ═══ 依赖属性 ═══
    public static readonly DependencyProperty ValueProperty =
        DependencyProperty.Register(
            nameof(Value), typeof(double), typeof(AlarmGauge),
            new FrameworkPropertyMetadata(0.0,
                FrameworkPropertyMetadataOptions.AffectsRender,
                OnValueChanged));

    public double Value
    {
        get => (double)GetValue(ValueProperty);
        set => SetValue(ValueProperty, value);
    }

    public static readonly DependencyProperty AlarmThresholdProperty =
        DependencyProperty.Register(
            nameof(AlarmThreshold), typeof(double), typeof(AlarmGauge),
            new PropertyMetadata(80.0));

    public double AlarmThreshold
    {
        get => (double)GetValue(AlarmThresholdProperty);
        set => SetValue(AlarmThresholdProperty, value);
    }

    private static void OnValueChanged(DependencyObject d,
        DependencyPropertyChangedEventArgs e)
    {
        var gauge = (AlarmGauge)d;
        gauge.InvalidateVisual();

        // 检查是否触发报警
        double newVal = (double)e.NewValue;
        double oldVal = (double)e.OldValue;
        if (newVal >= gauge.AlarmThreshold
            && oldVal < gauge.AlarmThreshold)
        {
            // ═══ 触发自定义路由事件 ═══
            var args = new RoutedEventArgs(AlarmTriggeredEvent, gauge);
            gauge.RaiseEvent(args);
        }
    }

    protected override void OnRender(DrawingContext dc)
    {
        var w = ActualWidth; var h = ActualHeight;
        dc.DrawRectangle(
            new SolidColorBrush(Color.FromRgb(0x16, 0x1B, 0x22)),
            null, new Rect(0, 0, w, h));

        double ratio = Value / 100.0;
        var color = Value >= AlarmThreshold
            ? Color.FromRgb(0xCC, 0x22, 0x22)
            : Color.FromRgb(0x3F, 0xB9, 0x50);

        // 仪表条
        dc.DrawRectangle(new SolidColorBrush(color), null,
            new Rect(0, 0, w * ratio, h));

        // 阈值线
        double lineX = w * (AlarmThreshold / 100.0);
        dc.DrawLine(new Pen(Brushes.Yellow, 1),
            new Point(lineX, 0), new Point(lineX, h));

        // 数值文字
        var text = new FormattedText(
            $"{Value:F1}%  (报警阈值: {AlarmThreshold}%)",
            System.Globalization.CultureInfo.CurrentCulture,
            FlowDirection.LeftToRight,
            new Typeface("Consolas"), 12,
            Brushes.White, 1.0);
        dc.DrawText(text,
            new Point(10, (h - text.Height) / 2));
    }

    static AlarmGauge()
    {
        DefaultStyleKeyProperty.OverrideMetadata(
            typeof(AlarmGauge),
            new FrameworkPropertyMetadata(typeof(AlarmGauge)));
    }
}
 ```
>
> **MainWindow.xaml**——父容器监听自定义路由事件：
 ```xml
<Window x:Class="HmiDemo.MainWindow"
        xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
        xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"

          local:AlarmGauge.AlarmTriggered="OnAnyAlarmTriggered">

 ```
>
> **MainWindow.xaml.cs**
 ```csharp
using System.Windows;

namespace HmiDemo;

public partial class MainWindow : Window
{
    public MainWindow()
    {
        InitializeComponent();
    }

    /// <summary>
    /// 统一处理所有仪表冒泡上来的 AlarmTriggered 事件
    /// </summary>
    private void OnAnyAlarmTriggered(object sender, RoutedEventArgs e)
    {
        // e.Source 是触发事件的 AlarmGauge 实例
        if (e.Source is AlarmGauge gauge)
        {
            txtLog.Text = $"[报警!] Value={gauge.Value:F1}%, "
                + $"Threshold={gauge.AlarmThreshold}%\n"
                + $"  事件源: {e.Source.GetType().Name}\n"
                + $"  路由事件: {e.RoutedEvent.Name} (Bubble)\n"
                + $"  父容器 Grid 收到冒泡事件 ✓";
        }
    }

    private void OnRaiseAlarmClick(object sender, RoutedEventArgs e)
    {
        // 把仪表2的值推到阈值以上——触发 AlarmTriggered 路由事件
        gauge2.Value = 55;  // 从 45 → 55，跨越阈值 50
    }
}
 ```
>
> 点击"制造报警"按钮后，`gauge2.Value` 从 45 变成 55（跨越了报警阈值 50），`OnValueChanged` 回调检测到跨越后调用 `RaiseEvent`，事件沿可视树冒泡——最终到达 `Grid`，被 `OnAnyAlarmTriggered` 捕获。这就是自定义路由事件的完整流程。

> [!scene] 适用场景
> ✅ 自定义控件有"事件通知"需求——让外部容器响应（如上例报警）
> ✅ 希望父容器统一管理自定义控件的状态变化事件
> ✅ 自定义控件需要"冒泡通知"功能（如导航栏中的"当前项改变"事件）
> ✅ 让控件使用者可以在任何层级注册事件处理器
> ❌ 简单的内部计算通知——用普通 CLR 事件就够了，不需要路由开销

> [!pitfall] 常见踩坑
> 坑 1：**用普通 delegate 语法代替 AddHandler/RemoveHandler** → `public event RoutedEventHandler Xxx;` 的自动 `+=/-=` 是普通的 multicast delegate，不会注册到 WPF 事件路由系统。这样父容器无法通过冒泡收听到事件。必须手动写 `add/remove { AddHandler/RemoveHandler }`。
>
> 坑 2：**忘记在 RaiseEvent 中传入 RoutedEvent** → `new RoutedEventArgs(AlarmTriggeredEvent, this)` 缺了 RoutedEvent 参数，事件触发后沿着树查找不到匹配的处理器。
>
> 坑 3：**隧道事件和冒泡事件同时注册时事件嵌套调用** → 如果在冒泡事件的处理器中又触发了另一个隧道事件，可能造成事件递归。解决方案：用 `_isRaising` 标志位防止重入。

> [!best] 最佳实践
> - 自定义路由事件推荐使用冒泡策略——让父容器能统一监听
> - 事件参数如果需要传递自定义数据，继承 `RoutedEventArgs` 创建子类
> - 路由事件命名避开 WPF 内置前缀：不用 `Preview` 开头（隧道事件专属）
> - 只在值真正"跨越"阈值时才触发事件——不要在每次 Value 变化时都触发
