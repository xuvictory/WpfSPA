# 数据验证

> [!plain] 白话理解
> 数据绑定的双向绑定很棒，但用户可能输入非法值——给"温度上限"输入 `999`（实际范围 0~200）、给设备 IP 输入 `hello world`。WPF 的数据验证就是在数据写入 ViewModel 之前加一道"安检门"：不合法？打回去，同时 UI 上显示红色边框提醒用户。三种验证方式按简洁度排序：(1) 在属性 setter 中抛异常（最简单）；(2) 用 `ValidationRule` 子类做规则验证；(3) 实现 `IDataErrorInfo` 或 `INotifyDataErrorInfo` 做 Model 级别的验证。上位机界面中，数据校验是必须的——任何输错的参数都可能触发设备异常。

> [!def] 官方定义
> WPF 数据绑定框架支持三层验证机制：(1) `ExceptionValidationRule`——捕获数据源属性 setter 中抛出的异常，自动将异常消息显示在 UI 上；(2) 自定义 `ValidationRule`——在绑定更新数据源之前执行，返回 `ValidationResult`（成功或失败+错误消息）；(3) `IDataErrorInfo` / `INotifyDataErrorInfo`——在 ViewModel 中实现，提供属性级别的错误信息给 UI。验证结果通过 `Validation.Errors` 附加属性暴露，可用 ErrorTemplate 自定义错误提示样式。

> [!origin] 由来背景
> WinForms 的数据验证需要通过 `Validating` 事件手动实现——每个控件一个事件处理器，代码重复率极高。WPF 一开始就认识到验证应该和绑定深度集成——你把验证规则写到 `Binding.ValidationRules` 集合中，绑定在更新数据前自动执行验证。`IDataErrorInfo` 是 .NET 2.0 引入的恐龙技术，WPF 3.0 支持了它。`INotifyDataErrorInfo` 是 .NET 4.5 的改进版——支持异步验证和多错误消息。在 CommunityToolkit.Mvvm 中，`[ObservableProperty]` 配合 `[Required]` / `[Range]` 等 DataAnnotation 自动生成 IDataErrorInfo。

> [!essentials] 核心要点
> - **三层验证**：异常验证（最简单）→ ValidationRule（独立可复用）→ IDataErrorInfo（MVVM 标准）
> - **Validation.ErrorTemplate**：自定义错误提示外观（默认是红色边框）
> - **Validation.HasError**：附加属性，检查是否有验证错误
> - **Validation.Errors**：附加属性，获取错误集合
> - **NotifyOnValidationError=true**：允许监听 Validation.Error 路由事件

> [!example] 完整示例
>
> 一个设备参数配置表单——三层验证方式对比：
>
> **ConfigViewModel.cs**
 ```csharp
using System;
using System.ComponentModel;
using System.Runtime.CompilerServices;

namespace HmiDemo;

public class ConfigViewModel : INotifyPropertyChanged, IDataErrorInfo
{
    private double _targetTemp = 85.0;
    public double TargetTemp
    {
        get => _targetTemp;
        set
        {
            // 方式1：异常验证——setter 中抛异常
            if (value < 0 || value > 200)
                throw new ArgumentException("温度范围: 0°C ~ 200°C");
            _targetTemp = value;
            OnPropertyChanged();
        }
    }

    private int _motorSpeed;
    public int MotorSpeed
    {
        get => _motorSpeed;
        set { _motorSpeed = value; OnPropertyChanged(); }
    }

    private string _ipAddress = "192.168.1.100";
    public string IPAddress
    {
        get => _ipAddress;
        set { _ipAddress = value; OnPropertyChanged(); }
    }

    // ═══ IDataErrorInfo — 方式3：Model 级验证 ═══
    public string this[string columnName]
    {
        get
        {
            return columnName switch
            {
                nameof(MotorSpeed) => MotorSpeed is < 0 or > 3000
                    ? "转速范围: 0 ~ 3000 RPM" : null!,
                nameof(IPAddress) => !System.Net.IPAddress.TryParse(IPAddress, out _)
                    ? "无效的 IP 地址格式" : null!,
                _ => null!
            };
        }
    }

    public string Error => null!;

    public event PropertyChangedEventHandler? PropertyChanged;
    protected void OnPropertyChanged([CallerMemberName] string? n = null)
        => PropertyChanged?.Invoke(this, new PropertyChangedEventArgs(n));
}
 ```
>
> **IPValidationRule.cs**——自定义 ValidationRule：
 ```csharp
using System.Globalization;
using System.Net;
using System.Windows.Controls;

namespace HmiDemo;

public class IPValidationRule : ValidationRule
{
    public override ValidationResult Validate(object value, CultureInfo cultureInfo)
    {
        string? input = value?.ToString();
        if (string.IsNullOrWhiteSpace(input))
            return new ValidationResult(false, "IP 地址不能为空");

        // 格式校验
        if (!IPAddress.TryParse(input, out _))
            return new ValidationResult(false, $"无效的 IP 格式: {input}");

        // 禁止特殊 IP
        if (input.StartsWith("127."))
            return new ValidationResult(false, "不允许使用回环地址 (127.x.x.x)");

        return ValidationResult.ValidResult;
    }
}
 ```

> [!scene] 适用场景
> ✅ 数字范围校验——温度、转速、压力
> ✅ 格式校验——IP 地址、端口号、序列号
> ✅ 必填校验——设备名称不能为空
> ✅ 业务规则校验——"最大值"必须大于"最小值"
> ❌ 只在 Model 层做的纯数据校验——不需要 UI 反馈

> [!pitfall] 常见踩坑
> 坑 1：**只写了 ValidatesOnExceptions=True 但 setter 没抛异常** → 如果 setter 只是 `_field=value` 不校验，异常验证不生效。解决方案：在 setter 中加范围判断并 throw。
>
> 坑 2：**ValidationRule 中 Validate 返回 null → 运行时异常** → 必须返回 `new ValidationResult(false, "消息")` 或 `ValidationResult.ValidResult`。
>
> 坑 3：**IDataErrorInfo 索引器返回 null 但绑定仍报错** → 如果语法中没写 `ValidatesOnDataErrors=true`，IDataErrorInfo 不生效。

> [!best] 最佳实践
> - 简单范围校验用 setter 异常验证 + `ValidatesOnExceptions=True`——最简单
> - 可复用的格式校验用 ValidationRule——跨界面共用
> - MVVM 标准用 IDataErrorInfo/INotifyDataErrorInfo——属性级错误信息
> - 用 ErrorTemplate 美化验证提示——默认红色边框不够明显
