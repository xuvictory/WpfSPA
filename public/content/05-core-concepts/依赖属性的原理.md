# 依赖属性的原理

> [!plain] 白话理解
> 依赖属性的底层原理可以用**酒店房卡系统**来理解。普通 CLR 属性就像每个房间门上贴的纸质号码牌（每个实例自己存自己的值）。依赖属性则是：每个房间号对应酒店前台的一个**电子系统**——你刷卡（调用 `GetValue`），系统查数据库（`PropertyStore`）返回当前房间状态。如果这间房没被修改过（未设置本地值），系统就用"连锁酒店标准配置"（默认值）；如果总公司发了新标准（样式 Setter），系统自动覆盖；如果临时 VIP 入住（动画在运行），临时值优先。这种**集中管理、动态计算**的架构，就是 WPF 依赖属性系统高效运作的秘密。

> [!def] 官方定义
> 依赖属性系统由三个核心组件构成：
>
> `DependencyProperty`（属性标识符，全局唯一）、`DependencyObject`（宿主对象，提供 `GetValue/SetValue` 方法）、
>
> 和内部 `EffectiveValueEntry` 数组（值存储）。
>
> 每个 `DependencyObject` 内部维护一个稀疏数组，按属性全局索引号（`GlobalIndex`）存取值。
>
> 未显式赋值的属性不使用存储空间。
>
> 属性值的实际确定遵循 11 级优先级规则：强制值（Coercion）→ 活动动画 → 本地值 → 模板绑定 → 隐式样式 → 样式触发 → 模板触发 → 样式 Setter → 默认样式 → 继承值 → 默认值。

> [!origin] 由来背景
> WinForms 控件的属性约有 50-80 个，但 99% 的应用只修改其中不到 10 个。然而，每个 `Button` 实例都要为全部 80 个属性分配内存（哪怕只用了默认值），这是巨大的浪费。WPF 的属性系统设计目标就是**按需分配**——只在"属性值被显式修改过"时才消耗内存。同时，`Trigger`、`Storyboard`、`Binding` 这些高级机制都需要一个能拦截属性读写的中间层，这正是依赖属性能同时实现"稀疏存储"和"值拦截计算"的原因。

> [!essentials] 核心要点
> - **稀疏存储**：默认值不占内存，只有被修改过的属性才在 `EffectiveValueEntry` 数组中占据条目
> - **优先级计算**：`GetValue()` 不是简单读字段，而是按 11 级优先级逐级查找，返回第一个命中的值
> - **全局索引**：每个 `DependencyProperty` 在注册时分配一个全局唯一的 `GlobalIndex`，作为内部数组下标
> - **变化通知**：`SetValue()` 调用后触发 `PropertyChangedCallback` 和强制回调链路，驱动 UI 刷新
> - **线程亲和性**：`DependencyObject` 创建线程和访问线程必须一致（STA 线程模型限制）

> [!example] 完整示例
>
> 下面代码演示了依赖属性值优先级的完整链路——从默认值到动画驱动：
>
> **自定义控件：PriorityDemoControl**
 ```csharp
using System.Windows;
using System.Windows.Controls;
using System.Windows.Media;

namespace HmiDemo;

public class PriorityDemoControl : Control
{
    // 注册一个带多层默认值演示的依赖属性
    public static readonly DependencyProperty PressureProperty =
        DependencyProperty.Register(
            nameof(Pressure),
            typeof(double),
            typeof(PriorityDemoControl),
            new FrameworkPropertyMetadata(
                100.0,                              // 默认值（最低优先级）
                FrameworkPropertyMetadataOptions.AffectsRender,
                OnPressureChanged,
                CoercePressure));                   // 强制回调（最高优先级）

    public double Pressure
    {
        get => (double)GetValue(PressureProperty);
        set => SetValue(PressureProperty, value);
    }

    private static object CoercePressure(DependencyObject d, object baseValue)
    {
        double val = (double)baseValue;
        // Coercion 优先级最高——强制钳制在允许范围内
        if (val < 0) return 0.0;
        if (val > 500.0) return 500.0;
        return val;
    }

    private static void OnPressureChanged(DependencyObject d,
        DependencyPropertyChangedEventArgs e)
    {
        var ctrl = (PriorityDemoControl)d;
        System.Diagnostics.Debug.WriteLine(
            $"压力变化: {e.OldValue:F1} → {e.NewValue:F1}");
        ctrl.InvalidateVisual();  // 触发重绘
    }

    // 读取当前值的来源——演示优先级
    public string GetValueSource()
    {
        var source = DependencyPropertyHelper
            .GetValueSource(this, PressureProperty);
        return $"BaseValueSource: {source.BaseValueSource}";
    }

    static PriorityDemoControl()
    {
        DefaultStyleKeyProperty.OverrideMetadata(
            typeof(PriorityDemoControl),
            new FrameworkPropertyMetadata(typeof(PriorityDemoControl)));
    }

    protected override void OnRender(DrawingContext dc)
    {
        base.OnRender(dc);
        var w = ActualWidth; var h = ActualHeight;
        // 深色背景
        dc.DrawRectangle(
            new SolidColorBrush(Color.FromRgb(0x16, 0x1B, 0x22)),
            null, new Rect(0, 0, w, h));
        // 压力条
        double ratio = Pressure / 500.0;
        var barColor = ratio > 0.8
            ? Color.FromRgb(0xCC, 0x22, 0x22)
            : ratio > 0.5
                ? Color.FromRgb(0xD4, 0xA0, 0x17)
                : Color.FromRgb(0x3F, 0xB9, 0x50);
        dc.DrawRectangle(
            new SolidColorBrush(barColor), null,
            new Rect(0, 0, w * ratio, h));
        // 文字
        var text = new FormattedText(
            $"{Pressure:F1} PSI",
            System.Globalization.CultureInfo.CurrentCulture,
            FlowDirection.LeftToRight,
            new Typeface("Consolas"), 14,
            Brushes.White, 1.0);
        dc.DrawText(text, new Point(10, (h - text.Height) / 2));
    }
}
 ```

> **MainWindow.xaml.cs**：
 ```csharp
using System.Windows;
using System.Windows.Media.Animation;

namespace HmiDemo;

public partial class MainWindow : Window
{
    public MainWindow()
    {
        InitializeComponent();
        Loaded += (_, _) => ShowCurrentState();
    }

    private void ShowCurrentState()
    {
        txtSource.Text = $"当前值: {pressureBar.Pressure:F1} | "
            + pressureBar.GetValueSource();
    }

    private void OnClearValueClick(object sender, RoutedEventArgs e)
    {
        // ClearValue 清除本地值，让样式生效
        pressureBar.ClearValue(PriorityDemoControl.PressureProperty);
        txtLog.Text = "ClearValue：本地值被清除，回退到样式 Setter 的 250";
        ShowCurrentState();
    }

    private void OnSetValueClick(object sender, RoutedEventArgs e)
    {
        // 本地值，优先级高于样式 Setter
        pressureBar.Pressure = 400;
        txtLog.Text = "SetValue(400)：本地值设为 400，覆盖样式的 250";
        ShowCurrentState();
    }

    private void OnAnimateClick(object sender, RoutedEventArgs e)
    {
        // 动画运行时优先级最高（除了 Coercion）
        var anim = new DoubleAnimation
        {
            From = 0, To = 450,
            Duration = System.TimeSpan.FromSeconds(2),
            AutoReverse = false
        };
        pressureBar.BeginAnimation(
            PriorityDemoControl.PressureProperty, anim);
        txtLog.Text = "BeginAnimation：动画值覆盖本地值，Coercion 仍然钳制 ≤500";
        anim.Completed += (_, _) =>
        {
            txtLog.Text = "动画结束，值回退到之前的本地值 400";
            ShowCurrentState();
        };
    }

    private void OnBeyondClick(object sender, RoutedEventArgs e)
    {
        // Coercion 强制钳制——优先级最高
        pressureBar.Pressure = 800;
        txtLog.Text = "SetValue(800)：Coercion 强制钳制到 500！优先级高于一切";
        ShowCurrentState();
    }
}
 ```
>
> 运行后你会看到：本地值(180) > 样式(250) > 默认(100)。`ClearValue` 后值变回 250；动画运行时值被动画驱动；即使手动设 800，Coercion 也会强制钳制回 500。这就是依赖属性 11 级优先级的实际体现。

> [!scene] 适用场景
> ✅ 需要精确控制属性"最终取值"的自定义控件开发（如 <0 钳制为 0）
> ✅ 调试"为啥属性值不是我设的？"——用 `DependencyPropertyHelper.GetValueSource()` 排查
> ✅ 理解 WPF 内部机制后优化默认样式和资源继承
> ✅ 解决样式不生效、动画覆盖不了绑定值等问题
> ❌ 不需要深入了解原理的简单应用开发——会用就行

> [!pitfall] 常见踩坑
> 坑 1：**"样式没生效"其实是值优先级问题** → 设置了样式但本地也设了值（`<Button Width="100"`），本地值优先级高于样式 Setter。解决方案：用 `ClearValue()` 清除本地值，或者不在 XAML 中设置本地值。
>
> 坑 2：**动画结束后值回退到本地值** → 因为动画"活动期"优先级高，"失效期"就回退。解决方案：用 `FillBehavior="HoldEnd"` 让动画保持终值（但注意这可能阻止后续修改），或者在 `Completed` 事件中用 `SetValue` 固化终值。
>
> 坑 3：**Coercion 回调写成死循环** → 在 Coercion 中又修改了触发 Coercion 的属性。Coercion 是最高优先级回调，循环调用会栈溢出。

> [!best] 最佳实践
> - 自定义控件中，对需要范围限制的属性（如温度 -50~200）务必加上 CoerceValueCallback
> - 排查属性值异常时，第一步就用 `DependencyPropertyHelper.GetValueSource()` 查看值来源
> - 不要把 Coercion 当成业务逻辑的入口——它会被频繁调用（包括动画每帧），只做范围钳制
> - 了解 `FrameworkPropertyMetadataOptions` 标志位：`AffectsRender` 触发重绘、`AffectsMeasure` 触发重新测量、`Inherits` 实现值继承
