# 自定义命令

> [!plain] 白话理解
> WPF 内置命令只覆盖了"通用操作"（剪切、复制、粘贴、打开、保存等），但你的上位机业务中要的是"启动电机"、"打开阀门"、"清零计数器"、"导出报表"——这些只能自定义。自定义命令本质就是实现 `ICommand` 接口的一个类，把"做什么"写在 `Execute` 里，把"能不能做"写在 `CanExecute` 里。和内置命令的区别只有一个：自定义的 ICommand 不需要 CommandBinding——直接把它作为 ViewModel 的属性暴露，UI 通过 `{Binding XxxCommand}` 绑上去就行了。

> [!def] 官方定义
> 自定义命令是实现了 `ICommand` 接口的类，通常配合 ViewModel 使用。它不像 `RoutedCommand` 那样沿控件树路由，而是作为 ViewModel 的普通属性直接绑定到控件的 `Command` 属性上。自定义命令的核心职责是：在 ViewModel 中定义业务操作逻辑，通过 `Execute` 执行、通过 `CanExecute` 控制可用性、通过 `CanExecuteChanged` 事件通知 UI 刷新。参数通过 `CommandParameter` 绑定额外传递。

> [!origin] 由来背景
> WPF 1.0 的命令系统主要面向 RoutedCommand（路由命令），但很快开发者发现 RoutedCommand 有几个致命缺陷：(1) 它必须和 UI 元素耦合（需要 CommandTarget）；(2) CanExecute 更新依赖于 CommandManager 的轮询；(3) 代码量巨大——每个自定义操作要写一个 RoutedUICommand 静态字段 + CommandBinding + Executed/CanExecute 两个事件处理器。Josh Smith 在 2008 年发表了经典的《WPF Apps With The Model-View-ViewModel Design Pattern》，其中提出的 `RelayCommand` 模式彻底改变了这个局面——它用委托把 ICommand 的实现精简到了 10 行代码。

> [!essentials] 核心要点
> - **标准模式是 RelayCommand**：一个可复用的泛型类，构造时传入 Execute 和 CanExecute 委托
> - **不依赖路由**：自定义 ICommand 不走控件树，直接方法调用
> - **CommandParameter 传参**：XAML 中 `CommandParameter="{Binding}"` 传递上下文数据
> - **比 RoutedCommand 轻量得多**：不需要 CommandBinding、不需要 RoutedUICommand、不需要静态注册
> - **ViewModel 是命令的家**：所有命令定义为 ViewModel 的 `public ICommand XxxCommand { get; }`

> [!example] 完整示例
>
> 一个设备控制面板——6 个自定义命令，管理 3 台设备的启动/停止：
>
> **DeviceItem.cs**——设备数据模型：
 ```csharp
using System.ComponentModel;
using System.Runtime.CompilerServices;

namespace HmiDemo;

public class DeviceItem : INotifyPropertyChanged
{
    public string Name { get; set; } = "";
    public string Type { get; set; } = "";

    private string _status = "停止";
    public string Status
    {
        get => _status;
        set { _status = value; OnPropertyChanged(); }
    }

    public event PropertyChangedEventHandler? PropertyChanged;
    protected void OnPropertyChanged([CallerMemberName] string? n = null)
        => PropertyChanged?.Invoke(this, new PropertyChangedEventArgs(n));
}
 ```
>
> **DevicePanelViewModel.cs**——命令的定义中心：
 ```csharp
using System.Collections.ObjectModel;
using System.ComponentModel;
using System.Runtime.CompilerServices;
using System.Windows;
using System.Windows.Input;

namespace HmiDemo;

public class DevicePanelViewModel : INotifyPropertyChanged
{
    public ObservableCollection<DeviceItem> Devices { get; } = new();

    // ═══ 6 个自定义命令 ═══
    // 每台设备对应 1 个启动命令 + 1 个停止命令
    public ICommand StartMotorCommand { get; }
    public ICommand StopMotorCommand { get; }
    public ICommand StartVfdCommand { get; }
    public ICommand StopVfdCommand { get; }
    public ICommand StartPlcCommand { get; }
    public ICommand StopPlcCommand { get; }

    private string _log = "";
    public string Log
    {
        get => _log;
        set { _log = value; OnPropertyChanged(); }
    }

    public DevicePanelViewModel()
    {
        // 初始化设备列表
        Devices.Add(new DeviceItem { Name = "电机 M-101", Type = "电机", Status = "停止" });
        Devices.Add(new DeviceItem { Name = "变频器 VFD-01", Type = "变频器", Status = "停止" });
        Devices.Add(new DeviceItem { Name = "PLC-CPU2", Type = "PLC", Status = "停止" });

        // ═══ 自定义命令——用委托注入逻辑 ═══
        StartMotorCommand = new RelayCommand(
            _ => StartDevice("电机", Devices[0]),
            _ => Devices[0].Status == "停止");

        StopMotorCommand = new RelayCommand(
            _ => StopDevice("电机", Devices[0]),
            _ => Devices[0].Status == "运行中");

        StartVfdCommand = new RelayCommand(
            _ => StartDevice("变频器", Devices[1]),
            _ => Devices[1].Status == "停止");

        StopVfdCommand = new RelayCommand(
            _ => StopDevice("变频器", Devices[1]),
            _ => Devices[1].Status == "运行中");

        StartPlcCommand = new RelayCommand(
            _ => StartDevice("PLC", Devices[2]),
            _ => Devices[2].Status == "停止");

        StopPlcCommand = new RelayCommand(
            _ => StopDevice("PLC", Devices[2]),
            _ => Devices[2].Status == "运行中");
    }

    private void StartDevice(string type, DeviceItem device)
    {
        device.Status = "运行中";
        Log = $"[{type}] {device.Name} 已启动 — {System.DateTime.Now:T}";
        RefreshCommands();
    }

    private void StopDevice(string type, DeviceItem device)
    {
        device.Status = "停止";
        Log = $"[{type}] {device.Name} 已停机 — {System.DateTime.Now:T}";
        RefreshCommands();
    }

    // 状态改变后刷新所有命令的 CanExecute
    private void RefreshCommands()
    {
        CommandManager.InvalidateRequerySuggested();
    }

    public event PropertyChangedEventHandler? PropertyChanged;
    protected void OnPropertyChanged([CallerMemberName] string? n = null)
        => PropertyChanged?.Invoke(this, new PropertyChangedEventArgs(n));
}
 ```
>

>
> 6 个自定义命令全部定义在 ViewModel 中，UI 通过绑定即可——不需要 CommandBinding、不需要 RoutedCommand、不需要 XAML 的事件处理器。

> [!scene] 适用场景
> ✅ MVVM 架构的所有操作——每个 ViewModel 操作对应一个自定义命令
> ✅ 需要根据多个条件动态判断执行能力的操作
> ✅ 需要携带复杂参数的命令——通过 `CommandParameter` 绑定传递
> ✅ 多个控件绑定同一个命令实现统一操作
> ❌ 简单的一次性操作——用抽象命令反而增加复杂度

> [!pitfall] 常见踩坑
> 坑 1：**CanExecute 中返回了正确值但 UI 不刷新** → 需要调用 `CommandManager.InvalidateRequerySuggested()` 通知 WPF 重新查询所有命令的 CanExecute。
>
> 坑 2：**在 DataTemplate 内绑定命令时用了 `{Binding SomeCommand}` 但找不到** → DataTemplate 内的 DataContext 是列表项，而命令在 ViewModel 上。解决方案：`{Binding DataContext.SomeCommand, RelativeSource={RelativeSource AncestorType=Window}}`。
>
> 坑 3：**命令的 Execute 中操作 UI 控件** → 违反了 MVVM 原则。解决方案：操作 ViewModel 属性，通过 Binding 间接驱动 UI。

> [!best] 最佳实践
> - 一个 ViewModel 对应一组命令——命令数 ≤ 操作数 × 2（启动/停止成对）
> - 命令构造函数中传入条件回调——让 CanExecute 逻辑内聚在 ViewModel
> - 上位机中常用模式：`StartXxxCommand` + `StopXxxCommand` 成对出现
> - 复杂条件判断（多字段联合判定）在 ViewModel 中封装为一个布尔方法
