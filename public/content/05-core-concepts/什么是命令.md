# 什么是命令

> [!plain] 白话理解
> 回想一下你最初写 WPF 的方式：每个按钮一个 `Click="OnXxxClick"` 事件处理器。按钮多了，代码散落一地。更麻烦的是——如果你的工具条上有个"保存"按钮，菜单里也有个"保存"菜单项，还有个 Ctrl+S 快捷键——这三个操作要做同一件事，你就得在三处分别注册事件处理器。**命令（Command）**就是用来解决这个问题的：它把"做什么"（Execute）和"能不能做"（CanExecute）抽象成一个独立的对象，按钮、菜单、快捷键都可以绑定到同一个命令上。命令知道当前能不能执行（按条件自动禁用按钮），执行逻辑只写一份。这就是 WPF 命令系统的核心价值。

> [!def] 官方定义
> WPF 命令系统基于 `ICommand` 接口，包含两个核心方法：`Execute(object? parameter)`（执行命令逻辑）和 `CanExecute(object? parameter)`（判断命令是否可执行），以及一个 `CanExecuteChanged` 事件（通知 UI 重新查询可执行状态）。WPF 提供了六类内置命令库：`ApplicationCommands`、`NavigationCommands`、`EditingCommands`、`ComponentCommands`、`MediaCommands` 和自定义命令。命令通过 `CommandBinding` 与控件关联，`CommandTarget` 指定命令的目标元素。

> [!origin] 由来背景
> WinForms 时代，实现"保存按钮 + 保存菜单 + Ctrl+S"的统一操作，通常做法是三个事件处理器都调用同一个 `Save()` 方法。但还有一个问题没解决：当文档没被修改时，"保存"按钮应该变灰。WinForms 中你需要手动在多个地方 `.Enabled = false`——极易出现"菜单灰了但按钮还亮着"的不一致。WPF 引入了完整的命令系统，灵感来自设计模式中的 Command 模式（GoF），并将其深度集成到 UI 框架中——控件监听 `CanExecuteChanged` 事件自动刷新可用状态。

> [!essentials] 核心要点
> - **命令四要素**：命令对象（ICommand）、命令源（Button/MenuItem/KeyGesture）、命令目标（操作哪个控件）、命令绑定（CommandBinding）
> - **ICommand 两个方法**：Execute（执行）、CanExecute（可否执行）
> - **UI 自动响应**：CanExecuteChanged 触发后，绑定的控件自动刷新 IsEnabled 状态
> - **内置命令库**：ApplicationCommands（Cut/Copy/Paste/Undo/Redo 等）
> - **WPF 命令不是 RoutedCommand 才有路由**：RoutedCommand 自带冒泡路由，ICommand 是纯接口

> [!example] 完整示例
>
> 一个上位机配方管理界面——演示命令的统一管理、自动禁用、快捷键绑定：
>
> **RecipeViewModel.cs**
 ```csharp
using System;
using System.ComponentModel;
using System.Runtime.CompilerServices;
using System.Windows.Input;

namespace HmiDemo;

public class RecipeViewModel : INotifyPropertyChanged
{
    private string _recipeName = "配方-001";
    public string RecipeName
    {
        get => _recipeName;
        set { _recipeName = value; OnPropertyChanged(); OnPropertyChanged(nameof(IsModified)); }
    }

    private string _originalName = "配方-001";
    public bool IsModified => RecipeName != _originalName;

    private string _log = "";
    public string Log
    {
        get => _log;
        set { _log = value; OnPropertyChanged(); }
    }

    // ═══ 命令定义 ═══
    public ICommand SaveCommand { get; }
    public ICommand ResetCommand { get; }
    public ICommand LoadCommand { get; }
    public ICommand ExitCommand { get; }

    public RecipeViewModel()
    {
        SaveCommand = new RelayCommand(
            _ => ExecuteSave(),
            _ => IsModified);  // 只有修改过才能保存

        ResetCommand = new RelayCommand(
            _ => ExecuteReset(),
            _ => IsModified);  // 只有修改过才能重置

        LoadCommand = new RelayCommand(
            _ => ExecuteLoad());

        ExitCommand = new RelayCommand(
            _ => ExecuteExit());
    }

    private void ExecuteSave()
    {
        _originalName = RecipeName;
        OnPropertyChanged(nameof(IsModified));
        Log = $"[保存] 配方 '{RecipeName}' 已保存 — {DateTime.Now:T}";
    }

    private void ExecuteReset()
    {
        RecipeName = _originalName;
        Log = $"[重置] 配方已恢复到 '{RecipeName}'";
    }

    private void ExecuteLoad()
    {
        Log = $"[加载] 打开配方选择窗口... (模拟)";
    }

    private void ExecuteExit()
    {
        Log = $"[退出] 应用程序即将关闭...";
        System.Windows.Application.Current.Shutdown();
    }

    // ═══ INotifyPropertyChanged ═══
    public event PropertyChangedEventHandler? PropertyChanged;
    protected void OnPropertyChanged([CallerMemberName] string? name = null)
        => PropertyChanged?.Invoke(this, new PropertyChangedEventArgs(name));
}
 ```
>
> **RelayCommand.cs**
 ```csharp
using System;
using System.Windows.Input;

namespace HmiDemo;

public class RelayCommand : ICommand
{
    private readonly Action<object?> _execute;
    private readonly Func<object?, bool>? _canExecute;

    public RelayCommand(Action<object?> execute,
        Func<object?, bool>? canExecute = null)
    {
        _execute = execute;
        _canExecute = canExecute;
    }

    public bool CanExecute(object? parameter)
        => _canExecute?.Invoke(parameter) ?? true;

    public void Execute(object? parameter)
        => _execute(parameter);

    public event EventHandler? CanExecuteChanged
    {
        add => CommandManager.RequerySuggested += value;
        remove => CommandManager.RequerySuggested -= value;
    }
}
 ```

> 运行后观察：修改配方名称 → "保存"和"重置"按钮自动变亮；点击保存 → 按钮变灰；按 Ctrl+S 同样生效。

> [!scene] 适用场景
> ✅ 同一操作需要多种触发方式（按钮 + 菜单 + 快捷键 + 工具栏）
> ✅ 操作有"可用/不可用"状态需要 UI 自动同步
> ✅ MVVM 架构——让 ViewModel 持有命令，View 通过 Binding 绑定
> ✅ 操作日志、权限校验等横切关注点——命令层统一拦截
> ❌ 简单的、不可复用的单次事件——直接用 Click="..." 更简单

> [!pitfall] 常见踩坑
> 坑 1：**用 RoutedUICommand 注册自定义命令，但 CanExecute 不更新** → 内置路由命令的 CanExecute 更新依赖 CommandManager.RequerySuggested，在复杂场景中可能不触发。解决方案：IVM 中手动调用 `CommandManager.InvalidateRequerySuggested()`。
>
> 坑 2：**按钮绑定命令后 IsEnabled=true 但还是灰的** → 检查 CanExecute 返回值。如果返回 false，按钮自动禁用——这正是命令系统的核心特性，不是 Bug。
>
> 坑 3：**CommandBinding 绑在错误的层级上** → RoutedCommand 沿树冒泡，如果 CommandBinding 在按钮内部而命令目标在外部，绑定可能找不到。

> [!best] 最佳实践
> - 新项目直接用 ICommand + RelayCommand，不要用 RoutedUICommand（太重且耦合 UI）
> - 命令命名用 `XxxCommand` 后缀：`SaveCommand`、`DeleteCommand`、`RefreshCommand`
> - CanExecute 逻辑要轻量——它会被频繁调用（每次 UI 事件后都可能触发），不要在里面做 IO
> - 同一个 Command 实例可以绑定到多个控件——这正是命令系统的设计目标
