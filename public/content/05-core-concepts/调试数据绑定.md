# 调试数据绑定

> [!plain] 白话理解
> WPF 数据绑定有个"暗黑面"：当绑定失败时，它不会崩溃，不会弹窗，不会在界面上打叉——而是**静默失败**。你写了 `{Binding Speed}`，DataContext 里没有 `Speed` 属性，文本框就显示空，没有任何提示。这对开发体验极其不友好。好在 WPF 提供了两层调试手段：(1) **Output 窗口**——Visual Studio 的调试输出中能看到绑定错误（路径找不到、类型转换失败）；(2) **PresentationTraceSources**——在 Binding 上设置追踪级别，把绑定细节打印到 Output 窗口。这两招用好了，绑定调试不再靠猜。

> [!def] 官方定义
> WPF 数据绑定调试有三种方式：(1) 绑定引擎自动将绑定错误写入 `System.Diagnostics.Debug` 输出流（Visual Studio 的"输出"窗口 → 选择"调试"）；(2) 在 Binding 上设置 `PresentationTraceSources.TraceLevel` 附加属性为 `High` 或 `None`，打印绑定全程的详细日志；(3) 第三方工具 Snoop / WPF Inspector，通过可视化树检查每个控件的 DataContext 和绑定状态。错误会以 `System.Windows.Data Error: N` 的格式输出，N 是错误代码（4=路径错误、5=类型转换失败、40=绑定到已处理的源事件）。

> [!origin] 由来背景
> WPF 1.0 发布后，"绑定静默失败"是最受诟病的体验问题。2008 年，微软的调试工程师决定添加 `PresentationTraceSources.TraceLevel` 附加属性——这是一个底层 Tracing 框架的 UI 包装。有趣的是，这个属性本身也是一种"附加属性"，通过 `System.Diagnostics.PresentationTraceSources.SetTraceLevel()` 方法设置。2009 年 Snoop 工具出现，提供了可视化调试方式。2012 年 Runtime 4.5 改进了错误消息的清晰度。

> [!essentials] 核心要点
> - **Output 窗口**：VS 输出窗口（调试模式）自动显示绑定错误
> - **TraceLevel=High**：`xmlns:diag="clr-namespace:System.Diagnostics;assembly=WindowsBase"` → `diag:PresentationTraceSources.TraceLevel=High`
> - **常见错误码**：4=路径错误、5=类型转换失败、40=源异常
> - **Snoop 工具**：可视化检查 DataContext、绑定路径和当前值
> - **确认 DataContext**：最常见的问题是 DataContext 为 null 或不是预期的对象

> - `System.Windows.Data Error: 40 : BindingExpression path error: 'SpeedWrite' property not found ...`

> [!scene] 适用场景
> ✅ 绑定不生效时排查——先看 Output 窗口
> ✅ 复杂绑定链路——用 TraceLevel=High 追踪每一步
> ✅ DataContext 继承链搞不清——用 Snoop 可视化
> ✅ 新上手一个项目——先把所有隐藏的绑定错误清掉
> ❌ 生产环境——TraceLevel 会影响性能，发布时务必关掉

> [!pitfall] 常见踩坑
> 坑 1：**Output 窗口有大量绑定错误但界面看起来正常** → 这些"隐藏错误"迟早会出问题。解决方案：把 Output 窗口清空，运行一遍应用，处理掉所有绑定错误。
>
> 坑 2：**TraceLevel=High 在用户机器上也会输出（性能影响）** → 发布版本必须去掉 TraceLevel。解决方案：用 `#if DEBUG` 条件编译或发布前批量移除。
>
> 坑 3：**WPF 绑定错误被淹没在大量 Output 中** → VS 输出窗口搜索 "System.Windows.Data Error" 精确定位。

> [!best] 最佳实践
> - 开发阶段：所有关键绑定加 FallbackValue——绑定的定失败至少能看到兜底
> - 上手新项目：清掉所有 Output 窗口的绑定错误（错误 0 容忍）
> - 用 Snoop 而非 TraceLevel 做日常调试——Snoop 更快更直观
> - TraceLevel 仅在深埋 Bug 时使用——它会输出大量日志

> [!practice] 上手练习
> **Lv.1 照猫画虎**：运行上面的演示，打开 VS 输出窗口观察绑定错误信息
