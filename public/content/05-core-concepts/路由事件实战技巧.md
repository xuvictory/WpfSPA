# 路由事件实战技巧

> [!plain] 白话理解
> 前面的文章讲完了路由事件的"是什么"和"怎么用"，这篇来聊"怎么用得好"——那些老手上位机程序员在项目中积累的实战经验。比如：怎么用一个事件处理器处理 50 个按钮、怎么给控件的"原生"事件加上额外数据、怎么做事件防抖避免高频触发、怎么在 MVVM 中用路由事件而不破坏架构。这些技巧不是 API 文档里写的，而是踩过坑之后总结出来的。

> [!def] 官方定义
> 路由事件实战技巧指的是在实际项目中高效使用路由事件的设计模式和编码规范，包括但不限于：统一事件管理（Event Aggregation）、`AddHandler` 的 `handledEventsToo` 参数、`RegisterClassHandler` 在静态构造函数中注册类级处理器、事件防抖（Debounce）和节流（Throttle）、路由事件与 MVVM 绑定的集成模式（EventTrigger、Behavior、Attached Behavior）、以及性能优化（避免在高频事件中做重计算）。

> [!origin] 由来背景
> WPF 路由事件的设计目标是灵活性和可扩展性，但这种灵活性也带来了"有多种写法"的问题——同一个需求（比如"按钮点击后做某事"）可以用 Click 事件、可以用 Command 绑定、可以用 EventTrigger、可以用 Attached Behavior。每个新手都会经历"先随便写、发现架构崩了、再重构"的过程。本文汇总了上位机开发中 6 个最常见的最优实践模式。

> [!essentials] 核心要点
> - **统一事件管理**：父容器统一监听子元素事件，减少 `+=` 散落
> - **handledEventsToo**：`AddHandler(event, handler, true)` 第三参数让处理器连"已处理事件"也能收到
> - **防抖/节流**：高频事件（MouseMove、TextChanged）加延迟限制，保护性能
> - **MVVM 集成**：用 EventTrigger 或 Behavior 桥接 View 事件和 ViewModel 命令
> - **RegisterClassHandler**：类级别的静态事件注册，不用等到实例创建

> **RelayCommand.cs**——MVVM 命令基础：
 ```csharp
using System;
using System.Windows.Input;

namespace HmiDemo;

public class RelayCommand : ICommand
{
    private readonly Action<object?> _execute;
    private readonly Func<object?, bool>? _canExecute;

    public RelayCommand(Action<object?> execute, Func<object?, bool>? canExecute = null)
    {
        _execute = execute;
        _canExecute = canExecute;
    }

    public bool CanExecute(object? parameter) => _canExecute?.Invoke(parameter) ?? true;
    public void Execute(object? parameter) => _execute(parameter);

    public event EventHandler? CanExecuteChanged
    {
        add => CommandManager.RequerySuggested += value;
        remove => CommandManager.RequerySuggested -= value;
    }
}
 ```

> **MainViewModel.cs**
 ```csharp
using System;
using System.ComponentModel;
using System.Runtime.CompilerServices;
using System.Windows.Input;

namespace HmiDemo;

public class MainViewModel : INotifyPropertyChanged
{
    private string _mousePos = "移动鼠标...";
    public string MousePos
    {
        get => _mousePos;
        set { _mousePos = value; OnPropertyChanged(); }
    }

    private string _log = "";
    public string Log
    {
        get => _log;
        set { _log = value; OnPropertyChanged(); }
    }

    public ICommand DeviceCommand { get; }

    public MainViewModel()
    {
        DeviceCommand = new RelayCommand(param =>
        {
            Log = $"[MVVM Command] 执行: {param}\n{Log}";
        });
    }

    public event PropertyChangedEventHandler? PropertyChanged;
    protected void OnPropertyChanged([CallerMemberName] string? name = null)
        => PropertyChanged?.Invoke(this, new PropertyChangedEventArgs(name));
}
 ```

> **MainWindow.xaml.cs**
 ```csharp
using System;
using System.Threading;
using System.Threading.Tasks;
using System.Windows;
using System.Windows.Controls;
using System.Windows.Input;

namespace HmiDemo;

public partial class MainWindow : Window
{
    private CancellationTokenSource? _debounceCts;

    public MainWindow()
    {
        InitializeComponent();
        DataContext = new MainViewModel();
    }

    // ═══ 技巧1：父容器统一管理所有按钮事件 ═══
    private void OnDeviceButtonClick(object sender, RoutedEventArgs e)
    {
        if (e.Source is Button btn)
            txtLog.Text = $"[统一事件] {btn.Tag} — 按钮被点击";
    }

    // ═══ 技巧2：TextBox 防抖 ═══
    private void OnWindowLoaded(object sender, RoutedEventArgs e)
    {
        txtSearch.TextChanged += OnSearchTextChanged;
    }

    private async void OnSearchTextChanged(object sender, TextChangedEventArgs e)
    {
        // 取消上一次防抖计时
        _debounceCts?.Cancel();
        _debounceCts = new CancellationTokenSource();
        var token = _debounceCts.Token;

        txtDebounce.Text = "输入中...";

        try
        {
            await Task.Delay(300, token);
            if (!token.IsCancellationRequested)
            {
                txtDebounce.Text = $"搜索: \"{txtSearch.Text}\" (300ms防抖完成)";
                txtLog.Text = $"[防抖] 执行搜索: {txtSearch.Text}";
            }
        }
        catch (TaskCanceledException)
        {
            // 被取消——用户还在输入
        }
    }

    // ═══ 技巧3：handledEventsToo ═══
    private void OnBtnPreviewKeyDown(object sender, KeyEventArgs e)
    {
        if (e.Key == Key.Escape)
        {
            e.Handled = true;  // 阻止冒泡事件
            txtLog.Text = "[PreviewKeyDown] Escape 被拦截，handled=true";
        }
    }

    // 在 Loaded 中用 handledEventsToo=true 注册——能"绕过" Handled
    private void SetHandledEventsToo()
    {
        btnIntercepted.AddHandler(
            UIElement.KeyDownEvent,
            new KeyEventHandler(OnBtnKeyDownEvenIfHandled),
            handledEventsToo: true);
    }

    private void OnBtnKeyDownEvenIfHandled(object sender, KeyEventArgs e)
    {
        txtLog.Text = $"[handledEventsToo] 收到 KeyDown: {e.Key} "
            + "(即使 Preview 阶段已设 Handled=true)";
    }

    private void OnInterceptedBtnClick(object sender, RoutedEventArgs e)
    {
        txtLog.Text = "[Click] 按钮被点击";
    }

    // ═══ 技巧5：MouseMove 频率控制 ═══
    private void OnMouseTracking(object sender, MouseEventArgs e)
    {
        var pos = e.GetPosition((IInputElement)sender);
        // 直接用 ViewModel 的 Binding 驱动更新——自然节流
        ((MainViewModel)DataContext).MousePos
            = $"鼠标坐标: X={pos.X:F0}, Y={pos.Y:F0}";
    }
}
 ```

> [!scene] 适用场景
> ✅ 统一事件管理：上位机工具条/菜单栏，父容器 `+=` 一次覆盖所有子按钮
> ✅ 防抖：搜索框、编码器参数输入、过滤条件输入
> ✅ handledEventsToo：需要"无论如何都要监控"的场景——全局热键即使被拦截也要日志
> ✅ MVVM Command：事件驱动 → 命令模式迁移，实现 View 和 ViewModel 的解耦
> ❌ 过度使用 handledEventsToo 破坏事件拦截机制

> [!pitfall] 常见踩坑
> 坑 1：**防抖没做好取消了上一个 CancellationToken** → 永远只执行最后一次——这是正确的防抖行为。但如果忘了 cancel 旧 token，会出现"多个防抖同时到期"的 Bug。解决方案：每次都 `Cancel()` + 新建 `CancellationTokenSource`。
>
> 坑 2：**Batic 的统一事件中没判断 Source 类型** → `Button.Click` 冒泡上来，Source 可能是 `Button` 也可能是 `MenuButton` 或 `RepeatButton`。解决方案：用 `is Button` 或检查 Tag 来区分。
>
> 坑 3：**在 MVVM 中给 ViewModel 传 `RoutedEventArgs`** → ViewModel 不应该依赖 UI 框架的类型。解决方案：通过 `CommandParameter` 传简单数据（string/int），在 View 层把事件参数转换为业务数据。

> [!best] 最佳实践
> - 上位机工具条用统一事件管理——一个 `Button.Click` handler 处理所有按钮，通过 `Tag` 区分
> - 搜索框必须加防抖——300ms 是工业软件的标准值
> - `handledEventsToo` 仅用于监控/日志类非功能性需求，不要让业务逻辑依赖它
> - 用 Command 绑定替代 `Click="..."` 是迈向 MVVM 的第一步
