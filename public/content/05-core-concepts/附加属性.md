# 附加属性

> [!plain] 白话理解
> 附加属性就是**让别人的东西替你干活**。你写 `<TextBox Grid.Row="1" Grid.Column="2" />` 的时候，`Row` 和 `Column` 属性并不属于 `TextBox`——它们是 `Grid` 类的属性，但"附加"到了 `TextBox` 身上。就像你租了一间酒店房间（TextBox），房间本身没有"楼层"属性，但酒店管理系统（Grid）给每个房间分配了楼层号。附加属性的精妙之处在于：**提供者**定义属性、**使用者**承载属性、**中介者**（通常是父布局容器）读取属性来做决策。这种"解耦定义和使用"的能力，是 WPF 布局系统如此灵活的关键。

> [!def] 官方定义
> 附加属性是依赖属性的一种特殊形式，通过 `DependencyProperty.RegisterAttached()` 而非 `Register()` 注册。它的 CLR 包装器也不是普通属性 get/set，而是一对静态方法：`static T GetXxx(DependencyObject obj)` 和 `static void SetXxx(DependencyObject obj, T value)`。任何 `DependencyObject` 都可以作为附加属性的宿主，不要求宿主类的类型与注册者匹配。最常见的例子包括 `Grid.Row`、`Canvas.Left`、`DockPanel.Dock` 等布局属性。

> [!origin] 由来背景
> WPF 布局系统面临一个难题：父容器需要控制子元素的位置和行为，但子元素不应该知道父容器的类型（那样就无法复用）。在 WinForms 中，布局逻辑全在容器代码里——`FlowLayoutPanel` 遍历子控件设置位置，子控件完全不参与布局决策。WPF 的设计更优雅：父容器声明附加属性（如 Grid 声明 Row、Column），子元素通过 XAML 直接"申请"自己的布局参数。这样既保持了子元素的无知性（不依赖具体容器类型），又让布局表达式直观——看 XAML 就知道元素在哪行哪列。

> [!essentials] 核心要点
> - **用 RegisterAttached 注册**：`DependencyProperty.RegisterAttached("IsBroughtToFront", ...)`
> - **CLR 包装器是静态方法**：`public static bool GetIsBroughtToFront(UIElement el)` 和 `public static void SetIsBroughtToFront(UIElement el, bool val)`
> - **任何 DependencyObject 可承载**：不要求宿主类与注册者类型匹配
> - **解除"属性必须在类中定义"的限制**：Grid 给放在 Canvas 里的 Button 设 Row——完全不违和
> - **支持 PropertyChangedCallback**：宿主属性变化时注册者类可以响应，这正是"附加行为"模式的基础

> [!example] 完整示例
>
> 自定义一个附加属性 `DeviceMonitor.AlarmPriority`，让任何控件都能标记报警优先级，然后父容器遍历读取并统一处理：
>
> **DeviceMonitor.cs**——定义附加属性：
 ```csharp
using System.Collections.Generic;
using System.Windows;
using System.Windows.Controls;
using System.Windows.Media;
using System.Windows.Media.Animation;

namespace HmiDemo;

/// <summary>
/// 设备监控附加属性类
/// </summary>
public static class DeviceMonitor
{
    // ═══ 附加属性 1：报警优先级（0=正常 1=警告 2=严重） ═══
    public static readonly DependencyProperty AlarmPriorityProperty =
        DependencyProperty.RegisterAttached(
            "AlarmPriority",
            typeof(int),
            typeof(DeviceMonitor),
            new FrameworkPropertyMetadata(
                0,
                FrameworkPropertyMetadataOptions.Inherits,
                OnAlarmPriorityChanged));

    public static int GetAlarmPriority(DependencyObject obj)
        => (int)obj.GetValue(AlarmPriorityProperty);

    public static void SetAlarmPriority(DependencyObject obj, int value)
        => obj.SetValue(AlarmPriorityProperty, value);

    // ═══ 附加属性 2：设备标签（自定义字符串） ═══
    public static readonly DependencyProperty DeviceTagProperty =
        DependencyProperty.RegisterAttached(
            "DeviceTag",
            typeof(string),
            typeof(DeviceMonitor),
            new PropertyMetadata(null));

    public static string GetDeviceTag(DependencyObject obj)
        => (string)obj.GetValue(DeviceTagProperty);

    public static void SetDeviceTag(DependencyObject obj, string value)
        => obj.SetValue(DeviceTagProperty, value);

    // ═══ 附加属性 3：是否闪烁报警（bool） ═══
    public static readonly DependencyProperty IsBlinkingProperty =
        DependencyProperty.RegisterAttached(
            "IsBlinking",
            typeof(bool),
            typeof(DeviceMonitor),
            new PropertyMetadata(false, OnIsBlinkingChanged));

    public static bool GetIsBlinking(DependencyObject obj)
        => (bool)obj.GetValue(IsBlinkingProperty);

    public static void SetIsBlinking(DependencyObject obj, bool value)
        => obj.SetValue(IsBlinkingProperty, value);

    // ═══ 变化回调 ═══
    private static void OnAlarmPriorityChanged(
        DependencyObject d, DependencyPropertyChangedEventArgs e)
    {
        if (d is Border border)
        {
            int priority = (int)e.NewValue;
            border.BorderBrush = priority switch
            {
                2 => new SolidColorBrush(
                    Color.FromRgb(0xCC, 0x22, 0x22)),
                1 => new SolidColorBrush(
                    Color.FromRgb(0xD4, 0xA0, 0x17)),
                _ => new SolidColorBrush(
                    Color.FromRgb(0x55, 0x55, 0x55))
            };
            border.BorderThickness = priority > 0
                ? new Thickness(2)
                : new Thickness(1);
        }
    }

    private static void OnIsBlinkingChanged(
        DependencyObject d, DependencyPropertyChangedEventArgs e)
    {
        if (d is FrameworkElement fe && (bool)e.NewValue)
        {
            var anim = new DoubleAnimation(0.3, 1.0,
                new Duration(System.TimeSpan.FromSeconds(0.5)))
            {
                AutoReverse = true,
                RepeatBehavior = RepeatBehavior.Forever
            };
            fe.BeginAnimation(UIElement.OpacityProperty, anim);
        }
    }

    // ═══ 工具方法：扫描子元素并汇总报警 ═══
    public static List<FrameworkElement> ScanAlarms(Panel container)
    {
        var alarms = new List<FrameworkElement>();
        foreach (var child in LogicalTreeHelper.GetChildren(container))
        {
            if (child is FrameworkElement fe
                && GetAlarmPriority(fe) > 0)
            {
                alarms.Add(fe);
            }
        }
        return alarms;
    }
}
 ```

> **MainWindow.xaml.cs**：
 ```csharp
using System.Linq;
using System.Windows;
using System.Windows.Controls;

namespace HmiDemo;

public partial class MainWindow : Window
{
    public MainWindow()
    {
        InitializeComponent();
    }

    private void OnScanAlarmsClick(object sender, RoutedEventArgs e)
    {
        var alarms = DeviceMonitor.ScanAlarms(panelDevices);
        txtLog.Text = alarms.Count > 0
            ? $"共 {alarms.Count} 台设备处于报警状态"
            : "所有设备运行正常";
    }

    private void OnClearAlarmsClick(object sender, RoutedEventArgs e)
    {
        foreach (var child in LogicalTreeHelper
            .GetChildren(panelDevices).OfType<FrameworkElement>())
        {
            DeviceMonitor.SetAlarmPriority(child, 0);
            DeviceMonitor.SetIsBlinking(child, false);
        }
        txtLog.Text = "所有报警已清除";
    }
}
 ```
>
> 这个例子展示了附加属性的精髓：
> - `Border` 控件本身不知道什么是"报警优先级"，但我们可以通过 `local:DeviceMonitor.AlarmPriority="2"` 附加给它
> - 父容器可以遍历子元素，读取附加属性值来决定行为
> - 附加属性变化通知（`OnAlarmPriorityChanged`）让注册者类"被动感知"宿主的变化

> [!scene] 适用场景
> ✅ 布局相关参数（Grid.Row、Canvas.Left、DockPanel.Dock）——这是附加属性的"原教旨"用途
> ✅ 为任意控件附加自定义行为（如本例的报警优先级标记）——"附加行为"模式
> ✅ 跨多个不相关控件类型的统一标记（ToolTip、FocusManager、InputBindings 都用附加属性）
> ✅ 一种"解耦扩展"的设计模式——不让基类膨胀，通过附加属性增加功能
> ❌ 简单的数据传递——用 Binding 或事件更直接

> [!pitfall] 常见踩坑
> 坑 1：**RegisterAttached 和 Register 混用** → `RegisterAttached` 的访问器方法是静态的 `GetXxx/SetXxx`，普通 `Register` 是实例属性包装器。把附加属性注册成普通属性会导致 XAML `<Grid.Row="1">` 不可用。
>
> 坑 2：**在附加属性的 Changed 回调中"消费"了事件不释放** → 如果附加属性变化时注册了全局事件处理器，务必在属性被清除时取消注册，否则会造成内存泄漏。
>
> 坑 3：**附加属性的值不会被 XAML 序列化保存** → 如果你用设计器拖拽保存界面，自定义附加属性不会被写入生成的 XAML 文件。解决方案：如果需要持久化，用普通依赖属性或者手动保存。

> [!best] 最佳实践
> - 附加属性类命名为 `XxxService` 或 `XxxManager` 风格，明确表示它是"服务提供者"而非"数据载体"
> - GetXxx/SetXxx 的参数类型尽量宽松——用 `DependencyObject` 而非具体类型，这样所有控件都能承载
> - 如果附加属性只服务于一个特定的父容器，用 `FrameworkPropertyMetadataOptions.Inherits` 让值沿逻辑树向下传递
> - 不要把业务数据存到附加属性里——附加属性更适合"元数据"或"行为标记"
