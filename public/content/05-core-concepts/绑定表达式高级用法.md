# 绑定表达式高级用法

> [!plain] 白话理解
> 基本绑定你已经会了：`{Binding Speed}`。但实际项目中你会遇到更复杂的需求：想把"姓"和"名"拼在一起显示、传一个新值之前先格式化处理、绑定的数据是空值怎么办、想让绑定生效前等用户停止输入 500ms。这些高级用法不常用，但一旦需要，没有它们代码会变得很绕。WPF 已经为你准备好了：`StringFormat`（格式化）、`MultiBinding`（多路绑定）、`FallbackValue`（失败兜底）、`TargetNullValue`（NULL 兜底）、`Delay`（防抖）、`PriorityBinding`（异步降级）。掌握这些，你的绑定表达式就毕业了。

> [!def] 官方定义
> 绑定表达式高级用法涵盖：`MultiBinding`（多数据源聚合为一个值，配合 `IMultiValueConverter` 使用）、`PriorityBinding`（多候选源按优先级降级，异步加载场景）、`Binding.Delay`（延迟更新，适合实时输入场景）、`FallbackValue`（整个绑定解析失败时的显示值）、`TargetNullValue`（数据为 null 但不表示绑定失败的显示值）、`BindingGroup`（一组绑定的统一提交验证和事务管理）。这些特性从 .NET 3.0 开始逐步引入，在 .NET 4.0 中趋于完整。

> [!origin] 由来背景
> WPF 在 .NET Framework 3.0（2006 年）引入声明式数据绑定，绑定表达式随之逐步完善：.NET 3.0 就有 `MultiBinding`（一个目标属性依赖多个数据源，如"设备状态 = 在线标志 + 最后心跳时间"）和 `PriorityBinding`（数据加载慢时先用候选值顶住，异步数据到了再切换），.NET 4.0 增加 `Binding.Delay`（延迟提交，避免打字过程中反复写数据源）与 `BindingGroup`（一组绑定的统一提交验证）。这些特性都服务于同一个目标：让 UI 与数据源的同步逻辑留在 XAML 里声明，而不是散落在事件代码中——上位机界面数据量大、刷新频繁时尤其受益。

> [!essentials] 核心要点
> - **MultiBinding**：`<MultiBinding StringFormat="{}{0} - {1}"><Binding .../><Binding .../></MultiBinding>` 多条路径合成一个值
> - **PriorityBinding**：多候选降级，"慢的数据还没来先用快的凑"
> - **FallbackValue**：整个绑定失败（如路径不存在）时显示的值
> - **TargetNullValue**：数据就是 null（不是绑定错误）时的显示值
> - **Delay**：从 UI 改到数据源的延迟毫秒数

using System.ComponentModel;
using System.Runtime.CompilerServices;

namespace HmiDemo;

public class DeviceInfoViewModel : INotifyPropertyChanged
{
    private string _brand = "Siemens";
    public string Brand
    {
        get => _brand;
        set { _brand = value; OnPropertyChanged(); OnPropertyChanged(nameof(FullName)); }
    }

    private string _model = "S7-1500";
    public string Model
    {
        get => _model;
        set { _model = value; OnPropertyChanged(); OnPropertyChanged(nameof(FullName)); }
    }

    // 计算属性：MultiBinding 也显示同样结果但走不同路径
    public string FullName => $"{Brand} {Model}";

    private string? _operator;
    public string? Operator
    {
        get => _operator;
        set { _operator = value; OnPropertyChanged(); }
    }

    private string _ip = "192.168.1.100";
    public string IP
    {
        get => _ip;
        set { _ip = value; OnPropertyChanged(); }
    }

    private bool _isConnected = true;
    public bool IsConnected
    {
        get => _isConnected;
        set { _isConnected = value; OnPropertyChanged(); }
    }

    public event PropertyChangedEventHandler? PropertyChanged;
    protected void OnPropertyChanged([CallerMemberName] string? n = null)
        => PropertyChanged?.Invoke(this, new PropertyChangedEventArgs(n));
}

> **ConnectionStatusConverter.cs**
 ```csharp
using System;
using System.Globalization;
using System.Windows.Data;
using System.Windows.Media;

namespace HmiDemo;

public class ConnectionStatusConverter : IValueConverter, IMultiValueConverter
{
    public object Convert(object value, Type targetType, object parameter, CultureInfo culture)
    {
        if (value is bool connected)
            return connected ? "已连接" : "已断开";
        return "未知";
    }

    public object ConvertBack(object value, Type targetType, object parameter, CultureInfo culture)
        => throw new NotSupportedException();

    // IMultiValueConverter
    public object Convert(object[] values, Type targetType, object parameter, CultureInfo culture)
    {
        if (values.Length >= 1 && values[0] is bool connected)
            return new SolidColorBrush(connected
                ? Color.FromRgb(0x16, 0x1B, 0x22) : Color.FromRgb(0xCC, 0x22, 0x22));
        return new SolidColorBrush(Color.FromRgb(0x16, 0x1B, 0x22));
    }

    public object[] ConvertBack(object value, Type[] targetTypes, object parameter, CultureInfo culture)
        => throw new NotSupportedException();
}
 ```

> [!scene] 适用场景
> ✅ MultiBinding：要在 UI 上拼合多个数据源字段
> ✅ FallbackValue：数据源可能不存在或初始化时为空
> ✅ TargetNullValue：数据字段可为空，需要显示替代文字
> ✅ Delay：搜索框、编码器
> ✅ PriorityBinding：大型对象使用异步加载

> [!pitfall] 常见踩坑
> 坑 1：**StringFormat 第一个参数没有 {} → 显示成了原始字符串** → WPF 解析器要求 StringFormat 第一个字符如果是 {，需要在前面加 `{}` 转义。解决方案：`StringFormat={}{0}°C`，前面加 `{}` 做转义。
>
> 坑 2：**MultiBinding 忘写 IMultiValueConverter → 空白** → 除非你用 StringFormat，否则 MultiBinding 必须有 IMultiValueConverter 来处理多个值的聚合。
>
> 坑 3：**FallbackValue 和 TargetNullValue 混淆** → FallbackValue 是"绑定本身失败了"；TargetNullValue 是"绑定成功了但数据是 null"。它们是递进关系——先判断绑定是否成功，再判断数据是否是 null。

> [!best] 最佳实践
> - 多用 StringFormat 做格式化，少写 Converter——StringFormat 比 IValueConverter 简洁得多
> - FallbackValue 给"安全数值"（如 0、"无数据"），不要给 null
> - MultiBinding 配合 StringFormat 比 IMultiValueConverter 更简单——先考虑 StringFormat
> - Delay 默认值就很好——300~500ms 是工业软件防抖黄金区间
