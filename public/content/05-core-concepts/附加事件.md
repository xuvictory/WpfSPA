# 附加事件

> [!plain] 白话理解
> 附加事件是附加属性的"事件版"——你在 Button 上可以写 `<Button Mouse.MouseDown="OnMouseDown"/>`，但 `Mouse.MouseDown` 是 `Mouse` 类的附加事件，不是 `Button` 自己的事件。就像你去酒店住，酒店的 WiFi 密码不是你房间自带的——是酒店（Mouse 类）"附加"给每个房间（Button）的服务。附加事件的精妙之处在于：**事件提供者和事件宿主不一定是同一种类型**，而且父容器可以在不关心具体子元素类型的情况下统一监听。

> [!def] 官方定义
> 附加事件使用 `EventManager.RegisterRoutedEvent` 注册，但 CLR 包装器使用静态方法而非实例属性：`public static void AddXxxHandler(DependencyObject element, RoutedEventHandler handler)` 和 `public static void RemoveXxxHandler(DependencyObject element, RoutedEventHandler handler)`。因为附加事件允许任何 `DependencyObject` 承载，无法用 `this.AddHandler` 模式。XAML 中使用 `提供者类.事件名="处理器"` 语法（如 `Mouse.MouseDown="..."`）。WPF 内置的附加事件包括 `Mouse.MouseDown`、`Keyboard.KeyDown`、`ScrollViewer.ScrollChanged` 等。

> [!origin] 由来背景
> WPF 输入系统面临一个问题：鼠标事件应该定义在哪里？如果定义在 `UIElement` 上，那 `UIElement` 的子类几十种控件都继承了这个事件——这是合理的。但 `ContentElement`（FlowDocument 中的文本元素）也需要鼠标事件。`UIElement` 和 `ContentElement` 没有共同的基类（除了 `DependencyObject`）。MS 的解决方案是：把 `MouseDown` 定义成 `Mouse` 类的附加事件——任何 `DependencyObject` 都可以承载它。这也是为什么 XAML 中写的是 `Mouse.MouseDown` 而不是 `Button.MouseDown`。

> [!essentials] 核心要点
> - **不同于普通事件**：XAML 中用 `提供者类.事件名="处理器名"`，如 `Mouse.MouseDown="OnMouseDown"`
> - **静态 add/remove 访问器**：`public static void AddXxxHandler(DependencyObject d, ...)`
> - **任何 DependencyObject 都可用**：不限制宿主类型
> - **XAML 不能直接使用自定义附加事件**：需要借助附加属性 + 行为模式
> - **WPF 内置的输入事件基本都是附加事件**：Mouse.MouseDown、Keyboard.KeyDown、Stylus 系列

> **MainWindow.xaml.cs**
 ```csharp
using System.Windows;
using System.Windows.Controls;
using System.Windows.Input;

namespace HmiDemo;

public partial class MainWindow : Window
{
    public MainWindow()
    {
        InitializeComponent();
    }

    /// <summary>
    /// Window 层的 Mouse.MouseDown 附加事件处理
    /// 所有子元素的鼠标点击都会冒泡到这里
    /// </summary>
    private void OnWindowMouseDown(object sender, MouseButtonEventArgs e)
    {
        string src = e.Source.GetType().Name;
        txtLog.Text = $"[鼠标] Source={src}, "
            + $"Position=({e.GetPosition(this).X:F0},{e.GetPosition(this).Y:F0})";
    }

    /// <summary>
    /// StackPanel 层的 Mouse.MouseDown 附加事件处理
    /// </summary>
    private void OnStackPanelMouseDown(object sender, MouseButtonEventArgs e)
    {
        if (e.Source is Button btn)
        {
            txtLog.Text = $"[设备操作] 点击了: {btn.Content}";
        }
    }

    /// <summary>
    /// Window 层的 Keyboard.KeyDown 附加事件处理
    /// 所有键盘按键都会冒泡到这里
    /// </summary>
    private void OnWindowKeyDown(object sender, KeyEventArgs e)
    {
        string action = e.Key switch
        {
            Key.F1    => "全屏切换",
            Key.F2    => "打开设置",
            Key.F3    => "打开诊断",
            Key.Escape => "关闭弹窗",
            _         => $"按键: {e.Key}"
        };
        txtLog.Text = $"[键盘] {action}";
    }
}
 ```
>
> 运行后点击任意按钮或 Element，鼠标事件冒泡到 Window 层的 `OnWindowMouseDown`；按 F1/F2/F3/Escape 键，键盘事件冒泡到 Window 层的 `OnWindowKeyDown`。注意 XAML 中的写法是 `Mouse.MouseDown="..."` 而不是 `Button.MouseDown="..."`——这正是附加事件的语法特点。

> [!scene] 适用场景
> ✅ 希望父容器统一处理所有子控件的输入事件——用 Window 层监听 Mouse/Keyboard 附加事件
> ✅ 跨不同控件类型的事件统一响应（Button、TextBox、Slider 的键盘事件统一处理）
> ✅ 自定义附加事件 + 行为模式（Behavior Pattern）——让任意控件"拥有"新行为
> ✅ 全局快捷键/全局鼠标手势
> ❌ 单一控件的特定事件——直接在控件上注册更清晰

> [!pitfall] 常见踩坑
> 坑 1：**XAML 中写成 `Button.MouseDown` 而不是 `Mouse.MouseDown`** → `Button` 虽然有 `MouseDown` 事件，但 WPF 输入事件的标准注册点在 `Mouse` 类上。用 `Button.MouseDown` 在 .NET 4.0+ 也可以触发（因为 `UIElement` 做了包装），但附加事件的"原汁原味"是 `Mouse.MouseDown`。
>
> 坑 2：**在附加事件处理中不设 Handled=true，但期望截断** → 附加事件的 `e.Handled` 同样对所有冒泡/隧道机制生效。如果设了 Handled=true 就真的截断了。
>
> 坑 3：**自定义附加事件无法直接在 XAML 中使用** → 不像内置附加事件，自定义的附加事件没有 IDE 支持，必须在代码中 `AddHandler`。解决方案：配合附加属性 + PropertyChangedCallback 间接触发。

> [!best] 最佳实践
> - Window 层统一监听 `Keyboard.KeyDown` 是上位机全局快捷键的标准做法
> - 不要在附加事件中做大量计算——附加事件沿树传递的特性意味着它可能被多次触发
> - 自定义附加事件通常不直接用，而是通过"附加行为"模式（附加属性 + Changed 回调中注册事件）
> - 区分"附加事件"和"控件的路由事件"——`Button.Click` 不是附加事件，`Mouse.MouseDown` 才是
