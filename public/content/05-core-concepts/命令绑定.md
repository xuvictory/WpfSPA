# 命令绑定

> [!plain] 白话理解
> 命令绑定（CommandBinding）就像是**给命令和控件之间搭了一座桥**。内置命令 `ApplicationCommands.Copy` 本身不知道"复制什么"——它只是一个抽象概念。CommandBinding 负责告诉它："当你要执行 Copy 时，调用这个方法来获取选中的文本；当你要判断 Copy 能不能执行时，用这个条件来判断。"一个窗口可以有多个 CommandBinding——你把 Copy 命令绑定到不同的处理器，就实现了自定义的复制逻辑。上层命令不变，下层绑定切换——这是依赖注入思想在 UI 层的应用。

> [!def] 官方定义
> `CommandBinding` 是连接 `RoutedCommand` 和处理逻辑的桥梁。它包含三个核心成员：`Command`（指定要绑定的命令）、`Executed`（命令执行时触发的事件，在此处写执行逻辑）、`CanExecute`（查询命令是否可执行时触发的事件，在此处写判断逻辑）。CommandBinding 跟路由事件一样沿可视树冒泡——所以你可以把 CommandBinding 注册在 Window 层，所有子控件都能用。XAML 中声明 `CommandBinding` 要在 `CommandBindings` 集合中：`<Window.CommandBindings><CommandBinding .../></Window.CommandBindings>`。

> [!origin] 由来背景
> WPF 命令系统刚推出时，有人认为每个命令一个 CommandBinding 写起来太麻烦。但后来做自定义控件和上位机项目时，大家发现 CommandBinding 的"注册层级"设计非常巧妙——你可以把全局操作（如 F5 刷新）的 CommandBinding 注册在 Window 层，各子控件只负责声明绑定而不负责实现。这种"集中定义、分散使用"的模式和依赖属性的值继承机制一脉相承。在 .NET 4.5 中，还增加了 `CommandManager.InvalidateRequerySuggested()` 的智能合并策略，减少高频 CanExecute 查询的开销。

> [!essentials] 核心要点
> - **CommandBinding 沿树冒泡**：可以从子控件一路查找到 Window 层
> - **Executed 和 CanExecute 是两个独立事件**：必须分别注册处理器
> - **多个 CommandBinding 可以绑定到同一个命令**：就近优先（子控件 > 父容器）
> - **代码中注册**：`CommandBindings.Add(new CommandBinding(Command, OnExecuted, OnCanExecute))`
> - **XAML 中注册**：在 `Window.CommandBindings` 或 `UserControl.CommandBindings` 中声明

> [!example] 完整示例
>
> 自定义 Copy/Paste 行为——复制时加上设备编号前缀，粘贴时做格式校验：
>
> **MainWindow.xaml**
 ```xml
<Window x:Class="HmiDemo.MainWindow"
        xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
        xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
        Title="命令绑定 — 自定义 Copy/Paste" Height="550" Width="750"
        WindowStartupLocation="CenterScreen">

    <!-- ═══ 在 Window 层注册 CommandBinding ═══ -->
    <Window.CommandBindings>
        <CommandBinding Command="ApplicationCommands.Copy"
                        Executed="OnCustomCopy"
                        CanExecute="OnCanCustomCopy"/>
        <CommandBinding Command="ApplicationCommands.Paste"
                        Executed="OnCustomPaste"
                        CanExecute="OnCanCustomPaste"/>
    </Window.CommandBindings>

    <Grid Background="#0D1117" Margin="15">
        <Grid.RowDefinitions>
            <RowDefinition Height="Auto"/>
            <RowDefinition Height="Auto"/>
            <RowDefinition Height="*"/>
        </Grid.RowDefinitions>

        <TextBlock Text="命令绑定 — 自定义复制粘贴行为"
                   Foreground="#FF6B35" FontSize="16"
                   FontWeight="Bold" Margin="0,0,0,8"/>

        <!-- 工具栏 -->
        <ToolBar Grid.Row="1" Background="#161B22"
                 BorderBrush="#30363D" Margin="0,0,0,8">
            <Button Command="ApplicationCommands.Copy" Width="70"
                    Background="#161B22" Foreground="White"
 ```

> **MainWindow.xaml.cs**
 ```csharp
using System;
using System.Windows;
using System.Windows.Controls;
using System.Windows.Input;

namespace HmiDemo;

public partial class MainWindow : Window
{
    private const string DeviceId = "M-101";

    public MainWindow()
    {
        InitializeComponent();
    }

    /// <summary>
    /// CanExecute：判断是否可以复制
    /// </summary>
    private void OnCanCustomCopy(object sender, CanExecuteRoutedEventArgs e)
    {
        // 只有当焦点在 txtParam 且选中了文字时才允许复制
        var focused = FocusManager.GetFocusedElement(this);
        if (focused == txtParam && txtParam.SelectionLength > 0)
        {
            e.CanExecute = true;   // ✓ 可以复制
            e.Handled = true;      // 停止冒泡，不用内置 Copy 了
        }
    }

    /// <summary>
    /// Executed：执行自定义复制——加上设备编号前缀
    /// </summary>
    private void OnCustomCopy(object sender, ExecutedRoutedEventArgs e)
    {
        string selectedText = txtParam.SelectedText;
        string enriched = $"[{DeviceId}] {selectedText}";
        Clipboard.SetText(enriched);
        txtLog.Text = $"[自定义 Copy] 已复制:\n"
            + $"  原文: {selectedText}\n"
            + $"  添加前缀后: {enriched}";
    }

    /// <summary>
    /// CanExecute：判断是否可以粘贴
    /// </summary>
    private void OnCanCustomPaste(object sender, CanExecuteRoutedEventArgs e)
    {
        var focused = FocusManager.GetFocusedElement(this);
        e.CanExecute = focused == txtTarget && Clipboard.ContainsText();
        e.Handled = true;
    }

    /// <summary>
    /// Executed：自定义粘贴——校验格式，过滤无效数据
    /// </summary>
    private void OnCustomPaste(object sender, ExecutedRoutedEventArgs e)
    {
        string raw = Clipboard.GetText();
        // 只允许带设备编号前缀或纯数字的内容粘贴
        if (raw.StartsWith($"[{DeviceId}]")
            || double.TryParse(raw, out _))
        {
            txtTarget.Text += raw;
            txtLog.Text = $"[自定义 Paste] 已粘贴: {raw}";
        }
        else
        {
            txtLog.Text = $"[自定义 Paste] 拒绝粘贴（格式不符）: {raw}";
        }
    }
}
 ```
>
> 运行后：在左侧文本框选中文字 → 点击复制 → 剪贴板中自动加上了 `[M-101]` 前缀；在右侧文本框粘贴 → 只有符合格式的内容才能粘贴成功。

> [!scene] 适用场景
> ✅ 自定义内置命令行为——如复制时添加归属信息
> ✅ 为没有 CommandBinding 的控件（如自定义控件）添加命令支持
> ✅ 分层注册 CommandBinding——全局操作在 Window 层，局部操作在子控件层
> ✅ 权限控制——在 CanExecute 中检查用户权限
> ❌ ICommand 的自定义命令——ICommand 不需要 CommandBinding，直接绑定即可

> [!pitfall] 常见踩坑
> 坑 1：**CanExecute 设了返回值但按钮还是灰** → `CanExecuteRoutedEventArgs.CanExecute` 默认是 `false`。必须显式设 `e.CanExecute = true` 按钮才会启用。而且别忘了设 `e.Handled = true` 防止上一层覆盖。
>
> 坑 2：**CommandBinding 注册在错误层级** → 放在 StackPanel 层的 CommandBinding 只对 `CommandTarget` 为这个 StackPanel 内的控件生效。如果不设 CommandTarget，WPF 用焦点元素找绑定——焦点在 Grid 外的控件，Grid 上的 CommandBinding 找不到。
>
> 坑 3：**使用 `CommandManager.AddPreviewExecutedHandler` 和 `CommandBinding` 的 Executed 冲突** → PreviewExecuted 优先级更高，如果 PreviewExecuted 设 `e.Handled=true`，CommandBinding 的 Executed 不触发。

> [!best] 最佳实践
> - Window 层注册全局 CommandBinding（如 Ctrl+S 保存、Escape 关闭）
> - CanExecute 中只做简单判断——不要做数据库查询或网络请求
> - 如果多个控件都需要同一组命令，把 CommandBinding 注册在它们的共同父容器上
> - 自定义命令（ICommand）不需要 CommandBinding——直接用 RelayCommand 更简洁
