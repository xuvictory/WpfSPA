# 常用布局属性

> [!plain] 白话理解
> 如果把 WPF 布局容器比作"停车场的车位线"，那布局属性就是每辆车的"停车规矩"——**车该占多大位置（Width/Height）、和相邻车位保持多大距离（Margin）、车身能撑满整个车位还是居中停放（Alignment）、车里坐垫的厚度（Padding）**。这四个属性组合在一起，决定了每个控件在布局容器中最终呈现的大小和位置。它们看上去简单，但组合使用时有很多"化学反应"。

> [!def] 官方定义
> 所有 WPF 控件继承自 `FrameworkElement`，因此都拥有以下核心布局属性：**Width/Height**（控件的宽度和高度）、**MinWidth/MinHeight** 与 **MaxWidth/MaxHeight**（尺寸约束范围）、**Margin**（控件外边界到相邻元素或容器的间距）、**Padding**（控件内部内容到边界的间距）、**HorizontalAlignment**（水平对齐：Left/Center/Right/Stretch）和 **VerticalAlignment**（垂直对齐：Top/Center/Bottom/Stretch）。这些属性在布局的 Arrange 阶段共同决定控件的最终渲染矩形。

> [!origin] 由来背景
> WinForms 中控件有 `Left`、`Top`、`Width`、`Height`、`Anchor`、`Dock` 六个属性，组合逻辑经常让人抓狂——Anchor 是"锁定边距"，Dock 是"填满一侧"，两者同时设置行为不可预测。WPF 对此做了大幅简化：去掉 Left/Top（Canvas 除外），统一用 Margin 表达间距，用 Alignment 替代 Anchor/Dock 的常见场景，用 Padding 让每个控件自带"内衬"。这套设计直接延续到后来的 WinUI 和 MAUI，足以证明它的正确性。

> [!essentials] 核心要点
> - **Width/Height**：默认值 `Double.NaN`（表示 Auto，即自动计算）；显式设值后控件不再自动伸缩
> - **Min/Max 约束**：`MinWidth` ≤ 实际 Width ≤ `MaxWidth`，即使设了 `Width="*"` 或 `HorizontalAlignment="Stretch"` 也会被这个范围限制
> - **Margin**：`控件和周围元素之间的"安全距离"`；四个值顺序为 L,T,R,B（左、上、右、下），`Margin="10,5,10,5"` 或 `Margin="10"`（四边相同）
> - **Padding**：`控件边框到内部内容的"内边距"`，只有 Block、Border、TextBox 等有可见背景的控件效果明显
> - **Alignment**：决定控件在父容器分配的"单元格"内如何定位——Stretch（默认，撑满）、Center、Left/Right、Top/Bottom
> - **Visibility**：三种状态——`Visible`（正常显示且占位）、`Hidden`（不可见但占位）、`Collapsed`（不可见且不占位，布局空间释放）
> - **关键区别**：Margin 控制的是"外面"（控件与邻居的关系），Padding 控制的是"里面"（边框与内容的关系）

> [!scene] 适用场景
> ✅ **Margin**：所有控件都需要用它来拉开间距，替代 WinForms 里"拖个空 Label 占位"的土办法
> ✅ **Padding**：卡牌式布局（Border + Padding + 背景色）打造现代 UI 风格，数据面板的内容留白
> ✅ **MinWidth/MaxWidth**：限制输入框、下拉框的最大宽度，防止窗口拉大后控件丑陋地拉伸到全屏
> ✅ **Alignment**：工具栏按钮右对齐（`HorizontalAlignment="Right"`）、弹窗居中（`HorizontalAlignment/VerticalAlignment="Center"`）
> ✅ **Visibility.Collapsed**：动态面板展开/收起——细节区折叠后下方内容自动上移
> ❌ 滥用固定 Width/Height：想让界面"好看"却破坏了 WPF 的流式布局优势

> [!pitfall] 常见踩坑
> 坑 1：**Margin 和 Padding 搞混** → Margin 是"我要离别人多远"，Padding 是"我的内容要离我边框多远"。给 Button 设 Margin 是调整 Button 之间的间距，设 Padding 是调整按钮内文字到按钮边缘的距离。初学者最常见的错误就是该用 Margin 的地方用了 Padding。
>
> 坑 2：**Stretch 对齐需要显式配合** → `HorizontalAlignment="Stretch"` 是默认值，但它只有在 Width 为 Auto（不设值）时才生效。一旦你设了 `Width="200"`，Stretch 就失效了——因为 Width 明确说"我只要 200"。
>
> 坑 3：**Hidden vs Collapsed 用错** → 想"临时隐藏但保留位置"用 `Hidden`，想"彻底隐藏并让出位置"用 `Collapsed`。典型错误：折叠侧边栏用 `Hidden`，结果侧边栏消失了但留了一大片空白区域。

> [!best] 最佳实践
> - Margin 统一管理：用 `Margin="12,8,12,8"` 统一页面级间距，不要每个控件单独给不同值
> - 用 MinWidth/MinHeight 做"兜底保护"：输入框 `MinWidth="80"` 防止太窄，`MaxWidth="300"` 防止太宽
> - Padding 做视觉层次：外层卡片 `Padding="16"`、内层分组 `Padding="8"`，通过 Padding 大小建立内容层级感
> - Alignment 配合 Panel 使用：不要单独依赖 Alignment，让父容器先把空间分配好
> - Visibility 的 Data Binding：`Visibility="{Binding IsDetailVisible, Converter={StaticResource BoolToVisibilityConverter}}"` 是上位机最常用的数据驱动面板切换模式

> [!practice] 上手练习
> **Lv.1 照猫画虎**：运行上面的完整示例，一一点击各个控件、拖拽窗口，直观感受 Width/MinMax/Stretch、Margin/Padding、Alignment、Visibility 各自的视觉效果
> **Lv.2 小试牛刀**：用 Margin 和 Padding 设计一个"报警列表"面板：红色报警项、黄色警告项、绿色正常项各一行，要求项与项之间间距统一、文字不贴边框
> **Lv.3 融会贯通**：做一个可折叠的"高级参数面板"：默认折叠（Collapsed），点击"展开"按钮显示详细配置项，面板下方的内容自动下移（体会 Collapsed 释放空间 vs Hidden 保留空间的本质区别）
