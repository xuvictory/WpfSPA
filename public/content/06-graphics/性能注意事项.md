# 性能注意事项

> [!plain] 白话理解
> Effect 特效是把"双刃剑"：单个元素挂一个模糊/投影很漂亮，但**给几十个元素同时挂**（比如 8 路监控画面全部模糊）GPU 负担陡增，界面开始掉帧。本篇用 8 路画面示例演示"特效数量 × 刷新频率"与性能的关系——理解特效的渲染开销规律，比记住某个 API 更重要。
>
> 类比：一台印钞机印一张钞票很快，但同一台机器同时印 8 张还要每张加防伪，吞吐量就会骤降。

> [!def] 官方定义
> WPF 的 Effect（`System.Windows.Media.Effects`）由 GPU 像素着色器执行，每个挂载特效的元素都需要独立渲染批次（Render Pass）。特效开销 ∝ 元素数量 × 特效复杂度 × 刷新频率。`RenderOptions.ProcessRenderMode`（`RenderMode`）可强制软件/硬件渲染；`System.Windows.Media.RenderCapability` 可查询 GPU 能力。性能问题可用 Visual Studio 的"WPF 分析器"（Diagnostics 工具）定位。
>
> 官方文档：https://learn.microsoft.com/zh-cn/dotnet/desktop/wpf/graphics-multimedia/optimizing-performance-rendering-behavior

> [!origin] 由来背景
> WPF 的渲染管线设计目标是"GPU 硬件加速"，但特效（像素着色器）每个实例都要消耗 GPU 资源。微软官方性能文档明确建议"尽量少使用 Effect、大尺寸特效慎用、避免在动画元素上挂特效"。这些经验来自大量真实应用——尤其是监控墙、多画面看板这类"元素多 + 高频刷新"的工控场景，特效滥用是卡顿的常见根源。

> [!essentials] 核心要点
> - **特效成本公式**：元素数量 × 特效复杂度 × 刷新频率 = 渲染开销
> - **批量挂特效最贵**：给 N 个元素分别挂 = N 倍开销；能合并就合并（如整个画面一个特效）
> - **动画 + 特效最贵**：动画元素每帧重渲染，特效再叠加几乎必卡
> - **移除比复用重要**：特效用完（弹窗关闭）立即 `Effect = null`，别留 8 个模糊在那空转
> - **软件渲染兜底**：远程桌面/低端机可能走软件渲染，特效开销剧增，需有降级方案

>         {
>             foreach (var cam in _cams)
>             {
>                 cam.Effect = _blur;
>             }
>         }
>
>         // 正确做法：无需特效时及时移除 Effect
>         private void OnDisableEffects(object sender, RoutedEventArgs e)
>         {
>             foreach (var cam in _cams)
>             {

>             }
>         }

> [!scene] 适用场景
> ✅ 监控墙/多画面看板：多个画面元素叠加特效前的性能评估
> ✅ 高频动画 + 特效：判断动画元素能否安全叠加模糊/投影
> ✅ 大数据量图形（曲线/图墙）：评估对象数量对渲染的影响
> ✅ 远程桌面/低配工控机：确认软件渲染下特效的降级策略
> ✅ 长时间运行的上位机：检查特效是否残留（内存/GPU 占用）
> ❌ 只有一两个元素的简单页面：无需过度优化，先按默认写
> ❌ 未验证就大面积上特效：先做性能测试再铺开

> [!pitfall] 常见踩坑
> 坑 1：**给 N 个元素分别挂同一个特效** → 现象：8 路画面同时模糊后拖动窗口掉帧 → 原因：每个元素独立执行像素着色器，N 倍开销（示例的"错误示范"） → 解决：能合并就合并（整块区域一个特效），或用遮罩/纯色替代
> 
> 坑 2：**特效挂上去忘了移除** → 现象：弹窗关闭后界面仍慢 → 原因：Effect 还挂在元素上持续消耗 GPU → 解决：弹窗/状态结束时 `Effect = null`（示例的"正确做法"），养成清理习惯
>
> 坑 3：**在远程桌面/虚拟机上看性能"正常"误导** → 现象：本机流畅、部署现场卡顿 → 原因：远程桌面走软件渲染，特效开销暴增 → 解决：上线前在目标机（尤其无独显的工控机）实测，必要时降级特效

> [!best] 最佳实践
> - 记住成本公式：特效开销 ∝ 元素数 × 复杂度 × 刷新率，先估量再使用
> - 动画元素默认不挂特效；动画结束后再挂/再移除
> - 用 Visual Studio 的 WPF 分析器/性能探查器定位瓶颈，别凭感觉优化
> - 特效数量多的场景先做"关掉特效看帧率"对比实验，量化差异
> - 低配部署环境准备"精简特效模式"（配置开关），一键降级

> [!practice] 上手练习
> **Lv.1 运行体验**：运行特效对比示例，点"开启 8 路模糊"后拖动窗口感受掉帧，再点"关闭特效"对比
> **Lv.2 动手改造**：把 BlurEffect 的 Radius 从 4 改成 12，再对比开关特效的性能差异
> **Lv.3 综合实战**：给"开启 8 路模糊"改成"仅第 1 路模糊"，对比 1 个 vs 8 个特效的开销差异
> **Lv.4 挑战进阶**：用 DispatcherTimer 让 8 个画面持续平移，同时开启特效，用任务管理器观察 GPU 占用变化，写一份"特效成本"笔记
