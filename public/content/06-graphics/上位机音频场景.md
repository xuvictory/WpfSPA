# 上位机音频场景

> [!plain] 白话理解
> 这一篇不是新 API，而是"音频工具箱的总指挥"：上位机里既有"滴"一声的短提示音，也有"3 号产线缺料"这样的长语音播报。短音用 SoundPlayer 播 WAV 最轻，长语音/视频用 MediaElement 播 mp3 最合适。本篇教你按"时长、格式、控制需求"三把尺子选对工具，再把报警、完成、缺料这些状态和声音挂上钩，让设备"会说话"。

> [!def] 官方定义
> 本篇是对 `System.Media.SoundPlayer` 与 `System.Windows.Controls.MediaElement` 两种音频方案的选型与集成实践，并非单一 API。两类场景的边界：短提示音/报警音（WAV，`SoundPlayer`）与长语音/音视频（mp3/wav/wmv，`MediaElement`）。上位机音频方案的核心是把"设备状态事件"映射为"音频播报动作"，并做好互斥与优先级管理。
>
> 官方文档：https://learn.microsoft.com/zh-cn/dotnet/api/system.media.soundplayer 与 https://learn.microsoft.com/zh-cn/dotnet/api/system.windows.controls.mediaelement

> [!origin] 由来背景
> 早期工控交互靠"指示灯 + 蜂鸣器"，HMI 上位机普及后，屏幕和扬声器成为新的状态通道。WPF 恰好提供两类互补的音频 API：SoundPlayer 出身 Win32 `sndPlaySound`（短音效、极简），MediaElement 封装完整媒体管线（长音频、可控制）。把这两者按场景组织成"短音长语音、报警循环、播报互斥"的方案，正是工控 HMI 音频模块的标准形态。

> [!essentials] 核心要点
> - **选型三原则**：时长（<2s 短音用 SoundPlayer）、格式（wav 用 SoundPlayer，mp3/mp4 用 MediaElement）、控制需求（需定位/倍速用 MediaElement）
> - **事件驱动**：设备状态变化（报警/完成/缺料）触发对应音频，用事件或回调而非轮询
> - **互斥与优先级**：两类播放器各自独立，需自行管理"谁打断谁"；报警优先于语音播报
> - **资源管理**：音频文件集中放 `Assets/audio`，命名 `alarm_xx.wav`/`voice_xx.mp3`，启动时统一检查存在性
> - **可测试**：音频封装成 `AudioManager`（PlayAlarm/PlayVoice/Mute），界面只调接口不碰播放器

> **MainWindow.xaml.cs —— 后台代码：**
> ```csharp
> using System.Media;
> using System.Windows;
>
> namespace HmiDemo
> {
>     public partial class MainWindow : Window
>     {
>         private readonly SoundPlayer _beep = new SoundPlayer("Assets/beep.wav");
>
>         public MainWindow()
>         {
>             InitializeComponent();
>         }
>
>         private void OnBeep(object sender, RoutedEventArgs e)
>         {
>             _beep.Play();                    // 短提示音：立即播放
>             Log.Text = "已播放提示音（SoundPlayer）";
>         }
>
>         private void PlayVoice()
>         {
>             VoicePlayer.Stop();              // 长语音：手动控制
>             VoicePlayer.Position = System.TimeSpan.Zero;
>             VoicePlayer.Play();
>             Log.Text = "正在语音播报（MediaElement）";
>         }
>     }
> }
> ```

> [!scene] 适用场景
> ✅ 设备报警声光联动：报警音循环 + 状态灯闪烁 + 界面弹窗，三合一提醒
> ✅ 生产事件语音播报："第 1000 件下线""3 号工位缺料"，解放操作员视线
> ✅ 班次提醒：交接班/休息时间到，播报提示音 + 语音
> ✅ 操作引导：新员工培训时"先点启动、再确认参数"的步骤播报
> ❌ 需要 TTS 语音合成（把文字读出来）：用 System.Speech 的 SpeechSynthesizer
> ❌ 多路混音/背景音乐：需要 NAudio 等第三方库做混音与播放列表

> [!pitfall] 常见踩坑
> 坑 1：**报警音和语音播报同时响"打架"** → 现象：界面又响报警又播语音，一片嘈杂 → 原因：SoundPlayer 与 MediaElement 是两套独立播放，无默认互斥 → 解决：设计优先级（报警 > 播报），播新的前先 `Stop()` 旧的，报警解除再恢复播报
> 
> 坑 2：**音频文件缺失时静默失败** → 现象：上线后某些提示音"不响"，无任何报错 → 原因：路径写错/文件未部署，SoundPlayer 与 MediaElement 都可能静默失败 → 解决：启动时统一校验 `Assets/audio` 下文件存在性，缺失项界面亮黄标提示
>
> 坑 3：**语音播报被打断后从头重播** → 现象：播报中途报警，报警解除后语音又从头开始 → 原因：`Stop()` 后 `Position` 归零 → 解决：打断前记录 `Position`，恢复时 `Position = 记录值` 再 Play

> [!best] 最佳实践
> - 封装 `AudioManager`：提供 `PlayAlarm()/PlayVoice()/StopAll()/Mute` 接口，界面与业务只调接口，播放器细节不扩散
> - 音频资源集中放 `Assets/audio`，命名规范 `alarm_xx.wav`、`voice_xx.mp3`，统一清单管理
> - 全局"静音/音效开关"做成资源级开关，现场调试和夜班值班非常实用
> - 多段播报用 List<Uri> 顺序播放：一段播完在 `MediaEnded` 里播下一段，做成"播报队列"
> - 播报逻辑挂在设备状态事件（如 MVVM 的消息/事件）上，而不是界面按钮里，保证任何入口都发声

> [!practice] 上手练习
> **Lv.1 运行体验**：运行示例，点"测试提示音"听短音，理解两类播放器的分工
> **Lv.2 动手改造**：增加"语音播报"按钮，调用示例里的 `PlayVoice()` 播一段 mp3 语音
> **Lv.3 综合实战**：实现"报警优先"——报警音响起时暂停语音播报，解除报警后从断点恢复
> **Lv.4 挑战进阶**：把音频封装成 `AudioManager` 类（PlayAlarm/PlayVoice/StopAll/Mute），改造界面全部改走该接口
