# 增量更新与版本管理

> [!plain] 白话理解
> 全量更新是"每次都发整个安装包"，现场网速差时几十 MB 慢慢传；**增量更新只发"变了的文件"**——比如改了 3 个 dll，就只传这 3 个，现场下载快、停线时间短。版本管理则是给每个发布打上**唯一版本号**（`1.2.0`），谁装了哪个版本、该更新到哪一版，清清楚楚。上位机"少停机、可回退"靠这两件事。

> [!def] 官方定义
> **增量更新（Delta Update）**指更新包只包含自上一版本以来变更的文件/数据块，客户端下载后与本地合并完成升级，以减少传输量（常见实现：对比文件哈希清单，打包差异文件）。**版本管理（Versioning）**指用语义化版本（SemVer，`主版本.次版本.修订号`）标识每个发布，并维护"版本 → 变更内容/文件清单"的元数据。.NET 中版本信息存于程序集 `AssemblyVersion`/`AssemblyInformationalVersion`（`AssemblyInfo.cs`）与 NuGet 包版本，读取用 `Assembly.GetName().Version`：https://learn.microsoft.com/zh-cn/dotnet/standard/assembly/versioning 。两者是 `自动更新检测与下载` 的进阶设计。

> [!origin] 由来背景
> "增量更新"的工程源头可追溯到软件分发早期（补丁包、差分文件），移动应用与游戏领域将其规模化（Google/Apple 的 delta 更新）。上位机场景催生其独特价值：产线不能长时间停机，几百 MB 全量包在车间局域网尚可、跨外网则不可接受；于是"文件级增量"（对比文件清单只传差异）成为标配。版本管理则来自软件工程"可追溯发布"的共识：语义化版本（SemVer 2014 年正式发布）规范了"何时升主/次/修订号"，配合发布清单与回滚通道，让"哪台机器装了什么版本、要不要升、怎么回滚"都可回答——这正是 `增量更新与版本管理` 组合的意义。

> [!essentials] 核心要点
> - **语义化版本**：`主版本.次版本.修订号`（如 `1.2.0`）：破坏性变更升主版本、加功能升次版本、修复升修订号
> - **文件清单对比**：服务端维护"版本 → 文件哈希列表"，客户端比对生成差异清单，只下载变化的文件
> - **增量包结构**：`update.json`（版本 + 文件列表 + 哈希）+ `files/`（变更文件），客户端合并进本地
> - **程序集版本**：`AssemblyInformationalVersion` 统一管理，运行时 `Assembly.GetName().Version` 读取展示
> - **回滚机制**：保留上一版本备份（`backup/1.1.0/`），新版本启动失败自动回退

> [!example] 完整示例
> **增量更新演示：对比新旧版本文件清单（文件名+哈希），只下载差异文件，并展示版本管理（主版本.次版本.修订号）规则：**
>
> **MainWindow.xaml：**
> ```xml
> <Window x:Class="HmiDemo.MainWindow"
>         xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
>         xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
>         Title="增量更新与版本管理" Height="360" Width="480"
>         WindowStartupLocation="CenterScreen" Background="#0D1117">
>     <StackPanel Margin="15">
>         <TextBlock Text="增量更新：只下载差异文件" Foreground="#58A6FF" FontWeight="Bold"/>
>         <Button Content="对比版本并生成增量清单" Click="OnCompare" Margin="0,12,0,0" Padding="8"
>                 Background="#21262D" Foreground="White"/>
>         <TextBlock x:Name="OutputText" Margin="0,12,0,0" Foreground="#8B949E" TextWrapping="Wrap"/>
>     </StackPanel>
> </Window>
> ```
>
> **MainWindow.xaml.cs —— 后台代码：**
> ```csharp
> using System.Collections.Generic;
> using System.Windows;
> using System.Windows.Media;
>
> namespace HmiDemo
> {
>     // 文件清单条目：文件名 + 内容哈希
>     public class FileEntry
>     {
>         public string Name { get; set; }
>         public string Hash { get; set; }
>     }
>
>     public partial class MainWindow : Window
>     {
>         // 本地 v2.0.0 与服务器 v2.0.1 的文件清单
>         private readonly List<FileEntry> _local = new List<FileEntry>
>         {
>             new FileEntry { Name = "HmiDemo.exe", Hash = "A1B2C3" },
>             new FileEntry { Name = "config.json", Hash = "D4E5F6" },
>         };
>
>         private readonly List<FileEntry> _server = new List<FileEntry>
>         {
>             new FileEntry { Name = "HmiDemo.exe", Hash = "A1B2C3" },
>             new FileEntry { Name = "config.json", Hash = "9X8Y7Z" }, // 已变化
>             new FileEntry { Name = "report.dll",  Hash = "M3N4P5" }, // 新增
>         };
>
>         public MainWindow() => InitializeComponent();
>
>         private void OnCompare(object sender, RoutedEventArgs e)
>         {
>             // 遍历服务器清单，找出"新增或哈希不同"的文件 → 只需下载这些
>             List<string> diff = new List<string>();
>             foreach (var item in _server)
>             {
>                 bool changed = true;
>                 foreach (var local in _local)
>                 {
>                     if (local.Name == item.Name && local.Hash == item.Hash) changed = false;
>                 }
>                 if (changed) diff.Add(item.Name);
>             }
>
>             OutputText.Text =
>                 "版本 v2.0.0 → v2.0.1\n差异文件（增量下载）：\n  " +
>                 string.Join("\n  ", diff) +
>                 "\n\n全量 3 个文件 → 增量仅 2 个文件，节省带宽";
>             OutputText.Foreground = new SolidColorBrush(Color.FromRgb(0x23, 0x86, 0x36));
>         }
>     }
> }
> ```
> 

> [!scene] 适用场景
> ✅ 更新包大、现场带宽小：几十 MB 全量包换成几 MB 增量包（示例场景）
> ✅ 频繁小版本迭代：每周发版，全量传输浪费严重
> ✅ 多现场版本参差：同一服务器要支持"从 1.1、1.2 都能升到 1.3"
> ✅ 需要回滚与审计：版本号 + 清单让"装了啥、能不能回"一目了然
> ❌ 程序很小（几 MB）：增量省不了多少，直接全量更简单
> ❌ 只服务单机单版本：版本管理是多余复杂度

> [!pitfall] 常见踩坑
> 坑 1：**增量包漏了"删除文件"信息** → 现象：旧版本有、新版本删掉的 dll 没从客户端删除，程序行为怪异 → 原因：增量只比"变化/新增"，没处理"删除" → 解决：清单里明确"删除文件列表"，客户端合并时执行删除
> 
> 坑 2：**跳版本升级不支持** → 现象：客户端 1.0 想直接升 1.3，但服务器只有"1.2→1.3"增量 → 原因：增量链断裂 → 解决：方案一：客户端逐级升级；方案二：版本差异过大时自动改全量包
>
> 坑 3：**哈希校验只覆盖 zip 不覆盖解压后文件** → 现象：解压被篡改/损坏的文件没被发现 → 原因：只验了下载包的哈希 → 解决：`update.json` 记录每个文件的哈希，解压后逐文件校验再替换

> [!best] 最佳实践
> - 语义化版本严格执行：破坏性变更升主版本（可能不兼容旧配置），加功能升次版本，修复升修订号
> - 文件清单含哈希：`update.json` 记录"文件名+版本+哈希"，增量与校验都靠它
> - 增量合并支持"跳级"：差异过大自动降级为全量包，别让客户端卡在中间版本
> - 版本信息界面可见：`AssemblyInformationalVersion` 显示在"关于"窗口，现场报障能说出版本号
> - 回滚永远有备份：`backup/<旧版本>/` 保留上一版，新版本自检失败自动回退（见 `自动更新检测与下载`）

> [!practice] 上手练习
> **Lv.1 照猫画虎**：运行示例代码，查看"当前版本 1.0.0"与文件清单对比，理解本地与服务器版本的比较逻辑
> **Lv.2 小试牛刀**：构造"增量包"：对比本地文件列表与 `update.json` 的差异，模拟只下载"变化的文件"
> **Lv.3 融会贯通**：把示例升级为"逐文件哈希校验"：解压后对每个文件计算哈希与清单比对，不匹配的拒绝替换
> **Lv.4 拆层挑战**：实现"备份 + 回滚"：替换前把旧文件存 `backup/1.0.0/`，启动自检失败自动恢复并记录日志（见 `上位机日志场景`）
