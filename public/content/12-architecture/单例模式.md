# 单例模式

> [!plain] 白话理解
> 单例模式就是**整个程序只发一张"门禁卡"**：通信通道、全局配置、日志器这类资源，无论从哪个窗口、哪个类去取，拿到的都是同一个实例——不然每个窗口各建一条 TCP 连接，连接数爆炸、状态互相打架。示例里 `DeviceChannel.Instance` 两次访问 `ReferenceEquals` 为 true，正说明"全局唯一"。

> [!def] 官方定义
> 单例模式（Singleton Pattern）是 GoF（《设计模式：可复用面向对象软件的基础》，1994）定义的创建型设计模式之一：**确保一个类只有一个实例，并提供一个全局访问点**。实现要点：私有构造函数 + 静态字段保存实例 + 公开静态属性/方法返回实例。它是软件设计模式（Design Pattern），非微软 API；.NET 官方推荐用 `Lazy<T>` 实现线程安全单例：https://learn.microsoft.com/zh-cn/dotnet/framework/performance/lazyinitialization 。常见实现方式：静态初始化（`static readonly`，类型初始化器保证线程安全，即示例做法）与 `Lazy<T>` 延迟初始化。

> [!origin] 由来背景
> 单例模式的根源可追溯到 1970-80 年代面向对象实践中"全局对象"的需求——操作系统、图形库普遍需要"全系统唯一"的资源管理器。1994 年 Erich Gamma 等四人组（GoF）在《设计模式》中将其正式命名为 Singleton，与工厂、观察者等并列为经典模式。它与 .NET 框架本身无关，而是程序设计模式；微软在 `System.Data.SqlClient` 等库的历史实现中也长期采用单例思路管理连接等共享资源。上位机中，通信通道、全局配置、日志器天然适合单例——但要警惕"全局可变状态"的滥用（见踩坑）。

> [!essentials] 核心要点
> - **三个条件**：私有构造函数（禁 new）、静态实例字段（存唯一实例）、静态访问属性 `Instance`
> - **线程安全**：`static readonly` 字段靠类型初始化器保证；显式懒加载用 `Lazy<T>`（`LazyThreadSafetyMode.ExecutionAndPublication`）
> - **适用对象**：通信通道（TCP/串口）、全局配置（见 12.5 `appsettingsjson推荐方案`）、日志器（见 12.6 `serilog-结构化日志`）
> - **与 DI 的关系**：DI 容器注册 `Singleton` 生命周期也能实现"全局唯一"，且更利于测试（见第 7 章 `常用-di-容器`）
> - **反模式提醒**：可变全局状态是隐藏耦合源，单例只放"共享基础设施"，别放"业务数据"

> [!example] 完整示例
> **设备通信单例演示：DeviceChannel 采用"私有构造函数 + 静态 Instance"保证全局唯一，两个按钮分别验证：连接状态跨窗口共享、多次获取指向同一实例：**
>
> **MainWindow.xaml：**
> ```xml
> <Window x:Class="HmiDemo.MainWindow"
>         xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
>         xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
>         Title="通信管理 - 单例模式" Height="300" Width="420"
>         WindowStartupLocation="CenterScreen" Background="#0D1117">
>     <StackPanel Margin="15">
>         <TextBlock Text="设备通信通道（全局唯一）" Foreground="#58A6FF" FontWeight="Bold"/>
>         <Button Content="连接 PLC（写状态）" Click="OnConnect" Margin="0,12,0,0" Padding="8"
>                 Background="#21262D" Foreground="White"/>
>         <Button Content="模拟另一窗口读取状态" Click="OnRead" Margin="0,8,0,0" Padding="8"
>                 Background="#21262D" Foreground="White"/>
>         <TextBlock x:Name="StatusText" Margin="0,12,0,0" Foreground="#8B949E" TextWrapping="Wrap"/>
>     </StackPanel>
> </Window>
> ```
>
> **MainWindow.xaml.cs —— 后台代码：**
> ```csharp
> using System.Windows;
> using System.Windows.Media;
>
> namespace HmiDemo
> {
>     // 单例类：无论调用多少次 Instance，拿到的都是同一个对象
>     public sealed class DeviceChannel
>     {
>         private static readonly DeviceChannel _instance = new DeviceChannel(); // 静态字段，线程安全
>         public int ChannelId { get; } = 1001; // 模拟通信通道号
>         public string ConnectionStatus { get; private set; } = "未连接";
>
>         private DeviceChannel() { } // 私有构造函数，禁止外部 new
>
>         public static DeviceChannel Instance => _instance;
>
>         public void Connect() => ConnectionStatus = "已连接";
>     }
>
>     public partial class MainWindow : Window
>     {
>         public MainWindow() => InitializeComponent();
>
>         private void OnConnect(object sender, RoutedEventArgs e)
>         {
>             DeviceChannel.Instance.Connect(); // 通过单例写入连接状态
>             ShowStatus();
>         }
>
>         private void OnRead(object sender, RoutedEventArgs e)
>         {
>             // 无论从哪个"窗口"访问，都是同一个实例，因此能看到刚才写入的状态
>             ShowStatus();
>         }
>
>         private void ShowStatus()
>         {
>             var ch = DeviceChannel.Instance;
>             StatusText.Text = $"通道号：{ch.ChannelId}\n连接状态：{ch.ConnectionStatus}" +
>                               $"\n两次访问是否同一实例：{ReferenceEquals(DeviceChannel.Instance, ch)}";
>             StatusText.Foreground = ch.ConnectionStatus == "已连接"
>                 ? new SolidColorBrush(Color.FromRgb(0x23, 0x86, 0x36))
>                 : new SolidColorBrush(Color.FromRgb(0xDA, 0x36, 0x33));
>         }
>     }
> }
> ```
> 

> [!scene] 适用场景
> ✅ 全局唯一通信通道：TCP/串口连接全程序共享一份（示例场景）
> ✅ 全局配置中心：`AppConfig.Instance` 启动加载一次，到处可读（见 12.5 `appsettingsjson推荐方案`）
> ✅ 日志器：`Log.Instance` 所有模块写同一日志文件（见 12.6 `serilog-结构化日志`）
> ✅ 缓存/设备表等"只应存在一份"的共享基础设施
> ❌ 会被多个实例并行操作的对象（如每个设备独立连接）
> ❌ 需要可替换、可测试的组件（用 DI 的 Singleton 生命周期替代，见第 7 章 `常用-di-容器`）

> [!pitfall] 常见踩坑
> 坑 1：**多线程下重复初始化** → 现象：两个线程同时首次访问 `Instance`，各建了一个实例 → 原因：懒加载写法未加锁 → 解决：用 `static readonly` 字段（类型初始化器保证一次）或 `Lazy<T>`，别手写 `if (_instance == null)` 无锁判断
> 
> 坑 2：**单例里放了可变业务状态** → 现象：一个窗口改了单例的 `CurrentProduct`，其他窗口"莫名其妙"看到变化 → 原因：把应属实例的数据塞进全局单例 → 解决：单例只放共享基础设施；业务数据用局部实例 + 事件传递（见 `观察者模式`）
>
> 坑 3：**为了"方便"滥用单例** → 现象：`Helper.Instance`、`Data.Instance` 满天飞，依赖关系全藏在全局里 → 原因：把单例当全局变量用 → 解决：优先构造函数注入；真需要全局时也用 DI 容器注册 Singleton，便于测试替换

> [!best] 最佳实践
> - 优先 `static readonly` 静态初始化：简洁且天然线程安全，满足 99% 场景
> - 需要延迟加载再用 `Lazy<T>`：`private static readonly Lazy<DeviceChannel> _lazy = new(() => new DeviceChannel());`
> - 单例类标记 `sealed` 防继承破坏；构造函数保持 `private`
> - 上位机项目中把"配置、日志、通信"三类单例固定为框架层惯例，团队统一认知
> - 若用了 DI 容器（见第 7 章 `常用-di-容器`），用 `Singleton` 生命周期替代手写单例，测试更友好

> [!practice] 上手练习
> **Lv.1 照猫画虎**：运行示例代码，点击"连接 PLC"后点"模拟另一窗口读取状态"，观察两个按钮看到同一 `ConnectionStatus`，`ReferenceEquals` 输出 true
> **Lv.2 小试牛刀**：给 `DeviceChannel` 增加 `Disconnect()` 与 `LastError` 属性，界面加"断开"按钮，验证仍为同一实例
> **Lv.3 融会贯通**：把示例改造成 `Lazy<T>` 实现的延迟单例，加一个 `GetCreationTime()` 属性确认只创建一次
> **Lv.4 拆层挑战**：用 DI 容器把 `DeviceChannel` 注册为 Singleton（见第 7 章 `常用-di-容器`），在两个 ViewModel 里注入同一实例，验证行为一致
