# 配置加密与运行时修改

> [!plain] 白话理解
> 配置里最敏感的是**数据库密码、MES 接口 Token、PLC 通信密钥**——明文写在 `appsettings.json` 里，任何拿到程序目录的人都能看到。加密就是把这些字段加密存放，程序启动时解密使用；"运行时修改"则是**程序不重启也能改配置**（如现场改报警阈值立即生效）。上位机交付现场，这两招一个保安全、一个保体验。

> [!def] 官方定义
> 配置安全与热更新的两块官方能力：**配置加密**没有"内置一键加密 API"，业界标准做法是用 `System.Security.Cryptography` 的对称加密（AES）或 .NET 的 `ProtectedData`（DPAPI，与当前 Windows 用户绑定，无需密钥文件：https://learn.microsoft.com/zh-cn/dotnet/api/system.security.cryptography.protecteddata ）对敏感字段加解密；**配置热更新**是 `Microsoft.Extensions.Configuration` 内置能力：`ConfigurationBuilder.AddJsonFile(path, optional: true, reloadOnChange: true)` 后，读取端用 `IOptionsMonitor<T>`（`Microsoft.Extensions.Options`）即可在文件变更时自动拿到新值：https://learn.microsoft.com/zh-cn/dotnet/core/extensions/options 。WPF 中两者均可使用，需注意 UI 刷新时机（见第 8 章）。

> [!origin] 由来背景
> 配置明文风险从 .NET 1.0 时代就有：`App.config` 明文存储连接字符串，曾催生微软的 `RsaProtectedConfigurationProvider` 等保护机制（可对 `app.config` 节加密）。.NET Core 时代 JSON 配置更开放，敏感信息泄漏问题依旧，社区与微软的答案转向"**别把密钥写进配置**"（用环境变量、DPAPI、密钥管理服务）。配置热更新则来自云原生"配置即代码、变更即生效"的实践：`IOptionsMonitor` 2017 年前后随 ASP.NET Core 成熟，桌面端沿用同一套 `Configuration` 体系，上位机现场改参数"重启才生效"的痛点从此有了官方解法。

> [!essentials] 核心要点
> - **加密方案**：AES（可移植，带密钥管理）或 DPAPI `ProtectedData.Protect`（绑定当前用户，部署最简单）
> - **密钥存放**：加密的密钥别放同一配置文件——用环境变量/Windows 凭据管理器/外部密钥文件
> - **热更新前提**：`AddJsonFile(reloadOnChange: true)` + 用 `IOptionsMonitor<T>`/`IOptionsChangeTokenSource<T>` 订阅变更
> - **变更订阅**：`IOptionsMonitor<T>.OnChange(newVal => ...)`，回调里更新界面（注意线程：见第 8 章）
> - **安全底线**：无论如何加密，客户端程序里的密钥理论上都可被逆向——真正机密走服务端，客户端只放"泄露损失可接受"的字段

> [!example] 完整示例
> **配置加密与热更新演示：密码字段用 AES 简单加密后存储，界面上修改设备 IP 后点击保存立即生效（模拟运行时修改配置）：**
>
> **MainWindow.xaml：**
> ```xml
> <Window x:Class="HmiDemo.MainWindow"
>         xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
>         xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
>         Title="配置加密与热更新" Height="400" Width="440"
>         WindowStartupLocation="CenterScreen" Background="#0D1117">
>     <StackPanel Margin="15">
>         <TextBlock Text="配置加密 + 运行时修改" Foreground="#58A6FF" FontWeight="Bold"/>
>         <TextBox x:Name="IpBox" Margin="0,12,0,0" Padding="4"
>                  Background="#161B22" Foreground="#8B949E" Text="192.168.1.50"/>
>         <Button Content="加密保存密码（123456）" Click="OnEncrypt" Margin="0,10,0,0" Padding="8"
>                 Background="#21262D" Foreground="White"/>
>         <Button Content="应用新 IP（热更新）" Click="OnApply" Margin="0,8,0,0" Padding="8"
>                 Background="#238636" Foreground="White"/>
>         <TextBlock x:Name="OutputText" Margin="0,12,0,0" Foreground="#8B949E" TextWrapping="Wrap"/>
>     </StackPanel>
> </Window>
> ```
>
> **MainWindow.xaml.cs —— 后台代码：**
> ```csharp
> using System;
> using System.Security.Cryptography;
> using System.Text;
> using System.Windows;
> using System.Windows.Media;
>
> namespace HmiDemo
> {
>     public partial class MainWindow : Window
>     {
>         private string _currentIp = "192.168.1.50";
>         private string _encryptedPassword = "";
>
>         public MainWindow() => InitializeComponent();
>
>         // AES 加密：明文 → 密文（生产环境密钥应从环境变量/密钥服务获取）
>         private static string Encrypt(string plain)
>         {
>             using var aes = Aes.Create();
>             aes.Key = SHA256.HashData(Encoding.UTF8.GetBytes("Hmi-Demo-Key"));
>             aes.IV = new byte[16];
>             using var encryptor = aes.CreateEncryptor();
>             byte[] result = encryptor.TransformFinalBlock(Encoding.UTF8.GetBytes(plain), 0, plain.Length);
>             return Convert.ToBase64String(result);
>         }
>
>         private void OnEncrypt(object sender, RoutedEventArgs e)
>         {
>             _encryptedPassword = Encrypt("123456");
>             OutputText.Text = $"密码已加密保存（密文）：\n{_encryptedPassword}";
>             OutputText.Foreground = new SolidColorBrush(Color.FromRgb(0x23, 0x86, 0x36));
>         }
>
>         private void OnApply(object sender, RoutedEventArgs e)
>         {
>             // 运行时热更新：修改后立即生效，无需重启
>             _currentIp = IpBox.Text;
>             OutputText.Text = $"IP 已热更新为 {_currentIp}（无需重启程序）\n" +
>                               (string.IsNullOrEmpty(_encryptedPassword)
>                                   ? "提示：请先点击上方按钮保存加密密码"
>                                   : "密码密文已就绪，可在连接时解密使用");
>             OutputText.Foreground = new SolidColorBrush(Color.FromRgb(0x23, 0x86, 0x36));
>         }
>     }
> }
> ```
> 

> [!scene] 适用场景
> ✅ 配置文件含数据库密码、MES Token、PLC 通信密钥：必须加密存储（示例场景）
> ✅ 多操作员共用上位机、配置可能被拷走：明文配置 = 机密裸奔
> ✅ 现场需要"改阈值/改参数不重启"：`IOptionsMonitor` 热更新（示例场景）
> ✅ 多产线批量部署：一套程序 + 各产线独立加密配置
> ❌ 无敏感信息的小工具：加密是多余的复杂度
> ❌ 机密级密钥（PKI 私钥等）：客户端加密挡不住逆向，必须走服务端/HSM

> [!pitfall] 常见踩坑
> 坑 1：**密钥与密文放同一个文件** → 现象：配置文件里既有 `Password: "AES256:xxxx"` 又有 `AesKey: "yyyy"` → 原因：图方便 → 解决：密钥用环境变量/Windows 凭据管理器/外部独立文件保存，与密文隔离
> 
> 坑 2：**DPAPI 加密后换电脑解密失败** → 现象：开发机加密的配置拷到现场机器无法解密 → 原因：`ProtectedData` 默认绑定当前用户/机器 → 解决：统一部署用"机器级"范围（`DataProtectionScope.LocalMachine`），跨用户；跨机器仍不行则换 AES + 部署密钥文件
>
> 坑 3：**热更新回调里直接操作 UI** → 现象：`OnChange` 回调改 TextBlock 抛跨线程异常 → 原因：回调在配置线程触发 → 解决：回调里 `Dispatcher.Invoke` 回 UI 线程更新（见第 8 章）

> [!best] 最佳实践
> - 加密只保护"值得保护"的字段：密码、Token 加密；串口号、阈值明文（便于现场调试）
> - AES 优先：密钥放环境变量/外部文件；DPAPI 适合"单机单用户"快速方案
> - 热更新订阅后记得退订：`IDisposable` 释放 `OnChange` 订阅，防止泄漏（见 `观察者模式`）
> - 界面与配置分离：配置变更统一走"配置服务 → 事件广播 → 界面刷新"，别散落各处改控件
> - 加密逻辑封装成服务：`IConfigCrypto.Encrypt/Decrypt`，可单测可替换（见 12.8 `单元测试xunitmoq`）

> [!practice] 上手练习
> **Lv.1 照猫画虎**：运行示例代码，输入密码点"加密"，观察密文与解密后的明文对应；修改配置文件里的阈值观察"运行时修改"生效
> **Lv.2 小试牛刀**：给示例加"加密后写入配置文件"：`Encrypt` 结果存到 `appsettings.json` 的 `SecretValue` 节点，重启后能解密读取
> **Lv.3 融会贯通**：改用 DPAPI（`ProtectedData.Protect`/`Unprotect`）实现同一功能，对比与 AES 的差异（密钥管理方式）
> **Lv.4 拆层挑战**：把"运行时修改"升级为"配置服务"：`IConfigService` 封装读取/加密/热更新，`OnChange` 后通过观察者广播给界面（见 `观察者模式`）
