# 观察者模式

> [!plain] 白话理解
> 观察者模式是**"广播站 + 订阅听众"**：设备数据变了（广播站发声），所有订阅的界面/模块自动收到通知去刷新，谁都不用"点名"。示例里温度一旦超限，报警面板和日志面板同时更新——采集程序不写死"我要通知谁"，只管发事件，订阅方自己决定要不要听。这正是上位机里"一处采集、多处消费"的标准做法。

> [!def] 官方定义
> 观察者模式（Observer Pattern）是 GoF 行为型设计模式：**定义对象间一对多的依赖关系，当被观察者（Subject）状态改变时，自动通知所有观察者（Observer）**。它定义一对多的依赖关系，使多个观察者对象同时监听某一主题对象。.NET 原生支持该模式的两套机制：**C# 事件（`event` + `EventHandler`/`Action`）**与 **`System.ComponentModel.INotifyPropertyChanged`**（WPF 数据绑定的核心，见第 7 章）：https://learn.microsoft.com/zh-cn/dotnet/api/system.componentmodel.inotifypropertychanged 。事件是基于委托的观察者模式实现，`+=`/`-=` 即订阅/退订。

> [!origin] 由来背景
> 观察者模式在 1994 年 GoF《设计模式》中收录，但它更早的应用是 1980-90 年代 GUI 工具包（Smalltalk MVC 中的 Model 通知 View）——这正是"观察者"最早的温床。它的动机是消除"主动轮询/硬编码通知列表"：早期界面更新靠"界面每隔几百毫秒去查一遍数据"（轮询，浪费且滞后），或被通知方写死 `if (panel != null) panel.Refresh()`（紧耦合）。观察者模式把通知反转成"数据方发事件、订阅方响应"，随后 C# 用 `event` 关键字和 `INotifyPropertyChanged` 将其内建为语言级设施，WPF 数据绑定与上位机报警/曲线刷新都是它的直接受益者。

> [!essentials] 核心要点
> - **三要素**：发布者（Subject/数据源）、订阅者（Observer/界面或模块）、事件连接二者
> - **C# 事件写法**：`public event EventHandler<TemperatureChangedEventArgs>? TemperatureChanged;` 触发 `?.Invoke(this, args)`
> - **`INotifyPropertyChanged`**：属性 `set` 里调 `OnPropertyChanged(nameof(X))`，让绑定自动刷新（见第 7 章 `inotifypropertychanged-实现`）
> - **弱事件（WeakEvent）**：长生命周期对象订阅短生命周期对象要防内存泄漏，用 `WeakEventManager` 或退订
> - **适用定位**：报警广播、数据变化刷新曲线/列表、状态变更通知（见第 10 章 `报警系统`）

> [!example] 完整示例
> **设备状态推送演示：设备状态中心（主题）维护订阅者列表，状态变化时批量通知"指示灯观察者"与"日志观察者"，两者互不耦合：**
>
> **MainWindow.xaml：**
> ```xml
> <Window x:Class="HmiDemo.MainWindow"
>         xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
>         xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
>         Title="状态推送 - 观察者模式" Height="340" Width="440"
>         WindowStartupLocation="CenterScreen" Background="#0D1117">
>     <StackPanel Margin="15">
>         <TextBlock Text="设备状态中心（订阅-通知）" Foreground="#58A6FF" FontWeight="Bold"/>
>         <TextBlock x:Name="StatusLamp" Margin="0,12,0,0" FontSize="18" FontWeight="Bold"
>                    Foreground="#DA3633" Text="● 已停止"/>
>         <Button Content="切换运行状态（通知所有订阅者）" Click="OnToggle" Margin="0,12,0,0" Padding="8"
>                 Background="#21262D" Foreground="White"/>
>         <TextBlock Text="订阅者日志：" Foreground="#8B949E" Margin="0,12,0,0"/>
>         <TextBlock x:Name="LogText" Foreground="#8B949E" TextWrapping="Wrap"/>
>     </StackPanel>
> </Window>
> ```
>
> **MainWindow.xaml.cs —— 后台代码：**
> ```csharp
> using System;
> using System.Collections.Generic;
> using System.Windows;
> using System.Windows.Controls;
> using System.Windows.Media;
>
> namespace HmiDemo
> {
>     // 观察者接口：所有订阅者实现 Update，接收主题的变化
>     public interface IDeviceObserver
>     {
>         void Update(bool running);
>     }
>
>     // 主题（Subject）：维护订阅者列表，状态变化时广播通知
>     public class DeviceStatusCenter
>     {
>         private readonly List<IDeviceObserver> _observers = new List<IDeviceObserver>();
>         public bool IsRunning { get; private set; }
>
>         public void Attach(IDeviceObserver observer) => _observers.Add(observer);
>
>         public void Toggle()
>         {
>             IsRunning = !IsRunning;
>             foreach (var observer in _observers) observer.Update(IsRunning); // 逐个通知
>         }
>     }
>
>     public partial class MainWindow : Window, IDeviceObserver
>     {
>         private readonly DeviceStatusCenter _center = new DeviceStatusCenter();
>
>         public MainWindow()
>         {
>             InitializeComponent();
>             _center.Attach(this);                // 观察者 1：窗口自身（指示灯）订阅
>             _center.Attach(new LogObserver(LogText)); // 观察者 2：日志订阅
>         }
>
>         private void OnToggle(object sender, RoutedEventArgs e) => _center.Toggle();
>
>         // 观察者 1 实现：指示灯直接更新 UI
>         public void Update(bool running)
>         {
>             StatusLamp.Text = running ? "● 运行中" : "● 已停止";
>             StatusLamp.Foreground = new SolidColorBrush(Color.FromRgb(
>                 running ? 0x23 : 0xDA, running ? 0x86 : 0x36, running ? 0x36 : 0x33));
>         }
>     }
>
>     // 观察者 2 实现：追加一条日志，与指示灯互不依赖
>     public class LogObserver : IDeviceObserver
>     {
>         private readonly TextBlock _log;
>         public LogObserver(TextBlock log) => _log = log;
>
>         public void Update(bool running)
>         {
>             _log.Text = $"{DateTime.Now:HH:mm:ss} 状态变化 → {(running ? "运行" : "停止")}\n" + _log.Text;
>         }
>     }
> }
> ```
> 

> [!scene] 适用场景
> ✅ 数据变化广播：采集线程温度超限 → 报警面板/曲线/日志同时响应（示例场景）
> ✅ 多窗口联动：一个窗口改参数，其他窗口实时刷新
> ✅ 设备状态通知：连接断开/恢复，状态栏与维护弹窗都收到
> ✅ 订阅-发布解耦：数据生产方不认识消费方，各自独立演化
> ❌ 只有一个订阅者：事件是多余开销，直接方法调用更清晰
> ❌ 高频通知且订阅方处理慢：事件同步调用会拖慢发布者，需节流/异步（见第 8 章）

> [!pitfall] 常见踩坑
> 坑 1：**忘记退订导致内存泄漏** → 现象：关闭窗口后对象仍被事件引用，GC 无法回收，内存只涨不降 → 原因：发布者存活期长、订阅方被 `+=` 强引用 → 解决：窗口 `Closed`/`OnClosed` 里 `-=` 退订，或用 `WeakEventManager`
> 
> 坑 2：**事件在 UI 线程外触发刷新界面** → 现象：后台线程发事件，订阅方直接改 TextBlock 抛 `InvalidOperationException` → 原因：跨线程访问 UI（见第 8 章） → 解决：发布者 `await Task.Run` 后回到 UI 上下文再触发，或订阅方用 `Dispatcher.Invoke`
>
> 坑 3：**订阅方异常中断整个通知链** → 现象：一个订阅方抛异常，后续订阅方全收不到 → 原因：事件委托链一个异常即中断 → 解决：发布方 `try/catch` 包裹 `Invoke`，异常记录日志（见 12.6 `全局异常捕获与记录`），别让订阅方拖垮广播

> [!best] 最佳实践
> - 用 `EventHandler<T>` + `EventArgs` 定义事件，别裸用 `Action`（语义清晰、可携带数据）
> - 发布者属性变更统一走 `INotifyPropertyChanged`（见第 7 章 `inotifypropertychanged-实现`），与绑定天然配合
> - 订阅/退订成对出现：`OnLoaded` 订阅、`OnClosed` 退订，同一处代码管理
> - 高频数据用"节流 + 批量通知"：采集 1kHz 数据只在界面刷新周期（100ms）通知一次
> - 事件异常隔离：发布方捕获订阅方异常，保证"一个坏订阅不连累全体"

> [!practice] 上手练习
> **Lv.1 照猫画虎**：运行示例代码，点"产生超温"，观察报警面板与日志面板同时更新（两个订阅者）
> **Lv.2 小试牛刀**：新增第三个订阅者"曲线记录器"（模拟把温度追加到列表），验证广播新增订阅方发布者零修改
> **Lv.3 融会贯通**：把温度类改为实现 `INotifyPropertyChanged`，界面用 `{Binding Temperature}` 自动刷新（见第 7 章 `inotifypropertychanged-实现`）
> **Lv.4 拆层挑战**：给发布者加"事件异常隔离"：订阅方故意抛异常，验证其他订阅者仍收到通知，异常被记录
