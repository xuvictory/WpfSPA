# 各层职责与交互

> [!plain] 白话理解
> 三层架构只画了"有几间房"，本篇讲**房间之间怎么传话、哪些话不许越层传**。规矩就三条：请求自上而下（界面→服务→仓储→设备），数据自下而上返回，横向不许私聊（界面不能跳过服务层直接找仓储）。示例点"查询设备参数"，你能看到完整调用链：界面层→服务层→仓储层→返回结果，每一层只改自己那份"话"。层间交互是分层架构能不能撑住大型项目的关键。

> [!def] 官方定义
> 层间交互（Layer Interaction）规定分层架构中各层之间的**通信方向、通信载体与职责边界**：依赖方向单向自上而下；上层通过下层公开的接口/服务调用下层能力；跨层数据以**数据传输对象（DTO）/领域模型**承载；同层横向依赖应避免（防止层内耦合失控）。它是对"分层架构"的细化约束，属设计约定而非特定 API。微软官方架构指南的「层与依赖」部分给出依赖规则：https://learn.microsoft.com/zh-cn/dotnet/architecture/modern-web-apps-azure/common-web-application-architectures#layers ，并建议用依赖注入容器维持依赖方向的实现（见第 7 章 `什么是依赖注入`）。

> [!origin] 由来背景
> "层间如何交互"的答案来自实践教训：早期两层应用里界面直接访问数据库，SQL 散落每个按钮的 Click 事件，数据库一改字段全项目报错。分层架构引入后，新的问题变成"层是分了，但到处绕层调用、层与层纠缠不清"。为此业界总结了三条铁律：单向依赖、依赖抽象、数据用对象传递，并通过依赖注入（DI）从机制上保证方向不越界。Martin Fowler《企业应用架构模式》中的 Service Layer 与 Repository 模式，正是"服务层组装仓储层"的标准交互范式。

> [!essentials] 核心要点
> - **职责边界**：界面层管输入输出、服务层管业务流程、仓储层管数据读写，各管各的
> - **调用方向**：请求 UI→Service→Repository 单向下行；结果反向上行返回
> - **交互载体**：方法参数/返回值用 DTO 或实体，禁止直接传 `DataTable`、控件、`Dispatcher` 等实现细节
> - **组合方式**：服务层持有多仓储/多服务的引用完成编排（示例：`DeviceService` 调 `DeviceRepository`）
> - **异步交互**：采集、通信等耗时操作走 `async/await`（见第 8 章），避免阻塞界面线程

> [!example] 完整示例
> **层间交互演示：界面层调用服务层，服务层调用仓储层，数据沿"界面→服务→仓储→设备"单向流动，模拟按钮触发一次完整的"查询设备参数"调用链：**

>         Title="层间交互 - 各层职责" Height="300" Width="420"
>         WindowStartupLocation="CenterScreen" Background="#0D1117">

>         <Button Content="查询设备参数" Click="OnQuery" Margin="0,12,0,0" Padding="8"
>                 Background="#21262D" Foreground="White"/>
>         <TextBlock x:Name="OutputText" Margin="0,12,0,0" Foreground="#8B949E" TextWrapping="Wrap"/>
>     </StackPanel>
> </Window>
> ```
>
> **MainWindow.xaml.cs —— 后台代码：**
> ```csharp
> using System.Windows;
> using System.Windows.Media;
>
> namespace HmiDemo
> {
>     // 仓储层（数据访问）：直接与设备/数据库打交道
>     public class DeviceRepository
>     {
>         public string LoadParameter(string name) => $"{name} = 0.850";
>     }
>
>     // 服务层（业务）：组织调用顺序、做业务校验，是层间交互的枢纽
>     public class DeviceService
>     {
>         private readonly DeviceRepository _repo = new DeviceRepository();
>         public string QueryParameter(string name)
>         {
>             string raw = _repo.LoadParameter(name);
>             return $"服务层校验通过 → {raw} MPa"; // 业务加工
>         }
>     }
>
>     // 界面层：只负责把服务层结果渲染到控件
>     public partial class MainWindow : Window
>     {
>         private readonly DeviceService _service = new DeviceService();
>         public MainWindow() => InitializeComponent();
>
>         private void OnQuery(object sender, RoutedEventArgs e)
>         {
>             // 交互方向：界面 → 服务 → 仓储，返回结果反向传递
>             OutputText.Text = "调用链：\n界面层 → 服务层 → 仓储层\n结果：" +
>                               _service.QueryParameter("压力");
>             OutputText.Foreground = new SolidColorBrush(Color.FromRgb(0x23, 0x86, 0x36));
>         }
>     }
> }
> ```
> 

> [!scene] 适用场景
> ✅ 三层/多层架构项目：界面、服务、仓储各自独立演进，互不越权
> ✅ 服务层承担"编排"职责：一个界面操作背后要组合多次数据访问
> ✅ 数据源会切换：SQLite → SQL Server → 设备内存表，换 DAL 不动上层
> ✅ 需要单元测试：服务层依赖接口仓储，测试用 Mock 替换（见 12.8 `单元测试xunitmoq`）
> ❌ 单层小工具（几十行代码）：不需要层间交互规则
> ❌ 插件内部实现：插件与宿主的通信走契约接口，不套三层

> [!pitfall] 常见踩坑
> 坑 1：**界面跳过服务层直接调仓储** → 现象：业务规则散落在各窗口，服务层形同虚设 → 原因：贪快绕层 → 解决：强制"界面只能调服务层"，把权限/校验逻辑放服务层
> 
> 坑 2：**跨层传 `Dispatcher`、控件、DataTable** → 现象：DAL 返回 `DataTable` 被直接绑到 Grid，一换存储全崩 → 原因：层间载体不是对象而是实现细节 → 解决：定义 DTO，DAL 内部映射，上层只认 DTO（见第 7 章 `dto-vs-entity`）
>
> 坑 3：**同步阻塞跨层调用** → 现象：点按钮后界面卡死，因为 `ReadDevice()` 是同步长调用 → 原因：层间交互用同步方法 → 解决：耗时接口定义成 `Task<T>` 异步方法，界面 `await`（见第 8 章）

> [!best] 最佳实践
> - 服务层是"编排者"不写细节：它组合多个仓储、控制事务与流程，不写 SQL 不碰控件
> - 仓储层只暴露"业务语言"：`GetDeviceByAddress(address)` 而非 `ExecuteDataReader(sql)`
> - 层间全部走接口 + 构造函数注入：依赖方向由 DI 容器保证，测试好替换（见第 7 章 `什么是依赖注入`）
> - 返回结果用 DTO/结果对象：需要"数据 + 是否成功 + 错误信息"时定义结果类型，别用 `Tuple` 堆
> - 交互链路加日志：每个跨层调用记录"入口/出口/耗时"，出问题能快速定位（见 12.6 `serilog-结构化日志`）

> [!practice] 上手练习
> **Lv.1 照猫画虎**：运行示例代码，把 `DeviceService.GetParameter()` 里改成先查缓存再读仓储，观察调用链不变
> **Lv.2 小试牛刀**：新增 `AlarmService` 与 `AlarmRepository`，界面调用服务层查询最近报警，验证"界面→服务→仓储"链条
> **Lv.3 融会贯通**：为示例的服务层定义接口 `IDeviceService`，用构造函数注入替换直接 `new`，界面层只认接口
> **Lv.4 拆层挑战**：给仓储层加异步接口 `Task<List<DeviceDto>> GetDevicesAsync()`，界面 `await` 调用，感受"层间交互全异步"的改法
