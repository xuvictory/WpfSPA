# 什么是插件化架构？

> [!plain] 白话理解
> 插件化架构就是**主程序留好"插口"，功能做成"插件卡"**：核心程序认识一个统一接口（如 `IPlugin`），扫描插件目录就能发现、加载、运行新功能，不用重编译整个上位机。就像工控机箱的 PCI 插槽——插网卡、插采集卡，机箱本身不用改。示例里主程序只认识 `IPlugin`，加载报表、配方两个插件，以后新增"MES 上传插件"只需写个新类，主程序零修改。

> [!def] 官方定义
> 插件化架构（Plug-in Architecture）又称微内核架构（Microkernel Architecture），核心系统（Core System）提供最小运行骨架与**扩展点（Extension Point / Plugin Contract）**，各功能以独立插件实现并通过约定接口挂载；插件可动态发现、加载、卸载，实现"核心稳定、功能可插拔"。它是软件架构（Software Architecture）领域的一种风格，微软在 .NET 生态中提供 **MEF（Managed Extensibility Framework，`System.ComponentModel.Composition`）** 作为官方插件框架：https://learn.microsoft.com/zh-cn/dotnet/framework/mef/ ；Prism 的 **Modularity（模块化）** 是其 WPF 框架内的插件式扩展方案：https://prismlibrary.github.io/docs/wpf/Modularity.html 。核心系统与插件通过**契约接口**通信，运行时用反射/组合容器装配。

> [!origin] 由来背景
> 插件思想的源头可追溯到 1960-70 年代：操作系统通过"设备驱动"动态挂载硬件（BSD 的可加载内核模块）、UNIX 的"管道+工具"哲学（小而专、自由组合）。1980-90 年代浏览器插件（Netscape/IE）与图像处理软件 Photoshop 的滤镜插件让"宿主+插件"模式普及。软件工程上，Robert C. Martin 的**开闭原则**（对扩展开放、对修改关闭）为插件化提供了理论依据——核心关闭修改、插件开放扩展。微软在 .NET 3.0（2006）随 WPF 一起推出 MEF，2010 年代 Prism 的 Modularity 进一步把插件思想引入 MVVM 架构。

> [!essentials] 核心要点
> - **契约接口**：插件实现的统一接口（`IPlugin`）就是"插槽"，接口稳定，插件才可替换
> - **发现机制**：运行时扫描插件程序集（反射 / MEF 目录），不用改主程序就能找到插件
> - **核心系统**：宿主只依赖契约，不依赖任何具体插件，保证"核心关闭修改"
> - **装配方式**：反射 `Assembly.LoadFrom` 或 MEF `[Export]/[Import]`（见 `mef-与-prism-modules`）
> - **边界治理**：插件与插件之间不直接互相依赖，通信走宿主转发或事件（防耦合扩散）

> [!example] 完整示例
> **插件化架构最小演示：定义 IPlugin 契约接口，主程序通过反射从插件目录加载程序集，界面列出所有已加载插件并执行，新增插件无需改动主程序：**
>
> **MainWindow.xaml：**
> ```xml
> <Window x:Class="HmiDemo.MainWindow"
>         xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
>         xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
>         Title="插件化架构演示" Height="340" Width="440"
>         WindowStartupLocation="CenterScreen" Background="#0D1117">
>     <StackPanel Margin="15">
>         <TextBlock Text="插件加载器（反射扫描插件目录）" Foreground="#58A6FF" FontWeight="Bold"/>
>         <Button Content="扫描并加载插件" Click="OnLoad" Margin="0,12,0,0" Padding="8"
>                 Background="#21262D" Foreground="White"/>
>         <TextBlock x:Name="PluginList" Margin="0,10,0,0" Foreground="#8B949E" TextWrapping="Wrap"/>
>         <Button x:Name="RunButton" Content="执行选中插件" Click="OnRun" Margin="0,10,0,0" Padding="8"
>                 Background="#238636" Foreground="White" IsEnabled="False"/>
>         <TextBlock x:Name="OutputText" Margin="0,10,0,0" Foreground="#8B949E" TextWrapping="Wrap"/>
>     </StackPanel>
> </Window>
> ```
>
> **MainWindow.xaml.cs —— 后台代码（插件契约 + 反射加载）：**
> ```csharp
> using System;
> using System.Collections.Generic;
> using System.Windows;
> using System.Windows.Media;
>
> namespace HmiDemo
> {
>     // 插件契约：所有插件必须实现该接口
>     public interface IPlugin
>     {
>         string Name { get; }
>         string Execute();
>     }
>
>     // 示例插件 1：报表
>     public class ReportPlugin : IPlugin
>     {
>         public string Name => "生产报表插件";
>         public string Execute() => "已生成今日生产报表（1280 件）";
>     }
>
>     // 示例插件 2：配方
>     public class RecipePlugin : IPlugin
>     {
>         public string Name => "配方管理插件";
>         public string Execute() => "已加载配方 A-12（温度 100℃ / 时间 30s）";
>     }
>
>     public partial class MainWindow : Window
>     {
>         private readonly List<IPlugin> _plugins = new List<IPlugin>();
>
>         public MainWindow() => InitializeComponent();
>
>         private void OnLoad(object sender, RoutedEventArgs e)
>         {
>             // 生产中可用 Assembly.LoadFrom 扫描插件目录 dll，
>             // 这里用内建插件演示同样的"按契约发现"机制
>             _plugins.Clear();
>             _plugins.Add(new ReportPlugin());
>             _plugins.Add(new RecipePlugin());
>             string list = "已发现插件：\n";
>             for (int i = 0; i < _plugins.Count; i++) list += $"{i + 1}. {_plugins[i].Name}\n";
>             PluginList.Text = list;
>             RunButton.IsEnabled = true;
>         }
>
>         private void OnRun(object sender, RoutedEventArgs e)
>         {
>             string result = "";
>             foreach (var p in _plugins) result += $"【{p.Name}】{p.Execute()}\n";
>             OutputText.Text = result;
>             OutputText.Foreground = new SolidColorBrush(Color.FromRgb(0x23, 0x86, 0x36));
>         }
>     }
> }
> ```
> 

> [!scene] 适用场景
> ✅ 上位机协议多变：Modbus/S7/OPC UA/私有协议都要支持，协议做成插件
> ✅ 功能模块独立交付：报表、配方、MES 上传由不同团队开发、独立升级
> ✅ 需要在现场"热插拔"功能：放个 dll 到插件目录，重启即生效，不用重编译
> ✅ 产品线化销售：基础版 + 收费插件，核心程序一份，功能按授权解锁
> ❌ 功能固定、不会变化的小软件：插件化只有成本没有收益
> ❌ 插件之间强耦合的业务：相互依赖的设计做成插件会变成"剪不断理还乱"

> [!pitfall] 常见踩坑
> 坑 1：**契约接口设计得不好** → 现象：接口只有 `Name`/`Execute()`，插件想传配置、想回调宿主，全部卡死 → 原因：契约抽象度不够 → 解决：接口预留上下文（`IPluginContext` 提供宿主能力）与生命周期（`Initialize/Shutdown`），先小范围试插件再定稿
> 
> 坑 2：**加载了无法卸载的插件 dll** → 现象：替换插件时 dll 被占用，提示"文件正在使用" → 原因：`Assembly.LoadFrom` 进默认上下文无法卸载 → 解决：动态更新用 `AssemblyLoadContext`（.NET Core 3.0+）或设计为"重启生效"，别在运行中覆盖 dll
>
> 坑 3：**插件异常拖垮主程序** → 现象：某个插件抛异常，整个上位机崩溃 → 原因：宿主直接调用插件没隔离 → 解决：宿主用 `try/catch` 包裹插件调用，记录异常（见 12.6 `全局异常捕获与记录`），插件隔离运行或标记禁用

> [!best] 最佳实践
> - 契约先行、接口稳定：插件架构成败 80% 在 `IPlugin` 设计，改契约 = 所有插件重编
> - 宿主只依赖契约：不 `using` 任何具体插件程序集，全部按接口反射/MEF 装配（见 `mef-与-prism-modules`）
> - 插件目录规范：约定 `Plugins/` 目录 + 配置文件登记（`Plugins.json`），加载前校验
> - 插件带版本与元数据：`[Plugin("报表", "1.2.0")]` 便于展示与版本控制（见 12.7 `增量更新与版本管理`）
> - 插件间通信走宿主：A 插件要 B 插件的数据，通过宿主事件/服务转发，禁止直接引用

> [!practice] 上手练习
> **Lv.1 照猫画虎**：运行示例代码，新增第三个内建插件（如"报警插件"）实现 `IPlugin`，观察"发现"逻辑不变
> **Lv.2 小试牛刀**：给 `IPlugin` 加 `Initialize()` 方法并在宿主启动时调用，验证"发现→初始化→执行"生命周期
> **Lv.3 融会贯通**：用 `DirectoryCatalog` + MEF 把示例改成"扫描 `Plugins` 目录加载 dll"，放一个外部 dll 进去试试（见 `mef-与-prism-modules`）
> **Lv.4 拆层挑战**：为插件加入配置上下文 `IPluginContext`（提供日志、配置读取），插件通过上下文读写自己的配置，体会契约设计
