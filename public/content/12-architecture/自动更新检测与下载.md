# 自动更新检测与下载

> [!plain] 白话理解
> ClickOnce 适合"省事"，但上位机常有**特殊要求**：更新时不能停产、要校验文件完整性、版本回退。这时需要"自研更新器"：程序启动后访问更新服务器，读版本清单文件（`version.json`），比本地版本号——有新版本就下载压缩包、校验、替换、重启。示例演示的就是这套"检测→下载→解压→重启"自研流程，更新服务器用 HTTP 即可。

> [!def] 官方定义
> 自动更新（Auto-Update）指程序自行从更新服务器获取**版本清单（version manifest）**，比较本地与远程版本，下载增量/全量更新包并完成替换重启的机制。它没有"官方一键 API"，业界标准做法是：更新服务器提供版本描述文件（JSON/XML），客户端 `HttpClient` 拉取比对，下载后校验（哈希/签名）再应用（见 `增量更新与版本管理`）。.NET 提供 `System.Net.Http.HttpClient` 做下载，`System.IO.Compression` 解压更新包：https://learn.microsoft.com/zh-cn/dotnet/api/system.net.http.httpclient 。工业软件还常参考 ClickOnce 的安全模型（清单签名、校验）。

> [!origin] 由来背景
> 自动更新的需求来自"分散设备 + 频繁迭代"的现实：上位机分布在车间各产线，版本迭代往往以周计，逐台手动更新既慢又容易漏。ClickOnce 虽有自更新，但发布格式封闭、定制空间小（无法自定义下载进度、增量、回滚策略）。因此工业界流行"自研更新器"：一个轻量 Updater 进程（或程序内更新模块）+ HTTP/文件服务器，用 `version.json` 描述最新版本与下载地址。这套模式借鉴了软件行业"delta update / 增量更新"（游戏行业、移动端 OS 的成熟实践），成为上位机更新的事实标准。

> [!essentials] 核心要点
> - **版本清单**：`version.json`（`{ "version": "1.2.0", "url": "...", "md5": "..." }`）放更新服务器，程序启动拉取比对
> - **检测流程**：`HttpClient.GetStringAsync(versionUrl)` → `Version.Parse` 比较 → 有更新则提示/静默下载
> - **下载与校验**：下载更新包（zip）→ 计算哈希与清单比对 → 解压到临时目录（防半截文件）
> - **替换与重启**：关停主程序 → 覆盖文件 → 重启（可用独立 `Updater.exe` 进程完成，避免文件占用）
> - **失败回滚**：更新前备份旧版本目录，失败时自动恢复（可靠性第一，见 `增量更新与版本管理`）

> **MainWindow.xaml.cs —— 后台代码：**
> ```csharp
> using System;
> using System.Threading;
> using System.Windows;
> using System.Windows.Media;
> using System.Windows.Threading;
>
> namespace HmiDemo
> {
>     public partial class MainWindow : Window
>     {
>         private readonly DispatcherTimer _timer = new DispatcherTimer();
>         private int _progress = 0;
>
>         public MainWindow()
>         {
>             InitializeComponent();
>             _timer.Interval = TimeSpan.FromMilliseconds(150);
>             _timer.Tick += OnTick;
>         }
>
>         private void OnCheck(object sender, RoutedEventArgs e)
>         {
>             // 真实场景：请求 http://update.hmi.com/version 比对版本号
>             OutputText.Text = "服务器返回：最新版本 2.1.0（本地 2.0.5）\n→ 发现更新，可点击下载";
>             OutputText.Foreground = new SolidColorBrush(Color.FromRgb(0x23, 0x86, 0x36));
>         }
>
>         private void OnDownload(object sender, RoutedEventArgs e)
>         {
>             _progress = 0;
>             DownloadBar.Value = 0;
>             _timer.Start(); // 定时器模拟下载进度
>         }
>
>         private void OnTick(object sender, EventArgs e)
>         {
>             _progress += 5;
>             DownloadBar.Value = _progress;
>             if (_progress >= 100)
>             {
>                 _timer.Stop();
>                 OutputText.Text = "下载完成，校验 MD5 通过\n请重启程序完成安装";
>                 OutputText.Foreground = new SolidColorBrush(Color.FromRgb(0x23, 0x86, 0x36));
>             }
>         }
>     }
> }
> ```

> [!scene] 适用场景
> ✅ 需要自定义更新流程：进度显示、增量、灰度、回滚策略（ClickOnce 给不了）
> ✅ 更新包需要校验/加密：企业内网安全要求
> ✅ 多产线统一升级：一套更新服务器 + 版本清单，批量可控升级
> ✅ 更新时机可控：操作员确认/闲时更新，避免停线冲突
> ❌ 简单内网更新：ClickOnce 够用就别自研（见 `clickonce-部署与更新`）
> ❌ 无维护更新服务器的条件：本地文件共享 + 手动拷贝更实际

> [!pitfall] 常见踩坑
> 坑 1：**下载中断留下半截文件** → 现象：更新包只下载一半，解压失败程序损坏 → 原因：没做完整性校验 → 解决：下载到临时文件，计算哈希与 `version.json` 比对通过后再覆盖（示例已演示）
> 
> 坑 2：**正在运行时替换 dll 失败** → 现象：更新时提示"文件被占用" → 原因：主程序锁着程序集 → 解决：先写更新标记文件，主程序退出后由独立 `Updater.exe` 完成替换再启动；或更新时先退主程序
>
> 坑 3：**版本号格式不一致比较出错** → 现象：`"1.2.0"` 与 `"1.10.0"` 按字符串比，`1.10` < `1.2` → 原因：用 `string.Compare` 比版本 → 解决：统一用 `Version.Parse` 比较（示例即用 `Version`），本地与服务器清单格式一致

> [!best] 最佳实践
> - `version.json` 是事实标准：`{ "version": "1.2.0", "url": "...", "md5": "..." }`，客户端只依赖这份文件
> - 下载用临时目录 + 校验后替换：`temp/` 下载 → 哈希校验 → 备份旧版 → 覆盖 → 重启
> - 独立 Updater 进程做替换：`HmiUpdater.exe` 负责"关主程序→替换→重启"，避免文件占用
> - 更新全程记日志：开始/下载进度/校验结果/替换结果，出问题可查（见 `上位机日志场景`）
> - 失败回滚：替换前备份 `backup/`，新版本启动失败自动恢复旧版本并告警

> [!practice] 上手练习
> **Lv.1 照猫画虎**：运行示例代码，修改 `version.json` 版本号，点"检查更新"观察检测与提示
> **Lv.2 小试牛刀**：给示例加"下载进度条"：`HttpClient` 流式下载并 `ReportProgress` 到界面（见第 8 章异步）
> **Lv.3 融会贯通**：加哈希校验：`version.json` 里带 md5，下载后计算比对，不匹配则报错并删除临时文件
> **Lv.4 拆层挑战**：实现"备份回滚"：替换前把旧文件复制到 `backup/1.1.0/`，界面加"回滚到上一版本"按钮，恢复备份并重启
