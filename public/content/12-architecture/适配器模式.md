# 适配器模式

> [!plain] 白话理解
> 适配器模式就是**"转接头"**：旧设备的 `FetchRegister()` 接口和新系统的 `IDeviceReader.ReadData()` 对不上，直接接会崩，那就做一个 `ModbusAdapter` 转接头——它实现新接口、内部转调旧方法。新代码照常用 `ReadData()`，旧设备也接进来了，两边都不用改。上位机里接老设备、老库、老协议全靠它"救场"。

> [!def] 官方定义
> 适配器模式（Adapter Pattern）是 GoF 结构型设计模式：**将一个类的接口转换成客户希望的另一个接口，使原本因接口不兼容而无法一起工作的类能够协作**。两种形态：对象适配器（组合，持有被适配者，推荐）与类适配器（继承，C# 单继承下较少用）。它是软件设计模式，非微软 API。.NET 官方框架中 `System.Drawing.Bitmap` 与 WPF `BitmapSource` 的转换（`Imaging.CreateBitmapSourceFromHBitmap`）就是典型的"接口转换"场景：https://learn.microsoft.com/zh-cn/dotnet/desktop/wpf/graphics-multimedia/imaging-overview 。

> [!origin] 由来背景
> 适配器思想来自硬件世界的"插头转换器"与"打印/显示驱动"——早期设备厂商各定各的接口，软件要兼容它们就得做转换层。1994 年 GoF《设计模式》将"接口不兼容时提供转换层"抽象为 Adapter 模式。它在 .NET 生态中无处不在：`DataAdapter`（DataSet 与数据库的桥梁，正是 ADO.NET 的适配器）、`StreamReader`（字节流转文本流）、WPF 的 `TypeConverter`（类型转换）。上位机中老设备协议（Modbus 老版函数库）、第三方 DLL、遗留代码都是适配器的典型用武之地。

> [!essentials] 核心要点
> - **三个角色**：目标接口（`IDeviceReader`）、被适配者（`OldModbusDevice`）、适配器（`ModbusAdapter`）
> - **对象适配器写法**：适配器实现目标接口 + 持有被适配者实例，方法内转调（示例即此形态）
> - **调用方无感**：业务层只认目标接口，新旧设备一视同仁，零改动接入
> - **应用场景**：老设备接入新系统、第三方库接口转换、协议帧格式转换、图片/数据流转换
> - **与装饰器区别**：适配器"改接口"，装饰器"加功能"（不改接口）——别混用

> [!example] 完整示例
> **旧协议设备接入演示：老式 Modbus 设备的读取方法名与新版上位机接口不一致，用 ModbusAdapter 适配器转换接口，让新旧设备统一调用：**
>
> **MainWindow.xaml：**
> ```xml
> <Window x:Class="HmiDemo.MainWindow"
>         xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
>         xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
>         Title="设备适配 - 适配器模式" Height="320" Width="440"
>         WindowStartupLocation="CenterScreen" Background="#0D1117">
>     <StackPanel Margin="15">
>         <TextBlock Text="新系统统一设备接口" Foreground="#58A6FF" FontWeight="Bold"/>
>         <Button Content="读取新设备数据" Click="OnReadNew" Margin="0,12,0,0" Padding="8"
>                 Background="#21262D" Foreground="White"/>
>         <Button Content="读取旧设备数据（经适配器）" Click="OnReadOld" Margin="0,8,0,0" Padding="8"
>                 Background="#21262D" Foreground="White"/>
>         <TextBlock x:Name="OutputText" Margin="0,12,0,0" Foreground="#8B949E" TextWrapping="Wrap"/>
>     </StackPanel>
> </Window>
> ```
>
> **MainWindow.xaml.cs —— 后台代码：**
> ```csharp
> using System.Windows;
> using System.Windows.Media;
>
> namespace HmiDemo
> {
>     // 目标接口：新版上位机所有设备都实现该接口
>     public interface IDeviceReader
>     {
>         string ReadData();
>     }
>
>     // 新设备：直接实现目标接口
>     public class NewDevice : IDeviceReader
>     {
>         public string ReadData() => "新设备读取：温度 25.6℃，压力 0.82MPa";
>     }
>
>     // 旧设备（被适配者）：方法名与目标接口不兼容，无法直接使用
>     public class OldModbusDevice
>     {
>         public string FetchRegister() => "旧设备读取：温度 25.6℃，压力 0.82MPa";
>     }
>
>     // 适配器：把旧设备的方法转换为目标接口，调用方无需修改任何代码
>     public class ModbusAdapter : IDeviceReader
>     {
>         private readonly OldModbusDevice _oldDevice = new OldModbusDevice();
>         public string ReadData() => _oldDevice.FetchRegister(); // 转调旧设备方法
>     }
>
>     public partial class MainWindow : Window
>     {
>         public MainWindow() => InitializeComponent();
>
>         private void OnReadNew(object sender, RoutedEventArgs e)
>         {
>             IDeviceReader device = new NewDevice();
>             OutputText.Text = device.ReadData();
>             OutputText.Foreground = new SolidColorBrush(Color.FromRgb(0x23, 0x86, 0x36));
>         }
>
>         private void OnReadOld(object sender, RoutedEventArgs e)
>         {
>             // 同样以 IDeviceReader 身份调用，适配器内部完成转换
>             IDeviceReader device = new ModbusAdapter();
>             OutputText.Text = device.ReadData() + "\n（经适配器转换，业务层代码零改动）";
>             OutputText.Foreground = new SolidColorBrush(Color.FromRgb(0x23, 0x86, 0x36));
>         }
>     }
> }
> ```
> 

> [!scene] 适用场景
> ✅ 老设备接入新系统：旧 Modbus 函数库接口与统一设备接口不一致（示例场景）
> ✅ 第三方 DLL 接口转换：厂商 SDK 方法名/签名与业务层约定不同
> ✅ 数据格式转换：字节数组 ↔ 结构体、旧帧格式 ↔ 新帧格式
> ✅ 遗留代码复用：老模块方法无法修改，加一层适配器接入
> ❌ 接口本来就一致：适配器是多余包装
> ❌ 被适配类结构差异太大（不止接口不同）：先重构或重写，别硬套适配器

> [!pitfall] 常见踩坑
> 坑 1：**在业务层到处写"手动适配"** → 现象：`if (device is OldModbusDevice) ... FetchRegister()` 散落各处 → 原因：没建统一适配器 → 解决：建 `ModbusAdapter` 一次性转换，业务层永远只面对 `IDeviceReader`
> 
> 坑 2：**适配器里做"附加功能"** → 现象：适配器里加日志、加缓存、改行为 → 原因：把适配器和装饰器混用 → 解决：适配器只做"接口转换"，附加能力用装饰器/拦截器或直接放业务层
>
> 坑 3：**适配器泄漏被适配者细节** → 现象：适配器返回 `Dictionary<string, object>` 而非强类型，调用方还得解析 → 原因：转换层没完成"语义转换" → 解决：适配器输出业务模型/DTO（见第 7 章 `dto-vs-entity`），让上层无感知

> [!best] 最佳实践
> - 对象适配器优先：组合被适配者，别用继承（C# 单继承会限制扩展）
> - 适配器集中在"边界"位置：设备接入层、第三方 SDK 封装层各放一个，别散在业务中
> - 适配器输出"业务语言"：返回 `DeviceData` 强类型，而非寄存器数组（见第 10 章 `数据解析字节序类型转换`）
> - 适配器保持薄与纯：只转接口、不写业务规则，便于单测（见 12.8 `单元测试xunitmoq`）
> - 命名体现意图：`ModbusAdapter`/`LegacySdkAdapter`，一看就知道"适配谁"

> [!practice] 上手练习
> **Lv.1 照猫画虎**：运行示例代码，点"读取旧设备数据（经适配器）"，观察输出含"经适配器转换"提示，业务调用方式与"新设备"完全一致
> **Lv.2 小试牛刀**：再写一个 `FakeDeviceAdapter`：让一个"模拟器设备"（`ReadSimulatedData()`）也以 `IDeviceReader` 接入，界面加按钮验证
> **Lv.3 融会贯通**：把示例改成"老设备返回字节数组"：`OldModbusDevice.ReadRegisters()` 返回 `ushort[]`，适配器内转成 `DeviceData`（温度/压力），业务层拿到强类型
> **Lv.4 拆层挑战**：结合工厂模式，`DeviceFactory.Create(name)` 内部判断"新设备直接返回、老设备包适配器"，调用方彻底无感知
