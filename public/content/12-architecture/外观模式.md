# 外观模式

> [!plain] 白话理解
> 外观模式是**给整个系统装一个"一键总开关"**：通信、日志、报警、配方四个子系统的初始化步骤，界面不用挨个调，`HmiSystemFacade.Start()` 一次搞定。就像酒店前台——住客不用自己跑水电、保洁、安保，到前台说一声"入住"就行。界面从此只认识外观类，不认识十几个内部模块。

> [!def] 官方定义
> 外观模式（Facade Pattern）是 GoF 结构型设计模式：**为子系统中的一组接口提供一个统一的简化入口（Facade），客户端只与该入口交互，从而降低客户端与子系统内部的耦合**。它定义一个高层接口，让子系统更容易使用，但不禁止客户端直接访问子系统（与封装不同，外观是"门面"而非"黑盒"）。它属软件设计模式；微软 .NET 框架中 `System.Net.Http.HttpClient` 可视为 HTTP 协议的"外观"（统一封装连接、请求、响应细节）：https://learn.microsoft.com/zh-cn/dotnet/api/system.net.http.httpclient 。

> [!origin] 由来背景
> 外观模式 1994 年由 GoF 收录，动机源于"子系统复杂化后的调用灾难"：大型系统拆成许多模块后，客户端要完成一件事往往要按顺序调七八个对象的方法，且顺序错了就出错。GoF 提出 Facade 作为"与子系统通信的唯一集中点"，让高层接口变薄、内部实现可变。它在框架设计中屡见不鲜：`HttpClient` 封装了连接池/重定向/压缩细节，`DbConnection` 封装了连接生命周期，上位机里的 `Start()`/`Stop()` 一键启停正是外观思想的直接体现。

> [!essentials] 核心要点
> - **外观类**：持有一组子系统引用，提供 `Start()`/`Stop()` 等高层方法编排调用顺序
> - **客户端只依赖外观**：界面/调用方不认识内部模块，内部重构不波及外层（开闭原则）
> - **不限制直访**：需要细粒度控制时仍可直接调用子系统，外观是"门面"不是"壁垒"
> - **典型场景**：一键启动/停止系统、打包初始化流程、封装第三方库复杂 API
> - **与分层的关系**：服务层可看作业务子系统的外观，组合多个仓储完成编排（见 `各层职责与交互`）

> [!example] 完整示例
> **一键启动系统演示：HmiSystemFacade 外观类把通信、日志、报警、配方四个子系统的初始化步骤封装成一个 Start()，调用方无需了解内部细节：**
>
> **MainWindow.xaml：**
> ```xml
> <Window x:Class="HmiDemo.MainWindow"
>         xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
>         xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
>         Title="一键启动 - 外观模式" Height="320" Width="440"
>         WindowStartupLocation="CenterScreen" Background="#0D1117">
>     <StackPanel Margin="15">
>         <TextBlock Text="上位机系统一键启动" Foreground="#58A6FF" FontWeight="Bold"/>
>         <Button Content="启动系统（一键完成所有初始化）" Click="OnStart" Margin="0,12,0,0" Padding="8"
>                 Background="#21262D" Foreground="White"/>
>         <Button Content="停止系统" Click="OnStop" Margin="0,8,0,0" Padding="8"
>                 Background="#21262D" Foreground="White"/>
>         <TextBlock x:Name="OutputText" Margin="0,12,0,0" Foreground="#8B949E" TextWrapping="Wrap"/>
>     </StackPanel>
> </Window>
> ```
>
> **MainWindow.xaml.cs —— 后台代码：**
> ```csharp
> using System;
> using System.Windows;
> using System.Windows.Media;
>
> namespace HmiDemo
> {
>     // 子系统 1：通信模块
>     public class CommModule
>     {
>         public void Init() { /* 连接 PLC、配置端口等 */ }
>     }
>
>     // 子系统 2：日志模块
>     public class LogModule
>     {
>         public void Init() { /* 初始化日志文件 */ }
>     }
>
>     // 子系统 3：报警模块
>     public class AlarmModule
>     {
>         public void Init() { /* 加载报警阈值 */ }
>     }
>
>     // 子系统 4：配方模块
>     public class RecipeModule
>     {
>         public void Init() { /* 加载默认配方 */ }
>     }
>
>     // 外观类：统一封装复杂子系统的初始化顺序，简化客户端调用
>     public class HmiSystemFacade
>     {
>         private readonly CommModule _comm = new CommModule();
>         private readonly LogModule _log = new LogModule();
>         private readonly AlarmModule _alarm = new AlarmModule();
>         private readonly RecipeModule _recipe = new RecipeModule();
>
>         public string Start()
>         {
>             var steps = new[]
>             {
>                 "初始化日志模块", "初始化通信模块（连接 PLC）",
>                 "加载报警阈值", "加载默认配方"
>             };
>             _log.Init(); _comm.Init(); _alarm.Init(); _recipe.Init();
>             return string.Join("\n", steps);
>         }
>     }
>
>     public partial class MainWindow : Window
>     {
>         private readonly HmiSystemFacade _facade = new HmiSystemFacade();
>
>         public MainWindow() => InitializeComponent();
>
>         private void OnStart(object sender, RoutedEventArgs e)
>         {
>             // 客户端只面对一个简单接口，内部复杂性被外观类屏蔽
>             OutputText.Text = "系统启动中：\n" + _facade.Start();
>             OutputText.Foreground = new SolidColorBrush(Color.FromRgb(0x23, 0x86, 0x36));
>         }
>
>         private void OnStop(object sender, RoutedEventArgs e)
>         {
>             OutputText.Text = $"系统已停止（{DateTime.Now:HH:mm:ss}）";
>             OutputText.Foreground = new SolidColorBrush(Color.FromRgb(0xDA, 0x36, 0x33));
>         }
>     }
> }
> ```
> 

> [!scene] 适用场景
> ✅ 系统一键启动/停止：通信+日志+报警+配方按序初始化（示例场景）
> ✅ 封装复杂第三方库：给厂商 SDK 提供简化调用入口
> ✅ 界面需要"整操作"而非"碎操作"：点一个按钮完成一串动作
> ✅ 子系统内部重构时保护外层：界面只依赖外观，内部随便改
> ❌ 客户端需要细粒度控制每个子系统：外观挡住了灵活性
> ❌ 子系统本身很薄：外观是多余的一层

> [!pitfall] 常见踩坑
> 坑 1：**外观类变成"上帝类"** → 现象：`HmiSystemFacade` 方法越来越多，十几个方法各管各的 → 原因：把外观当成收纳所有调用的垃圾桶 → 解决：外观方法保持"高内聚编排"，一个方法对应一个业务动作，复杂子系统分多个外观
> 
> 坑 2：**把外观当封装，禁止直访子系统** → 现象：界面想单独"只启动通信"被外观挡住 → 原因：混淆门面与黑盒 → 解决：外观只提供便捷入口，不阻止客户端直接访问子系统对象
>
> 坑 3：**外观里写了具体业务逻辑** → 现象：`Start()` 里直接操作界面控件、拼 SQL → 原因：外观退化成业务层 → 解决：外观只做"编排与转发"，业务规则放对应子系统/服务层（见 `各层职责与交互`）

> [!best] 最佳实践
> - 外观方法对应"用户能理解的业务动作"：`Start()`、`Stop()`、`Login()`，而非 `InitCommThenLog()` 
> - 外观内部用 DI 注入子系统：`HmiSystemFacade(CommModule, LogModule, ...)`，便于测试（见第 7 章 `什么是依赖注入`）
> - 启动顺序与失败处理明确：哪一步失败要记录并回滚已启动模块（见 12.6 `全局异常捕获与记录`）
> - 一个复杂子系统一个外观：`CommFacade`、`ReportFacade`，别全塞一个类
> - 与单例配合：系统级外观可注册为单例/DI Singleton，全局唯一入口

> [!practice] 上手练习
> **Lv.1 照猫画虎**：运行示例代码，点"启动系统"，观察四个模块按序初始化输出，点"停止"查看结束时间
> **Lv.2 小试牛刀**：给 `HmiSystemFacade` 增加 `Restart()`（先 Stop 再 Start），界面加"重启系统"按钮
> **Lv.3 融会贯通**：把 `HmiSystemFacade` 改成构造函数注入四个模块，用第 7 章 `常用-di-容器` 装配，替换内部 `new`
> **Lv.4 拆层挑战**：模拟"启动失败回滚"：让 `AlarmModule.Init()` 抛异常，外观捕获后调用已初始化模块的 `Shutdown()` 回滚，输出错误信息
