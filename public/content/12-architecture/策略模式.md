# 策略模式

> [!plain] 白话理解
> 策略模式是**把"怎么做"做成可插拔的配件**：算法或行为（如"温度超限怎么处理"）封装成一个个策略类，运行时选哪个用哪个，业务代码只管调用策略接口。示例里 `NotifyStrategy` 从"日志"切到"弹窗"再切到"短信"——切换行为不用改业务逻辑，就像换台机器的模具。

> [!def] 官方定义
> 策略模式（Strategy Pattern）是 GoF 行为型设计模式：**定义一族算法，把它们各自封装起来，并使它们可以互相替换——让算法的变化独立于使用它的客户**。核心结构：策略接口（Strategy）+ 多个策略实现（ConcreteStrategy）+ 上下文（Context，持有策略引用并可切换）。它属软件设计模式；.NET 官方在 `System.Linq` 大量使用"策略式"委托（`Func<T>` 作为算法参数），依赖注入中也常见"按策略注册多个实现"：https://learn.microsoft.com/zh-cn/dotnet/core/extensions/dependency-injection-guidelines 。

> [!origin] 由来背景
> 策略模式源自 1980 年代面向对象"组合优于继承"的实践，1994 年 GoF 收录。其动机是对付"算法膨胀"：早期把"按类型分流"写成 `switch`/`if-else` 堆在业务方法里，每加一种算法（新协议解析、新数据校验规则）就要改业务方法，违反开闭原则（见 `solid-设计原则`）。策略模式把每个分支提取为独立策略类，业务方法变成"调策略接口"，于是"加算法 = 加策略类 + 注册"，业务代码不再膨胀。上位机里"协议解析"正是最经典的策略场景——Modbus/S7/私有协议就是一族可替换算法。

> [!essentials] 核心要点
> - **三要素**：策略接口（`IProtocolParser`/`INotifyStrategy`）、具体策略（每个算法一个类）、上下文（持有并切换策略）
> - **选择方式**：工厂按参数创建（见 `工厂模式`）、字典映射、配置驱动（见 12.5 `appsettingsjson推荐方案`）
> - **与委托/`Func<>` 的关系**：简单策略可用委托替代类，复杂策略保留接口更清晰
> - **状态管理**：策略对象可无状态（共享单例）或有状态（每上下文一份），注意线程安全
> - **典型应用**：协议解析（见 `上位机插件化场景`）、告警通知、数据校验规则、报表导出格式

> [!example] 完整示例
> **温控策略切换演示：定义策略接口 IControlStrategy，在 ComboBox 中切换"开关控制 / PID 控制"两种算法，点击按钮执行，展示策略模式如何消除 if-else：**
>
> **MainWindow.xaml：**
> ```xml
> <Window x:Class="HmiDemo.MainWindow"
>         xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
>         xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
>         Title="温控策略 - 策略模式" Height="340" Width="420"
>         WindowStartupLocation="CenterScreen" Background="#0D1117">
>     <StackPanel Margin="15">
>         <TextBlock Text="温度控制策略（运行时切换算法）" Foreground="#58A6FF" FontWeight="Bold"/>
>         <ComboBox x:Name="StrategyBox" Margin="0,10,0,0" Padding="4"
>                   Background="#161B22" Foreground="#8B949E">
>             <ComboBoxItem Content="开关控制（On/Off）"/>
>             <ComboBoxItem Content="PID 控制" IsSelected="True"/>
>         </ComboBox>
>         <TextBox x:Name="SetValueBox" Margin="0,10,0,0" Padding="4"
>                  Background="#161B22" Foreground="#8B949E" Text="100"/>
>         <Button Content="执行控制" Click="OnExecute" Margin="0,10,0,0" Padding="8"
>                 Background="#21262D" Foreground="White"/>
>         <TextBlock x:Name="OutputText" Margin="0,12,0,0" Foreground="#8B949E" TextWrapping="Wrap"/>
>     </StackPanel>
> </Window>
> ```
>
> **MainWindow.xaml.cs —— 后台代码：**
> ```csharp
> using System.Windows;
> using System.Windows.Media;
>
> namespace HmiDemo
> {
>     // 策略接口：定义一组算法的统一入口，调用方只依赖该接口
>     public interface IControlStrategy
>     {
>         string Control(double setValue, double currentValue);
>     }
>
>     // 具体策略 A：开关控制，温度低于设定值就开加热器
>     public class OnOffControl : IControlStrategy
>     {
>         public string Control(double setValue, double currentValue)
>         {
>             bool heaterOn = currentValue < setValue;
>             return heaterOn ? $"加热器【开】→ 目标 {setValue}℃" : $"加热器【关】→ 目标 {setValue}℃";
>         }
>     }
>
>     // 具体策略 B：PID 控制（这里演示比例项 P 的计算）
>     public class PidControl : IControlStrategy
>     {
>         public string Control(double setValue, double currentValue)
>         {
>             double output = (setValue - currentValue) * 0.5; // 比例系数 Kp=0.5
>             return $"PID 输出 P={output:F1} → 目标 {setValue}℃";
>         }
>     }
>
>     public partial class MainWindow : Window
>     {
>         private readonly double _current = 78.5; // 模拟当前温度
>         private IControlStrategy _strategy = new PidControl(); // 默认策略
>
>         public MainWindow() => InitializeComponent();
>
>         private void OnExecute(object sender, RoutedEventArgs e)
>         {
>             // 核心：根据选择替换策略对象，调用处代码保持不变
>             _strategy = StrategyBox.SelectedIndex == 0 ? new OnOffControl() : new PidControl();
>             double setValue = double.TryParse(SetValueBox.Text, out double v) ? v : 100.0;
>             OutputText.Text = $"当前温度 {_current}℃\n所选策略：{StrategyBox.Text}\n执行结果：{_strategy.Control(setValue, _current)}";
>             OutputText.Foreground = new SolidColorBrush(Color.FromRgb(0x8B, 0x94, 0x9E));
>         }
>     }
> }
> ```
> 

> [!scene] 适用场景
> ✅ 协议解析策略：Modbus/S7/私有协议按配置切换解析方式（见 `上位机插件化场景`）
> ✅ 告警通知方式：日志/弹窗/短信按严重级别选择（示例场景）
> ✅ 数据校验规则：不同产品线用不同校验算法
> ✅ 报表导出格式：CSV/Excel/PDF 运行时选择
> ❌ 算法固定不变：策略包装是多余抽象，直接方法实现
> ❌ 策略间需要共享大量状态：策略上下文传参复杂，考虑模板方法/状态模式

> [!pitfall] 常见踩坑
> 坑 1：**上下文持有具体策略类型** → 现象：`if (context.Strategy is LogStrategy)` 判断后强转 → 原因：策略"选择"写在了上下文里 → 解决：选择交给工厂/配置/委托，上下文只认接口（见 `工厂模式`）
> 
> 坑 2：**策略对象被多线程共享且有状态** → 现象：一个线程改策略状态，其他线程行为突变 → 原因：策略实例非线程安全 → 解决：策略做成无状态（状态放参数）或用单例安全共享
>
> 坑 3：**策略数量膨胀导致选择逻辑臃肿** → 现象：工厂里 switch 十几层，加策略还要改工厂 → 原因：策略多了还在手工分发 → 解决：用"名称 → 策略"字典注册或 MEF `[Export]` 自动发现（见 `mef-与-prism-modules`）

> [!best] 最佳实践
> - 策略接口方法小而纯：`string Format(string value)` 之类的单职责方法最好测
> - 无状态优先：策略实例可共享（结合 `单例模式`），性能好、无并发隐患
> - 选择策略用工厂 + 配置：`NotifyFactory.Create(severity)` 返回对应策略，上下文不写分支
> - 给每个策略加"名称/描述"元数据：便于界面下拉框展示（示例 `ComboBox` 切换）
> - 配套单元测试：每个策略类一个 `[Fact]`（见 12.8 `单元测试xunitmoq`），验证算法正确

> [!practice] 上手练习
> **Lv.1 照猫画虎**：运行示例代码，在通知策略下拉框切换"写日志/弹窗/发短信"，观察输出变化
> **Lv.2 小试牛刀**：新增 `EmailStrategy` 实现 `INotifyStrategy`，加入工厂与下拉框，验证业务层零修改
> **Lv.3 融会贯通**：把策略选择改为配置驱动：`appsettings.json` 里配置 `Notify:Strategy=Popup`，启动时读取创建（见 12.5 `appsettingsjson推荐方案`）
> **Lv.4 拆层挑战**：实现"协议解析策略"：`IProtocolParser` 接口 + `ModbusParser`/`S7Parser`，用字典 `Dictionary<string, IProtocolParser>` 注册，界面切换协议测试解析
