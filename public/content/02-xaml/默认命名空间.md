# 默认命名空间

> [!plain] 白话理解
> XAML 的默认命名空间就像一个**"词汇表"**。想象你去国外旅游，手上有一本词典——当你说"酒店"，别人知道你要找 Hotel。XAML 里你写 `<Button>`，WPF 怎么知道它对应 `System.Windows.Controls.Button` 这个类？靠的就是默认命名空间那把"映射钥匙"。它告诉编译器："不写前缀的标签名，都去 WPF 核心库里找对应的类。"

> [!def] 官方定义
> WPF 的默认命名空间通过 `xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"` 声明。这个 URI 看似是一个网页地址，实际上是一个**命名空间标识符**——它通过 `XmlnsDefinitionAttribute` 将多个 CLR 命名空间（如 `System.Windows`、`System.Windows.Controls`、`System.Windows.Media` 等）统一映射到一个 XML 命名空间下，使得 XAML 中可以不写前缀直接使用 WPF 核心控件。

> [!origin] 由来背景
> 这个 URI 的设计模仿了 XML 命名空间的 RFC 标准——XML 命名空间本身就设计为 URI 格式（不要求能访问）。微软选择 `http://schemas.microsoft.com/winfx/2006/xaml/presentation` 这个地址，其中 `winfx` 是 WPF 最初的代号（Windows Framework），`2006` 是 WPF 的首次发布年份，`xaml/presentation` 表示这是用于界面呈现的 XAML 词汇表。最终这个 URI 通过程序集级别的 `XmlnsDefinition` 特性被硬编码映射到若干个 CLR 命名空间。

> [!essentials] 核心要点
> - `xmlns` 是 XML Namespace 的缩写，不写前缀的是**默认命名空间**
> - 默认命名空间的 URI 是一个**标识符**，不是远程地址，浏览器打开它不会有有效内容
> - 它映射了 WPF 核心程序集（PresentationFramework.dll）中的 **N 个 CLR 命名空间**
> - 没有前缀的标签（如 `<Button>`、`<Grid>`、`<TextBlock>`）全部从这个命名空间解析
> - 映射关系通过程序集级别的 `[XmlnsDefinition]` 特性定义
> - 本质上是编译器层面的映射，运行时不需要这个 URI

> [!example] 完整示例
**默认命名空间中包含的主要 CLR 命名空间：**

```csharp
// 这些 CLR 命名空间全部被映射到了默认 xmlns 中
// 定义位置：PresentationFramework.dll 的 AssemblyInfo.cs

[assembly: XmlnsDefinition("http://schemas.microsoft.com/winfx/2006/xaml/presentation", 
    "System.Windows")]
[assembly: XmlnsDefinition("http://schemas.microsoft.com/winfx/2006/xaml/presentation", 
    "System.Windows.Controls")]
[assembly: XmlnsDefinition("http://schemas.microsoft.com/winfx/2006/xaml/presentation", 
    "System.Windows.Controls.Primitives")]
[assembly: XmlnsDefinition("http://schemas.microsoft.com/winfx/2006/xaml/presentation", 
    "System.Windows.Data")]
[assembly: XmlnsDefinition("http://schemas.microsoft.com/winfx/2006/xaml/presentation", 
    "System.Windows.Documents")]
[assembly: XmlnsDefinition("http://schemas.microsoft.com/winfx/2006/xaml/presentation", 
    "System.Windows.Input")]
[assembly: XmlnsDefinition("http://schemas.microsoft.com/winfx/2006/xaml/presentation", 
    "System.Windows.Media")]
[assembly: XmlnsDefinition("http://schemas.microsoft.com/winfx/2006/xaml/presentation", 
    "System.Windows.Media.Animation")]
[assembly: XmlnsDefinition("http://schemas.microsoft.com/winfx/2006/xaml/presentation", 
    "System.Windows.Shapes")]
```

**在 XAML 中的使用：**
```xml
<Window xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
        xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
        Title="默认命名空间演示">
    <Grid>
        <!-- 这些控件全部来自默认命名空间，不需要任何前缀 -->
        <!-- Button → System.Windows.Controls.Button -->
        <!-- TextBlock → System.Windows.Controls.TextBlock -->
        <!-- Grid → System.Windows.Controls.Grid -->
        <!-- LinearGradientBrush → System.Windows.Media.LinearGradientBrush -->
        
        <Button Width="120" Height="40" Content="点击我">
            <Button.Background>
                <LinearGradientBrush StartPoint="0,0" EndPoint="1,0">
                    <GradientStop Color="#FF6B6B" Offset="0"/>
                    <GradientStop Color="#4ECDC4" Offset="1"/>
                </LinearGradientBrush>
            </Button.Background>
        </Button>
    </Grid>
</Window>
```

**如果没有默认命名空间，你得这样写（想象一下有多痛苦）：**
```xml
<!-- 假如没有默认命名空间的映射，每种类型都得带前缀 -->
<src:Window 
    xmlns:src="clr-namespace:System.Windows;assembly=PresentationFramework"
    xmlns:ctrl="clr-namespace:System.Windows.Controls;assembly=PresentationFramework"
    xmlns:media="clr-namespace:System.Windows.Media;assembly=PresentationCore">
    
    <ctrl:Grid>
        <ctrl:Button Width="120" Height="40">
            <ctrl:Button.Background>
                <media:LinearGradientBrush>
                    <media:GradientStop Color="#FF6B6B" Offset="0"/>
                    <media:GradientStop Color="#4ECDC4" Offset="1"/>
                </media:LinearGradientBrush>
            </ctrl:Button.Background>
        </ctrl:Button>
    </ctrl:Grid>
</src:Window>
```
> 感谢默认命名空间——它把几十个 CLR 命名空间统一到一个 `xmlns` 下，让你写 XAML 时几乎不用考虑"这个控件在哪个命名空间"。

> [!scene] 适用场景
> ✅ 每份 XAML 文件的根元素上都**必须**声明默认命名空间，否则无法使用任何 WPF 控件
> ✅ 放在根元素上即可，子元素自动继承
> ❌ 不要尝试把它改成别的 URI——这串地址是"硬编码"的，改了就不认识了

> [!pitfall] 常见踩坑
> 坑 1：**忘记声明默认命名空间** → XAML 设计器和编译器都无法识别任何控件标签，一片红波浪线。检查根元素上有没有 `xmlns="http://..."`
>
> 坑 2：**以为 URI 要能访问** → 经常有初学者在浏览器里输入这个地址看到报错就慌了。放心，它只是一个唯一标识符，不需要联网。
>
> 坑 3：**`xmlns` 写错一个字母** → 哪怕多一个空格、少一个斜杠，整个命名空间映射都会失效。复制粘贴是最安全的方式。

> [!best] 最佳实践
> - 使用 VS 的项目模板创建新窗口/用户控件，它会自动帮你填好正确的默认命名空间
> - 不要把默认命名空间声明在中间的元素上，只放在根元素
> - 记住默认命名空间包含的控件范围：WPF 内置的所有控件、布局、形状、媒体、数据绑定相关类都在其中
> - 当你找不到某个标签时，先用"转到定义 (F12)"看看它所在的 CLR 命名空间是否在默认映射中

> [!practice] 上手练习
> **Lv.1 照猫画虎**：新建一个窗口，故意删掉 `xmlns` 声明，观察 VS 的错误提示，再恢复它
> **Lv.2 小试牛刀**：用 `clr-namespace` 方式手动引入 `System.Windows.Shapes`，体会默认命名空间的便利性
> **Lv.3 融会贯通**：查阅 `PresentationFramework.dll` 的 `AssemblyInfo.cs` 源码，找出默认命名空间到底映射了哪些 CLR 命名空间
