# 自定义命名空间引入

> [!plain] 白话理解
> WPF 内置的控件都在默认命名空间里，不需要声明就能直接用。但你自己写的 UserControl、第三方的控件库、甚至 .NET 框架里的 `System.String`、`System.Int32` ——WPF 编译器怎么知道它们在哪？答案就是 **`clr-namespace` 引入**。你可以把它理解为"告诉编译器去哪个文件夹（CLR 命名空间）找哪个工具箱（程序集）"，然后给这个工具箱起个小名（前缀），在 XAML 里用 `前缀:类名` 的方式使用它。

> [!def] 官方定义
> XAML 通过 `xmlns:前缀="clr-namespace:命名空间;assembly=程序集名"` 语法将 CLR 命名空间中的类型暴露给 XAML 文档。其中 `clr-namespace` 指定 .NET 命名空间，`assembly` 指定该命名空间所在的程序集名称（不含 `.dll` 扩展名）。同一项目内的命名空间引入可以省略 `assembly` 参数。XAML 编译器利用这一映射关系解析带有前缀的标签。

> [!origin] 由来背景
> 这个设计来自 XML 世界的"自定义 Schema"概念。普通 XML 可以通过 DOCTYPE 或 Schema 引用外部词汇表，XAML 将其扩展为 `clr-namespace` 语法——因为 XAML 最终要映射到 CLR 类型，而 CLR 类型的"住址"就是"命名空间 + 程序集"。微软巧妙地利用 XML 的 `xmlns` 语法，在值中嵌入了 `clr-namespace:` 和 `assembly=` 关键字，让编译器能"看懂"这个映射关系。

> [!essentials] 核心要点
> - 语法：`xmlns:前缀="clr-namespace:命名空间;assembly=程序集名"`
> - 引入**本项目**的命名空间时，`assembly=` 可以省略
> - 引入**外部程序集**时必须指定 `assembly=`，且程序集名不含 `.dll`
> - 引入 **.NET 框架**类型（如 `System.String`）需要指定 `assembly=mscorlib`
> - 多个 CLR 命名空间可以映射到同一个 XML 前缀（通过 `[XmlnsDefinition]`）
> - 前缀可以随便取名，但习惯上用语义化名称（`local`、`sys`、`ctrl`）

> [!example] 完整示例
**场景一：引用本项目自己的命名空间**

假设项目中有自定义控件 `DeviceCard`，位于 `MyApp.Controls` 命名空间：

```csharp
// Controls/DeviceCard.cs
namespace MyApp.Controls;

public class DeviceCard : ContentControl
{
    public string DeviceName { get; set; }
    public string Status { get; set; }
}
```

在 XAML 中引入并使用：
```xml
<Window x:Class="MyApp.MainWindow"
        xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
        xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
        
        <!-- 引入本项目命名空间，省略 assembly= -->
        xmlns:ctrl="clr-namespace:MyApp.Controls"
        
        Title="自定义命名空间演示" Height="400" Width="600">
    <StackPanel Margin="15">
        <TextBlock Text="自定义控件演示" FontSize="18" FontWeight="Bold" Margin="0,0,0,10"/>
        
        <!-- 用 ctrl: 前缀使用自定义控件 -->
        <ctrl:DeviceCard DeviceName="CNC机床-A1" 
                         Status="运行中" Margin="5"/>
        <ctrl:DeviceCard DeviceName="机械臂-B2" 
                         Status="待机" Margin="5"/>
    </StackPanel>
</Window>
```

**场景二：引用 System 命名空间中的类型**

```xml
<Window x:Class="MyApp.DemoWindow"
        xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
        xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
        
        <!-- 引入 System 命名空间（在 mscorlib 程序集中） -->
        xmlns:sys="clr-namespace:System;assembly=mscorlib"
        
        Title="System 命名空间引用" Height="400" Width="500">
    <Window.Resources>
        
        <!-- 直接在 XAML 资源中使用 System 类型 -->
        <sys:Double x:Key="DefaultFontSize">14</sys:Double>
        <sys:Int32 x:Key="MaxRetryCount">3</sys:Int32>
        <sys:String x:Key="AppTitle">设备监控系统 v2.0</sys:String>
        
        <!-- 也可以用 x:Array 构建集合 -->
        <x:Array x:Key="DeviceTypes" Type="sys:String">
            <sys:String>CNC机床</sys:String>
            <sys:String>机械臂</sys:String>
            <sys:String>传送带</sys:String>
            <sys:String>AGV小车</sys:String>
        </x:Array>
        
    </Window.Resources>
    
    <StackPanel Margin="15">
        <!-- 使用资源中的系统类型值 -->
        <TextBlock Text="{StaticResource AppTitle}" 
                   FontSize="{StaticResource DefaultFontSize}"
                   FontWeight="Bold"/>
        
        <ComboBox ItemsSource="{StaticResource DeviceTypes}" 
                  Width="200" Margin="0,10,0,0"/>
    </StackPanel>
</Window>
```

**场景三：引用第三方 / 外部程序集**

```xml
<Window x:Class="MyApp.ExternalLibDemo"
        xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
        xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
        
        <!-- 引入 MaterialDesign 控件库（假设已通过 NuGet 安装） -->
        xmlns:md="clr-namespace:MaterialDesignThemes.Wpf;assembly=MaterialDesignThemes.Wpf"
        
        Title="外部程序集引用" Height="400" Width="500">
    <StackPanel Margin="15">
        <TextBlock Text="外部控件库演示" FontSize="16" FontWeight="Bold"/>
        <!-- 使用外部库的控件 -->
        <!-- 注：实际使用时需先安装对应 NuGet 包 -->
    </StackPanel>
</Window>
```

**引入规则速查表：**
| 场景 | xmlns 写法 | 说明 |
|------|-----------|------|
| 本项目类 | `xmlns:local="clr-namespace:MyApp.ViewModels"` | 省略 `assembly` |
| 系统类型 | `xmlns:sys="clr-namespace:System;assembly=mscorlib"` | mscorlib 是核心库 |
| 系统颜色 | `xmlns:colors="clr-namespace:System.Windows.Media;assembly=PresentationCore"` | 引用 Colors 类 |
| 第三方库 | `xmlns:md="clr-namespace:MaterialDesign.Wpf;assembly=MaterialDesign"` | 完整指定 |

> [!scene] 适用场景
> ✅ 使用自定义 UserControl / 自定义控件 —— 必须引入其所在命名空间
> ✅ 在 XAML 资源中定义基本类型常量（Double、String、Int32）
> ✅ 使用 `x:Array` 时需要指定数组元素类型（`Type="sys:String"`）
> ✅ ValueConverter 的 XAML 实例化
> ✅ 第三方 UI 控件库（DevExpress、Telerik、MaterialDesign 等）的引入

> [!pitfall] 常见踩坑
> 坑 1：**`assembly=` 写错** → 最常见的错误是把 `assembly=mscorlib` 写成 `assembly=mscorlib.dll`，多写了 `.dll` 后缀，编译器直接报错说找不到程序集。
>
> 坑 2：**命名空间和文件夹不一致** → 默认情况下 VS 把文件放进文件夹不等于命名空间跟着变。`Controls/` 文件夹里的类可能在 `MyApp.Controls`，也可能还在 `MyApp`，取决于你创建类时的命名空间设置。
>
> 坑 3：**忘记添加程序集引用** → XAML 引用了 `assembly=某个NuGet包`，但项目里没安装对应的 NuGet 包，编译时提示 `Undefined CLR namespace`。

> [!best] 最佳实践
> - 前缀命名有约定：`local` 用于本项目核心类，`sys` 用于系统类型，`ctrl` 或 `uc` 用于自定义控件
> - 只引入实际用到的命名空间，不要无脑堆一堆 `xmlns:xxx`
> - 当引入很多自定义命名空间时，按字母顺序排列让代码更整洁
> - `.NET Framework → .NET Core/5+` 迁移时注意 `mscorlib` 变了：Core 中系统类型分散在 `System.Runtime`、`System.Collections` 等程序集中
> - 在团队项目中统一前缀命名规范，写入编码规范文档

> [!practice] 上手练习
> **Lv.1 照猫画虎**：新建一个 UserControl，在 MainWindow 中通过自定义命名空间引入并使用它
> **Lv.2 小试牛刀**：用 `xmlns:sys` 引入 System 类型，在 XAML 资源字典中定义一批常量（Double、String、Int32），通过 StaticResource 引用
> **Lv.3 融会贯通**：从 NuGet 安装 MaterialDesign 控件库，按照官方文档配置命名空间和资源字典，将默认的 WPF 按钮替换为 MaterialDesign 风格按钮
