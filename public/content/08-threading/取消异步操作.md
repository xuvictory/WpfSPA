# 取消异步操作

> [!plain] 白话理解
> 后台的批量采集任务跑起来后，操作员发现数据不对想立刻叫停，怎么办？"取消异步操作"就是一套**规范的下令停手机制**：后台任务握着一个小令牌（`CancellationToken`），命令员手里握着令牌的"源头"（`CancellationTokenSource`）。命令员一摇铃（`Cancel()`），令牌就标记为"已取消"，后台任务在每个检查点（`ThrowIfCancellationRequested()`）听到铃声就主动停手、收拾现场（finally）后优雅退出。这就好比给长途车队装了对讲机：总部说"取消今天的配送"，司机在下一个路口掉头回站，而不是直接砸车。**核心价值：让"停止"变得协作、及时、可清理，而不是粗暴中断**。
>
> 一句话：**CancellationTokenSource 下令、CancellationToken 听令、任务在检查点响应、finally 收拾现场**。

> [!def] 官方定义
> - **`System.Threading.CancellationTokenSource`**：取消的发起者。`Cancel()`/`CancelAfter(TimeSpan)` 触发取消；`Token` 属性取出令牌下发。
> - **`System.Threading.CancellationToken`**：取消的接收者。`IsCancellationRequested` 查询是否已取消；`ThrowIfCancellationRequested()` 已取消时抛 `OperationCanceledException`；可 `Register(Action)` 注册取消回调。
> - **`CancellationTokenSource.CancelAfter()`**：定时自动取消，常用于"超时即停止"（如等待设备回复 3 秒超时）。
> - **约定**：所有接受 `CancellationToken` 参数的 API 都应当把它传给内部任务（如 `Task.Delay(ms, token)`、`ReadAsync(..., token)`），实现"深度传播"。
> - 📖 官方文档：[任务中的取消](https://learn.microsoft.com/zh-cn/dotnet/standard/parallel-programming/task-cancellation)、[CancellationTokenSource 类](https://learn.microsoft.com/zh-cn/dotnet/api/system.threading.cancellationtokensource)、[CancellationToken 结构](https://learn.microsoft.com/zh-cn/dotnet/api/system.threading.cancellationtoken)

> [!origin] 由来背景
> 在 .NET 早期，取消只能靠 `Thread.Abort()`（粗暴终止线程，.NET 5 已移除）或"共享 bool 标志"（容易竞争、难以传播）。TPL 在 .NET 4.0（2010）引入 `CancellationToken` 协作式取消模型：取消不是"杀死"线程，而是"请求"——被取消方自己决定何时、如何响应，并在 `finally` 中清理资源。async/await 普及后，`CancellationToken` 与 `Task.Delay`、IO 异步方法深度集成，成为现代 .NET 异步代码的标配参数。上位机场景中，窗口关闭、用户点停止、通信超时都需要它来优雅收场。

> [!essentials] 核心要点
> - **Source 与 Token 配对**：`_cts = new CancellationTokenSource(); var token = _cts.Token;` 令牌只读，源头负责发令
> - **`ThrowIfCancellationRequested()`** 是主要检查点：在循环体开头调用，取消时抛 `OperationCanceledException`，由 `catch` 接管
> - **`Task.Delay(ms, token)` 可被取消**：等待期间取消会直接抛异常，不必等延时结束
> - **`OperationCanceledException` 用专用 catch**：不要用笼统的 `Exception` 吞掉，便于区分"取消"与"真错误"
> - **`finally` 里做清理**：释放资源、恢复按钮状态、`_cts.Dispose()`
> - **取消后 `IsCancellationRequested` 保持 true**：可在取消后判断状态决定 UI 文案（"已停止" vs "已完成"）
> - **关闭窗口时取消**：`Window.Closed` 里 `_cts?.Cancel()` 并等待任务退出，防止后台空转

> [!example] 完整示例
> **取消异步操作演示：用 CancellationTokenSource 取消批量采集：**
>
> **MainWindow.xaml：**
> ```xml
> <Window x:Class="HmiDemo.MainWindow"
>         xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
>         xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
>         Title="取消异步操作" Height="380" Width="440"
>         WindowStartupLocation="CenterScreen" Background="#0D1117">
>     <StackPanel Margin="15" Background="#161B22" Padding="15">
>         <TextBlock Text="取消异步操作演示" FontSize="16" FontWeight="Bold"
>                    Foreground="#58A6FF" Margin="0,0,0,10"/>
>         <!-- 启动批量采集（共 10 轮，每轮 0.5 秒） -->
>         <Button x:Name="StartButton" Content="启动批量采集（10 轮）" Click="OnStartClick"
>                 Margin="0,5" Padding="8" Background="#238636" Foreground="White"/>
>         <!-- 点击后发出取消请求 -->
>         <Button Content="取消采集" Click="OnCancelClick"
>                 Margin="0,5" Padding="8" Background="#DA3633" Foreground="White"/>
>         <TextBlock x:Name="LogText" Foreground="#8B949E" TextWrapping="Wrap"
>                    MinHeight="150" Margin="0,10,0,0"/>
>     </StackPanel>
> </Window>
> ```
>
> **MainWindow.xaml.cs —— 后台代码：**
> ```csharp
> using System;
> using System.Threading;
> using System.Threading.Tasks;
> using System.Windows;
>
> namespace HmiDemo
> {
>     public partial class MainWindow : Window
>     {
>         private CancellationTokenSource _cts; // 取消令牌源
>
>         public MainWindow() => InitializeComponent();
>
>         private async void OnStartClick(object sender, RoutedEventArgs e)
>         {
>             _cts = new CancellationTokenSource();
>             var token = _cts.Token; // 取出令牌传给任务
>             StartButton.IsEnabled = false;
>             LogText.Text = "";
>             try
>             {
>                 for (int i = 1; i <= 10; i++)
>                 {
>                     token.ThrowIfCancellationRequested(); // 主动检查取消
>                     await Task.Delay(500, token); // 等待期间也可被取消
>                     LogText.Text += $"第 {i} 轮采集完成（通道 {i}）\r\n";
>                 }
>                 LogText.Text += "全部 10 轮采集完成\r\n";
>             }
>             catch (OperationCanceledException)
>             {
>                 LogText.Text += "采集已被用户取消 ✓\r\n";
>             }
>             finally
>             {
>                 StartButton.IsEnabled = true;
>                 _cts?.Dispose();
>             }
>         }
>
>         // 请求取消：任务在下一个检查点响应
>         private void OnCancelClick(object sender, RoutedEventArgs e)
>         {
>             _cts?.Cancel();
>         }
>     }
> }
> ```
> 

> [!scene] 适用场景
> ✅ **用户主动停止采集/导出**：批量导出、批量下发参数，点"停止"立即在下一轮响应
> ✅ **窗口/页面关闭**：`Closed` 时取消后台任务，防止"人走了任务还在跑"导致泄漏
> ✅ **通信超时**：等待 PLC/串口回复超 3 秒自动取消，`CancelAfter(3000)` 一条语句实现
> ✅ **重试策略**：重试 N 次中用户点取消，循环立刻终止
> ❌ **CPU 纯计算取消**：计算密集型任务不会自动响应令牌，需在循环里 `ThrowIfCancellationRequested()`；计算块很小则意义不大
> ❌ **不可分割的原子操作**：如一次性大文件写入，取消无意义，应告知用户"无法中途停止"

> [!pitfall] 常见踩坑
> 坑 1：**只用 bool 标志不用 CancellationToken** → 现象：取消不及时或与其他异步库无法协作 → 原因：裸 bool 无"检查点异常"机制，第三方 API 也不认 → 解决：统一用 `CancellationToken`，`Task.Delay`/IO 方法直接传 token
>
> 坑 2：**取消后没 `Dispose()` `CancellationTokenSource`** → 现象：长期运行内存缓慢增长 → 原因：CTS 内部持有计时器等资源 → 解决：`finally` 里 `_cts?.Dispose()`；注意 Dispose 后不能再 Cancel
>
> 坑 3：**catch 里吞掉 `OperationCanceledException`** → 现象：取消后界面显示"成功完成" → 原因：catch(Exception) 把取消异常当普通异常处理 → 解决：单独 `catch (OperationCanceledException)` 区分"取消"，其他异常另处理
>
> 坑 4：**重复启动没处理旧任务** → 现象：点两次开始，两个采集并行跑、数据混乱 → 原因：旧 CTS 没取消/没等待 → 解决：启动前 `_cts?.Cancel()` + `await` 旧任务结束再建新 CTS

> [!best] 最佳实践
> - **从 UI 事件贯穿到最深层的等待**：每个异步方法都加 `CancellationToken` 参数并向下传，形成"可取消链路"
> - **`CancelAfter` 实现超时**：`new CancellationTokenSource(TimeSpan.FromSeconds(3))` 即"3 秒未完成自动取消"
> - **关闭窗口三步走**：`Cancel()` → `await` 任务（`Task.WhenAll`）→ `Dispose()`；别直接不管
> - **`ThrowIfCancellationRequested` 放循环体开头**：每次迭代先听令再干活
> - **与 `Task.WhenAll` 配合**：取消时所有并行子任务一起收到令牌，统一收场（见 `并行任务whenallwhenany`）
> - **UI 反馈"已取消"而非静默结束**：catch 后更新日志/状态，让操作员明确知道发生了什么

> [!practice] 上手练习
> **Lv.1 运行改参数**：运行示例点"启动批量采集"后 1 秒内点"取消采集"，观察"已被用户取消"；把轮数改 50、`Delay` 改 200，体验更细粒度的取消时机
> **Lv.2 加属性**：加一个"3 秒超时自动取消"按钮：`new CancellationTokenSource(TimeSpan.FromSeconds(3))`，启动后不点取消，观察 3 秒自动停止
> **Lv.3 改造**：把示例改成"可重启动"：启动时若旧任务在跑，先取消并等待，再启动新任务；用状态日志证明旧任务已退出
> **Lv.4 挑战**：实现"批量下发参数 + 取消"：模拟向 5 台设备下发参数（每台 800ms），支持中途取消；取消后已下发的设备保持成功、未下发的标记"已跳过"，并总结结果
