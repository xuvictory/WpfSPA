# 检查是否需要调度

> [!plain] 白话理解
> 后台线程要更新界面时，很多人不管三七二十一直接 `Dispatcher.Invoke(...)`。但如果**当前线程就是 UI 线程**，再调用 `Dispatcher.Invoke` 等自己，就闹了"自己给自己寄快递还站在原地等签收"的笑话——直接卡死。`CheckAccess()` 就是一道"要不要寄快递"的检查：**当前线程有权限访问控件（是 UI 线程）→ 直接改；没权限（后台线程）→ 才走 Dispatcher 调度**。把这个判断封装成一个 `SafeUpdate` 方法，任何线程调用它都能安全更新控件，UI 线程调用零开销，后台线程调用自动调度。
>
> 一句话：**先问"我在哪条线程"，再决定"要不要绕道"**——避免多余的调度，也避免同线程死锁。

> [!def] 官方定义
> - **`DispatcherObject.CheckAccess()`**：返回当前线程是否有权访问该对象（true = 可以，false = 不可以）。它是 WPF 线程亲和校验的"只读询问"版本，不抛异常。
> - **`DispatcherObject.VerifyAccess()`**：无权访问时立即抛 `System.InvalidOperationException`，有权则静默通过。用于"必须有权限否则立即失败"的防御式编程。
> - **`Dispatcher.CheckAccess()`**（对 `Dispatcher` 本身）：等价于 `Dispatcher.Thread == Thread.CurrentThread`。
> - 使用模式：`if (control.Dispatcher.CheckAccess()) { 直接更新 } else { control.Dispatcher.Invoke(...) }`。
> - 📖 官方文档：[DispatcherObject.CheckAccess 方法](https://learn.microsoft.com/zh-cn/dotnet/api/system.windows.threading.dispatcherobject.checkaccess)、[DispatcherObject 类](https://learn.microsoft.com/zh-cn/dotnet/api/system.windows.threading.dispatcherobject)

> [!origin] 由来背景
> WPF 的 `DispatcherObject`（2006）为所有依赖对象提供线程亲和能力，`CheckAccess`/`VerifyAccess` 就是这套校验的两个入口：一个温和询问、一个严格执法。早期 WinForms 开发者常写 `if (InvokeRequired) { Invoke(...) } else { 直接改 }`，WPF 把这套模式标准化为 `CheckAccess()` + `Dispatcher`。如今 `async/await` 普及后多数场景不再需要手动判断，但封装通用 UI 更新工具（日志控件、状态灯组件）时，`CheckAccess` 仍是"既能被主线程调用、又能被后台线程调用"的基石。

> [!essentials] 核心要点
> - **`CheckAccess() == true` 表示当前线程拥有该控件**：通常就是 UI 线程，直接操作即可
> - **`CheckAccess() == false` 必须调度**：用 `Dispatcher.Invoke`/`BeginInvoke` 把操作排队到 UI 线程
> - **同线程还 `Invoke` 会死锁**：这正是要先 `CheckAccess` 的核心原因
> - **`VerifyAccess()` 是"强校验"**：适合公共方法入口，无权访问立即抛异常暴露 bug
> - **封装成通用方法后处处可用**：UI 更新工具、日志助手、MVVM 服务都能用同一模式
> - **不要混淆 `CheckAccess` 与 `Dispatcher.CurrentDispatcher`**：后者拿"当前线程"的 Dispatcher，后台线程调用会拿到一个无关调度器

> [!example] 完整示例
> **CheckAccess 判断是否需要调度：写一个通用的安全更新方法：**
>
> **MainWindow.xaml：**
> ```xml
> <Window x:Class="HmiDemo.MainWindow"
>         xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
>         xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
>         Title="检查是否需要调度" Height="360" Width="440"
>         WindowStartupLocation="CenterScreen" Background="#0D1117">
>     <StackPanel Margin="15" Background="#161B22" Padding="15">
>         <TextBlock Text="CheckAccess 判断是否需要调度" FontSize="16" FontWeight="Bold"
>                    Foreground="#58A6FF" Margin="0,0,0,10"/>
>         <!-- 触发一次跨线程更新 -->
>         <Button Content="在后台线程更新界面（自动判断调度）" Click="OnUpdateClick"
>                 Margin="0,5" Padding="8" Background="#238636" Foreground="White"/>
>         <!-- 日志区：展示 CheckAccess 在不同线程下的返回值 -->
>         <TextBlock x:Name="LogText" Foreground="#8B949E" TextWrapping="Wrap"
>                    MinHeight="120" Margin="0,10,0,0"/>
>     </StackPanel>
> </Window>
> ```
>
> **MainWindow.xaml.cs —— 后台代码：**
> ```csharp
> using System.Threading;
> using System.Windows;
>
> namespace HmiDemo
> {
>     public partial class MainWindow : Window
>     {
>         public MainWindow() => InitializeComponent();
>
>         // 通用安全更新方法：先检查 CheckAccess()，需要调度才调度
>         private void SafeUpdate(string message)
>         {
>             if (LogText.CheckAccess())
>             {
>                 // 当前就在 UI 线程，直接更新，无需调度
>                 LogText.Text += message + "\r\n";
>             }
>             else
>             {
>                 // 当前在后台线程，把更新动作排队回 UI 线程
>                 Dispatcher.Invoke(() => LogText.Text += message + "\r\n");
>             }
>         }
>
>         private void OnUpdateClick(object sender, RoutedEventArgs e)
>         {
>             LogText.Text = "";
>             // 主线程调用：CheckAccess 为 True，走直接更新分支
>             SafeUpdate($"主线程直接更新（CheckAccess = {LogText.CheckAccess()}）");
>
>             new Thread(() =>
>             {
>                 Thread.Sleep(300);
>                 // 后台线程调用：CheckAccess 为 False，自动走 Dispatcher 分支
>                 SafeUpdate($"后台线程更新（CheckAccess = {LogText.CheckAccess()}，" +
>                            "已调度到主线程）");
>             }).Start();
>         }
>     }
> }
> ```
> 

> [!scene] 适用场景
> ✅ **封装通用 UI 更新工具**：日志控件、状态灯、通用提示条——不确定调用方在哪个线程时统一用 `SafeUpdate`
> ✅ **公共服务被多线程调用**：采集服务、命令服务里更新界面/通知，用 `CheckAccess` 让方法"线程无关"
> ✅ **重构遗留代码**：把散落的 `Dispatcher.Invoke` 收敛成带 `CheckAccess` 的工具方法，顺便避免同线程死锁
> ❌ **纯 UI 线程内的简单更新**：写事件处理器时没必要加判断，直接更新更清晰
> ❌ **能用 `async/await` 的场景**：`await` 自动回 UI 上下文，手动 `CheckAccess` 反而啰嗦

> [!pitfall] 常见踩坑
> 坑 1：**`CheckAccess` 返回值理解反** → 现象：明明在 UI 线程却走了 `Invoke` 分支，结果死锁 → 原因：把"true=有权限"当成"需要调度" → 解决：记住 `true → 直接改`，`false → 调度`；先打印 `CheckAccess()` 结果再写分支
>
> 坑 2：**所有更新无条件 `Dispatcher.Invoke`** → 现象：UI 线程自身也调用了该方法，卡死或性能浪费 → 原因：没先判断线程归属 → 解决：统一用带 `CheckAccess` 的工具方法，同线程零调度
>
> 坑 3：**把 `CheckAccess` 当"万能保险"乱用** → 现象：代码处处是 if/else，反而难读 → 原因：过度防御 → 解决：只在"多线程都可能调用"的公共入口使用；确定只跑在后台的采集循环里，直接 `Dispatcher.Invoke` 更直白

> [!best] 最佳实践
> - **封装 `SafeUpdate` 模式为公共工具类**：`UiThreadHelper.RunOnUi(control, action)`，全局复用
> - **组合 `CheckAccess` 与 `BeginInvoke`**：不需要同步结果时走 `BeginInvoke`，避免阻塞调用方线程
> - **公共方法入口加 `VerifyAccess()`**：期望必须在 UI 线程执行的逻辑，用强校验把误用扼杀在调试期
> - **优先 `SynchronizationContext`/`IProgress<T>`**：采集场景用 `Progress<T>` 自动回 UI 上下文，比手写 `CheckAccess` 更简洁（见 `从-ui-线程安全更新控件`）
> - **注释写明线程假设**：方法头注明"可被任意线程调用"或"必须在 UI 线程调用"，团队协作不易误用

> [!practice] 上手练习
> **Lv.1 运行改参数**：运行示例看两条日志（主线程直接更新、后台线程调度更新）；把 `Dispatcher.Invoke` 改成 `BeginInvoke` 观察日志顺序变化
> **Lv.2 加属性**：给 `SafeUpdate` 加一个 `bool forceDispatch = false` 参数，为 true 时强制走 `Dispatcher` 分支，并在主线程调用看是否会卡死（学会复现再修复）
> **Lv.3 改造**：把 `SafeUpdate` 抽到静态工具类 `UiThreadHelper`，方法签名 `public static void SetText(TextBlock tb, string text)`，后台线程与主线程都调用它
> **Lv.4 挑战**：写一个"跨线程日志服务"：任意线程调用 `LogService.Append("...")`，内部用 `CheckAccess` 判断并写入一个全局日志 `ListBox`；再用 3 个 `Task` 并发写入 100 条，验证顺序正确不丢行
