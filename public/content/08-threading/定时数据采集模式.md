# 定时数据采集模式

> [!plain] 白话理解
> 上位机最常规的需求就是"**每 500ms 读一次设备数据，画成实时曲线**"。定时数据采集模式就是这套动作的标准骨架：**定时器（Timer）决定"何时采"、采集逻辑决定"采什么"、UI 更新决定"怎么显示"**。这里有个关键取舍：**定时器要跑在哪个线程**？只是 UI 上轮询模拟值，用 `DispatcherTimer`（UI 线程、免调度、方便但会被 UI 阻塞拖慢）；真正从 PLC/串口定时读数据，要用 `System.Timers.Timer` 或 `Task.Run + Task.Delay`（后台线程、准时可靠，但更新控件要绕道）。选对了定时器，采集节奏才稳；选错了，界面一卡数据就丢拍。
>
> 一句话：**UI 轮询用 DispatcherTimer，真实采集用后台定时器——先定节拍，再谈显示**。

> [!def] 官方定义
> - **定时采集模式（Scheduled Sampling Pattern）**：按固定时间间隔周期性执行"采集-处理-展示"流程的架构模式。三个环节：**节拍源**（定时器）、**采集动作**（读设备/传感器）、**数据呈现**（UI 更新/存储）。
> - **节拍源选型**：
>   - `System.Windows.Threading.DispatcherTimer`：跑在 UI 线程，Tick 内可直接改控件；受 UI 负载影响，**适合 UI 轮询**（见 `dispatchertimer`）。
>   - `System.Timers.Timer`：线程池回调，准时可靠；`Elapsed` 在后台线程，更新控件需 `Dispatcher`/`await`。
>   - `Task.Run` + `Task.Delay`：异步轮询循环，配合 `CancellationToken` 最灵活（见 `taskrun-与-taskdelay`、`取消异步操作`）。
> - **数据呈现**：采集结果经 `ConcurrentQueue` 缓冲或 `Dispatcher` 回 UI；高频曲线可写 `WriteableBitmap` 像素。
> - 📖 官方文档：[System.Timers.Timer 类](https://learn.microsoft.com/zh-cn/dotnet/api/system.timers.timer)、[DispatcherTimer 类](https://learn.microsoft.com/zh-cn/dotnet/api/system.windows.threading.dispatchertimer)、[Task.Delay 方法](https://learn.microsoft.com/zh-cn/dotnet/api/system.threading.tasks.task.delay)

> [!origin] 由来背景
> 数据采集程序自工业监控诞生起就是"定时读表"的形态：早期用 C 语言的 `sleep()` 循环或操作系统定时器。Windows 消息时代，WinForms 的 `System.Windows.Forms.Timer` 提供了 UI 线程定时器；.NET 2.0（2005）补充了后台 `System.Timers.Timer`。WPF 继承并演进为 `DispatcherTimer`（2006）。.NET 4.0/4.5 引入 TPL 与 async/await 后，"`Task.Run` + `Task.Delay` + `CancellationToken`"成为现代异步采集循环的标准写法——它比定时器事件更灵活：可以在采集循环里做复杂的条件等待、批量读取、优雅停止。上位机中"100ms 采一次温湿度""10ms 采一次高速信号"都在这个模式的射程内。

> [!essentials] 核心要点
> - **选定时器三问**：要 UI 更新免调度吗？（DispatcherTimer）要后台准时吗？（System.Timers.Timer）要异步可取消吗？（Task.Delay 循环）
> - **`DispatcherTimer` 的 Tick 在 UI 线程**：直接改控件，但 UI 卡一下采集就跟着卡
> - **`System.Timers.Timer.Elapsed` 在后台线程**：更新控件必须 `Dispatcher.Invoke`/`BeginInvoke` 或 `IProgress<T>`
> - **采集周期要大于"单次采集耗时"**：读一次设备要 200ms，就别设 100ms 周期，否则任务叠着跑
> - **停止用 `CancellationToken`**：采集循环支持优雅停止，窗口关闭时取消并等待收尾（见 `取消异步操作`）
> - **高频（>100Hz）不要逐点调度 UI**：批量聚合或写 `WriteableBitmap`，见 `从-ui-线程安全更新控件` 的坑 3
> - **节拍漂移**：`Task.Delay` 循环是"采完再等"，周期比"等完再采"更稳定（先干活后延时）

> [!example] 完整示例
> **定时数据采集模式演示：定时采样设备数据并绘制趋势：**
>
> **MainWindow.xaml：**
> ```xml
> <Window x:Class="HmiDemo.MainWindow"
>         xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
>         xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
>         Title="定时数据采集模式" Height="440" Width="480"
>         WindowStartupLocation="CenterScreen" Background="#0D1117">
>     <StackPanel Margin="15" Background="#161B22" Padding="15">
>         <TextBlock Text="定时数据采集模式" FontSize="16" FontWeight="Bold"
>                    Foreground="#58A6FF" Margin="0,0,0,10"/>
>         <TextBlock Text="DispatcherTimer 定时采集 + Canvas 绘制实时曲线"
>                    Foreground="#8B949E" TextWrapping="Wrap" Margin="0,0,0,10"/>
>         <!-- 采集开关与采样周期输入 -->
>         <StackPanel Orientation="Horizontal">
>             <Button x:Name="ToggleButton" Content="开始采集" Click="OnToggleClick"
>                     Padding="10,6" Background="#238636" Foreground="White"/>
>             <TextBlock Text="采样间隔(ms):" Foreground="#8B949E"
>                        VerticalAlignment="Center" Margin="12,0,4,0"/>
>             <TextBox x:Name="IntervalBox" Text="500" Width="60"
>                      Background="#0D1117" Foreground="#8B949E"
>                      VerticalContentAlignment="Center"/>
>         </StackPanel>
>         <!-- 曲线绘图区 -->
>         <Border Height="220" Margin="0,10,0,0" Background="#0D1117"
>                 BorderBrush="#21262D" BorderThickness="1">
>             <Canvas x:Name="ChartCanvas"/>
>         </Border>
>         <TextBlock x:Name="LastValueText" Foreground="#58A6FF"
>                    Margin="0,8,0,0" FontSize="14"/>
>     </StackPanel>
> </Window>
> ```
>
> **MainWindow.xaml.cs —— 后台代码：**
> ```csharp
> using System;
> using System.Windows;
> using System.Windows.Controls;
> using System.Windows.Media;
> using System.Windows.Shapes;
> using System.Windows.Threading;
>
> namespace HmiDemo
> {
>     public partial class MainWindow : Window
>     {
>         private readonly DispatcherTimer _timer = new DispatcherTimer();
>         private readonly Random _random = new Random();
>         private int _count; // 已采集点数
>
>         public MainWindow()
>         {
>             InitializeComponent();
>             _timer.Tick += OnCollectTick; // 定时采集回调
>         }
>
>         private void OnToggleClick(object sender, RoutedEventArgs e)
>         {
>             if (_timer.IsEnabled)
>             {
>                 _timer.Stop();
>                 ToggleButton.Content = "开始采集";
>                 ToggleButton.Background = new SolidColorBrush(Color.FromRgb(0x23, 0x86, 0x36));
>                 return;
>             }
>             // 按输入框的毫秒数设置采样周期，最小 100ms
>             int interval = int.TryParse(IntervalBox.Text, out int v) ? v : 500;
>             _timer.Interval = TimeSpan.FromMilliseconds(Math.Max(100, interval));
>             _count = 0;
>             ChartCanvas.Children.Clear();
>             ToggleButton.Content = "停止采集";
>             ToggleButton.Background = new SolidColorBrush(Color.FromRgb(0xDA, 0x36, 0x33));
>             _timer.Start();
>         }
>
>         // 每次采样：生成一个数据点并追加到曲线末端
>         private void OnCollectTick(object sender, EventArgs e)
>         {
>             double value = 50 + _random.NextDouble() * 20; // 模拟 50~70℃
>             _count++;
>             double x = (_count - 1) * 4; // 每点水平间距 4px
>             var line = new Line
>             {
>                 X1 = Math.Max(x - 4, 0),
>                 Y1 = 200 - _random.NextDouble() * 180,
>                 X2 = x,
>                 Y2 = 200 - value * 2.4, // 把温度映射为 Y 坐标
>                 Stroke = new SolidColorBrush(Color.FromRgb(0x58, 0xA6, 0xFF)),
>                 StrokeThickness = 2
>             };
>             ChartCanvas.Children.Add(line);
>             // 横轴滚动：超过画布宽度时整体左移
>             if (x > ChartCanvas.Width)
>             {
>                 ChartCanvas.RenderTransform =
>                     new TranslateTransform(-(x - ChartCanvas.Width + 4), 0);
>             }
>             LastValueText.Text = $"最新采样：{value:F1} ℃（第 {_count} 点）";
>         }
>     }
> }
> ```
> 

> [!scene] 适用场景
> ✅ **UI 模拟仪表轮询**：温度、转速、液位等状态灯/数值每 500ms 刷新，`DispatcherTimer` 最省事
> ✅ **真实设备定时采集**：定时读 PLC 寄存器、串口仪表，用 `System.Timers.Timer` 或 `Task.Delay` 循环，后台准时
> ✅ **趋势曲线/历史记录**：按周期采样入 `ConcurrentQueue`，UI 定时批量画线（见 `生产者-消费者模式`）
> ✅ **定时下发/巡检**：周期向多台设备发心跳、读状态，`Task.Run` 循环 + `WhenAll` 并行巡检
> ✅ **超时重试**：读设备失败后 `Task.Delay(1000)` 自动重试，配取消令牌
> ❌ **高速连续采集（>100Hz）**：逐点调度 UI 会饱和，用 `WriteableBitmap` 或缓存区批量刷新
> ❌ **事件驱动的数据**：设备主动上报（串口数据到达事件）时用事件，不要硬套定时轮询

> [!pitfall] 常见踩坑
> 坑 1：**采集周期小于单次采集耗时** → 现象：Timer 事件叠着触发，队列暴涨、数据乱序 → 原因：采集动作本身耗时超过 Interval → 解决：实测单次耗时，周期设为 2~3 倍；或加 `IsBusy` 防重入（上次没采完本次跳过）
>
> 坑 2：**`DispatcherTimer` 采集真实设备** → 现象：UI 卡一下，采集就漏拍、丢数据 → 原因：Tick 依赖 UI 线程空闲 → 解决：真实设备采集用后台定时器（`System.Timers.Timer`/`Task.Delay`），UI 只做显示
>
> 坑 3：**停止采集没等收尾就关窗** → 现象：关闭后偶发异常、线程残留 → 原因：定时器/循环还在跑，控件已销毁 → 解决：`Closed` 事件里 `Stop()`/`Cancel()` + `await` 任务收尾（见 `取消异步操作`）
>
> 坑 4：**曲线点无限累积** → 现象：运行几小时后界面越来越卡、内存上涨 → 原因：`Canvas.Children` 只加不删 → 解决：画布只保留最近 N 个点（移除旧点），或改用环形缓冲

> [!best] 最佳实践
> - **固定三选一**：UI 轮询→`DispatcherTimer`；后台定时→`System.Timers.Timer`；异步灵活→`Task.Delay` 循环
> - **采集与显示分离**：采集线程入队，UI 定时器批量取显示（`生产者-消费者模式`），节拍互不拖累
> - **周期先于"干活后延时"**：`while(true) { 采集(); await Task.Delay(period); }` 周期更稳
> - **用 `Stopwatch` 校验节拍**：采集循环里 `Stopwatch` 打点，日志输出实际周期，发现漂移及时调参
> - **高频数据用 `WriteableBitmap`**：像素直写，性能比逐点画 Line 高一个数量级
> - **采集状态可视化**：界面上显示"最近采样时间、丢包数、实际周期"，让节拍问题一眼可见

> [!practice] 上手练习
> **Lv.1 运行改参数**：运行示例调整采样间隔（100/500/2000ms）观察曲线密度；把 `IntervalBox` 输入 50 观察最小 100ms 的下限保护
> **Lv.2 加属性**：加"历史最大/最小值"显示：每次采样后统计 `max`/`min` 并刷新 `TextBlock`；加"曲线点数"显示并限制最多 200 个点（旧点移除）
> **Lv.3 改造**：把采集从 `DispatcherTimer` 改成 `System.Timers.Timer`：`Elapsed` 里模拟采集 → `Dispatcher.Invoke` 更新曲线，对比"UI 卡 3 秒"（加一个 `Thread.Sleep(3000)` 按钮）时两种定时器的表现差异
> **Lv.4 挑战**：实现"多通道定时采集 + 曲线"：3 个通道（温度/压力/流量）用 3 个 `Task.Delay` 循环并行采集，结果入 `ConcurrentQueue`，UI 每 200ms 批量取并画 3 条不同颜色曲线；支持各自独立的采集周期与启停
