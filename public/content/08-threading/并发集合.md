# 并发集合

> [!plain] 白话理解
> 普通的 `List<T>`、`Dictionary<K,V>` 在多个线程同时读写时就像**没有管理员的储物柜**：两个人同时放东西可能互相挤掉，甚至把柜子撑爆（抛异常）。`System.Collections.Concurrent` 命名空间下的**并发集合**则像配了管理员的储物柜：`ConcurrentQueue`（排队取号）、`ConcurrentDictionary`（每个格子独立上锁）、`ConcurrentBag`（不分顺序的筐）、`BlockingCollection`（能"叫醒"取货人的传送带）。它们内部用细粒度锁或原子操作保证线程安全，**你不需要手动加 lock**，直接调用就能安全并发。上位机里"采集线程写数据、UI 线程读显示"，正是并发集合的用武之地。
>
> 一句话：**并发集合 = 内置线程安全的容器，多线程读写不用自己加锁**。

> [!def] 官方定义
> - **`System.Collections.Concurrent` 命名空间**（.NET 4.0，2010）：提供线程安全集合，面向多线程并发读写场景。
> - **`ConcurrentQueue<T>`**：线程安全先进先出队列。`Enqueue` 入队、`TryDequeue` 出队（失败返回 false 不抛异常）。适合"生产者入队、消费者出队"。
> - **`ConcurrentDictionary<TKey,TValue>`**：线程安全字典。`TryAdd`/`TryGetValue`/`TryUpdate`/`AddOrUpdate`/`GetOrAdd` 原子操作。适合"按 key 并发读写配置/缓存"。
> - **`ConcurrentBag<T>`**：无序线程安全集合，`Add`/`TryTake`。适合"并发收集结果，顺序不重要"。
> - **`BlockingCollection<T>`**：**生产者-消费者的高级封装**：包装任意并发集合，支持 `Add`（满则阻塞）、`Take`/`TryTake`（空则阻塞）、`CompleteAdding` 标记结束、`IsCompleted` 查询。它是实现"采集→缓冲→处理"管线的首选（见 `生产者-消费者模式`）。
> - **`ConcurrentStack<T>`**：线程安全后进先出栈，`Push`/`TryPop`。
> - 📖 官方文档：[System.Collections.Concurrent 命名空间](https://learn.microsoft.com/zh-cn/dotnet/api/system.collections.concurrent)、[线程安全集合](https://learn.microsoft.com/zh-cn/dotnet/standard/collections/thread-safe/)、[BlockingCollection 类](https://learn.microsoft.com/zh-cn/dotnet/api/system.collections.concurrent.blockingcollection)

> [!origin] 由来背景
> .NET 1.x-3.5 时代，多线程共享集合只能靠"外部加锁"（lock 包住每次访问），代码繁琐且易错：漏一处锁就数据错乱。TPL 随 .NET 4.0（2010）发布时，微软提供了 `Concurrent*` 并发集合，把"线程安全"内置到容器本身：内部用细粒度锁、`Interlocked`、无锁 CAS 等技术，并针对高频场景优化（如 ConcurrentDictionary 按桶分段加锁）。`BlockingCollection` 进一步把"阻塞等待"语义内置，让生产者-消费者模式从"手写 while + lock + Monitor.Pulse"变成几行标准代码。如今并发集合是 .NET 多线程编程的默认选择，只有在"性能极敏感且懂原理"时才回退到手写锁。

> [!essentials] 核心要点
> - **读操作也线程安全**：`TryGetValue`/`TryDequeue` 等"尝试"方法失败返回 false，**绝不抛异常**（区别于普通集合越界）
> - **`ConcurrentQueue` 适合"一个写多个读"的日志/数据流**：生产者 `Enqueue`，消费者 `TryDequeue` 循环
> - **`ConcurrentDictionary` 用 `AddOrUpdate`/`GetOrAdd` 做原子操作**：先查后改不再需要外部锁
> - **`BlockingCollection` 的 `Add`/`Take` 会阻塞**：配合 `CompleteAdding` 与 `GetConsumingEnumerable` 实现优雅退出
> - **并发集合不是"免费"的**：内部有锁/原子开销，单线程场景比普通集合慢；只有多线程共享时才划算
> - **`foreach` 遍历是弱一致快照**：遍历期间别的线程改动不影响本次遍历完整性（可能看到旧值，但不会崩）

> [!example] 完整示例
> **并发集合演示：BlockingCollection 实现线程安全的采集队列：**
>
> **MainWindow.xaml：**
> ```xml
> <Window x:Class="HmiDemo.MainWindow"
>         xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
>         xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
>         Title="并发集合" Height="420" Width="460"
>         WindowStartupLocation="CenterScreen" Background="#0D1117">
>     <StackPanel Margin="15" Background="#161B22" Padding="15">
>         <TextBlock Text="并发集合演示" FontSize="16" FontWeight="Bold"
>                    Foreground="#58A6FF" Margin="0,0,0,10"/>
>         <!-- 生产 100 条数据，消费线程边取边显示 -->
>         <Button Content="启动 生产/消费（BlockingCollection）" Click="OnRunClick"
>                 Margin="0,5" Padding="8" Background="#238636" Foreground="White"/>
>         <TextBlock x:Name="LogText" Foreground="#8B949E" TextWrapping="Wrap"
>                    MinHeight="200" Margin="0,10,0,0"/>
>     </StackPanel>
> </Window>
> ```
>
> **MainWindow.xaml.cs —— 后台代码：**
> ```csharp
> using System;
> using System.Collections.Concurrent;
> using System.Threading;
> using System.Threading.Tasks;
> using System.Windows;
>
> namespace HmiDemo
> {
>     public partial class MainWindow : Window
>     {
>         // BlockingCollection 内部线程安全，支持阻塞式取数据
>         private readonly BlockingCollection<string> _queue =
>             new BlockingCollection<string>(new ConcurrentQueue<string>());
>
>         public MainWindow() => InitializeComponent();
>
>         private void OnRunClick(object sender, RoutedEventArgs e)
>         {
>             LogText.Text = "";
>
>             // 消费者线程：循环取数据，直到集合标记完成
>             var consumer = Task.Run(() =>
>             {
>                 while (!_queue.IsCompleted)
>                 {
>                     if (_queue.TryTake(out string item, 300)) // 阻塞等待最多 300ms
>                     {
>                         AppendLog($"[消费] {item}");
>                     }
>                 }
>                 AppendLog("[消费] 队列已空，消费结束");
>             });
>
>             // 生产者：向集合写入 100 条模拟数据
>             Task.Run(() =>
>             {
>                 for (int i = 1; i <= 100; i++)
>                 {
>                     _queue.Add($"数据点 {i}");
>                     Thread.Sleep(10); // 模拟采样间隔
>                 }
>                 _queue.CompleteAdding(); // 标记不再添加，消费者可结束
>                 AppendLog("[生产] 已写入 100 条数据并标记完成");
>             });
>
>             consumer.Wait(); // 等待消费者跑完再返回
>             AppendLog("生产/消费演示结束");
>         }
>
>         private void AppendLog(string line) =>
>             Dispatcher.Invoke(() => LogText.Text += line + Environment.NewLine);
>     }
> }
> ```
> 

> [!scene] 适用场景
> ✅ **采集数据缓冲**：采集线程写入 `ConcurrentQueue`，UI/存储线程读取，天然解耦（见 `生产者-消费者模式`）
> ✅ **多线程共享配置/缓存**：`ConcurrentDictionary` 存设备参数、实时值，各线程安全读写
> ✅ **并发收集任务结果**：`ConcurrentBag` 收集 100 个并行计算的结果，顺序无关
> ✅ **日志流水线**：多线程 `Enqueue` 日志，单消费者写文件/刷新 UI
> ❌ **单线程或读多写少的场景**：普通 `List`/`Dictionary` + 必要时 `lock` 更高效
> ❌ **需要"整体快照"的绑定**：`ObservableCollection` 绑定的 UI 场景，并发集合不直接支持绑定，需先快照到 UI 集合（见第 7 章 MVVM 的集合线程更新）

> [!pitfall] 常见踩坑
> 坑 1：**忘调 `CompleteAdding`，消费者永远不结束** → 现象：`IsCompleted` 一直 false，程序挂住 → 原因：没通知"不再有数据" → 解决：生产者收尾必须 `CompleteAdding()`；消费者用 `GetConsumingEnumerable()` 遍历更省事
>
> 坑 2：**在 `BlockingCollection.Add`/`Take` 里没设超时** → 现象：满/空时线程无限阻塞，UI 或工作线程卡死 → 原因：阻塞语义没控制 → 解决：`Add(item, token)`/`TryTake(out item, 300)` 传超时或取消令牌（见 `取消异步操作`）
>
> 坑 3：**把并发集合当普通集合用错方法** → 现象：`queue[0]` 不存在、`dict[key]=v` 报错 → 原因：并发集合 API 语义不同 → 解决：用 `TryDequeue`/`AddOrUpdate`/`GetOrAdd`；先查官方文档的成员表
>
> 坑 4：**`ConcurrentDictionary` 的 `ContainsKey` 后 `this[key]`** → 现象：偶发 `KeyNotFoundException` → 原因：两步之间别的线程删了 key → 解决：用 `TryGetValue` 一次完成，或 `GetOrAdd`
>
> 坑 5：**在 UI 线程直接遍历大并发集合** → 现象：界面卡顿 → 原因：遍历是弱一致快照但仍有开销 + 渲染开销 → 解决：先取快照（`ToArray()`/`.ToList()`）再绑定显示

> [!best] 最佳实践
> - **"一个生产者/一个消费者"选 `ConcurrentQueue`**：最轻量；`BlockingCollection` 加阻塞能力
> - **"按 key 并发共享"选 `ConcurrentDictionary`**：配置、缓存、实时值表首选
> - **"结果收集、顺序无关"选 `ConcurrentBag`**：并行计算结果的简单聚合
> - **生产者-消费者管线用 `BlockingCollection`**：配合 `GetConsumingEnumerable()` 遍历，代码最少（见 `生产者-消费者模式`）
> - **UI 绑定先快照再更新**：`Dispatcher.Invoke` 里 `list.Clear(); list.AddRange(queue.ToArray());` 一次刷新
> - **控制边界**：用 `BoundedCapacity` 限制 `BlockingCollection` 容量（如 1000），防止生产者无界堆积吃内存

> [!practice] 上手练习
> **Lv.1 运行改参数**：运行示例观察"生产→消费"日志流；把生产间隔 `Thread.Sleep(10)` 改成 100，观察消费者阻塞等待效果；把 `TryTake(out item, 300)` 超时改成 50，观察"等不到就放弃"
> **Lv.2 加属性**：在日志上方加"队列剩余"计数：生产 `Add` 后与消费 `TryTake` 后各更新一次 `_queue.Count`，观察缓冲水位变化
> **Lv.3 改造**：给 `BlockingCollection` 设置 `BoundedCapacity = 20`，生产者每 `Add` 一条就记录，观察生产者何时被"阻塞"；体会有界缓冲的背压（backpressure）机制
> **Lv.4 挑战**：实现"多生产者-单消费者"：3 个模拟通道同时向同一个 `BlockingCollection` 写数据（各 50 条、不同间隔），1 个消费者边取边显示，用 `Channel`（.NET Core 3.0+ 异步通道）重写一版对比
