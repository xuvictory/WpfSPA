# 生产者-消费者模式

> [!plain] 白话理解
> 上位机最常见的架构难题：**采集线程以 20Hz 产数据，UI 线程跟不上、又不能丢**。生产者-消费者模式就是给两方之间加一条**"传送带"（线程安全队列）**：生产者（采集线程）只管往传送带上放货（`Enqueue`），放完就走、绝不回头等；消费者（UI 线程/存储线程）按自己的节奏从传送带上取货（`TryDequeue`），取多少算多少。两边**速度解耦、互不阻塞**：生产快了队列积一点，UI 空闲了一次性取一批；生产慢了 UI 就空转一下。这就是"采集 → 缓冲 → 显示/存储"的标准骨架，比"采集线程直接改控件"稳定得多，也不会有"UI 卡一下采集就崩"的连锁反应。
>
> 一句话：**生产者只管产、消费者只管销，中间有条线程安全的传送带——速度不匹配也不互相拖累**。

> [!def] 官方定义
> - **生产者-消费者模式（Producer–Consumer Pattern）**：经典并发设计模式，生产者线程产生数据放入共享缓冲，消费者线程从中取出处理，两者通过缓冲解耦，不直接交互。
> - **核心组件**：
>   - **生产者**：采集/接收数据的线程（串口、TCP、传感器）。
>   - **共享缓冲**：线程安全队列——`ConcurrentQueue<T>`（无阻塞）或 `BlockingCollection<T>`（可阻塞、可限容量）。
>   - **消费者**：处理/显示/存储数据的线程（UI 刷新、写库、转发）。
> - **`ConcurrentQueue<T>`**：无锁/细粒度锁实现，`Enqueue`（入队）与 `TryDequeue`（出队）线程安全。
> - **`BlockingCollection<T>`**：包装 `ConcurrentQueue` 并提供阻塞语义：`Add` 满则等、`Take`/`TryTake` 空则等、`CompleteAdding` 通知结束（见 `并发集合`）。
> - 📖 官方文档：[生产者/消费者模式（.NET）](https://learn.microsoft.com/zh-cn/dotnet/standard/collections/thread-safe/when-to-use-a-thread-safe-collection)、[BlockingCollection 概述](https://learn.microsoft.com/zh-cn/dotnet/standard/collections/thread-safe/blockingcollection-overview)、[Channel（异步通道）](https://learn.microsoft.com/zh-cn/dotnet/api/system.threading.channels.channel)

> [!origin] 由来背景
> 生产者-消费者问题是计算机科学最经典的同步问题之一，由 Dijkstra 在 1965 年用信号量（见 `semaphore-信号量`）提出并解决。早期实现要手写"队列 + lock + Monitor.Pulse/Wait"，代码复杂且易错。.NET 4.0（2010）的 `ConcurrentQueue` 提供了线程安全队列；`BlockingCollection` 进一步内置阻塞与完成语义；.NET Core 3.0（2019）又引入异步 `Channel`（`System.Threading.Channels`），让生产者-消费者管线可以全程 `await`。上位机中"串口/网口采集 → 缓冲 → 界面/存储"正是这一模式的经典落地，几十年来一直是多线程架构的基石。

> [!essentials] 核心要点
> - **解耦是核心**：生产者与消费者通过队列通信，互不知道对方速度，谁慢都不阻塞谁（或有界阻塞）
> - **`ConcurrentQueue` 无阻塞入队/出队**：`Enqueue`/`TryDequeue` 立即返回，适合"生产者不停、消费者定时批处理"
> - **`BlockingCollection` 可阻塞**：`Add` 满则阻塞（背压）、`TryTake(out item, timeout)` 空则等待，适合"消费者等数据再处理"
> - **`CompleteAdding` 通知生产结束**：消费者据此退出循环（`IsCompleted` 为 true 且队列清空）
> - **一个队列多个消费者安全**：`ConcurrentQueue`/`BlockingCollection` 支持多读多写
> - **有界缓冲防堆积**：`new BlockingCollection<T>(queue, boundedCapacity)` 限制队列长度，防止内存暴涨
> - **UI 消费用定时器/Channel**：UI 线程用 `DispatcherTimer` 批量取，或 `Channel` + `await ReadAllAsync` 逐条消费（见 `dispatchertimer`）

> [!example] 完整示例
> **生产者-消费者模式演示：采集线程生产数据，UI 线程消费显示：**
>
> **MainWindow.xaml：**
> ```xml
> <Window x:Class="HmiDemo.MainWindow"
>         xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
>         xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
>         Title="生产者-消费者模式" Height="440" Width="480"
>         WindowStartupLocation="CenterScreen" Background="#0D1117">
>     <StackPanel Margin="15" Background="#161B22" Padding="15">
>         <TextBlock Text="生产者-消费者模式演示" FontSize="16" FontWeight="Bold"
>                    Foreground="#58A6FF" Margin="0,0,0,10"/>
>         <TextBlock Text="生产者（后台采集）→ 通道队列 → 消费者（UI 显示）"
>                    Foreground="#8B949E" TextWrapping="Wrap" Margin="0,0,0,10"/>
>         <!-- 开始与停止按钮 -->
>         <Button x:Name="StartButton" Content="开始采集" Click="OnStartClick"
>                 Margin="0,5" Padding="8" Background="#238636" Foreground="White"/>
>         <Button Content="停止采集" Click="OnStopClick"
>                 Margin="0,5" Padding="8" Background="#DA3633" Foreground="White"/>
>         <!-- 通道队列长度与最新一条数据 -->
>         <TextBlock x:Name="QueueInfo" Foreground="#58A6FF" Margin="0,8,0,0"/>
>         <ListBox x:Name="DataList" Height="140" Margin="0,5,0,0"
>                  Background="#0D1117" Foreground="#8B949E" BorderThickness="0"/>
>     </StackPanel>
> </Window>
> ```
>
> **MainWindow.xaml.cs —— 后台代码：**
> ```csharp
> using System;
> using System.Collections.Concurrent;
> using System.Threading;
> using System.Windows;
> using System.Windows.Threading;
>
> namespace HmiDemo
> {
>     public partial class MainWindow : Window
>     {
>         private readonly ConcurrentQueue<string> _queue = new ConcurrentQueue<string>();
>         private volatile bool _running; // 采集开关
>         private readonly DispatcherTimer _consumerTimer = new DispatcherTimer();
>
>         public MainWindow()
>         {
>             InitializeComponent();
>             // 消费者：UI 线程定时器每 200ms 取一次数据刷新界面
>             _consumerTimer.Interval = TimeSpan.FromMilliseconds(200);
>             _consumerTimer.Tick += OnConsumeTick;
>         }
>
>         // 生产者：后台线程每 50ms 生产一条数据放入队列
>         private void OnStartClick(object sender, RoutedEventArgs e)
>         {
>             _running = true;
>             StartButton.IsEnabled = false;
>             DataList.Items.Clear();
>             _consumerTimer.Start();
>             new Thread(() =>
>             {
>                 int i = 0;
>                 while (_running)
>                 {
>                     _queue.Enqueue($"数据 {i++}: 温度 {40 + i % 20}.{i % 10}℃");
>                     Thread.Sleep(50); // 模拟 50ms 采样周期
>                 }
>             }) { IsBackground = true }.Start();
>         }
>
>         // 消费者：从队列取数据，批量更新界面
>         private void OnConsumeTick(object sender, EventArgs e)
>         {
>             while (_queue.TryDequeue(out string item))
>             {
>                 DataList.Items.Insert(0, item); // 最新数据放最上面
>             }
>             QueueInfo.Text = $"通道队列剩余：{_queue.Count} 条";
>         }
>
>         private void OnStopClick(object sender, RoutedEventArgs e)
>         {
>             _running = false; // 停止生产者
>             _consumerTimer.Stop(); // 停止消费者
>             StartButton.IsEnabled = true;
>         }
>     }
> }
> ```
> 

> [!scene] 适用场景
> ✅ **串口/网口采集 → 界面显示**：采集线程高速收数据入队，UI 定时器批量取显示，协议解析、波形绘制都稳
> ✅ **采集 → 存储解耦**：数据同时写数据库/文件，写入慢不影响采集（存储作为第二消费者）
> ✅ **多通道数据汇总**：多路采集线程入同一队列，单消费者统一处理（见 `并行任务whenallwhenany` 的多任务配合）
> ✅ **日志收集**：各线程 `Enqueue` 日志，单线程异步写文件，避免频繁 IO 锁
> ✅ **流水线任务**：解析 → 校验 → 入库多级队列串成流水线
> ❌ **必须实时响应的点对点**：UI 与采集一对一强同步（如急停反馈），直接事件/await 更直接
> ❌ **数据量极小且低频**：加队列反而复杂，简单 `Dispatcher` 更新即可

> [!pitfall] 常见踩坑
> 坑 1：**生产端不设队列上限** → 现象：长时间采集内存暴涨，程序越来越慢 → 原因：消费者偶尔卡一下，生产者无界堆积 → 解决：`BlockingCollection` 设 `boundedCapacity`，满时生产端阻塞（背压）或主动丢弃旧数据
>
> 坑 2：**消费者取不完、UI 越积越多** → 现象：`ListBox` 条目无限增长卡死 → 原因：消费快于显示，且列表不清空 → 解决：界面只保留最近 N 条（`Items.RemoveAt` 到上限），曲线用环形缓冲
>
> 坑 3：**停止时不同步（生产者还在跑）** → 现象：点停止后队列还在涨、线程残留 → 原因：只停消费者没停生产者，或 `Thread.Abort` 式粗停 → 解决：先置 `_running=false` 让生产循环退出，`DispatcherTimer` 停止，必要时 `await` 生产任务收尾（见 `取消异步操作`）
>
> 坑 4：**用普通 `Queue<T>` 代替并发队列** → 现象：偶发"集合已修改"异常或数据丢失 → 原因：`Queue` 非线程安全，生产/消费并发踩踏 → 解决：必须 `ConcurrentQueue` 或 `BlockingCollection`（见 `并发集合`）

> [!best] 最佳实践
> - **结构固定三件套**：生产者线程 + `ConcurrentQueue`/`BlockingCollection` + 消费者（UI 定时器或工作线程）
> - **UI 消费用 `DispatcherTimer` 批量取**：一次 `while(TryDequeue)` 取完，再统一刷新界面，减少调度次数
> - **有界队列 + 丢弃策略**：队列满时记录丢弃计数（`Interlocked.Increment`），界面显示"丢包 N 条"提醒用户
> - **停止流程统一**：`Stop()` → 生产循环退出 → 消费者处理完剩余数据 → 资源释放，按序收场
> - **数据对象用不可变/值类型**：队列里传 `struct` 或只读对象，杜绝"生产端改了消费者正在读的数据"
> - **新代码考虑 `Channel<T>`**：`.NET Core 3.0+` 的异步通道，天然支持 `await`、取消、背压，比手写线程 + 队列更现代

> [!practice] 上手练习
> **Lv.1 运行改参数**：运行示例观察"生产者 50ms 一条、消费者 200ms 一批"的节奏与队列水位；把生产间隔改 10ms，观察队列积压与 `QueueInfo` 数字
> **Lv.2 加属性**：加"丢弃计数"`TextBlock`：队列超过 200 条时生产者不再入队并计数；UI 显示"已丢弃 N 条"，验证背压保护
> **Lv.3 改造**：把 UI 定时器消费改成后台消费者 + 快照回传：工作线程 `while(TryDequeue)` 收集 20 条后用 `Dispatcher.Invoke` 一次性刷新列表，对比两种消费方式的差异
> **Lv.4 挑战**：用 `BlockingCollection` 实现"采集→解析→入库"两级流水线：生产者入原始帧队列，解析消费者出队解析后入结果队列，存储消费者出队模拟写库；三线程并发，验证吞吐与解耦，再尝试改用 `Channel<T>` 重写
