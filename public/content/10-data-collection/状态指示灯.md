# 状态指示灯

> [!plain] 白话理解
> 状态指示灯就是**产线上的"塔灯"（三色警示灯）搬进电脑屏幕**：绿灯 = 运行正常、黄灯 = 待机/注意、红灯 = 报警/故障。现场操作员习惯抬头看塔灯判断设备状态，上位机界面用一排"圆灯泡"模拟塔灯，让操作员**不用读任何文字，扫一眼颜色就知道整条产线哪台设备出了事**。
>
> 技术上它特别朴素：一个 `Ellipse` 圆形 + 一个背景色（`Fill`）——绿就是 `Brushes.LimeGreen`，红就是 `Brushes.Red`。状态变化时换颜色；要引起注意就**闪烁**（定时切换"亮色/暗色"两态）。难的不是画灯泡，而是**颜色语义要统一、闪烁逻辑要可靠**。
>
> 一句话：**指示灯 = 用"颜色 + 闪烁"把设备状态压缩成一眼可读的信号**，红黄绿三色的含义必须全场统一，否则操作员会被误导。

> [!def] 官方定义
> - **状态指示灯**：以圆形色块（通常 `Ellipse`）表达离散状态（运行/待机/报警/停机）的指示型 UI 元素。WPF 中无官方专用控件，直接用 `System.Windows.Shapes.Ellipse` 的 `Fill` 属性设置颜色实现；闪烁用 `System.Windows.Threading.DispatcherTimer` 切换颜色，或用 `System.Windows.Media.Animation.Storyboard` 做颜色动画。
> - **颜色语义标准**：工控现场按钮与指示灯颜色由 **IEC 60204-1**（机械电气安全）规范约定——**红色=危险/紧急/故障、黄色=注意/异常、绿色=正常/运行**；上位机界面应遵循同一约定，避免混乱。
> - 关键 API 归属：`Shape.Fill`（`System.Windows.Media.Brushes`）、`DispatcherTimer`（闪烁）、`Storyboard`/`DoubleAnimation`（颜色渐变动画）。
> - 📖 官方文档：[Ellipse 类](https://learn.microsoft.com/zh-cn/dotnet/api/system.windows.shapes.ellipse)、[DispatcherTimer 类](https://learn.microsoft.com/zh-cn/dotnet/api/system.windows.threading.dispatchertimer)

> [!origin] 由来背景
> 指示灯的历史就是工控可视化的历史：在 PLC 问世前的继电器时代，控制柜上就用**物理灯泡**（白炽灯/氖灯）显示继电器通断；PLC 时代塔灯（Signal Tower，红黄绿堆叠）成为设备状态的标配。颜色语义后来被 **IEC 60204-1**（1970 年代起多次修订）固化为国际标准：红色是"危险/故障"，黄色是"注意"，绿色是"正常"。
> 上位机软件从组态软件时代（1990 年代）起就模拟物理塔灯——`Ellipse` 画圆、绑状态、变颜色，到今天仍是 SCADA/HMI 画面里出现频率最高的元素之一。它的核心价值没有变：**把"无数个状态位"压缩成"一排可扫读的颜色"**，这是任何复杂报表替代不了的。

> [!essentials] 核心要点
> - **红黄绿语义必须严格**：红=故障/报警（不可用于正常运行）、黄=待机/注意/预警、绿=运行/正常——全项目统一（IEC 60204-1 约定）
> - **`Ellipse` + `Fill` 是最简实现**：状态切换 = 换 `Brush` 颜色；`RenderOptions.SetEdgeMode` 可消除圆形锯齿
> - **闪烁用 `DispatcherTimer` 切换两态**：亮色 ↔ 暗色（或暗色 ↔ 透明），如示例红灯 300ms 切一次；**停用/关闭窗口时务必 `Stop()` 定时器**，否则泄漏
> - **颜色要配文字，别只靠颜色**：色盲操作员（约 8% 男性）无法分辨红绿，每个指示灯旁配状态文字（如"运行/报警"）
> - **闪烁 = 未确认的紧急报警**：常亮表示"已确认但仍在"，闪烁表示"新报警未确认"——与 `报警系统` 的确认流程联动
> - **后台线程禁止直接改 `Fill`**：状态来自采集线程，更新 UI 必须 `Dispatcher.Invoke`（见 `采集线程模型设计`）

> **MainWindow.xaml.cs —— 后台代码：**
> ```csharp
> using System;
> using System.Windows;
> using System.Windows.Media;
> using System.Windows.Threading;
>
> namespace HmiDemo
> {
>     public partial class MainWindow : Window
>     {
>         private readonly DispatcherTimer _blinkTimer;   // 报警灯闪烁定时器
>         private bool _blinkOn;                          // 闪烁相位
>         private bool _alarm;                            // 是否处于报警态
>
>         public MainWindow()
>         {
>             InitializeComponent();
>             _blinkTimer = new DispatcherTimer { Interval = TimeSpan.FromMilliseconds(300) };
>             _blinkTimer.Tick += OnBlinkTick;
>         }
>
>         // 启动设备：绿灯亮、黄灯灭，报警灯复位
>         private void OnRunClick(object sender, RoutedEventArgs e)
>         {
>             _alarm = false;
>             _blinkTimer.Stop();
>             RunLight.Fill = Brushes.LimeGreen;      // 正常=绿色
>             IdleLight.Fill = Brushes.DimGray;       // 待机=暗灰
>             AlarmLight.Fill = Brushes.DimGray;      // 报警灯熄灭
>             StatusText.Text = "设备状态：运行中";
>         }
>
>         // 模拟报警：红灯开始闪烁(亮/暗交替)，吸引注意
>         private void OnAlarmClick(object sender, RoutedEventArgs e)
>         {
>             _alarm = true;
>             RunLight.Fill = Brushes.DimGray;        // 运行灯熄灭
>             IdleLight.Fill = Brushes.DimGray;
>             AlarmLight.Fill = Brushes.Red;          // 红灯先亮起
>             _blinkOn = true;
>             _blinkTimer.Start();                    // 启动闪烁
>             StatusText.Text = "设备状态：报警！(未确认)";
>         }
>
>         // 闪烁：300ms 一次在 红色/暗红 间切换
>         private void OnBlinkTick(object sender, EventArgs e)
>         {
>             _blinkOn = !_blinkOn;
>             AlarmLight.Fill = _blinkOn ? Brushes.Red : Brushes.DarkRed;
>         }
>
>         // 复位：停止闪烁，恢复待机
>         private void OnResetClick(object sender, RoutedEventArgs e)
>         {
>             _alarm = false;
>             _blinkTimer.Stop();
>             RunLight.Fill = Brushes.DimGray;
>             IdleLight.Fill = Brushes.Gold;          // 待机=黄色
>             AlarmLight.Fill = Brushes.DimGray;
>             StatusText.Text = "设备状态：待机";
>         }
>     }
> }
> ```

> [!scene] 适用场景
> ✅ **设备状态总览矩阵**：几十台设备每台一排指示灯（运行绿/待机黄/报警红），整产线状态一眼扫完
> ✅ **报警/故障提示**：报警灯闪烁 + `报警系统` 弹窗，操作员第一时间定位问题设备
> ✅ **流程节点状态**：工序是否到位、联锁是否满足，用指示灯表达"通过/未通过"
> ✅ **通信状态显示**：PLC/仪表在线（绿）、离线（红）——上位机采集链路的健康信号（呼应 `采集系统总体设计` 的链路状态）
> ❌ **多状态/连续量表达**：5 种以上状态、或温度压力这种连续值，指示灯无法表达，用仪表盘/曲线/文字
> ❌ **需要精确语义的场景**（如"报警代码 23"）：颜色表达不了细节，配 `报警系统` 的明细列表

> [!pitfall] 常见踩坑
> 坑 1：**只靠颜色区分状态** → 现象：色盲操作员分不清红绿，把报警当正常 → 原因：颜色是唯一信息通道 → 解决：每个指示灯旁配文字标签（示例第 2 行），闪烁+颜色+文字三重表达
>
> 坑 2：**闪烁定时器没停止/没释放** → 现象：窗口关闭后程序仍占用资源、指示灯逻辑残留 → 原因：`DispatcherTimer` 持有 UI 引用未 `Stop` → 解决：切换状态时 `_blinkTimer.Stop()`（如示例），窗口 `Closed` 事件里兜底 `Stop()`
>
> 坑 3：**颜色语义乱用（报警用绿色、正常用红色）** → 现象：操作员误判"正在报警却以为正常" → 原因：各页面自己定颜色 → 解决：全项目统一遵循 IEC 60204-1（红=故障、黄=注意、绿=正常），最好用 `ResourceDictionary` 统一定义 `Brushes` 供所有页面引用
>
> 坑 4：**后台采集线程直接改 `Fill`** → 现象：偶发 `InvalidOperationException` → 原因：WPF 控件只能 UI 线程访问 → 解决：状态值从后台线程经 `Dispatcher.Invoke` 封送后再更新 `Fill`（见 `采集线程模型设计`）

> [!best] 最佳实践
> - **状态封装成枚举**：`DeviceState { Running, Standby, Alarm }`，界面通过枚举 → 颜色的映射表（或 `IValueConverter`）渲染，杜绝散落的 `if (x) Fill=red` 逻辑
> - **颜色统一放 `ResourceDictionary`**：`LightGreenBrush`/`LightYellowBrush`/`LightRedBrush` 集中定义，全项目复用、改主题只改一处
> - **闪烁语义与报警确认联动**：未确认 → 闪烁；已确认仍存在 → 常亮；恢复 → 熄灭——对接 `报警系统` 的状态机
> - **指示灯只做显示层**：真正的状态判定（阈值、报警逻辑）放在采集/报警服务里，UI 只"画"不"算"
> - **尺寸与间距规整**：`Ellipse` 统一 `Width/Height`（如 36×36），多行矩阵对齐，视觉上像一排塔灯

> [!practice] 上手练习
> **Lv.1 运行改参数**：运行示例点"启动设备→模拟报警→复位"走一遍流程，观察报警灯闪烁；把 `_blinkTimer.Interval` 改成 100ms，观察闪烁变急促
> **Lv.2 加属性**：加第 4 个"通信状态"指示灯：模拟 PLC 掉线（红色常亮）与恢复（绿色），体会"通信状态"与"设备状态"是两套灯
> **Lv.3 改造**：把闪烁从 `DispatcherTimer` 换成 `Storyboard`（`ColorAnimation` 让红/暗红渐变过渡），对比 Timer 的硬切换与动画的柔和感
> **Lv.4 挑战**：定义 `DeviceState` 枚举 + `StateToBrushConverter`（`IValueConverter`），做一个 3×3 设备状态矩阵（9 台设备各一个灯+文字），后台线程模拟各设备随机状态变化并 `Dispatcher.Invoke` 刷新——可复用的设备状态总览组件
