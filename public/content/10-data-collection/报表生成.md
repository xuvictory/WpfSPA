# 报表生成

> [!plain] 白话理解
> 把报表生成比作**做一份周报**：原始数据是"这一周的每笔流水记录"，报表是"本周产量、平均温度、几次超温报警、哪台设备最忙"——**把海量明细浓缩成几张能决策的表**。
>
> 上位机里最常见的三张报表：
> - **日报/交接班报**：本班产量、开机时长、越限次数
> - **设备运行统计**：每台设备运行时间、故障次数、平均温度
> - **报警统计**：按类型/优先级统计报警次数、最长报警时长
>
> 它们的共同套路是：**从存储层（SQLite/关系库）取明细 → 用 LINQ 做聚合统计（`GroupBy` + `Max/Min/Avg/Count`）→ 把结果填充到 Excel/PDF/CSV 输出**。报表的本质不是"导出文件"，而是"**先算清楚，再输出**"。
>
> 一句话：**报表生成 = 查询原始明细 + LINQ 分组聚合统计 + 导出成 Excel/PDF/CSV**，让管理者"一张表看懂全局"。

> [!def] 官方定义
> - **报表（Report）**：对一定时间范围内的业务/过程数据做**汇总、统计、分析**后形成的结构化呈现，是 SCADA/HMI 的常规功能模块（如日报、月报、交班报、报警报）。
> - 核心统计手段（`System.Linq`）：`Where`（时间范围/条件筛选）、`GroupBy`（按设备/按小时分组）、`Count`/`Sum`/`Max`/`Min`/`Average`（聚合指标）。
> - 输出载体：`导出-excelepplusclosedxml`（交互分析）、`导出-pdf`（正式版式）、`导出-csv`（海量明细）。
> - **统计口径（Business Rule）**：报表的灵魂——"产量"按什么算、"越限"以什么阈值判、"故障时长"从哪到哪，口径不一致的报表会误导决策。
> - 📖 官方文档：[Enumerable.GroupBy](https://learn.microsoft.com/zh-cn/dotnet/api/system.linq.enumerable.groupby)、[LINQ 聚合操作](https://learn.microsoft.com/zh-cn/dotnet/standard/linq/aggregation-operations)

> [!origin] 由来背景
> 报表与工业管理几乎同龄：手工台账时代，车间统计员每晚汇总"产量、废品、停机原因"，管理层靠这些纸表决策。计算机化后（1980 年代的 MIS 管理信息系统、1990 年代 ERP），报表从"人工誊写"变为"SQL 查询 + 打印"。工业上位机领域，SCADA 软件的报表模块（日报/月报）成为标配，数据源也从早期"文件解析"演进为"数据库查询"。
> 今天的上位机报表流程高度标准：**采集落库（`轻量级数据库-sqlite`/关系库）→ LINQ/SQL 聚合 → Excel/PDF 输出**。报表的难度早已不在"生成文件"，而在**统计口径与数据质量**——数据清洗（`数据过滤与清洗`）和统一定义，才是一份可信报表的前提。

> [!essentials] 核心要点
> - **报表三步走**：① `SELECT`/读取时间范围内的明细 → ② LINQ 聚合（`GroupBy` + 聚合函数）→ ③ 填充 Excel/PDF/CSV
> - **`GroupBy` 是统计核心**：`data.GroupBy(d => d.Device).Select(g => new { 设备 = g.Key, 平均温度 = g.Average(...), 次数 = g.Count() })`——按设备/按小时/按班次分组统计
> - **统计口径要写清楚**：最大值=瞬时最大还是 5 分钟均值？越限=超过阈值还是超过阈值持续 N 秒？口径必须先定死再写代码
> - **时间边界处理**：跨天（23:50~00:10）、跨班次（白班 8:00~20:00）的数据归属要按口径明确，`DateTime` 比较用半开区间 `>= start && < end`
> - **输出载体按需求选**：明细海量 → CSV；交互分析 → Excel；正式交付 → PDF（三篇文章见 `导出-csv`/`导出-excelepplusclosedxml`/`导出-pdf`）
> - **定时 + 手动双触发**：日报按 `DispatcherTimer` 到点自动生成，也可点按钮手动补生成——现场交接班不能靠人记着点按钮

> **报表生成演示：从内存数据按设备分组统计产量、平均温度、越限次数并输出汇总：**

> **MainWindow.xaml.cs —— 后台代码：**
> ```csharp
> using System;
> using System.Collections.Generic;
> using System.Linq;
> using System.Windows;
>
> namespace HmiDemo
> {
>     public partial class MainWindow : Window
>     {
>         // 采集明细：时间 + 设备 + 温度(模拟一天 3 台设备每 10 分钟一条)
>         private List<(DateTime Time, string Device, double Temp)> _detail =
>             new List<(DateTime, string, double)>();
>         private const double AlarmLimit = 85;      // 越限阈值(统计口径)
>
>         public MainWindow() => InitializeComponent();
>
>         private void OnGenClick(object sender, RoutedEventArgs e)
>         {
>             _detail.Clear();
>             var rnd = new Random();
>             DateTime start = DateTime.Today;
>             for (int i = 0; i < 24 * 6; i++)                       // 全天每 10 分钟一条
>                 for (int d = 1; d <= 3; d++)
>                     _detail.Add((start.AddMinutes(i * 10),
>                                  "设备" + d,
>                                  rnd.Next(30, 100) + (d == 2 ? 20 : 0)));
>             InfoText.Text = $"已生成 {_detail.Count} 条明细（3 台设备 × 全天每 10 分钟）";
>         }
>
>         // 日报表：按设备分组，统计采样数/平均/最大/越限次数
>         private void OnReportClick(object sender, RoutedEventArgs e)
>         {
>             if (_detail.Count == 0) { InfoText.Text = "请先生成模拟数据"; return; }
>
>             ReportTitle.Text = $"设备日报表（{DateTime.Today:yyyy-MM-dd}，越限阈值 {AlarmLimit}℃）";
>             ReportList.Items.Clear();
>             ReportList.Items.Add($"{"设备",-6}{"采样数",-8}{"平均温",-10}{"最高温",-10}{"越限次数",-8}");
>
>             var stat = _detail.GroupBy(x => x.Device)              // 按设备分组
>                 .Select(g => new
>                 {
>                     Device = g.Key,
>                     Count = g.Count(),
>                     Avg = g.Average(x => x.Temp),
>                     Max = g.Max(x => x.Temp),
>                     Over = g.Count(x => x.Temp > AlarmLimit)        // 越限统计
>                 });
>
>             foreach (var s in stat.OrderBy(s => s.Device))
>                 ReportList.Items.Add(
>                     $"{s.Device,-8}{s.Count,-10}{s.Avg,8:F1}℃{s.Max,8:F1}℃{s.Over,8}");
>
>             ReportList.Items.Add("-------------------------------");
>             ReportList.Items.Add($"全天总越限次数：{_detail.Count(x => x.Temp > AlarmLimit)}");
>             InfoText.Text = "日报表已生成（可再接导出 Excel/PDF）";
>         }
>     }
> }
> ```

> [!scene] 适用场景
> ✅ **日报/交接班报**：每班/每天自动生成"产量、开机时间、越限次数"，交接班不再靠嘴说
> ✅ **设备运行统计**：按设备统计运行时长、故障次数、平均负载，支撑设备健康评价
> ✅ **报警统计报表**：按类型/优先级统计报警次数与时长，识别"总是报警的那台设备"（呼应 `报警系统`）
> ✅ **月度管理报告**：管理层看趋势（产量、能耗环比），从明细聚合出 KPI
> ❌ **实时监控画面**：报表是"事后总结"，实时状态用曲线/指示灯（见 `实时曲线livecharts2`、`状态指示灯`）
> ❌ **复杂多维分析（钻取/联机分析）**：那是 BI 工具（Power BI 等）的领域，上位机做标准报表即可

> [!pitfall] 常见踩坑
> 坑 1：**统计口径不统一** → 现象：生产部说"今天产量 1000"，工艺部说"今天产量 950"，两边吵起来 → 原因：一个按合格品算、一个按下线数算，报表口径没说清 → 解决：**口径先行**——在代码里把定义写成注释/常量（如示例 `AlarmLimit`），并同步到报表表头，让使用者知道"越限=超过 85℃"
>
> 坑 2：**时间边界错位（跨天/跨班次）** → 现象：00:10 的数据既算进昨天又算进今天，或两边都不算 → 原因：用 `>= start && <= end` 闭区间导致边界点重复统计 → 解决：统一半开区间 `>= start && < end`；班次划分（白班 8:00 起）在代码里用常量定义
>
> 坑 3：**除零/空分组导致崩溃** → 现象：某台设备当天没有数据，`g.Average(...)` 抛 `InvalidOperationException` → 原因：空序列不能取 Average → 解决：分组后先判断 `g.Any()`，或聚合用可空结果（`g.Average(...) ?? 0`）兜底
>
> 坑 4：**报表在 UI 线程同步算大数据** → 现象：统计 100 万条明细时界面卡死十几秒 → 原因：LINQ 聚合是 CPU 密集操作占用 UI 线程 → 解决：`Task.Run` 后台统计，`Dispatcher.Invoke` 回 UI 刷新（见 `采集线程模型设计`）

> [!best] 最佳实践
> - **报表服务独立成层**：`ReportService.BuildDailyReport(DateTime day)` 返回强类型报表模型（`DailyReport` 类），UI 只负责展示与导出
> - **统计口径做成配置**：越限阈值、班次时间、保留期放配置文件（呼应 `数据转换与工程值计算` 的点位配置思想），口径调整不改代码
> - **报表输出模板化**：同一份报表模型可导出 Excel/PDF/CSV 三种格式（复用 `导出-excelepplusclosedxml`/`导出-pdf`/`导出-csv`），输出层与统计层解耦
> - **定时任务自动生成**：`DispatcherTimer` 到点（如交接班 7:55）自动生成日报并存档，操作员上班就能看（见「第 8 章·dispatchertimer」）
> - **报表数据先清洗**：统计前过滤掉越界毛刺（`数据过滤与清洗`），否则一个 99.0 的假尖峰就能让"最高温"失真

> [!practice] 上手练习
> **Lv.1 运行改参数**：运行示例生成数据 → 生成日报表，观察按设备分组的统计行；把 `AlarmLimit` 改成 95，观察"越限次数"如何变化——体会统计口径的影响
> **Lv.2 加属性**：加"按小时统计"视图：`GroupBy(x => x.Time.Hour)` 统计每小时平均温度与越限次数，绘制"温度时段分布"——日报的进阶
> **Lv.3 改造**：数据源换成 `轻量级数据库-sqlite`：明细落库后用 `SELECT` 查询 + LINQ 聚合，报表结果用 `导出-csv` 落盘——实现"采集→存储→统计→导出"完整链路
> **Lv.4 挑战**：实现"定时日报 + 多格式导出"：`DispatcherTimer` 每天 07:55 自动统计昨日数据，同时生成 CSV（明细）与 Excel（汇总，用 `导出-excelepplusclosedxml`），文件按 `日报_2026-08-17.csv` 命名归档——一个可交付车间使用的报表模块
