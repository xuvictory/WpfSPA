# 报警系统

> [!plain] 白话理解
> 报警系统就是**产线的"哨兵+值班日志"**：哨兵负责"值超限了立刻喊人"（报警触发 + 闪烁提示），值班日志负责"哪年哪月谁报过警、谁确认的、什么时候恢复"（报警记录，随时可查）。
>
> 一套完整报警不是"超了变红"那么简单，它是一条**闭环流程**：
> 1. **触发**：值超过阈值（如温度 > 85℃）
> 2. **提示**：界面红灯闪烁 + 蜂鸣/弹窗，提醒操作员
> 3. **确认**：操作员点"确认"——表示"我知道了"，闪烁变常亮
> 4. **恢复**：值回到安全区，报警自动消除
> 5. **记录**：触发/确认/恢复三个时间点全部入库，事后可追溯
>
> 没有这套闭环，报警就是"闪了一下没人管"——出了事故查不到证据。一句话：**报警系统 = 阈值判定 + 状态机（触发→确认→恢复）+ 全流程记录**，是工业安全与追溯的底线功能。

> [!def] 官方定义
> - **报警系统（Alarm Management）**：检测过程量/状态量超限并触发"提示—确认—恢复—记录"闭环的管理机制。工业领域有正式标准：**ISA-18.2**（美国）与 **IEC 62682**（国际，2014 年）《过程工业报警系统管理》，定义报警定义、设计、运维与性能指标（如报警率、滞留报警）。
> - 关键概念：**报警阈值**（触发值）、**死区（Deadband/Hysteresis）**——恢复阈值与触发阈值之差（如触发 85℃、恢复 80℃，避免临界抖动反复报警）、**确认（Acknowledge）**、**报警优先级**（紧急/高/中/低）。
> - 工程实现要点：报警判定在数据服务层（基于清洗后的工程值），UI 层负责闪烁/列表/确认交互，记录持久化到数据库（见 `轻量级数据库-sqlite`），保留策略独立配置。
> - 📖 官方文档：[ISA-18.2 报警管理标准](https://www.isa.org/standards-and-publications/isa-standards/isa-standards-committees/isa18)、[IEC 62682](https://webstore.iec.ch/en/publication/22748)

> [!origin] 由来背景
> 报警管理的痛点来自一个惨痛教训：**报警泛滥（Alarm Flood）**。1990 年代连续发生多起因报警系统失效导致的工业事故（如 2005 年英国邦斯菲尔德油库大爆炸，事故调查指出"报警过多、操作员无法处理"），监管机构要求系统化治理。2009 年 **ISA-18.2** 发布、2014 年升级为 **IEC 62682** 国际标准，规定：报警必须分级、必须设死区、必须有确认流程、报警率必须可度量（推荐每操作员每小时不超过 6 条新报警）。
> 在此之前，上位机报警常是"弹窗 + 蜂鸣"的野路子：不持久化、无确认、无死区——阈值附近一抖动就刷屏。标准化的结果，就是今天 WPF 上位机报警系统的标准形态：**数据服务判定 + 界面闭环 + 数据库全记录**。

> [!essentials] 核心要点
> - **判定放服务层、显示放 UI 层**：阈值判定在数据服务（吃清洗后的工程值），UI 只展示状态与交互，别在 XAML 里 if 颜色
> - **必须设死区（Hysteresis）**：触发 85℃、恢复 80℃，否则温度在 85℃ 上下抖动时报警疯狂"触发→恢复"刷屏
> - **报警状态机三态**：`已触发（未确认）` → `已确认（仍在报警）` → `已恢复`；界面表现：触发闪烁 → 确认常亮 → 恢复熄灭
> - **全流程持久化**：触发时间、确认人/时间、恢复时间、阈值、当前值都要入库，审计与事故追溯全靠它
> - **优先级分级**：紧急（停机级）/高/中/低，紧急报警单独醒目（声音+弹窗），避免与普通报警混在一起
> - **报警数据保留策略独立**：报警记录不要跟趋势数据一样 30 天 TTL 删除，至少保留 1~2 年（见 `存储策略与数据保留`）

> **MainWindow.xaml.cs —— 后台代码：**
> ```csharp
> using System;
> using System.Windows;
> using System.Windows.Media;
>
> namespace HmiDemo
> {
>     public partial class MainWindow : Window
>     {
>         private double _temp = 50;                 // 当前温度
>         private bool _alarming;                    // 是否处于报警状态(已触发)
>         private bool _acknowledged;                // 是否已确认
>
>         // 阈值与死区：触发 85，恢复 80(死区=5)，防止临界抖动反复报警
>         private const double TriggerLimit = 85;
>         private const double RecoverLimit = 80;
>
>         public MainWindow() => InitializeComponent();
>
>         private void OnIncClick(object sender, RoutedEventArgs e)
>         {
>             _temp += 5;
>             UpdateStatus();
>         }
>
>         private void OnDecClick(object sender, RoutedEventArgs e)
>         {
>             _temp -= 5;
>             UpdateStatus();
>         }
>
>         // 状态机：未触发 / 触发(未确认) / 触发(已确认) / 恢复
>         private void UpdateStatus()
>         {
>             TempText.Text = _temp.ToString("F1") + " ℃";
>             bool trigger = _temp >= TriggerLimit;   // 进入报警区(用触发阈值)
>             bool recover = _temp <= RecoverLimit;   // 退出报警区(用恢复阈值，死区防抖)
>
>             if (_alarming && recover)
>             {
>                 // 已报警且回到安全区 → 报警恢复
>                 _alarming = false;
>                 _acknowledged = false;
>                 AlarmState.Foreground = Brushes.LimeGreen;
>                 AlarmState.Text = "报警状态：已恢复";
>                 AlarmList.Items.Insert(0, $"[恢复] {DateTime.Now:HH:mm:ss} 温度 {_temp:F1}℃ 降至安全区");
>             }
>             else if (!_alarming && trigger)
>             {
>                 // 正常且进入报警区 → 触发报警(未确认)
>                 _alarming = true;
>                 _acknowledged = false;
>                 AlarmState.Foreground = Brushes.Red;
>                 AlarmState.Text = "报警状态：温度超限！(点击列表确认)";
>                 AlarmList.Items.Insert(0, $"[触发] {DateTime.Now:HH:mm:ss} 温度 {_temp:F1}℃ 超过 {TriggerLimit}℃");
>             }
>             else if (_alarming && !_acknowledged && !trigger)
>             {
>                 // 报警中但仍在死区(85~80之间)保持报警，不反复触发
>                 AlarmState.Text = $"报警状态：死区保持(温度 {_temp:F1}℃ 未回安全区)";
>             }
>         }
>
>         // 确认：把“未确认”置为“已确认”，界面从闪烁转常亮(此处简化为文字提示)
>         private void OnConfirmAlarm(object sender, System.Windows.Input.MouseButtonEventArgs e)
>         {
>             if (_alarming && !_acknowledged)
>             {
>                 _acknowledged = true;
>                 AlarmState.Text = "报警状态：已确认(仍在报警)";
>                 AlarmState.Foreground = Brushes.Orange;
>                 AlarmList.Items.Insert(0, $"[确认] {DateTime.Now:HH:mm:ss} 操作员已确认报警");
>             }
>         }
>     }
> }
> ```

> [!scene] 适用场景
> ✅ **过程量超限**：温度/压力/液位超限报警，带死区防抖，上位机最常见报警形态
> ✅ **设备故障/通信中断**：PLC 离线、看门狗超时，红灯+蜂鸣立即提示（呼应 `状态指示灯`）
> ✅ **工艺参数越界**：批次参数偏离设定值，及时提醒操作员干预
> ✅ **多级报警分级**：紧急（停机保护）与普通（提示）分开管理，按优先级呈现
> ❌ **毫秒级联锁保护**：真正的安全联锁（急停、超速跳机）必须在 PLC/安全回路完成，上位机报警只是"提示"，不是"保护"
> ❌ **无追溯需求的小工具**：纯展示型小软件不需要完整的"确认+记录"闭环

> [!pitfall] 常见踩坑
> 坑 1：**没有死区，报警疯狂抖动** → 现象：温度在 85℃ 上下波动时，报警"触发-恢复"刷屏、日志爆炸 → 原因：触发阈值=恢复阈值，临界点来回穿越 → 解决：恢复阈值低于触发阈值（如 85 触发/80 恢复），死区宽度 ≥ 正常波动幅度
>
> 坑 2：**报警不持久化** → 现象：事故后查不到"当时到底有没有报警" → 原因：报警只活在界面上，没入库 → 解决：触发/确认/恢复三事件全部落库（`轻量级数据库-sqlite`），保留期独立配置（`存储策略与数据保留`）
>
> 坑 3：**用未清洗的原始值判定** → 现象：电磁干扰的尖峰触发一堆假报警 → 原因：跳过 `数据过滤与清洗` 直接判定 → 解决：报警判定吃清洗后的工程值；仍要防"真超限瞬间"被滤波抹平，注意平滑延迟
>
> 坑 4：**确认与恢复逻辑混在一起** → 现象：点确认后报警消失，实际设备还在超温 → 原因：把"确认"当成了"消除" → 解决：状态机三态严格分离——确认只改"是否已知"，恢复必须等值回安全区（示例 `_alarming`/`_acknowledged` 两变量分离）

> [!best] 最佳实践
> - **报警服务独立成层**：`AlarmService` 负责阈值判定与状态机，UI 只订阅结果（事件/`INotifyPropertyChanged`），报警逻辑可单测
> - **死区从点位配置读取**：`触发阈值/恢复阈值` 进配置（见 `数据转换与工程值计算` 的点位配置思想），现场调参不用改代码
> - **紧急报警多通道提示**：界面闪烁 + 蜂鸣 + 弹窗 + 大屏高亮，但**声音要能一键静音**（避免夜班报警声骚扰）
> - **报警列表永远保留"未确认"置顶**：`DataGrid` 按 `未确认 > 已确认 > 已恢复` 排序，操作员先处理最紧急的
> - **遵循报警率指标**：参考 ISA-18.2，单操作员每小时新报警 ≤ 6 条——报警太频繁就是设计问题，该合并的合并、该降级的降级

> [!practice] 上手练习
> **Lv.1 运行改参数**：运行示例反复点"升温"到超过 85℃ 触发报警，再"降温"到 80℃ 以下恢复；把 `RecoverLimit` 改成 84，观察临界抖动的"触发-恢复"刷屏——亲手感受死区的作用
> **Lv.2 加属性**：把"确认"从鼠标事件改成独立的"确认报警"按钮，确认前后 `AlarmState` 文字与颜色变化（红→橙），验证"确认≠消除"
> **Lv.3 改造**：把报警记录落库：`触发/确认/恢复` 三条记录写入 `SQLite` 的 `AlarmRecord` 表（时间、类型、值、阈值），启动时加载历史——配合 `轻量级数据库-sqlite`
> **Lv.4 挑战**：实现"优先级+闪烁"完整报警：`AlarmRecord` 加 `Priority` 字段（紧急/高/中/低），紧急报警红灯闪烁（`DispatcherTimer`）+ 弹窗，普通报警列表静默记录；按"未确认优先"排序展示——一个接近工业实践的报警中心
