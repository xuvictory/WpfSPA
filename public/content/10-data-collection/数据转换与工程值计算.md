# 数据转换与工程值计算

> [!plain] 白话理解
> 把原始值比作**温度计上的"刻度格数"**，工程值比作"实际温度"。一根量程 -50~150℃ 的温度计，满格是 200 格——你读到 100 格时，实际温度不是 100℃，而是按比例换算出的 50℃。
>
> 工业现场一模一样：变送器把物理量变成 4-20mA 电流，PLC 的模拟量模块把它 ADC 成数字（西门子是 0~27648，三菱是 0~4000），上位机读到的就是这个"格数"。**格数本身毫无意义，只有按"量程比例"翻译成 ℃、MPa、m³/h 才是人看得懂的工程值。**
>
> 一句话：**工程值计算 = 把设备的"刻度"按比例翻译成物理量的"单位"**——`工程值 = 原始值在原始量程中的位置 × 工程量程 + 工程下限`。换算错一位小数，现场就是误报警甚至误动作。

> [!def] 官方定义
> - **工程值计算（Engineering Value Scaling / 标度变换）**：把设备原始值（ADC 码、寄存器整型）按线性或非线性关系映射为工程量纲数值的过程。线性标度公式为：
>   `eng = (raw - rawMin) / (rawMax - rawMin) × (engMax - engMin) + engMin`
>   其中 `[rawMin, rawMax]` 是原始值量程（如西门子 0~27648），`[engMin, engMax]` 是工程量程（如 0~100 ℃）。
> - **非线性标度**：热电偶/热电阻用**分度表查表**（如 K 型热电偶 mv→℃），差压流量计需**开方**（流量 ∝ √ΔP），气体用**温压补偿**公式。
> - 相关 API：类型转换用 `System.Convert`、`double.TryParse`；字节序读取见 `数据解析字节序类型转换`。
> - 📖 官方文档：[Convert 类](https://learn.microsoft.com/zh-cn/dotnet/api/system.convert)、[double.TryParse](https://learn.microsoft.com/zh-cn/dotnet/api/system.double.tryparse)

> [!origin] 由来背景
> 早期仪表输出的是**模拟信号（4-20mA、0-10V）**，PLC/采集卡的 ADC 把它变成数字量——不同厂商 ADC 位宽不同：西门子 S7 系列常用 **0~27648**（对应 15 位 ADC 的工程量程）、三菱 FX 系列是 **0~4000**（12 位）、AB 是 **0~16384**。而每个变送器的量程也不同：同一块 4-20mA 板子，配 0-100℃ 的探头和 0-1.6MPa 的变送器，读到的原始值含义完全不同。
> 于是"原始值→工程值"的换算层成为必须：它把"厂商相关、探头相关"的原始码统一成"人看的物理量"，让显示、报警、存储、报表只认工程值。这一层在现代上位机里被固化为"点位配置 + 标度计算"的标准结构。

> [!essentials] 核心要点
> - **线性标度是核心**：`比例 × 量程 + 下限`——先归一化到 0~1，再映射到工程区间，任何模拟量都适用
> - **量程必须与变送器严格一致**：`rawMin/rawMax` 由采集模块决定（27648/4000/16384），`engMin/engMax` 由探头量程决定，两对数字错一对就全错
> - **防除零**：`rawMax == rawMin` 时公式崩溃，直接返回 `engMin` 或记错误日志
> - **类型转换与符号要谨慎**：`ushort` 当 `short` 读会让负数变 65535；`ushort`→`int` 要先转再减偏移
> - **非线性场景用查表/公式**：热电偶查分度表、差压开方 `√ΔP`、气体温压补偿，别硬套线性公式
> - **单位统一后再进下游**：℃/℉、MPa/kPa 在换算层就统一，存储、报警、报表只认一套单位

> **MainWindow.xaml.cs —— 后台代码：**
> ```csharp
> using System;
> using System.Windows;
>
> namespace HmiDemo
> {
>     public partial class MainWindow : Window
>     {
>         public MainWindow() => InitializeComponent();
>
>         private void OnConvertClick(object sender, RoutedEventArgs e)
>         {
>             double raw = double.Parse(RawBox.Text.Trim());
>             double engMin = double.Parse(EngMinBox.Text.Trim());
>             double engMax = double.Parse(EngMaxBox.Text.Trim());
>
>             // 核心换算：原始值按比例线性映射到工程值区间
>             double eng = LinearScale(raw, 0, 27648, engMin, engMax);
>
>             ResultText.Text = $"工程值：{eng:F2} ℃";
>             LogList.Items.Insert(0, $"原始值 {raw} → 工程值 {eng:F2} ℃（量程 {engMin}~{engMax}）");
>         }
>
>         // 通用线性标度公式：把 [rawMin, rawMax] 区间映射到 [engMin, engMax]
>         private double LinearScale(double raw, double rawMin, double rawMax,
>                                    double engMin, double engMax)
>         {
>             if (rawMax == rawMin) return engMin;                 // 防除零
>             double ratio = (raw - rawMin) / (rawMax - rawMin);   // 归一化到 0~1
>             return ratio * (engMax - engMin) + engMin;           // 映射到工程值区间
>         }
>     }
> }
> ```

> [!scene] 适用场景
> ✅ **模拟量输入点表**：4-20mA 变送器（温度、压力、液位）经 ADC 后必须换算成工程值显示与报警
> ✅ **西门子 S7（0~27648）/ 三菱（0~4000）模拟量**：不同品牌原始量程不同，换算层统一处理
> ✅ **流量计开方**：差压式流量计 `流量 = K·√ΔP`，必须做开方标度，直接线性映射是错的
> ✅ **热电偶/热电阻**：mv 值查分度表转温度（K/S/B 型各有分度表）
> ❌ **已由设备算好的工程值**：智能仪表/变送器本身支持直接读工程值（如 Modbus 读到的就是 ℃），无需再换算
> ❌ **纯数字量（开关量）**：通/断、运行/停机无标度需求

> [!pitfall] 常见踩坑
> 坑 1：**量程范围搞错（把 27648 当 4000）** → 现象：温度显示偏大/偏小约 6.9 倍 → 原因：不同品牌 ADC 原始量程不同（西门子 27648、三菱 4000、AB 16384），按记忆写错 → 解决：从 PLC 手册/组态确认 `rawMax`，并做成点位配置，现场可改
>
> 坑 2：**有符号无符号转换错位** → 现象：负温度显示成 65535 或 32768 → 原因：设备寄存器是无符号 `ushort`，负数用补码表示，直接当 `ushort` 读就变 65535 → 解决：按协议把负数区（如 `0x8000~0xFFFF`）先转 `short` 再换算
>
> 坑 3：**除零未防护** → 现象：`DivideByZeroException` 崩溃或显示 NaN → 原因：`rawMax - rawMin == 0`（如量程没配置）→ 解决：`LinearScale` 开头判断（如示例），返回下限并记日志
>
> 坑 4：**差压流量计用线性映射** → 现象：流量显示与现场不符，小流量偏差尤其大 → 原因：流量 ∝ √ΔP 是非线性关系 → 解决：开方后再标度，或用温压补偿公式（见 `本地文件存储jsonxmlcsv二进制` 的场景联动）

> [!best] 最佳实践
> - **换算层独立成服务**：`IScalingService.Scale(PointConfig cfg, double raw)`，所有点位统一走它，换算逻辑只写一遍
> - **点位配置驱动**：`PointConfig`（名称、rawMin/rawMax、engMin/engMax、单位、是否开方、滤波方式）放配置文件，新增点位不改代码
> - **输入用 `TryParse` 而非 `Parse`**：用户/配置输入不合法时优雅降级（提示+默认值），别让异常打断采集主流程
> - **换算结果四舍五入规则统一**：显示 2 位小数、报警阈值按实际精度，避免"显示 0.0 但报警判定在 0.0001 级别"的偏差
> - **与清洗、校验串成流水线**：`校验 → 清洗 → 换算 → 存储`，换算必须吃干净的原始值（见 `数据过滤与清洗`）

> [!practice] 上手练习
> **Lv.1 运行改参数**：运行示例把原始值 13824、量程 0~100 换成 0~50，观察工程值变化；再输入 27648 验证满量程映射
> **Lv.2 加属性**：增加"开方模式"复选框：勾选时对 `ratio` 先 `Math.Sqrt` 再映射（模拟差压流量计），对比线性与开方曲线的差异
> **Lv.3 改造**：把输入从 `double.Parse` 换成 `double.TryParse`，非法输入时在 `LogList` 显示友好提示而不是崩溃；再把换算方法扩展为支持"反算"（工程值→原始值）
> **Lv.4 挑战**：设计 `PointConfig` 类与 `ScalingService` 服务，用 `DataGrid` 配置 5 个点位（不同原始量程/工程量程/单位），实时采集换算并显示——这就是真实上位机点表管理的雏形（可结合 `实时曲线livecharts2` 画出来）
