# 数据过滤与清洗

> [!plain] 白话理解
> 把采集到的数据比作**渔网捞上来的渔获**：里面既有好鱼（真实数据），也有死鱼烂虾（越界毛刺）、空壳（NaN 无效值）、混进来的杂物（电磁干扰噪声）。**清洗**就是把渔获倒上分拣台：烂虾扔掉（越界剔除）、空壳挑出（NaN 过滤）、杂质筛掉（噪声平滑），留下能用的好鱼。
>
> 如果你**不洗就直接下锅**（存库、画曲线），结果就是：历史库里躺着一堆 `99.0` 的异常温度，曲线上突然冒出一个尖刺，操作员看到的是"设备疯了"。而设备其实没疯，只是数据没洗干净。
>
> 一句话：**脏数据直接进下游 = 垃圾进、垃圾出（GIGO）；清洗就是"剔除明显错误的值 + 压平噪声"，但绝不无脑覆盖真实信号**。

> [!def] 官方定义
> - **数据清洗（Data Cleaning）**：数据处理流程中的规范化环节，负责**检测并处理缺失值、越界值、重复值、噪声**，使数据满足后续存储/计算/展示的质量要求。工业上位机中特指对采集原始值做的实时预处理。
> - 关键 API 归属：无效值检测用 `double.IsNaN`（NaN 永远不等于自己，`v == double.NaN` 恒为 false）、`double.IsInfinity`；聚合用 `System.Linq.Enumerable.Average`/`Min`/`Max`；类型安全转换用 `double.TryParse`。
> - 常见算法：**越界阈值剔除**（区间过滤）、**滑动平均**（Moving Average，窗口内求均值）、**中值滤波**（Median Filter，取窗口内中位数，抗尖峰更强）、**一阶低通/指数平滑**（`y = α·x + (1-α)·y_prev`，实时场景常用）。
> - 📖 官方文档：[double.IsNaN](https://learn.microsoft.com/zh-cn/dotnet/api/system.double.isnan)、[Enumerable.Average](https://learn.microsoft.com/zh-cn/dotnet/api/system.linq.enumerable.average)

> [!origin] 由来背景
> "垃圾进、垃圾出（GIGO，Garbage In Garbage Out）"是 1957 年由编程先驱 George Fuechsel 提出的计算机格言，数据质量意识由此诞生。工业现场是脏数据的重灾区：**电磁干扰**让模拟量瞬间跳变、**设备重启**时寄存器返回默认值 0 或 0xFFFF、**断线期间**读到的是上一次缓存、**ADC 溢出**产生 NaN——这些数据若直接进历史库，会让报表、报警、统计全部失真。
> 早期由 PLC 内部简单处理，后来上位机承担更多数据质量职责；到大数据时代，数据仓库把清洗固化为 ETL（抽取-转换-加载）的第一环节。在 WPF 上位机里，清洗也从"可选优化"变成了"采集链路的标准一环"（对应 `采集系统总体设计` 的处理层）。

> [!essentials] 核心要点
> - **三步标准流程**：①越界剔除（按量程上下限）→ ②NaN/Infinity 剔除 → ③噪声平滑；顺序不能乱——先扔垃圾，再压噪声
> - **NaN 判断必须用 `double.IsNaN`**：`v == double.NaN` 永远为 false，这是无数人踩过的坑
> - **平滑算法按场景选**：滑动平均最简单但有延迟；中值滤波抗尖峰（适合毛刺多）；一阶低通 `α` 平滑适合实时流（延迟小）
> - **永远保留原始数据链**：清洗结果与原始数据并存，不要就地覆盖——现场排查"为什么这条数据没了"时全靠原始记录
> - **剔除要计数、要日志**：剔除率（剔除条数/总数）是数据质量的核心指标，异常飙升说明现场设备出了问题
> - **清洗参数可配置**：阈值、窗口大小、α 系数按设备/点位配置，别写死在代码里

> **MainWindow.xaml.cs —— 后台代码：**
> ```csharp
> using System;
> using System.Collections.Generic;
> using System.Linq;
> using System.Windows;
>
> namespace HmiDemo
> {
>     public partial class MainWindow : Window
>     {
>         private List<double> _raw = new List<double>();
>         private List<double> _clean = new List<double>();
>
>         public MainWindow() => InitializeComponent();
>
>         // 生成含噪声、越界毛刺、NaN 无效值的模拟原始数据
>         private void OnGenClick(object sender, RoutedEventArgs e)
>         {
>             var rnd = new Random();
>             _raw.Clear();
>             for (int i = 0; i < 30; i++)
>             {
>                 double v = rnd.Next(50, 400) / 5.0;      // 正常值约 10~80
>                 if (i % 10 == 3) v = 99.0;               // 人为制造越界毛刺
>                 if (i % 10 == 7) v = double.NaN;         // 人为制造无效值
>                 _raw.Add(v);
>             }
>             DataList.Items.Clear();
>             DataList.Items.Add("原始数据：" + string.Join(", ", _raw.Select(v => v.ToString("F1"))));
>             StatText.Text = $"原始 {_raw.Count} 条 | 待清洗";
>         }
>
>         // 清洗流程：①越界剔除 → ②NaN 剔除 → ③滑动平均平滑
>         private void OnCleanClick(object sender, RoutedEventArgs e)
>         {
>             var valid = _raw.Where(v => !double.IsNaN(v) && v >= 20 && v <= 80).ToList();
>             _clean = MovingAverage(valid, 3);
>
>             DataList.Items.Insert(0, "清洗后：" + string.Join(", ", _clean.Select(v => v.ToString("F1"))));
>             StatText.Text = $"原始 {_raw.Count} 条 | 清洗后 {_clean.Count} 条 | 剔除 {_raw.Count - valid.Count} 条";
>         }
>
>         // 滑动平均：取每 N 个连续点的均值替代原序列，抑制随机噪声
>         private List<double> MovingAverage(List<double> data, int window)
>         {
>             var result = new List<double>();
>             for (int i = 0; i <= data.Count - window; i++)
>                 result.Add(data.Skip(i).Take(window).Average());
>             return result;
>         }
>     }
> }
> ```

> [!scene] 适用场景
> ✅ **模拟量采集前置处理**：温度、压力、液位等模拟量易受电磁干扰，采集后立刻清洗再进入展示/存储
> ✅ **历史库入库前**：脏数据一旦入库极难清洗（要重放全流程），入库前清洗性价比最高（见 `存储策略与数据保留`）
> ✅ **实时曲线显示前**：毛刺会撕裂曲线、触发误报警，清洗后曲线才能看（见 `实时曲线livecharts2`）
> ✅ **报警判定前**：报警必须基于清洗后的数据，否则一次干扰就能误触发停机级联锁
> ❌ **开关量/数字量**：通断状态无平滑需求，直接原样使用
> ❌ **要求保留真实尖峰的场景**：如边缘检测、故障特征提取，清洗反而会抹掉有用信息

> [!pitfall] 常见踩坑
> 坑 1：**用 `v == double.NaN` 判断无效值** → 现象：NaN 永远滤不掉，脏数据照常入库 → 原因：IEEE 754 规定 NaN 与任何值（包括自己）比较都返回 false → 解决：必须用 `double.IsNaN(v)`（示例正是这么写的）
>
> 坑 2：**清洗参数一刀切，误杀正常数据** → 现象：夜班温度正常 20~30℃，白天却出现大量"越界剔除"记录 → 原因：上下限按最坏工况配，正常工况的数据被误判 → 解决：阈值按点位/工况分段配置，且"越界连续 N 次"才算坏点，容忍单次抖动
>
> 坑 3：**平滑过度把真实变化也抹平** → 现象：温度已经升到 90℃，曲线还停在 60℃慢慢爬 → 原因：滑动平均窗口过大 / α 太小 → 解决：实时场景用一阶低通（α=0.2~0.3），并测试"阶跃响应"——看真实突变要多久才能反映到输出
>
> 坑 4：**清洗后直接覆盖原始数据** → 现象：排查问题时找不到"原始值是多少" → 原因：原地修改 → 解决：原始链与清洗链并存（如示例 `_raw`/`_clean`），剔除时记录原因

> [!best] 最佳实践
> - **做成"过滤器链"**：每个清洗规则一个 `IFilter` 实现（越界过滤器/NaN 过滤器/平滑器），可插拔、可排序、可单独开关
> - **实时流用"增量清洗"**：逐点流式处理（保留前一个值用于一阶低通），不要攒一批再算——滑动平均有延迟，实时场景慎用
> - **统计剔除率并上屏**：把"原始 N / 清洗后 M / 剔除 K"显示在状态栏（如示例 `StatText`），剔除率异常是现场故障的早期信号
> - **清洗日志带原因码**：`[越界][NaN][超突变]` 标记每条剔除原因，统计各原因占比，定位是干扰还是设备故障
> - **与校验、换算组合成流水线**：校验 → 清洗 → 换算 → 存储，顺序固定（见 `数据校验crc校验和等`、`数据转换与工程值计算`）

> [!practice] 上手练习
> **Lv.1 运行改参数**：运行示例多次点"生成含噪数据"再"过滤与清洗"，观察剔除数量；把阈值改成 `v >= 0 && v <= 100`，看毛刺是否漏网
> **Lv.2 加属性**：给 `OnCleanClick` 增加"中值滤波"逻辑：把窗口 3 的滑动平均改成"取 3 个数的中位数"，对比两者对同一个尖峰的抑制效果
> **Lv.3 改造**：把清洗逻辑抽成 `IValueFilter` 接口（`bool IsValid(double v)` + `double Process(double v)`），实现越界过滤器和一阶低通平滑器，按链式顺序执行——体验可插拔清洗流水线
> **Lv.4 挑战**：做一个实时数据流模拟：后台线程每 50ms 产出一个含噪点，前台用"校验→清洗→一阶低通"流水线处理后显示"原始值/清洗值"双行曲线，并统计剔除率——这就是 `实时曲线oxyplot` + 清洗的完整实战
