# 工控看板模板项目

> [!plain] 白话理解
> 每个上位机项目都要做"监控大屏"：产量、OEE、良品率、报警一排卡片 + 实时数据。如果每次从零画，样式调整能折腾一星期。**工控看板模板项目**就是现成的"大屏图纸"——界面布局、配色、卡片、曲线、报警列表都搭好了，你只需把数据源换成自己的，改改标题和绑定就能交付。好比装修公司给的"样板间照片"，照着改最快。

> [!def] 官方定义
> **工控看板模板项目**指 GitHub 等平台上的**第三方开源**的工业监控看板/上位机界面模板（不是微软官方产物），常见代表：
> - **WPF_SCADA_SimpleUITemplate**（GitHub：https://github.com/chenlongkuan/WPF_SCADA_SimpleUITemplate ）：WPF 上位机简单 UI 模板，含设备卡片、状态灯、趋势等常用界面元素
> - **smartfactory-monitor**（GitHub：https://github.com/agentthink/smartfactory-monitor ）：基于 .NET 8 + WPF 的智能工厂设备实时监控看板，含产量、OEE 等 KPI 与报警展示
> - 以及 GitHub 上大量 `WPF dashboard`、`HMI template` 关键词下的社区模板项目
>
> 它们通常基于 `handycontrol`、`materialdesigninxaml` 等控件库搭建，配合 `livecharts2`/`oxyplot` 画曲线。微软官方没有提供"工控看板"专用模板，只有 WPF 基础控件（https://learn.microsoft.com/zh-cn/dotnet/desktop/wpf/controls/ ），看板布局全靠开发者组合与模板化。

> [!origin] 由来背景
> 工控看板模板的流行源于上位机项目的"高度同质化"：几乎每个项目都要"产量/OEE/报警"三件套。早期开发者反复重画，后来陆续有人把自己的框架开源，如 **WPF_SCADA_SimpleUITemplate**（作者 chenlongkuan，国内工业软件工程师）在 2018 年前后发布，为大量入门开发者提供了可直接改用的界面骨架；近年随 .NET 8 发布，**smartfactory-monitor** 等新一代模板又加入了现代化看板与分层设计。这些项目填补了"官方只有控件、没有成套看板"的空白，成为上位机开发者的效率加速器。

> [!essentials] 核心要点
> - **布局模板**：卡片式 `UniformGrid`/`Grid` 布局 + 暗色工控配色，一眼可读
> - **KPI 卡片**：产量、OEE、良品率、报警数等指标卡片，数字醒目、配色分级（绿/蓝/红）
> - **状态指示**：`Ellipse` 状态灯 + 文字状态，运行/停止/报警三色区分
> - **实时列表**：报警/事件列表滚动追加，时间戳 + 描述 + 级别
> - **曲线联动**：模板通常预留曲线区域，接入 `livecharts2`/`oxyplot` 即得实时趋势
> - **数据源替换点**：模板内定时器或模拟数据是"数据源桩"，替换为 `开源-plc-通信库`/`nmodbus` 采集即接真实设备

> **MainWindow.xaml.cs —— 后台代码：**
> ```csharp
> using System;
> using System.Windows;
> using System.Windows.Media;
> using System.Windows.Threading;
>
> namespace HmiDemo
> {
>     public partial class MainWindow : Window
>     {
>         private readonly DispatcherTimer _timer = new DispatcherTimer { Interval = TimeSpan.FromSeconds(2) };
>         private readonly Random _random = new Random();
>         private int _output;      // 累计产量
>         private int _alarmCount;  // 累计报警数
>
>         public MainWindow()
>         {
>             InitializeComponent();
>             _timer.Tick += OnTimerTick;
>             _timer.Start();
>         }
>
>         private void OnTimerTick(object sender, EventArgs e)
>         {
>             // 模拟产线数据源每 2 秒推送一批数据
>             _output += _random.Next(3, 9);
>             OutputText.Text = _output.ToString();
>             OeeText.Text = _random.Next(80, 98) + "%";
>             YieldText.Text = _random.Next(96, 100) + "%";
>
>             // 偶发报警，演示报警滚动列表
>             if (_random.Next(0, 5) == 0)
>             {
>                 _alarmCount++;
>                 AlarmText.Text = _alarmCount.ToString();
>                 AlarmText.Foreground = Brushes.OrangeRed;
>                 var time = DateTime.Now.ToString("HH:mm:ss");
>                 AlarmListText.Text = $"[{time}] 3 号工位温度过高，请检查冷却回路\n" + AlarmListText.Text;
>             }
>         }
>     }
> }
> ```

> [!scene] 适用场景
> ✅ 产线/车间大屏看板快速原型与交付
> ✅ 设备状态、产量、质量指标的集中展示
> ✅ 演示 Demo 与投标演示界面
> ✅ 学习"看板界面如何组织"的参考骨架
> ❌ 需要深度定制的正式交付系统（模板仅作起点，样式/交互需按甲方要求细化）
> ❌ 复杂工艺流程图（需专门的图元设计，模板不覆盖）

> [!pitfall] 常见踩坑
> 坑 1：**模板样式与业务不匹配硬凑** → 现象：拿模板改标题直接交付，甲方不认可 → 原因：没根据业务梳理布局与指标 → 解决：先定"看哪几个指标、谁看、多大数据量"，再在模板骨架上定制
>
> 坑 2：**模拟数据换成真实数据后崩溃** → 现象：模板定时器模拟数据换 `nmodbus` 后 UI 卡死/偶发异常 → 原因：采集在后台线程，直接改控件未切 UI 线程 → 解决：数据源接入点用 `Dispatcher` 或绑定 `ObservableCollection`（第 8 章异步）
>
> 坑 3：**大屏分辨率适配不佳** → 现象：在 4K/拼接屏上布局错乱或过小 → 原因：模板按固定尺寸写死 → 解决：用 `Viewbox` 缩放或响应式 Grid 比例布局，字体与间距用相对单位

> [!best] 最佳实践
> - 用模板快速定型后再替换数据源：先把模拟数据换成 `ObservableCollection` 绑定，再接真实采集
> - KPI 卡片配色统一规范：运行绿、停止灰、报警红、待机黄，全站一致
> - 大屏优先 `Viewbox` 整体缩放 + 设计分辨率（如 1920×1080），保证拼接屏适配
> - 报警列表固定最大条数（如 100 条）滚动覆盖，防内存与渲染膨胀
> - 把"看板骨架"沉淀成团队自己的模板工程，后续项目直接复用

> [!practice] 上手练习
> **Lv.1 照猫画虎**：运行本节示例，把"今日产量"改成"本班产量"并调整刷新频率
> **Lv.2 小试牛刀**：给看板加一块"温度趋势"区域，用 `livecharts2` 画实时曲线
> **Lv.3 融会贯通**：把模拟数据源替换成 `nmodbus` 真实读取的寄存器值，驱动 KPI 卡片
> **Lv.4 拆层挑战**：把看板改造成"采集服务 + 实时缓存 + WPF 看板"三层架构，配合 `dapper` 落库与 `serilog` 日志，做成团队可复用模板
