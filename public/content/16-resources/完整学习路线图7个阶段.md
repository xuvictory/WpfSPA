# 完整学习路线图（7个阶段）

> [!plain] 白话理解
> 学 WPF 上位机最怕"东一榔头西一棒子"：今天学个控件、明天学个动画，三个月过去还是拼不出一个完整程序。**学习路线图**就是给你一张"登山地图"——把"从零到能独立开发上位机"拆成 **7 个阶段**，每阶段有明确目标和验收标准。照着地图走，不迷路、不返工，每一步都踩在下一步的地基上。

> [!def] 官方定义
> 学习路线图不是某种官方技术规范，而是**社区/教程总结的系统学习路径**，它把 WPF/.NET 上位机开发的知识体系组织为 7 个递进阶段：
> 1. **C# 基础**：类型、集合、LINQ、异步（对应本书第 1~3 章与 `c-高级编程`）
> 2. **XAML 布局**：XAML 语法、布局容器、资源（对应 `什么是样式`/`资源字典` 等章节）
> 3. **控件与样式**：常用控件、`Style`/`ControlTemplate`、`DataTemplate`
> 4. **数据绑定与 MVVM**：`Binding`、`INotifyPropertyChanged`、命令、`communitytoolkitmvvm`
> 5. **多线程与通信**：`async/await`、串口/Modbus/MQTT（对应第 8 章与 `nmodbus`/`mqttnet`）
> 6. **项目实战**：完整上位机项目（看板、通信、日志、数据库）
> 7. **性能优化与部署**：性能分析、`clickonce-发布`/`msi-安装包wix-toolset`
>
> 各阶段都基于微软官方技术（WPF 平台 https://learn.microsoft.com/zh-cn/dotnet/desktop/wpf/ 与 .NET 文档 https://learn.microsoft.com/zh-cn/dotnet/ ），路线本身是学习组织方式，非官方标准。

> [!origin] 由来背景
> "7 阶段路线图"这类结构化的学习路径，源自 WPF 上位机开发"知识面广、实践门槛高"的特点——语法、界面、通信、并发、部署缺一不可。社区与培训机构在长期带新人的实践中发现：**按"语言 → 界面 → 绑定 → 通信 → 项目"递进组织**，学习效率远高于零散学。微软官方也提供类似的引导（`microsoft-learn-wpf-学习路径`），但"上位机行业专属路线"更多来自一线工程师的经验总结。本书的章节组织正是按此递进设计：前面章节打语言与界面基础，中段深入绑定与通信，后段覆盖测试、架构与部署。

> [!essentials] 核心要点
> - **阶段递进原则**：前一阶段是后一阶段的前提，不要跳级（尤其别在 C# 不熟时直接啃通信）
> - **每阶段验收**：用"能独立完成的小功能"验收，而不是"看完了"（见各章 `practice` 练习）
> - **阶段 1~2 打底**：C#（LINQ/异步）与 XAML（布局/资源）是地基，占全部精力约 30%
> - **阶段 3~4 关键**：样式模板 + 数据绑定 MVVM 是 WPF 的"灵魂"，占 30%，多花时间
> - **阶段 5 上位机特色**：多线程 + 通信（串口/Modbus/MQTT）是上位机区别于普通桌面软件的核心
> - **阶段 6~7 出成品**：完整项目 + 测试 + 部署，让学习产出可交付成果
> - **持续迭代**：路线图不是终点，做完 7 阶段回到阶段 4~5 结合新技术再深化

>                 new Stage { Name = "阶段 4 数据绑定与 MVVM", Progress = 100 },
>                 new Stage { Name = "阶段 5 多线程与通信", Progress = 100 },
>                 new Stage { Name = "阶段 6 项目实战", Progress = 100 },
>                 new Stage { Name = "阶段 7 性能优化与部署", Progress = 80 }
>             };
>             SummaryText.Text = "已完成 6.8 / 7 个阶段";
>             StatusText.Text = "综合成果：已能独立开发带实时曲线、PLC 通信与日志记录的上位机程序";
>         }
>     }
>
>     // 阶段数据模型：实现 INotifyPropertyChanged 供进度条绑定更新
>     public class Stage : INotifyPropertyChanged
>     {
>         public string Name { get; set; }
>
>         private int _progress;
>         public int Progress
>         {
>             get => _progress;
>             set
>             {
>                 _progress = value;
>                 Raise();
>             }
>         }
>
>         public event PropertyChangedEventHandler PropertyChanged;
>         private void Raise([CallerMemberName] string name = null) =>
>             PropertyChanged?.Invoke(this, new PropertyChangedEventArgs(name));
>     }
> }
> ```

> [!scene] 适用场景
> ✅ 零基础转行/入行上位机开发的系统学习规划
> ✅ 在职工程师查漏补缺、明确下一步学什么
> ✅ 团队新人培训的路径安排
> ✅ 以"能交付完整上位机项目"为目标的长期学习
> ❌ 已有完整项目经验的开发者（按需挑阶段深入，不必从头走）
> ❌ 只想快速做一个简单工具的短期需求（直接看 `工控看板模板项目` 更快）

> [!pitfall] 常见踩坑
> 坑 1：**跳级学习，地基不稳** → 现象：C# 不熟直接学通信，代码一堆低级错误 → 原因：跳过阶段 1~2 → 解决：严格按递进顺序，前阶段用 `practice` 的 Lv.1/Lv.2 快速验收后再前进
>
> 坑 2：**只学不做，眼高手低** → 现象：视频/文档刷了很多，写不出完整程序 → 原因：缺"每阶段动手产出" → 解决：每阶段至少完成一个可运行的小项目（阶段 6 必须独立完成一个完整上位机）
>
> 坑 3：**路线僵化，不按需调整** → 现象：明明只做数据采集，却花大量时间学动画 → 原因：路线图是参考不是教条 → 解决：按岗位/项目需求裁剪：只做界面就重阶段 3~4，偏通信就重阶段 5

> [!best] 最佳实践
> - 用"30% 打底 + 30% 灵魂 + 30% 实战 + 10% 部署"分配各阶段精力
> - 每阶段设"验收小项目"，完成才进入下一阶段（参考各章 `practice` 的 Lv.3/Lv.4）
> - 学习笔记持续沉淀（`博客园与-csdn` 思路），阶段间回看
> - 阶段 6 的项目要"真需求"：真实设备/模拟从站 + 日志 + 数据库，别做玩具
> - 完成 7 阶段后回到阶段 4~5，结合新版本/新技术再深化，形成"学-做-学"循环

> [!practice] 上手练习
> **Lv.1 照猫画虎**：运行本节示例，把阶段 7 的进度改成 100，观察总览与进度条
> **Lv.2 小试牛刀**：按路线图评估自己的进度，把示例中的 `Progress` 改成真实值
> **Lv.3 融会贯通**：结合 `microsoft-learn-wpf-学习路径` 给每个阶段排一个学习周计划（如 6 个月）
> **Lv.4 拆层挑战**：为阶段 6 制定一个完整上位机项目方案（需求 → 架构 → 通信 → 界面 → 测试 → 部署），并按方案完成开发验收
