# 单实例应用实现

> [!plain] 白话理解
> 你见过有人同时打开两个任务管理器吗？没有——因为任务管理器是"单实例"的，不管你双击多少次图标，始终只有一个窗口。上位机软件通常也需要这样——你不想用户不小心双击了桌面快捷方式，结果开了两个相同的采集程序，两个程序同时给 PLC 发指令，那场景想想就刺激。单实例实现的核心思路是：程序启动时先问"有没有另一个我？有的话我就把焦点给它，然后自己退出"。

> [!def] 官方定义
> 单实例应用（Single Instance Application）是指同一进程（或程序）在操作系统中只允许运行一份实例的应用程序。WPF 中通常通过 `System.Threading.Mutex`（互斥体）来实现：在程序启动时尝试创建一个命名的 Mutex，如果创建失败说明已经有同名 Mutex 存在（即程序已在运行），此时将控制权转移给已有实例后退出。

> [!origin] 由来背景
> 单实例限制并不是操作系统提供的原生能力，而是应用层自己实现的规则。Windows 系统级 Mutex 对象是内核对象，在整个系统中可以通过名称跨进程访问——两个同名 Mutex 不能同时存在。WPF 开发者利用这一特性来实现单实例检测。.NET 中还有更新的替代方案：`EventWaitHandle`、命名管道（Named Pipe）、或 UWP/Windows App SDK 的原生单实例支持。

> 本章节背景：WPF 快速入门让你快速领略 WPF 的魅力。本章节目的不是深入理解每个概念，而是建立感性认知。

> [!essentials] 核心要点
> - 使用 `new Mutex(true, "唯一名称", out bool createdNew)` 来检测——`createdNew` 为 true 表示是第一个实例
> - Mutex 的命名必须全局唯一——推荐格式：`"Global\\公司名.应用名.SingleInstance"`（注意：Windows 中反斜杠要写双反斜杠 `"Global\\\\..."`）
> - 检测到已有实例后，可以用 `FindWindow` + `SetForegroundWindow` 把已有窗口拉到前台
> - 第二个实例启动时可以"通知"已有实例——如通过命名管道传递命令行参数，实现"双击文件打开时由已有实例处理"
> - 必须保持 Mutex 引用——GC 如果回收了 Mutex 对象，锁就失效了，所以通常存为 `static readonly`

> [!example] 完整示例
> 完整的上位机单实例方案——包含 Mutex 检测 + 前台激活已有窗口。
>
> ```xml
> <!-- App.xaml -->
> <Application x:Class="HmiDemo.App"
>              xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
>              xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
>              Startup="Application_Startup">
> </Application>
> ```
>
> ```csharp
> // App.xaml.cs
> using System.Diagnostics;
> using System.Runtime.InteropServices;
> using System.Windows;
>
> namespace HmiDemo;
>
> public partial class App : Application
> {
>     // 全局唯一的名称——产品发布前改成正式名称
>     private const string AppMutexName = 
>         "Global\\MyCompany.HmiDemo.SingleInstance";
>    
>     // 必须持有 Mutex 的引用，防止被 GC 回收
>     private static Mutex? _mutex;
>
>     // Win32 API：激活已有窗口
>     [DllImport("user32.dll")]
>     private static extern bool SetForegroundWindow(IntPtr hWnd);
>    
>     [DllImport("user32.dll")]
>     private static extern bool ShowWindowAsync(IntPtr hWnd, int nCmdShow);
>    
>     [DllImport("user32.dll")]
>     private static extern bool IsIconic(IntPtr hWnd);
>    
>     private const int SW_RESTORE = 9;
>
>     private void Application_Startup(object sender, StartupEventArgs e)
>     {
>         // 尝试创建 Mutex
>         _mutex = new Mutex(true, AppMutexName, out bool isFirstInstance);
>
>         if (!isFirstInstance)
>         {
>             // 不是第一个实例——把已有实例的窗口拉到前台
>             ActivateExistingInstance();
>            
>             // 当前实例直接退出
>             Shutdown();
>             return;
>         }
>
>         // 是第一个实例——正常启动
>         var mainWindow = new MainWindow();
>         mainWindow.Show();
>     }
>
>     /// <summary>
>     /// 找到已有实例的窗口并激活它
>     /// </summary>
>     private static void ActivateExistingInstance()
>     {
>         // 通过进程名找到已有进程
>         var current = Process.GetCurrentProcess();
>         var existingProcess = Process.GetProcessesByName(current.ProcessName)
>             .FirstOrDefault(p => p.Id != current.Id);
>
>         if (existingProcess == null) return;
>        
>         IntPtr hWnd = existingProcess.MainWindowHandle;
>        
>         // 如果窗口被最小化了，先恢复它
>         if (IsIconic(hWnd))
>             ShowWindowAsync(hWnd, SW_RESTORE);
>        
>         // 把窗口拉到前台
>         SetForegroundWindow(hWnd);
>     }
>
>     protected override void OnExit(ExitEventArgs e)
>     {
>         // 释放 Mutex
>         _mutex?.Close();
>         _mutex?.Dispose();
>         base.OnExit(e);
>     }
> }
> ```
>
> 配合命令行参数的高级版——第二次启动传递参数给第一次：
>
> ```csharp
> private void Application_Startup(object sender, StartupEventArgs e)
> {
>     _mutex = new Mutex(true, AppMutexName, out bool isFirst);
>
>     if (!isFirst)
>     {
>         // 把命令行参数传给已有实例（通过命名管道或剪贴板）
>         if (e.Args.Length > 0)
>         {
>             // 简单方案：把参数写到临时文件，已有实例监听文件变化
>             File.WriteAllText(
>                 Path.Combine(Path.GetTempPath(), "HmiDemo_Args.txt"),
>                 string.Join(" ", e.Args));
>         }
>         ActivateExistingInstance();
>         Shutdown();
>         return;
>     }
>
>     var main = new MainWindow();
>    
>     // 处理命令行参数
>     if (e.Args.Contains("--minimized"))
>     {
>         main.WindowState = WindowState.Minimized;
>     }
>    
>     main.Show();
> }
> ```
>
> MainWindow 加上标题提示：
>
> ```csharp
> // MainWindow.xaml.cs
> public MainWindow()
> {
>     InitializeComponent();
>     // 标题栏显示"单实例"标识
>     Title = "HMI 监控系统 v1.0 [单实例模式]";
> }
> ```

> [!scene] 适用场景
> ✅ 上位机/HMI 软件——同一台工控机上不能有两个采集程序同时给 PLC 发指令
> ✅ 系统配置工具——配置数据不能同时被两个进程修改
> ✅ 托盘常驻程序——开机自启动后用户双击图标不应该再开一个实例
> ✅ 文件关联程序——双击 .xyz 文件打开应用时，应该由已有实例加载文件而不是新开实例
> ❌ 多窗口编辑工具（如 VS Code 允许开多个窗口）——不需要单实例限制
> ❌ 命令行工具——每次运行都是独立的作业，不需要互斥

> [!pitfall] 常见踩坑
> 坑 1：**Mutex 名称冲突** → 如果另一个软件碰巧用了相同的 Mutex 名，你的程序会检查出"已有实例"然后拒绝启动。解决方案：加上公司和产品名 `"Global\\MyCompany.MyProduct.SingleInstance"`，足够长就不怕冲突
> 
> 坑 2：**Mutex 被 GC 回收后失效** → Mutex 对象创建后如果没有被任何强引用持有，GC 会回收它，然后"伪单例"就破了。所以务必把 Mutex 存为 `static` 字段
>
> 坑 3：**FindWindow/MainWindowHandle 找不到窗口** → `Process.MainWindowHandle` 只在窗口可见时有效，如果已有实例最小化到托盘（Window 被 Hide 了），MainWindowHandle 是 `IntPtr.Zero`。解决方案：在已有实例中暴露一个命名 EventWaitHandle 来接收激活信号

> [!best] 最佳实践
> - Mutex 名称用常量定义，发布前检查是否包含项目正式名称
> - 单实例检测放在 `OnStartup` 的最前面，尽早判断，尽早退出第二个实例
> - 上位机务必做单实例——同时开两个采集进程可能导致 PLC 收到冲突指令，安全隐患极大
> - 如果程序支持"最小化到托盘"，激活已有实例时需要额外处理：Show 窗口、从托盘恢复、然后 SetForegroundWindow
> - 定期释放 Mutex 资源——在 `OnExit` 中 `_mutex?.Close()`，避免资源泄露
