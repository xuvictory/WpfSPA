# 窗口传值与数据交互

> [!plain] 白话理解
> 打开一个子窗口就像"派个下属去办事"——你得告诉他要做什么（传入参数），他办完事回来还得向你汇报结果（传出结果）。WPF 里传值的方式有好几种，就像一个公司里有正式报告（公开属性）、邮件抄送（事件）、公司大群广播（Application.Current）、以及人力资源档案（静态类）。上位机最常见的场景：主窗口打开"参数设置"子窗口、设置完成后把新的温度值和压力值传回主窗口。

> [!def] 官方定义
> 窗口传值与数据交互是指在不同 Window 实例之间传递信息和共享数据的技术机制。WPF 支持的主要方式包括：（1）通过公开属性/方法传递（构造函数注入 + 公开属性读取）；（2）通过事件/委托回调通知；（3）通过 `Application.Current` 全局单例共享数据；（4）通过静态类或服务容器；（5）通过消息机制（如 MVVM 框架中的 Messenger/EventAggregator）。

> [!origin] 由来背景
> WinForms 时代的窗口传值比较简单粗暴——直接把控件的 Modifiers 设为 Public，然后 `form2.textBox1.Text = "xxx"`。这种写法虽然方便，但破坏了封装性，后期维护困难。WPF 提倡"属性通信"而非"控件暴露"——子窗口暴露 `public string Result` 属性，主窗口读取属性值，而不是直接操作子窗口内部的 TextBox。这也是 MVVM 架构思想的雏形。

> 本章节背景：WPF 快速入门让你快速领略 WPF 的魅力。本章节目的不是深入理解每个概念，而是建立感性认知。

> [!essentials] 核心要点
> - **构造函数传参**：主窗口创建子窗口时通过构造函数把参数传入——最基本的"下发"方式
> - **公开属性传出**：子窗口定义 `public` 属性，ShowDialog 返回后主窗口读取——最基本的"回传"方式
> - **事件回调**：子窗口定义 `event`，主窗口订阅后在事件中拿到数据——适合非模态窗口的实时通知
> - **Application.Current 全局共享**：数据存在 App 类的 public 属性中，所有窗口都能读写——适合全局配置、当前用户等
> - **静态服务类**：定义一个 `static class DataService`，存放需要跨窗口访问的业务数据——比 Application.Current 更解耦

> ```csharp
> // MainWindow.xaml.cs
> using System.Windows;
>
> namespace HmiDemo;
>
> public partial class MainWindow : Window
> {
>     private PlcConfig _config = new() 
>     { 
>         IpAddress = "192.168.1.100", 
>         Port = 502, 
>         SlaveId = 1 
>     };
>
>     public MainWindow()
>     {
>         InitializeComponent();
>         RefreshDisplay();
>     }
>
>     // ========== 方式1：属性传值（ShowDialog + 公开属性） ==========
>     private void BtnProperty_Click(object sender, RoutedEventArgs e)
>     {
>         // 构造函数传入当前配置
>         var child = new ConfigWindow(_config)
>         {
>             Owner = this,
>             WindowStartupLocation = WindowStartupLocation.CenterOwner
>         };
>        
>         if (child.ShowDialog() == true) // 用户点了确认
>         {
>             _config = child.ResultConfig; // 通过公开属性读取结果
>             RefreshDisplay();
>         }
>     }
>
>     // ========== 方式2：事件回调（Show + event） ==========
>     private void BtnEvent_Click(object sender, RoutedEventArgs e)
>     {
>         var child = new ConfigWindow(_config)
>         {
>             Owner = this,
>             WindowStartupLocation = WindowStartupLocation.CenterOwner
>         };
>        
>         // 订阅子窗口的事件——每当用户修改参数就实时通知
>         child.ConfigChanged += (s, newConfig) =>
>         {
>             _config = newConfig;
>             RefreshDisplay();
>         };
>        
>         child.Show(); // 非模态——主窗口仍可操作
>     }
>
>     // ========== 方式3：Application.Current 全局共享 ==========
>     private void BtnGlobal_Click(object sender, RoutedEventArgs e)
>     {
>         // 把配置放到 App 的全局属性中
>         ((App)Application.Current).SharedPlcConfig = _config;
>        
>         var child = new GlobalConfigWindow
>         {
>             Owner = this,
>             WindowStartupLocation = WindowStartupLocation.CenterOwner
>         };
>        
>         child.Closed += (s, args) =>
>         {
>             // 子窗口关闭后，从全局属性中读回配置
>             _config = ((App)Application.Current).SharedPlcConfig;
>             RefreshDisplay();
>         };
>        
>         child.Show();
>     }
>
>     // ========== 方式4：静态服务类 ==========
>     private void BtnStaticService_Click(object sender, RoutedEventArgs e)
>     {
>         PlcConfigService.CurrentConfig = _config;
>        
>         var child = new ServiceConfigWindow
>         {
>             Owner = this,
>             WindowStartupLocation = WindowStartupLocation.CenterOwner
>         };
>        
>         child.Closed += (s, args) =>
>         {
>             _config = PlcConfigService.CurrentConfig;
>             RefreshDisplay();
>         };
>        
>         child.Show();
>     }
>
>     private void RefreshDisplay()
>     {
>         txtCurrentParams.Text = 
>             $"IP：{_config.IpAddress} | 端口：{_config.Port} | 从站ID：{_config.SlaveId}";
>     }
> }

>     public int SlaveId { get; set; } = 1;

> {
>     public static PlcConfig CurrentConfig { get; set; } = new();
> }

> 子窗口——属性传值 + 事件回调的核心实现：
>
> ```csharp
> // ConfigWindow.xaml.cs
> using System.Windows;
>
> namespace HmiDemo;
>
> public partial class ConfigWindow : Window
> {
>     // 公开属性：主窗口通过它读取结果
>     public PlcConfig ResultConfig { get; private set; }
>    
>     // 公开事件：实时通知主窗口参数变化（方式2用）
>     public event EventHandler<PlcConfig>? ConfigChanged;
>
>     public ConfigWindow(PlcConfig currentConfig)
>     {
>         InitializeComponent();
>         // 初始化字段（实际项目中应该是 TextBox 绑定）
>         ResultConfig = new PlcConfig
>         {
>             IpAddress = currentConfig.IpAddress,
>             Port = currentConfig.Port,
>             SlaveId = currentConfig.SlaveId
>         };
>     }
>
>     private void BtnApply_Click(object sender, RoutedEventArgs e)
>     {
>         // 触发事件——通知主窗口参数变化
>         ConfigChanged?.Invoke(this, ResultConfig);
>     }
>
>     private void BtnSave_Click(object sender, RoutedEventArgs e)
>     {
>         DialogResult = true;
>         Close();
>     }
>
>     private void BtnCancel_Click(object sender, RoutedEventArgs e)
>     {
>         DialogResult = false;
>         Close();
>     }
> }
> ```

> [!scene] 适用场景
> ✅ 属性传值（方式1）——参数配置对话框、文件选择器——简单、类型安全、最常用
> ✅ 事件回调（方式2）——非模态窗口需要实时反馈给主窗口（如实时预览、颜色选择器）
> ✅ Application.Current（方式3）——全局状态：登录用户、系统主题、语言设置
> ✅ 静态服务类（方式4）——解耦的业务数据服务，配合依赖注入使用时更加灵活
> ❌ 属性传值——需要实时双向同步的场景（应该用事件或数据绑定）
> ❌ Application.Current——非全局性质的数据（滥用会导致代码耦合过高）

> [!pitfall] 常见踩坑
> 坑 1：**ShowDialog 之后访问子窗口的控件属性** → Close() 后 TextBox 等控件可能已被 Dispose。正确做法：在 Close 之前把需要的值存入窗口级别的变量（如上面的 `ResultConfig`），ShowDialog 之后读变量而不读控件
> 
> 坑 2：**事件订阅后忘了取消订阅导致内存泄漏** → 主窗口订阅子窗口事件后，如果主窗口已关闭但子窗口还引用着，GC 无法回收。用 `child.ConfigChanged += OnConfigChanged` 后，在合适的时机（Closed 事件） `-= OnConfigChanged`
>
> 坑 3：**Application.Current 为 null 时访问全局属性** → 在后台线程或单元测试中 `(App)Application.Current` 是 null。解决方法：对 `Application.Current` 先判空，或使用 `?.` 操作符

> [!best] 最佳实践
> - **默认选择**：ShowDialog + 公开属性——覆盖80%的传值需求，简单可靠
> - **实时反馈**：Show + 事件回调——子窗口修改任何值时都能立即通知主窗口
> - **全局状态**：Application.Current 或静态服务类——但只在真正"全局"的数据上使用
> - 传递复杂对象时用构造函数注入 + 只读属性，避免子窗口意外修改传入对象
> - 不要直接暴露控件的 internal 字段——用属性封装，遵循"告诉而非询问"原则
