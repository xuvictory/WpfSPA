# 异步通信与高并发

> [!plain] 白话理解
> 上位机面对大量设备/大量消息时，最大的敌人是"阻塞"：网络读卡住了，UI 卡死；轮询排队，数据越积越多。异步就是把"等"交给系统，让程序在等待期间继续干活。本文把 async/await、并发集合、线程池这些工具讲清楚，并演示一个"多设备并发轮询 + UI 实时刷新"的高并发上位机骨架。

> [!def] 官方定义
> 异步通信指不阻塞调用线程即可发起并完成 IO 操作（网络/串口/文件）的编程模型：async/await 将异步操作挂起，线程返回线程池执行其他任务，操作完成由 I/O 完成端口回调继续。高并发涉及：Task 与 Task.WhenAll（并行发起多个请求）、SemaphoreSlim（限流并发数）、ConcurrentDictionary/Channel（线程安全数据通道）、ThreadPool（线程复用）、Dispatcher/BeginInvoke（UI 线程安全更新）。核心目标：避免阻塞 UI、充分利用 IO 等待时间、稳定支撑大量并发连接。

> [!origin] 由来背景
> 早期 .NET 网络代码常用"一连接一线程"模型，连接数一多线程数暴涨，线程切换开销拖垮性能；同步 IO 还会在等待时白白占用线程。.NET 4.5 引入 async/await 后，"异步 IO + 线程池"成为标准范式：发起操作不占线程、完成时恢复执行，单机可支撑数千并发连接。WPF 上位机也从"每设备一个线程的轮询"进化为"Task 并发 + 消息通道"的架构，在保证界面流畅的同时显著提升采集吞吐。

> [!essentials] 核心要点
> - **async/await 核心**：方法返回 Task，await 挂起不占线程，完成后续执行；UI 事件处理函数可 async void
> - **并发发起**：Task.WhenAll(tasks) 同时执行多个 IO 请求，比逐个 await 快 N 倍
> - **限流**：SemaphoreSlim(5) 控制并发上限（如同时最多 5 个轮询），防设备/服务器被打爆
> - **线程安全集合**：ConcurrentDictionary 管理连接/缓存；Channel<T> 做生产者-消费者消息队列，解耦采集与 UI
> - **UI 更新**：后台线程更新控件必须 Dispatcher.Invoke/BeginInvoke；高频更新用节流合并
> - **取消支持**：CancellationToken 贯穿 ConnectAsync/ReceiveAsync/轮询循环，窗口关闭能干净停止
> - **异常隔离**：每个 Task 内 try-catch，一个设备失败不影响其它任务
> - **避免阻塞调用**：不用 .Result/.Wait()（会死锁 UI），全程 await

> [!example] 完整示例
> **异步通信与高并发演示：async/await + Task.WhenAll 并发执行多个请求：**
>
> **MainWindow.xaml：**
> ```xml
> <Window x:Class="HmiDemo.MainWindow"
>         xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
>         xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
>         Title="异步通信与高并发" Height="480" Width="500"
>         WindowStartupLocation="CenterScreen" Background="#0D1117">
>     <StackPanel Margin="15">
>         <TextBlock Text="async/await 让耗时网络操作不阻塞 UI，Task.WhenAll 并行处理多路请求"
>                    Foreground="#58A6FF" FontWeight="Bold" TextWrapping="Wrap"/>
>         <StackPanel Orientation="Horizontal" Margin="0,8,0,0">
>             <TextBlock Text="并发数量" Foreground="#8B949E" VerticalAlignment="Center"/>
>             <TextBox x:Name="CountBox" Width="60" Text="10" Margin="8,0,0,0"
>                      Background="#161B22" Foreground="#8B949E" BorderBrush="#30363D"/>
>             <Button Content="模拟并发请求" Click="OnRunClick" Padding="10,4" Margin="12,0,0,0"
>                     Background="#238636" Foreground="White"/>
>         </StackPanel>
>         <ListBox x:Name="ResultList" Height="220" Margin="0,10,0,0" Background="#161B22"
>                  Foreground="#8B949E" BorderBrush="#30363D"/>
>         <TextBlock x:Name="StatusText" Foreground="#8B949E" Margin="0,8,0,0" TextWrapping="Wrap"/>
>     </StackPanel>
> </Window>
> ```
>
> **MainWindow.xaml.cs —— 后台代码：**
> ```csharp
> using System;
> using System.Diagnostics;
> using System.Threading.Tasks;
> using System.Windows;
>
> namespace HmiDemo
> {
>     public partial class MainWindow : Window
>     {
>         public MainWindow() => InitializeComponent();
>
>         // 演示：并发发起多个模拟网络请求，Task.WhenAll 等待全部完成
>         private async void OnRunClick(object sender, RoutedEventArgs e)
>         {
>             int count = int.Parse(CountBox.Text);
>             ResultList.Items.Clear();
>             StatusText.Text = $"正在并发发起 {count} 个请求...";
>             var sw = Stopwatch.StartNew();
>
>             // 创建 count 个并行任务，模拟每路 200ms 的网络耗时
>             Task[] tasks = new Task[count];
>             for (int i = 0; i < count; i++)
>             {
>                 int id = i;
>                 tasks[i] = Task.Run(async () =>
>                 {
>                     await Task.Delay(200); // 模拟网络往返
>                     Dispatcher.Invoke(() => ResultList.Items.Add($"请求 #{id} 完成"));
>                 });
>             }
>
>             await Task.WhenAll(tasks); // 并发等待，UI 不卡顿
>             sw.Stop();
>             StatusText.Text = $"全部完成，总耗时 {sw.ElapsedMilliseconds} ms（串行需 {count * 200} ms）";
>             StatusText.Foreground = System.Windows.Media.Brushes.LimeGreen;
>         }
>     }
> }
> ```
> 

> [!scene] 适用场景
> ✅ 上位机数据展示与交互界面开发
> ✅ 工业自动化设备状态监控系统
> ✅ 需要高效数据绑定的实时数据处理场景
> ✅ 多窗口、多页面复杂导航的企业级应用
> ❌ 简单的控制台工具程序（用控制台更省事）
> ❌ 对性能要求极端苛刻的底层驱动开发（用 C++ 更合适）

> [!pitfall] 常见踩坑
> 坑 1：**UI 线程用 .Result/.Wait() 死锁** → 同步阻塞 async 方法在 UI 上下文会死锁；必须一路 await，或改用 ConfigureAwait(false)
>
> 坑 2：**并发写共享集合抛异常** → List/Dictionary 非线程安全；改用 ConcurrentDictionary/ConcurrentQueue 或 lock
>
> 坑 3：**无限制并发 Task 打爆设备/服务器** → 不加限流几十个请求同时打一台 PLC 会超时；用 SemaphoreSlim 控制并发上限
>
> 坑 4：**窗口关闭后后台 Task 还在跑** → 关闭时用 CancellationTokenSource.Cancel() 停止所有循环任务，否则线程泄漏、资源占用
>
> 坑 5：**async void 滥用导致异常难定位** → async void 的异常会直接抛到 UI 线程；仅用于事件处理，内部 try-catch 并记录日志

> [!best] 最佳实践
> - **采集与界面解耦**：采集线程/任务把结果写入 Channel/缓存，UI 定时器消费刷新，二者互不阻塞
> - **并发数做成配置**：最大并发轮询数、超时、重试次数进配置，现场按设备数量调优
> - **按设备粒度隔离异常**：每台设备的轮询 Task 独立 try-catch，单台故障只记日志不拖垮全局
> - **关闭流程标准化**：窗口关闭 → Cancel() → Task.WhenAll(等待退出) → 释放资源，确保干净收尾
> - **压测验证设计**：上线前用模拟器压测"目标设备数 × 轮询频率"下的吞吐与内存，发现瓶颈早调整
