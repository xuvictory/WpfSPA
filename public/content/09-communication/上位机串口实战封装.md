# 上位机串口实战封装

> [!plain] 白话理解
> 直接把 SerialPort 撒在窗口里写，项目一大会失控：多个界面都要收发、都要连串口，代码重复且难维护。封装思路是：把"打开/关闭/收发/事件"收进一个独立的 SerialPortHelper 类，界面只订阅它暴露的高层事件、调用它提供的方法，永远不直接碰 SerialPort。示例展示了一个最小可用的封装类与主窗口的简洁调用，后续做 Modbus、自定协议时都在这层封装上扩展。

> [!def] 官方定义
> 串口封装指围绕 SerialPort 建立的面向业务的服务层，通常包含：连接管理（Open/Close、IsOpen、端口与参数校验）、数据出口（对外暴露事件如 event Action<string> DataReceived）、数据入口（Send/Write 方法）、可选的数据解析（把字节流转成帧或指令对象）。它让业务层只依赖"发送指令、接收数据"两个抽象能力，隔离 SerialPort 的线程模型与生命周期细节，是可测试、可替换通信底层（串口→TCP 无缝切换）的关键设计。

> [!origin] 由来背景
> 串口代码散落各处带来的痛点：换一块屏要改十几处、测试时没法模拟设备、串口异常退出后资源泄漏。项目实践中发现，把通信收敛为"一个类、一个事件、几个方法"后，界面与通信彻底解耦——设备从串口换成网络只需替换封装内部实现。这一模式在工控上位机（HMI 组态、产线监控）中广泛使用，成为上位机架构的基本功。

> [!essentials] 核心要点
> - **单一出口**：封装类只暴露"Open/Close/Send/DataReceived 事件"，界面不接触 SerialPort 细节
> - **事件上抛**：底层 DataReceived 读到的数据通过自定义事件上抛，界面只订阅高层事件
> - **线程安全由封装层负责**：封装内部做好锁与线程切换，调用方无感知
> - **参数校验前置**：Open 前检查端口名、波特率合法性，异常统一抛给上层提示
> - **可替换性**：把通信底层接口抽象出来（ISerialPortService），串口换 TCP 只换实现不换业务
> - **生命周期管理**：封装类负责 Dispose/Close，防止窗口关闭后端口泄漏
> - **调试友好**：封装内部打点日志（打开/关闭/收发字节数），排查问题不用改业务代码

> **串口封装实战演示：SerialPortHelper 封装打开/发送/接收事件，主界面简洁调用：**

> **MainWindow.xaml：**

>                  Background="#161B22" Foreground="#8B949E" BorderBrush="#30363D"/>
>         <Button Content="发送指令" Click="OnSendClick" Margin="0,8,0,0" Padding="10,4"
>                 Background="#21262D" Foreground="White"/>
>         <TextBox x:Name="LogBox" Height="150" IsReadOnly="True" TextWrapping="Wrap"
>                  Margin="0,10,0,0" Background="#161B22" Foreground="#8B949E"
>                  BorderBrush="#30363D" VerticalScrollBarVisibility="Auto"/>
>     </StackPanel>

> ```
>
> **MainWindow.xaml.cs —— 后台代码：**
> ```csharp
> using System;
> using System.IO.Ports;
> using System.Windows;
>
> namespace HmiDemo
> {
>     // 串口封装类：集中处理打开/关闭/收发，隔离底层细节
>     public class SerialPortHelper
>     {
>         private readonly SerialPort _port = new SerialPort();
>
>         public event Action<string> DataReceived; // 封装后的高层数据事件
>
>         public bool IsOpen => _port.IsOpen;
>
>         public SerialPortHelper()
>         {
>             _port.DataReceived += (s, e) =>
>                 DataReceived?.Invoke(_port.ReadExisting());
>         }
>
>         public void Open(string portName, int baudRate)
>         {
>             _port.PortName = portName;
>             _port.BaudRate = baudRate;
>             if (!_port.IsOpen) _port.Open();
>         }
>
>         public void Close()
>         {
>             if (_port.IsOpen) _port.Close();
>         }
>
>         public void Send(string data)
>         {
>             if (_port.IsOpen) _port.Write(data);
>         }
>     }
>
>     public partial class MainWindow : Window
>     {
>         private readonly SerialPortHelper _helper = new SerialPortHelper();
>
>         public MainWindow()
>         {
>             InitializeComponent();
>             foreach (string name in SerialPort.GetPortNames())
>                 PortCombo.Items.Add(name);
>             if (PortCombo.Items.Count > 0) PortCombo.SelectedIndex = 0;
>             // 只订阅封装类提供的高层事件，界面不用接触 SerialPort 细节
>             _helper.DataReceived += data =>
>                 Dispatcher.Invoke(() => LogBox.AppendText($"[接收] {data}\r\n"));
>         }
>
>         private void OnConnectClick(object sender, RoutedEventArgs e)
>         {
>             try
>             {
>                 _helper.Open(PortCombo.SelectedItem as string, 115200);
>                 LogBox.AppendText("已连接\r\n");
>             }
>             catch (Exception ex) { LogBox.AppendText("连接失败：" + ex.Message + "\r\n"); }
>         }
>
>         private void OnDisconnectClick(object sender, RoutedEventArgs e)
>         {
>             _helper.Close();
>             LogBox.AppendText("已断开\r\n");
>         }
>
>         private void OnSendClick(object sender, RoutedEventArgs e)
>         {
>             _helper.Send(SendBox.Text);
>             LogBox.AppendText($"[发送] {SendBox.Text}\r\n");
>         }
>     }
> }
> ```
> 

> [!scene] 适用场景
> ✅ 项目有多个界面/多个 ViewModel 都要收发串口数据（必须收敛到单例服务）
> ✅ 设备通信层需要单元测试（用封装接口 mock 掉真实串口）
> ✅ 同一套业务需要兼容串口/网络两种通信（抽象接口替换实现）
> ✅ 商用上位机产品（HMI 组态、产线监控软件）的通信基础层
> ❌ 一次性调试小工具（直接使用 SerialPort 更简单，过度设计反而累赘）
> ❌ 对性能极致敏感的场景（封装会带来微小的调度开销，可接受则无碍）

> [!pitfall] 常见踩坑
> 坑 1：**封装成静态类，状态散落在全局，测试困难** → 用实例 + 接口（如 ISerialPortService），便于注入 mock 做单元测试
>
> 坑 2：**封装只包方法不包线程模型，UI 线程照样崩** → 封装层必须自己完成 Dispatcher 切换，否则调用方在事件里更新界面还是会遇到跨线程问题
>
> 坑 3：**事件重复订阅导致一次数据多次回调** → 单例服务 + 初始化处订阅一次；或事件用弱引用模式避免内存泄漏
>
> 坑 4：**封装层吞掉所有异常，问题无法定位** → 底层异常应上抛或记录日志，不能只 catch 后静默忽略

> [!best] 最佳实践
> - **接口先行**：先定义 ISerialPortService（Open/Close/Send/DataReceived），实现类可替换，业务层面向接口编程
> - **单例或注入**：多窗口共享通信用单例服务或依赖注入，保证同一端口只有一个实例持有
> - **封装内完成线程切换**：事件上抛前已在封装层切回 UI 线程（SynchronizationContext），调用方无感
> - **可插拔协议层**：在封装上加一层 IProtocol（Encode/Decode），Modbus、自定协议可插拔
> - **异常与日志收口**：所有异常在封装层统一记录，对外只抛业务可理解的错误信息

> [!practice] 上手练习
> **Lv.1 照猫画虎**：运行示例，确认通过 SerialPortHelper 完成连接/发送/接收全流程，界面不直接接触 SerialPort
> **Lv.2 小试牛刀**：把 SerialPortHelper 改成基于接口 ISerialPortService，用 mock 实现替换后验证界面层代码无需改动
> **Lv.3 融会贯通**：在封装层之上增加 IProtocol 帧协议层（Encode/Decode），实现 Modbus RTU 读寄存器的完整封装，并接入 MVVM 的 ViewModel
