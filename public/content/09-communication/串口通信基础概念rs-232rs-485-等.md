# 串口通信基础概念（RS-232、RS-485 等）

> [!plain] 白话理解
> 串口通信就像设备之间的"对讲机"。RS-232/RS-485/RS-422 是三种最常见的电气层标准，决定信号怎么在线上传输、能传多远、能接几台设备；波特率、数据位、校验位、停止位则是收发双方约定的"说话语速和格式"。上位机用 SerialPort 打开串口时，就是在用这套参数和设备对上话。

> [!def] 官方定义
> 串口通信指按位（bit）顺序逐字节传输数据的通信方式。物理层由 RS-232/RS-485/RS-422 等标准定义电压电平、接线方式与传输距离，数据链路由 UART 控制器负责。双方约定波特率（如 9600/115200bps）、数据位（通常 8）、校验位（None/Even/Odd）、停止位（1/2）即可双向通信。RS-232 为 ±12V 单端信号、点对点、约 15m；RS-485 为差分信号、总线式最多 32 台、约 1200m、半双工；RS-422 为 4 线差分、全双工。

> [!origin] 由来背景
> 早期计算机与外部设备（电传机、调制解调器）通信，美国电子工业协会（EIA）于 1962 年发布 RS-232 标准，定义了串行通信的电气与机械接口。但它传输距离短、只能点对点，于是 1983 年推出 RS-485：用差分信号抗干扰，支持一主多从总线拓扑，迅速成为工业现场（PLC、变频器、仪表组网）的事实标准。WPF 上位机里的 SerialPort 不关心底层是 232 还是 485，只要接口电平一致即可通信。

> [!essentials] 核心要点
> - **RS-232**：单端 ±12V 电平、点对点、最远约 15m，适合短距离一对一（如仪表直连）
> - **RS-485**：差分信号、总线拓扑一主多从（最多 32 台）、最远约 1200m、半双工，工厂总线标配
> - **RS-422**：4 线差分、全双工，可同时收发，适合需要双向高速的链路
> - **波特率**：双方必须一致（9600/19200/38400/115200 常见），决定了每秒传输的比特数
> - **数据位**：通常 8；校验位 None/Even/Odd 需按设备协议约定；停止位一般为 1
> - **接线关键**：RS-232 是交叉线（TX↔RX），RS-485 是 A/B 双线并注意共地；接错线是"收不到数据"的头号原因
> - **与软件关系**：SerialPort 只关心参数一致，物理层是 232 还是 485 对代码透明

> ```csharp
> using System;
> using System.IO.Ports;
> using System.Windows;
> using System.Windows.Controls;
>
> namespace HmiDemo
> {
>     public partial class MainWindow : Window
>     {
>         private SerialPort _port;
>
>         public MainWindow()
>         {
>             InitializeComponent();
>             foreach (string name in SerialPort.GetPortNames())
>                 PortCombo.Items.Add(name);
>             if (PortCombo.Items.Count > 0) PortCombo.SelectedIndex = 0;
>         }
>
>         // 选择不同串口电气标准时给出说明
>         private void OnTypeSelected(object sender, SelectionChangedEventArgs e)
>         {
>             InfoText.Text = TypeList.SelectedIndex switch
>             {
>                 0 => "RS-232：工业现场最传统的串口，适合短距离一对一通信",
>                 1 => "RS-485：工厂总线标配，一条总线可挂 32 台设备，半双工",
>                 2 => "RS-422：全双工差分传输，适合需要同时收发的高速链路",
>                 _ => ""
>             };
>         }
>
>         private void OnOpenClick(object sender, RoutedEventArgs e)
>         {
>             try
>             {
>                 _port = new SerialPort(PortCombo.SelectedItem as string, 9600);
>                 _port.DataReceived += (s, ev) =>
>                     Dispatcher.Invoke(() => RecvBox.AppendText(_port.ReadExisting() + "\r\n"));
>                 _port.Open();
>             }
>             catch (Exception ex) { InfoText.Text = "打开失败：" + ex.Message; }
>         }
>
>         private void OnSendClick(object sender, RoutedEventArgs e)
>         {
>             if (_port == null || !_port.IsOpen) return;
>             _port.WriteLine(SendBox.Text);
>             RecvBox.AppendText($"[发送] {SendBox.Text}\r\n");
>         }
>     }
> }
> ```

> [!scene] 适用场景
> ✅ 设备距离近、一对一通信（RS-232：仪表、条码枪、老式 PLC）
> ✅ 现场多设备组网、总线轮询（RS-485：变频器、电表、传感器总线）
> ✅ 需要同时收发的高速串口链路（RS-422：伺服驱动、运动控制器）
> ✅ 短距离、低速率、对实时性要求不高的工业控制场景
> ❌ 跨车间/跨厂区远距离通信（应改用以太网、无线）
> ❌ 高速大流量数据传输（串口物理带宽有限，TCP 更合适）

> [!pitfall] 常见踩坑
> 坑 1：**RS-232 用交叉线接成直通线，收不到数据** → 232 是 TX↔RX 交叉对接；DB9 公头母头接法不同，先核对引脚定义与线序
>
> 坑 2：**RS-485 只接 A/B 两根线却不共地，数据不稳定** → 485 是差分信号但也需要参考地，长距离/多机场景必须共地或加隔离器，否则偶发乱码
>
> 坑 3：**以为 RS-485 是全双工** → 485 是半双工，同一时刻只能一方发送；需要同时收发时选 RS-422 或改用工业以太网
>
> 坑 4：**超过 32 台设备硬挂 RS-485 总线** → 标准负载 32 台，超载会导致信号衰减通信失败；需加 485 中继器或分组隔离

> [!best] 最佳实践
> - **选型先问距离与拓扑**：距离 <15m 点对点选 RS-232；多机组网、远距离选 RS-485；需全双工同时收发选 RS-422
> - **长距离必用屏蔽双绞线**：485 用屏蔽双绞线并单点接地，A/B 线不可接反
> - **总线两端加终端电阻**：RS-485 总线两端各加 120Ω 匹配电阻，抑制信号反射引起的误码
> - **波特率宁低勿高**：现场布线差时，115200 降到 9600 往往立竿见影，可靠优先于速度
> - **电平转换器要匹配**：USB 转串口芯片（CH340/FT232/CP2102）驱动一致，避免供电不足导致通信时好时坏
