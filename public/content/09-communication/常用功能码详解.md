# 常用功能码详解

> [!plain] 白话理解
> 功能码就是 Modbus 的"动词"：读线圈用 01、读离散输入用 02、读保持寄存器用 03、读输入寄存器用 04、写单个线圈用 05、写单个寄存器用 06、写多个线圈用 15、写多个寄存器用 16。上位机 90% 的工作就落在 03/04（读）和 06/16（写）上。本文把每个常用功能码的请求帧、响应帧、数据范围讲透，让你拿到设备点表就能直接组帧。

> [!def] 官方定义
> Modbus 功能码（Function Code）是报文中紧跟从站地址的 1 字节字段，决定操作类型与数据区格式。常用码定义：01 读线圈状态（0x/位操作）、02 读离散输入（1x）、03 读保持寄存器（4x，16 位/寄存器）、04 读输入寄存器（3x）、05 写单个线圈、06 写单个寄存器、15 写多个线圈、16 写多个寄存器。异常响应为"功能码 + 0x80"，随后紧跟异常码（01 非法功能、02 非法地址、03 非法数据、04 从站故障）。

> [!origin] 由来背景
> Modbus 从 Modicon 时代就定义了完整的功能码体系，以覆盖 PLC 四类数据对象：线圈（Coil，可读写位）、离散输入（Discrete Input，只读位）、输入寄存器（Input Register，只读 16 位）、保持寄存器（Holding Register，可读写 16 位）。这一划分源于 PLC 物理 I/O 与内存的天然差异，沿用至今。上位机开发只需掌握 03/04/05/06/15/16 六个码即可覆盖绝大多数设备，其它码（如诊断 08、文件记录 0x14）现场极少用到。

> [!essentials] 核心要点
> - **03 读保持寄存器**：请求=地址(2B)+数量(2B)；响应=字节数(1B)+数据(N×2B)；4x 区可读写，最常用
> - **04 读输入寄存器**：帧格式同 03，但对应 3x 区只读（如传感器测量值）
> - **01/02 读位**：请求=起始线圈(2B)+数量(2B)；响应按字节打包位，注意"低位在前"的位排列
> - **06 写单个寄存器**：请求=地址(2B)+值(2B)，响应原样回显请求帧（成功即正确）
> - **16 写多个寄存器**：请求=起始地址+数量+字节数+数据；响应=起始地址+数量
> - **异常响应**：功能码+0x80（如 0x83），后续异常码 01~04 对应非法功能/地址/数据/从站故障
> - **数量上限**：一次读寄存器最多 125 个（RTU），读写数量超限会收到 0x03 非法数据异常

> **MainWindow.xaml.cs —— 后台代码：**
> ```csharp
> using System;
> using System.Windows;
> using System.Windows.Controls;
>
> namespace HmiDemo
> {
>     public partial class MainWindow : Window
>     {
>         public MainWindow()
>         {
>             InitializeComponent();
>             CodeCombo.SelectedIndex = 0;
>         }
>
>         // 功能码选择变化时更新说明并重新生成报文
>         private void OnCodeChanged(object sender, SelectionChangedEventArgs e)
>         {
>             string[] desc =
>             {
>                 "03：读保持寄存器，返回多个 16 位寄存器值",
>                 "04：读输入寄存器，返回设备输入型寄存器值",
>                 "05：写单个线圈，FF00 置 ON，0000 置 OFF",
>                 "06：写单个寄存器，写入一个 16 位值",
>                 "15：写多个线圈，可一次控制多个开关量",
>                 "16：写多个寄存器，可一次写入多个数值"
>             };
>             DescText.Text = desc[CodeCombo.SelectedIndex];
>             OnBuildClick(null, null); // 联动重新生成
>         }
>
>         // 按所选功能码构建 RTU 请求帧
>         private void OnBuildClick(object sender, RoutedEventArgs e)
>         {
>             ushort addr = ushort.Parse(AddrBox.Text);
>             ushort val = ushort.Parse(ValueBox.Text);
>             byte[] body = CodeCombo.SelectedIndex switch
>             {
>                 // 03 读保持寄存器：地址 + 数量
>                 0 => new byte[] { 0x03, (byte)(addr >> 8), (byte)addr,
>                                   (byte)(val >> 8), (byte)val },
>                 // 04 读输入寄存器：地址 + 数量
>                 1 => new byte[] { 0x04, (byte)(addr >> 8), (byte)addr,
>                                   (byte)(val >> 8), (byte)val },
>                 // 05 写单个线圈：FF00 表示 ON
>                 2 => new byte[] { 0x05, (byte)(addr >> 8), (byte)addr,
>                                   (byte)(val == 1 ? 0xFF : 0x00), 0x00 },
>                 // 06 写单个寄存器：地址 + 值
>                 3 => new byte[] { 0x06, (byte)(addr >> 8), (byte)addr,
>                                   (byte)(val >> 8), (byte)val },
>                 // 15 写多个线圈：地址 + 数量 + 字节数 + 数据
>                 4 => new byte[] { 0x0F, (byte)(addr >> 8), (byte)addr,
>                                   (byte)(val >> 8), (byte)val, 0x01, 0x01 },
>                 // 16 写多个寄存器：地址 + 数量 + 字节数 + 2 字节数据
>                 5 => new byte[] { 0x10, (byte)(addr >> 8), (byte)addr,
>                                   (byte)(val >> 8), (byte)val, 0x02, 0x00, 0x00 },
>                 _ => Array.Empty<byte>()
>             };
>             byte[] frame = BuildRtuFrame(1, body); // 站号 1 + 报文体 + CRC
>             FrameBox.Text = BitConverter.ToString(frame);
>         }
>
>         // 组装 RTU 帧：站号 + 报文体 + CRC16
>         private byte[] BuildRtuFrame(byte slave, byte[] body)
>         {
>             byte[] frame = new byte[body.Length + 3];
>             frame[0] = slave;
>             Array.Copy(body, 0, frame, 1, body.Length);
>             ushort crc = Crc16(frame, frame.Length - 2);
>             frame[frame.Length - 2] = (byte)crc;
>             frame[frame.Length - 1] = (byte)(crc >> 8);
>             return frame;
>         }
>
>         private ushort Crc16(byte[] data, int len)
>         {
>             ushort crc = 0xFFFF;
>             for (int i = 0; i < len; i++)
>             {
>                 crc ^= data[i];
>                 for (int j = 0; j < 8; j++)
>                     crc = (crc & 1) != 0 ? (ushort)((crc >> 1) ^ 0xA001) : (ushort)(crc >> 1);
>             }
>             return crc;
>         }
>     }
> }
> ```

> [!scene] 适用场景
> ✅ 轮询 PLC 工艺参数（温度、压力、产量）→ 03/04 读寄存器
> ✅ 下发设定值（目标温度、速度、PID 参数）→ 06/16 写寄存器
> ✅ 控制继电器、指示灯、阀体开合 → 05 写单个线圈 / 15 写多个线圈
> ✅ 读取按钮、行程开关等离散输入状态 → 02 读离散输入
> ✅ 需要区分"只读测量值"与"可写参数"的设备点表 → 04 vs 03
> ❌ 高速实时控制回路（功能码轮询延迟高，应走专用运动控制总线）

> [!pitfall] 常见踩坑
> 坑 1：**把 03 和 04 混用导致数据不对** → 03 读保持寄存器（4x，可写）、04 读输入寄存器（3x，只读）；点表写了 3x 就必须用 04，用 03 会报非法地址或读到别的数据
>
> 坑 2：**读取数量超过 125 上限** → 一次 03/04 最多 125 个寄存器（RTU 单帧限制），超限设备回 0x03 异常；大段数据分批读
>
> 坑 3：**响应里位数按高字节在前解析** → 01/02 读回的是打包位，位序是低位在前；逐字节拆位时先处理 bit0
>
> 坑 4：**收到 0x83 异常不解析异常码** → 异常响应也有内容（异常码 01~04），必须在代码里解析并向界面提示"非法地址/非法数据"，否则排查无头绪
>
> 坑 5：**06 写成功后误以为响应是设备回显数据** → 06 的响应就是请求回显，成功标志=帧一致；别拿它当读取结果解析

> [!best] 最佳实践
> - **用枚举定义功能码**：`enum ModbusFunction : byte { ReadHolding = 0x03, ... }`，避免魔法数字散落
> - **建立"点表→代码"映射表**：寄存器地址、功能码、数据类型、缩放系数集中在配置类，业务层按变量名取值
> - **写操作前置校验**：06/16 写入前校验数据范围与寄存器只读性，防止误写损坏工艺参数
> - **批量读按"连续性"分组**：把连续地址合并成一次 03/04 读取，不连续的分多次，减少轮询报文数
> - **异常码统计上报**：累计 01~04 异常次数供监控界面显示，快速定位"地址表错"还是"设备故障"

> [!practice] 上手练习
> **Lv.1 照猫画虎**：运行示例，对功能码枚举列表逐个点击，观察请求/响应帧构建结果的差异（03 vs 04、06 vs 16）
> **Lv.2 小试牛刀**：用 Modbus 从站模拟器配置几个 3x/4x 寄存器，分别用 03/04 读取，验证"地址区与功能码必须匹配"
> **Lv.3 融会贯通**：实现一个"批量读写面板"：按点表分组连续地址批量读、单点写设定值，并正确处理 0x80+ 异常码显示错误原因
