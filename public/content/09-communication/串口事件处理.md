# 串口事件处理

> [!plain] 白话理解
> SerialPort 的"事件"是串口主动通知你的三种时机：DataReceived——设备发来数据时触发，是收数据的主入口；ErrorReceived——帧错误、奇偶校验错误、溢出时触发，用于发现线路异常；PinChanged——CTS/DSR/CD/RI 等引脚电平跳变时触发，可感知对端握手状态。三个事件都在后台线程异步触发，拿到数据后要回到 UI 线程再更新界面。

> [!def] 官方定义
> SerialPort 提供三个核心事件：DataReceived（SerialDataReceivedEventArgs，有数据进入接收缓冲时触发）、ErrorReceived（SerialErrorReceivedEventArgs，发生帧错误 FrameError、奇偶校验 ParityError、接收溢出 RXOver 等时触发）、PinChanged（SerialPinChangedEventArgs，CTS/DSR/CD/RI 引脚状态变化时触发）。三者都在 System.IO.Ports 命名空间下，需先订阅再 Open() 才能收到通知。

> [!origin] 由来背景
> 早期串口程序靠"轮询"BytesToRead 判断是否有数据，要么 CPU 空转、要么延迟高、还容易漏数据。SerialPort 引入事件机制后，操作系统在串口中断处理中检测到数据到达即回调 DataReceived，程序无需忙等；同时提供 ErrorReceived 帮助开发者在噪声干扰、电平异常时第一时间发现通信故障，PinChanged 则让 Modem 类握手状态变化也能被感知。

> [!essentials] 核心要点
> - **订阅时机**：必须在 Open() 之前订阅事件，否则打开瞬间的数据会丢失
> - **DataReceived 是主通道**：有数据进缓冲即触发，事件里按 BytesToRead 读尽，避免残留数据下次重复读到
> - **ErrorReceived 三兄弟**：FrameError（帧错误）、ParityError（奇偶校验错误）、RXOver（接收溢出），多是线路噪声或波特率不匹配导致
> - **PinChanged 常用于握手**：CTS/DSR/CD/RI 电平变化，Modem 通信、流控诊断会用到
> - **线程切换**：三个事件都在后台线程触发，更新 UI 必须 Dispatcher.Invoke；也可用 SynchronizationContext
> - **退订再关闭**：关闭前先 -= 退订，防止关闭瞬间事件回调访问已关闭端口抛异常
> - **多次订阅会重复触发**：同一事件多次 += 会回调多次，初始化处订阅一次即可

> **MainWindow.xaml.cs —— 后台代码：**
> ```csharp
> using System;
> using System.IO.Ports;
> using System.Windows;
>
> namespace HmiDemo
> {
>     public partial class MainWindow : Window
>     {
>         private SerialPort _port;
>
>         public MainWindow()
>         {
>             InitializeComponent();
>             foreach (string name in SerialPort.GetPortNames())
>                 PortCombo.Items.Add(name);
>             if (PortCombo.Items.Count > 0)
>                 PortCombo.SelectedIndex = 0;
>         }
>
>         private void OnOpenClick(object sender, RoutedEventArgs e)
>         {
>             try
>             {
>                 _port = new SerialPort(PortCombo.SelectedItem as string, 115200);
>                 _port.DataReceived += OnDataReceived;   // 有数据到达时触发
>                 _port.ErrorReceived += OnErrorReceived; // 帧错误/溢出等异常时触发
>                 _port.PinChanged += OnPinChanged;       // CD/CTS/DSR 等引脚变化时触发
>                 _port.Open();
>                 AppendLog("串口已打开，三个事件已订阅");
>                 StatusText.Text = "运行中";
>                 StatusText.Foreground = System.Windows.Media.Brushes.LimeGreen;
>             }
>             catch (Exception ex)
>             {
>                 StatusText.Text = "打开失败：" + ex.Message;
>                 StatusText.Foreground = System.Windows.Media.Brushes.OrangeRed;
>             }
>         }
>
>         private void OnCloseClick(object sender, RoutedEventArgs e)
>         {
>             if (_port == null) return;
>             // 取消订阅再关闭，避免关闭瞬间事件空引用
>             _port.DataReceived -= OnDataReceived;
>             _port.ErrorReceived -= OnErrorReceived;
>             _port.PinChanged -= OnPinChanged;
>             _port.Close();
>             _port.Dispose();
>             AppendLog("串口已关闭，事件已退订");
>             StatusText.Text = "已停止";
>             StatusText.Foreground = System.Windows.Media.Brushes.Gray;
>         }
>
>         private void OnSendClick(object sender, RoutedEventArgs e)
>         {
>             if (_port == null || !_port.IsOpen) return;
>             _port.WriteLine(SendBox.Text);
>             AppendLog($"[发送] {SendBox.Text}");
>         }
>
>         // DataReceived：串口有字节进入接收缓冲时触发
>         private void OnDataReceived(object sender, SerialDataReceivedEventArgs e)
>         {
>             string data = _port.ReadExisting();
>             Dispatcher.Invoke(() => AppendLog($"[DataReceived] {data}"));
>         }
>
>         // ErrorReceived：发生帧错误、奇偶校验错误、溢出时触发
>         private void OnErrorReceived(object sender, SerialErrorReceivedEventArgs e)
>         {
>             Dispatcher.Invoke(() => AppendLog($"[ErrorReceived] {e.EventType}"));
>         }
>
>         // PinChanged：CTS/CD/DSR/RI 等引脚电平变化时触发
>         private void OnPinChanged(object sender, SerialPinChangedEventArgs e)
>         {
>             Dispatcher.Invoke(() => AppendLog($"[PinChanged] {e.EventType}"));
>         }
>
>         private void AppendLog(string msg) =>
>             EventList.Items.Add($"{DateTime.Now:HH:mm:ss}  {msg}");
>     }
> }
> ```
> 

> [!scene] 适用场景
> ✅ 设备主动上报数据，上位机被动接收（条码枪、称重仪表、报警器）
> ✅ 上位机周期轮询设备，等待响应帧到达（Modbus RTU 主站）
> ✅ 实时监测串口线路质量：校验错误、帧错误计数（ErrorReceived）
> ✅ 使用流控或握手信号的 Modem、电台通信（PinChanged 感知 CTS/CD）
> ❌ 纯主动发送、不需要感知对端状态的控制（事件机制收益不大）
> ❌ 高频超大数据流（事件频繁触发，应合并批量读取并做好缓冲策略）

> [!pitfall] 常见踩坑
> 坑 1：**事件订阅在 Open() 之后，打开瞬间的数据全丢了** → 事件必须在 Open() 之前订阅，打开后设备立即回复的响应才能收到
>
> 坑 2：**DataReceived 里用 ReadExisting() 读残留，下次事件重复读** → 每次事件读尽缓冲（按 BytesToRead 循环读），或先 DiscardInBuffer() 再读
>
> 坑 3：**UI 线程直接访问控件崩溃** → 事件在后台线程触发，必须 Dispatcher.Invoke；高频数据用 BeginInvoke 异步切线程避免卡界面
>
> 坑 4：**关闭窗口后事件仍在触发，导致对象已释放异常** → 窗口关闭事件里先 -= 退订所有事件，再 Close()/Dispose() 端口

> [!best] 最佳实践
> - **初始化处统一订阅**：构造或 Initialize 阶段一次订阅，避免重复 += 造成多次回调
> - **事件处理器保持轻量**：只做读数据、入缓冲、上抛事件，重活（解析/存储）放到后台队列
> - **UI 更新用 Dispatcher.BeginInvoke**：高频数据下 BeginInvoke 异步投递不阻塞接收线程，界面更流畅
> - **关闭流程标准化**：退订事件 → Close() → Dispose()，顺序固定且写在 finally 中保证异常时也执行
> - **ErrorReceived 做统计上报**：把校验/帧错误计数暴露给监控界面，线路劣化早发现
