# 串口通信调试

> [!plain] 白话理解
> 串口调不通时，问题往往不在代码而在链路。本文的调试面板把常用调试手段集中起来：Hex 收发让你看到真实字节而不是被转义的文本；定时发送模拟周期指令；日志记录每条收发的十六进制与时间。配合"回环测试"（把 TX 与 RX 短接）能快速判断是硬件、接线还是软件问题——先自环再连设备，问题范围立刻缩小一半。

> [!def] 官方定义
> 串口调试是对串口通信链路（物理线缆、电平转换、驱动、参数配置、协议实现）逐层排查的过程。核心工具能力：十六进制收发（规避文本编码干扰）、定时发送（模拟周期性报文）、接收日志（带时间戳记录字节与长度）。常用辅助手段：回环头（短接 TX/RX，验证本机收发通路）、虚拟串口对（如 com0com/VSPD，无硬件时模拟对端）、逻辑分析仪或示波器（物理层信号验证）。本文给出一个 WPF 调试面板的完整实现。

> [!origin] 由来背景
> 上位机联调设备时，最头疼的是"代码看着没问题但就是收不到数据"——可能是线没接对、电平不匹配、波特率不一致，也可能是协议字节数不对。早期只能靠串口助手逐个试参数，效率极低。把 Hex 收发、定时发送、日志记录集成到上位机里，等于把"调试工具"嵌入"产品"：既能复现问题，又能录下现场报文让研发远程分析，逐渐成为工业上位机的标配功能。

> [!essentials] 核心要点
> - **回环优先**：TX 短接 RX 自环发送，能收到自己发的字节=本机串口通路正常，先排除软件问题
> - **Hex 收发是关键**：文本模式会被编码转换掩盖字节真相，Hex 模式才能核对协议字节是否一致
> - **波特率/校验位排查**：乱码优先查波特率，间歇性错误优先查校验位与数据位配置
> - **定时发送模拟周期报文**：用 DispatcherTimer 定时下发，复现"上位机周期轮询"场景
> - **日志要带时间戳与方向**：`[发送]/[接收]` + 十六进制 + 时间，现场排障的第一手证据
> - **虚拟串口对模拟对端**：无硬件时用 com0com 等工具建 COM 对，配合自写回环程序联调协议
> - **工具不止一种**：串口助手、Wireshark（USB 串口抓包）、逻辑分析仪按需选用

> **MainWindow.xaml.cs —— 后台代码：**
> ```csharp
> using System;
> using System.IO.Ports;
> using System.Linq;
> using System.Windows;
> using System.Windows.Threading;
>
> namespace HmiDemo
> {
>     public partial class MainWindow : Window
>     {
>         private SerialPort _port;
>         private DispatcherTimer _timer; // 定时发送用的时钟
>
>         public MainWindow()
>         {
>             InitializeComponent();
>             foreach (string name in SerialPort.GetPortNames())
>                 PortCombo.Items.Add(name);
>             if (PortCombo.Items.Count > 0) PortCombo.SelectedIndex = 0;
>             foreach (var b in new[] { "9600", "19200", "38400", "115200" })
>                 BaudCombo.Items.Add(b);
>             BaudCombo.SelectedIndex = 3;
>             _timer = new DispatcherTimer { Interval = TimeSpan.FromSeconds(1) };
>             _timer.Tick += (s, e) => OnSendClick(null, null); // 每 1 秒自动发送一次
>         }
>
>         private void OnOpenClick(object sender, RoutedEventArgs e)
>         {
>             try
>             {
>                 _port = new SerialPort(PortCombo.SelectedItem as string,
>                                        int.Parse(BaudCombo.SelectedItem as string));
>                 _port.DataReceived += OnDataReceived;
>                 _port.Open();
>                 AppendLog("串口已打开：" + _port.PortName);
>             }
>             catch (Exception ex) { AppendLog("打开失败：" + ex.Message); }
>         }
>
>         private void OnCloseClick(object sender, RoutedEventArgs e)
>         {
>             _timer.Stop();
>             _port?.Close();
>             AppendLog("串口已关闭");
>         }
>
>         // 把 "01 03 00 00" 这样的字符串解析为字节数组
>         private byte[] ParseHex(string text) =>
>             text.Split(new[] { ' ', ',', '-' }, StringSplitOptions.RemoveEmptyEntries)
>                 .Select(t => Convert.ToByte(t, 16)).ToArray();
>
>         private void OnSendClick(object sender, RoutedEventArgs e)
>         {
>             if (_port == null || !_port.IsOpen) return;
>             try
>             {
>                 byte[] bytes = ParseHex(SendBox.Text);
>                 _port.Write(bytes, 0, bytes.Length);
>                 AppendLog($"[发送] {BitConverter.ToString(bytes)}");
>                 if (TimerCheck.IsChecked == true) _timer.Start();
>                 else _timer.Stop();
>             }
>             catch (Exception ex) { AppendLog("发送失败：" + ex.Message); }
>         }
>
>         private void OnDataReceived(object sender, SerialDataReceivedEventArgs e)
>         {
>             int n = _port.BytesToRead;
>             byte[] data = new byte[n];
>             _port.Read(data, 0, n);
>             Dispatcher.Invoke(() =>
>             {
>                 RecvBox.AppendText(BitConverter.ToString(data) + "\r\n");
>                 AppendLog($"[接收] {data.Length} 字节");
>             });
>         }
>
>         private void AppendLog(string msg) =>
>             LogList.Items.Add($"{DateTime.Now:HH:mm:ss}  {msg}");
>     }
> }
> ```

> [!scene] 适用场景
> ✅ 现场联调：设备没反应、收不到数据、收到乱码时的第一步排查
> ✅ 无硬件时的协议联调：虚拟串口对 + 自写模拟设备回环
> ✅ 交付后远程排障：让现场人员用调试面板录制报文日志回传
> ✅ 验证新接设备协议：先手动 Hex 收发确认指令格式，再写正式代码
> ❌ 需要自动化回归测试的长期测试（应写脚本或测试用例而非手动点按钮）
> ❌ 物理层信号问题排查（需示波器/逻辑分析仪，软件层面看不到电平）

> [!pitfall] 常见踩坑
> 坑 1：**用文本模式收发导致"看着不对"** → 文本模式会做字符编码转换，调试协议务必切 Hex 模式，按字节核对
>
> 坑 2：**忘记回环测试直接连设备，问题定位困难** → 先自环验证本机通路，再连设备；一步到位连设备出问题难以区分是软件、线缆还是设备
>
> 坑 3：**定时发送的 Timer 在串口未打开时仍触发** → 发送前检查 _port.IsOpen，Timer 在 Close 后要 Stop，否则狂报异常
>
> 坑 4：**Hex 输入非法字符（如 "GG"）直接崩** → ParseHex 用 Convert.ToByte 会抛异常，需 try-catch 或先做格式校验并给出提示

> [!best] 最佳实践
> - **调试面板常驻产品**：正式上位机保留隐藏调试入口，现场问题能当场复现抓日志
> - **日志分级**：通信日志与业务日志分开，避免刷屏掩盖关键信息；错误日志必须完整记录原始字节
> - **记录设备参数快照**：打开串口时把端口名/波特率/校验位写入日志，换参数后能追溯现场配置
> - **回环测试前置化**：联调前先自环验证，把"硬件/软件问题"的二分法固化进调试流程
> - **导出报文功能**：日志支持导出文本/CSV，方便回传研发分析异常时序

> [!practice] 上手练习
> **Lv.1 照猫画虎**：运行调试面板，用回环头发送 `01 03 00 00 00 02`，确认能收到一模一样的字节
> **Lv.2 小试牛刀**：给调试面板增加"日志导出"按钮（保存为 txt/CSV），并增加清空接收区功能
> **Lv.3 融会贯通**：用虚拟串口对 + 自写模拟设备（按 Modbus RTU 应答），在调试面板中完成一轮完整的"读寄存器"联调，验证协议字节完全一致
