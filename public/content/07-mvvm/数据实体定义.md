# 数据实体定义

> [!plain] 白话理解
> 设备台账是什么？就是"设备清单"。实体定义就是把清单里的每一行变成一个 C# 类：设备编号、名称、功率、状态。这个类**只装数据、不做任何事**——它不知道自己会被显示在表格里，也不管状态是绿色还是红色。
> 为什么要单独定义实体而不是用 `Dictionary` 或散装变量？因为有了类型，编译器帮你检查"功率"不能赋给"名称"；列表绑定、序列化、数据库映射都有了明确依据。**实体是 Model 层的地基，地基不牢，上层绑定、验证、持久化全都会歪。**

> [!def] 官方定义
> 数据实体（Entity）是业务领域中的对象模型，通常对应数据库表、PLC 寄存器表或协议报文结构。在 MVVM 的 Model 层，实体是**纯数据容器（POCO，Plain Old CLR Object）**：只包含属性与轻量业务方法（如换算、判断），不实现 `INotifyPropertyChanged`、不引用 UI 命名空间。
> 常见形态：
> - **POCO 实体**：`public class DeviceEntity { public string DeviceId { get; set; } ... }`
> - **记录（record）**：C# 9+ 用 `record DeviceEntity(...)`，自带值相等性，适合不可变数据传输
> - **ORM 实体**：配合 EF Core / Dapper 映射数据库表
> 参考：https://learn.microsoft.com/zh-cn/dotnet/architecture/microservices/microservice-ddd-cqrs-patterns/

> [!origin] 由来背景
> 面向对象时代早期，"实体"概念从领域建模而来：把现实业务（设备、订单、用户）抽象成对象，让代码说人话。但桌面开发长期习惯"界面驱动一切"——把设备信息塞进 DataTable 或界面变量，程序一重启就丢、换个界面就没法复用。WPF 数据绑定出现后，界面需要"可绑定的属性来源"，于是实体作为**数据层与界面层的中间契约**被正式固化：Entity 定义"有什么数据"，ViewModel 定义"界面怎么用这些数据"。ORM（EF Core 等）兴起后，实体还承担了数据库表映射的职责，成为从数据库到界面的统一载体。

> [!essentials] 核心要点
> - **属性类型即契约**：`double Power` 与 `string Power` 决定了表格排序、校验规则、数据库列类型，定义时就要想清楚
> - **实体不进 UI 依赖**：不引用 `System.Windows`、不实现 INPC；界面刷新由 ViewModel 的包装属性负责
> - **集合实体用 `ObservableCollection<T>` 展示**：实体集合绑定 `ItemsSource`，增删自动刷新（见示例）
> - **命名即文档**：`DeviceId`/`DeviceName` 一目了然，避免 `A1`、`d` 之类无意义缩写
> - **实体可以带纯业务方法**：如 `IsOverTemperature(max)` 判断是否超温——"关于数据的规则"属于 Model，不属于 ViewModel

> [!example] 完整示例
> **数据实体定义演示：Model 层定义设备实体（POCO，只存数据），列表绑定到 ObservableCollection 展示设备台账，新增按钮向集合添加实体：**
>
> **MainWindow.xaml：**
> ```xml
> <Window x:Class="HmiDemo.MainWindow"
>         xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
>         xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
>         Title="数据实体定义" Height="400" Width="460"
>         WindowStartupLocation="CenterScreen" Background="#0D1117">
>     <DockPanel Margin="15">
>         <TextBlock DockPanel.Dock="Top" Text="设备台账（Model 层实体）" Foreground="#58A6FF"
>                    FontSize="16" FontWeight="Bold" Margin="0,0,0,10"/>
>         <Button DockPanel.Dock="Bottom" Content="新增设备" Command="{Binding AddCommand}"
>                 Padding="8" Background="#21262D" Foreground="White"
>                 HorizontalAlignment="Left" Margin="0,10,0,0"/>
>         <!-- ItemsSource 绑定实体集合，每行展示实体的各属性 -->
>         <DataGrid ItemsSource="{Binding Devices}" AutoGenerateColumns="False"
>                   Background="#161B22" Foreground="White" BorderBrush="#21262D"
>                   HeadersVisibility="Column" GridLinesVisibility="None">
>             <DataGrid.Columns>
>                 <DataGridTextColumn Header="设备编号" Binding="{Binding DeviceId}" Width="100"/>
>                 <DataGridTextColumn Header="设备名称" Binding="{Binding Name}" Width="*"/>
>                 <DataGridTextColumn Header="装机功率(kW)" Binding="{Binding Power}" Width="110"/>
>                 <DataGridTextColumn Header="状态" Binding="{Binding Status}" Width="80"/>
>             </DataGrid.Columns>
>         </DataGrid>
>     </DockPanel>
> </Window>
> ```
>
> **MainWindow.xaml.cs —— 实体定义与 ViewModel：**
> ```csharp
> using System;
> using System.Collections.ObjectModel;
> using System.ComponentModel;
> using System.Windows;
> using System.Windows.Input;
>
> namespace HmiDemo
> {
>     // ── Model 层：设备实体，纯数据容器，可对应数据库表 ──
>     public class DeviceEntity
>     {
>         public string DeviceId { get; set; }   // 设备编号
>         public string Name { get; set; }       // 设备名称
>         public double Power { get; set; }      // 装机功率
>         public string Status { get; set; }     // 运行状态
>     }
>
>     public class MainViewModel : INotifyPropertyChanged
>     {
>         // ObservableCollection：集合变化时界面自动刷新
>         public ObservableCollection<DeviceEntity> Devices { get; } =
>             new ObservableCollection<DeviceEntity>();
>
>         public ICommand AddCommand { get; }
>
>         public MainViewModel()
>         {
>             // 初始台账数据（实际项目从 Repository / 数据库读取）
>             Devices.Add(new DeviceEntity { DeviceId = "DEV-001", Name = "空压机", Power = 22, Status = "运行" });
>             Devices.Add(new DeviceEntity { DeviceId = "DEV-002", Name = "注塑机", Power = 45, Status = "停机" });
>             AddCommand = new RelayCommand(AddDevice);
>         }
>
>         private void AddDevice()
>         {
>             var count = Devices.Count + 1;
>             Devices.Add(new DeviceEntity
>             {
>                 DeviceId = "DEV-" + count.ToString("000"),
>                 Name = "新增设备-" + count,
>                 Power = 7.5,
>                 Status = "待机"
>             });
>         }
>
>         public event PropertyChangedEventHandler PropertyChanged;
>     }
>
>     public class RelayCommand : ICommand
>     {
>         private readonly Action _execute;
>         public RelayCommand(Action execute) => _execute = execute;
>         public bool CanExecute(object parameter) => true;
>         public void Execute(object parameter) => _execute();
>         public event EventHandler CanExecuteChanged;
>     }
>
>     public partial class MainWindow : Window
>     {
>         public MainWindow()
>         {
>             InitializeComponent();
>             DataContext = new MainViewModel();
>         }
>     }
> }
> ```
> 

> [!scene] 适用场景
> ✅ 设备台账/档案管理：每台设备一行记录，对应 `DeviceEntity`，绑定 DataGrid 展示
> ✅ 报警记录：`AlarmRecord` 实体含时间、级别、内容、确认状态，用于历史查询与列表
> ✅ 参数配置：`ProcessParam` 实体承载工艺参数，配合验证与下发（见「数据验证逻辑」）
> ✅ 采集点位表：`TagPoint` 实体描述寄存器地址、数据类型、量程，供采集引擎遍历
> ❌ 界面临时状态（选中项、过滤条件）：属于 ViewModel，不定义成实体
> ❌ 极简散数据（两个 int）：定义实体反而啰嗦，按实际复杂度取舍

> [!pitfall] 常见踩坑
> 坑 1：**实体实现 `INotifyPropertyChanged`** → 实体被序列化/复制/测试时带上大量样板且语义混乱。界面要刷新请包装在 ViewModel 或改用 `ObservableObject` 的框架实体（明确告知"这是可观察实体"）
>
> 坑 2：**属性类型用错** → `Status` 用 `string` 存"运行/停机"，排序和判断全靠字符串比较，改个叫法全局炸。用枚举（`DeviceStatus.Running`）配合转换器显示文本
>
> 坑 3：**实体里塞界面字段** → 加 `IsSelected`、`RowColor` 之类属性，实体开始依赖界面，复用性归零。这些状态放 ViewModel 包装类
>
> 坑 4：**集合用 `List<T>` 直接绑定** → 增删后界面不刷新。绑定集合必须用 `ObservableCollection<T>`（或实现 INotifyCollectionChanged）

> [!best] 最佳实践
> - 主键统一命名 `Id`/`DeviceId`，数据库、DTO、实体三处保持一致，减少映射心智负担
> - 用 C# 9 `record` 定义不可变 DTO/实体（`record DeviceInfo(string Id, string Name)`），值相等性对列表去重、测试断言友好
> - 实体属性加 XML 注释或中文注释说明单位与含义（`// 装机功率（kW）`），避免"20 是电流还是温度"的歧义
> - 与数据库/PLC 地址强关联的字段（寄存器地址、字节序）集中在实体顶部，附注释便于现场排查
> - 实体放独立目录 `Models/`，与 ViewModel/View 分开放置（见「项目结构与目录规划」）

> [!practice] 上手练习
> **Lv.1 照猫画虎**：运行示例，向设备列表添加一台设备，观察 DataGrid 是否立即出现新行（验证 ObservableCollection 的集合通知）
> **Lv.2 小试牛刀**：给 `DeviceEntity` 增加 `Power`（double，装机功率 kW）与 `PowerText` 格式化属性，并加入 DataGrid 展示
> **Lv.3 融会贯通**：把 `DeviceStatus` 从 `string` 改为枚举，用 `[ValueConversion]` 转换器把枚举显示为中文，体会类型带来的安全
> **Lv.4 挑战**：新增 `TagPoint` 实体（地址、数据类型、量程），写一个静态方法 `Parse()` 从 PLC 报文字节解析实体，验证 Model 层不依赖界面即可测试
