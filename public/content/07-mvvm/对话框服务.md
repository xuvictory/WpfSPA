# 对话框服务

> [!plain] 白话理解
> 车间中控台要提醒操作工确认"是否停机"，不会自己跑去车间喊话，而是通过**统一的广播系统**。对话框服务就是这个"广播系统"：ViewModel 只需要对服务说"帮我问一下'确定停机吗'"——它返回"是"还是"否"，**ViewModel 完全不关心弹窗长什么样、怎么显示的**。
> 不这样做会怎样？直接在 ViewModel 里写 `MessageBox.Show(...)`，界面逻辑就渗进了业务代码：单元测试一跑就弹窗卡住，换一种弹窗样式（比如改成右上角通知）要翻遍所有 ViewModel。封装成服务后，业务代码保持纯净，测试时还能换成"自动点确定"的假服务。

> [!def] 官方定义
> 对话框服务（`IDialogService`）是 MVVM 中**将"消息提示、确认、文件选择等窗口交互"从 ViewModel 中剥离的抽象层**。WPF 原生静态方法 `MessageBox.Show()` 强依赖 View 且难以测试；服务封装后 ViewModel 只依赖接口，例如 `bool Confirm(string title, string message)`。
> 复杂对话框（自定义 View + ViewModel、带返回值）在 Prism 中由框架级 `IDialogService.ShowDialog(...)` + `IDialogAware` 接口支撑（注册对话框窗口，参数通过 `DialogParameters` 传递，结果通过 `DialogResult` 回调）。文件对话框（`OpenFileDialog`/`SaveFileDialog`）同样建议封装进服务。
> 官方文档：https://learn.microsoft.com/zh-cn/dotnet/desktop/wpf/windows/how-to-open-message-box ；Prism：https://prismlibrary.github.io/docs/wpf/Dialog-Service.html

> [!origin] 由来背景
> MVVM 模式强调"ViewModel 不依赖 View"，但早期示例里 `MessageBox.Show` 常被直接写进 ViewModel 方法——这成了 MVVM 纯净度最常被违反的地方。单元测试一执行到弹窗代码就**挂起等待用户点击**，CI 无法通过。
> 社区由此提出"服务化"解法：把弹窗封装为 `IDialogService` 接口，测试注入返回固定结果的假实现。Prism 4.x 起把 `IDialogService` 正式纳入框架，支持自定义对话框注册与参数传递；上位机场景中"停机确认""参数修改确认"等高频交互让对话框服务成为标配服务。

> [!essentials] 核心要点
> - **接口化**：ViewModel 只依赖 `IDialogService`（`ShowMessage`/`Confirm`），不引用 `MessageBox`、不 new 任何 Window
> - **返回结果驱动逻辑**：`Confirm` 返回 `bool`，ViewModel 据"是/否"决定后续流程
> - **测试替身**：注入 `FakeDialogService`（固定返回 Yes）即可单元测试，不弹真实窗口
> - **文件对话框同样封装**：`OpenFileDialog`/`SaveFileDialog` 也要藏进服务接口
> - **复杂对话框**：自定义 View+VM 用 `IDialogAware` 模式（Prism），参数与结果显式传递
> - **单一职责**：对话框服务只负责"弹窗交互"，不含业务逻辑

> [!example] 完整示例
> **对话框服务演示：把 MessageBox 封装成 IDialogService 注入 ViewModel。ViewModel 不再直接依赖界面弹窗，测试时可以换成假对话框自动点击：**
>
> **MainWindow.xaml：**
> ```xml
> <Window x:Class="HmiDemo.MainWindow"
>         xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
>         xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
>         Title="对话框服务" Height="340" Width="420"
>         WindowStartupLocation="CenterScreen" Background="#0D1117">
>     <StackPanel Margin="20">
>         <TextBlock Text="停机确认（对话框服务）" Foreground="#58A6FF"
>                    FontSize="16" FontWeight="Bold"/>
>         <TextBlock Text="设备名称" Foreground="#8B949E" Margin="0,15,0,4"/>
>         <TextBlock Text="{Binding DeviceName}" Foreground="White" FontSize="20" FontWeight="Bold"/>
>         <TextBlock Text="当前状态" Foreground="#8B949E" Margin="0,12,0,4"/>
>         <TextBlock Text="{Binding Status}" Foreground="#238636" FontSize="18"/>
>         <Button Content="执行停机操作" Command="{Binding StopCommand}" Padding="8"
>                 Margin="0,15,0,0" Background="#DA3633" Foreground="White"
>                 HorizontalAlignment="Left"/>
>         <TextBlock Text="{Binding ResultText}" Foreground="#8B949E" Margin="0,10,0,0"
>                    TextWrapping="Wrap"/>
>     </StackPanel>
> </Window>
> ```
>
> **MainWindow.xaml.cs —— IDialogService 与注入：**
> ```csharp
> using System;
> using System.ComponentModel;
> using System.Windows;
> using System.Windows.Input;
>
> namespace HmiDemo
> {
>     // 对话框服务接口：定义弹窗能力（消息提示 / 确认）
>     public interface IDialogService
>     {
>         void ShowMessage(string title, string message);
>         bool Confirm(string title, string message);
>     }
>
>     // WPF 实现：内部使用 MessageBox（ViewModel 不直接触碰它）
>     public class MessageBoxDialogService : IDialogService
>     {
>         public void ShowMessage(string title, string message) =>
>             MessageBox.Show(message, title, MessageBoxButton.OK,
>                 MessageBoxImage.Information);
>
>         public bool Confirm(string title, string message) =>
>             MessageBox.Show(message, title, MessageBoxButton.YesNo,
>                 MessageBoxImage.Question) == MessageBoxResult.Yes;
>     }
>
>     public class MainViewModel : INotifyPropertyChanged
>     {
>         private readonly IDialogService _dialogs;
>         private string _status = "运行中";
>         private string _resultText;
>
>         public MainViewModel(IDialogService dialogs) => _dialogs = dialogs;
>
>         public string DeviceName { get; } = "空压机 #2";
>         public string Status { get; private set; }
>         public string ResultText { get; private set; }
>         public ICommand StopCommand { get; }
>
>         public MainViewModel Init()
>         {
>             StopCommand = new RelayCommand(Stop);
>             return this;
>         }
>
>         private void Stop()
>         {
>             // 通过服务弹确认框，而不是直接 MessageBox.Show（便于测试替换）
>             if (_dialogs.Confirm("停机确认", "确定要停止 " + DeviceName + " 吗？"))
>             {
>                 Status = "已停机";
>                 _dialogs.ShowMessage("提示", DeviceName + " 已安全停止");
>                 OnPropertyChanged(nameof(Status));
>             }
>             ResultText = "刚才通过 IDialogService 完成了一次确认交互";
>             OnPropertyChanged(nameof(ResultText));
>         }
>
>         public event PropertyChangedEventHandler PropertyChanged;
>         private void OnPropertyChanged(string name) =>
>             PropertyChanged?.Invoke(this, new PropertyChangedEventArgs(name));
>     }
>
>     public class RelayCommand : ICommand
>     {
>         private readonly Action _execute;
>         public RelayCommand(Action execute) => _execute = execute;
>         public bool CanExecute(object parameter) => true;
>         public void Execute(object parameter) => _execute();
>         public event EventHandler CanExecuteChanged;
>     }
>
>     public partial class MainWindow : Window
>     {
>         public MainWindow()
>         {
>             InitializeComponent();
>             DataContext = new MainViewModel(new MessageBoxDialogService()).Init();
>         }
>     }
> }
> ```

> [!scene] 适用场景
> ✅ **破坏性操作确认**：停机、覆盖配方、删除数据——先 `Confirm` 再执行
> ✅ **操作结果提示**：下发成功/失败、保存完成等信息反馈
> ✅ **文件交互**：导入导出配方时的文件选择对话框
> ✅ **需要单元测试的交互逻辑**：注入假对话框服务，覆盖"确认/取消"两条分支
> ❌ 只有一两个 `MessageBox` 的小工具：直接 `Show` 更直接，封装是过度设计
> ❌ **复杂表单对话框**（多字段输入、联动校验）：应使用独立 Window + ViewModel（或 Prism `IDialogAware`），服务只做入口与结果回传

> [!pitfall] 常见踩坑
> 坑 1：**ViewModel 里直接 `MessageBox.Show`** → 现象：单元测试跑到弹窗处挂起，CI 卡死；原因：ViewModel 强依赖 View 的静态方法，违反 MVVM 分层；解决：全部弹窗封装进 `IDialogService`，测试注入假实现
>
> 坑 2：**对话框里做耗时操作** → 现象：点"确定"后界面长时间无响应；原因：`ShowDialog` 模态等待期间，业务代码又同步阻塞 UI；解决：耗时逻辑放对话框关闭之后（拿到返回结果再执行），或放到后台线程
>
> 坑 3：**忽略 `Confirm` 返回值** → 现象：用户点了"否"，破坏性操作照样执行；原因：没判断返回结果就继续；解决：破坏性操作严格 `if (_dialogs.Confirm(...))` 才执行，把"确认"当作安全闸门

> [!best] 最佳实践
> - **接口放 Infrastructure**：`IDialogService` 定义在公共层，VM 只引用接口，实现（MessageBox/自研）在 UI 层
> - **返回值必须消费**：`Confirm` 的 `bool` 一定要参与流程判断，杜绝"弹了窗等于确认了"的错觉
> - **文案统一管理**：对话框标题、按钮文案集中定义（常量/资源文件），避免散落魔法字符串
> - **测试双分支**：`FakeDialogService` 分别返回 Yes/No 跑两遍单测，覆盖确认与取消两条路径
> - **复杂对话框用 `IDialogAware`**（Prism）：注册对话框、`DialogParameters` 传参、`RequestClose` 回传结果，别把复杂弹窗逻辑硬塞进服务类

> [!practice] 上手练习
> **Lv.1 照猫画虎**：运行示例，点"执行停机操作"，分别点"是"和"否"，观察 `Status` 的变化（只有点是才会变"已停机"）
> **Lv.2 小试牛刀**：新增"删除配方"按钮：`Confirm` 确认后 `ShowMessage` 提示结果，并记录一次状态变化
> **Lv.3 融会贯通**：写 `FakeDialogService`（`Confirm` 固定返回 `true`/`false` 由属性控制），注入后验证 `Stop()` 两条路径都能被测试覆盖
> **Lv.4 拆层挑战**：用自定义 Window + ViewModel 实现一个"输入参数"对话框（如设置目标温度），`IDialogService` 增加 `T Ask<T>(...)` 泛型方法，返回输入值
