# 日志服务集成

> [!plain] 白话理解
> 日志服务就是程序的"黑匣子"：**程序运行中发生了什么，出问题时按时间线回放**。车间现场没有调试器，设备通信失败、数据异常、操作员误操作——没有日志，只能靠人肉回忆；有了日志，几点几分下了什么配方、PLC 回没回、报了什么错，一目了然。
> 不这样做会怎样？程序崩溃了，界面上连个提示都没有，维护人员到场只能重启设备重试。而把日志服务注入到每个 ViewModel，任何关键动作都留下记录，排查问题的时间从几小时降到几分钟。

> [!def] 官方定义
> 日志服务在 .NET 中对应 **`Microsoft.Extensions.Logging`** 抽象，核心类型是泛型接口 `ILogger<T>`（`T` 为使用日志的类），提供分级方法：`LogTrace/LogDebug/LogInformation/LogWarning/LogError/LogCritical`。
> 日志记录最终由 **Provider** 落地：控制台（`AddConsole`）、文件（`AddFile`，常见配合 Serilog/NLog）、数据库等。日志框架（如 Serilog）通过 `Log.Logger` + 配置（输出模板、按天滚动文件）统一控制。WPF 中常用 `LoggerFactory` 创建 `ILogger<T>` 并经 DI 注入。
> 官方文档：https://learn.microsoft.com/zh-cn/dotnet/core/extensions/logging

> [!origin] 由来背景
> 早期 WPF 项目的"日志"五花八门：`MessageBox` 弹错误、`Console.WriteLine` 到调试器、手写 `File.AppendAllText`——没有统一级别、没有时间格式、生产环境无法配置。2017 年 .NET Core 推出 `Microsoft.Extensions.Logging`，把**级别 + Provider + 配置**标准化；随后 Serilog、NLog 提供结构化日志与文件滚动。
> 上位机场景是日志价值最突出的地方之一：设备 7×24 小时运行，故障往往在深夜发生，现场没有开发人员，**日志几乎是唯一的事故现场**。因此"日志服务集成"成为 MVVM 工程化项目的标配，通常与配置服务一起在启动时装配好。

> [!essentials] 核心要点
> - **级别分级**：Trace/Debug（调试）、Information（日常）、Warning（可恢复异常）、Error（业务错误）、Critical（致命）
> - **注入 `ILogger<T>`**：`T` 用当前类，日志里自动带类别名，便于筛选
> - **参数化消息**：`LogInformation("PLC {Ip} 连接失败", ip)` 用占位符而非字符串拼接，支持结构化检索
> - **全局异常捕获**：`DispatcherUnhandledException` 与 `TaskScheduler.UnobservedTaskException` 统一记 Error，防止静默崩溃
> - **Provider 决定去向**：开发用控制台，生产用按天滚动文件（Serilog `RollingFile`）
> - **级别可配置**：日志开关与级别由配置文件控制，现场可调详细程度

> [!example] 完整示例
> **日志服务集成演示：日志服务（ILogger）注入 ViewModel，每次下发配方都会记录一条日志并实时显示在界面上，方便追溯操作记录：**
>
> **MainWindow.xaml：**
> ```xml
> <Window x:Class="HmiDemo.MainWindow"
>         xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
>         xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
>         Title="日志服务集成" Height="400" Width="460"
>         WindowStartupLocation="CenterScreen" Background="#0D1117">
>     <DockPanel Margin="15">
>         <TextBlock DockPanel.Dock="Top" Text="配方下发与日志（ILogger 注入）" Foreground="#58A6FF"
>                    FontSize="16" FontWeight="Bold" Margin="0,0,0,10"/>
>         <StackPanel DockPanel.Dock="Bottom" Orientation="Horizontal" Margin="0,10,0,0">
>             <Button Content="下发配方" Command="{Binding DownloadCommand}" Padding="8"
>                     Background="#21262D" Foreground="White"/>
>             <TextBlock Text="{Binding LogCountText}" Foreground="#8B949E"
>                        VerticalAlignment="Center" Margin="12,0,0,0"/>
>         </StackPanel>
>         <!-- 日志列表由 ObservableCollection 驱动，新日志自动出现 -->
>         <ListBox ItemsSource="{Binding LogEntries}" Background="#161B22"
>                  Foreground="#8B949E" BorderBrush="#21262D" FontFamily="Consolas"
>                  FontSize="13"/>
>     </DockPanel>
> </Window>
> ```
>
> **MainWindow.xaml.cs —— 日志服务与注入：**
> ```csharp
> using System;
> using System.Collections.ObjectModel;
> using System.ComponentModel;
> using System.Windows;
> using System.Windows.Input;
>
> namespace HmiDemo
> {
>     // 日志服务接口：记录操作/报警等日志
>     public interface ILogger
>     {
>         void Log(string level, string message);
>         ObservableCollection<string> Entries { get; }
>     }
>
>     // 实现：内存列表存储 + 打印（生产环境写入文件/数据库/日志框架）
>     public class MemoryLogger : ILogger
>     {
>         public ObservableCollection<string> Entries { get; } =
>             new ObservableCollection<string>();
>
>         public void Log(string level, string message)
>         {
>             var line = string.Format("[{0}] [{1}] {2}",
>                 DateTime.Now.ToString("HH:mm:ss"), level, message);
>             Entries.Add(line);
>         }
>     }
>
>     public class MainViewModel : INotifyPropertyChanged
>     {
>         private readonly ILogger _logger;
>         private string _logCountText = "日志 0 条";
>
>         public MainViewModel(ILogger logger) => _logger = logger;
>
>         public ObservableCollection<string> LogEntries => _logger.Entries;
>         public string LogCountText { get; private set; }
>         public ICommand DownloadCommand { get; }
>
>         public MainViewModel Init()
>         {
>             DownloadCommand = new RelayCommand(Download);
>             _logger.Log("INFO", "系统启动，日志服务就绪");
>             UpdateCount();
>             return this;
>         }
>
>         private void Download()
>         {
>             _logger.Log("INFO", "下发配方【配方B-标准】至 PLC");
>             UpdateCount();
>         }
>
>         private void UpdateCount()
>         {
>             LogCountText = "日志 " + LogEntries.Count + " 条";
>             OnPropertyChanged(nameof(LogCountText));
>         }
>
>         public event PropertyChangedEventHandler PropertyChanged;
>         private void OnPropertyChanged(string name) =>
>             PropertyChanged?.Invoke(this, new PropertyChangedEventArgs(name));
>     }
>
>     public class RelayCommand : ICommand
>     {
>         private readonly Action _execute;
>         public RelayCommand(Action execute) => _execute = execute;
>         public bool CanExecute(object parameter) => true;
>         public void Execute(object parameter) => _execute();
>         public event EventHandler CanExecuteChanged;
>     }
>
>     public partial class MainWindow : Window
>     {
>         public MainWindow()
>         {
>             InitializeComponent();
>             DataContext = new MainViewModel(new MemoryLogger()).Init();
>         }
>     }
> }
> ```

> [!scene] 适用场景
> ✅ **现场排障**：设备通信失败、数据异常，需要事后按时间线定位第一现场
> ✅ **操作审计**：谁在什么时间下发了什么配方、改了什么参数（合规与追溯）
> ✅ **后台任务跟踪**：定时采集、配方下发、数据上传等后台操作留痕
> ✅ **生产状态监控**：周期性记录关键状态（在线率、温度曲线），辅助分析
> ❌ **性能敏感的高频循环**：每秒上千次的采集循环里直接打日志会拖垮程序——应节流、采样或只在关键节点打
> ❌ 日志内容含**密码等敏感信息**又未脱敏：日志文件本身也要当敏感资产管理

> [!pitfall] 常见踩坑
> 坑 1：**高频打日志卡死 UI** → 现象：采集循环里每秒写日志，界面明显卡顿；原因：日志写入（文件 IO）阻塞了 UI 线程，或日志量爆炸；解决：日志写放后台线程/异步，高频关键路径只记汇总或采样；控制台日志用 `AddConsole` 之外的生产配置
>
> 坑 2：**日志没有时间戳和级别** → 现象：排障时看不出先后顺序与严重程度；原因：手写字符串拼接、格式随意；解决：统一输出模板 `[时间][级别][类别] 消息`，用日志框架自带模板，禁止散装字符串
>
> 坑 3：**全局异常未接住** → 现象：程序静默崩溃，重启后日志一片空白；原因：UI 线程异常（`DispatcherUnhandledException`）和 Task 异常（`UnobservedTaskException`）没挂处理器；解决：`App` 启动时注册两个全局异常处理器，统一 `LogError` 并可选弹窗/重启

> [!best] 最佳实践
> - **注入 `ILogger<T>` 而非静态日志类**：保持可测试性，测试时注入内存实现断言日志内容
> - **结构化参数化消息**：`LogWarning("PLC {Ip} 响应超时", ip)`，便于按字段检索，不字符串拼接
> - **全局异常双保险**：`DispatcherUnhandledException` + `TaskScheduler.UnobservedTaskException` 都挂上
> - **生产落盘按天滚动**：Serilog/NLog 配置 `RollingFile`（如 `logs/log-20260817.txt`），防止单文件无限膨胀
> - **级别由配置驱动**：`Logging:LogLevel` 放配置文件，现场可按需调详细程度，不用改代码
> - **敏感信息脱敏**：日志前过滤密码、令牌，或打码显示

> [!practice] 上手练习
> **Lv.1 照猫画虎**：运行示例，点"下发配方"看日志行实时追加、计数变化；把 `MemoryLogger.Log` 里的模板加一个 `[级别]` 再跑一次
> **Lv.2 小试牛刀**：给 `ILogger` 增加 `LogError` 用法：模拟一次"下发失败"（随机数大于 5 视为失败），失败时记 `ERROR` 级日志
> **Lv.3 融会贯通**：用 Serilog 替换 `MemoryLogger`：`LoggerFactory` + Serilog 文件 Provider，日志写入 `logs/` 按天滚动文件，并在界面下方增加"打开日志目录"按钮
> **Lv.4 拆层挑战**：实现全局异常捕获：`App` 里注册 `DispatcherUnhandledException` 与 `UnobservedTaskException`，主动抛一个 Task 异常验证日志能记到 `ERROR`，并把日志级别控制接到配置文件
