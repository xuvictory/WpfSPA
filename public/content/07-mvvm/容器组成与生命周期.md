# 容器组成与生命周期

> [!plain] 白话理解
> 仓库管理员（容器）手里有一张"物料清单"：哪个服务该用哪个实例、用多久、坏了谁负责回收。它有两本账：**单例账**——像公用的扳手，全车间只有一把，谁借都是同一把；**瞬时账**——像一次性手套，每次要都发新的，用完即弃。
> 容器组成与生命周期的价值在于**把"创建、共享、释放"三件事从业务代码里拿掉**：通信服务这类"只允许一个实例、退出时还要关串口"的对象，交给容器管成单例；ViewModel 这类"每次打开窗口都要新的"对象，注册成瞬时。这样业务类只关心"用"，不关心"什么时候建、什么时候销毁"。

> [!def] 官方定义
> 依赖注入容器（IoC Container / DI Container）是一个**负责实例化与组装对象的库**，其组成包含三部分：**注册表**（服务 → 创建方式/生命周期的映射，如 `IServiceCollection`）、**解析器**（按类型返回实例，如 `IServiceProvider.GetService<T>()`）、**释放管理器**（跟踪 `IDisposable` 实例并在容器销毁时统一释放）。
> 生命周期（Lifetime）是容器控制实例存活时长的策略，`Microsoft.Extensions.DependencyInjection` 提供三种：**Singleton**（单例，容器存活期间只有一个实例）、**Scoped**（作用域，每个作用域一个实例）、**Transient**（瞬时，每次解析都新建）。
> 官方文档：https://learn.microsoft.com/zh-cn/dotnet/core/extensions/dependency-injection-usage

> [!origin] 由来背景
> 依赖注入思想提出后（2004 年，Martin Fowler），社区很快意识到"手动组装"在大型应用里同样痛苦：几十个服务互相依赖，构造参数层层传递，谁创建、谁释放全凭自觉。于是出现了第一批**自动组装工具**：2003 年前后的 Spring（Java）带来"容器"概念；.NET 生态则先后出现 Autofac、Unity、Ninject、Castle Windsor 等容器。
> 2018 年起，.NET 官方在 `Microsoft.Extensions.DependencyInjection` 中内置了一套轻量容器（ASP.NET Core 默认容器），虽然功能朴素（不支持属性注入、按名称注册等高级特性），但**零第三方依赖**，很快成为 WPF 应用 + `Microsoft.Extensions.Hosting` 组合的默认选择。容器从"可选项"变成了 .NET 官方基础设施的一部分。
> 上位机场景尤其看重生命周期：串口、TCP 连接、数据库连接都是**有限且必须释放的资源**，容器的释放管理正好把"退出时关串口"这类易漏的收尾工作制度化。

> [!essentials] 核心要点
> - **注册表**：注册 = 告诉容器"这个类型怎么造、活多久"，如 `services.AddSingleton<SerialService>()`
> - **解析器**：解析 = 按类型取出实例，如 `container.Resolve<MainViewModel>()`，依赖链由容器自动完成
> - **释放管理器**：容器销毁时按创建顺序反向释放它跟踪的 `IDisposable` 对象
> - **Singleton**：全应用一个实例，适合无状态或有共享状态的通信、配置、日志服务
> - **Transient**：每次解析都新建，适合 ViewModel 这类"每窗口/每页一个"的对象
> - **Scoped**：一个作用域（如一个请求/一个窗体会话）内共享，适合数据库上下文等按会话存活的服务
> - **容器只释放它创建的实例**：如果实例是注册的委托里 `new` 出来的，归属权（ownership）归容器，由容器负责释放；自行 new 出来传给容器的，容器通常不负责

> **MainWindow.xaml.cs —— 容器与对象生命周期管理：**
> ```csharp
> using System;
> using System.Collections.Generic;
> using System.ComponentModel;
> using System.Windows;
> using System.Windows.Input;
>
> namespace HmiDemo
> {
>     // 通信服务：实现 IDisposable，容器销毁时释放串口资源
>     public class SerialService : IDisposable
>     {
>         public string State => "串口 COM3 打开中";
>         private bool _disposed;
>
>         public void Dispose()
>         {
>             if (_disposed) return;
>             _disposed = true;
>             // 生产环境：serialPort.Close();
>         }
>     }
>
>     // 容器：注册表（类型→工厂） + 单例缓存 + 释放管理
>     public class Container : IDisposable
>     {
>         private readonly Dictionary<Type, Func<object>> _factories =
>             new Dictionary<Type, Func<object>>();
>         private readonly Dictionary<Type, object> _singletons =
>             new Dictionary<Type, object>();
>         private readonly List<IDisposable> _tracked = new List<IDisposable>();
>
>         public void RegisterSingleton<T>(Func<object> factory)
>         {
>             _factories[typeof(T)] = () =>
>             {
>                 if (!_singletons.TryGetValue(typeof(T), out var obj))
>                 {
>                     obj = factory();
>                     _singletons[typeof(T)] = obj;
>                     if (obj is IDisposable d) _tracked.Add(d);
>                 }
>                 return obj;
>             };
>         }
>
>         public void RegisterTransient<T>(Func<object> factory) =>
>             _factories[typeof(T)] = factory;
>
>         public T Resolve<T>() => (T)_factories[typeof(T)]();
>
>         // 应用退出时调用：释放所有被容器跟踪的单例对象
>         public void Dispose()
>         {
>             foreach (var d in _tracked) d.Dispose();
>             _tracked.Clear();
>             _singletons.Clear();
>         }
>     }
>
>     public class MainViewModel : INotifyPropertyChanged
>     {
>         private readonly SerialService _serial;
>         private int _createdCount;
>
>         public MainViewModel(SerialService serial) => _serial = serial;
>
>         public string ServiceState => _serial.State;
>         public string ContainerNote => "单例服务由容器统一释放（Dispose 时关闭串口）；" +
>                                        "ViewModel 为瞬时对象，创建后不再跟踪。";
>         public string VmCreatedText { get; private set; } = "已创建 1 个 ViewModel";
>         public ICommand NewVmCommand { get; }
>
>         public MainViewModel InitCommands()
>         {
>             NewVmCommand = new RelayCommand(() =>
>             {
>                 _createdCount++;
>                 VmCreatedText = "已创建 " + (_createdCount + 1) + " 个 ViewModel";
>                 OnPropertyChanged(nameof(VmCreatedText));
>             });
>             return this;
>         }
>
>         public event PropertyChangedEventHandler PropertyChanged;
>         private void OnPropertyChanged(string name) =>
>             PropertyChanged?.Invoke(this, new PropertyChangedEventArgs(name));
>     }
>
>     public class RelayCommand : ICommand
>     {
>         private readonly Action _execute;
>         public RelayCommand(Action execute) => _execute = execute;
>         public bool CanExecute(object parameter) => true;
>         public void Execute(object parameter) => _execute();
>         public event EventHandler CanExecuteChanged;
>     }
>
>     public partial class MainWindow : Window
>     {
>         private readonly Container _container;
>
>         public MainWindow()
>         {
>             InitializeComponent();
>             _container = new Container();
>             _container.RegisterSingleton<SerialService>(() => new SerialService());
>             _container.RegisterTransient<MainViewModel>(() =>
>                 new MainViewModel(_container.Resolve<SerialService>()).InitCommands());
>             DataContext = _container.Resolve<MainViewModel>();
>         }
>
>         protected override void OnClosed(EventArgs e)
>         {
>             _container.Dispose(); // 窗口关闭时释放容器管理的单例资源
>             base.OnClosed(e);
>         }
>     }
> }
> ```

> [!scene] 适用场景
> ✅ 需要**统一管理资源释放**的应用：串口、TCP 连接、数据库连接等 `IDisposable` 服务注册为单例，退出时由容器统一 `Dispose`
> ✅ **通信、配置、日志等全局唯一服务**：用 Singleton 保证全应用只有一个实例、共享一份状态
> ✅ **多窗口/多页面应用**：每个窗体解析各自的 ViewModel（Transient），服务层保持单例共享
> ✅ **数据库上下文按会话存活**：如 EF Core 的 `DbContext` 注册为 Scoped，一次交互一个上下文
> ❌ 小型单窗口工具：手动 `new` 加 `using` 释放更直观，容器反而引入抽象层
> ❌ 大量瞬时短命对象（如每秒创建的数据包处理器）：容器解析有开销，高频场景应直接构造

> [!pitfall] 常见踩坑
> 坑 1：**单例捕获瞬时依赖** → 现象：单例服务拿到的"瞬时服务"实际是同一个实例，状态互相污染；原因：容器默认**捕获**（captive dependency）——单例解析时创建的依赖，即使注册为瞬时也被复用；解决：单例服务只依赖单例，或改用工厂 `Func<T>` 按需获取
>
> 坑 2：**忘记释放容器** → 现象：程序退出后串口仍被占用，第二次启动报"端口被占用"；原因：容器的 `Dispose` 从未被调用，`IDisposable` 单例未被回收；解决：应用退出路径（`OnClosed`/`Application.Exit`）统一调用容器释放
>
> 坑 3：**持有容器引用到处解析** → 现象：业务类里到处 `container.Resolve<X>()`，DI 退化为"全局静态仓库"，测试难以替换；原因：把容器当服务定位器滥用；解决：只在组合根（启动处）解析，业务类一律构造函数注入

> [!best] 最佳实践
> - **组合根唯一**：容器只在 `App` 启动处创建并完成全部注册，窗口/VM 通过注入获得依赖
> - **生命周期按"共享需求"选**：共享状态用 Singleton；每次要新的用 Transient；按会话用的用 Scoped——别图省事全用 Singleton
> - **实现 `IDisposable` 且资源用完即放**：串口、网络流这类原生资源交给容器管理，业务类不要再手动 `Dispose`（避免双重释放）
> - **退出时统一释放**：在 `Application.Exit` 或主窗口 `OnClosed` 中 `Dispose` 根容器，让单例资源链式回收
> - **警惕捕获依赖**：注册时用 `Func<T>` 工厂模式应对"单例需要新实例"的场景，避免生命周期错配（见踩坑 1）
> - **明确所有权**：容器创建的实例归容器管；外部 `new` 出来传给容器的实例，由创建方负责释放

> [!practice] 上手练习
> **Lv.1 照猫画虎**：运行示例，点击"创建新的 ViewModel"看计数累加；改代码把 `SerialService` 从单例注册改成瞬时注册，观察输出与注释不符——理解两种生命周期的差异
> **Lv.2 小试牛刀**：给 `Container` 增加 `RegisterScoped<T>`（作用域：窗口内共享、窗口间不同），把通信服务改成 Scoped，开两个窗口验证各自持有不同实例
> **Lv.3 融会贯通**：让 `MainViewModel` 实现 `IDisposable`（释放订阅），容器在解析瞬时对象时也跟踪它，并在 `Dispose()` 里一并释放——体会"谁创建谁释放"
> **Lv.4 拆层挑战**：接入 `Microsoft.Extensions.DependencyInjection`（NuGet 包），用 `ServiceCollection` 完成同样的注册，验证 `GetRequiredService<T>` 的解析行为与生命周期语义一致
