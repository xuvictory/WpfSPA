# 数据验证逻辑

> [!plain] 白话理解
> 给 PLC 下发参数前，谁保证"温度上限"填的不是 999、"压力上限"不是负数？如果在按钮事件里写一堆 `if (temp < 10 || temp > 200)`，逻辑散落各处、还测不了。
> 数据验证就是把"这输入合不合理"变成一个可复用的约定：ViewModel 告诉 WPF"MaxTemp 的合法范围"，WPF 的绑定系统在用户输入时就自动标红错误、并禁止"下发"按钮。**用户输错了，界面立刻提示；逻辑写在 ViewModel 里，可以脱离界面单元测试。** 相比在按钮里逐项校验，这是"验证前置、防呆先行"的工程做法。

> [!def] 官方定义
> 数据验证（Validation）是让**非法输入无法进入业务逻辑**的机制。在 WPF 中，验证发生在绑定层：`TextBox.Text` 通过 `UpdateSourceTrigger` 在输入时把值写回绑定源，绑定引擎调用验证规则，失败则标记 `Validation.HasError` 并触发错误模板（默认红框）。
> 三种主流实现方式：
> - **`IDataErrorInfo`**（`System.ComponentModel`）：ViewModel 实现 `this[string columnName]` 索引器，按属性名返回错误文本，适合 MVVM（示例即用此方案）；
> - **`INotifyDataErrorInfo`**（`System.ComponentModel`）：支持异步验证与多错误，WPF 4.5+ 推荐；
> - **`ValidationRule`**（`System.Windows.Controls`）：在 XAML 绑定上声明规则，偏 View 侧，适合纯格式校验。
> 官方文档：https://learn.microsoft.com/zh-cn/dotnet/desktop/wpf/data/how-to-implement-binding-validation

> [!origin] 由来背景
> 桌面程序的数据校验长期是"事后主义"：用户点确定，后台代码从头到尾 `if` 一遍，报错再弹 MessageBox。WinForms 时代微软提供了 `ErrorProvider` 控件，但它需要手工关联每个控件，与业务逻辑纠缠。WPF 时代数据绑定成为主通道后，微软顺势把验证"内置"进绑定管道：`ValidationRule`、`IDataErrorInfo`、`INotifyDataErrorInfo` 依次演进，让"输入→校验→提示→拦截"成为绑定的标准环节。这一演进与 MVVM 天然合拍——验证逻辑写在 ViewModel 里，界面只负责呈现错误，测试者可以直接调用索引器断言错误文本。

> [!essentials] 核心要点
> - **验证点绑定**：XAML 用 `ValidatesOnDataErrors=True`（或 `ValidatesOnExceptions=True`）开启验证，配合 `UpdateSourceTrigger=PropertyChanged` 实现输入即校验
> - **IDataErrorInfo 两个成员**：`Error`（整表级错误，常返回空串）+ `this[string]` 索引器（按属性名返回错误文本，无错返回空串）
> - **双保险**：验证错误时命令 `CanExecute` 同步返回 false 禁用按钮，防止绕过界面直接执行非法下发
> - **错误提示不侵入业务**：ViewModel 只返回错误字符串，红框、ToolTip 等视觉由绑定错误模板呈现
> - **字符串 vs 强类型**：`TextBox.Text` 是 string，验证里先 `TryParse` 再查范围，避免类型转换异常与逻辑短路

> [!example] 完整示例
> **数据验证演示：ViewModel 实现 IDataErrorInfo 接口，参数非法时绑定自动显示红色错误提示，"下发"命令同时被 CanExecute 拦截，双保险防呆：**
>
> **MainWindow.xaml：**
> ```xml
> <Window x:Class="HmiDemo.MainWindow"
>         xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
>         xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
>         Title="数据验证逻辑" Height="360" Width="420"
>         WindowStartupLocation="CenterScreen" Background="#0D1117">
>     <StackPanel Margin="20">
>         <TextBlock Text="参数下发（带验证）" Foreground="#58A6FF" FontSize="16" FontWeight="Bold"/>
>         <TextBlock Text="温度上限（10~200）" Foreground="#8B949E" Margin="0,15,0,4"/>
>         <!-- ValidatesOnDataErrors=True 让绑定监听 IDataErrorInfo 的错误提示 -->
>         <TextBox Text="{Binding MaxTemp, UpdateSourceTrigger=PropertyChanged,
>                           ValidatesOnDataErrors=True}"
>                  Background="#161B22" Foreground="White" BorderBrush="#21262D" Padding="4"/>
>         <TextBlock Text="压力上限（1~50）" Foreground="#8B949E" Margin="0,12,0,4"/>
>         <TextBox Text="{Binding MaxPressure, UpdateSourceTrigger=PropertyChanged,
>                           ValidatesOnDataErrors=True}"
>                  Background="#161B22" Foreground="White" BorderBrush="#21262D" Padding="4"/>
>         <Button Content="下发参数" Command="{Binding SendCommand}" Padding="8"
>                 Margin="0,15,0,0" Background="#21262D" Foreground="White"
>                 HorizontalAlignment="Left"/>
>         <TextBlock Text="{Binding ResultText}" Foreground="#238636" Margin="0,10,0,0"
>                    TextWrapping="Wrap"/>
>     </StackPanel>
> </Window>
> ```
>
> **MainWindow.xaml.cs —— IDataErrorInfo 验证实现：**
> ```csharp
> using System;
> using System.ComponentModel;
> using System.Windows;
> using System.Windows.Input;
>
> namespace HmiDemo
> {
>     public class MainViewModel : INotifyPropertyChanged, IDataErrorInfo
>     {
>         private string _maxTemp = "150";
>         private string _maxPressure = "30";
>         private string _resultText;
>
>         public string MaxTemp
>         {
>             get => _maxTemp;
>             set { _maxTemp = value; OnPropertyChanged(nameof(MaxTemp)); }
>         }
>
>         public string MaxPressure
>         {
>             get => _maxPressure;
>             set { _maxPressure = value; OnPropertyChanged(nameof(MaxPressure)); }
>         }
>
>         public string ResultText { get; private set; }
>         public ICommand SendCommand { get; }
>
>         public MainViewModel()
>         {
>             SendCommand = new RelayCommand(Send, CanSend);
>         }
>
>         // IDataErrorInfo 成员 1：整表级错误（本例不使用，返回空串）
>         public string Error => string.Empty;
>
>         // IDataErrorInfo 成员 2：按属性名返回错误信息，无错误返回空串
>         public string this[string columnName]
>         {
>             get
>             {
>                 switch (columnName)
>                 {
>                     case nameof(MaxTemp):
>                         if (!double.TryParse(MaxTemp, out var t) || t < 10 || t > 200)
>                             return "温度上限须为 10~200 的数字";
>                         break;
>                     case nameof(MaxPressure):
>                         if (!double.TryParse(MaxPressure, out var p) || p < 1 || p > 50)
>                             return "压力上限须为 1~50 的数字";
>                         break;
>                 }
>                 return string.Empty;
>             }
>         }
>
>         // 有任意错误时禁止下发（与界面红框形成双保险）
>         private bool CanSend() => this["MaxTemp"] == string.Empty && this["MaxPressure"] == string.Empty;
>
>         private void Send()
>         {
>             ResultText = "已下发：温度≤" + MaxTemp + "℃，压力≤" + MaxPressure + " MPa";
>             OnPropertyChanged(nameof(ResultText));
>         }
>
>         public event PropertyChangedEventHandler PropertyChanged;
>         private void OnPropertyChanged(string name) =>
>             PropertyChanged?.Invoke(this, new PropertyChangedEventArgs(name));
>     }
>
>     public class RelayCommand : ICommand
>     {
>         private readonly Action _execute;
>         private readonly Func<bool> _canExecute;
>         public RelayCommand(Action execute, Func<bool> canExecute = null)
>         {
>             _execute = execute;
>             _canExecute = canExecute;
>         }
>         public bool CanExecute(object parameter) => _canExecute == null || _canExecute();
>         public void Execute(object parameter) => _execute();
>         public event EventHandler CanExecuteChanged;
>     }
>
>     public partial class MainWindow : Window
>     {
>         public MainWindow()
>         {
>             InitializeComponent();
>             DataContext = new MainViewModel();
>         }
>     }
> }
> ```
> 

> [!scene] 适用场景
> ✅ 参数下发界面：温度/压力/速度上下限输入，输错立即标红并禁用"下发"
> ✅ 配方管理：配方名非空、比例合计=100% 等跨字段校验（在 `Error` 或命令执行前统一校验）
> ✅ 点位配置：寄存器地址范围、数据类型合法性校验，防止配置错误导致采集异常
> ✅ 登录/表单：用户名格式、密码强度、确认密码一致性（`INotifyDataErrorInfo` 支持多错误更合适）
> ❌ 只读展示数据：无需校验，绑定的转换失败可用 `ValidatesOnExceptions` 兜底即可
> ❌ 高频实时数据（采集线程写入）：实时值来自设备不应"弹红框"，校验放在业务层用日志/报警处理

> [!pitfall] 常见踩坑
> 坑 1：**只标红不拦截** → 错误提示显示了，"下发"按钮却还能点，非法参数照样下发。验证与 `CanExecute` 必须联动，形成双保险
>
> 坑 2：**忘写 `UpdateSourceTrigger=PropertyChanged`** → 绑定默认在失去焦点时才回写源，用户边输边等提示却始终不出现，误以为验证失效
>
> 坑 3：**在 setter 里抛异常做验证** → `ValidatesOnExceptions` 依赖异常，一旦忘开标记，异常直接崩界面。业务验证优先用 `IDataErrorInfo`/`INotifyDataErrorInfo`，异常留给类型转换
>
> 坑 4：**验证逻辑与业务混在命令里** → 命令里堆 `if` 返回 MessageBox，界面弹窗又多又丑还测不了。验证放绑定层，命令只处理"已验证合法"的数据

> [!best] 最佳实践
> - 用 `INotifyDataErrorInfo` 替代 `IDataErrorInfo`：支持多错误、异步验证，CommunityToolkit.Mvvm 的 `ObservableValidator` 已封装好，直接继承即可
> - 错误文本集中在常量或资源字典（如 `ErrorMessages.MaxTempRange`），避免魔法字符串四处飘
> - 自定义错误模板：在窗口 `Resources` 里定义带 ToolTip 的红色边框样式，全局复用，比默认红框更有提示性
> - 跨字段校验（如比例合计=100%）放在 `Error` 或保存命令入口统一验证，别在索引器里查其他属性（易引发反复通知）
> - 验证方法可单独提取为 `ValidateMaxTemp(string value)` 返回错误文本，单元测试直接断言，无需起界面

> [!practice] 上手练习
> **Lv.1 照猫画虎**：运行示例，输入 999 或 abc 观察红框出现与"下发"按钮置灰；把按钮 `CanExecute` 里的验证删掉再试，体会双保险的必要性
> **Lv.2 小试牛刀**：新增"湿度下限（0~100）"字段与验证，界面同步标红提示
> **Lv.3 融会贯通**：把 `IDataErrorInfo` 换成 `INotifyDataErrorInfo`（用 `ObservableValidator`），给"压力上限"加一条异步验证——延迟 500ms 模拟查数据库上限
> **Lv.4 挑战**：写 3 条单元测试：`ValidateMaxTemp("999")` 返回错误、`("150")` 返回空、`("abc")` 返回错误，验证逻辑完全脱离界面可测
