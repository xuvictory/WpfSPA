# 配置服务

> [!plain] 白话理解
> 每台设备的参数——站点名、PLC 的 IP 地址、采集周期——就像车间里贴在设备旁的"参数卡"。**参数不能写死在程序里**：换个车间部署，IP 变了，难道要现场改代码重新编译吗？配置服务就是这张"参数卡"的读取器：程序启动时从配置文件（JSON/INI）读一遍，把参数交给界面和通信服务。
> 不这样做会怎样？参数硬编码在代码里，每换一个现场就要改源码、重新编译、重新发布；有了配置服务，现场只改配置文件、重启程序即可。这就是"配置与代码分离"的价值。

> [!def] 官方定义
> 配置服务（`IConfiguration`）是 .NET 提供的**统一配置读取抽象**。它来自 `Microsoft.Extensions.Configuration` 包，核心 API：
> - `ConfigurationBuilder`：组合多个配置源（JSON 文件、XML、环境变量、命令行参数），后添加的源**覆盖**先添加的
> - `IConfiguration.GetValue<T>(key)` / `GetSection(section)`：读取强类型值或分层配置节
> - `AddJsonFile("appsettings.json")`：从 JSON 文件加载配置，可设 `reloadOnChange: true` 监视文件变化
> - WPF 中通常把 `IConfiguration` 注册为**单例**，注入到 ViewModel 或通信服务使用
> 官方文档：https://learn.microsoft.com/zh-cn/dotnet/core/extensions/configuration

> [!origin] 由来背景
> .NET Framework 时代，桌面程序配置靠 `App.config`（XML）+ `ConfigurationManager`，读取繁琐、强类型支持差、多环境切换要靠手动改文件。2016 年 .NET Core 推出 `Microsoft.Extensions.Configuration`，带来全新的设计：**键值对扁平模型 + 分层 Section + 多源叠加 + 环境变量覆盖**，并在 ASP.NET Core 中大范围普及。
> WPF 上位机项目随后跟进：`appsettings.json` 取代 `App.config`，配置服务成为 MVVM 工程中的标准单例服务。上位机的多现场部署（每台设备 IP、采集参数不同）正是配置服务的典型受益场景。

> [!essentials] 核心要点
> - **配置与代码分离**：运行参数放配置文件，不硬编码在代码里
> - **多源叠加与覆盖**：JSON 文件为基底，环境变量/命令行可覆盖（如 `PLC__Ip` 覆盖文件里的值）
> - **强类型读取**：`GetValue<int>("PollIntervalMs")` 避免手工字符串转换
> - **Options 绑定**：`GetSection("PLC").Get<PlcOptions>()` 把配置映射为强类型对象
> - **只读单例**：配置在启动时读入、运行期只读，通常注册为 Singleton
> - **敏感信息保护**：连接串密码等放环境变量或 Secret Manager，不提交到代码库

> [!example] 完整示例
> **配置服务演示：配置服务（ConfigService）从 JSON/INI 读取站点与通信参数并注入 ViewModel，界面展示配置项。修改配置文件无需重新编译即可生效：**
>
> **MainWindow.xaml：**
> ```xml
> <Window x:Class="HmiDemo.MainWindow"
>         xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
>         xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
>         Title="配置服务" Height="360" Width="420"
>         WindowStartupLocation="CenterScreen" Background="#0D1117">
>     <StackPanel Margin="20">
>         <TextBlock Text="系统配置（来自配置服务）" Foreground="#58A6FF"
>                    FontSize="16" FontWeight="Bold"/>
>         <TextBlock Text="站点名称" Foreground="#8B949E" Margin="0,15,0,4"/>
>         <TextBlock Text="{Binding StationName}" Foreground="White" FontSize="18" FontWeight="Bold"/>
>         <TextBlock Text="PLC 地址" Foreground="#8B949E" Margin="0,12,0,4"/>
>         <TextBlock Text="{Binding PlcAddress}" Foreground="White" FontSize="18"/>
>         <TextBlock Text="采集周期" Foreground="#8B949E" Margin="0,12,0,4"/>
>         <TextBlock Text="{Binding PollInterval}" Foreground="White" FontSize="18"/>
>         <TextBlock Text="{Binding ConfigSource}" Foreground="#238636" Margin="0,12,0,0"/>
>     </StackPanel>
> </Window>
> ```
>
> **MainWindow.xaml.cs —— 配置服务注入：**
> ```csharp
> using System;
> using System.Collections.Generic;
> using System.ComponentModel;
> using System.Windows;
>
> namespace HmiDemo
> {
>     // 配置服务：封装配置读取（生产环境读取 appsettings.json / App.config）
>     public class ConfigService
>     {
>         // 模拟从配置文件读取的键值对
>         private readonly Dictionary<string, string> _items =
>             new Dictionary<string, string>(StringComparer.OrdinalIgnoreCase)
>             {
>                 { "StationName", "一号装配车间" },
>                 { "PlcAddress", "192.168.1.50:102" },
>                 { "PollInterval", "500 ms" }
>             };
>
>         public string Get(string key) => _items.TryGetValue(key, out var v) ? v : "未配置";
>     }
>
>     public class MainViewModel : INotifyPropertyChanged
>     {
>         private readonly ConfigService _config;
>
>         // 构造函数注入配置服务
>         public MainViewModel(ConfigService config) => _config = config;
>
>         public string StationName => _config.Get("StationName");
>         public string PlcAddress => _config.Get("PlcAddress");
>         public string PollInterval => _config.Get("PollInterval");
>         public string ConfigSource => "以上配置由 ConfigService 注入，修改配置即生效";
>
>         public event PropertyChangedEventHandler PropertyChanged;
>     }
>
>     public partial class MainWindow : Window
>     {
>         public MainWindow()
>         {
>             InitializeComponent();
>             DataContext = new MainViewModel(new ConfigService());
>         }
>     }
> }
> ```

> [!scene] 适用场景
> ✅ **多现场部署**：同一程序换车间只改配置文件（站点名、PLC 地址、采集周期），无需重新编译
> ✅ **通信参数现场可调**：PLC 的 IP/端口、串口号、波特率等需要运维人员直接修改
> ✅ **配方/参数集中管理**：几十个参数集中在一个文件，便于备份、导出与对比
> ✅ **环境隔离**：开发、测试、生产三套配置（`appsettings.Development.json` 覆盖），一套代码跑三套环境
> ❌ 参数永远不变、单机单环境的小工具：配置文件反而增加一层间接
> ❌ 需要**秒级热更新**参数的场景：默认 `IConfiguration` 不监视文件变化，需 `reloadOnChange: true` 或引入专门方案

> [!pitfall] 常见踩坑
> 坑 1：**key 写错，静默返回默认值** → 现象：界面显示"未配置"或默认值，程序不报错，问题难察觉；原因：配置读取找不到 key 时按默认处理，不会抛异常；解决：启动时**校验必填配置**，缺失直接抛出明确异常，fail-fast
>
> 坑 2：**改了配置不生效** → 现象：修改 `appsettings.json` 后程序仍用旧值；原因：文件没随程序复制到输出目录（`Copy to Output Directory` 未设为"如果较新则复制"），或程序在缓存旧配置；解决：确认输出目录里的配置文件被更新；需要热更新则 `AddJsonFile(..., reloadOnChange: true)`
>
> 坑 3：**类型转换异常不直观** → 现象：`GetValue<int>("PollInterval")` 抛 `InvalidOperationException`；原因：配置值写成了 `"500 ms"` 而非纯数字；解决：配置值规范化（数字只写数字，单位由代码拼接），或用 `TryGetValue` 容错

> [!best] 最佳实践
> - **强类型绑定**：用 `GetSection("PLC").Get<PlcOptions>()` 把配置映射成 `PlcOptions` 类，代替到处写字符串 key
> - **必填配置启动校验**：启动时检查关键配置项，缺失直接报错，避免运行到一半才暴露
> - **环境隔离**：开发/生产用 `appsettings.{Environment}.json` 覆盖，通过环境变量切换
> - **敏感信息不入配置库**：密码、令牌放环境变量或 Secret Manager
> - **配置服务只读单例**：注入到需要的地方，运行期不修改配置对象

> [!practice] 上手练习
> **Lv.1 照猫画虎**：运行示例，修改 `_items` 里 `PlcAddress` 的值为另一地址，运行看界面变化；把 `PollInterval` 改为 `"1000 ms"`，体会"改配置即生效"
> **Lv.2 小试牛刀**：给 `ConfigService` 增加 `int GetInt(string key)`（带默认值、失败返回默认），界面新增"采集周期（毫秒）"用数字显示
> **Lv.3 融会贯通**：把字典模拟换成真 `System.Text.Json`：项目加 `appsettings.json`（含 `StationName/PlcAddress`），`ConfigService` 启动时反序列化读取
> **Lv.4 拆层挑战**：引入 `Microsoft.Extensions.Configuration`，用 `ConfigurationBuilder` 组合 `AddJsonFile` + `AddEnvironmentVariables`，实现环境变量覆盖文件配置，并绑定 `IOptions<PlcOptions>`
