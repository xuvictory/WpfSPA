# 导航服务实现

> [!plain] 白话理解
> 车间中控看板要在"设备总览、报警记录、配方管理"几个画面之间切换——这不是开一个新窗口，而是**换掉当前显示的画面**。导航服务就是"换画面"的调度员：ViewModel 只需说"切到报警页"，服务负责把对应的页面内容换上来。
> 不这样做会怎样？用 `Visibility` 堆一堆面板、或到处 `new` 窗口，页面多了代码失控、页面状态（滚动位置、筛选条件）全部丢失。有了导航服务，页面注册后按 key 切换，状态可控、职责清晰。

> [!def] 官方定义
> 导航（Navigation）指**应用在多个页面/视图之间切换、传递参数并管理页面状态**的机制。WPF 原生方案是 `Frame` + `Page`（`Navigate(Uri)`）；MVVM 实践中更常用 **`ContentControl` + `DataTemplate` 映射**或 **Prism 区域导航**：页面 ViewModel 注册到区域，`IRegionNavigationService.NavigateAsync("Alarm", parameters)` 切换内容并触发页面 VM 的 `INavigationAware.OnNavigatedTo`。
> 导航服务的核心职责：**按标识解析页面 ViewModel → 替换当前展示内容 → 传递导航参数 → 处理返回**。
> 官方文档：https://learn.microsoft.com/zh-cn/dotnet/desktop/wpf/windows/navigation-overview ；Prism：https://prismlibrary.github.io/docs/wpf/Navigation.html

> [!origin] 由来背景
> MVVM 项目做多页面切换时，早期做法五花八门：堆 `Visibility` 控制面板显隐、每个按钮 `new` 一个窗口、`Frame` 塞满代码隐藏。痛点很快暴露：**页面状态丢失**（切走再切回来滚动位置没了）、**页面与 ViewModel 解耦难**、**传参靠全局静态变量**。
> Prism 4.x 引入 **Region（区域）+ 导航**抽象：页面注册进 `Region`，导航命令只传页面名与参数，框架负责创建/切换页面并通知生命周期。上位机看板类应用（总览/报警/配方多页轮换）正是受益者，因此"导航服务"成了 7.7 实战的关键一课。

> [!essentials] 核心要点
> - **页面注册**：导航服务维护"页面 key → 页面 ViewModel"的映射，如 `Register("Overview", new OverviewViewModel())`
> - **切换机制**：`ContentControl` 绑定 `CurrentPage`（VM 属性），换 VM 即换页面；生产可用 `DataTemplate` 完成 VM→View 自动映射
> - **参数传递**：`NavigateTo(key, parameters)`，目标页面实现 `OnNavigatedTo` 接收参数并初始化
> - **状态管理**：页面实例可缓存（切回保留状态）或每次新建（释放资源），按需选择
> - **返回导航**：维护导航历史栈，支持 `GoBack`（Prism 提供 `IRegionNavigationJournal`）
> - **与容器配合**：页面 ViewModel 由 DI 容器创建并注入依赖（见「di-在-mvvm-中的应用」）

> [!example] 完整示例
> **导航服务演示：用一个简单的导航服务在"设备总览"与"报警记录"两个页面之间切换。每个页面一个 ViewModel，导航服务负责替换当前页面（生产环境可用 Prism 的 Region/导航框架）：**
>
> **MainWindow.xaml：**
> ```xml
> <Window x:Class="HmiDemo.MainWindow"
>         xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
>         xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
>         Title="导航服务实现" Height="400" Width="460"
>         WindowStartupLocation="CenterScreen" Background="#0D1117">
>     <DockPanel Margin="15">
>         <TextBlock DockPanel.Dock="Top" Text="生产看板（导航服务切换页面）" Foreground="#58A6FF"
>                    FontSize="16" FontWeight="Bold" Margin="0,0,0,10"/>
>         <!-- 导航按钮统一绑定到 ViewModel 的 NavCommand，参数指定目标页 -->
>         <StackPanel DockPanel.Dock="Top" Orientation="Horizontal" Margin="0,0,0,12">
>             <Button Content="设备总览" Command="{Binding NavCommand}" CommandParameter="Overview"
>                     Padding="8" Background="#21262D" Foreground="White" Margin="0,0,8,0"/>
>             <Button Content="报警记录" Command="{Binding NavCommand}" CommandParameter="Alarm"
>                     Padding="8" Background="#21262D" Foreground="White"/>
>         </StackPanel>
>         <!-- ContentControl 的内容由导航服务切换 -->
>         <Border Background="#161B22" CornerRadius="6" Padding="15">
>             <ContentControl Content="{Binding CurrentPage}"/>
>         </Border>
>     </DockPanel>
> </Window>
> ```
>
> **MainWindow.xaml.cs —— 导航服务与页面 ViewModel：**
> ```csharp
> using System;
> using System.Collections.Generic;
> using System.ComponentModel;
> using System.Windows;
> using System.Windows.Input;
>
> namespace HmiDemo
> {
>     // 页面 ViewModel 基类（简单版）
>     public abstract class PageViewModel : INotifyPropertyChanged
>     {
>         public event PropertyChangedEventHandler PropertyChanged;
>         protected void OnPropertyChanged(string name) =>
>             PropertyChanged?.Invoke(this, new PropertyChangedEventArgs(name));
>     }
>
>     // 页面1：设备总览
>     public class OverviewViewModel : PageViewModel
>     {
>         public string Title { get; } = "设备总览";
>         public string Info { get; } = "当前运行设备：12 / 15";
>     }
>
>     // 页面2：报警记录
>     public class AlarmViewModel : PageViewModel
>     {
>         public string Title { get; } = "报警记录";
>         public string Info { get; } = "今日报警 3 条：E-101 电机过载、E-203 油温过高、W-5 维护提醒";
>     }
>
>     // 导航服务：维护页面字典，按 key 切换当前页
>     public class NavigationService
>     {
>         private readonly Dictionary<string, PageViewModel> _pages =
>             new Dictionary<string, PageViewModel>();
>
>         public void Register(string key, PageViewModel page) => _pages[key] = page;
>
>         // 供绑定调用：属性变化时 ContentControl 自动刷新
>         public void NavigateTo(string key, Action<PageViewModel> onChanged)
>         {
>             if (_pages.TryGetValue(key, out var page)) onChanged(page);
>         }
>     }
>
>     public class MainViewModel : INotifyPropertyChanged
>     {
>         private readonly NavigationService _nav = new NavigationService();
>         private PageViewModel _currentPage;
>
>         public PageViewModel CurrentPage
>         {
>             get => _currentPage;
>             private set { _currentPage = value; OnPropertyChanged(nameof(CurrentPage)); }
>         }
>
>         public ICommand NavCommand { get; }
>
>         public MainViewModel()
>         {
>             // 注册页面（实际项目由容器创建）
>             _nav.Register("Overview", new OverviewViewModel());
>             _nav.Register("Alarm", new AlarmViewModel());
>             NavCommand = new RelayCommand<string>(Navigate);
>             _nav.NavigateTo("Overview", p => CurrentPage = p); // 初始定位到总览页
>         }
>
>         private void Navigate(string key) => _nav.NavigateTo(key, p => CurrentPage = p);
>
>         public event PropertyChangedEventHandler PropertyChanged;
>         private void OnPropertyChanged(string name) =>
>             PropertyChanged?.Invoke(this, new PropertyChangedEventArgs(name));
>     }
>
>     public class RelayCommand<T> : ICommand
>     {
>         private readonly Action<T> _execute;
>         public RelayCommand(Action<T> execute) => _execute = execute;
>         public bool CanExecute(object parameter) => true;
>         public void Execute(object parameter) => _execute((T)parameter);
>         public event EventHandler CanExecuteChanged;
>     }
>
>     public partial class MainWindow : Window
>     {
>         public MainWindow()
>         {
>             InitializeComponent();
>             DataContext = new MainViewModel();
>         }
>     }
> }
> ```

> [!scene] 适用场景
> ✅ **看板类应用**：设备总览/报警记录/配方管理多页面切换（生产车间大屏看板）
> ✅ **主界面侧边栏/顶部 Tab 导航**：各功能页独立 ViewModel，切换即换页
> ✅ **需要传递参数的跳转**：总览页点设备 → 详情页带设备 ID（`NavigateTo("Detail", { id })`）
> ✅ **多步流程**：登录 → 主界面 → 参数设置，流程化管理页面
> ❌ 单窗口、无页面切换的小工具：导航服务是过度设计
> ❌ 只有 2 个静态页面且无参数无状态：`DataTemplate` + 属性绑定即可

> [!pitfall] 常见踩坑
> 坑 1：**切走再回来，页面状态丢失** → 现象：报警页筛选条件、滚动位置全没了；原因：每次导航都 `new` 新页面 VM；解决：需要保留状态的页面用字典缓存（单例页），或 VM 实现状态保存（切出时记录、切入时恢复）
>
> 坑 2：**ContentControl 显示类型名（字符串）** → 现象：界面显示 `HmiDemo.OverviewViewModel` 而不是页面；原因：没有把 VM 映射到对应的 View（缺 `DataTemplate`）；解决：在 `Resources` 中声明 `DataTemplate DataType="{x:Type vm:OverviewViewModel}"`，模板内放对应的 `Views/OverviewView`
>
> 坑 3：**导航 key 拼错，点了没反应** → 现象：按钮点击后页面无变化也不报错；原因：`Dictionary.TryGetValue` 找不到 key 直接跳过；解决：导航失败时记录日志或抛异常，导航 key 用**常量类**（`PageKeys.Overview`）管理，杜绝魔法字符串

> [!best] 最佳实践
> - **key 常量化**：`PageKeys.Overview`、`PageKeys.Alarm` 集中定义，避免字符串拼写错误
> - **页面 VM 由容器创建**：注册进 DI，`NavigationService` 通过容器解析页面（见「di-在-mvvm-中的应用」），页面依赖自动注入
> - **按需决定页面生命周期**：需保留状态 → 缓存实例（单例）；需释放资源 → 每次新建并在离开时 `Dispose`
> - **用 `DataTemplate` 完成 VM→View 映射**：切换只换 VM，View 自动跟着换，XAML 里不出现 `new`
> - **大项目直接上 Prism**：Region + `NavigateAsync` + `INavigationAware` + `Journal` 回退，别手写轮子

> [!practice] 上手练习
> **Lv.1 照猫画虎**：运行示例，点"设备总览/报警记录"观察 `ContentControl` 内容切换；再添加一个 `Register` 的 key 并点按钮验证
> **Lv.2 小试牛刀**：新增第三个页面"配方管理"：建 `RecipeViewModel`（含配方列表），注册 key 为 `Recipe`，加导航按钮切换过去
> **Lv.3 融会贯通**：给导航服务加参数：`NavigateTo(key, params)`，跳到报警页时传"近 1 小时"时间范围，`AlarmViewModel` 在 `OnNavigatedTo` 接收并展示（模拟筛选）
> **Lv.4 拆层挑战**：用 `DataTemplate` 完成 VM→View 自动映射（`Resources` 中声明模板指向 `OverviewView`/`AlarmView`），并实现"页面栈 + GoBack"返回导航，对比与手写字典的差异
