# 属性封装字段的技巧

> [!plain] 白话理解
> 属性封装字段，就相当于给裸数据穿了三层衣服。第一层：`get; private set;` —— 外面只能看不能改。第二层：`set` 里加验证——温度必须 ≥ -273℃（绝对零度）。第三层：计算属性——根本不需要后台字段，`=> FirstName + LastName` 直接算出来。封装的核心不是"藏起来不给看"，而是"你只能通过我允许的方式看和改"。

> [!def] 官方定义
> 属性封装是将私有字段通过属性对外暴露的面向对象实践。通过设置不同的 `get`/`set` 访问级别（如 `get; private set;`）和在访问器中添加验证逻辑，实现受控的数据访问。关键是：对外表现像字段一样简单（`obj.Name`），对内拥有方法的全部能力（验证、计算、通知）。

> [!origin] 由来背景
> C# 1.0 时期暴露数据只能写"Get 方法 + Set 方法"（如 `get_Name()`/`set_Name()`），调用繁琐。C# 2.0 引入属性，把读写合成一个语法：`obj.Name`，像字段一样简单；C# 3.0 又给了自动属性 `{ get; set; }`。属性真正的价值在于"外观是字段、内核是方法"——以后想加验证、计算、通知，不需要改任何调用方。上位机模型（传感器量程校验、MVVM 通知）遍布属性，理解封装技巧是写 WPF 界面的前提。

> [!essentials] 核心要点
> - 访问级别组合：`{ get; }` 只读、`{ get; private set; }` 对外只读、`{ get; internal set; }` 程序集内可写
> - set 内验证：非法值直接抛异常，把"写坏数据"消灭在入口
> - 计算属性：无后台字段，`=>` 表达式体，随用随算
> - 懒加载：`_cache ??= new()`，首次访问才创建，节省内存
> - MVVM 模式：set 里判断值变化 → `OnPropertyChanged(nameof(Xxx))` → 联动通知计算属性
> - 传属性名一律 `nameof(PropertyName)`，别硬编码字符串（重构才不会断）

> [!example] 完整示例
> ```csharp
> public class SensorConfig
> {
>     // 技巧1：不同访问级别的 get/set
>     public string Id { get; }                    // 只读（构造函数可设）
>     public string Name { get; private set; }     // 对外只读，对内可写
>     public bool IsCalibrated { get; internal set; } // 程序集内可设
    
>     // 技巧2：set 中加验证
>     private double _temperature;
>     public double Temperature
>     {
>         get => _temperature;
>         set
>         {
>             if (value < -273.15)  // 低于绝对零度，拒绝
>                 throw new ArgumentOutOfRangeException("温度不能低于绝对零度");
>             _temperature = value;
>         }
>     }
    
>     // 技巧3：计算属性（无后台字段）
>     public string StatusDisplay => IsCalibrated ? "✅已校准" : "⚠未校准";
    
>     // 技巧4：懒加载属性
>     private List<AlertRecord>? _alerts;
>     public List<AlertRecord> Alerts => _alerts ??= new List<AlertRecord>();
>     // ??= 首次访问时才初始化
> }

> // 上位机中 MVVM 的标准属性模式
> public class DeviceViewModel : INotifyPropertyChanged
> {
>     private double _temperature;
>     public double Temperature
>     {
>         get => _temperature;
>         set
>         {
>             if (Math.Abs(_temperature - value) < 0.01) return; // 值没变就不通知
>             _temperature = value;
>             OnPropertyChanged(nameof(Temperature));
>             OnPropertyChanged(nameof(StatusColor));  // 联动通知
>         }
>     }
    
>     public string StatusColor => Temperature > 80 ? "Red" : "Green";
    
>     public event PropertyChangedEventHandler? PropertyChanged;
>     private void OnPropertyChanged(string name) 
>         => PropertyChanged?.Invoke(this, new PropertyChangedEventArgs(name));
> }
> ```

> [!scene] 适用场景
> ✅ `get; private set;`：ID、创建时间（外部只读）
> ✅ set 验证：量程范围、端口号、IP格式
> ✅ 计算属性：显示文本、颜色、状态枚举
> ✅ `INotifyPropertyChanged`：MVVM 数据绑定

> [!pitfall] 常见踩坑
> 坑 1：**`get; private set;` 不等于不可变** → 类内部方法还是能改。
> 坑 2：**计算属性被频繁调用** → `StatusColor` 每次都重新计算。高频场景可加缓存。
> 坑 3：**`INotifyPropertyChanged` 里写错属性名** → 用 `nameof()` 而不是硬编码字符串。

> [!best] 最佳实践
> - 对外只读用 `{ get; }`，对内可变用 `{ get; private set; }`
> - 验证逻辑放在 set 里，比放在外部方法更安全
> - 多字段联动的计算属性（改了 A 触发 B 的 PropertyChanged）
> - 用 `nameof(Xxx)` 代替字符串传属性名
