# 方法重载

> [!plain] 白话理解
> 方法重载就是"同一个名字，不同套餐"——你进餐馆说"来碗面"，厨师根据你说的"大碗/小碗"、"加辣/不加辣"、"汤面/拌面"给你端不同的面。方法名一样，参数不同（个数、类型或顺序），C# 编译器根据你传入的参数自动选对的那个版本。`Console.WriteLine` 有 19 个重载——传 int、传 string、传 double，全是同一个名字。上位机中，一个 `Connect` 方法也可以有三张面孔：`Connect(string ip)`、`Connect(string ip, int port)`、`Connect(string ip, int port, int timeout)`。

> [!def] 官方定义
> 方法重载（Overload）是指在同一类（或继承层次）中定义多个**同名但参数签名不同**的方法。编译器根据调用时传入的实参类型和数量选择匹配的重载版本（编译期多态/静态多态）。要求：参数的类型/数量/顺序至少有一项不同；仅返回类型不同不算重载。

> [!origin] 由来背景
> 方法重载从 C++ 时代（1980年代）就是面向对象语言的标配。没有重载之前，C 语言里你只能写 `abs_int`、`abs_double`、`abs_long`——名字长得让人崩溃。C# 完整继承并强化了重载：配合可选参数、`params`、泛型，重载在 .NET 框架中无处不在。上位机开发最常做的重载：`SendCommand(byte[])` 发原始字节 / `SendCommand(string)` 发自描述文本命令 / `SendCommand(byte[], int timeout)` 带超时。

> [!essentials] 核心要点
> - 重载依据：参数个数、参数类型、参数顺序（`ref`/`out` 也算签名一部分）
> - 不算重载：仅返回类型不同（编译器无法区分）
> - 重载解析规则：编译器选"最匹配"的版本，有歧义时编译报错
> - 可选参数 + 重载共存时要小心歧义
> - 构造函数也可以重载

> [!example] 完整示例
> ```csharp
> public class ModbusMaster
> {
>     public string IpAddress { get; }
>     public int Port { get; }
>     public int TimeoutMs { get; }
    
>     // 重载 1：最简版
>     public bool Connect(string ip)
>         => Connect(ip, 502);
    
>     // 重载 2：指定端口
>     public bool Connect(string ip, int port)
>         => Connect(ip, port, 3000);
    
>     // 重载 3：完整版（最终实现）
>     public bool Connect(string ip, int port, int timeoutMs)
>     {
>         Console.WriteLine($"连接 {ip}:{port} 超时{timeoutMs}ms");
>         return true; // 模拟成功
>     }
    
>     // 重载：按字节数组发送
>     public bool SendCommand(byte[] command)
>     {
>         Console.WriteLine($"发送 [{string.Join(" ", command.Select(b => $"{b:X2}"))}]");
>         return true;
>     }
    
>     // 重载：按十六进制字符串发送
>     public bool SendCommand(string hexCommand)
>     {
>         byte[] bytes = Convert.FromHexString(hexCommand.Replace(" ", ""));
>         return SendCommand(bytes); // 内部调用字节版本
>     }
    
>     // 重载：带超时
>     public bool SendCommand(byte[] command, int timeoutMs)
>     {
>         Console.WriteLine($"发送（超时{timeoutMs}ms）");
>         return SendCommand(command);
>     }
> }

> // ========== 使用 ==========
> var master = new ModbusMaster();
> master.Connect("192.168.1.100");           // → Connect(string)
> master.Connect("192.168.1.100", 8080);     // → Connect(string, int)
> master.Connect("192.168.1.100", 502, 5000);// → Connect(string, int, int)

> master.SendCommand(new byte[] { 0x01, 0x03, 0x00, 0x00 });  // → byte[]
> master.SendCommand("01 03 00 00 00 04");                     // → string → byte[]
> ```

> [!scene] 适用场景
> ✅ 提供不同粒度的便捷方法（Connect/Connect+Port/Connect+Port+Timeout）
> ✅ 同一操作接受不同类型输入（字节数组 / 字符串 / Stream）
> ✅ 带默认值的参数模式（用重载替代可选参数）
> ❌ 仅有语义差异但参数签名相同 → 取不同名字

> [!pitfall] 常见踩坑
> 坑 1：**可选参数和重载的歧义** → `void M(int a, int b = 0)` + `void M(int a)`，调用 `M(5)` 两个都匹配！
> 坑 2：**`null` 导致重载歧义** → `void M(string s)` + `void M(object o)`，`M(null)` 不明确，必须加类型转换。

> [!best] 最佳实践
> - 用重载链（一个最终实现，其余调用它）避免代码重复
> - 参数多的重载放在前面（IDE 按顺序显示）
> - 不要为"语义不同但参数签名相同"的操作创建重载
