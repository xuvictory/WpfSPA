# 基类与派生类

> [!plain] 白话理解
> 继承就是"儿子遗传了爸爸的所有家当，还能自己添置新东西"。`ModbusClient` 作为基类定义了"连接"和"发送命令"的本领，`ModbusRtuClient`（RTU协议）和 `ModbusTcpClient`（TCP协议）作为子类继承了这些本领，又各自添加了协议特有的细节（CRC校验 vs TCP帧头）。你不需要为每种协议从头写连接逻辑——这就是继承的核心价值：**复用共性，扩展个性**。

> [!def] 官方定义
> 继承是面向对象编程的核心机制之一。派生类（子类）继承基类（父类）的所有非私有成员（字段、属性、方法），并可以添加新成员或重写虚成员。C# 支持单继承（一个类只能有一个直接基类），但支持多层继承。所有类隐式继承自 `System.Object`。

> [!origin] 由来背景
> 继承的概念来自生物学分类学（界门纲目科属种）的层级结构。在 C# 中，继承实现了一个强大的设计原则：**开闭原则**——对扩展开放，对修改关闭。你不需要修改 `ModbusClient` 的源码就能扩展出新的协议客户端。上位机架构中，`DeviceBase` → `PlcDevice` / `SensorDevice` / `ActuatorDevice` 这种继承层次是标准的代码组织方式。

> [!essentials] 核心要点
> - 语法：`class Child : Parent { }`（冒号表示继承）
> - `base.XXX()` 调用基类成员
> - 构造函数中 `: base(...)` 调用基类构造（基类先构造，子类后构造）
> - 子类可以**隐式转换**为基类类型：`DeviceBase d = new PlcDevice();`
> - `is` 检查类型：`if (d is PlcDevice plc) { }`
> - `as` 安全转换：`PlcDevice? plc = d as PlcDevice;`

> [!example] 完整示例
> ```csharp
> // ====== 基类 ======
> public abstract class DeviceBase
> {
>     public string Id { get; }
>     public string Name { get; protected set; }
>     public bool IsConnected { get; protected set; }
    
>     protected DeviceBase(string id, string name)
>     {
>         Id = id;
>         Name = name;
>     }
    
>     public virtual bool Connect()
>     {
>         Console.WriteLine($"[{Id}] 通用连接...");
>         IsConnected = true;
>         return true;
>     }
    
>     public virtual void Disconnect()
>     {
>         IsConnected = false;
>         Console.WriteLine($"[{Id}] 已断开");
>     }
    
>     public abstract string ReadData();
> }

> // ====== 派生类 1 ======
> public class PlcDevice : DeviceBase
> {
>     public string IpAddress { get; }
    
>     public PlcDevice(string id, string ip) : base(id, $"PLC-{id}")
>     {
>         IpAddress = ip;
>     }
    
>     public override bool Connect()
>     {
>         Console.WriteLine($"[{Id}] 通过 TCP 连接 {IpAddress}...");
>         IsConnected = true;
>         return true;
>     }
    
>     public override string ReadData() => $"[{Id}] 读取 PLC 数据...";
> }

> // ====== 派生类 2 ======
> public class SensorDevice : DeviceBase
> {
>     public double LastValue { get; private set; }
    
>     public SensorDevice(string id) : base(id, $"传感器-{id}") { }
    
>     public override string ReadData()
>     {
>         LastValue = 85.5;  // 模拟读数
>         return $"[{Id}] 温度={LastValue}℃";
>     }
> }

> // ====== 多态：基类引用操作子类 ======
> var devices = new List<DeviceBase>
> {
>     new PlcDevice("001", "192.168.1.100"),
>     new SensorDevice("TEMP-01"),
>     new SensorDevice("PRES-01")
> };

> foreach (var device in devices)
> {
>     device.Connect();
>     Console.WriteLine($"  {device.ReadData()}");
    
>     // 类型判断 + 特殊处理
>     if (device is PlcDevice plc)
>         Console.WriteLine($"  [PLC特殊] IP={plc.IpAddress}");
    
>     Console.WriteLine();
> }
> ```

> [!scene] 适用场景
> ✅ 设备类型层次：DeviceBase → PlcDevice/Sensor/Actuator
> ✅ 通信协议层次：ProtocolBase → ModbusRtu/ModbusTcp/Profinet
> ✅ UI 控件继承（WPF 自定义控件）
> ❌ 深层继承（>3层）→ 优先考虑组合而非继承

> [!pitfall] 常见踩坑
> 坑 1：**子类的构造函数忘了 `: base(...)`** → 如果基类没有无参构造，必须显式调用。
> 坑 2：**用 `new` 而不是 `override`** → 隐藏基类成员而非重写，多态行为异常。
> 坑 3：**子类中给 `base` 只读属性赋值** → base 的 `get` only 不能被赋值。

> [!best] 最佳实践
> - 继承层次不超过 3 层
> - 基类设计为 `abstract` 或提供有意义的默认实现
> - `protected` 成员用于给子类提供扩展点
> - 能用组合就别用继承（"is-a"才用继承，"has-a"用组合）
