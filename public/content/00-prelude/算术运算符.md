# 算术运算符

> [!plain] 白话理解
> 加减乘除取余——这些你小学数学就会的东西，在 C# 里多了两个"坑"和一个"神器"。两个坑：整数除法会截断小数（`5 / 2 = 2` 而不是 `2.5`），整数溢出不报错（`int.MaxValue + 1` 变成负数）。一个神器：`%` 取余运算，上位机里用它在表格上隔行变色、判断传感器采样序号的奇偶、计算环形缓冲区的索引位置。算术运算符是上位机数据处理的地基——几万行代码的项目，至少有几千行在做 `+` `-` `*` `/` `%`。

> [!def] 官方定义
> C# 的算术运算符用于执行基本数学运算，包括：
> - `+` 加法 / `-` 减法 / `*` 乘法 / `/` 除法 / `%` 取余（取模）
> - 自增 `++` / 自减 `--`（前置 vs 后置有语义差异）
> - 复合赋值：`+=` `-=` `*=` `/=` `%=`
> - 所有算术运算符对数值类型（`int`/`long`/`float`/`double`/`decimal`）均有效
> - 整数运算在 `checked` 上下文中检测溢出

> [!origin] 由来背景
> 算术运算符是所有编程语言最古老的部分。但 C# 的 `%` 运算符有个历史细节值得注意：在 C 语言中 `%` 叫"取模"（modulo），但 C# 的 `%` 实际上是"取余"（remainder），当操作数有负数时行为不同：`-5 % 3` 在 C# 中结果是 `-2`，在 Python 中是 `1`。这个差异曾让不少代码迁移项目翻车。另外，C# 的整数除法"向零截断"（`-5 / 2 = -2`）而非"向下取整"，也是新手常掉的坑。

> [!essentials] 核心要点
> - 整数 `/` 整数 = 整数（小数部分直接丢弃，不四舍五入）
> - 要小数结果，至少一个操作数是浮点：`5.0 / 2 = 2.5`
> - `%` 的结果符号跟**被除数**一致：`-5 % 3 = -2`，`5 % -3 = 2`
> - `++i`（前置）先加再用；`i++`（后置）先用再加
> - `checked` 关键字可以捕获溢出：`checked { int x = int.MaxValue + 1; }` 会抛异常
> - `double.PositiveInfinity` / `double.NaN` 来自浮点除零（`1.0 / 0.0`）

> [!example] 完整示例
> ```csharp
> // ========== 整数除法的隐藏陷阱 ==========
> int a = 5, b = 2;
> Console.WriteLine(5 / 2);        // 2 —— 不是 2.5！
> Console.WriteLine(5.0 / 2);      // 2.5 —— 有浮点数就按浮点算
> Console.WriteLine((double)5 / 2);// 2.5 —— 显式转一个

> // ========== 取余 % 的妙用 ==========
> // 1. 判断奇偶
> int sensorId = 7;
> Console.WriteLine(sensorId % 2 == 0 ? "偶数号传感器" : "奇数号传感器");

> // 2. 环形缓冲 —— 上位机数据采集的经典模式
> int bufferIndex = 0;
> for (int i = 0; i < 15; i++)
> {
>     bufferIndex = i % 8; // 永远在 0~7 之间循环
>     Console.WriteLine($"写入缓冲区位置: {bufferIndex}");
> }

> // 3. 格式化输出 —— 每 N 个换行
> for (int i = 1; i <= 20; i++)
> {
>     Console.Write($"{i,3} ");
>     if (i % 5 == 0) Console.WriteLine(); // 每5个数换行
> }

> // ========== ++i 和 i++ 的区别（在表达式中才有意义）==========
> int x = 5;
> int y = x++;  // y=5, x=6（先赋值 y，x 再加 1）
> x = 5;
> int z = ++x;  // z=6, x=6（x 先加 1，再赋值 z）
> Console.WriteLine($"x++: y={y}, ++x: z={z}");

> // ========== 溢出问题 ==========
> int max = int.MaxValue;  // 2147483647
> // int overflow = max + 1;  // 变 -2147483648，不报错！

> checked
> {
>     try
>     {
>         int safe = max;  // checked 块内检测溢出
>         // int overflow = max + 1; // 会抛 OverflowException
>     }
>     catch (OverflowException)
>     {
>         Console.WriteLine("检测到溢出！");
>     }
> }

> // ========== 上位机实战：温度补偿计算 ==========
> double rawValue = 1023;       // ADC 原始值（0~1023）
> double referenceVoltage = 5.0;
> double offset = 0.5;         // 零点偏移补偿
> double tempScale = 100.0;    // 100℃/V 传感器灵敏度

> // 浮点运算才有精确结果
> double voltage = rawValue / 1023.0 * referenceVoltage;
> double temperature = (voltage - offset) * tempScale;
> Console.WriteLine($"ADC={rawValue}, 电压={voltage:F3}V, 温度={temperature:F1}℃");
> ```

> [!scene] 适用场景
> ✅ `+` `-` `*` `/`：传感器数值换算、坐标变换、数据处理 —— 无处不在
> ✅ `%`：环形缓冲区索引、奇偶行样式（上位机表格隔行变色 `rowIndex % 2`）、定时器轮询调度
> ✅ `++/--`：循环计数器、状态机步进
> ✅ `checked`：金融/计费系统中必须开启，防止偷偷溢出导致财务错误

> [!pitfall] 常见踩坑
> 坑 1：**`3 / 2` 结果是 `1`** → 两个 int 相除得 int。解决：`3.0 / 2` 或 `(double)3 / 2`
>
> 坑 2：**浮点运算有精度误差** → `0.1 + 0.2 != 0.3` 在 double 下是 `False`！金融/精确计数场景用 `decimal` 而不是 `double`。
>
> 坑 3：**除数为 0 但没崩** → `1.0 / 0.0` 结果是 `double.PositiveInfinity`（正无穷），不抛异常！但 `1 / 0`（整数除零）会抛 `DivideByZeroException`。上位机中要特别防范传感器的零读数导致的除零。

> [!best] 最佳实践
> - 除法运算如果想让结果是小数，至少有一个操作数是浮点类型
> - 金融计算用 `decimal`，科学计算用 `double`，计数器用 `int`
> - 循环计数器尽可能用 `int`（CPU 处理 int 最快）
> - 上位机项目默认关闭算数溢出检测（性能好），但在关键计算处加 `checked` 块保护
> - 大数字字面量用下划线分隔：`int count = 1_000_000;` — 可读性好很多

> [!practice] 上手练习
> **Lv.1 照猫画虎**：新建控制台程序，计算 `(1023 / 1023.0 * 5 - 0.5) * 100`，打印每一步的中间结果
> **Lv.2 小试牛刀**：写一个循环，模拟串口收到 100 个 ADC 采样值（`0~1023` 之间的随机整数），对前 10 个值不做处理，第 11~50 个值乘 2，后面的值保持不变，用 `%` 和 `++` 配合条件判断实现
> **Lv.3 融会贯通**：实现一个 `CircularBuffer` 类，内部用固定长度数组，用 `%` 计算写入位置，自动覆盖最旧的数据
