# 项目文件结构详解

> [!plain] 白话理解
> WPF 项目的文件结构就像是建一栋大楼的「施工图纸堆」——每个文件各司其职：`.csproj` 是施工总规划书（编译配置），`App.xaml` 是地基（程序入口+全局资源），`MainWindow.xaml` 是大楼主体框架，`.cs` 文件是各个房间的内部装修实现，`Images/` 是装饰材料仓库。搞清楚每个文件是干什么的，你才不会在项目里乱放东西。

> [!def] 官方定义
> WPF 项目采用 MSBuild 项目系统，文件按功能和类型分层组织。核心结构包括：项目文件（`.csproj`）、应用程序定义（`App.xaml` + `App.xaml.cs`）、窗口/页面/用户控件（`*.xaml` + `*.xaml.cs`）、资源文件（图片、字体、样式字典）、以及 `Properties/` 下的程序集信息文件。所有文件在编译时由 MSBuild 根据 `.csproj` 中的配置统一处理。

> [!origin] 由来背景
> WPF 项目结构继承自 .NET 通用的项目组织方式，但多了一个关键的 XAML 维度。2006 年 WPF 推出时，面临一个问题：XAML 文件是标记语言（像 HTML），.cs 文件是编程语言（像 C#），它们必须配对工作（`Window.xaml` + `Window.xaml.cs` 是 partial class），但又需要不同的编译器处理。微软用 MSBuild 的 `<Page>` 和 `<Compile>` ItemGroup 解决了这个问题，XAML → BAML（二进制标记）的转换在编译时自动完成。这个结构稳定运行了 18 年，.NET 8 的 WPF 项目结构几乎没变。

> [!essentials] 核心要点

> **标准 WPF 项目文件夹全景**：

> ```
> MyScadaApp/                      ← 解决方案文件夹
> ├── MyScadaApp.sln               ← 解决方案文件（管理多个项目）
> └── MyScadaApp/                  ← 项目文件夹
>     ├── MyScadaApp.csproj        ← 【核心】项目构建配置
>     ├── App.xaml                 ← 应用程序入口（全局资源）
>     ├── App.xaml.cs              ← 应用程序启动/退出代码
>     ├── MainWindow.xaml          ← 主窗口界面
>     ├── MainWindow.xaml.cs       ← 主窗口业务逻辑
>     ├── AssemblyInfo.cs          ← 程序集版本信息
>     ├── Models/                  ← （自己创建）数据模型
>     ├── ViewModels/              ← （自己创建）视图模型
>     ├── Views/                   ← （自己创建）子窗口/用户控件
>     ├── Services/                ← （自己创建）业务服务（串口、PLC通信）
>     ├── Resources/               ← （自己创建）图片、图标、字体
>     ├── Styles/                  ← （自己创建）全局样式字典
>     ├── bin/                     ← 【自动生成】编译输出目录
>     │   └── Debug/
>     │       └── net8.0-windows/
>     │           ├── MyScadaApp.exe       ← 可执行文件
>     │           ├── MyScadaApp.dll       ← 程序集
>     │           └── MyScadaApp.deps.json ← 依赖清单
>     └── obj/                     ← 【自动生成】编译中间文件（不要手动改）
> ```

> **六大类文件职责速查**：

> | 类别 | 文件 | 你做什么 | 编译后去哪 |
> |------|------|---------|-----------|
> | 项目配置 | `.csproj` | 改目标框架、加 NuGet 包 | 作为构建指令 |
> | 入口文件 | `App.xaml` + `.cs` | 配全局资源、启动窗口、启动逻辑 | 编译进 .dll |
> | 窗口文件 | `*Window.xaml` + `.cs` | 画界面 + 写业务逻辑 | 编译进 .dll |
> | 资源文件 | `*.png/*.ico/*.xaml` | 放图片、图标、样式文件 | 打包进 .dll |
> | 元数据 | `AssemblyInfo.cs` | 设版本号、公司名 | 编译进 .dll |
> | 生成输出 | `bin/`、`obj/` | **别碰** | 编译产物 |

> [!example] 完整示例
>
> **上位机项目的推荐目录结构**（你自己建子文件夹）：
>
> ```
> PlcMonitor/
> ├── PlcMonitor.sln
> └── PlcMonitor/
>     ├── PlcMonitor.csproj
>     ├── App.xaml / App.xaml.cs
>     ├── Models/                 ← 数据模型
>     │   ├── PlcRegister.cs      // D0=温度, D1=压力, D2=转速
>     │   ├── AlarmRecord.cs      // 报警记录
>     │   └── DeviceConfig.cs     // 设备配置（COM口、波特率）
>     ├── ViewModels/             ← MVVM 视图模型
>     │   ├── MainViewModel.cs    // 主窗口逻辑（属性 + 命令）
>     │   └── ConfigViewModel.cs  // 配置窗口逻辑
>     ├── Views/                  ← 窗口和用户控件
>     │   ├── MainWindow.xaml     // 主监控界面
>     │   ├── ConfigWindow.xaml   // 配置窗口
>     │   └── AlarmList.xaml      // 报警列表用户控件
>     ├── Services/               ← 业务服务层
>     │   ├── PlcCommunication.cs // PLC 读写服务（Modbus TCP）
>     │   ├── SerialPortService.cs// 串口服务
>     │   └── DataLogger.cs      // 数据记录服务
>     ├── Resources/
>     │   ├── Images/             // 图标、背景图
>     │   │   ├── app.ico
>     │   │   ├── logo.png
>     │   │   ├── icon_green.png  // 运行状态
>     │   │   ├── icon_red.png    // 报警状态
>     │   │   └── icon_gray.png   // 离线状态
>     │   └── Fonts/              // 自定义字体
>     │       └── Digital-7.ttf   // 数码管字体
>     ├── Styles/
>     │   └── AppStyles.xaml      // 全局样式（按钮、文本框统一样式）
>     ├── Converters/             // 值转换器
>     │   └── BoolToColorConverter.cs  // true=绿色/false=红色
>     ├── Helpers/                // 工具类
>     │   └── Crc16Helper.cs      // Modbus CRC16 校验
>     └── appsettings.json       // 配置文件（运行时读，不参与编译）
> ```
>
> ```csharp
> // Models/PlcRegister.cs — 数据模型示例
> namespace PlcMonitor.Models
> {
>     public class PlcRegister
>     {
>         public string Address { get; set; }      // 如 "D100"
>         public string Name { get; set; }          // 如 "炉温"
>         public double Value { get; set; }         // 当前值
>         public string Unit { get; set; }          // 单位：℃/kPa/RPM
>         public double MinAlarm { get; set; }      // 报警下限
>         public double MaxAlarm { get; set; }      // 报警上限
> 
>         public bool IsAlarming => Value < MinAlarm || Value > MaxAlarm;
>     }
> }
> ```

> [!scene] 适用场景
> ✅ 新项目第一件事：规划好目录结构，别把所有文件堆在根目录
> ✅ 接手他人项目：先看 `.csproj` 理解引用，再看目录结构理解分层
> ✅ 重构现有项目：对照标准结构，把散乱的文件归类到 Models/Views/Services 等文件夹
> ❌ 小 Demo/临时测试项目——几个文件就够，不需要建完整的文件夹层级

> [!pitfall] 常见踩坑
> 坑 1：**资源文件放错位置导致找不到** → 图片、字体等资源文件必须设为正确的「生成操作」。右键文件 → 属性 → 生成操作：图片一般选 `Resource`（编译进 .dll），配置文件选 `Content` + 复制到输出目录选「如果较新则复制」。如果是 `None`，运行时找不到文件就报 `FileNotFoundException`。
>
> 坑 2：**`bin/` 和 `obj/` 里手动改了东西，下次编译被覆盖** → 这两个目录是编译输出目录，每次编译都会重新生成。不要在里面放任何需要保留的文件。Git 应该把它们加入 `.gitignore`。
>
> 坑 3：**把所有代码都写在 MainWindow.xaml.cs 里** → 初学者常犯。随着功能越加越多，MainWindow.xaml.cs 变成几千行的「上帝类」。解决方案：从第一天起就养成拆分的习惯——数据放 Models、业务逻辑放 Services、UI 逻辑放 ViewModels。

> [!best] 最佳实践
> - 命名约定：文件夹用英文复数（Models、Services、Views），文件名用 PascalCase（`PlcRegister.cs`）
> - 一个类一个文件：不要把多个 class 塞进同一个 .cs 文件
> - 分层不要过早过度：刚开始 2-3 个文件夹（Models、Views、Services）就够了，等代码规模上来再细化
> - `.gitignore` 标准化：`bin/`、`obj/`、`.vs/`、`*.user` 必须加入忽略，避免把编译产物和用户本地配置提交到仓库
> - 配置文件外置：`appsettings.json` 生成操作设为 `Content`，确保运行时能找到

> [!practice] 上手练习
> **Lv.1 照猫画虎**：新建 WPF 项目，对照上面的标准结构创建 Models、ViewModels、Views、Services、Resources 五个文件夹。在每个文件夹下用「添加 → 新建项」创建一个空类文件（如 `Models/DeviceInfo.cs`）。查看解决方案资源管理器，确认文件夹结构正确。
>
> **Lv.2 小试牛刀**：在 Resources 文件夹中建一个 Images 子文件夹，放入一张 png 图片，设为 Resource 生成操作。在 MainWindow.xaml 中用 `<Image Source="Resources/Images/xxx.png"/>` 引用它（注意路径格式）。运行确认图片能显示。
>
> **Lv.3 融会贯通**：依照上位机推荐结构，搭建一个完整的项目骨架。创建 `PlcRegister.cs`（Model）、`MainViewModel.cs`（ViewModel）、`PlcCommunication.cs`（Service）、`AppStyles.xaml`（全局样式）。让每个文件里有一行有意义的注释说明其用途。最后在 `App.xaml` 中引用 `AppStyles.xaml` 作为全局资源字典。
