# 位运算符

> [!plain] 白话理解
> 位运算就是直接对二进制位（0 和 1）动手脚。比如你有一个字节 `00101011`（十进制 43），你想只把第 3 位从变成 1——用 `|`（或运算）和掩码，咔一下就行。在上位机开发中，PLC 的状态字（一个字 16 个位分别代表 16 个开关量）、Modbus 线圈状态、串口控制寄存器的标志位——这些"一位一个含义"的数据，离开位运算根本没法玩。你可以一辈子不用位运算写业务逻辑，但在设备通信层面，它就是你的瑞士军刀。

> [!def] 官方定义
> 位运算符直接操作整型数据（`int`/`uint`/`long`/`ulong`/`short`/`ushort`/`byte`/`sbyte`）的二进制位：
> - `&` 按位与：两位都为 1 结果才为 1
> - `|` 按位或：任意一位为 1 结果就为 1
> - `^` 按位异或：两位不同结果为 1，相同为 0
> - `~` 按位取反：0→1，1→0（注意：是**按位补码**，`~0` 全都是 1）
> - `<<` 左移：所有位左移，右边补 0，等价于 ×2ⁿ
> - `>>` 右移：所有位右移，左边补符号位（算术右移）

> [!origin] 由来背景
> 位运算是最接近硬件的编程操作，早在汇编语言时代就是基本指令。C# 完整保留了这套能力是因为：.NET 不能只做"高层业务"，它是微软的旗舰平台，需要能和 C/C++ 库交互、能写驱动程序级的代码。上位机开发中，串口通信的每一帧数据、Modbus 协议的每个功能码、寄存器的每个标志位——全是二进制位级别的操作。不懂位运算，你只能在"别人封装好的库"里打转；懂了位运算，你就可以自己写通信协议解析器。

> [!essentials] 核心要点
> - `&` 与：掩码操作，提取/清零指定位（`value & 0x0F` 取低四位）
> - `|` 或：置位操作，将指定位设为 1（`value | 0x80` 最高位置1）
> - `^` 异或：翻转位，也可以用 `value ^= 1;` 来翻转最低位
> - `~` 取反：整个数按位翻转（`~0` = -1，因为补码）
> - `<<` 左移 N 位：值乘以 2 的 N 次方
> - `>>` 右移 N 位：值除以 2 的 N 次方（向下取整）
> - 位运算通常用**十六进制**字面量（`0xFF`、`0x80`）更直观
> - `value & (1 << n)` 判断第 n 位是否为 1（经典寄存器位检测）

> [!example] 完整示例

> ##### 基本位运算演示
> ```csharp
> byte a = 0b_1010_1100;  // 二进制字面量（C# 7.0）: 172
> byte b = 0b_1111_0000;  // 240

> Console.WriteLine($"a & b = 0x{a & b:X2}");  // 0xA0 (1010 0000)
> Console.WriteLine($"a | b = 0x{a | b:X2}");  // 0xFC (1111 1100)
> Console.WriteLine($"a ^ b = 0x{a ^ b:X2}");  // 0x5C (0101 1100)
> Console.WriteLine($"~a    = 0x{(byte)~a:X2}");  // 0x53 (0101 0011)
> Console.WriteLine($"a << 2 = 0x{a << 2:X2}");   // 左移=×4
> Console.WriteLine($"a >> 2 = 0x{a >> 2:X2}");   // 右移=÷4
> ```

> ##### 上位机核心场景：PLC 状态字解析
> ```csharp
> // 场景：PLC 返回一个 16 位状态字，每一位代表一个开关量
> // Bit 0: 急停         Bit 1: 运行中
> // Bit 2: 故障         Bit 3: 手动/自动
> // ...
> ushort statusWord = 0b_0000_0000_0000_0101;  // 急停+运行中

> // 提取单个位：& + 移位
> bool emergencyStop = (statusWord & (1 << 0)) != 0;  // Bit 0
> bool isRunning     = (statusWord & (1 << 1)) != 0;  // Bit 1
> bool hasFault      = (statusWord & (1 << 2)) != 0;  // Bit 2
> bool isAutoMode    = (statusWord & (1 << 3)) != 0;  // Bit 3

> Console.WriteLine($"急停:{emergencyStop} 运行:{isRunning} 故障:{hasFault} 自动:{isAutoMode}");

> // 设置某个位：| 
> ushort startMotor = statusWord | (1 << 1);       // 强制运行位置1
> ushort stopMotor  = statusWord & (ushort)~(1 << 1); // 清零运行位

> // 翻转某个位：^
> ushort toggleAuto = (ushort)(statusWord ^ (1 << 3)); // 自动/手动切换

> // 取高字节/低字节：Modbus 寄存器操作
> byte highByte = (byte)(statusWord >> 8);   // 高8位
> byte lowByte  = (byte)(statusWord & 0xFF);  // 低8位
> Console.WriteLine($"高字节: 0x{highByte:X2}, 低字节: 0x{lowByte:X2}");
> ```

> ##### Modbus RTU 校验码计算
> ```csharp
> // CRC-16/Modbus 校验码（位运算的实战）
> static ushort CalculateCRC(byte[] data)
> {
>     ushort crc = 0xFFFF;
>     foreach (byte b in data)
>     {
>         crc ^= b;
>         for (int i = 0; i < 8; i++)
>         {
>             if ((crc & 0x0001) != 0)
>                 crc = (ushort)((crc >> 1) ^ 0xA001);
>             else
>                 crc >>= 1;
>         }
>     }
>     return crc;
> }

> byte[] frame = { 0x01, 0x03, 0x00, 0x00, 0x00, 0x04 };
> ushort crc = CalculateCRC(frame);
> Console.WriteLine($"CRC-16: 0x{crc:X4}");
> byte crcLow = (byte)(crc & 0xFF);
> byte crcHigh = (byte)(crc >> 8);
> Console.WriteLine($"CRC 低字节: 0x{crcLow:X2}, 高字节: 0x{crcHigh:X2}");
> ```

> [!scene] 适用场景
> ✅ 协议解析：Modbus 寄存器读写、PLC 状态字/控制字解析
> ✅ 标志位管理：用一个整数存储多个布尔开关（权限系统、设备状态）
> ✅ 数据打包：把多个小值打包进一个字节数组（串口通信帧构造）
> ✅ 硬件寄存器：嵌入式/驱动开发中直接操作硬件寄存器位
> ✅ 性能优化：`n % 2` → `n & 1`，`n * 2` → `n << 1`
> ❌ 业务逻辑：用 `bool` 变量替代位标记（可读性远优于位运算）

> [!pitfall] 常见踩坑
> 坑 1：**位移位数超出类型位数是未定义行为？不对，C# 有明确定义！** → `int x = 1; x << 33;` 结果 `= 2`（只移了 33 % 32 = 1 位）。对于 `int`（32位），位移量被隐式取模：`x << n` 实际位移量是 `n & 0x1F`。
>
> 坑 2：**`~` 取反要注意类型宽度** → `byte b = 0x0F; var result = ~b;` 推断为 `int`！因为 `~` 运算符会先将操作数提升为 `int`。结果是 `~0x0000000F = 0xFFFFFFF0` 而不是 `0xF0`。正解：`byte result = (byte)~b;`
>
> 坑 3：**有符号数右移是算术右移（保留符号）** → `int x = -8; x >> 1;` 结果是 `-4`，不是正数。如果要做逻辑右移（左边补 0），用无符号类型：`uint x = 0x80000000; x >> 1;` 结果是 `0x40000000`。

> [!best] 最佳实践
> - 位运算操作数一律用**无符号**类型（`byte`/`ushort`/`uint`/`ulong`），避免符号位捣乱
> - 用**命名常量**定义掩码，不要到处散布魔术数字：
>   ```csharp
>   const byte BIT_EMERGENCY = 0x01;
>   const byte BIT_RUNNING   = 0x02;
>   const byte BIT_FAULT     = 0x04;
>   ```
> - 使用 `[Flags]` 特性标记枚举，用枚举代替裸位运算（可读性天差地别）：
>   ```csharp
>   [Flags]
>   enum AlarmFlags { None=0, OverTemp=1, OverPressure=2, CommLost=4 }
>   AlarmFlags flags = AlarmFlags.OverTemp | AlarmFlags.CommLost;
>   bool overTemp = flags.HasFlag(AlarmFlags.OverTemp);
>   ```
> - 上位机协议解析时，屏蔽寄存器值和位运算逻辑抽成独立方法，方便单元测试
> - 十六进制字面量用 `0x` 前缀，二进制用 `0b` 前缀（C# 7.0+），清晰无比

> [!practice] 上手练习
> **Lv.1 照猫画虎**：定义 `byte flags = 0b_1010_0101;`，用位运算提取第 0、2、5、7 位的值并打印
> **Lv.2 小试牛刀**：模拟一个 8 位设备控制字——Bit 0 启停、Bit 1 方向、Bit 2 急停——写三个方法分别实现"读取控制字某位"、"设置某位为1"、"清零某位"
> **Lv.3 融会贯通**：实现一个简单的 Modbus 线圈解析器——输入一个 `ushort` 值（代表 16 个线圈状态），输出 16 个 `bool` 的数组，并进一步解析：线圈 0~3 代表阀门状态、线圈 4~7 代表电机状态、线圈 8~15 是保留位
