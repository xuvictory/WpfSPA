# 赋值运算符

> [!plain] 白话理解
> 赋值运算符是"把右边的值塞进左边的盒子"这个动作。最基础的 `=` 你已经用了无数次，但复合赋值（`+=` `-=` `*=` 等）才是真正提高代码可读性的利器——`count = count + 1` 不如 `count += 1` 清爽，`message = message + " 完毕"` 不如 `message += " 完毕"` 自然。更还有 `??=` 这个"懒人专属"的空合并赋值，上位机代码里处理配置默认值时几乎必用。

> [!def] 官方定义
> 赋值运算符将右侧表达式的值赋给左侧的变量、属性或索引器：
> - `=` 简单赋值
> - `+=` `-=` `*=` `/=` `%=` `&=` `|=` `^=` `<<=` `>>=` 复合赋值
> - `??=` 空合并赋值（C# 8.0）：左侧为 `null` 时才赋值
> - 赋值表达式本身有返回值（是赋值后的值），可以链式赋值 `a = b = c = 0;`
> - `ref` 赋值（C# 7.3+）可以赋值给 `ref` 局部变量

> [!origin] 由来背景
> 复合赋值运算符（`+=`、`-=` 等）最早来自 C 语言的精简哲学——`i = i + 1` 写多了手疼，于是有了 `i += 1`，进而有了 `i++`。C# 完整继承了这套语法，但最有原创性的当属 `??=`（空合并赋值）。这源于一个极常见的模式：
> ```csharp
> if (config.Timeout == null)
>     config.Timeout = 3000;
> // 有了 ??= 后：
> config.Timeout ??= 3000;  // 如果没设过值，就用默认值
> ```
> 这个语法把 4 行的 null 检查默认值设置压缩成了 1 行，在上位机的配置初始化代码中出镜率极高。

> [!essentials] 核心要点
> - `=` 是右结合性：`a = b = c = 0` 从右往左赋（c=0 → b=c=0 → a=b=0)
> - 复合赋值是**先运算再赋值**：`x += 5` 等价于 `x = x + 5`
> - `x += y` 不等于 `x = x + y` 在类型提升场景下（`byte x=1; x += 5;` ✅ 但 `x = x + 5;` ❌ 因为 `x+5` 提升为 `int`）
> - `??=` 只在左侧为 `null` 时才赋值——是"填充默认值"的语义
> - 属性赋值实际调用 `set` 访问器，可能有副作用
> - `++` `--` 也算是赋值运算符，只不过隐式自增 1

> [!example] 完整示例
> ```csharp
> // ========== 简单赋值与链式赋值 ==========
> int a, b, c;
> a = b = c = 42;        // 三个变量全是 42（从右往左）
> Console.WriteLine($"{a} {b} {c}");

> // ========== 复合赋值 ==========
> int counter = 0;
> counter += 10;    // counter = 10
> counter -= 3;     // counter = 7
> counter *= 2;     // counter = 14
> counter /= 4;     // counter = 3（整数除法，14/4=3）
> counter %= 2;     // counter = 1（3%2=1）
> Console.WriteLine($"counter: {counter}");

> // 字符串拼接：上位机日志的常见写法
> string log = "[14:30] 系统启动";
> log += " → 串口已打开";
> log += " → 设备连接成功";
> log += " → 开始数据采集";
> Console.WriteLine(log);

> // ========== ??= 空合并赋值 ==========
> int? port = null;
> port ??= 502;      // port 是 null，赋值为 502
> port ??= 8080;     // port 已经是 502，不赋值
> Console.WriteLine(port);  // 502

> string? deviceName = null;
> deviceName ??= "默认设备";          // null → "默认设备"
> deviceName ??= "不会生效的名字";     // 已有值，不触发
> Console.WriteLine(deviceName);       // "默认设备"

> // ========== 上位机实战：配置初始化 ==========
> public class DeviceConfig
> {
>     public string? IpAddress { get; set; }
>     public int? Port { get; set; }
>     public int? TimeoutMs { get; set; }
>     public bool? AutoReconnect { get; set; }
    
>     public void ApplyDefaults()
>     {
>         // 优雅的一行式默认值填充
>         IpAddress ??= "192.168.1.100";
>         Port ??= 502;
>         TimeoutMs ??= 3000;
>         AutoReconnect ??= true;
>     }
    
>     public void Display()
>     {
>         Console.WriteLine($"IP={IpAddress}, Port={Port}, Timeout={TimeoutMs}ms, 自动重连={AutoReconnect}");
>     }
> }

> var config = new DeviceConfig { IpAddress = "10.0.0.55" };
> config.ApplyDefaults();
> config.Display(); // IP=10.0.0.55, Port=502, Timeout=3000ms, 自动重连=True

> // ========== 复合赋值的类型安全性 ==========
> byte value = 1;
> value += 5;        // ✅ 编译通过！复合赋值自动处理类型提升
> // value = value + 5;  // ❌ 编译错误：int 不能隐式转为 byte
> ```

> [!scene] 适用场景
> ✅ `+=` `-=`：计数器、累加器、进度条更新 —— 上位机代码无处不在
> ✅ `+=` 字符串：日志拼接（少量时可用，大量拼接请用 `StringBuilder`）
> ✅ `??=`：配置文件默认值填充、可选参数的后备值
> ✅ 链式赋值：初始化一组相关变量为相同值
> ❌ `+=` 在事件订阅中（`button.Click += Handler` —— 不是赋值的 `+=` 语义，是事件订阅）

> [!pitfall] 常见踩坑
> 坑 1：**`??=` 不能用于非空值类型（C# 8.0 前）** → `int port = 0; port ??= 502;` ❌ `int` 不是可空类型！C# 8.0 的可空引用类型特性下，非空引用类型也不行。`??=` 只能用于可空类型。
>
> 坑 2：**循环里用 `+=` 拼接字符串是性能杀手** → 
> ```csharp
> string result = "";
> for (int i = 0; i < 10000; i++)
>     result += i + ",";  // 每次创建新字符串对象，10000次=10000个临时对象
> // 正解：用 StringBuilder
> ```
>
> 坑 3：**`byte x = 1; x = x + 5;` 编译不过但 `x += 5;` 可以** → 因为 `x + 5` 的结果是 `int`（算术提升），不能隐式赋值给 `byte`。但 `x += 5` 是复合赋值，编译器自动插入了 `(byte)(x + 5)` 的转换。这是一个容易让新人困惑的不一致行为。

> [!best] 最佳实践
> - `??=` 是初始化默认值的首选写法，可读性远超 `if (x == null) x = defaultValue;`
> - 配置类的 `ApplyDefaults()` 方法中大量使用 `??=`，视觉对齐效果极好
> - 少量（<10次）字符串拼接用 `+=` 没问题；循环中或大批量拼接用 `StringBuilder`
> - 复合赋值比"变量在等号两边都出现"的写法更可读：
>   `data[index] += 1;` ✅ / `data[index] = data[index] + 1;` ❌
> - 链式赋值别跨多行，容易看漏：`a = b = c = 0;` 一行搞定

> [!practice] 上手练习
> **Lv.1 照猫画虎**：定义 `int score = 0;`，依次用 `+=` `-=` `*=` `/=` `%=` 操作并打印每次结果
> **Lv.2 小试牛刀**：创建一个 `DeviceSettings` 类，包含5个可空属性（IP、端口、超时、重试次数、启停状态），写 `ApplyDefaults()` 方法用 `??=` 一次性填充所有默认值
> **Lv.3 融会贯通**：在实际的上位机通信类中，实现一个 `SendWithRetry` 方法，内部用 `retryCount += 1` 记录重试次数，用 `elapsed += delay` 累计等待时间，达到最大重试或超时后退出
