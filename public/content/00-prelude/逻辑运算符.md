# 逻辑运算符

> [!plain] 白话理解
> 逻辑运算符就是把多个"判断题"串成一个"综合结论"的工具。比如"温度超过80 **且** 压力超过2.0"才报警——少一个条件就不响；"设备离线 **或** 通信超时"都要发通知——中一个就行；"**不是**正常状态"就暂停采集——把结论反过来。这三个词：且（`&&`）、或（`||`）、非（`!`），构成了程序里所有决策判断的骨架。

> [!def] 官方定义
> C# 的逻辑运算符操作 `bool` 类型的操作数，返回 `bool` 结果：
> - `&&` 逻辑与（条件与、短路与）：两边都为 `true` 才为 `true`；左边为 `false` 时**不执行右边**
> - `||` 逻辑或（条件或、短路或）：任意一边为 `true` 即为 `true`；左边为 `true` 时**不执行右边**
> - `!` 逻辑非：`true` 变 `false`，`false` 变 `true`
> - `&` 逻辑与（不短路）/ `|` 逻辑或（不短路）：两边都执行
> - `^` 逻辑异或：两边不同为 `true`，相同为 `false`

> [!origin] 由来背景
> `&&` 和 `||` 的**短路求值（Short-Circuit Evaluation）** 是编程语言史上最优雅的设计之一。它的价值不只在性能——更在安全："先判断对象是不是 null，再访问它的属性"这个模式就完全依赖短路：
> ```csharp
> if (device != null && device.IsOnline)
> ```
> 如果没有短路，`device.IsOnline` 会在 `device == null` 时崩掉。这个特性从 C 语言时代就存在，C# 完美继承。而上位机开发中，短路几乎出现在每一个条件判断里——"通信已连接 且 收到有效数据"、"配置不为空 且 设备ID匹配"。

> [!essentials] 核心要点
> - `&&` `||` 短路：左操作数能决定结果时，右操作数不执行
> - `&` `|` 不短路：两边都一定会执行（用于整数位运算和副作用场景）
> - `!` 优先级很高：`!a && b` 是 `(!a) && b`
> - `&&` 优先级高于 `||`：`a || b && c` 等价于 `a || (b && c)`
> - 可空的 `bool?` 也支持逻辑运算，但结果为 `null` 时行为需注意
> - `^` 异或：`a ^ b` 当 a 和 b 不同时为 true

> [!example] 完整示例
> ```csharp
> // ========== 短路求值的威力 ==========
> string? deviceName = null;

> // ✅ 利用短路防止空引用：deviceName 为 null 时，右边不执行
> if (deviceName != null && deviceName.Length > 0)
>     Console.WriteLine($"设备名: {deviceName}");
> else
>     Console.WriteLine("设备名无效");

> // ❌ 如果不短路（用 &），NullReferenceException！
> // if (deviceName != null & deviceName.Length > 0)  // 会崩！

> // ========== 或运算的短路 ==========
> int? cachedTemp = 85;     // 缓存的数据
> int? liveTemp = null;     // 实时数据还没拿到

> // 有实时数据用实时，没有用缓存，都没有才报错
> if (liveTemp.HasValue || cachedTemp.HasValue)
> {
>     int display = liveTemp ?? cachedTemp ?? 0;
>     Console.WriteLine($"显示温度: {display}℃");
> }

> // ========== 非运算 ==========
> bool isFaulted = false;
> if (!isFaulted)  // "没有故障"可读性远好于 "isFaulted == false"
>     Console.WriteLine("系统正常，继续采集");

> // ========== 上位机实战：复合告警条件 ==========
> double temperature = 85.5;
> double pressure = 2.1;
> bool communicationOk = true;
> bool emergencyStop = false;

> // 告警级别：红色（紧急停机 或 高温高压同时满足）
> //         黄色（仅高温 或 仅高压）
> //         绿色（一切正常）
> bool redAlarm = emergencyStop || (temperature > 80 && pressure > 2.0);
> bool yellowAlarm = !emergencyStop && (temperature > 80 || pressure > 2.0) && !redAlarm;
> bool greenStatus = !redAlarm && !yellowAlarm;

> Console.WriteLine($"红色告警: {redAlarm}, 黄色告警: {yellowAlarm}, 正常: {greenStatus}");

> // ========== 德摩根定律：把复杂条件变简洁 ==========
> // 需求：不是(温度正常 且 压力正常)
> // 写法A：! (temp <= 80 && pressure <= 2.0)
> // 写法B：temp > 80 || pressure > 2.0   ← 更直观

> bool wayA = !(temperature <= 80 && pressure <= 2.0);
> bool wayB = temperature > 80 || pressure > 2.0;
> Console.WriteLine($"德摩根验证: wayA={wayA}, wayB={wayB}");  // 结果相同

> // ========== 异或：恰好一个成立 ==========
> bool hasSerial = true;
> bool hasEthernet = false;
> bool singleChannel = hasSerial ^ hasEthernet; // True，恰好一个通信方式
> Console.WriteLine($"单一通信通道: {singleChannel}");

> // ========== bool? 的逻辑运算 ==========
> bool? a = true;
> bool? b = null;
> Console.WriteLine(a & b);  // null（任意操作数为 null，结果 null）
> Console.WriteLine(a | b);  // true（或运算只要有一个 true 就是 true）
> ```

> [!scene] 适用场景
> ✅ `&&`：多条件同时满足（"设备在线且数据有效且未过期"）
> ✅ `||`：多条件任一满足（"超温或超压或通信中断"任一触发告警）
> ✅ `!`：取反语义（`!isRunning` 比 `isRunning == false` 更自然）
> ✅ 短路保护：`obj != null && obj.Property` 是上位机代码中的绝对标配
> ✅ `^`：互斥逻辑（"PLC 和 DCS 不能同时处于主控模式"）
> ❌ 不要在 `||` 右边放有副作用的方法调用（短路可能导致该方法不被调用）

> [!pitfall] 常见踩坑
> 坑 1：**把 `&` 和 `&&` 搞混** → `if (CheckA() & CheckB())` 会执行两个方法，`&&` 可能只执行一个。除非你明确需要两边都执行的副作用（极少见），否则永远用 `&&` `||`。
>
> 坑 2：**`if (x > 10 || x < 5)` 和 `if (x > 10 && x < 5)` 搞反** → `&&` 是"同时满足"，`||` 是"至少一个"。`x > 10 || x < 5` 表示"x要么大于10要么小于5"（中间区域被排除）；`x > 10 && x < 5` 永远为 `false`（一个数不可能同时大于10又小于5）。
>
> 坑 3：**`bool?` 的逻辑运算返回 `bool?`** → `null & true` 是 `null` 不是 `false`！如果你在 `if (nullableBool & true)` 里，`null` 不会被视为 `false` 进入 else 分支。解决：`if (nullableBool == true)` 显式检查。

> [!best] 最佳实践
> - 复杂条件用中间变量命名，不要写一行 200 字符的超长 if：
>   ```csharp
>   bool tempHigh = temperature > 80;
>   bool pressureHigh = pressure > 2.0;
>   bool commLost = !communicationOk;
>   bool alarm = tempHigh && pressureHigh || commLost; // 一眼看懂
>   ```
> - 善用德摩根定律简化条件：
>   `!(a && b)` → `!a || !b`
>   `!(a || b)` → `!a && !b`
> - 永远不要依赖 `|` 的副作用（两边都执行），同事会问候你
> - 在上位机的告警逻辑中，建议用多级告警变量（`redAlarm`/`yellowAlarm`）而不是一个复杂表达式
> - `if` 后面即使只有一行也写花括号——这是工业代码的硬性规范

> [!practice] 上手练习
> **Lv.1 照猫画虎**：运行上面"复合告警条件"的代码，分别修改 temperature=70、pressure=1.5、emergencyStop=true，观察告警级别的变化
> **Lv.2 小试牛刀**：写一个设备连接判断方法，输入三个 bool（电源正常/网络连通/鉴权通过），用逻辑运算符判断：三个全满足→"完全可用"、缺一项→"部分可用"、缺两项以上→"不可用"
> **Lv.3 融会贯通**：设计一个"生产线联锁"逻辑：5个工位，第N个工位启动的前提是前N-1个工位都就绪且紧急停机未触发。用循环+逻辑运算符实现这个联锁检查
