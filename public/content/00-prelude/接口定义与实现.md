# 接口定义与实现

> [!plain] 白话理解
> 接口就是一个"能力证书"——某类实现了 `IDisposable` 接口，就说明"我有释放资源的本领"；实现了 `IEnumerable`，就说明"我可以被 foreach 遍历"。接口不关心你怎么实现这个能力，只关心你有没有。就像驾照不关心你开的是比亚迪还是特斯拉，只关心"你有驾驶能力吗"。上位机中，`ICommunication` 接口定义了 `Connect`/`Send`/`Receive` 的契约，至于底层是串口还是 TCP——接口不在乎。

> [!def] 官方定义
> 接口（Interface）是一种只包含方法、属性、事件、索引器**签名**（无实现）的类型。接口定义了类的**行为契约**——任何实现该接口的类必须提供接口所有成员的实现。C# 8.0 引入**默认接口方法**（可有默认实现）。一个类可以实现多个接口（弥补单继承的局限）。

> [!origin] 由来背景
> 接口是面向对象设计中最强大的抽象机制。C# 的单继承限制了代码复用，但多接口实现完美弥补——一个类只能有一个爸爸（基类），但可以有多张"证书"（接口）。在 .NET 中，`IDisposable`、`IEnumerable<T>`、`INotifyPropertyChanged` 这些接口是整个框架的基石。上位机中，接口让"依赖倒置原则"（DIP）落地——上层依赖 `IProtocol` 接口而非具体 `ModbusProtocol` 类，换协议时不需要改动上层代码。

> [!essentials] 核心要点
> - 声明：`interface IName { 成员签名; }`（命名惯例 `I` 前缀）
> - 实现：`class MyClass : IName { 实现所有成员 }`
> - 一个类可以实现多个接口：`class A : IX, IY, IZ`
> - 接口成员默认是 `public`（不能加访问修饰符，C# 8 前）
> - 接口之间可以继承：`interface IA : IB { }`
> - C# 8.0+ 可以有默认实现、静态成员、`virtual`/`sealed` 成员

> [!example] 完整示例
> ```csharp
> // ====== 定义接口 ======
> public interface ICommunication
> {
>     bool IsConnected { get; }
>     bool Connect(string address);
>     void Disconnect();
>     byte[] SendAndReceive(byte[] command);
> }

> public interface IConfigurable
> {
>     void LoadConfig(string filePath);
>     void SaveConfig(string filePath);
> }

> public interface ILoggable
> {
>     string GetLogInfo();
> }

> // ====== 一个类实现多个接口 ======
> public class ModbusTcpDriver : ICommunication, IConfigurable, ILoggable
> {
>     public bool IsConnected { get; private set; }
    
>     public bool Connect(string address)
>     {
>         Console.WriteLine($"[ModbusTCP] 连接 {address}");
>         IsConnected = true;
>         return true;
>     }
    
>     public void Disconnect()
>     {
>         Console.WriteLine("[ModbusTCP] 断开");
>         IsConnected = false;
>     }
    
>     public byte[] SendAndReceive(byte[] command)
>     {
>         Console.WriteLine($"[ModbusTCP] 发送 {command.Length} 字节");
>         return new byte[] { 0x01, 0x03, 0x08, 0xFF };
>     }
    
>     public void LoadConfig(string filePath)
>         => Console.WriteLine($"加载配置: {filePath}");
    
>     public void SaveConfig(string filePath)
>         => Console.WriteLine($"保存配置: {filePath}");
    
>     public string GetLogInfo()
>         => $"ModbusTCPDriver(已连接={IsConnected})";
    
>     // 显式接口实现：避免成员名冲突
>     string ILoggable.GetLogInfo() => $"[LOG] {GetLogInfo()}";
> }

> // ====== 面向接口编程 ======
> public class DataCollector
> {
>     private readonly ICommunication _comm;  // 依赖接口，不依赖具体类
    
>     public DataCollector(ICommunication comm) => _comm = comm;
    
>     public double CollectTemperature()
>     {
>         var cmd = new byte[] { 0x01, 0x03, 0x00, 0x00 };
>         var response = _comm.SendAndReceive(cmd);
>         return 85.5; // 解析...
>     }
> }

> // ====== 接口类型判断 ======
> var driver = new ModbusTcpDriver();
> driver.Connect("192.168.1.100");

> if (driver is IConfigurable configurable)
>     configurable.LoadConfig("config.json");
> if (driver is ILoggable loggable)
>     Console.WriteLine($"日志: {loggable.GetLogInfo()}");
> ```

> [!scene] 适用场景
> ✅ 依赖注入：`ICommunication` 取代具体类
> ✅ 能力标记：`IDisposable`、`IComparable<T>`
> ✅ 插件架构：定义插件接口，第三方实现
> ✅ 单元测试 Mock：Mock 接口比 Mock 具体类容易得多
> ❌ 有大量共用代码且只有一个实现 → 用抽象类

> [!pitfall] 常见踩坑
> 坑 1：**显式接口实现不能直接通过类引用调用** → 必须转到接口类型。
> 坑 2：**接口中加新成员会破坏所有实现者** → C# 8 默认接口方法缓解了此问题。
> 坑 3：**接口属性和自动属性** → 接口中声明 `int Count { get; }` 就只是契约，实现者可以自由选择自动属性或完整属性。

> [!best] 最佳实践
> - 接口命名以 `I` 开头（`ICommunication`、`IDevice`）
> - 接口只定义"做什么"（契约），不定义"怎么做"
> - 细粒度接口 > 大接口（接口隔离原则）
> - 构造函数注入接口，而非直接 new 具体类
> - C# 8 默认接口方法慎用——让接口保持纯契约更清晰
