# 泛型方法

> [!plain] 白话理解
> 泛型方法就是"方法也能带类型参数"，不限于类本身。你写一个 `T Swap<T>(T a, T b)`，传入什么类型就处理什么类型——不需要为 `int` 写一遍、为 `string` 再写一遍。编译器根据调用时传入的参数自动推断 `T`，你甚至不需要显式写出 `Swap<int>(1, 2)`——直接 `Swap(1, 2)` 就够了。

> [!def] 官方定义
> 泛型方法是在普通类（或泛型类）中定义的带独立类型参数的方法。类型参数在方法名后声明：`ReturnType MethodName<T>(T param)`。调用时可显式指定或利用类型推断。

> [!origin] 由来背景
> 泛型方法源于 C# 2.0 的泛型机制。在没有它之前，想做"对任意类型生效的工具方法"，要么为每种类型写重载（十几个重载代码爆炸），要么用 `object` 传参——值类型装箱、强转易错。泛型方法把类型参数下沉到方法级别，配合编译器的类型推断，让"写一次、处处用"成为现实。上位机里的量程限制（Clamp）、寄存器值换算、配置反序列化，都是泛型方法大显身手的典型场景。

> [!essentials] 核心要点
> - 语法：`ReturnType MethodName<T>(T param)`，类型参数写在方法名后
> - 编译器类型推断：多数情况 `Swap(1, 2)` 即可，无需显式写 `Swap<int>(1, 2)`
> - 泛型方法可定义在普通类、静态类、泛型类中，互不影响
> - 需要调用成员或做运算时加约束：`where T : IComparable<T>` 才能用 `CompareTo`
> - 常见应用：工具方法（Clamp/Parse/Convert）、工厂方法、序列化辅助
> - 注意：泛型方法的 `T` 与所在泛型类的 `T` 是两个独立类型参数

> [!example] 完整示例
> ```csharp
> // ====== 泛型方法 ======
> public static T Clamp<T>(T value, T min, T max) where T : IComparable<T>
> {
>     if (value.CompareTo(min) < 0) return min;
>     if (value.CompareTo(max) > 0) return max;
>     return value;
> }

> Console.WriteLine(Clamp(105, 0, 100));  // 100
> Console.WriteLine(Clamp(1.5, 0.0, 1.0)); // 1.0

> // ====== 上位机：泛型寄存器解析 ======
> public static T ParseRegisterValue<T>(ushort raw, double scale = 1.0, double offset = 0)
> {
>     double engineering = raw * scale + offset;
>     return (T)Convert.ChangeType(engineering, typeof(T)); // 带约束
> }

> double temp = ParseRegisterValue<double>(1023, 5.0 / 1023, 0);
> Console.WriteLine($"温度: {temp:F1}℃");
> ```

> [!scene] 适用场景
> ✅ 工具方法（限制/转换/序列化/反序列化）
> ✅ 工厂方法
> ❌ 类型之间毫无共同契约 → 用重载更直白

> [!pitfall] 常见踩坑
> 坑 1：**无约束时无法调用成员** → `T` 只保证是 `object`，不能 `+`、不能调方法。需要运算或成员必须先加 `where` 约束。
> 坑 2：**`Convert.ChangeType` 与 `T` 转换失败** → `(T)Convert.ChangeType(...)` 类型不匹配时抛 `InvalidCastException`。调用方必须保证目标类型正确，或改用 `TryParse` 模式。
> 坑 3：**把泛型方法当万能方案** → 两个类型毫无共同点时，泛型反而让代码绕。必要时用重载或接口更清晰。

> [!best] 最佳实践
> - 利用类型推断
> - 需要约束时加约束（`where T : class`）
