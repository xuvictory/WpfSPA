# 泛型约束

> [!plain] 白话理解
> 泛型的 `T` 可以是任何类型，但有时候你需要限制一下——"这个 `T` 必须是引用类型"、"必须有无参构造函数"、"必须实现了 `IComparable`"。这就是 `where` 约束的作用：`where T : class`（T 须是引用类型）、`where T : IComparable<T>`（T 须实现了该接口）、`where T : new()`（T 有无参构造）。上位机中写泛型工具类时几乎必加约束——否则 `T` 为任意类型时连 `new()` 都调不了。

> [!def] 官方定义
> 泛型约束（Generic Constraints）通过 `where T : 约束` 限制类型参数的类型范围：
> - `where T : class` → 引用类型
> - `where T : struct` → 值类型
> - `where T : new()` → 有无参构造函数
> - `where T : BaseClass` → 基类约束
> - `where T : IInterface` → 接口约束

> [!origin] 由来背景
> 泛型刚推出时，"无约束的 T"几乎什么都做不了——不能 `new`、不能比较、不能调用方法，只能当 `object` 用，价值大打折扣。C# 2.0 同时提供了 `where T : ...` 约束机制：告诉编译器"这个 T 至少具备哪些能力"，编译器就能放心地在泛型代码里 `new`、比较、调用接口成员。`new()` 约束让泛型工厂成为可能，`IComparable<T>` 约束让泛型排序成为可能——上位机里的缓存池、命令工厂、配置仓储都建立在约束之上。

> [!essentials] 核心要点
> - 常用约束：`class`（引用类型）、`struct`（值类型）、`new()`（无参构造）、基类、接口
> - `new()` 约束必须写在**最后**：`where T : class, IComparable<T>, new()`
> - 多个约束用逗号叠加：`where T : BaseClass, IInterface, new()`
> - 约束是编译期检查，不增加运行期开销
> - 接口约束最常见两个：`IComparable<T>`（比较/排序）、`IDisposable`（统一释放）
> - 约束即文档：`where T : DeviceBase` 比无约束更能自解释意图

> [!example] 完整示例
> ```csharp
> // 约束：T必须有无参构造
> public class ObjectPool<T> where T : new()
> {
>     private readonly Queue<T> _pool = new();
    
>     public T Get() => _pool.Count > 0 ? _pool.Dequeue() : new T();
>     public void Return(T item) => _pool.Enqueue(item);
> }

> // 约束：T 必须实现 IComparable<T>
> public static T Max<T>(T a, T b) where T : IComparable<T> => a.CompareTo(b) >= 0 ? a : b;

> Console.WriteLine(Max(10, 5));   // 10
> Console.WriteLine(Max("app", "zoo")); // "zoo"
> ```

> [!scene] 适用场景
> ✅ 泛型工具方法限制类型
> ✅ 泛型工厂（`new()` 约束）
> ✅ 数值运算（`struct, IComparable`）

> [!pitfall] 常见踩坑
> 坑 1：**`new()` 约束误用于抽象类/接口** → 它们无法实例化，编译直接报错。改用工厂方法注入或委托创建。
> 坑 2：**约束太宽形同虚设** → 只写 `where T : class` 照样 new 不了、比较不了。约束应与方法体需求严格对应。
> 坑 3：**`where T : struct, new()` 中 new() 多余** → 值类型天然有无参构造，写上不报错但属于冗余。
> 坑 4：**把约束当性能优化** → 约束是编译期契约，不是运行期优化，别为"快一点"加多余约束。

> [!best] 最佳实践
> - 只加必要的约束
> - `new()` 要放最后（`where T : class, IComparable<T>, new()`）
