# 构造函数

> [!plain] 白话理解
> 构造函数是对象的"出生证明"——你 `new DeviceConfig("PLC-001")` 的那一刻，构造函数跑起来，把初始值装进对象的各个抽屉里。它长得像方法，但没有返回值类型（连 `void` 都不写），名字必须和类一模一样。如果在工厂里，构造函数就是"产线启动程序"：零件到位、参数校验、组装完成，一个合格的产品（对象）才能下线。

> [!def] 官方定义
> 构造函数是在创建类（或结构）的实例时自动调用的特殊方法。它负责初始化对象的状态（字段和属性）。特点：
> - 名称与类名相同，无返回类型
> - 可以被重载（多个不同参数的构造函数）
> - 可以使用 `this(...)` 调用同类其他构造函数（构造函数链）
> - 可以使用 `base(...)` 调用基类构造函数
> - 如果不定义任何构造函数，编译器生成默认无参构造函数
> - 静态构造函数（`static 类名()`）在类型首次使用时调用一次

> [!origin] 由来背景
> 构造函数的概念源自 Simula 67（第一个面向对象语言）。C# 从 C++/Java 继承了构造函数的基本范式，但做了三处重要改进：(1) 默认初始化——字段和属性在构造前先被清零/赋默认值，不会出现 C++ 中未初始化内存的野值；(2) 构造函数链 `this(...)`/`base(...)` 让继承层次中的初始化顺序清晰可控；(3) C# 12 的**主构造函数**（Primary Constructor）直接把参数放在类声明上，进一步消灭样板代码。

> [!essentials] 核心要点
> - 默认构造函数：不写任何构造函数时，编译器提供 `public 类名() { }`
> - 重载：`Device(string id)` / `Device(string id, int port)`
> - 构造链：`public Device(string id) : this(id, 502) { }` 调用另一个构造函数
> - 基类链：`public PlcDevice(string id) : base(id) { }` 调用基类构造函数
> - `this` 在构造函数中引用正在构造的对象
> - 主构造函数（C# 12）：`public class Device(string id, int port) { }` 

> [!example] 完整示例
> ```csharp
> // ========== 构造函数重载与链 ==========
> public class DeviceConfig
> {
>     public string Id { get; }
>     public string Name { get; }
>     public int Port { get; }
>     public int TimeoutMs { get; }
>     public DateTime CreatedAt { get; }
    
>     // 主构造函数：必须的参数
>     public DeviceConfig(string id, string name, int port, int timeoutMs)
>     {
>         // 参数校验（防御式编程）
>         if (string.IsNullOrWhiteSpace(id))
>             throw new ArgumentException("设备ID不能为空", nameof(id));
>         if (port < 1 || port > 65535)
>             throw new ArgumentException($"端口号 {port} 无效", nameof(port));
        
>         Id = id;
>         Name = name;
>         Port = port;
>         TimeoutMs = timeoutMs;
>         CreatedAt = DateTime.Now;
>     }
    
>     // 便捷构造函数：只给 ID，其他用默认值
>     public DeviceConfig(string id) 
>         : this(id, id, 502, 3000)  // 链式调用主构造函数
>     {
>     }
    
>     // 另一个便捷构造函数
>     public DeviceConfig(string id, int port)
>         : this(id, id, port, 3000)
>     {
>     }
    
>     public override string ToString() 
>         => $"{Id}({Name})@{Port}:{TimeoutMs}ms";
> }

> // ========== 使用 ==========
> var dev1 = new DeviceConfig("PLC-001");
> var dev2 = new DeviceConfig("PLC-002", 8080);
> var dev3 = new DeviceConfig("TEMP-01", "温度变送器", 102, 5000);

> Console.WriteLine(dev1);
> Console.WriteLine(dev2);
> Console.WriteLine(dev3);

> // ========== 静态构造函数：只执行一次 ==========
> public class ProtocolDefaults
> {
>     public static int ModbusPort { get; }
>     public static string Version { get; }
    
>     // 静态构造函数：类型首次加载时执行一次
>     static ProtocolDefaults()
>     {
>         ModbusPort = 502;
>         Version = "1.0.0";
>         Console.WriteLine("协议默认配置已加载");
>     }
> }
> // 首次使用 ProtocolDefaults 时自动执行静态构造
> Console.WriteLine($"Modbus默认端口: {ProtocolDefaults.ModbusPort}");
> ```

> [!scene] 适用场景
> ✅ 依赖注入：构造函数接收必需的依赖项
> ✅ 参数校验：在构造函数中拒绝非法状态（"绝不让无效对象诞生"）
> ✅ 工厂模式：多个构造函数提供不同的创建路径
> ✅ 上位机中几乎所有配置类、驱动类都有自定义构造函数

> [!pitfall] 常见踩坑
> 坑 1：**写了带参构造函数就没默认构造函数了** → 需要无参构造时必须显式写出！
> 坑 2：**构造函数中调虚方法** → 派生类的重写版本会在自己的构造函数跑完之前被调用（此时字段还是默认值），极易出 bug。永远不要在构造函数里调用 `virtual` 方法。
> 坑 3：**`readonly` 字段只能在声明时和构造函数中赋值** → 如果在普通方法里尝试改 `readonly` 会编译错误。

> [!best] 最佳实践
> - 构造函数中完成对象必需状态的初始化，校验参数合法性
> - 用构造函数链 `this(...)` 减少重复代码
> - 构造逻辑太重时考虑工厂方法或 Builder 模式
> - 不要做 IO/网络/数据库操作（会阻塞调用方且测试困难）

> [!practice] 上手练习
