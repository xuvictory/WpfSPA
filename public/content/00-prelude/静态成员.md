# 静态成员

> [!plain] 白话理解
> 普通成员（实例成员）是属于"每一个对象"的——张三有张三的温度，李四有李四的温度。静态成员（`static`）是属于"这个类型"的——不管创建了多少个对象，大家都共享同一个值。就像公司的门牌号（静态），你问张三公司地址和李四公司地址是一样的；而他们各自的工位号（实例），每个人都不一样。上位机中最常见的静态成员：`Configuration.DefaultPort`（全局配置）、`Logger.Log()`（全局日志方法）、`Convert.ToInt32()`（工具方法）。

> [!def] 官方定义
> `static` 关键字修饰的成员属于**类型本身**而非某个实例。特点：
> - 静态字段在所有实例间共享（存在于类型的"静态存储区"）
> - 静态方法不能访问实例成员（没有 `this`）
> - 静态构造函数在类型首次被使用前自动执行一次
> - 静态类（`static class`）只能包含静态成员，不能实例化
> - 访问方式：`类名.成员名`（如 `Math.PI`）

> [!origin] 由来背景
> 静态成员从面向对象诞生之初就存在，但在 C# 中有一个独特的应用：**扩展方法**必须定义在静态类中。静态类在 .NET 框架中扮演工具库角色：`Math`、`Console`、`Convert` 全是静态类。而在上位机中，静态成员有特殊价值——设备连接池、全局配置、日志器都是"全局一份就够了"的典型场景。但要小心：滥用静态会引入全局状态，让代码难以测试。

> [!essentials] 核心要点
> - `static` 成员属于类型，不依赖实例
> - 调用：`ClassName.StaticMethod()` 而非 `instance.StaticMethod()`
> - 静态方法中不能直接用 `this`、不能访问实例属性和方法
> - `static class`：不能 `new`，所有成员必须是 `static`
> - `static constructor`：无参无修饰符，类型加载时自动执行一次

> [!example] 完整示例
> ```csharp
> public class DeviceManager
> {
>     // ====== 静态字段：所有实例共享 ======
>     private static int _totalDeviceCount = 0;
>     private static readonly List<string> _allDeviceIds = new();
    
>     // ====== 静态属性 ======
>     public static int TotalDeviceCount => _totalDeviceCount;
>     public static IReadOnlyList<string> AllDeviceIds => _allDeviceIds.AsReadOnly();
    
>     // ====== 实例字段 ======
>     public string Id { get; }
>     public string Name { get; }
    
>     // ====== 静态构造函数：类型首次使用前执行 ======
>     static DeviceManager()
>     {
>         Console.WriteLine("[静态构造] DeviceManager 类型已加载");
>     }
    
>     // ====== 实例构造函数 ======
>     public DeviceManager(string id, string name)
>     {
>         Id = id;
>         Name = name;
>         _totalDeviceCount++;
>         _allDeviceIds.Add(id);
>     }
    
>     // ====== 静态方法（工具方法） ======
>     public static bool IsValidDeviceId(string id)
>     {
>         return !string.IsNullOrWhiteSpace(id) && id.Length >= 3;
>     }
> }

> // ====== 静态类：纯粹的工具库 ======
> public static class ModbusUtils
> {
>     public const int DefaultPort = 502;
>     public const byte ReadHoldingRegisters = 0x03;
    
>     public static byte[] BuildReadCommand(byte slaveId, ushort startAddr, ushort count)
>     {
>         return new byte[]
>         {
>             slaveId,
>             ReadHoldingRegisters,
>             (byte)(startAddr >> 8),
>             (byte)(startAddr & 0xFF),
>             (byte)(count >> 8),
>             (byte)(count & 0xFF)
>         };
>     }
    
>     public static ushort CalculateCRC(byte[] data)
>     {
>         ushort crc = 0xFFFF;
>         foreach (byte b in data)
>         {
>             crc ^= b;
>             for (int i = 0; i < 8; i++)
>                 crc = (crc & 1) != 0 ? (ushort)((crc >> 1) ^ 0xA001) : (ushort)(crc >> 1);
>         }
>         return crc;
>     }
> }

> // ========== 使用 ==========
> Console.WriteLine($"端口: {ModbusUtils.DefaultPort}");

> var dev1 = new DeviceManager("PLC-001", "主控PLC");
> var dev2 = new DeviceManager("PLC-002", "备用PLC");
> Console.WriteLine($"设备总数: {DeviceManager.TotalDeviceCount}");

> byte[] cmd = ModbusUtils.BuildReadCommand(0x01, 0x0000, 0x0004);
> Console.WriteLine($"命令: [{string.Join(" ", cmd.Select(b => $"{b:X2}"))}]");
> ```

> [!scene] 适用场景
> ✅ 工具方法（`Math.Abs`、`Convert.ToInt32`）
> ✅ 全局配置/常量（`AppSettings.Default`）
> ✅ 扩展方法（必须静态类）
> ✅ 工厂方法（`Device.Create()`）
> ❌ 有状态的服务（难以测试）→ 用依赖注入代替静态

> [!pitfall] 常见踩坑
> 坑 1：**静态方法里访问实例成员** → 编译错误。静态方法没有 `this`。
> 坑 2：**静态字段在多线程下的竞态条件** → `static int counter = 0; counter++;` 不加锁会丢计数。
> 坑 3：**静态构造函数抛异常** → 类型此后永远不可用（`TypeInitializationException`），且无法恢复。

> [!best] 最佳实践
> - 纯函数（无副作用、无状态）适合做 `static`
> - 有全局状态的需求优先考虑依赖注入 + 单例，而非静态类
> - 静态字段在多线程环境下加 `lock` 或使用 `Interlocked`
