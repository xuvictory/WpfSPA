# 监视窗口与即时窗口

> [!plain] 白话理解
> 程序断住后，你肯定想知道「现在这个变量到底是多少？」。监视窗口就像你的「仪表盘」——把关键变量拖进去，数值实时刷新，变化一目了然。即时窗口则像「对讲机」——你可以在程序暂停时直接输入 C# 表达式或代码，比如 `temperature.ToString("F2")` 或 `list.Count`，它当场算出结果给你看。甚至你可以在这里临时修改变量值——`temperature = 25.0`——下一秒程序换个方向继续跑。

> [!def] 官方定义
> **监视窗口（Watch Window）**：VS 调试器提供的变量监控面板，支持 4 个独立的监视组（Watch 1-4）。开发者可手动输入变量名、表达式或拖入代码中的变量，调试器在每次中断时重新求值并显示。支持对象展开（查看成员）、值编辑、格式化说明符（如 `,h` 十六进制显示）。
>
> **即时窗口（Immediate Window）**：调试时用于直接执行 C# 表达式和语句的交互式控制台。输入表达式回车即求值（如 `? sensorData.Temperature`），输入语句可产生副作用（如 `Log.Write(msg)`、`list.Clear()`）。执行在调试器当前上下文中进行。

> [!origin] 由来背景
> 变量监视在早期调试器中就已存在（如 Borland Turbo Debugger 的 Watches 窗口）。即时窗口（Immediate Window）从 VB6 时代就成为了 VS 的特色功能——当时 VB 开发者可以在「立即窗口」里输入任何 VB 语句并立即执行，这个交互式体验在 1998 年来说是革命性的。C# 从 VS 2003 起也继承了即时窗口，并随着 Roslyn 编译器的引入支持了更完整的 C# 语法和 LINQ。

> [!essentials] 核心要点

> **监视窗口核心操作**：

> | 操作 | 方法 | 说明 |
> |------|------|------|
> | 打开 | 调试 → 窗口 → 监视 → 监视1 | `Ctrl+Alt+W, 1` |
> | 添加变量 | 右键变量 →「添加监视」/ 拖入 | 高亮变量后直接拖进去最快 |
> | 编辑变量值 | 双击「值」列 → 输入新值 | 临时改变程序走向 |
> | 格式化显示 | 变量名后加 `,h`（十六进制）`,ac`（强制计算） | 如 `rawData, h` |
> | 查看对象内部 | 点击变量左侧三角展开 | 嵌套对象层层展开 |

> **即时窗口核心操作**：

> | 操作 | 方法 | 说明 |
> |------|------|------|
> | 打开 | 调试 → 窗口 → 即时 | `Ctrl+Alt+I` |
> | 查看变量值 | `? 变量名` 或直接写变量名 | `? sensorData.Temperature` |
> | 执行方法 | 直接调用 | `sensorData.ToString()` |
> | 修改变量 | 直接赋值 | `sensorData.Temperature = 50.0` |
> | 创建对象 | `new` 关键字 | `new List<int> {1,2,3}` |

> [!example] 完整示例
> ```csharp
> // 用监视窗口和即时窗口调试上位机数据采集
> using System;
> using System.Collections.Generic;
> using System.Linq;
> 
> namespace PlcMonitor.Debug
> {
>     public class SensorSimulator
>     {
>         public static void Run()
>         {
>             var sensor = new SensorData
>             {
>                 DeviceId = "PLC-01",
>                 Temperature = 36.8,
>                 Pressure = 102,
>                 Speed = 1500,
>                 RawBytes = new byte[] { 0x01, 0x03, 0x04, 0x17, 0x00, 0x66, 0x05, 0xDC }
>             };
> 
>             // 👈 在此处设断点，然后：
>             // 
>             // 【监视窗口操作】
>             // 1. 拖 sensor 到监视1窗口 → 展开看所有字段
>             // 2. 添加 sensor.Temperature → 看温度值
>             // 3. 添加 sensor.RawBytes.Length → 看字节数
>             // 4. 添加 sensor.RawBytes, h → 以十六进制显示：0x00000008
>             //    ??? 不对！应该是：0x01, 0x03, 0x04, 0x17, 0x00, 0x66, 0x05, 0xDC
>             //    (逗号后面不能有空格，否则格式符不生效)
> 
>             bool isDataValid = ValidateSensorData(sensor);
> 
>             if (isDataValid)
>             {
>                 ProcessSensorData(sensor);
>             }
>         }
> 
>         static bool ValidateSensorData(SensorData data)
>         {
>             // 👈 此处设断点
>             //
>             // 【即时窗口操作】
>             // 输入以下命令并观察结果：
>             // 
>             // > ? data.RawBytes          ← 查看原始字节数组
>             // > data.RawBytes.Length     ← 查看字节数
>             // > BitConverter.ToString(data.RawBytes) ← 格式化的十六进制
>             // > data.RawBytes[0]         ← 查看第一个字节 (0x01 = 设备地址)
>             // > data.RawBytes[2]         ← 查看功能码 (0x04 = 读输入寄存器)
>             // 
>             // 假设发现数据有问题，可以在即时窗口临时修改：
>             // > data.Temperature = 25.0  ← 临时把温度改正常
>             // > data.Pressure = 100      ← 临时把压力改正常
> 
>             bool valid = data.RawBytes.Length >= 8
>                          && data.Temperature is >= 0 and <= 100
>                          && data.Pressure is >= 0 and <= 200;
> 
>             return valid;
>         }
> 
>         static void ProcessSensorData(SensorData data)
>         {
>             // 处理数据（省略）
>         }
>     }
> 
>     public class SensorData
>     {
>         public string DeviceId { get; set; }
>         public double Temperature { get; set; }
>         public int Pressure { get; set; }
>         public int Speed { get; set; }
>         public byte[] RawBytes { get; set; }
>     }
> }
> ```
>
> **实战操作流**：
> ```
> 1. F5 启动 → 停在断点
> 2. 把 sensor 变量拖进「监视1」窗口 → 展开看所有字段
> 3. 在监视窗口中双击 Temperature 的「值」→ 改成 100.5 → 看后续逻辑变化
> 4. Ctrl+Alt+I 打开即时窗口
> 5. 输入 ? DateTime.Now → 看当前时间
> 6. 输入 sensor.RawBytes.Sum(b => (int)b) → 验证校验和
> 7. 发现校验和不符 → 输入 sensor.Temperature = 36.0 修正 → F5 继续
> ```

> [!scene] 适用场景
> ✅ 断点停住后查看任意变量值——监视窗口是最直观的方式
> ✅ 测试表达式——在即时窗口试试 `str.Substring(0, 5)` 会不会越界
> ✅ 临时修改程序状态——在即时窗口把 `isConnected` 改成 `true` 来模拟设备连接状态
> ✅ 诊断数据异常——监视窗口中变量值变红（刚改变的变量），一眼看出哪些值变了
> ✅ 调用静态方法——即时窗口中 `System.IO.File.Exists(@"C:\config.json")`
> ❌ 频繁修改的代码逻辑——即时窗口适合验证，不适合替代正确代码

> [!pitfall] 常见踩坑
> 坑 1：**即时窗口里输入 `? data.Name` 报错「'data' 不存在」** → 即时窗口的上下文是当前断点停住的位置的局部作用域。如果当前在另一个方法中，`data` 不在作用域内。**解决方案**：先在调用堆栈窗口双击切换到 `data` 所在的方法帧，再回即时窗口执行。
>
> 坑 2：**监视窗口里的表达式求值有副作用** → 如果你监视了 `list.RemoveAt(0)`，每次断点停住时调试器都会求值这个表达式——也就是说每次都会真的删除一个元素！**解决方案**：不要在监视窗口中使用有副作用的表达式（修改集合、写文件、发网络请求等）。副作用操作放在即时窗口里手动执行。
>
> 坑 3：**监视窗口中变量显示「无法计算表达式」或卡住** → 可能原因：① 变量在当前作用域中不可用（如被释放的 `using` 块变量）；② 对象的 `ToString()` 实现有问题导致死循环；③ LINQ 查询触发了危险的延迟执行。**解决方案**：关掉该监视项，改用即时窗口手动求值。

> [!best] 最佳实践
> - 4 个监视窗口分组用：Watch1 放核心业务变量，Watch2 放通讯相关，Watch3 放临时排查用——按主题分离，不混淆
> - 监视窗口支持格式化说明符：`value, h`（十六进制）、`value, d`（十进制）、`value, ac`（强制计算，用于属性）
> - 即时窗口的 `?` 前缀是 VB 时代的约定，C# 中可以用也可以不用，但不加 `?` 时可以直接写赋值语句
> - 即时窗口支持 `using` 语句：即使当前文件没 `using System.Linq`，在即时窗口写 `using System.Linq;` 后就能用 LINQ
> - 利用即时窗口验证修复方案：发现 bug 后，先在即时窗口执行你的修复代码看结果对不对，再回源码改

> [!practice] 上手练习
> **Lv.1 照猫画虎**：写一个方法，创建一个包含 5 个数据的 `List<int>`。在遍历前设断点，把 list 拖入监视窗口，展开看元素。在即时窗口中输入 `list.Count`、`list[0]`、`list.Sum()` 观察结果。双击监视窗口中的某个元素值，改成 999，F5 继续看效果。
>
> **Lv.2 小试牛刀**：写一个串口模拟方法，生成一个 `byte[]` 响应帧。在断点处：① 监视窗口用 `rawData, h` 以十六进制查看；② 即时窗口用 `BitConverter.ToString(rawData)` 格式化输出；③ 即时窗口输入 `rawData[1] = 0x04` 临时修改功能码，F5 看看后续解析是否会报错。
>
> **Lv.3 融会贯通**：模拟一个上位机报警判断流程：采集温度数组 `double[] temps`，用 LINQ 判断是否有超标值。在判断逻辑处设断点：① 监视窗口同时监视 `temps.Max()`、`temps.Min()`、`temps.Average()`；② 即时窗口输入 `temps.Where(t => t > 35).ToList()` 查看所有超标值；③ 用即时窗口临时把其中一个超标值改成正常值，验证报警是否消失。
