# 字符串插值

> [!plain] 白话理解
> 字符串插值就是打破字符串的"墙"，把变量直接拎进来。想象你在写一份设备报告，不用 `"设备" + name + "的状态是" + status` 这种绕口令，而是直接 `$"设备{name}的状态是{status}"`——花括号里的东西就是活的、会被求值替换的。`$` 符号像一个"魔术开关"，打开之后，文本里 `{...}` 里的内容就不再是文本，而是 C# 表达式。

> [!def] 官方定义
> 字符串插值（String Interpolation）是 C# 6.0 引入的语法，以 `$` 前缀开头。它允许在字符串字面量中直接嵌入表达式，编译器将其转换为等效的 `string.Format` 调用（或 `FormattableString`）。支持格式说明符（`{value:F1}`）和对齐（`{value,10}`），以及 C# 10 引入的**常量字符串插值**和 C# 11 的**换行插值表达式**。

> [!origin] 由来背景
> 2015年 C# 6.0 发布时，字符串插值是呼声最高的特性之一。在此之前，.NET 开发者已经忍受了 10 多年 `string.Format("{0} {1} {2}", a, b, c)` 的痛苦——加一个参数意味着要小心地调整所有占位符编号。`$""` 让参数顺序直接从视觉上确认，大幅降低出错率。而且 IDE 对插值字符串内的语法高亮和智能提示远优于 `string.Format`。一个有趣的细节：C# 10 引入了**常量字符串插值**——`const string s = $"version {MAJOR}.{MINOR}";`（前提是花括号里也是常量），这让配置字符串的声明终于可以和插值共存。

> [!essentials] 核心要点
> - 语法：`$"文本{表达式}文本"` 或 `$@"多行{表达式}文本"`（逐字字符串+插值）
> - 花括号内可以放任何返回值的 C# 表达式
> - 格式说明符：`{value:F1}`（小数点后1位）、`{value:X4}`（4位十六进制）
> - 对齐：`{value,8}`（右对齐8位）、`{value,-8}`（左对齐8位）
> - 转义花括号：`{{` → `{`，`}}` → `}`
> - `$@"..."` 或 `@$"..."`：逐字字符串（保留换行）配合插值
> - C# 11：插值字符串中的表达式可以换行

> [!example] 完整示例
> ```csharp
> // ========== 基本用法 ==========
> string deviceId = "PLC-001";
> double temp = 85.5;
> bool isOnline = true;

> // 最简单的插值
> Console.WriteLine($"设备 {deviceId} 温度 {temp}℃");

> // 带格式说明符
> Console.WriteLine($"设备 {deviceId} 温度 {temp:F1}℃，状态 {(isOnline ? "在线" : "离线")}");

> // 条件表达式（需加括号）
> Console.WriteLine($"告警等级: {(temp > 80 ? "🔴紧急" : "🟢正常")}");

> // ========== 对齐控制（生成报告表格）==========
> Console.WriteLine($"{"名称",-15}{"温度",8}{"状态",8}");
> Console.WriteLine(new string('-', 31));
> Console.WriteLine($"{"PLC-001",-15}{85.5,8:F1}{"告警",8}");
> Console.WriteLine($"{"温度变送器",-15}{62.0,8:F1}{"正常",8}");
> Console.WriteLine($"{"压力传感器",-15}{23.1,8:F1}{"正常",8}");

> // ========== 嵌入方法调用 ==========
> Console.WriteLine($"当前时间: {DateTime.Now:yyyy-MM-dd HH:mm:ss}");
> Console.WriteLine($"设备名大写: {deviceId.ToUpperInvariant()}");
> Console.WriteLine($"PI 约等于: {Math.PI:F6}");

> // ========== 逐字字符串 + 插值（多行文本）==========
> string report = $@"
> ========== 设备状态报告 ==========
> 时间: {DateTime.Now:yyyy-MM-dd HH:mm:ss}
> 设备: {deviceId}
> 温度: {temp:F1}℃
> 状态: {(isOnline ? "在线" : "离线")}
> ===================================
> ";
> Console.WriteLine(report);

> // ========== 上位机实战：构造 Modbus 命令帧 ==========
> byte slaveAddress = 0x01;
> byte functionCode = 0x03;
> ushort startRegister = 0x0000;
> ushort registerCount = 0x0004;

> // 用插值生成格式化的十六进制命令帧
> string commandFrame = $"{slaveAddress:X2} {functionCode:X2} {startRegister:X4} {registerCount:X4}";
> Console.WriteLine($"\nModbus 命令帧: {commandFrame}");
> // 输出: 01 03 0000 0004

> // ========== 数据包日志（十六进制对齐）==========
> byte[] packetData = { 0x01, 0x03, 0x08, 0x00, 0xFF, 0x00, 0x00, 0x00, 0x01, 0x00, 0x02 };
> Console.WriteLine($"\n接收数据包({packetData.Length}字节):");
> for (int i = 0; i < packetData.Length; i++)
> {
>     // 每8个字节换行
>     string separator = (i > 0 && i % 8 == 0) ? "\n" : "";
>     Console.Write($"{separator}{packetData[i]:X2} ");
> }

> // ========== 复杂计算内嵌 ==========
> double[] samples = { 85.5, 78.2, 92.1, 65.0, 88.8 };
> double avg = samples.Average();
> double max = samples.Max();
> double min = samples.Min();

> Console.WriteLine($"\n\n采样统计: 共{samples.Length}个 | " +
>     $"平均{avg:F1}℃ | 最大{max:F1}℃ | 最小{min:F1}℃ | " +
>     $"波动幅度{max - min:F1}℃ | " +
>     $"超温率{samples.Count(s => s > 80) * 100.0 / samples.Length:F0}%");
> ```

> [!scene] 适用场景
> ✅ 日志输出：`$"[{DateTime.Now:HH:mm:ss}] {level}: {message}"`
> ✅ 数据展示：`$"温度:{temp:F1}℃ 压力:{pressure:F2}MPa"`
> ✅ 协议帧构造：`$"{slave:X2}{func:X2}{addr:X4}{count:X4}"`
> ✅ SQL 参数化提醒（仅用于日志打印，绝不用于拼接 SQL！）
> ✅ 异常消息：`throw new Exception($"设备{id}通信超时,已重试{retry}次")`
> ❌ 构建 SQL 查询字符串（应该用参数化查询！）

> [!pitfall] 常见踩坑
> 坑 1：**逐字字符串+插值的顺序** → `$@"..."` 和 `@$"..."` 两种写法都可以，但 `$` 在 `@` 前面更常见。注意 `@$"path\{name}"` 里的反斜杠不会被转义，但 `{name}` 仍然被插值处理。
>
> 坑 2：**FormatException：格式说明符用了不兼容的类型** → `$"{123:X}"` ✅ `$"{123.5:X}"` ❌ 浮点数不能用十六进制格式。编译器不能检查所有运行时格式错误。
>
> 坑 3：**性能陷阱：`$""` 在热点路径中** → 每次 `$""` 都会调用 `string.Format`，在每秒 10 万次调用的循环里，这会产生大量临时字符串。换成 `StringBuilder` 或结构化日志框架。

> [!best] 最佳实践
> - 字符串构造的默认选择永远是 `$""` 插值
> - 格式对齐：左对齐用负数宽度 `{value,-10}`，右对齐用正数 `{value,10}`
> - 十六进制输出：`{value:X2}` 保证每个字节两位（`0x0A` 不是 `0xA`）
> - 复杂表达式在 `{ }` 中应该简单（不超过 1 行），太复杂就抽成变量
> - 异常消息中带上关键参数值：`throw new TimeoutException($"设备{id} {timeout}ms超时")`
> - 上位机日志建议用结构化日志框架（Serilog/NLog），它们原生支持插值且性能更好

> [!practice] 上手练习
> **Lv.1 照猫画虎**：定义 `string name`、`int age`、`double score`，用插值输出一句话自我介绍（含年龄和分数保留1位小数）
> **Lv.2 小试牛刀**：用插值输出九九乘法表，要求对齐（每列右对齐2位），不嵌套循环的代码也全用插值
> **Lv.3 融会贯通**：构造一个 Modbus RTU 读取命令的完整十六进制字符串（`01 03 0000 0004 + CRC16`），各字段用变量定义，CRC 计算结果也通过插值嵌入。输出"发送"和"预期响应"两行完整帧
