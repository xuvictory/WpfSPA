# 比较运算符

> [!plain] 白话理解
> 比较运算符就是程序里的"判断题"——"温度超过 80 了吗？"、"两个压力传感器的读数一样吗？"、"设备状态不是 Running 吧？"。它们永远返回 `true` 或 `false`（布尔值），是 `if`、`while`、`switch` 这些流程控制语句的燃料。没有比较运算符，程序就像没有感官的机器人——它不知道外界发生了什么，只能机械地一路执行到底。

> [!def] 官方定义
> C# 的比较运算符用于比较两个值的大小或相等关系，返回 `bool` 类型结果：
> - `==` 等于 / `!=` 不等于
> - `>` 大于 / `<` 小于 / `>=` 大于等于 / `<=` 小于等于
> - `is` 类型检测运算符 / `as` 类型转换运算符
> - 对于值类型：比较的是**值本身**
> - 对于引用类型：`==` 默认比较**引用地址**（但 `string` 重载了 `==` 比较内容）

> [!origin] 由来背景
> `==` 和 `Equals()` 的"双轨制"是 C# 设计中最微妙的地方之一。`==` 是静态运算符，在编译时就确定了调用哪个版本；`Equals()` 是虚方法，运行时多态。这意味着 `object a = 5; object b = 5; a == b` 返回 `false`（比较引用），而 `a.Equals(b)` 返回 `true`（调用 `int.Equals` 比较值）。这个差异是 .NET 从 Java 继承来的设计遗产，也是面试高频考点。对新手来说记住一条就够了：同类型比较用 `==`，涉及 `object` 类型用 `Equals()`。

> [!essentials] 核心要点
> - 所有比较运算符返回 `bool`（true/false）
> - `=` 是赋值，`==` 是判等——新人最容易犯的错误
> - `double.NaN == double.NaN` 结果是 `false`！用 `double.IsNaN()` 判断
> - 浮点数不要用 `==` 比较，用 `Math.Abs(a - b) < 0.0001` 判断"足够接近"
> - `string` 的 `==` 比较内容（C# 特例），但大小写敏感
> - 引用类型默认 `==` 比较引用地址，需要比较内容请重写 `Equals`

> [!example] 完整示例
> ```csharp
> // ========== 基本比较 ==========
> int temp = 85;
> Console.WriteLine(temp > 80);    // True  — 高温告警
> Console.WriteLine(temp <= 60);   // False — 不在安全范围
> Console.WriteLine(temp == 85);   // True  — 恰好等于阈值

> // ========== 浮点数比较的陷阱 ==========
> double a = 0.1 + 0.2;
> double b = 0.3;
> Console.WriteLine(a == b);       // False！浮点精度问题
> Console.WriteLine(Math.Abs(a - b) < 0.0001); // True，正确比较方式

> // NaN 的特殊性
> Console.WriteLine(double.NaN == double.NaN);  // False！
> Console.WriteLine(double.IsNaN(double.NaN));  // True，这才是正确方法

> // ========== 字符串比较 ==========
> string s1 = "Plc-001";
> string s2 = "PLC-001";
> Console.WriteLine(s1 == s2);                          // False，大小写不同
> Console.WriteLine(s1.Equals(s2, StringComparison.OrdinalIgnoreCase)); // True

> // ========== 引用类型的 == 陷阱 ==========
> object obj1 = 100;
> object obj2 = 100;
> Console.WriteLine(obj1 == obj2);    // False！object 的 == 比较引用地址
> Console.WriteLine(obj1.Equals(obj2)); // True，Equals 被 int 重写了

> // ========== 连写比较（C# 不支持数学式连写）==========
> int value = 50;
> // if (0 < value < 100)  // ❌ 在 C# 中不是合法写法！
> if (value > 0 && value < 100)  // ✅ 必须分开写
>     Console.WriteLine("值在 0~100 范围内");

> // ========== 上位机实战：设备状态判断 ==========
> enum DeviceState { Offline, Idle, Running, Alarm }

> DeviceState state = DeviceState.Running;

> // bool 变量命名惯例：以 Is/Has/Can/Should 开头
> bool isRunning = state == DeviceState.Running;
> bool needsAttention = state == DeviceState.Alarm || state == DeviceState.Offline;
> bool isNormal = state == DeviceState.Idle || state == DeviceState.Running;

> Console.WriteLine($"运行中: {isRunning}, 需关注: {needsAttention}, 正常: {isNormal}");

> // 范围判断：窗口告警（温度在 60~80 是偏高，>80 报警）
> double temp1 = 75.5;
> bool inWarningRange = temp1 > 60 && temp1 <= 80;  // 黄色告警区间
> bool inAlarmRange = temp1 > 80;                     // 红色告警区间
> string level = inAlarmRange ? "红色告警" : (inWarningRange ? "黄色告警" : "正常");
> Console.WriteLine($"{temp1}℃ → {level}");
> ```

> [!scene] 适用场景
> ✅ 传感器阈值判断：`temperature > alarmThreshold`
> ✅ 数据过滤：`samples.Where(s => s > 0)` 
> ✅ 状态机转换条件：`if (currentState == State.Idle && commandReceived)`
> ✅ 数据校验：`if (parsedValue != null && parsedValue >= minValue)`
> ❌ 精确的浮点值判等（用容差法代替 `==`）
> ❌ 复杂对象的深度比较（用 `IEquatable<T>` 或 `IComparable<T>` 接口）

> [!pitfall] 常见踩坑
> 坑 1：**`if (x = 5)` 而不是 `if (x == 5)`** → 这个在 C# 中是编译错误（`int` 不能隐式转 `bool`），算是微软帮你挡了一枪。但 `if (flag = true)` 编译不过这点让很多 C/C++ 转过来的开发者不适应。
>
> 坑 2：**`NaN` 让所有比较失效** → `NaN > 0`、`NaN < 0`、`NaN == NaN` 全是 `false`！如果你有一个传感器读数列，只要混入一个 `NaN`，排序结果就全乱了。解决：先 `double.IsNaN()` 过滤。
>
> 坑 3：**忽略 `StringComparison` 参数** → `"straße".Equals("STRASSE")` 在有些文化下返回 `true`！上位机中设备 ID 的匹配永远用 `StringComparison.Ordinal` 或 `OrdinalIgnoreCase`，不要依赖当前系统文化设置。

> [!best] 最佳实践
> - 比较两个 `double` 的"相等"：`Math.Abs(a - b) < 1e-6`
> - 比较两个 `string` 忽略大小写：`a.Equals(b, StringComparison.OrdinalIgnoreCase)`
> - 检查变量是否在范围内：`if (min <= x && x <= max)` 而不是写反 `if (min <= x <= max)`
> - 布尔变量命名：`isRunning`、`hasError`、`canConnect`——阅读代码时一看就知道是 bool
> - 用 `is` 代替 `==` 判断枚举：`state is DeviceState.Running` 更现代（C# 7.0+）
> - 大量比较判断时考虑用 `switch` 表达式替代嵌套 `if-else`

> [!practice] 上手练习
> **Lv.1 照猫画虎**：定义温度值 `78.5`，写三个布尔表达式：是否>80、是否在60~80、是否为整数，打印结果
> **Lv.2 小试牛刀**：创建一个 `SensorValidator` 方法，输入传感器读数值，返回校验结果：NaN→无效、负数→传感器故障、>1000→超出量程、0~1000→正常。先用 if-else 写，再用 switch 表达式重写
> **Lv.3 融会贯通**：用数组存 10 个传感器温度读数（包含正常值、NaN、负数、超大值），写一个"数据质量报告"方法，统计正常/超标/NaN/负数各多少个
