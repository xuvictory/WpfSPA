# 三元运算符与空合并运算符

> [!plain] 白话理解
> 三元运算符 `?:` 是一个"压缩版的 if-else"——把"如果...那么...否则..."浓缩成一行。`??` 空合并运算符更专一：它只关心"左边是不是 null？是 null 就用备胎（右边），不是就用原值"。比如 `string name = input ?? "未知设备";` —— 有名字就显示名字，没名字就叫"未知设备"。这两个运算符的共同目标：消灭那些"只有两行但占五行的 if-else"，让代码更紧凑但同样清楚。

> [!def] 官方定义
> - **三元（条件）运算符 `condition ? trueValue : falseValue`**：计算 `condition`，若为 `true` 返回 `trueValue`，否则返回 `falseValue`。要求 `trueValue` 和 `falseValue` 类型兼容。
> - **空合并运算符 `left ?? right`**：若 `left` 不为 `null` 返回 `left`；否则返回 `right`。要求 `left` 是可空类型，`right` 是同类型的非空值。
> - **空合并赋值 `left ??= right`**（C# 8.0）：若 `left` 为 `null`，将 `right` 赋给 `left`。
> - **空条件运算符 `obj?.Property`**（C# 6.0）：若 `obj` 为 `null`，整个表达式返回 `null`，不访问 `Property`。

> [!origin] 由来背景
> 三元运算符 `?:` 诞生于 C 语言，是早期程序员对抗"代码膨胀"的重要武器。但它的真正繁荣在 C# 中——配合 LINQ、lambda、属性初始化器等现代语法，`?:` 几乎出现在每一行非平凡的代码中。`??` 则是 C# 2.0 的原创，灵感来自数据库的 `COALESCE` 函数和 Perl 的 `//` 运算符。`?.` 空条件运算符更是革命性——它让"防御式 null 检查"从多层嵌套的噩梦变成了一行优雅链式调用。这三者结合，让 C# 的 null 处理从"啰嗦但安全"进化到"简洁且安全"。

> [!essentials] 核心要点
> - `?:` 三元：`condition ? valueIfTrue : valueIfFalse` —— 必有三分支，不能省略
> - `??` 空合并：`possibleNull ?? fallbackValue` —— 左边 null 就用右边
> - `??=` 空合并赋值：`x ??= defaultValue;` —— 等价于 `x = x ?? defaultValue;`
> - `?.` 空条件：`obj?.Prop` —— obj 为 null 时返回 null，不崩
> - `?[]` 空条件索引：`arr?[0]` —— arr 为 null 时返回 null
> - 可链式使用：`person?.Address?.City ?? "未知城市"`
> - 三元可嵌套，但不要超过两层（可读性急剧下降）

> [!example] 完整示例
> ```csharp
> // ========== 三元运算符 ?: ==========
> int temperature = 85;
> string status = temperature > 80 ? "高温告警" : "正常";
> Console.WriteLine(status);  // 高温告警

> // 传统 if-else 等效写法（4行 vs 1行）：
> // string status;
> // if (temperature > 80)
> //     status = "高温告警";
> // else
> //     status = "正常";

> // ========== 空合并运算符 ?? ==========
> string? deviceName = null;
> string displayName = deviceName ?? "未命名设备";
> Console.WriteLine(displayName);  // 未命名设备

> deviceName = "PLC-001";
> displayName = deviceName ?? "未命名设备";
> Console.WriteLine(displayName);  // PLC-001

> // 链式 ?? ：多个备选，找到第一个非空值
> string? configValue = null;
> string? envValue = null;
> string final = configValue ?? envValue ?? "硬编码默认值";
> Console.WriteLine(final);  // 硬编码默认值

> // ========== ?. 空条件运算符 ==========
> string? serialData = null;
> int? length = serialData?.Length;   // null，不崩
> Console.WriteLine($"数据长度: {length?.ToString() ?? "无数据"}");

> // 链式安全访问 —— 上位机配置导航的经典写法
> public class DeviceNode
> {
>     public string? Name { get; set; }
>     public DeviceNode? SubDevice { get; set; }
>     public SensorData? Sensor { get; set; }
> }
> public class SensorData
> {
>     public double? Value { get; set; }
> }

> DeviceNode? root = new DeviceNode 
> { 
>     Name = "主控", 
>     SubDevice = new DeviceNode { Name = "子站" } 
> };

> // 安全穿越 null 引用链
> double? sensorReading = root?.SubDevice?.Sensor?.Value ?? 0.0;
> Console.WriteLine($"传感器读数: {sensorReading}");  // 0.0（Sensor 为 null）

> // ========== 上位机实战：告警状态到 UI 文本的映射 ==========
> enum AlarmLevel { Normal, Warning, Critical }

> AlarmLevel level = AlarmLevel.Warning;

> // 三元运算符做枚举到文本的映射（简单的场景）
> string message = level switch
> {
>     AlarmLevel.Normal   => "✅ 运行正常",
>     AlarmLevel.Warning  => "⚡ 注意：参数偏高",
>     AlarmLevel.Critical => "🔴 紧急：立即停机",
>     _                   => "❓ 未知状态"
> };

> // 或者是简单的二元判断用三元
> ConsoleColor color = level == AlarmLevel.Critical ? ConsoleColor.Red
>                    : level == AlarmLevel.Warning  ? ConsoleColor.Yellow
>                    :                                ConsoleColor.Green;
> // 但不要嵌套超过两层！

> // ========== 组合使用：工业配置的完整解析 ==========
> // 解析 Modbus 配置，每个字段都有默认值兜底
> public void ParseModbusConfig(string? ip, int? port, int? timeout, string? name)
> {
>     string finalIp = ip ?? "192.168.1.100";
>     int finalPort = port ?? 502;
>     int finalTimeout = timeout ?? 3000;
>     string finalName = (name?.Trim() ?? "").Length > 0 ? name : $"设备{finalIp}:{finalPort}";
>     // 三元：用户给了名字就用，没给就自动生成
    
>     Console.WriteLine($"连接 {finalName} @ {finalIp}:{finalPort}，超时{finalTimeout}ms");
> }

> ParseModbusConfig(null, null, null, null);
> // 输出：连接 设备192.168.1.100:502 @ 192.168.1.100:502，超时3000ms
> ```

> [!scene] 适用场景
> ✅ `?:`：简单的二选一赋值（如"正常/告警"、"启用/禁用"、"是/否"）
> ✅ `??`：为可空值提供默认值（配置项、用户输入、数据库查询结果）
> ✅ `?.`：访问可能为 null 的对象链（设备树导航、复杂对象的属性访问）
> ✅ `??=`：配置初始化时的默认值填充
> ❌ `?:` 嵌套超过两层 → 用 `switch` 表达式或抽出方法
> ❌ 三元运算符里有方法调用 → 可读性差，改用 if-else

> [!pitfall] 常见踩坑
> 坑 1：**三元两边类型不一致** → `var result = condition ? 5 : "hello";` ❌ 编译器不知道 result 该是 int 还是 string。但 `var result = condition ? 5 : 0;` ✅（两边都是 int）<br>
> 注意：`var x = condition ? 5 : 5.0;` 会推断为 `double`（int 可隐式转 double）。
>
> 坑 2：**`?.` 的返回值是可空类型** → `int length = text?.Length;` ❌ 右边是 `int?`。正解：`int length = text?.Length ?? 0;`
>
> 坑 3：**`??` 的短路特性+方法调用** → `var result = GetValue() ?? ExpensiveFallback();`。如果 `GetValue()` 返回非空，`ExpensiveFallback()` 不会执行。利用这个特性可以做懒加载，但也要小心别依赖没有保证的副作用。

> [!best] 最佳实践
> - `??` 是给默认值的首选语法，比三目 `x != null ? x : default` 更简洁
> - `?.` + `??` 组合消除 null 检查地狱：
>   ```csharp
>   string city = person?.Address?.City ?? "未知城市"; // 1行替代5行if
>   ```
> - 三元嵌套不超过一层，超了改用 `switch` 表达式或抽出方法
> - 三元运算符的 `trueValue` 和 `falseValue` 应该是简单表达式，不要放方法调用
> - 属性的 getter 中 `??` 很常用：`get => _cache ??= ComputeExpensive();`（懒加载模式）
> - 上位机代码尤其善用 `?.`：配置缺失、设备离线、数据为空是常态，不是异常

> [!practice] 上手练习
> **Lv.1 照猫画虎**：定义 `string? name = null;`，分别用 `??`、`??=`、`?.` 操作它，打印每个操作的结果
> **Lv.2 小试牛刀**：创建一个三层嵌套的设备结构（设备→模块→通道），用 `?.` + `??` 链式安全访问最深层的通道值，值为 null 时显示"未配置"
> **Lv.3 融会贯通**：实现一个上位机配置解析器，输入全是 `string?` 类型字段（从 JSON 解析来的），输出是强类型的 `DeviceConfig` 对象。要求：IP 缺失用默认值、端口非数字用默认值、设备名缺失自动生成，全部用 `??` 和 `?:` 一行搞定
