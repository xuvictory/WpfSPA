# 类库项目的作用

> [!plain] 白话理解
> 类库项目就像你家的「工具箱」——里面装着各种趁手的工具（类和方法），平时收纳在柜子里不碍事，要用的时候拿出来就能干活。比如你把 Modbus 协议解析、CRC16 校验、数据格式转换这些通用功能写成一个类库项目，编译成 `PlcUtils.dll`。以后不管开发几个上位机，直接把 DLL 引进来就能用，不用再 Ctrl+C / Ctrl+V 代码。类库是你从「写代码」到「搭积木」的关键一步。

> [!def] 官方定义
> 类库项目（Class Library）是一种编译输出为 `.dll`（动态链接库）而非 `.exe` 的 .NET 项目类型。它不包含程序入口点（`Main` 方法），仅提供类型定义（类、接口、枚举、结构体）供其他项目引用。创建方式：`dotnet new classlib -n 项目名`，.csproj 中 `<OutputType>Library</OutputType>`。

> [!origin] 由来背景
> 代码复用是软件工程最古老的需求之一。从 C 语言的 `.h/.c` 文件对，到 C++ 的静态库（`.lib`）和动态库（`.dll`），再到 .NET 的程序集（Assembly），本质上都在做同一件事：把可复用的代码打包、分发、版本化。.NET 的类库相比传统 DLL 有两大优势：① 平台无关（编译成 IL 中间代码，.NET 运行时负责 JIT 编译，不绑定机器架构）；② 元数据丰富（DLL 自带反射信息，你引用后 VS 的智能提示就能列出所有公开类型和方法）。

> [!essentials] 核心要点

> **类库项目 vs WPF 项目的关键区别**：

> | 维度 | WPF 项目 | 类库项目 |
> |------|---------|---------|
> | 输出文件 | `.exe` | `.dll` |
> | 有窗口吗 | 有 (`Window`) | 没有 |
> | 能独立运行 | 能 | 不能（需要宿主程序） |
> | 程序入口 | `App.xaml` → `Main()` | 无 |
> | 引用方向 | 被其他项目调用 | 仅被调用，不调用别人（或调用更底层的库） |
> | .csproj 标记 | `<UseWPF>true</UseWPF>` | 无特殊标记 |
> | 创建命令 | `dotnet new wpf` | `dotnet new classlib` |

> **上位机项目中的典型类库**：

> | 类库名 | 包含内容 | 举例 |
> |--------|---------|------|
> | `Xxx.Models` | 数据模型（POCO 类） | `DeviceInfo`, `AlarmRecord`, `PlcRegister` |
> | `Xxx.Services` | 业务服务层 | `PlcCommunicationService`, `DataLogService` |
> | `Xxx.Protocols` | 通讯协议实现 | Modbus RTU/TCP, OPC UA, Siemens S7 |
> | `Xxx.Utils` | 工具类 | CRC16, 字节转换, 数据校验 |
> | `Xxx.Data` | 数据访问层 | 数据库读写, 文件存储 |

> [!example] 完整示例
>
> **创建上位机通讯协议类库**：
> ```bash
> dotnet new classlib -n PlcMonitor.Protocols -o src/PlcMonitor.Protocols
> ```
>
> ```csharp
> // Protocols/ModbusHelper.cs — 编译成 PlcMonitor.Protocols.dll
> using System;
> 
> namespace PlcMonitor.Protocols
> {
>     /// <summary>
>     /// Modbus 协议工具类——任何上位机项目都能引用
>     /// </summary>
>     public static class ModbusHelper
>     {
>         /// <summary>
>         /// 计算 Modbus CRC16 校验码
>         /// </summary>
>         public static ushort CalculateCRC16(byte[] data)
>         {
>             ushort crc = 0xFFFF;
>             foreach (byte b in data)
>             {
>                 crc ^= b;
>                 for (int i = 0; i < 8; i++)
>                 {
>                     if ((crc & 0x0001) != 0)
>                     {
>                         crc >>= 1;
>                         crc ^= 0xA001;
>                     }
>                     else
>                     {
>                         crc >>= 1;
>                     }
>                 }
>             }
>             return crc;
>         }
> 
>         /// <summary>
>         /// 构建 Modbus RTU 读取保持寄存器的请求帧
>         /// </summary>
>         public static byte[] BuildReadHoldingRegistersRequest(
>             byte slaveId, ushort startAddress, ushort quantity)
>         {
>             byte[] frame = new byte[8];
>             frame[0] = slaveId;                         // 从站地址
>             frame[1] = 0x03;                            // 功能码：读保持寄存器
>             frame[2] = (byte)(startAddress >> 8);       // 起始地址高字节
>             frame[3] = (byte)(startAddress & 0xFF);     // 起始地址低字节
>             frame[4] = (byte)(quantity >> 8);           // 寄存器数量高字节
>             frame[5] = (byte)(quantity & 0xFF);         // 寄存器数量低字节
> 
>             // CRC16 校验
>             ushort crc = CalculateCRC16(frame, 6);
>             frame[6] = (byte)(crc & 0xFF);
>             frame[7] = (byte)(crc >> 8);
> 
>             return frame;
>         }
> 
>         /// <summary>
>         /// 将两个寄存器的值组合为 32 位浮点数（大端序）
>         /// </summary>
>         public static float RegistersToFloat(ushort regHigh, ushort regLow)
>         {
>             byte[] bytes = new byte[4];
>             bytes[0] = (byte)(regHigh >> 8);
>             bytes[1] = (byte)(regHigh & 0xFF);
>             bytes[2] = (byte)(regLow >> 8);
>             bytes[3] = (byte)(regLow & 0xFF);
>             return BitConverter.ToSingle(bytes, 0);
>         }
>     }
> }
> ```
>
> **在其他项目中引用这个类库**：
> ```csharp
> // 在 WPF 项目的 MainWindow.xaml.cs 中
> using PlcMonitor.Protocols;
> 
> // 构建读取 D100 寄存器的 Modbus 指令
> byte[] request = ModbusHelper.BuildReadHoldingRegistersRequest(
>     slaveId: 1, startAddress: 100, quantity: 2);
> 
> Console.WriteLine($"发送指令：{BitConverter.ToString(request)}");
> // 输出：发送指令：01-03-00-64-00-02-85-CA
> ```

> [!scene] 适用场景
> ✅ 代码复用：多个 WPF 项目共用同一个 Models 类库
> ✅ 架构分层：界面层（App）→ 业务层（Services）→ 数据层（Models），每层一个类库
> ✅ 团队分工：通讯组维护 `Protocols` 库，UI 组用它的 API 即可
> ✅ 测试友好：测试项目可以直接引用 Services/Models 类库，不需要启动 WPF 界面
> ❌ 只有几个简单类的项目——没必要为 3 个 class 单独建库

> [!pitfall] 常见踩坑
> 坑 1：**创建了类库但 WPF 项目里引用后找不到类型** → 检查三件事：① 类库中的类是否声明为 `public`（默认 `internal` 类库外看不到）；② 是否在 WPF 项目中添加了项目引用；③ 是否在代码文件顶部加了 `using` 命名空间。
>
> 坑 2：**类库的命名空间和文件夹结构不一致** → `Models/Data/DeviceInfo.cs` 在 `Models` 类库中，如果用 `namespace PlcMonitor.Models` 而不是 `namespace PlcMonitor.Models.Data`，使用时路径会让人困惑。建议让命名空间和文件夹结构保持一致。
>
> 坑 3：**类库中引了大重量 NuGet 包，导致引用它的项目编译慢** → 类库会「传染」它的 NuGet 依赖给引用者。如果类库引用了整个 Entity Framework，那引用它的 WPF 项目也会拉下 EF，即使根本不需要。**解决方案**：慎选类库的依赖，不要为了一个方法引入一个重型框架。

> [!best] 最佳实践
> - 一个类库一个职责：不要搞「Common」「Utils」这种万能垃圾篓类库
> - 接口定义在类库中：`ICommunicationService` 定义在 `Protocols` 库中，具体实现在 `Services` 库中，依赖反转
> - 类库的 TargetFramework 统一：所有项目用相同的 .NET 版本，避免兼容问题
> - 类库的 API 设计：只公开需要的方法（`public`），内部实现细节保持 `private/internal`，降低耦合
> - 用 XML 文档注释：类库是给别人（包括三个月后的自己）用的，写清楚每个 public 方法是干什么的

> [!practice] 上手练习
> **Lv.1 照猫画虎**：创建一个名为 `MyScadaUtils` 的类库项目，在里面写一个 `MathHelper` 静态类，包含一个方法 `CelsiusToFahrenheit(double c)` 把摄氏度转华氏度。在 WPF 项目中引用这个类库，并在按钮点击事件中调用转换方法显示结果。
>
> **Lv.2 小试牛刀**：在类库中添加一个 `ByteConverter` 工具类，实现 `HexStringToBytes(string hex)` 方法（把 "01 03 00 64" 转成 `byte[]`）。在 WPF 中模拟串口数据解析：输入十六进制字符串 → 调用方法转换 → 显示字节数组。
>
> **Lv.3 融会贯通**：创建两个类库 `MyScada.Models` 和 `MyScada.Protocols`。Models 中定义 `RegisterValue` 类（地址、值、单位）。Protocols 引用 Models，实现 `ParseRegisterResponse(byte[] data)` 方法返回 `List<RegisterValue>`。WPF 项目引用 Protocols，实现完整的「发送指令 → 解析响应 → 显示数据」流程。
