# 选择类控件对比指南

> [!plain] 白话理解
> "单选用哪个？多选用哪个？要不要表格？"——选择类控件家族（ComboBox / ListBox / ListView / RadioButton / CheckBox）看起来功能重叠，其实各有所长。选错了，轻则界面别扭，重则操作员误选引发事故。
> 决策逻辑其实很简单：**选项少且可见**用 RadioButton（一组排开）；**选项多要省空间**用 ComboBox（收起一行）；**要常驻列表多选**用 ListBox；**要多列表格展示**用 ListView；**独立开关可多项勾选**用 CheckBox。本指南把这些维度一次性讲透。

> [!def] 官方定义
> 本指南不是新控件，而是对 WPF 选择类控件族（均位于 `System.Windows.Controls`）的横向对比。核心成员：`ComboBox`（`Selector`，下拉单选，省空间）、`ListBox`（`Selector`，常驻列表，单选/多选）、`ListView`（`ListBox` 子类，`View=GridView` 多列表格）、`RadioButton`（`ToggleButton` 子类，组内互斥单选）、`CheckBox`（`ToggleButton` 子类，独立多选/三态）。决策维度：可见性、选项数、多选需求、表格需求、空间预算。
> 官方资料：https://learn.microsoft.com/zh-cn/dotnet/desktop/wpf/controls/

> [!origin] 由来背景
> 每个选择类控件都是针对"特定选择交互"优化的产物，但新开发者面对它们时最常问"该用哪个"。WinForms 时代的选择控件各成体系、绑定方式互不相同，选型全靠经验；WPF 将它们统一在 `Selector`（单选/多选）与 `ToggleButton`（互斥/独立）两条继承线上，交互语义清晰后，"选型"变成"按需求匹配维度"。本指南正是把这种匹配规则显式化：上位机里"通信方式必选其一→RadioButton""采样档位多且省空间→ComboBox""报警批量确认→ListBox""设备台账表格→ListView"，避免凭感觉选控件。

> [!essentials] 核心要点
> - **RadioButton：必选其一、选项可见**（≤5 个），组内互斥
> - **ComboBox：选项多、要省空间**，收起一行、展开选择
> - **ListBox：常驻列表 + 选择/多选**，需要可滚动、可 Ctrl/Shift 多选
> - **ListView：多列表格**，多条记录多字段一览无余，可排序
> - **CheckBox：独立开关/多项勾选**，可三态（部分选中）
> - **共同基础**：都支持 `ItemsSource` + `ItemTemplate`（RadioButton/CheckBox 为 ToggleButton 族，用 `IsChecked`）

> [!example] 完整示例
> **一个界面同时演示四种选择控件的适用差异：ComboBox 省空间、ListBox 常驻多选、ListView 表格化：**
>
> **MainWindow.xaml：**
> ```xml
> <Window x:Class="HmiDemo.MainWindow"
>         xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
>         xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
>         Title="选择控件对比 - ComboBox/ListBox/ListView" Height="520" Width="760"
>         WindowStartupLocation="CenterScreen" Background="#0D1117">
>     <Grid Margin="12">
>         <Grid.ColumnDefinitions>
>             <ColumnDefinition Width="2*"/>
>             <ColumnDefinition Width="10"/>
>             <ColumnDefinition Width="3*"/>
>         </Grid.ColumnDefinitions>
>
>         <!-- 左栏：ComboBox 单选 + ListBox 多选 -->
>         <StackPanel Grid.Column="0">
>             <TextBlock Text="ComboBox：空间紧凑，适合下拉单选" Foreground="#8B949E"/>
>             <ComboBox x:Name="cmbDevice" DisplayMemberPath="Name" Margin="0,4,0,12"
>                       Background="#161B22" Foreground="White" Padding="4"/>
>
>             <TextBlock Text="ListBox：常驻展示，支持多选" Foreground="#8B949E"/>
>             <ListBox x:Name="lstDevice" SelectionMode="Extended" Height="180"
>                      DisplayMemberPath="Name" Background="#161B22" Foreground="White"/>
>         </StackPanel>
>
>         <!-- 右栏：ListView 表格 -->
>         <ListView x:Name="lvDevice" Grid.Column="2" Background="#161B22"
>                   Foreground="White" BorderBrush="#2A4A6C" BorderThickness="1">
>             <ListView.View>
>                 <GridView>
>                     <GridViewColumn Header="编号" Width="80" DisplayMemberBinding="{Binding Id}"/>
>                     <GridViewColumn Header="名称" Width="140" DisplayMemberBinding="{Binding Name}"/>
>                     <GridViewColumn Header="状态" Width="90" DisplayMemberBinding="{Binding Status}"/>
>                 </GridView>
>             </ListView.View>
>         </ListView>
>     </Grid>
> </Window>
> ```
>
> **MainWindow.xaml.cs —— 后台代码：**
> ```csharp
> using System.Collections.Generic;
> using System.Windows;
>
> namespace HmiDemo
> {
>     public partial class MainWindow : Window
>     {
>         public MainWindow()
>         {
>             InitializeComponent();
>
>             // 同一份数据源可以同时喂给三种控件
>             var devices = new List<Device>
>             {
>                 new Device { Id = "D1", Name = "电机 M-101", Status = "运行" },
>                 new Device { Id = "D2", Name = "变频器 V-202", Status = "运行" },
>                 new Device { Id = "D3", Name = "传感器 S-303", Status = "待机" }
>             };
>             cmbDevice.ItemsSource = devices;
>             lstDevice.ItemsSource = devices;
>             lvDevice.ItemsSource = devices;
>         }
>     }
>
>     public class Device
>     {
>         public string Id { get; set; }
>         public string Name { get; set; }
>         public string Status { get; set; }
>     }
> }
> ```

> [!scene] 适用场景
> ✅ 选型决策：新界面要"选一个控件"时的快速对照参考
> ✅ 需求评审：用维度表检查"这个选择控件是否合适"
> ✅ 面试/知识梳理：把 5 个选择控件的关系一次性理清
> ✅ 代码评审：指出同事"用 ListBox 装 3 个固定选项"这类欠妥选型
> ❌ 学习单个控件的细节用法（去读对应控件专篇）
> ❌ 需要执行代码的具体练习（用专篇示例）

> [!pitfall] 常见踩坑
> 坑 1：**选项多却用 RadioButton** → 面板被撑爆，操作员还得挨个找。原因：没考虑空间与查找效率。解决：>5 个选项用「combobox-下拉选择框」
>
> 坑 2：**多选需求用了 ComboBox** → 只能选一个，交互受限。原因：ComboBox 是单选。解决：多选用「listbox-列表框」（`SelectionMode`）或 CheckBox 组
>
> 坑 3：**表格数据用了 ListBox** → 字段挤在一行看不全。原因：ListBox 是单列。解决：多字段用「listview-列表视图」（GridView）
>
> 坑 4：**"必选其一"却用 CheckBox 组** → 用户能全不选/多选，业务校验复杂。原因：CheckBox 语义是独立多选。解决：互斥用 RadioButton 或 ComboBox，CheckBox 只用于"可多可少"的勾选

> [!best] 最佳实践
> - 选型先问三个问题：能否多选？选项多少？要不要表格？再决定控件
> - "必选其一且可见" → RadioButton；"必选其一且选项多" → ComboBox
> - "多项选择/批量操作" → ListBox；"多字段表格" → ListView
> - "独立开关/部分选中" → CheckBox（三态表达中间态）
> - 定下选型后，去对应控件专篇抄示例，本指南只负责"指路"

> [!practice] 上手练习
> **Lv.1 照猫画虎**：运行示例，观察 5 个控件在同一个界面中的布局差异与选择行为
> **Lv.2 小试牛刀**：给每个控件补一个典型上位机场景的注释（协议选择/报警确认/设备台账等），验证选型直觉
> **Lv.3 融会贯通**：设计一个"采样配置"面板：协议（RadioButton）、采样频率（ComboBox）、启用通道（CheckBox 组）、历史报警（ListView），逐项说明选型理由
> **Lv.4 挑战**：写一份"选择控件速查表"（Markdown）：按 需求维度 × 控件 × 关键属性 三列整理，作为团队新人的选型手册
