# 焦点管理

> [!plain] 白话理解
> 焦点就像**现场操作员手里的"接力棒"**：某一时刻只有一个人（一个控件）握得住键盘——按键、回车都先落到它手里。上位机里最常见的场景是参数录入：操作员希望一开机光标就在"设备编号"框里，按 Tab 依次跳到转速、温度，填完自动校验。示例里的 `DeviceNoBox.Focus()` 就是把接力棒塞给第一个输入框；`GotFocus`/`LostFocus` 相当于交接棒瞬间的哨声，可用来做数据预填、合法性校验。不注意焦点管理，就会变成"鼠标点哪儿光标才到哪儿"，批量录入时操作员手都要酸了。

> [!def] 官方定义
> 焦点管理指 WPF 中对**键盘焦点（Keyboard Focus）**与**逻辑焦点（Logical Focus）**的分配与控制。键盘焦点指向当前接收键盘输入的单个元素，`FocusManager` 静态类提供 `GetFocusedElement`/`SetFocusedElement`；逻辑焦点可同时落在多个元素上（如每个焦点作用域各有一个）。控件通过 `UIElement.Focus()` 请求键盘焦点，`GotFocus`/`LostFocus` 事件在焦点转移时触发，`IsKeyboardFocused`/`IsKeyboardFocusWithin` 等属性反映焦点状态。Tab 键顺序由 `TabIndex`/`KeyboardNavigation.TabNavigation` 控制。详见官方文档：[焦点概述](https://learn.microsoft.com/zh-cn/dotnet/desktop/wpf/advanced/focus-overview)、[FocusManager 类](https://learn.microsoft.com/zh-cn/dotnet/api/system.windows.input.focusmanager)。

> [!origin] 由来背景
> 焦点是图形界面自命令行时代就存在的核心概念：终端里"当前光标位置"演化成 GUI 的"当前活动窗口/活动控件"。WinForms 用 `ActiveControl` 加 `TabIndex` 管理焦点，但 WPF 2006 年随 .NET Framework 3.0 发布时，把焦点拆成了**键盘焦点**与**逻辑焦点**两层——因为 WPF 支持多焦点作用域（如每个窗口/`FocusManager.FocusScope` 独立维护焦点），且控件模板内部元素获得焦点时外部要能感知（路由事件 `GotKeyboardFocus` 沿树冒泡）。这一设计让焦点不仅能服务"Tab 遍历输入框"，还能支撑键盘无障碍（辅助功能）、菜单导航、任务型操作员界面等更复杂的交互需求。

> [!essentials] 核心要点
> - **两类焦点**：键盘焦点（唯一，接收按键）与逻辑焦点（每个 `FocusScope` 一个，`FocusManager` 管理）
> - **请求焦点**：`element.Focus()` 返回 `bool`（`true` 表示成功）；`Keyboard.Focus(element)` 强制设置键盘焦点
> - **焦点事件**：`GotFocus`/`LostFocus`（路由事件，模板内元素聚焦时沿树冒泡到模板外）、`GotKeyboardFocus`/`LostKeyboardFocus`
> - **状态属性**：`IsKeyboardFocused`、`IsKeyboardFocusWithin`（自身或其子树内）、`IsFocused`
> - **Tab 顺序**：`TabIndex` 从小到大，`IsTabStop=false` 可跳过某控件，`KeyboardNavigation.TabNavigation` 控制方向键遍历
> - **失焦校验惯用法**：`LostFocus` 里做输入校验，比"点确定再校验"体验好（示例 `OnLostFocus`）

> **MainWindow.xaml.cs —— 后台代码：**
> ```csharp
> using System.Windows;
> using System.Windows.Controls;
>
> namespace HmiDemo
> {
>     public partial class MainWindow : Window
>     {
>         public MainWindow()
>         {
>             InitializeComponent();
>             // 窗口加载后把焦点放到第一个输入框，方便操作员直接录入
>             Loaded += (s, e) => DeviceNoBox.Focus();
>         }
>
>         // 获得焦点：可在这里做数据预填、高亮提示等
>         private void OnGotFocus(object sender, RoutedEventArgs e)
>         {
>             if (sender is TextBox tb)
>                 LogBox.AppendText($"获得焦点：{tb.Name}（TabIndex={tb.TabIndex}）\n");
>         }
>
>         // 失去焦点：常用于校验输入是否合法
>         private void OnLostFocus(object sender, RoutedEventArgs e)
>         {
>             if (sender is TextBox tb)
>                 LogBox.AppendText($"失去焦点：{tb.Name}，内容「{tb.Text}」\n");
>         }
>
>         // 代码手动聚焦：Focus() 立即把键盘焦点交给目标控件
>         private void OnFocusSpeed(object sender, RoutedEventArgs e)
>         {
>             SpeedBox.Focus();
>         }
>     }
> }
> ```

> [!scene] 适用场景
> ✅ 参数录入界面：开机自动聚焦第一个输入框、Tab 依次遍历、`LostFocus` 逐项校验（示例场景）
> ✅ 工业平板/无鼠标操作：用键盘 Tab、方向键、回车完成全部操作，焦点顺序决定工作效率
> ✅ 模态交互：弹窗打开后把焦点放进输入框，关闭后把焦点还给主窗口（`FocusManager.SetFocusedElement`）
> ✅ 自定义复合控件：模板内 TextBox 聚焦时通过路由事件冒泡让外部感知并联动高亮
> ❌ 纯展示型看板：只有文本和图表、无键盘输入的界面，焦点管理收益有限
> ❌ 多点触控纯手势操作界面（焦点主要服务键盘与鼠标，触控场景另有命中测试逻辑）

> [!pitfall] 常见踩坑
> 坑 1：**在窗口构造或 `InitializeComponent` 前调 `Focus()`** → 现象：焦点没设置成功，`Focus()` 返回 `false` → 原因：控件尚未进入可视化树，焦点无处安放 → 解决：放到 `Loaded` 事件里执行（示例即如此）
> 
> 坑 2：**`GotFocus`/`LostFocus` 在模板内外部触发时机不同** → 现象：模板内 TextBox 聚焦时外层 `GotFocus` 没触发 → 原因：模板内焦点事件是路由事件，但需处理者监听 `GotKeyboardFocus` 或使用 `IsKeyboardFocusWithin` → 解决：复合控件监听 `GotKeyboardFocus`（冒泡含模板内部）判断是否"焦点在我内部"
>
> 坑 3：**每次弹窗都重新 `Focus()` 导致焦点循环** → 现象：输入框刚聚焦又被抢走，输入错乱 → 原因：多个 `Loaded`/`PreviewGotKeyboardFocus` 处理互相抢焦点 → 解决：用 `FocusManager.GetFocusedElement` 先检查当前焦点归属，避免无谓的 `Focus()` 调用

> [!best] 最佳实践
> - 录入类界面统一在 `Loaded` 中设置初始焦点，并保证 Tab 顺序与视觉排列一致（`TabIndex` 明确编号）
> - 用 `LostFocus` 做输入校验：校验失败时 `tb.Focus()` 把焦点拉回错误框并提示，形成"填错立即纠正"闭环
> - 只读展示控件设 `IsTabStop="False"`，避免 Tab 键停在不该停的元素上
> - 自定义控件要参与焦点导航时，重写 `Focusable`/`IsTabStop` 语义并在模板中正确设置 `FocusVisualStyle`
> - 多窗口切换后恢复焦点：记录上次聚焦元素，`Activated` 事件里 `FocusManager.SetFocusedElement`

> [!practice] 上手练习
> **Lv.1 照猫画虎**：运行示例，看启动后焦点是否落在"设备编号"；按 Tab 观察焦点顺序与日志；点按钮验证 `Focus()` 手动聚焦
> **Lv.2 小试牛刀**：给三个输入框增加 `TabIndex` 调整（如把"加工温度"设为 1），观察 Tab 顺序变化；把"设备编号"设 `IsTabStop="False"` 看是否跳过
> **Lv.3 融会贯通**：在 `OnLostFocus` 中校验"主轴转速"必须是数字，非法时弹出错误提示并把焦点拉回该框；成功后才允许进入下一框
> **Lv.4 拆层挑战**：把参数录入做成自定义 `UserControl`（`ProcessForm`），暴露"校验全部参数"与"清空重置并聚焦第一个框"的接口，供 MVVM 命令调用
