# 控件生命周期

> [!plain] 白话理解
> 把控件想象成一名新上岗的操作员：**构造**是入职登记（人来了，但还没分配岗位）；**OnInitialized** 是岗前培训完成（具备基本能力，但还没领工具）；**OnApplyTemplate** 是领取工装和操作手册（此时才能拿到模板里的零件——`GetTemplateChild`）；**Loaded** 是走到工位开始干活（已连上产线，可以交互）；**Unloaded** 是换岗/下班离岗（移出产线，但人还在，随时可能再上岗）。上位机里最常见的场景就是"动态增删设备卡片"：不按这个顺序来，比如在构造函数里就去抢模板里的元素，只会拿到 `null`——就像人还没上岗就伸手够工具一样。

> [!def] 官方定义
> 控件生命周期指 WPF 元素从实例化、初始化、应用模板、挂载到可视化树到卸载所经历的一系列状态与回调。核心阶段：构造函数 → `OnInitialized`（`FrameworkElement.Initialized` 事件对应的虚方法，元素已初始化但未应用模板）→ `OnApplyTemplate`（`Control` 应用 `ControlTemplate`，此时才能用 `GetTemplateChild<T>()` 访问模板内命名元素）→ `Loaded` / `Unloaded`（`FrameworkElement` 事件，表示元素已挂载/脱离 `PresentationSource`）。详见官方文档：[FrameworkElement 类](https://learn.microsoft.com/zh-cn/dotnet/api/system.windows.frameworkelement)、[Control.OnApplyTemplate](https://learn.microsoft.com/zh-cn/dotnet/api/system.windows.frameworkelement.onapplytemplate)、[Loaded/Unloaded 事件](https://learn.microsoft.com/zh-cn/dotnet/api/system.windows.frameworkelement.loaded)。

> [!origin] 由来背景
> WPF 于 2006 年随 .NET Framework 3.0 发布，采用**保留模式渲染**（Retained Mode），控件不再像 WinForms 那样拥有稳定的底层窗口句柄（HWND），而是以"可视化树"的形式组织。WinForms 时代判断控件是否"真的在界面上"要靠 `HandleCreated`/`HandleDestroyed`，而窗口重建、句柄回收会导致这些事件反复横跳，非常不可靠。WPF 因此从逻辑层面引入了 `Loaded`/`Unloaded` 作为"挂载/卸载"的明确通知，并把"模板应用"抽成独立的 `OnApplyTemplate` 阶段——因为控件只有应用模板后才真正拥有视觉外观。这套设计让控件生命周期有了清晰、可预测的阶段边界。

> [!essentials] 核心要点
> - **阶段顺序**：构造 → `OnInitialized` → `OnApplyTemplate` → `Loaded` → `Unloaded`，动态控件每次加入/移出可视化树都会再次触发 `Loaded`/`Unloaded`
> - **`OnApplyTemplate` 是取模板元素的唯一可靠时机**：`GetTemplateChild<T>("name")` 在模板应用前返回 `null`
> - **虚方法与事件的差异**：`OnInitialized`/`OnApplyTemplate` 用 `override`；`Loaded`/`Unloaded` 是事件，用订阅
> - **`IsLoaded` 属性**：代码里判断控件当前是否已挂载，避免在未挂载时操作渲染相关逻辑
> - **构造阶段只做轻量初始化**：不要在构造函数里访问模板、启动昂贵任务
> - **`Unloaded` 不等于销毁**：控件对象仍存活，只是脱离了可视化树；真正的销毁由 GC 决定

> [!example] 完整示例
> **设备面板按钮生命周期演示：通过自定义 DeviceButton 控件输出 构造 → OnInitialized → OnApplyTemplate → Loaded → Unloaded 各阶段日志，直观体验 WPF 控件的完整生命周期：**
>
> **MainWindow.xaml：**
> ```xml
> <Window x:Class="HmiDemo.MainWindow"
>         xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
>         xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
>         Title="控件生命周期 - 设备面板" Height="440" Width="480"
>         WindowStartupLocation="CenterScreen" Background="#0D1117">
>     <Grid Margin="15">
>         <Grid.RowDefinitions>
>             <RowDefinition Height="Auto"/>
>             <RowDefinition Height="Auto"/>
>             <RowDefinition Height="Auto"/>
>             <RowDefinition Height="*"/>
>         </Grid.RowDefinitions>
>         <TextBlock Text="设备面板（动态添加 / 移除按钮，观察生命周期日志）"
>                    Foreground="#58A6FF" FontSize="14" FontWeight="Bold"/>
>         <StackPanel Grid.Row="1" Orientation="Horizontal" Margin="0,12,0,0">
>             <Button Content="添加设备按钮" Click="OnAddClick" Margin="0,0,10,0" Padding="10,6"
>                     Background="#21262D" Foreground="White"/>
>             <Button Content="移除最后一个" Click="OnRemoveClick" Padding="10,6"
>                     Background="#21262D" Foreground="White"/>
>         </StackPanel>
>         <!-- 设备按钮的容器：动态添加的按钮会在这里经历完整的生命周期 -->
>         <StackPanel x:Name="Panel" Grid.Row="2" Margin="0,12,0,0" MinHeight="56"
>                     Background="#161B22" HorizontalAlignment="Left"/>
>         <TextBox x:Name="LogBox" Grid.Row="3" Margin="0,12,0,0" IsReadOnly="True"
>                  TextWrapping="Wrap" AcceptsReturn="True" VerticalScrollBarVisibility="Auto"
>                  Background="#161B22" Foreground="#8B949E" BorderBrush="#21262D"/>
>     </Grid>
> </Window>
> ```

> **MainWindow.xaml.cs —— 后台代码与自定义控件：**
> ```csharp
> using System;
> using System.Windows;
> using System.Windows.Controls;
> using System.Windows.Media;
>
> namespace HmiDemo
> {
>     // 自定义按钮：在关键生命周期节点输出日志，直观展示 WPF 控件的一生
>     public class DeviceButton : Button
>     {
>         // 静态日志回调：由 MainWindow 注入，避免控件与窗口强耦合
>         public static Action<string> Log;
>
>         public DeviceButton()
>         {
>             Log?.Invoke("[构造] DeviceButton 实例已创建");
>             // Loaded / Unloaded 是事件而非虚方法，用事件订阅记录挂载状态
>             Loaded += (s, e) => Log?.Invoke("[Loaded] 已加入可视化树，可以开始工作");
>             Unloaded += (s, e) => Log?.Invoke("[Unloaded] 已移出可视化树");
>         }
>
>         // 初始化阶段：元素已可用，但尚未应用模板
>         protected override void OnInitialized(EventArgs e)
>         {
>             base.OnInitialized(e);
>             Log?.Invoke("[OnInitialized] 控件初始化完成");
>         }
>
>         // 模板应用阶段：此时才能通过 GetTemplateChild 获取模板内的命名元素
>         public override void OnApplyTemplate()
>         {
>             base.OnApplyTemplate();
>             Log?.Invoke("[OnApplyTemplate] 控件模板已应用");
>         }
>     }
>
>     public partial class MainWindow : Window
>     {
>         private int _seq;
>
>         public MainWindow()
>         {
>             InitializeComponent();
>             // 注入日志回调，让自定义控件把生命周期信息写进窗口日志框
>             DeviceButton.Log = msg => LogBox.AppendText(msg + Environment.NewLine);
>         }
>
>         // 动态创建按钮：依次触发 构造 → OnInitialized → OnApplyTemplate → Loaded
>         private void OnAddClick(object sender, RoutedEventArgs e)
>         {
>             var btn = new DeviceButton
>             {
>                 Content = $"设备按钮 {++_seq}",
>                 Foreground = Brushes.White,
>                 Background = new SolidColorBrush(Color.FromRgb(0x21, 0x26, 0x2D)),
>                 Margin = new Thickness(0, 4, 0, 0)
>             };
>             Panel.Children.Add(btn);
>         }
>
>         // 移除按钮：触发 Unloaded，之后控件不再参与布局与渲染
>         private void OnRemoveClick(object sender, RoutedEventArgs e)
>         {
>             if (Panel.Children.Count > 0)
>             {
>                 Panel.Children.RemoveAt(Panel.Children.Count - 1);
>             }
>         }
>     }
> }
> ```
> 

> [!scene] 适用场景
> ✅ 动态增删的设备卡片、报警列表、工单条目（每个条目经历完整的 构造→挂载→卸载 闭环）
> ✅ 控件模板需要按主题/状态切换重绘的复合控件
> ✅ 挂载后要启动 `DispatcherTimer` 刷新、卸载时要退订事件和释放资源的场景
> ✅ 列表虚拟化（如 `ListBox` 虚拟化）中缓存复用的条目容器
> ❌ 一次性静态布局：窗口打开后控件树不再变化，生命周期只有一次
> ❌ 与模板无关的纯自绘轻量元素（如自定义 `FrameworkElement` 直接 `OnRender`，不需要 `OnApplyTemplate`）

> [!pitfall] 常见踩坑
> 坑 1：**构造函数里调用 `GetTemplateChild` 拿到 `null`** → 现象：控件内部功能失效甚至空引用 → 原因：模板此时尚未应用 → 解决：把取模板元素的逻辑移到 `OnApplyTemplate`，且每次应用模板都重新获取
> 
> 坑 2：**把 `Unloaded` 当"控件被销毁"来释放资源** → 现象：控件从列表移除再放回后功能异常或闪烁 → 原因：`Unloaded` 后控件对象仍存活，再次挂载会重新触发 `Loaded`，但初始化代码没有重跑 → 解决：初始化/释放成对放在 `Loaded`/`Unloaded` 中，并接受它们可能多次触发
>
> 坑 3：**在 `Loaded` 里订阅外部事件却从不退订** → 现象：页面关闭后日志仍被写入、内存只增不减 → 原因：`Loaded` 事件源（静态事件、数据源等）持有控件引用形成泄漏 → 解决：在 `Unloaded` 中对称退订，或改用 `WeakEventManager`

> [!best] 最佳实践
> - 自定义控件先用"日志法"摸清真实生命周期顺序，再决定初始化逻辑放哪个阶段，避免凭直觉猜测
> - 模板元素获取统一收敛在 `OnApplyTemplate`，模板可能被重新应用，因此每次都要重新获取
> - 昂贵初始化（加载字体、建立连接、加载图片）放到 `Loaded` 之后，防止阻塞界面首帧
> - 资源释放放 `Unloaded`，同时做好"重新 Loaded 时重建"的对称逻辑
> - 用 `IsLoaded` 守卫异步回调中的 UI 操作，防止在卸载后访问已失效的元素

> [!practice] 上手练习
> **Lv.1 照猫画虎**：运行示例，点击"添加设备按钮"观察日志输出顺序：构造 → OnInitialized → OnApplyTemplate → Loaded；再点"移除最后一个"观察 Unloaded。连续添加两个按钮，看日志顺序有什么规律
> **Lv.2 小试牛刀**：在 `DeviceButton` 的构造、`OnInitialized`、`OnApplyTemplate` 中分别输出 `ActualWidth`，观察它在各阶段是否有效
> **Lv.3 融会贯通**：让 `DeviceButton` 在 `Loaded` 时启动一个 `DispatcherTimer` 每秒更新按钮文本（如显示运行秒数），`Unloaded` 时停止并退订，验证动态增删时不会泄漏
> **Lv.4 拆层挑战**：把 `DeviceButton` 的日志输出改为弱事件（`WeakEventManager`）订阅，用内存分析器验证移除控件后窗口不再被控件引用
