# 多屏适配（拼接屏场景）

> [!plain] 白话理解
> 调度室的上位机经常是"一台主机拖两三块屏幕"，有的还是视频拼接墙。多屏适配就是解决**"窗口该上哪块屏、多大、什么位置"**的问题：先用 `Screen.AllScreens` 枚举出系统里每块屏幕的名字、坐标、工作区尺寸（示例启动时打印出来），再按需把窗口 `Left/Top/Width/Height` 设成目标屏的工作区，窗口就"钉"在那块屏上了。示例两个按钮——铺满主屏、铺满 2 号屏——就是拼接屏场景最常见的需求：监控画面铺副屏，操作界面留主屏。

> [!def] 官方定义
> 多屏适配指程序运行时枚举系统全部显示器、按目标屏的**工作区**（`System.Windows.Forms.Screen.WorkingArea`，不含任务栏）定位与调整窗口的技术。核心 API 为 `System.Windows.Forms.Screen.AllScreens`（每项含 `DeviceName`/`Primary`/`Bounds`/`WorkingArea`）与 WPF 的 `SystemParameters.WorkArea`/`VirtualScreen`（主屏/虚拟屏工作区）。窗口定位通过设置 `Window.Left`/`Top`/`Width`/`Height`（DIP 坐标，与屏幕工作区同为像素时注意 DPI 换算）实现；拼接墙可配合 `Screen` + `SystemParameters.VirtualScreen` 计算整体逻辑分辨率。详见官方文档：[Screen 类](https://learn.microsoft.com/zh-cn/dotnet/api/system.windows.forms.screen)、[SystemParameters.WorkArea](https://learn.microsoft.com/zh-cn/dotnet/api/system.windows.systemparameters.workarea)。

> [!origin] 由来背景
> 多显示器支持是 Windows 长期存在的需求：Win32 时代用 `EnumDisplayMonitors`/`GetSystemMetrics(SM_CXSCREEN)` 枚举屏幕，WinForms 在 .NET Framework 1.0（2002 年）起提供 `Screen.AllScreens` 简化此过程。WPF（2006 年）的 `Window.Left/Top` 采用与 DPI 相关的 DIP 坐标，直接读屏幕像素工作区在 DPI 非 100% 时会错位，因此实际项目常混用 `SystemParameters` 与 `Screen`。拼接屏（视频墙）场景在调度中心、指挥大厅很常见：一块"大屏"逻辑上是多块物理屏拼成，程序要么铺到某块屏、要么把窗口横跨虚拟屏。示例展示了最实用的"枚举 + 定位铺满"流程，多屏适配其余部分（DPI 换算）见 `per-monitor-dpi-awareness`。

> [!essentials] 核心要点
> - **枚举屏幕**：`Screen.AllScreens` 返回全部显示器，`DeviceName`/`Primary`/`WorkingArea`（工作区）/`Bounds`（整屏）
> - **窗口定位**：`win.Left = area.X; win.Top = area.Y; win.Width = area.Width; win.Height = area.Height`（示例 `FillScreen`）
> - **主屏工作区**：`SystemParameters.WorkArea`（WPF 侧，主屏）；`Screen.PrimaryScreen.WorkingArea`（WinForms 侧）
> - **拼接屏铺开**：铺满用 `WorkingArea`；覆盖任务栏/边框用 `Bounds` + 无边框窗口样式
> - **DPI 注意**：`Left/Top/Width/Height` 是 DIP，与 `WorkingArea` 像素在非 100% DPI 下需换算（见 `per-monitor-dpi-awareness`）
> - **引用**：需引用 `System.Windows.Forms` 程序集（示例顶部注释已注明）

> [!example] 完整示例
> **拼接屏多屏适配演示：用 SystemParameters 枚举主屏/工作区，再结合 System.Windows.Forms.Screen 列出所有显示器信息，把上位机窗口移动到指定显示器并铺满，适配调度室拼接大屏：**
>
> **说明：需添加 System.Windows.Forms 与 System.Drawing 程序集引用。**
>
> **MainWindow.xaml：**
> ```xml
> <Window x:Class="HmiDemo.MainWindow"
>         xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
>         xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
>         Title="多屏适配 - 拼接屏场景" Height="460" Width="520"
>         WindowStartupLocation="CenterScreen" Background="#0D1117">
>     <Grid Margin="15">
>         <Grid.RowDefinitions>
>             <RowDefinition Height="Auto"/>
>             <RowDefinition Height="*"/>
>             <RowDefinition Height="Auto"/>
>         </Grid.RowDefinitions>
>         <TextBlock Text="拼接屏多屏适配（枚举屏幕 + 移动窗口 + 全屏铺开）"
>                    Foreground="#58A6FF" FontSize="14" FontWeight="Bold" TextWrapping="Wrap"/>
>         <TextBox x:Name="ScreenInfo" Grid.Row="1" Margin="0,12,0,0" IsReadOnly="True"
>                  TextWrapping="Wrap" VerticalScrollBarVisibility="Auto"
>                  Background="#161B22" Foreground="#8B949E" BorderBrush="#21262D"/>
>         <StackPanel Grid.Row="2" Orientation="Horizontal" Margin="0,12,0,0">
>             <Button Content="窗口铺满主屏" Click="OnFillPrimary" Padding="12,6" Margin="0,0,10,0"
>                     Background="#21262D" Foreground="White"/>
>             <Button Content="窗口铺满 2 号屏" Click="OnFillSecond" Padding="12,6"
>                     Background="#21262D" Foreground="White"/>
>         </StackPanel>
>     </Grid>
> </Window>
> ```
>
> **MainWindow.xaml.cs —— 后台代码：**
> ```csharp
> using System.Windows;
> using System.Windows.Forms; // 提供 Screen 类枚举显示器
>
> namespace HmiDemo
> {
>     public partial class MainWindow : Window
>     {
>         public MainWindow()
>         {
>             InitializeComponent();
>             // 启动时枚举全部显示器信息
>             foreach (var screen in Screen.AllScreens)
>             {
>                 ScreenInfo.AppendText(
>                     $"屏幕「{screen.DeviceName}」主屏={screen.Primary} " +
>                     $"工作区={screen.WorkingArea.Width}×{screen.WorkingArea.Height} " +
>                     $"位置=({screen.WorkingArea.X},{screen.WorkingArea.Y})\n");
>             }
>             ScreenInfo.AppendText($"\n主屏工作区（SystemParameters）：" +
>                 $"{SystemParameters.WorkArea.Width}×{SystemParameters.WorkArea.Height}\n");
>         }
>
>         // 把窗口移动到指定显示器并铺满其工作区（不含任务栏）
>         private static void FillScreen(Window win, Screen target)
>         {
>             var area = target.WorkingArea;
>             win.Left = area.X;
>             win.Top = area.Y;
>             win.Width = area.Width;
>             win.Height = area.Height;
>             // 拼接屏副屏建议再全屏化：
>             // win.WindowState = WindowState.Maximized;
>         }
>
>         private void OnFillPrimary(object sender, RoutedEventArgs e)
>             => FillScreen(this, Screen.PrimaryScreen);
>
>         private void OnFillSecond(object sender, RoutedEventArgs e)
>         {
>             // 取第二块显示器（若存在）
>             if (Screen.AllScreens.Length > 1)
>                 FillScreen(this, Screen.AllScreens[1]);
>             else
>                 ScreenInfo.AppendText("未检测到 2 号屏幕！\n");
>         }
>     }
> }
> ```
> 

> [!scene] 适用场景
> ✅ 调度室/指挥中心多屏上位机：监控画面铺副屏、操作面板留主屏（示例场景）
> ✅ 拼接墙大屏展示：程序启动自动铺满指定物理屏或虚拟屏
> ✅ 多工位多屏场景：每台操作站显示到各自屏幕
> ✅ 程序启动时恢复"上次窗口所在屏幕与大小"（记录 `Screen.DeviceName` 对应关系）
> ❌ 单屏程序（枚举与定位纯属多余）
> ❌ 拼接墙硬件自带"整屏输出"方案（如视频处理器把多屏合成一块逻辑屏，无需程序处理）

> [!pitfall] 常见踩坑
> 坑 1：**拔插显示器后 `Screen.AllScreens` 索引变化** → 现象：启动时铺 2 号屏，拔掉副屏后铺错屏 → 原因：`AllScreens[1]` 按枚举顺序取，不是稳定标识 → 解决：用 `DeviceName` 匹配目标屏，找不到时回退主屏；运行中监听显示器热插拔
> 
> 坑 2：**DPI 不同导致窗口铺不满** → 现象：副屏 125% 缩放下窗口比屏幕小一截或溢出 → 原因：`WorkingArea` 是物理像素，`Window.Left/Width` 是 DIP，两者未换算 → 解决：用 `WorkingArea` 做 DPI 换算（`物理像素 / DPI 缩放比`），或先 `WindowState=Maximized` 让系统处理（详见 `per-monitor-dpi-awareness`）
>
> 坑 3：**窗口铺满后仍被任务栏遮挡** → 现象：铺满的窗口底部被任务栏盖住 → 原因：用了 `Bounds`（整屏含任务栏）而窗口非无边框 → 解决：默认用 `WorkingArea`（不含任务栏）；确需覆盖整屏时无边框 + `Bounds` + `Topmost`

> [!best] 最佳实践
> - 屏幕定位统一封装 `ScreenManager`：`FindByName`/`GetPrimary`/`FillScreen(window, screen)`，业务层不直接碰 `Screen` API
> - 默认铺 `WorkingArea`（不含任务栏），全屏铺开再单独提供"演示模式"（无边框 + `Bounds`）
> - 用 `DeviceName` 而不是索引标识屏幕，显示器热插拔/顺序变化也不出错
> - 启动时恢复上次窗口位置：持久化 `DeviceName` + 工作区尺寸，找不到目标屏回退主屏
> - 拼接屏场景配合 `per-monitor-dpi-awareness`，各屏 DPI 不同时先统一换算再定位

> [!practice] 上手练习
> **Lv.1 照猫画虎**：双屏环境运行示例，查看启动日志里各屏信息；点"窗口铺满 2 号屏"观察窗口跳过去铺满工作区
> **Lv.2 小试牛刀**：增加第三个按钮"横跨虚拟屏铺开"（用 `SystemParameters.VirtualScreenLeft/Top/Width/Height`），在拼接屏上验证跨屏全宽
> **Lv.3 融会贯通**：把窗口位置与所在屏 `DeviceName` 持久化到设置，启动时自动恢复到上次屏幕并铺满，验证多屏状态记忆
> **Lv.4 拆层挑战**：封装 `ScreenManager`（枚举/定位/DPI 换算），结合 `per-monitor-dpi-awareness` 实现"不同 DPI 混合多屏"下窗口精确铺满，并处理显示器热插拔事件
