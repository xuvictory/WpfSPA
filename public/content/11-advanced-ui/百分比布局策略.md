# 百分比布局策略

> [!plain] 白话理解
> 上位机界面要应对"不同分辨率、不同屏幕尺寸"，最朴素可靠的办法就是**按比例分地盘**：不写死宽度（`Width=500`），而是用 `Grid` 的星号列（`3*`/`7*`）告诉 WPF"左边占 30%、右边占 70%"，窗口一拉大，两边跟着同比例变宽。示例里整体是"标题 40px + 内容 100% + 状态栏 32px"，内容区再分 30/70，右侧再分 60/40——像俄罗斯套娃一样层层按比例切分。拖动窗口时结构纹丝不动，这正是操作站"1920×1080 和 1366×768 都能看"的答案。

> [!def] 官方定义
> 百分比布局指使用 `Grid` 的行/列 `RowDefinition`/`ColumnDefinition` 的**星号（`*`）尺寸**按比例分配可用空间：`3*` 与 `7*` 表示该行列占剩余空间的 3/10 与 7/10；混合 `Auto`（按内容）、固定值（像素 DIP）与 `*`（余量比例）可实现"固定区域 + 弹性区域"结构。这是 WPF 布局系统（`Measure`/`Arrange` 两遍算法）下的标准响应式手段，配合 `HorizontalAlignment`/`VerticalAlignment`（`Stretch`）与 `Margin` 实现自适应。详见官方文档：[Grid 概述](https://learn.microsoft.com/zh-cn/dotnet/desktop/wpf/controls/grid)、[GridUnitType 星号尺寸](https://learn.microsoft.com/zh-cn/dotnet/api/system.windows.gridunittype)。

> [!origin] 由来背景
> 传统 UI（WinForms，2002 年随 .NET Framework 1.0）用绝对坐标 `Location`/`Size` 定位控件，窗体一缩放就错位，为此开发者只能写大量 `Resize` 事件手动重排。WPF（2006 年随 .NET Framework 3.0 发布）引入弹性布局面板：`Grid` 的星号列天然支持"按比例分配"，布局系统自动在窗口缩放时重新计算每个区域尺寸，开发者不再写重排代码。这一机制成为 WPF 响应式设计的地基——上位机屏幕从 1024×768 的旧工控屏到 4K 大屏，同一份 XAML 靠星号列就能自适应。后续 `Viewbox`、`DockPanel`、`UniformGrid` 都是在不同维度上解决同类问题。

> [!essentials] 核心要点
> - **星号比例**：`<ColumnDefinition Width="3*"/>` + `<ColumnDefinition Width="7*"/>` = 30%/70% 分列；行同理（`Height`）
> - **三种尺寸混用**：固定像素（`40`）+ `Auto`（按内容）+ `*`（占余量），示例"标题 40px + 内容 * + 状态栏 32px"
> - **嵌套切分**：外层 `Grid` 分大区，内层 `Grid` 再细分（示例右侧再分 60%/40%），套娃式层层比例
> - **对齐方式**：子元素默认 `Stretch` 填满所在格；`HorizontalAlignment`/`VerticalAlignment` 控制收缩
> - **`SizeChanged` 观察**：`Window.SizeChanged` 可实时读取 `ActualWidth`/`ActualHeight` 验证布局（示例）
> - **与固定布局对比**：能不用固定像素就少用，固定尺寸在分辨率变化时最先出问题

> [!example] 完整示例
> **上位机监控面板百分比布局演示：全部用 Grid 星号（*）行/列按比例分配空间，拖动窗口任意缩放，面板各区域始终按百分比自适应：**
>
> **MainWindow.xaml：**
> ```xml
> <Window x:Class="HmiDemo.MainWindow"
>         xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
>         xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
>         Title="百分比布局策略 - 监控面板" Height="480" Width="640"
>         WindowStartupLocation="CenterScreen" Background="#0D1117">
>     <!-- 整体：标题占 40，下方内容占 *（100% 余量） -->
>     <Grid Margin="15">
>         <Grid.RowDefinitions>
>             <RowDefinition Height="40"/>
>             <RowDefinition Height="*"/>
>             <RowDefinition Height="32"/>
>         </Grid.RowDefinitions>
>         <TextBlock Text="百分比布局：Grid 星号列按比例分配，窗口任意缩放都保持结构"
>                    Foreground="#58A6FF" FontSize="14" FontWeight="Bold"/>
>         <!-- 内容区：左侧占 30%，右侧占 70% -->
>         <Grid Grid.Row="1" Margin="0,12,0,0">
>             <Grid.ColumnDefinitions>
>                 <ColumnDefinition Width="3*"/>   <!-- 30% -->
>                 <ColumnDefinition Width="7*"/>   <!-- 70% -->
>             </Grid.ColumnDefinitions>
>             <!-- 左侧设备列表 -->
>             <Border Background="#161B22" BorderBrush="#21262D" BorderThickness="1"
>                     CornerRadius="4" Margin="0,0,6,0" Padding="10">
>                 <StackPanel>
>                     <TextBlock Text="设备列表" Foreground="#58A6FF" FontWeight="Bold"/>
>                     <ListBox Background="Transparent" BorderThickness="0" Margin="0,8,0,0"
>                              Foreground="White">
>                         <ListBoxItem Content="1# 注塑机"/>
>                         <ListBoxItem Content="2# 注塑机"/>
>                         <ListBoxItem Content="3# 干燥机"/>
>                         <ListBoxItem Content="4# 冷水机"/>
>                     </ListBox>
>                 </StackPanel>
>             </Border>
>             <!-- 右侧：上 60% 曲线区 + 下 40% 参数区 -->
>             <Grid Grid.Column="1" Margin="6,0,0,0">
>                 <Grid.RowDefinitions>
>                     <RowDefinition Height="3*"/>
>                     <RowDefinition Height="2*"/>
>                 </Grid.RowDefinitions>
>                 <Border Background="#161B22" BorderBrush="#21262D" BorderThickness="1"
>                         CornerRadius="4" Padding="10">
>                     <TextBlock Text="温度曲线（占右侧 60%）" Foreground="#8B949E"/>
>                 </Border>
>                 <Border Grid.Row="1" Background="#161B22" BorderBrush="#21262D"
>                         BorderThickness="1" CornerRadius="4" Margin="0,12,0,0" Padding="10">
>                     <TextBlock Text="参数面板（占右侧 40%）" Foreground="#8B949E"/>
>                 </Border>
>             </Grid>
>         </Grid>
>         <TextBlock x:Name="SizeText" Grid.Row="2" Foreground="#8B949E"
>                    Text="拖动窗口大小观察布局自适应"/>
>     </Grid>
> </Window>
> ```

> **MainWindow.xaml.cs —— 后台代码：**
> ```csharp
> using System.Windows;
>
> namespace HmiDemo
> {
>     public partial class MainWindow : Window
>     {
>         public MainWindow()
>         {
>             InitializeComponent();
>             // 监听尺寸变化，实时显示当前窗口大小，验证百分比布局
>             SizeChanged += (s, e) =>
>                 SizeText.Text = $"当前窗口：{ActualWidth:F0} × {ActualHeight:F0}";
>         }
>     }
> }

> [!scene] 适用场景
> ✅ 监控主界面"左列表 + 右曲线"式布局，窗口可自由缩放（示例场景）
> ✅ 上位机要同时适配 1024×768 工控屏与 1920×1080 操作站的场景
> ✅ 图表区/参数区/日志区需要按比例分配且可拖动分隔的场景
> ✅ 多窗口应用统一布局骨架，各窗口内部再按比例切分
> ❌ 内容尺寸固定的表单（打印单据、固定样式的报表）——绝对布局更可控
> ❌ 需要等比整体放缩的整屏画面（应改用 `Viewbox` 或 `UniformGrid`，见 `viewbox-缩放适配`）

> [!pitfall] 常见踩坑
> 坑 1：**全部用 `*` 导致内容被压瘪** → 现象：窗口拖很小时列表/曲线被压缩得没法看 → 原因：行/列没有最小尺寸约束 → 解决：关键区域设 `MinWidth`/`MinHeight`，或窗口设 `MinWidth`/`MinHeight` 下限（示例窗口可加 `MinWidth="480" MinHeight="360"`）
> 
> 坑 2：**`*` 与 `Auto` 混用顺序理解错** → 现象：某个区域突然占了大部分空间 → 原因：`Auto` 行按内容撑开后再算 `*` 余量，内容一变比例就变 → 解决：明确"固定/内容/弹性"三段职责，弹性格永远最后分配余量，内容行预估好最大内容
>
> 坑 3：**嵌套 Grid 忘了 `Grid.Column`/`Row`** → 现象：内容全堆在第一个格子里 → 原因：子元素没指定 `Grid.Row`/`Grid.Column`，默认都在 0 行 0 列 → 解决：嵌套时逐个核对行/列索引（示例右侧用 `Grid.Column="1"`、下区用 `Grid.Row="1"`）

> [!best] 最佳实践
> - 布局骨架"固定 + 弹性"分层：标题栏/状态栏固定，内容区全 `*`，可预测且好维护
> - 比例用"语义化"星号（`3*:7*`、`1*:1*`），比写死百分数数字更易读、更好改
> - 给窗口设 `MinWidth`/`MinHeight`，防止用户把界面拖到不可用
> - 嵌套层级不超过三层，超过就抽成 `UserControl`，避免 XAML 深到看不下去
> - 结合 `Viewbox`/`ScrollViewer` 处理"内容最小尺寸"问题，大屏与小屏都保持可读性

> [!practice] 上手练习
> **Lv.1 照猫画虎**：运行示例，拖动窗口四个角观察布局比例不变、状态栏尺寸实时更新；把窗口拉最小看哪些区域被压
> **Lv.2 小试牛刀**：把右侧"上 60% / 下 40%"改成"上 40% / 下 60%"，再给左侧加一个 20% 的第三列（日志区），验证比例灵活可调
> **Lv.3 融会贯通**：给窗口加 `MinWidth`/`MinHeight`，并在内容区放一个 `ScrollViewer`，验证小窗口下内容仍可访问
> **Lv.4 拆层挑战**：把示例拆成 `HeaderBar`/`DevicePanel`/`ChartPanel` 三个 `UserControl`，用 `Grid` 星号组合装配主界面，再为"1920×1080 与 1366×768"两套分辨率做截图对比验收
