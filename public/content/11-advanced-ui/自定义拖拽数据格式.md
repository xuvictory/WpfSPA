# 自定义拖拽数据格式

> [!plain] 白话理解
> 控件间拖拽传文本就像**只递一张便条**，但对方要的是"设备对象"（名称、类型、状态、IP 全都要）。解决办法是给托盘上刻一个**专属标签**（自定义格式字符串），把整个对象放进去，只有认识这个标签的接收方才能取出来。示例里发起方 `data.SetData(DeviceFormat, device)` 就是"贴上专属标签放好对象"，接收方 `e.Data.GetData(DeviceFormat) is Device d` 是"凭标签取回对象"。同时再放一份 `DataFormats.Text`（名字）给外部程序用——一货两标，各取所需。

> [!def] 官方定义
> 自定义拖拽数据格式指在 `DataObject` 中使用**自定义格式字符串**（通常为命名空间 + 语义名 + 唯一标识，如 `HmiDemo.DeviceFormat.3F2A1B4C`）作为 `DataFormats` 的键，用 `DataObject.SetData(format, value)` 装载任意对象、`GetData(format)` 按同格式取出。由于 OLE 拖放可跨进程，自定义格式需保证唯一性（惯例用 GUID 或命名空间前缀）；对**不可序列化对象**，拖放仅在**同一进程内**可靠（跨进程需实现 `[Serializable]` 或用二进制序列化）。详见官方文档：[DataObject.SetData](https://learn.microsoft.com/zh-cn/dotnet/api/system.windows.dataobject.setdata)、[DataObject.GetData](https://learn.microsoft.com/zh-cn/dotnet/api/system.windows.dataobject.getdata)。

> [!origin] 由来背景
> OLE 拖放（1990 年代）从设计上就支持自定义数据格式：`RegisterClipboardFormat` 注册任意格式名，数据以该格式传递，避免不同应用间的格式冲突。WPF（2006 年）的 `DataObject` 沿用了这一理念——`SetData` 的第一个参数就是格式名，既支持标准 `DataFormats`（Text/FileDrop/UnicodeText），也支持开发者自定义字符串。上位机场景中，拖动一个 `Device` 对象而不仅是设备名，接收方才能拿到状态、参数、连接信息做后续处理。跨进程时对象须可序列化（WPF 内部用二进制序列化传递），同进程内则可直接传引用。

> [!essentials] 核心要点
> - **格式命名**：自定义格式用 `命名空间.语义.唯一后缀`（示例 `HmiDemo.DeviceFormat.3F2A1B4C`），避免与其他应用格式冲突
> - **装载**：`data.SetData(DeviceFormat, device)` 放对象，`data.SetData(DataFormats.Text, device.Name)` 顺带文本（示例双格式）
> - **校验**：`e.Data.GetDataPresent(DeviceFormat)` 判断是否携带自定义格式（示例 `OnDragEnter`）
> - **取出**：`e.Data.GetData(DeviceFormat) is Device d` 强类型还原对象（示例 `OnDrop`）
> - **进程边界**：跨进程拖放要求对象可序列化；同进程（示例场景）直接传引用，简单高效
> - **多格式兼容**：同一 `DataObject` 可装多种格式，标准格式留给外部应用，自定义格式自己用

> [!example] 完整示例
> **自定义拖拽数据格式演示：定义私有拖拽格式字符串，把整个设备对象（不只是文本）封装进 DataObject，接收方用 SetData / GetData 按自定义格式读写复杂对象：**

> **MainWindow.xaml：**
> ```xml
> <Window x:Class="HmiDemo.MainWindow"
>         xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
>         xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
>         Title="自定义拖拽数据格式" Height="420" Width="520"
>         WindowStartupLocation="CenterScreen" Background="#0D1117">
>     <Grid Margin="15">
>         <Grid.RowDefinitions>
>             <RowDefinition Height="Auto"/>
>             <RowDefinition Height="*"/>
>         </Grid.RowDefinitions>
>         <TextBlock Text="自定义 DataObject 格式拖拽设备对象（保留全部字段）"
>                    Foreground="#58A6FF" FontSize="14" FontWeight="Bold" TextWrapping="Wrap"/>
>         <Grid Grid.Row="1" Margin="0,12,0,0">
>             <Grid.ColumnDefinitions>
>                 <ColumnDefinition Width="*"/>
>                 <ColumnDefinition Width="*"/>
>             </Grid.ColumnDefinitions>

>                 <StackPanel Margin="10">

> **MainWindow.xaml.cs —— 后台代码：**
> ```csharp
> using System;
> using System.Collections.Generic;
> using System.Windows;
> using System.Windows.Controls;
> using System.Windows.Input;
> using System.Windows.Media;
>
> namespace HmiDemo
> {
>     // 设备对象：拖拽时整体传递，接收方拿到的是完整对象而非字符串
>     public class Device
>     {
>         public string Name { get; set; }
>         public string Type { get; set; }
>         public int Status { get; set; } // 0=停止 1=运行
>         public override string ToString() => Name;
>     }
>
>     public partial class MainWindow : Window
>     {
>         // 自定义拖拽格式：用 GUID 保证全局唯一，避免与其他应用冲突
>         public static readonly string DeviceFormat = "HmiDemo.DeviceFormat.3F2A1B4C";
>         private Point _dragStart;
>
>         public MainWindow()
>         {
>             InitializeComponent();
>             DeviceList.ItemsSource = new List<Device>
>             {
>                 new Device { Name = "1# 注塑机", Type = "注塑", Status = 1 },
>                 new Device { Name = "2# 注塑机", Type = "注塑", Status = 0 },
>                 new Device { Name = "3# 干燥机", Type = "干燥", Status = 1 },
>             };
>         }
>
>         private void OnDeviceMouseDown(object sender, MouseButtonEventArgs e)
>         {
>             _dragStart = e.GetPosition(null);
>         }
>
>         // 发起拖拽：SetData 使用自定义格式写入整个对象
>         private void OnDeviceMouseMove(object sender, MouseEventArgs e)
>         {
>             if (e.LeftButton != MouseButtonState.Pressed) return;
>             var pos = e.GetPosition(null);
>             if (Math.Abs(pos.X - _dragStart.X) < SystemParameters.MinimumHorizontalDragDistance &&
>                 Math.Abs(pos.Y - _dragStart.Y) < SystemParameters.MinimumVerticalDragDistance) return;
>
>             if (DeviceList.SelectedItem is Device device)
>             {
>                 var data = new DataObject();
>                 data.SetData(DeviceFormat, device); // 自定义格式装载对象
>                 data.SetData(DataFormats.Text, device.Name); // 顺带一份文本，便于外部程序读取
>                 DragDrop.DoDragDrop(DeviceList, data, DragDropEffects.Copy);
>             }
>         }
>
>         // 校验拖入数据是否带自定义格式
>         private void OnDragEnter(object sender, DragEventArgs e)
>         {
>             e.Effects = e.Data.GetDataPresent(DeviceFormat)
>                 ? DragDropEffects.Copy : DragDropEffects.None;
>             e.Handled = true;
>         }
>
>         // 落点：GetData 按自定义格式还原完整对象
>         private void OnDrop(object sender, DragEventArgs e)
>         {
>             DetailPanel.Children.Clear();
>             if (e.Data.GetData(DeviceFormat) is Device device)
>             {
>                 DetailPanel.Children.Add(NewText($"设备名称：{device.Name}", "White", true));
>                 DetailPanel.Children.Add(NewText($"设备类型：{device.Type}", "#8B949E", false));
>                 DetailPanel.Children.Add(NewText($"运行状态：{(device.Status == 1 ? "运行中" : "已停止")}",
>                     device.Status == 1 ? "#238636" : "#DA3633", false));
>             }
>             e.Handled = true;
>         }
>
>         // 快捷生成一行文本，用于动态展示拖入的设备信息
>         private static TextBlock NewText(string text, string color, bool bold)
>             => new TextBlock
>             {
>                 Text = text,
>                 Foreground = new SolidColorBrush((Color)ColorConverter.ConvertFromString(color)),
>                 FontWeight = bold ? FontWeights.Bold : FontWeights.Normal,
>                 Margin = new Thickness(0, 2, 0, 2)
>             };
>     }
> }
> ```
> 

> [!scene] 适用场景
> ✅ 拖拽传递"带状态的业务对象"：设备、报警、工单、配方（示例场景）
> ✅ 同进程多窗口/多区域间拖放（`ListBox` 到详情面板、列表到图表）
> ✅ 需要"文本 + 对象"双格式兼容：外部应用读到文本，自己应用读对象
> ✅ 拖拽时要携带附加信息（来源列表、操作类型），用自定义格式字段区分
> ❌ 跨进程传给第三方应用时自定义格式对方不认识（应同时提供标准 `DataFormats`）
> ❌ 大数据对象拖拽（对象巨大时序列化开销高，改为拖拽引用/ID 更合适）

> [!pitfall] 常见踩坑
> 坑 1：**格式字符串不一致** → 现象：`GetDataPresent` 返回 false、`Drop` 收不到数据 → 原因：发起方与接收方写的格式字符串不完全一致（大小写/后缀差异） → 解决：格式定义为 `public static readonly string` 常量集中管理（示例 `DeviceFormat`），不要手写字符串
> 
> 坑 2：**跨进程拖对象崩** → 现象：拖到另一个应用/进程时 `GetData` 抛序列化异常 → 原因：自定义格式对象未实现 `[Serializable]`，跨进程无法传递 → 解决：同进程传引用；跨进程用 `[Serializable]` 标记类，或只传标准格式（文本/路径）
>
> 坑 3：**接收方不知道格式存在就强取** → 现象：`GetData` 返回 null 或类型转换失败 → 原因：拖入的不是本应用发起的数据 → 解决：先 `GetDataPresent(DeviceFormat)` 校验（示例 `OnDragEnter`/`OnDrop` 判空），不匹配时给"不支持"反馈

> [!best] 最佳实践
> - 自定义格式统一用静态常量定义（`public static readonly string`），发起与接收引用同一常量，杜绝拼写漂移
> - 格式字符串带命名空间前缀 + 唯一标识（GUID 片段），避免与系统及其他应用格式冲突
> - 一份 `DataObject` 同时装自定义格式（对象）+ 标准格式（文本），兼顾自用与外部兼容（示例双 `SetData`）
> - 拖放对象定义成 DTO（只含字段，不含行为），跨层传递更安全
> - 接收侧一律先 `GetDataPresent` 再 `GetData`，并用 `is` 模式匹配强类型转换，防止类型不符

> [!practice] 上手练习
> **Lv.1 照猫画虎**：运行示例，拖一台设备到右侧查看完整信息；对比 `控件间拖拽` 的文本版本，体会差异
> **Lv.2 小试牛刀**：给 `Device` 增加 `IpAddress`/`Port` 字段并在明细里显示；再给 `DeviceFormat` 加一个版本号后缀，验证格式变化后接收方行为
> **Lv.3 融会贯通**：把拖入设备自动加入"连接列表"（去重 + 状态更新），用 `ObservableCollection<Device>` 驱动 UI 自动刷新
> **Lv.4 拆层挑战**：实现跨窗口拖拽（两个窗口各有一个设备列表，互相拖放），验证同进程对象传递；再给 `Device` 加 `[Serializable]` 观察跨进程行为差异
