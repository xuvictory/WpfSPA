# 文件拖入

> [!plain] 白话理解
> 文件拖入就是**让资源管理器"送货上门"**：操作员不用点"浏览"弹窗找文件，直接把配方表、工艺文件从文件夹拖进窗口，松手即导入。实现上比控件间拖拽更简单——窗口说一句"我能接货"（`AllowDrop="True"`），在 `Drop` 里问系统"这次送的是什么"（`DataFormats.FileDrop`），系统把文件路径数组给你（`string[] files`），你逐个读文件、导入、刷新列表即可。示例里每条路径还能顺便读出文件名和大小，就像收货时当场清点货物。

> [!def] 官方定义
> 文件拖入是 OLE 拖放中的"文件传输"场景：资源管理器（或任意符合规范的应用）发起拖放时，`DataObject` 携带 `DataFormats.FileDrop` 格式的数据——一个文件完整路径的 `string[]`。WPF 应用设置 `AllowDrop="True"` 并处理 `Drop` 事件，用 `e.Data.GetData(DataFormats.FileDrop) as string[]` 取路径，再通过 `System.IO` 读取文件内容。`DragOver` 中用 `GetDataPresent(DataFormats.FileDrop)` 判断是否文件数据并设置 `e.Effects`。详见官方文档：[拖放概述](https://learn.microsoft.com/zh-cn/dotnet/desktop/wpf/advanced/drag-and-drop-overview)、[DataFormats.FileDrop](https://learn.microsoft.com/zh-cn/dotnet/api/system.windows.dataformats.filedrop)。

> [!origin] 由来背景
> 文件拖入的底层同样是 1990 年代的 Windows OLE 拖放规范：Explorer 把被拖文件封装成 `IDataObject`，数据格式注册为 `CF_HDROP`（文件列表）。.NET Framework 1.0（2002 年）的 WinForms 就支持 `AllowDrop` + `DragEnter` 接收文件；WPF（2006 年）以 `DataFormats.FileDrop` 延续此格式，与系统 Explorer 完全互通。上位机领域，"拖入配方文件自动解析参数""拖入工艺 CSV 批量下发"这类交互，比弹文件对话框少两步点击，在频繁切换配方的产线上尤其顺手。FileDrop 数据在 WPF 中就是一个 `string[]` 路径数组，读取方式与普通文件操作一致。

> [!essentials] 核心要点
> - **窗口/容器开接收**：`AllowDrop="True"`（示例放在 `Window` 上，全窗口可拖入）
> - **`DragOver` 校验格式**：`e.Data.GetDataPresent(DataFormats.FileDrop)` 判断是否文件，决定 `e.Effects`
> - **`Drop` 取路径**：`e.Data.GetData(DataFormats.FileDrop) as string[]`，一次可多文件（示例遍历 `files`）
> - **读文件用 `System.IO`**：拿到路径后 `File.ReadAllText`/`FileInfo` 等按需处理（示例显示文件名与大小）
> - **`e.Handled = true`**：处理完标记，防止事件继续冒泡
> - **文件类型过滤**：`Drop` 里按扩展名（`.csv`/`.xls`/`.prc`）决定是否接收，不是所有拖进来的文件都处理

> [!example] 完整示例
> **文件拖入导入演示：窗口设置 AllowDrop 后，把文件从资源管理器拖入界面，Drop 事件通过 DataFormats.FileDrop 取到文件路径数组，常用于上位机导入配方、工艺文件等：**
>
> **MainWindow.xaml：**
> ```xml
> <Window x:Class="HmiDemo.MainWindow"
>         xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
>         xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
>         Title="文件拖入导入" Height="400" Width="480"
>         WindowStartupLocation="CenterScreen" Background="#0D1117" AllowDrop="True"
>         DragOver="OnDragOver" Drop="OnDrop">
>     <Grid Margin="15">
>         <Grid.RowDefinitions>
>             <RowDefinition Height="Auto"/>
>             <RowDefinition Height="*"/>
>         </Grid.RowDefinitions>
>         <TextBlock Text="把配方 / 工艺文件从资源管理器拖入本窗口"
>                    Foreground="#58A6FF" FontSize="14" FontWeight="Bold" TextWrapping="Wrap"/>
>         <Border Grid.Row="1" Margin="0,12,0,0" Background="#161B22"
>                 BorderBrush="#21262D" BorderThickness="1" CornerRadius="6">
>             <StackPanel>
>                 <TextBlock Text="拖拽文件到此处" Foreground="#8B949E"
>                            HorizontalAlignment="Center" VerticalAlignment="Center"
>                            FontSize="16" Margin="0,24,0,0"/>
>                 <TextBlock Text="支持一次拖入多个文件" Foreground="#8B949E"
>                            HorizontalAlignment="Center" FontSize="12"/>
>                 <ListBox x:Name="FileList" Background="Transparent" BorderThickness="0"
>                          Margin="10,16,10,10" Foreground="White"/>
>             </StackPanel>
>         </Border>
>     </Grid>
> </Window>
> ```
>
> **MainWindow.xaml.cs —— 后台代码：**
> ```csharp
> using System.Collections.Generic;
> using System.IO;
> using System.Windows;
>
> namespace HmiDemo
> {
>     public partial class MainWindow : Window
>     {
>         public MainWindow()
>         {
>             InitializeComponent();
>             FileList.ItemsSource = new List<string>();
>         }
>
>         // 拖拽经过：只有文件数据才显示"复制"效果
>         private void OnDragOver(object sender, DragEventArgs e)
>         {
>             e.Effects = e.Data.GetDataPresent(DataFormats.FileDrop)
>                 ? DragDropEffects.Copy : DragDropEffects.None;
>             e.Handled = true;
>         }
>
>         // 松手落点：核心是从 e.Data 中取出 FileDrop 格式的路径数组
>         private void OnDrop(object sender, DragEventArgs e)
>         {
>             if (e.Data.GetData(DataFormats.FileDrop) is string[] files)
>             {
>                 var items = (List<string>)FileList.ItemsSource;
>                 foreach (var file in files)
>                 {
>                     // 只显示文件名，完整路径仍可通过 file 获取
>                     items.Add(Path.GetFileName(file) + $"  [{new FileInfo(file).Length / 1024.0:F1} KB]");
>                 }
>                 FileList.Items.Refresh();
>             }
>             e.Handled = true;
>         }
>     }
> }
> ```
> 

> [!scene] 适用场景
> ✅ 导入配方/工艺参数文件：拖入 `.csv`/`.prc` 自动解析并下发（示例场景）
> ✅ 批量导入图片/日志/数据文件到列表或存储区
> ✅ 配置文件拖入应用后自动加载设置（比找菜单更直观）
> ✅ 组态软件里拖入图片作为背景图、拖入 DLL 注册插件
> ❌ 文件需要用户选择"保存位置"的导出场景（那是拖出，机制不同）
> ❌ 触屏环境（无资源管理器可拖，应提供浏览按钮兜底）

> [!pitfall] 常见踩坑
> 坑 1：**窗口子控件挡住了拖入** → 现象：窗口能拖，但拖到内部 `ListBox` 上没反应 → 原因：`AllowDrop` 只在设置它的元素上生效，子元素默认不接收 → 解决：把 `AllowDrop` 放到最外层容器（窗口/根 Grid），或给子控件也设 `AllowDrop`
> 
> 坑 2：**拖入的不是文件（是文本/链接）** → 现象：`GetData(FileDrop)` 返回 null 或崩溃 → 原因：没有校验格式就直接取 → 解决：先 `GetDataPresent(DataFormats.FileDrop)` 判断（示例 `OnDragOver`），格式不对时 `e.Effects = None`
>
> 坑 3：**读文件时抛异常（占用/权限）** → 现象：拖入后程序崩溃或提示"正由另一进程使用" → 原因：文件被打开、权限不足或路径失效 → 解决：`File.ReadAllText` 等操作包 `try/catch`，失败弹提示并继续处理其他文件

> [!best] 最佳实践
> - 文件格式校验放 `DragOver`（决定光标），内容级校验放 `Drop`（解析失败给出明确提示）
> - 读取文件统一 `try/catch`，拖入的文件可能被占用、可能损坏，不能让一个坏文件拖垮整个导入流程
> - 支持多文件时逐个处理，逐条反馈结果（成功/失败），别整体一把梭
> - 大文件拖入用异步读取（`async/await`）+ 进度提示，避免 UI 卡死（配合 `08-threading` 知识）
> - 拖入后把常用目录记住，下次拖入前预校验扩展名，减少无效操作

> [!practice] 上手练习
> **Lv.1 照猫画虎**：运行示例，从资源管理器拖入几个文件观察文件名与大小显示；拖入文件夹（目录）观察区别
> **Lv.2 小试牛刀**：在 `Drop` 里过滤扩展名：只接受 `.txt`/`.csv`，其他类型弹提示"不支持的格式"
> **Lv.3 融会贯通**：拖入 `.csv` 配方文件后自动解析首行标题与参数行，在表格（`DataGrid`）中展示，实现"拖入即导入"
