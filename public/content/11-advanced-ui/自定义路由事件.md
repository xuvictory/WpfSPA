# 自定义路由事件

> [!plain] 白话理解
> 普通事件像"点对点电话"：按钮拨给谁，谁就接，中间没有转接。路由事件像**车间广播**：报警按钮一按，声音沿工位往上广播（冒泡），车间主任、厂长、门卫都能听到；谁感兴趣谁处理，处理完还可以决定"要不要继续往上喊"。上位机里最典型的就是报警：几十个设备按钮不用各自绑 `Click` 处理，只要在窗口层 `AddHandler` 一次"报警广播"，`e.Source` 会告诉你到底是哪个设备按钮按的。自定义路由事件，就是给你的控件注册一个专属的"广播频道"，再配上标准的订阅接口。

> [!def] 官方定义
> 路由事件（Routed Event）是一种沿元素树进行路由的 WPF 事件，路由策略分为 `Bubble`（从源元素向上冒泡）、`Tunnel`（从根向下隧道）、`Direct`（仅源元素）。自定义路由事件通过 `EventManager.RegisterRoutedEvent(name, strategy, handlerType, ownerType)` 注册，控件内部用 `RaiseEvent(new RoutedEventArgs(...))` 触发，外部用 `AddHandler`/`RemoveHandler` 或事件包装属性订阅。`RoutedEventArgs.Source` 恒指向触发源元素而非当前处理者。详见官方文档：[路由事件概述](https://learn.microsoft.com/zh-cn/dotnet/desktop/wpf/advanced/routed-events-overview)、[EventManager.RegisterRoutedEvent](https://learn.microsoft.com/zh-cn/dotnet/api/system.windows.eventmanager.registerroutedevent)。

> [!origin] 由来背景
> WPF 2006 年随 .NET Framework 3.0 发布时，需要一个与"可视化树"模型配套的事件机制。WinForms 的事件是"点对点"的 CLR 事件：订阅者必须直接引用事件源对象，控件树中深层元素的事件要逐层手动转发，界面层级一变代码就要跟着改。WPF 的控件树常深达十几层（窗口→Grid→StackPanel→Button），若仍用点对点事件，模板内部元素触发的事件外部根本无法监听。路由事件让事件沿树"自动传播"，任何一层都可选择性处理，还天然支持 `EventTrigger`、`CommandBinding` 等 XAML 声明式响应——这是依赖属性之外的另一个 WPF 架构基石。

> [!essentials] 核心要点
> - **注册**：`EventManager.RegisterRoutedEvent("名称", RoutingStrategy.Bubble/Tunnel/Direct, typeof(RoutedEventHandler), typeof(OwnerType))` 得到静态 `RoutedEvent` 字段
> - **触发**：控件内 `RaiseEvent(new RoutedEventArgs(MyEvent, this))`，`RoutedEventArgs` 第二参是 `Source`
> - **订阅**：提供标准事件包装 `add => AddHandler(...)` / `remove => RemoveHandler(...)`，便于 XAML `MyEvent="..."` 直接挂接
> - **`e.Source` vs `e.OriginalSource`**：`Source` 是逻辑触发者，`OriginalSource` 是可视化树上最初命中的元素（模板内部元素时两者不同）
> - **`AddHandler` 的 handledEventsToo 参数**：传 `true` 可监听已被标记 `Handled` 的事件
> - **`RoutedEventArgs.Handled`**：处理者设为 `true` 可阻止冒泡继续（谨慎使用，可能影响其他层监听）

> [!example] 完整示例
> **设备报警演示：自定义 AlarmButton 用 EventManager.RegisterRoutedEvent 注册冒泡路由事件，点击按钮在内部 RaiseEvent 抛事件，由窗口 AddHandler 统一捕获并显示报警内容：**
>
> **MainWindow.xaml：**
> ```xml
> <Window x:Class="HmiDemo.MainWindow"
>         xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
>         xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
>         xmlns:local="clr-namespace:HmiDemo"
>         Title="自定义路由事件 - 设备报警" Height="360" Width="460"
>         WindowStartupLocation="CenterScreen" Background="#0D1117">
>     <Grid Margin="15">
>         <Grid.RowDefinitions>
>             <RowDefinition Height="Auto"/>
>             <RowDefinition Height="Auto"/>
>             <RowDefinition Height="*"/>
>         </Grid.RowDefinitions>
>         <TextBlock Text="点击报警按钮，AlarmRaised 事件将沿可视化树向上冒泡到窗口"
>                    Foreground="#58A6FF" FontSize="14" FontWeight="Bold" TextWrapping="Wrap"/>
>         <StackPanel Grid.Row="1" Orientation="Horizontal" Margin="0,15,0,0">
>             <!-- 自定义控件：Tag 区分设备，事件统一由窗口层捕获 -->
>             <local:AlarmButton x:Name="Alarm1" Content="1# 电机过载报警" Tag="电机过载"
>                                Margin="0,0,10,0" Padding="10,6"
>                                Background="#DA3633" Foreground="White"/>
>             <local:AlarmButton x:Name="Alarm2" Content="2# 温度越限报警" Tag="温度越限"
>                                Padding="10,6" Background="#DA3633" Foreground="White"/>
>         </StackPanel>
>         <TextBox x:Name="LogBox" Grid.Row="2" Margin="0,15,0,0" IsReadOnly="True"
>                  TextWrapping="Wrap" VerticalScrollBarVisibility="Auto"
>                  Background="#161B22" Foreground="#8B949E" BorderBrush="#21262D"/>
>     </Grid>
> </Window>
> ```
>
> **MainWindow.xaml.cs —— 后台代码与自定义路由事件：**
> ```csharp
> using System;
> using System.Windows;
> using System.Windows.Controls;
>
> namespace HmiDemo
> {
>     // 报警按钮：定义自己的路由事件，点击时向上冒泡，窗口可统一监听
>     public class AlarmButton : Button
>     {
>         // 注册路由事件：Bubble 表示从触发源沿可视化树向上冒泡
>         public static readonly RoutedEvent AlarmRaisedEvent = EventManager.RegisterRoutedEvent(
>             "AlarmRaised", RoutingStrategy.Bubble,
>             typeof(RoutedEventHandler), typeof(AlarmButton));
>
>         // 提供标准的 .NET 事件包装，便于 XAML 或代码直接订阅
>         public event RoutedEventHandler AlarmRaised
>         {
>             add => AddHandler(AlarmRaisedEvent, value);
>             remove => RemoveHandler(AlarmRaisedEvent, value);
>         }
>
>         // 点击时通过 RaiseEvent 抛出路由事件，Source 指向触发源自身
>         protected override void OnClick()
>         {
>             base.OnClick();
>             RaiseEvent(new RoutedEventArgs(AlarmRaisedEvent, this));
>         }
>     }
>
>     public partial class MainWindow : Window
>     {
>         public MainWindow()
>         {
>             InitializeComponent();
>             // 在窗口层 AddHandler 捕获任意子按钮冒泡上来的报警事件
>             AddHandler(AlarmButton.AlarmRaisedEvent, new RoutedEventHandler(OnAlarmRaised));
>             LogBox.AppendText("窗口已注册 AlarmRaised 监听，等待报警...\n");
>         }
>
>         // 路由事件处理：e.Source 是原始触发源，而非当前处理者
>         private void OnAlarmRaised(object sender, RoutedEventArgs e)
>         {
>             if (e.Source is AlarmButton source)
>             {
>                 LogBox.AppendText($"[{DateTime.Now:HH:mm:ss}] 报警：{source.Tag}，来源控件 {source.Name}\n");
>             }
>         }
>     }
> }
> ```
> 

> [!scene] 适用场景
> ✅ 一组同类控件要"统一响应"：设备报警按钮、工位急停按钮、操作站功能键，窗口层一处 `AddHandler`
> ✅ 复合控件的内部元素事件需要暴露给外部（模板里的 Button 点击 → 控件抛自定义路由事件）
> ✅ 事件需要被 `EventTrigger`、样式触发器或命令绑定以 XAML 方式响应
> ✅ 事件沿树"传递信息"且各层都能参与处理（记录日志、拦截、放行）
> ❌ 控件内部自用、不对外暴露的私有通知（用普通 CLR 事件或回调即可，路由开销不必要）
> ❌ 需要在多线程间传递消息的场景（路由事件只存在于 UI 线程的可视化树）

> [!pitfall] 常见踩坑
> 坑 1：**把 `sender` 当触发源用** → 现象：窗口层收到事件，`sender` 是窗口而不是按钮，取 `Tag` 取到空 → 原因：路由事件处理时 `sender` 是"当前处理者"，冒泡到哪层就是哪层 → 解决：一律用 `e.Source`（触发源）判断发起者
> 
> 坑 2：**忘记给事件加 `event` 包装** → 现象：XAML 里写 `<local:AlarmButton AlarmRaised="..."/>` 报事件不存在 → 原因：光有 `RoutedEvent` 字段不构成可订阅的 C# 事件，XAML 订阅走的是事件包装 → 解决：补上 `add/remove` 委托到 `AddHandler`/`RemoveHandler` 的标准包装
>
> 坑 3：**滥用 `e.Handled = true` 提前截断冒泡** → 现象：上层（如窗口）突然收不到某些报警了 → 原因：某层处理完把事件标记 `Handled`，默认不再继续冒泡 → 解决：确需阻断时再设 `Handled`；只是想"听一下"就用 `AddHandler(evt, handler, true)` 监听已处理事件

> [!best] 最佳实践
> - 触发源信息不够时自定义 `RoutedEventArgs` 子类携带业务数据（设备号、报警级别），不要塞 `Tag`
> - 控件对外只暴露 `RoutedEvent` 字段 + 事件包装，内部触发统一走 `RaiseEvent`，保持单向
> - 订阅方在不再需要时 `RemoveHandler` 退订，动态创建的子元素销毁前避免悬挂引用
> - 同源同类型的路由事件统一命名前缀（如 `AlarmRaised`），字段名加 `Event` 后缀（`AlarmRaisedEvent`）
> - 需要"谁都能拦一下"用 `Bubble`；需要"先拦截再放行"（如键盘预览）用 `Tunnel`

> [!practice] 上手练习
> **Lv.1 照猫画虎**：运行示例点击两个报警按钮，观察日志中 `Source` 与窗口的区分；在窗口上加第三个 `AlarmButton`，验证不需要改处理代码
> **Lv.2 小试牛刀**：给 `AlarmRaisedEventArgs` 自定义子类增加 `int Level` 字段（1 提示 / 2 报警 / 3 急停），点击时传入，窗口日志按级别着色
> **Lv.3 融会贯通**：在窗口与按钮之间插一层 `Grid`，给 Grid 也注册 `AlarmRaised`，验证冒泡顺序（按钮 → Grid → 窗口），并在 Grid 层统计报警次数
> **Lv.4 拆层挑战**：把示例改成 Tunnel 策略的 `AlarmPreview` 事件，在窗口层用 `e.Handled=true` 拦截低级别报警，验证隧道阶段拦截后按钮的 `AlarmRaised` 不再触发
